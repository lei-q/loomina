# 发布与合规

> 核心判断：**发布的第一能力是"导出合规成品"，不是"代你发"。**
> 平台不是管道，是有规则的房东；官方 API 是增强，不是依赖。

---

## 一、先认清三件事

1. **平台 API 开放程度差异极大。** 有的能发，有的只能导，有的要企业资质和审核。
2. **逆向登录 / 模拟点击 / Cookie 注入是违规的。** 轻则封号，重则法律风险。这条不做。
3. **合规是上线前置条件。** AI 标识、内容安全、授权链，缺一条就不能发。

---

## 二、三层发布能力

| 层 | 能力 | 覆盖 | 依赖 | 优先级 |
| --- | --- | --- | --- | --- |
| **L1 导出包** | 生成符合平台规格的成品 + 封面 + 文案 | 100% | 无 | **P0，永远可用** |
| **L2 官方 API** | OAuth 授权后代发 | 部分平台 | 企业资质/审核 | P2，逐个接 |
| **L3 分享扩展** | 手机系统分享 → 用户点一下发 | 几乎全部 | 移动端 | P1 |

**L1 是底线。** 任何平台规则变化、API 下线，用户至少还能导出、手动发。L2/L3 都是在 L1 之上的增强。

明确不做：逆向登录、模拟点击、批量养号、绕过平台审核。

---

## 三、平台规格矩阵

规格会变，所以**不写死在代码里**，维护成 `PlatformSpec` 表并定期校验。

| 平台 | 画幅 | 典型时长 | 封面 | 内容特点 | 发布方式 |
| --- | --- | --- | --- | --- | --- |
| 抖音 | 9:16 | 15s–15min（短剧多 1–3min） | 竖版 | 强钩子、强节奏 | 开放平台（需资质）/ 分享 |
| 快手 | 9:16 | 类似抖音 | 竖版 | 接地气、老铁文化 | 开放平台 / 分享 |
| 小红书 | 9:16 / 3:4 | 短视频为主 | 竖版/方图 | 封面与标题权重高 | **无公开 API，只做分享** |
| B 站 | 16:9 / 9:16 | 中长 | 横版 | 弹幕、二创 | 开放平台（权限有限） |
| 视频号 | 9:16 | 短视频 | 竖版 | 微信生态 | 无公开 API / 分享 |
| TikTok | 9:16 | 视地区 | 竖版 | 出海 | Content Posting API（需审核） |
| YouTube Shorts | 9:16 | ≤ 3min | 竖版 | 出海 | Data API（配额有限） |
| X | 16:9 / 1:1 / 9:16 | ≤ 2:20（普通账号） | 横/方 | 话题传播 | API（付费） |

> 具体码率、文件大小、标题字数、话题数量以平台最新文档为准；这张表是**结构**，数值进 `PlatformSpec` 并由校验任务更新。

**当前实现（2026-11-11，ADR-0099）**：规格表在 `apps/web/lib/platforms.ts`，版本号 `2026-11`，共 9 份（含「通用（不按平台卡）」）。只有画幅、时长上下限、编码（H.264）与分辨率短边 ≥720 会硬拦导出；帧率不符只提示复核；标题字数、话题数量、码率、文件大小与封面都标 `reference: true`，超了只提示，不单独拦。各平台的具体数值只写有公开依据的部分：抖音 15s–15min、快手 ≥15s、YouTube Shorts ≤180s、X ≤140s（普通账号），其余不设硬性时长。文件上限已核到两个（2026-11-14，ADR-0214）：B 站 16 GB、快手 2 GB，超限硬拦并写出处与复核日期；其余七个仍如实写「未核验」。成片页的目标平台下拉会立即重算「平台规格」列表与导出按钮；发布包记录 `platform`、`platformName`、`specVersion` 与逐项 `platformChecks`。**未做**：其余七个平台的文件上限（抖音 / TikTok / YouTube 文档站本次网络不可达）、多平台版本渲染（G9）、官方 API 发布（G4）。

### 规格校验项

- **硬校验**：分辨率短边 ≥720、画幅、编码（H.264）、帧率（不符只 review）、时长上下限、文件大小上限（有公开值才拦）
- **参考值**：码率区间、封面尺寸与安全区、标题/简介字数、话题数量与格式
- 字幕：烧录 vs 外挂（多数平台推荐烧录，保证样式）
- 音乐：平台曲库 vs 自带上传（版权限制）；发布包记录授权来源
- 首帧：是否允许黑帧/纯字幕帧

## 四、发布包结构

一个项目可以有多个平台的发布包，共享素材、各自规格：

```ts
interface PublishPackage {
  id: ID;
  episodeId: ID;
  platform: PlatformId;
  videoAssetId: ID;
  coverAssetId: ID;
  title: string;
  description: string;
  hashtags: string[];
  subtitleAssetId?: ID;
  aiLabel: AILabel;              // 显式 + 隐式
  compliance: ComplianceCheck;   // 预检结果
  specVersion: string;           // 对应 PlatformSpec 版本（当前 2026-11）
  platformChecks: { id: string; label: string; status: "pass" | "review" | "block"; detail: string; reference?: boolean }[];
  music: { title: string; mood: string; gainDb: number; duckDb: number; ducking: boolean; licenseRef: string }[];
  status: "draft" | "ready" | "exported" | "published" | "failed";
}
```

**发布包必须自包含**：拿到这个包，不登录产品也能手动发出去。

## 五、AI 生成内容标识

依据《人工智能生成合成内容标识办法》（2025-09-01 施行），做**显式 + 隐式**两层：

| 类型 | 位置 | 做法 |
| --- | --- | --- |
| **显式** | 画面角标 / 片头片尾 / 简介 | 渲染时烧录，不可被用户关闭 |
| **隐式** | 文件元数据 | 写入 AIGC 字段（如 `AIGC`、`ContentProducer`、`ProduceID`） |
| **音频** | 音频元数据 / 口播提示 | 按规范写入 |

实现要点：

- 在**渲染阶段**打标，不是在发布阶段补——导出即合规。
- 元数据写入放在封装/转码环节，避免被后续处理抹掉。
- 发布包携带 `AILabel`，平台要求填写时自动带上。
- **不得移除平台已添加的标识。**
- 标识样式可配置（角标位置/透明度），但不可关闭。

## 六、内容安全：四个检查点

| 检查点 | 对象 | 时机 |
| --- | --- | --- |
| 1 剧本 | 前提、台词、标题、话题 | 进入分镜前 |
| 2 关键帧 | 首尾帧、封面 | 生成后、Animatic 前 |
| 3 成片 | 视频 + 音频 + 字幕 | 导出前 |
| 4 发布文案 | 标题、简介、话题 | 发布前 |

三级处置：

- **pass**：通过；
- **review**：人工复核（价值观擦边、敏感但非违规）；
- **block**：阻断，必须改。

重点检查：涉政、涉黄、暴力、低俗、歧视、未成年人、拜金炫富、封建迷信、诱导消费。

所有检查结果留档（谁、什么时候、什么模型、什么结论），便于申诉与追溯。

**当前实现（2026-11-11，ADR-0095）**：成片页导出前统一跑四项检查——AI 标识、内容安全、素材授权、平台规格；内容安全是 17 条规则的关键词扫描，分 block / review 两级，覆盖上面列出的九类重点。成片 MP4 的渲染清单与发布包都带一份 `compliance` 证据（检查时间、内容指纹、确认状态、命中数量），渲染路由会用同一套规则再扫标题与占位文案。**未做**：图像 / 视频审核、第三方审核接口、四个检查点各自在剧本 / 关键帧 / 发布文案阶段独立执行。

## 七、资质与备案清单

面向公众提供生成式 AI 服务，国内通常涉及（**需专业法律意见，此处只列清单**）：

- 生成式人工智能服务备案 / 安全评估
- ICP 备案（网站/App）
- 算法备案（推荐/生成算法）
- 公安联网备案
- 网络文化经营许可证（视业务形态）
- 广播电视节目制作经营许可证（视内容形态）
- 个人信息保护合规（隐私政策、数据出境）

**MVP 可以先小范围内测**，但正式对外前必须把主体、属地网信办口径、备案路径确认清楚。

## 八、版权与授权链

发布前必须能回答：**这条片子的每一块素材，权利从哪来？**

| 素材 | 需要的授权 |
| --- | --- |
| 模型输出 | 供应商商用条款（写入能力矩阵 B12） |
| 音乐 | 生成音乐的商用条款 / 曲库授权 |
| 音色 | 声音克隆需本人书面授权 + 活体确认 |
| 字体 | 商用授权（很多字体免费版不能商用） |
| 参考图 / 真人肖像 | 肖像权授权 |
| 用户上传小说 | 权利声明 + 侵权责任约定 |
| 生成内容本身 | 用户协议约定权属与平台使用权 |

**授权台账**：每条素材挂 `AuthorizationRecord`，发布前自动检查，缺授权直接阻断。

> 当前状态：H7 未做，没有授权台账。导出前检查只能把上传 / 导入素材标成 review，让作者确认「有使用权」；剧本导入以「导入剧本」开头的 provenance 视为已声明原创或已获授权（ADR-0095）。

## 九、发布流程

```
预检（规格 + 合规 + 授权）
      ▼
多平台版本渲染（按 PlatformSpec）
      ▼
人工确认（成片闸门）
      ▼
导出 / API 发布 / 分享扩展
      ▼
发布台账（平台、时间、回执、链接）
      ▼
数据回流（仅官方允许的指标）
```

预检不通过，不进入渲染。**不要在渲染完才发现规格不对。**

当前实现：成片页的预检在导出区上方，未通过时五个导出按钮全部禁用；服务端渲染路由还有第二道扫描，缺合规证据或标题命中硬阻断都返回 400（ADR-0095）。

## 十、移动端分享扩展

这是覆盖无 API 平台的合规解法：

- **iOS**：Share Extension，从产品里"发送到抖音/小红书"。
- **Android**：系统 Sharesheet / Intent。
- 本质是**用户主动分享**，不是代发；平台看到的是用户操作。
- 优点：合规、覆盖全、不需要企业资质。
- 缺点：需要手机在场、需要用户点一下。

产品话术要诚实：说"一键分享到手机"，不要说"自动发布"。

---

## 十一、数据回流

只做官方 API 明确允许的指标（播放、点赞、评论数等）。

- 不做爬虫、不做模拟请求。
- 平台不提供就接受"没有数据"，不赌灰色手段。
- 回流数据用于选题与钩子 A/B，不用于其他用途。

---

## 十二、失败模式

| 失败 | 表现 | 原因 | 对策 |
| --- | --- | --- | --- |
| 规格不符 | 上传被拒/被压缩 | 未按 PlatformSpec 渲染 | 预检 + 多版本 |
| 未标识 | 下架/限流 | 漏打 AIGC | 渲染阶段强制打标 |
| 安全漏审 | 下架/封号 | 只审文本不审画面 | 四个检查点 |
| 授权断链 | 诉讼/下架 | 素材来路不明 | 授权台账 + 阻断 |
| 逆向封号 | 账号被封 | 模拟登录/点击 | 明令禁止 |
| 规则突变 | 功能失效 | 平台改政策 | 规格表版本化 + L1 兜底 |
| 包不完整 | 用户手动发不了 | 依赖平台字段 | 发布包自包含 |

## 十三、IR 映射

```ts
interface PlatformSpec {
  platform: PlatformId;
  version: string;
  aspectRatios: string[];
  resolution: { width: number; height: number };
  durationMs: { min: number; max: number };
  maxFileBytes: number;
  codec: string;
  cover: { ratio: string; safeArea: string };
  titleMaxChars: number;
  hashtagMax: number;
  subtitleMode: "burn-in" | "sidecar" | "both";
  publishMode: "api" | "share" | "export-only";
}

interface ComplianceCheck {
  id: ID;
  packageId: ID;
  checks: {
    kind: "spec" | "ai-label" | "content-safety" | "authorization" | "copyright";
    verdict: "pass" | "review" | "block";
    detail: string;
    model?: string;
    reviewer?: string;
    at: ISODate;
  }[];
  overall: "pass" | "review" | "block";
}

interface AuthorizationRecord {
  id: ID;
  assetId: ID;
  kind: "model-output" | "music" | "voice" | "font" | "portrait" | "text";
  grantee: string;
  scope: string;
  expiresAt?: ISODate;
  documentRef: ID;
}
```

**新增不变量**

30. **未通过 `ComplianceCheck` 的发布包不得进入 exported/published。**
31. **`AILabel` 必须在渲染阶段写入**，不得在发布阶段补。
32. **每个素材必须有 `AuthorizationRecord`**，缺失即 block。
33. **发布包必须自包含**：视频、封面、标题、简介、话题、字幕、标识缺一不可。
34. **不得移除平台已添加的 AI 标识。**
35. **禁止任何逆向登录、模拟点击、绕过审核的发布方式。**

## 十四、一句话

**发布的第一能力是"导出合规成品"，不是"代你发"。**
平台 API 是增强不是依赖；AI 标识在渲染时打；内容安全四个检查点；授权链断了就不发。
