# 路线图

> 约束：**单人开发**。所以每个阶段都必须是"能独立发布、能验证假设"的闭环。
> 原讨论中的 8–12 周按单人全职调整为 **16–22 周**（含契约层、能力测绘与 3D 最小版），宁可慢，不要烂尾。

## Phase 0 — MVP：证明"一个 C 端用户能 30 分钟出片"

**周期**：约 16–22 周（单人全职，含契约层、能力测绘与 3D 最小版）
**目标**：一句话/一段大纲 → 60 秒竖屏短剧 → 导出可发布文件。

### 验收标准（缺一不可）

1. 无视频经验的人，30 分钟内完成一条 60s、3–5 个镜头、1 个场景、2 个角色的竖屏片。
2. 角色在全部镜头中可辨识为同一人（人工通过率 ≥ 80%）。
3. 对白时长与画面时长自动对齐，无需手动变速。
4. 自动出字幕、自动配乐、自动混音，可逐项手动改。
5. 导出 MP4（1080×1920，H.264），带 AI 标识，可直接上传抖音/小红书。
6. 全流程成本可记账，能回答"这一条片子花了多少钱"。

### 明确不在 MVP

- 剧本医生（A2）、口型同步（C3）、节拍卡点（C5）、自动 QA（B4）
- 多比例适配（E5）、移动端分享扩展（G3）、官方 API 发布（G4）
- 协作、模板市场、摄影指导面板完整版

### 落地顺序（按风险退休，不按功能堆叠）

详细步骤见 [TECH-SELECTION.md](TECH-SELECTION.md) 第八节，这里只列节奏：

| 步骤 | 周期 | 先验证什么 |
| --- | --- | --- |
| S0 契约层 | 1–2 周 | IR、网关接口、状态机、提示词契约是否够用 |
| S1 能力测绘 | 1 周 | 模型的真实边界、单价、**商用条款** |
| S1.5 3D 最小版 | 2–3 周 | 灰盒场景板能否支撑摆位/机位/轴线 |
| S2 Animatic 闭环 | 2–3 周 | 低成本能否看出故事与节奏问题 |
| S3 单镜质量 | 3–4 周 | 一致性阈值与重试成本 |
| S4 前端骨架 | 3–4 周 | C 端能否在 UI 内走到 animatic |
| S5 时间线与渲染 | 3–4 周 | 预览与成片的差距 |
| S6 发布包 | 1–2 周 | 发布流程是否顺畅 |

> **S0–S3 不写 UI，先用脚本验证契约与质量。** 这四步验证的是不可逆或高成本的东西；先做 UI 会导致返工。

> **E7.2 帧级找点落地（2026-11-12，ADR-0129 落地节）**：不引 mp4box.js、不用 WebCodecs——`GET /api/preview/frame?asset=&at=&w=` 由服务端 ffmpeg `-ss`（在 `-i` 之前，精确到帧）切一张 JPEG 回来，浏览器 `<img>` 直接显示。`lib/preview-frame.ts` 全纯函数：地址换算、60ms 节流去重、`?probe=1` 能力探测缓存 5 分钟，22 条单测。预演右侧加「帧级找点」开关：勾上暂停并换帧、头部签变「帧级找点 · ffmpeg 9.0.2」、`‹ 一帧 / 一帧 ›` 与 `,` `.` 按 33ms 步进、拖时间轴跟着重切；按播放就退出（写成一个 `togglePlay` 动作——用「playing 变真就关」的 effect 会与「勾上就暂停」互相抵消，勾了立刻弹回）、换到没片子的镜自动关掉。`attachVideo` 也收 `loomina://assets/`（原来只收 http 与 data，与帧级找点合不上）。979 个测试全过；浏览器实测「把本机资产库那段 mp4 贴成 SH-02 的 take → 预演勾帧级找点 → 切帧地址随步进 0 → 33、随拖动变 1500 → 点播放自动退出」。**未做**：E7.3 WebGPU、540p 代理视频（真到远端部署时要评估）。

> **B13.3 结构参考图落地（2026-11-12，ADR-0126 落地节）**：不引 WebGL / Three.js——`packages/pipeline/src/structure.ts` 用一组正交基 + 一次针孔投影，把这一镜的坐标投到 360×640 画面上：地面网格、房间线框、家具矮盒（只画顶面与线框，填满会把身后的人盖死）、人物剪影（柱到肩 1.45 m + 头单独一个圆，中间留脖子）与名字，按深度着色（近暖远冷）、由远到近排序；`drawStructure` 画到 Canvas 2D。整人偏出画面的标「← 周 画面外」并计数，机位背后的计 `culled`。走位抽屉加「结构参考图」与「存成 PNG」。**顺手修了焦段口径**：模板焦段是 35 mm 全画幅等效，竖幅画面宽对应短边 24 mm，不是第一版抄来的 9.6 mm——35 mm 原本算出 15.6° 视场（比长焦还窄），现在是 37.8°；`fovRad` 一并改正，俯视图扇形与结构图取景同口径。995 个测试全过；浏览器实测「第 5 场用这个摆位 → 选中 SH-04 → 两个人按仰拍 40mm 一前一后 → 把周拖到林前面 → 结构图里周的剪影变大变暖、叠在林前」。**未做**：真实立体体积、接进生成当参考图、非矩形房间。
> **H3 对象存储落地（2026-11-12，ADR-0129 落地节）**：不引 `@aws-sdk/client-s3`、也不引 `aws4`——`apps/web/lib/s3-sigv4.ts` 自己写 SigV4 预签名（URI 编码 / 规范化请求 / 四层派生密钥），28 条单测里三条直接对照 AWS 官方向量（GET Object 的签名、PUT Object 的载荷哈希与签名、预签名 GET 的整条 URL 逐字一致）。`lib/s3-store.ts` 用预签名 URL 做写 / 读 / 删 / 列桶，key 按 `<prefix>/<两位>/<sha256>.<ext>` 内容寻址。`s3://桶/路径` 进 IR；渲染与帧级找点遇到它先拉到 `.loomina/assets/cache/` 再喂 ffmpeg；浏览器经 `GET /api/storage?uri=` 读。设置页加「对象存储」区（Endpoint / 桶 / 区域 / AK / SK / path-style、探测连通、清掉配置），密钥不回显。1050 个测试全过。**端到端用本地 MinIO 验过**：写读列删、中文与特殊字符 key、过期签名被拒、对象存储里的图片在浏览器显示、对象存储里的视频切帧（360×640 彩条）、带 `s3://` 素材的成片渲染（ffprobe 1080×1920 h264 1.000s）。**端到端跑出一个真实 bug**：`objectUrlOf` 与 `canonicalRequest` 各编码一次路径，中文 key 变成 `%25E4…`，MinIO 直接 403——单测里两边用同一个函数看不出来，已修并补两条回归。**未做**：桶里孤儿对象的清理界面、多项目分桶、分片上传。
