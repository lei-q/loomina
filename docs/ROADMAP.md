# 路线图

> 约束：**单人开发**。所以每个阶段都必须是"能独立发布、能验证假设"的闭环。
> 原讨论中的 8–12 周按单人全职调整为 **16–22 周**（含契约层、能力测绘与 3D 最小版），宁可慢，不要烂尾。

## Phase 0 — MVP：证明"一个 C 端用户能 30 分钟出片"

**周期**：约 16–22 周（单人全职，含契约层、能力测绘与 3D 最小版）
**目标**：一句话/一段大纲 → 60 秒竖屏短剧 → 导出可发布文件。

### 验收标准（缺一不可）

1. 无视频经验的人，30 分钟内完成一条 60s、3–5 个镜头、1 个场景、2 个角色的竖屏片。
2. 角色在全部镜头中可辨识为同一人（人工通过率 ≥ 80%）。
3. 对白时长与画面时长自动对齐，无需手动变速。
4. 自动出字幕、自动配乐、自动混音，可逐项手动改。
5. 导出 MP4（1080×1920，H.264），带 AI 标识，可直接上传抖音/小红书。
6. 全流程成本可记账，能回答"这一条片子花了多少钱"。

### 明确不在 MVP

- 剧本医生（A2）、口型同步（C3）、节拍卡点（C5）、自动 QA（B4）
- 多比例适配（E5）、移动端分享扩展（G3）、官方 API 发布（G4）
- 协作、模板市场、摄影指导面板完整版

### 落地顺序（按风险退休，不按功能堆叠）

详细步骤见 [TECH-SELECTION.md](TECH-SELECTION.md) 第八节，这里只列节奏：

| 步骤 | 周期 | 先验证什么 |
| --- | --- | --- |
| S0 契约层 | 1–2 周 | IR、网关接口、状态机、提示词契约是否够用 |
| S1 能力测绘 | 1 周 | 模型的真实边界、单价、**商用条款** |
| S1.5 3D 最小版 | 2–3 周 | 灰盒场景板能否支撑摆位/机位/轴线 |
| S2 Animatic 闭环 | 2–3 周 | 低成本能否看出故事与节奏问题 |
| S3 单镜质量 | 3–4 周 | 一致性阈值与重试成本 |
| S4 前端骨架 | 3–4 周 | C 端能否在 UI 内走到 animatic |
| S5 时间线与渲染 | 3–4 周 | 预览与成片的差距 |
| S6 发布包 | 1–2 周 | 发布流程是否顺畅 |

> **S0–S3 不写 UI，先用脚本验证契约与质量。** 这四步验证的是不可逆或高成本的东西；先做 UI 会导致返工。

> **H20 整场锁定落地（2026-11-12，ADR-0133）**：一场一个动作，不再逐镜点六次锁。`setSceneLock(sceneId, locked)` 一次写 N 条已有的 `shot.updated{locked}`——不发明场景级锁字段，锁是镜头的属性，加个场锁立刻会出现「场锁着但镜头没锁」这种要额外解释的状态。与单镜锁定共用同一条规则：没有 approved take 的镜头跳过，回执写明「锁了 1 镜，跳过 1 镜（还没留用 take）」，三种空结果各有一句话。按钮文案只看「这一场有没有锁着的」——若按「全锁才算解锁」，一场里只要有一镜没留用 take 就永远到不了全锁，锁上之后再也解不开（浏览器实测撞出来的）。无新事件、无 IR 变化、`LOG_VERSION` 不变。1121 个测试全过；浏览器实测「第 2 场点整段锁定 → 标题『锁 1』、按钮变『整段解锁』、下面写『锁了 1 镜，跳过 1 镜』→ 再点一次全部解开」。端到端跑出两处真问题：回执写进了场头不渲染的 `note`，按钮点了页面毫无反应；按钮按「全锁」判定方向导致部分锁定后无法整段解锁。**未做**：锁定历史页、场锁与镜锁的继承、整段锁定时自动留用、跨场批量锁定。

> **H6 生成结果人工复核落地（2026-11-12，ADR-0132）**：不引模型审核服务、不假装网关有审核能力——像素这一层由作者终审，系统负责把「会进成片的每一条生成结果」摆到一处、把结论写进 IR、让「不可用」真的拦住导出。只审画面轨 take、首尾帧与配音；定妆与参考图不审（它们影响下一次生成，不影响这一次发布）。`Asset.review` 是可选字段，`LOG_VERSION` 不用升；新事件 `asset.reviewed`（`null` = 收回复核）——不复用 `asset.updated`，因为那条是合并语义，`undefined` 过 JSON 会消失，收回复核删不掉字段（第一版这么写，store 测试当场抓到）。导出前检查从四项变五项，复核结论走同一套指纹与确认机制。1112 个测试全过；浏览器实测「示例项目 10 条画面资产本来就不存在 → 清单如实列成『资产不存在』且按钮禁用 → 配音那条标『已看』后摘要变『1 个已看通过，10 条没有文件』→ 标『不可用』后 1 处阻断、导出按钮锁死 → 撤销后回到待确认」。端到端跑出两处真问题：把已看的条目藏起来导致撤不掉（改成全部列出、通过的排最后）；缺资产的条目既不拦也不提醒却说「都复核过了」（改成进待确认并如实写摘要）。**未做**：模型审核服务、供应商审核结论的结构化落库、申诉与人工复审。

> **E1 配音与字幕按句偏移落地（2026-11-12，ADR-0131）**：不建独立轨表——画面轨必须首尾相接（渲染清单硬校验），能自由挪的只有叠加层。`DialogueLine.voiceOffsetMs` / `subtitleOffsetMs`（整数毫秒、±30 秒）走既有 `dialogue.updated` 的 patch，`null` 归零。成片页「音轨与字幕轨」逐句调：`‹ ›` 挪 100ms、Shift 挪 500ms、`↺` 只归这一条轨，两条轨互不影响。播放、字幕条、SRT、ASS、预览 HTML、渲染清单与 OTIO 六处改读 `audioStartMs` / `cueStartMs`；起点在片外时读模型夹回成片之内，IR 留作者填的原值。字幕条改成按绝对时间定位，挪过的字幕在条上能看见它离开原位。1091 个测试全过；浏览器实测「连点两次字幕前挪 → 一步一挪各记一条（第一版收目标值，闭包旧值让连点只挪一步，已改成收增量）→ 字幕条上的第一句左移 1.8% → 归位只影响这一条轨」。**未做**：自由拖动起点、独立多轨画外音层。

> **H5 AI 标识补全：角标按平台摆、标识带内容指纹（2026-11-12，ADR-0138）**：ADR-0090 留下两条：角标位置与「强隐式标识」。第一条不是洁癖——右下角正是抖音、快手、小红书、TikTok 摆点赞 / 评论 / 分享按钮的地方，角标压在那里，画面上就等于没有。做法是**角标位置进平台规格表**（`PlatformSpec.badge = { corner, insetPct }`）：竖屏信息流平台统一左上 8%（与 `SAFE_AREA.topPct` 对齐，右侧是互动栏、底部是文案与进度条），X 右上，通用规格回右下；预览 HTML、成片页播放器、MP4 canvas 叠加层三处共用 `badgePlacementOf(platform)`，不各写各的；没写位置的平台退回 `DEFAULT_BADGE` 不抛错。第二条的漏洞更直接：隐式标识只有一句固定文案，抄到另一条视频的元数据里没有任何东西能说明它对不上。**加一枚内容指纹**——`aiLabel` 多 `version: 1` 与 8 位十六进制 `contentHash`，取材只取决定「这份产物长什么样」的字段：标题（80 字裁切）、总长、每段时长与素材地址的 FNV（不是地址长度，长度相同分不出换没换 take）；换 take / 改时长 / 增删一镜都变，改字幕文案或配乐不变。指纹跟着产物走：预览 HTML 的 `<meta>`、OTIO 的 `metadata.loom.aiLabel`、发布包 `aiLabelRecord`、MP4 容器 `description=AI生成 · 内容指纹 <hash>`。**渲染路由重算并拒绝不一致**——客户端自己算自己核等于没检查。IR 的 `AILabelSchema` 加可选 `contentHash`（旧发布包照样合法，`LOG_VERSION` 不变），`publish.recorded` 校验格式。1173 个测试全过；浏览器实测「默认抖音角标在左上（偏移 9px、落在 8% 安全区）→ 切通用回右下 → 合规预检那一行写『左上角「AI 生成」角标（离边 8%）…（含内容指纹）』」+ 预览 HTML 三处 meta 齐全 + 渲染路由对 `deadbeef` 回 400、按规则算对的 202 → `ffprobe` 读到 `comment=AI生成`、`description=AI生成 · 内容指纹 2b2da29a`。**未做**：数字水印（扛转码的像素级标记）、签名与验签（密钥 / 公钥分发 / 离线校验）、标识分级（全生成 / 辅助生成、服务提供者名称）、按平台逐角实测角标位置。

> **G6 封面自动生成（第一档）落地（2026-11-12，ADR-0139）**：发布包里的 `cover` 一直只是「某一镜的一张原帧」——没有标题、没有排版、没有标识，作者还得自己拿剪图软件再做一张，E6 的「未做」挂着这条。做法是**封面当导出物，不进 IR**：成片页多一块「封面」区，选镜 + 拖滑杆找帧 → 「生成封面」→ 客户端画布出 1080×1920 PNG，可直接下载；刷新后要重出，但 IR 里不出现二进制，也不会出现「封面与剪辑对不上」的缓存。**画面复用 E7.2 的服务端精确切帧**（`/api/preview/frame`，`-ss` 在 `-i` 之前；`FRAME_MAX_WIDTH` 720 → 1080，预演默认仍取 360），静态图直读，两样都取不到就出**纯标题封面**（渐变底 + 标题 + 角标），不拿占位图冒充。**排版按「一眼读完」**：标题最多两行、每行 9 个全角字、优先切在标点后面，字号随最长行缩（宽 7.8%–11.5%，夹 56–140px）；标题贴左下、留 `SAFE_AREA` 的 6% / 14%，上方一条品牌色条；简介第一行当钩子（≤18 字）；底部压渐变。**封面也带「AI 生成」角标**，位置读 `badgePlacementOf(platform)`，与成片、预览同一张表（H5）。标题 / 平台改过，预览旁明说「重新生成才会带上新的」，不偷偷重画。发布包 JSON 多 `coverArt`（文件名 / 字节数 / 第几镜 / 第几毫秒 / 尺寸 / 平台 / 生成时间）。857 个 web 测试全过（新增 `cover` 15 条、`preview-frame` 宽度断言 2 条改；全仓 1188 条）；浏览器实测「补两条带图资产 → 封面区列出两镜 → 拖到 60% → 生成 1080×1920 / 612 KB，画面铺满、标题在左下、角标在右下 → 改平台出现过期提示 → 下载 `夜班-封面.png` 626599 B → 发布包 `coverArt` 的字节数与文件一致」。**未做**：封面模板与配色、人物抠图、按平台输出不同尺寸、封面进资产库 / 回滚、多版本 A/B。

> **D3 按角色给字幕着色落地（2026-11-12，ADR-0140）**：D3 的第二条「未做」是按角色分样式。两个人在竖屏里来回接话，字幕全白时观众得自己数「谁说的」；加「林：」前缀又会吃掉一行 16 个字里的两个。做法是**只换颜色、不换字体字号**：固定六色亮色板（琥珀 / 天蓝 / 粉 / 绿 / 薰衣草 / 珊瑚），按 `project.characters` 的**顺序**取，不按哈希——一两条片子里只有两三个角色，哈希取模有 1/6 撞色，按顺序六个以内一定不撞，之后轮回。颜色是派生值不进 IR，开关 `SubtitleLayout.speakerColors`（缺省开、`false` 全白、`null` 清覆盖）进 IR；读模型断句时给每条 `EditCue` 带 `speakerColor`，编辑页播放器、预览 HTML 的每条 cue、ASS 行内 `{\c&HBBGGRR&}`、成片 canvas 叠加层四处同源，关掉时四处一起回到白色；旁白 / 没标角色用白色。发布包 `subtitleLayout` 多记 `speakerColors`。成片页「版式微调」多一个「按角色着色」开关，「恢复模板」一并清掉。1198 个测试全过（`speaker-color` 4 条、读模型 / 导出 5 条、IR 事件 1 条）；浏览器实测「把林的 s-03 接进时间线 → 0.5s 周的字幕 `rgb(127,216,255)`、5.8s 林的 `rgb(255,214,102)` → 取消开关同一句变白 → 导出 ASS 两条事件带 `{\c&HFFD87F&}` / `{\c&H66D6FF&}`，预览 HTML 的 `color` 是 `#7FD8FF` / `#FFD666`」。**未做**：逐字动画、自定义色板 / 单角色指定颜色、角色名前缀、按角色换字体。

> **H19 一句话指令收口：规则表先跑，作者点头才让模型读（2026-11-12，ADR-0141）**：H19 剩下的两条里，「补充的删除编辑」本来就已由 chip 上的 × 完成；真正缺的是「对话式理解」。ADR-0039 当年刻意只做七类说法的**查表**，理由是「今天没有文本模型接入，不该假装成自然语言理解」——现在网关里已经有文本模型，同一个输入框却仍只认七句话。做法是**不拆掉确定性的前提下加第二条路**：回车仍然只走 `parseInstruction`；它返回 null 之后，输入框旁才出现「让模型读一遍」，**作者点它才发请求**。`POST /api/instruction` 把「当前镜头快照 + 作者原话」交给默认文本模型（`maxTokens: 600`），返回的补丁过**严格 schema**：只允许景别 / 角度 / 运镜 / 时长（1000–8000）/ 补充（≤60 字），多出来的键整条拒绝，空补丁与越界一律 422「没读出具体要改什么」、不写事件。机位整份带给模型，转回补丁时 `{ ...snapshot.camera, angle, movement }`，只换角度与运镜，焦段与 B13 坐标不被洗掉。等模型时按 shotId 重新取镜头：切镜 / 锁镜 / 只读就不写补丁；按钮置忙防重复点。成功 / 失败都记 `health-events`（空补丁单记 `instruction_noop`）。10 条单测、浏览器实测见 ADR-0141 附记。**未做**：多轮对话、跨镜头批量、规则命中后的模型复核、模型选择。

> **B1 四格过期标记与旧版回退（2026-11-12，ADR-0142）**：三视图是整条片子的一致性锚点，但改完「剪了短发」之后四格还是旧发型，界面不说；单格重出换了模型，四张脸一个画风，也没人说。做法是**只加派生读模型，不加 IR 字段**：`staleSheetCells` 拿每格资产的 `createdAt` 与 `character.updated`（名字 / 外形 / 不许变）比，改动之前出的格子挂小点并写明原因；四格来自两个以上模型时标少数派，各半则四格都标。旧版从事件日志回放：`sheetAssetHistory` 扫 `project.created` 与 `asset.updated`，按 uri 去重、当前版不算，图注下 `历史 n` 展开缩略图带，「用这版」只写一条 `asset.updated`，不重新生成、不花钱；换回来的资产保留原 `createdAt`，所以仍按原时间判过期——这是事实，不被一次点击洗白。定妆锁定时禁用。web 881 条全过（`read-model` 新增 5 条）；浏览器实测「灌两版带图资产 → 正脸出现 `历史 1` → 用这版后 `<img src>` 换成红版、事件 17→18 → 改外形后林四格各挂一个『外形描述』过期点，周不受影响」。**未做**：按人物回收旧图、四格视觉相似度（B14）、整组回退、旧版备注。

> **C12 对白按句归一响度（2026-11-12，ADR-0143）**：整片 loudnorm 只保证全片积分响度，救不了一句轻一句响——配音逐句生成，不同请求、不同音色的句间差拉平之后还在。做法是**混音前逐句量、进总线前逐句拉**：渲染时先对每条对白轨跑一遍 `loudnorm print_format=json` 取 `input_i`，`segmentGainDb` 把每句拉向 −18 LUFS（留 4 dB 给整片 loudnorm），单句夹 ±12 dB、0.1 dB 取整；`null` / 非有限值 / ≤−70 LUFS 的静音段一律不动，不把底噪抬上来。增益插在 `adelay` 之后、`atrim` 之前，0 dB 不插；`LoudnessReport.dialogueGainsDb` 记每句增益，成片页响度块下多一行「对白按句归一：n 句，增益 −8.0 … +12.0 dB（有一句已触 12 dB 上限）」。web 884 条全过（`render-audio` 新增 3 条）；浏览器实测「灌两句不同音量的 WAV → 导出草稿 MP4 → −14.0 LUFS / −11.4 dBTP，响度块写出 2 句增益 −8.0 … +12.0 dB 且点名触顶」。**未做**：自动二次归一、多声道 / 5.1、音效总线、句内压缩 / 限制。

> **B1 四格资产位与占位资产（2026-11-12，ADR-0144）**：新建人物点「生成三视图」只会得到一句「这个角色还没有三视图的资产位，先建四个格子」，而界面上根本没有建格子的入口；故事草稿落项目同样是 `sheet: {}`，从「一键成片」进来的角色全卡死。做法是**把「槽存在」和「槽里有图」拆开**：`sheetSlotsOf` 给四格确定性 id（`a-sheet-<id>-<angle>`，补格子幂等），`sheetSlotAssets` 给四个 `placeholder: true`、无 `uri` 的资产；新建人物先写四条 `asset.updated` 再写 `character.added`（IR 的 `REF_ASSET` 要求这个顺序），共五条事件。`castReadiness` 只数没有占位标记的资产，闸门不会被空格子骗过；`asset.updated` 写进 `uri` 时自动摘掉标记。事件层补 `character.updated { sheet }`（整份替换，校验角度与空串），旧项目第一次点「生成三视图」先补格子再出图，作者换过的 id 原样保留；四格过期 / 模型一致性读模型跳过占位。全仓 1224 条测试全过（IR 事件与 cast、web store 与 read-model 新增）；浏览器实测「灌一个 `sheet: {}` 的旧角色 → 点生成 → 四条占位 + 一条 `character.updated` → 四张图逐一入格、状态『可锁定』、无过期点」。**未做**：删某一格的独立入口、占位资产回收（H3）、悬空 `sheet` id 的脏数据修复。

> **E1 字幕条整句拖动（2026-11-12，ADR-0145）**：按句偏移一直是 `‹ ›` 按钮（100ms / Shift 500ms），对一下口型够用，把一句挪到画面空的地方要按十几下。做法是**在已经按绝对时间画出来的字幕条上直接拖**：像素按轨道宽度线性换算成毫秒（`dragDeltaMs`），10ms 一档，目标值夹 ±30 秒（`clampedDeltaMs`，贴边同向拖增量为 0）；按下只记起点、移动只更新本机预览让字幕跟手，松手才写一条 `dialogue.updated`——一次拖动在日志里只有一条记录。3px 以内仍算点击（跳转并打开手改断句），拖动后的 click 被吞掉；只读时不接管；按钮与 `↺` 保留给几十毫秒的精调与归位。画面轨仍首尾相接不可拖，配音没有自己的条。全仓 1228 条测试全过（`track-drag` 新增 4 条）；浏览器实测「拖第一句 40px → 条上实时跟手 → 松手只多一条 `subtitleOffsetMs: 440`、提示 +440ms、列表写『字幕 +440ms』→ 点一下仍打开手改 → `↺` 写回 `null`」。**未做**：独立多轨（画外音层）、吸附与卡点（C5）、配音轨拖动。

> **D3 按角色点名指定字幕颜色（2026-11-12，ADR-0146）**：按顺序取色对「谁在说」够用，但对连续剧不够——新加一个角色、顺序一变，主角的颜色就换了；作者也没法把反派固定成冷色。做法是**在同一个六色板里点名**，不自定义色板（深色画面里任意颜色都可能读不出来）：`SubtitleLayout.speakerColorOverrides`（角色 id → `#RRGGBB`）只存改过的角色，整份替换、空表与 `null` 等价、事件层统一大写并拒绝非法颜色。读模型先按顺序建色板再套点名，已删除角色的键忽略。界面在「版式微调」里给每个角色六个色块 + 当前色值 +「默认」，「恢复模板」一并清掉；颜色仍落在 `EditCue.speakerColor` 上，播放器、预览 HTML、ASS 与成片叠加层四处同源，发布包记下点名配色。全仓 1233 条测试全过（IR 事件 2 条、读模型 / 导出 1 条、store 2 条）；浏览器实测「给林点 `#FFA6C9` → 事件写入、色块选中 → 跳到林那句，播放器字幕 `rgb(255,166,201)` → 点『默认』写回 `null`，颜色回到色板默认」。**未做**：自定义色板、逐字动画、角色名前缀、按角色换字体。

> **A18 剧本医生第二档：模型改写与「采用」（2026-11-12，ADR-0147）**：第一档只告诉你「钩子偏弱」，字还是得自己改。做法是**一个模式一次调用、作者先点**：抽屉里六个模式按钮，点一个才发 `POST /api/doctor`，带精简剧本快照（场 / 镜 / 动作 / 台词 / 故事层五字段 + 本地提示；动作截 400 字、台词 160 字，不含素材与密钥）。回复过严格 schema：最多 3 条，只能是台词（≤120 字）/ 动作（≤160 字）/ 故事字段（≤400 字）；引用不存在的 id 逐条丢掉，一条不剩按「没读出」422。「采用」走既有的 `editDialogue` / `editAction` / `editStory`，锁镜、时长重估与空文本校验原样保留，一条建议写一条事件；减人物 / 减场景只允许改写，不删实体；建议不进 IR，关抽屉就没了。全仓 1247 条测试全过（`doctor-ai` 9 条、store 5 条）；浏览器实测「点『强化钩子』→ 真模型回 3 条建议（两条台词 + 一条梗概）→ 采用梗概 → 事件 40 → 41，卡片变『已采用』」。**未做**：多轮对话、整批采用、模式间比较、评测集标定。
