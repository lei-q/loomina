# ADR-0026 界面骨架：审片台，不是编辑器

- 状态：已接受
- 日期：2026-11-09
- 决策者：用户 + Claude
- 关联：P22（界面按任务组织）、H17、[UX.md](../UX.md) §5 / §13、[DESIGN-SYSTEM.md](../DESIGN-SYSTEM.md)

## 背景

第一版界面方案采用了行业默认的三栏编辑器解剖：左侧竖向阶段图标轨、中间画布、右侧属性面板，底部胶片轨默认折叠。

三个问题：

1. 它假设用户会"操作面板"，但短剧用户的动作是"看一格 → 说哪里不对 → 再出一版"。
2. 六个阶段被做成竖向导航，用户需要在脑内维护进度；流程本应提供位置感，不该是菜单。
3. 折叠胶片轨，等于把短剧最要紧的东西（整条节奏）藏起来，为了显得简洁而牺牲信息。

配色同样失败：近黑 + 琥珀、近黑 + 青（撞上文档明确否掉的赛博朋克）、米白 + 靛蓝，三套都是 AI 产品截图墙上的常见款。样机用 CSS 渐变假装视频画面，进一步拉低可信度。

## 决策

1. **骨架采用「一屏三带」**：顶带（位置与代价）/ 中台（前一格 · 当前 · 后一格）/ 下带（常驻胶片轨 + 一句话指令 + 留用/重做）。
2. **不设常驻侧栏。** 参数、提示词、参考图走浮层，用完即收。
3. **主案配色为「印片」**：中性炭黑 + 白，无彩色强调色。红（`#E0442E`）与蓝（`#3D6DDB`）只作批注，以 2px 底线出现在胶片格上（留用 / 淘汰）。
4. **保留「前一格 / 当前 / 后一格」并排。** 竖屏在宽屏上必然留白，用暗化的相邻镜头把空白变成上下文。
5. **标志采用「经线」**——片格里三根经线，中间一根是光。即用户说的"被织出来的光"。
6. 配套：影厅白（亮色，仅用于有文字的页面）、钨丝（暖色，后续可选）；中文不配衬线；全站唯一圆角 2px。

## 理由

- **大画面、一条带、一句话**与用户的真实循环同构，与 Runway / Sora / Krea / LTX Studio / 剪映 的可借部分一致：画面最大、整条常驻、入口是一句自然语言。
- **单色 + 白强调**避免了"AI 产品配色"的套路，也让视频画面成为唯一有颜色的东西——这正是产品要卖的东西。
- **红蓝作批注而非强调**，把语义色与品牌色分开，符合 P21 的成本可见性（每个动作都标价）而不牺牲判断效率。
- **并排三格**是这一版最像"审片"的地方，也是唯一让竖屏在横屏上不显空旷的解法。

## 后果

**正面**
- 布局与"判断"这个动作对齐，不再要求用户学面板。
- 主案的色彩负担极低，后续换主题只换变量。
- 标志可从同一几何延伸出图标网格。

**负面**
- 并排三格在窄窗口（<1200px）会挤压当前格，需要响应式降级（先隐藏两侧）。
- 无彩色强调意味着"当前 / 可用"完全依赖白描边与对比度，对亮色主题要求更高。
- 胶片轨常驻占去约 100px 高度，普通笔记本上当前画面会偏小。

**跟进**
- `tokens.css` 落地三套主题变量，组件不写死颜色。
- 先做 `TopBar` / `Stage` / `ReelBar` 三件，再接数据。
- 手机形态只做审批，不给参数。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 三栏编辑器（v1） | 假设用户操作面板；流程变导航；藏起整条片子 |
| 纯时间轴（剪映式） | 密度过高，第一次做短剧的人会被劝退 |
| 纯对话入口（Sora 式） | 只给一句话，参数与代价不可见，无法控成本 |
| 亮色主案（即梦式） | 亮底会把暗场视频压成一块黑 |
