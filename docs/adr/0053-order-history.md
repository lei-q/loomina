# ADR-0053 台词顺序的历史：镜头级改写，镜头级回退

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0047（排序）、ADR-0052（换人历史）、FEATURES A5

## 背景

排序做出来之后（ADR-0047），顺序改过几次、上一版是什么顺序，页面上看不到；ADR-0047 的负面清单里写着「顺序变化不进版本列表」。顺序是镜头级的：一次排序就是一条 `shot.updated { dialogueIds }`，日志里已经有完整的数组。

## 决策

1. **读模型 `dialogueOrderHistory(events, shotId)`**：只收显式带 `dialogueIds` 的 `shot.updated`，按时间排；`{ at, lineIds }`。加句 / 删句走的是 `dialogue.added` / `dialogue.removed`，不算排序改写。
2. **store `setDialogueOrder(shotId, lineIds)`**：把整组顺序写回，一条 `shot.updated { dialogueIds }`。四条拒绝：只读、锁定镜头、顺序与现在一致、这一版里的台词集合与现在对不上（之后删过或加过句子）。
3. **界面**：镜头台词列表下方一行 `这一镜的顺序改过 n 次` 折叠，展开倒序显示 `时间 门开着呢。/ 谁在那儿？` 与`用这版`。用文本而不是 id：看顺序是在看句子。超过 12 字截断。
4. **回退是再写一次**：选一个旧顺序就写一条新的 `shot.updated`；历史只增不减。
5. **对不上的版本不给按**：长度不同（之后删过句子）或集合不同（之后加过句子）时按钮置灰——这种版本恢复不了，不假装能。

## 理由

- **顺序的事实只有一处**：`Shot.dialogueIds` 的数组顺序；历史从日志里读这个数组的每个版本，不再存一份。
- **镜头级而不是句子级**：一句台词的「位置」离开同镜其他句子没有意义；把它挂在镜头下，摘要与回退都自然。
- **文本展示**：用户记的是「谁先说」，不是 id；截断 12 字足够分辨。
- **按钮置灰而不是报错**：版本能不能用，展开时就看得到，不必点了才知道。

## 后果

**正面**
- SH-02 把第一句往下挪一位后，镜头下出现 `这一镜的顺序改过 2 次`；展开是 `20:55 门开着呢。/ 谁在那儿？` 与 `20:32 谁在那儿？/ 门开着呢。`。
- 点较早那版的`用这版`：顺序回到 `谁在那儿？/ 门开着呢。`，摘要变成 3 次；日志多一条 `shot.updated { dialogueIds }`，台词 6 句、全片 35.6s 不动。
- 之后删过句子的旧版本按钮置灰，不会给出一个点了要报错的按钮。
- 测试：web 128 条（新增 4 条：历史过滤、整组写回与回放、四种拒绝）；IR / gateway / pipeline 不变，合计 229。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：headless Chrome 点 SH-02 的 `↓`，展开顺序历史，点旧版`用这版`；IndexedDB 第 30 条为恢复顺序的 `shot.updated`。

**负面**
- **只记顺序改写**：加句 / 删句不在这份历史里；删掉的句子想找回还是得翻日志。
- **没有「谁挪的」与原因**：只有时间与顺序。
- **旧版本可能失效**：之后增删过句子，旧顺序就恢复不了，只能置灰。
- **句子用文本辨认**：同镜里两句文本相同（如都写「嗯。」）时，截断后的顺序看起来一样。
- **面板越攒越多**：一镜反复调顺序，摘要数字会一直涨，没有「合并 / 清理」。

**跟进**
- 把加 / 删句也并进这份镜头级历史（含「恢复被删的那句」）。
- 顺序版本行加 diff（哪句挪了）。
- 与台词级历史合成一条时间线。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 新增 `dialogue.reordered` 事件 | ADR-0047 已经否决过：与 `dialogueIds` 重复，回放有两个事实来源 |
| 记在每句台词的历史里 | 位置是镜头级信息，挂在句子上会分裂成两份，还说不清以谁为准 |
| 排序历史用 id 显示 | 用户认的是句子，不是 `d-s-02-xxxx` |
| 恢复时允许跨版本增删句子 | 会把「改顺序」偷偷变成「加 / 删句」，事件语义与时长都对不上 |
| 只显示、不允许回退 | 看到旧顺序却用不回去，不如不给看 |

## 附记（2026-11-10，ADR-0054）

跨镜头挪台词也写 `shot.updated { dialogueIds }`，落地后它会被数成一次「换顺序」——与本文「加句 / 删句不算排序」的判断打架。读模型随之收紧：**只有句子集合没变、只换了顺序的改写才算一次排序历史**；集合变了（挪进 / 挪出）就跳过，但仍把它记为新的基线，后续排序照常比较。加句 / 删句在不同事件里，也一并推进基线，避免之后第一次真排序被误判成集合变化。测试基线从空白改成「先给这一镜挂两句」，否则第一次写入在语义上就是加句而非排序。
