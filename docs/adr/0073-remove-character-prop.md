# ADR-0073 删除人物与道具

- 状态：已接受
- 日期：2026-11-11
- 决策者：用户 + Claude
- 关联：ADR-0071（人物库）、ADR-0072（道具库）、ADR-0061 / ADR-0062（地点删除与搬移）、ADR-0070（这一镜里换人）、ADR-0030（道具引用即必锁）、FEATURES B1 / B8

## 背景

人物库（ADR-0071）与道具库（ADR-0072）都能新建了，但**不能删**：试建的人物、写错名字的道具只能永远留着。示例项目里已经攒下了"阿棠""旧铜钥匙"这类试验对象。地点早就有删除（ADR-0061），还有"搬过去再删"的搬移规则（ADR-0062），人物与道具缺的就是这最后一步。

麻烦在于引用：人物被 `shot.characterIds` 与 `dialogue.characterId` 点着，道具被 `shot.propIds` 点着。地点可以"整批搬到另一个地点"，人物与道具没有对等物——一个镜头里换人（ADR-0070）要连台词一起换，批量搬会悄悄改掉别人的镜头。

## 决策

1. **两个事件**，只做"摘掉"：
   - `character.removed { at, characterId }`
   - `prop.removed { at, propId }`
2. **先检查引用，有引用就拒绝**（`applyEvent` 与 store 双重拒绝）：
   - 人物还在 `shot.characterIds` 里 → 拒绝，报「还有 N 镜点着这个人」；
   - 人物还有台词（`dialogue.characterId`）→ 拒绝，报「还有 N 句台词属于这个人」；
   - 道具还在 `shot.propIds` 里 → 拒绝，报「还有 N 镜用着这件道具」。
3. **不做批量搬移**：地点删除时有"整批换到另一个地点"，人物与道具不给对等的搬移。理由是换人还要连台词一起换（ADR-0070 已经给了逐镜换人的入口），批量换人没有安全的默认值。用户先自己把镜头清干净，删除才放行。
4. **store 拒绝文案对齐界面动作**：
   - 人物：`「X」还在 N 镜的出场里：先去分镜页把他点掉（有台词的要先换人）。` / `「X」还有 N 句台词：先删掉或换人。`
   - 道具：`「X」还在 N 镜里：先去分镜页把它点掉，再删。`
5. **界面**：人物名旁、道具名旁各一个 `删`（与地点、场次、镜头同一个形状）：点了变成 `删这个人？/ 删这件道具？` + `确认删` / `取消`。**删不掉时确认块也收起**，原因写在页头——停在原地只会让几个确认框叠在一起，而原因不在那一行能修。只读标签页不显示 `删`。
6. **资产不回收**：三视图、主镜、参考图按资产 id 挂在别的表里，删人不删图（与地点删除一致，ADR-0061）。目前没有取消删除，资产也就没有回收路径——留作后续。

## 理由

- **拒绝而不是清引用**：删除要显式。悄悄把一个人从 5 个镜头里拿掉，等于替用户改了 5 个镜头。
- **双重拒绝**：`applyEvent` 是重放的安全网（旧的日志、外部导入的事件也得守规矩）；store 是给人看的那一层，负责说"先去哪儿做什么"。
- **不批量搬移**：人物的搬移语义比地点复杂（台词、出场顺序、已出的帧），一刀切会埋下"谁把周换成了林"的疑问。逐镜换人（ADR-0070）已经够用。
- **确认块在失败时收起**：拒绝原因在页头（和新建 / 改名的错误同一个位置），确认块留着会让人误以为"再点一次就行"。

## 后果

**正面**
- 定妆页点 `删` → `确认删`：「阿棠」整行消失，进度与必锁数跟着变，日志一条 `character.removed`。
- 「旧铜钥匙」没有镜头用着 → 删得掉；「台灯」还在 SH-01 里 → 删不掉，页头写「「台灯」还在 1 镜里：先去分镜页把它点掉，再删。」
- 「林」在 SH-01 出场 → 删不掉，页头写「「林」还在 1 镜的出场里：先去分镜页把他点掉（有台词的要先换人）。」
- 测试：IR 91（新增 3：删无引用人物、被镜头 / 台词挡住、删道具与被使用挡住）、web 189（新增 3）；gateway 17、pipeline 22；合计 319。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：定妆页删「阿棠」与「旧铜钥匙」→ 两行消失；把「林」「台灯」放进 SH-01 后再删 → 都被拒，页头给出下一步；新建「试删人物」再删 → 行消失、无报错。

**负面**
- **删错就没了**：没有撤销，也没进回收站。
- **资产成孤儿**：被删人物的三视图 / 被删道具的参考图留在资产表里，没有入口再看到，也不回收。
- **要手动清引用**：先逐镜点掉出场、逐句换人或删台词，才能删人——比地点删除（一步搬完）多几步。
- **不能删"有台词但不在镜头里"的人物**：哪怕是数据不一致的残留，也得先把台词清掉。
- **旧日志兼容**：`character.removed` / `prop.removed` 之后的事件如果又引用它，重放会报错；目前没有产生这种日志的入口。

**跟进**
- 删除的撤销（软删除 / 回收站）与孤儿资产回收。
- 删除前把引用列出来（"这 3 镜、2 句台词"），点了直接跳过去。
- 人物 / 道具的批量搬移（若逐镜换人不够用再说）。
- 地点删除的资产回收，一并考虑。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 删除时把引用一并清掉 | 悄悄改掉别人的镜头，违背"删除要显式" |
| 像地点那样"搬过去再删" | 人物搬移要连台词、出场顺序一起改，没有安全的默认目标；逐镜换人（ADR-0070）已够用 |
| 软删除（`archived` 标记，列表里藏起来） | 读侧、提示词、必锁统计都要跟着认这个标记；先把"真删"做对，撤销单开一刀 |
| 只删没被引用的对象，被引用时只显示提示不显示 `删` | 用户看不出"为什么这个不能删"；按钮 + 拒绝原因更直白 |
| 删除同时回收该对象的资产 | 资产回收要先想清楚引用（同一张图可能被别处引用），单开一刀 |
