# ADR-0207：镜头模板（F3 第二档）

- 状态：已采纳
- 日期：2026-11-14
- 决策者：用户 + Claude
- 关联：F3、I1、I2、I4、I7、ADR-0168、ADR-0180

## 背景

F3 第一档（ADR-0180）只做「班底模板」：人物 / 地点 / 道具 / 风格 / 画幅 / 品牌包。
收口时留下三个缺口：**镜头模板**、模板编辑与改名、模板导出 / 同步。

镜头模板真正要复用的是「一套摄影做法」：景别 + 机位角度 + 运镜 + 焦段，
外加可选的光影与构图模板（I2 / I4）。作者在某一集里调出一镜好看的
「低机位推近 + 逆光剪影 + 对角线」，下一集想再来一次，现在只能对着参数一项项抄。

镜头语言库（I1）有十四套固定说法，但那是**公共库**，不是作者自己的；
而且不含光影与构图。

## 决定

1. **`apps/web/lib/shot-template.ts` 定义 `ShotTemplate`**
   - `format: "loomina.shot-template"`，`version: 1`：与班底模板共用 `templates` 仓，
     靠 `format` 区分，不新增 IndexedDB 仓、不升 `DB_VERSION`；
   - 字段：`id / name / createdAt / from`（从哪个项目的哪一镜存下来的）、
     `shotSize / angle / movement / focalMm`、可选 `lighting / composition`。
   - **不含**：动作、台词、时长、出场人物 / 道具、关键帧、take——
     那些是这一镜的内容，不是摄影做法。
2. **两条来源**
   - 分镜页「语言 ·」抽屉里「把这一镜存成模板」：抓当前四参数 + 已有光影 / 构图；
   - 设置页「镜头模板」区也能从当前项目里挑一镜存。
3. **套用 = 一条 `shot.updated`**
   - `shotTemplatePatch(template)` 只产出 `shotSize / camera / lighting / composition`；
     锁定的镜头拒绝（与其它镜头改动同一口径）。
   - 套模板不动动作、台词、时长、出场人物与道具——它只换摄影做法。
4. **`template-store.ts` 扩两个函数**
   - `listShotTemplates()` / `removeShotTemplate(id)`：只认 `format === "loomina.shot-template"`，
     与班底模板互不干扰；
   - 读回来的数据要过 `looksLikeShotTemplate`，坏数据跳过而不是让界面崩。
5. **导出**：设置页「导出镜头模板」给一个 JSON 文件（下载），
   **不做导入与同步**：没有云端，导入要先设计冲突与 id 覆盖规则。
6. **编辑与改名**：这一档只支持「删了重存」。改名要引入模板元数据的写回路径，
   与「模板不进事件日志」的口径纠缠（改了没留痕），留到需要时另开 ADR。

## 理由

- **模板与内容分开**：镜头模板的价值就是「换一套拍法、内容不动」；
  把动作台词一起带走会变成「复制一镜」，那不是模板。
- **共用模板仓**：班底与镜头模板都是「这台机器上我攒下的东西」，
  同一处存储、同一套列表模式，作者不用记两份。
- **导出但不导入**：导出是只读备份，风险为零；导入会覆盖同名模板，
  得先定「同名怎么办、id 冲突怎么办」，本档不猜。

## 后果

**正面**

- 一套调好的摄影做法能跨集、跨项目复用，一条事件写回四项参数。
- 不新增 IR 字段、事件类型、日志版本或 IndexedDB 仓。
- 与 I1 的公共镜头语言互补：公共库给起点，作者自己的模板给手感。

**负面 / 代价**

- 模板只是参数快照：套用后改了镜头，模板不会跟着变（要再存一次）。
- 不支持改名、不支持在设置页直接编辑参数，只能删了重存。
- 导出是单向的：换机器后要自己比对，不能导入。
- 同一套参数可以在库里存很多份（不去重）。
- 模板不带「为什么这么拍」的说明字段，作者靠名字记。
