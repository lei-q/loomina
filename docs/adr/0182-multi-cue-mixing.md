# ADR-0182：多条配乐 cue 混排（C4）

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：C4、C10、C12、C5、ADR-0099、ADR-0125、ADR-0143

## 背景

C4 一直写着「多条 cue 混排」没做。数据层其实早就允许多条：`Timeline.music` 是数组，
`timeline.music.updated` 整条替换，渲染清单最多 4 条，混音器也按数组混。
缺的是**作者能不能操作**：

- 成片页只在「一条都没有」时显示导入表单；有了一条之后，表单消失，
  再加第二段没有入口；
- 每条 cue 只能调增益 / ducking / 情绪 / 作用，**起点与长度不可改**，
  加进来永远是「从 0 铺到片尾」；
- 「试听」永远播第一条。

于是「混排」在数据里成立，在界面上不成立。

## 决定

1. **一段配乐 = 一个时间段，可以各占一段，也可以叠在同一段上**
   - 不禁止重叠：两条 cue 叠在一起就是两层声音（铺底 + 重音），
     这是混排的常见用法，不是错误。
   - 起点必须落在成片之内（`0 ≤ startMs < timelineEnd`）；长度 ≥ 500ms。
     起点在片尾之后依然拒收——它不会发出声音，只会让「这条 cue 到底响没响」
     变成一个查不出来的问题。

2. **加一段时可以直接给起点**
   - `addMusic` 新增可选 `startMs` / `spanMs`；不给就是旧行为（从 0 铺到片尾）。
   - 表单在有 cue 之后仍然显示，按钮文案变成「再加一段」。
   - 仍然最多 4 段：这是渲染清单的上限，不是随便定的数字；到上限时表单换成一句说明。

3. **起点与长度可以事后改**
   - `updateMusic` 的 patch 增加 `startMs` / `durationMs`；仍是整条
     `timeline.music.updated`，一次改动一条事件。
   - 改起点**不自动改长度**：作者给的是「这一段多长」，不是「到片尾为止」。
     想铺到片尾就把长度也改掉。
   - 起点越界不夹到边界：输入框自己跳回去比一句「在成片之外」更难懂。

4. **试听跟着那一段走**
   试听按钮从固定播 `view.music[0]` 改成播被点的那一条；音量仍按这一条的
   `gainDb`，与导出时的基准增益一致。

5. **界面顺序：列表在前、加段在后**
   已有的段落每张卡显示编号、起点、长度、增益、ducking、情绪、试听、移除；
   下面才是「再加一段」。这样「我有哪些段」先于「我再加一段」。

## 理由

- **IR 不用动**：`MusicCue.startMs / durationMs` 从 ADR-0099 起就在，校验也早就写了。
  这次补的是操作面，不是模型。
- **重叠合法**：混音是叠加，不是排他；用「时间段不能重叠」去约束会禁掉
  铺底 + 重音这种最正常的写法。
- **上限留在 4**：渲染清单与混音命令都是按这个数写的；放宽要同时改清单校验、
  混音滤镜与界面，等真有需要再一起改。

## 后果

**正面**

- 一条片子可以「前半段紧张铺底、后半段换一首、结尾叠一记重音」，
  全部在成片页完成，不用改代码。
- 每条 cue 的起点 / 长度可见可改，混排结果不再只能靠耳朵猜。
- 仍然只写一种事件，撤销 / 回滚 / 历史文案都不用新增。

**负面 / 代价**

- 叠在同一段时间上的多条 cue 仍按各自的增益相加，没有总线压缩；
  叠太多会削波，最终由 C12 的 loudnorm 兜底，但素材本身的失真救不回来。
- 改起点不会连带缩长度，作者可能得到「超出片尾」的段；
  导出时按片尾截断，界面上不额外警告。
- 4 段上限对复杂配乐仍然偏少；要更多得先改渲染清单。

## 不做

- 拖拽时间条改起点（数字输入已经够用；拖动要先做时间线的通用交互）。
- cue 之间的自动避让 / 自动交叉淡化（属于 C5 节拍卡点与混音自动化）。
- 每段独立的淡入淡出（现在只有整体增益与 ducking）。
- 音乐生成与自动选段（供应商能力，C10 已明确不做自动选段）。
