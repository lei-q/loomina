# ADR-0031 定妆照的服务端出图：浏览器不碰密钥

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0008（模型网关）、ADR-0028（资产层与定妆闸门）、ADR-0029（锚点）、B1、[MODEL-GATEWAY.md](../MODEL-GATEWAY.md) 第九节

## 背景

图片接口 2026-11-10 复测已能出图（`POST /v1/images/generations` 对 `gpt-image-2` / `-c` / `gemini-2.5-flash-image` 都返回 200）。但前端的定妆台只有剪影占位，"去生成三视图"一直没有接上，原因不只是接口：

1. **密钥只在服务端。** `API_KEY` 不能进浏览器 bundle，而当前应用是静态站 + 浏览器里的 Zustand。
2. **生成是 20–45 秒的同步调用。** 四格要两分钟，界面必须如实显示"哪一格在生成"，不能做假进度。
3. **生成结果要有落点。** 资产已存在 IR 里（`Character.sheet` 四个槽位指向 `Asset.id`），但占位资产没有 `uri`，也没有任何事件能改资产。

## 决策

1. **新增服务端路由 `POST /api/sheet`**（`apps/web/app/api/sheet/route.ts`，Node 运行时）：接收 `{ character: { name, appearance, mustNotChange }, angle }`，在服务端读 `secrity.env`、调用 `TreecloudImageAdapter`，返回 `{ uri, model, prompt }`。
2. **密钥只出现在服务端进程内存。** 浏览器拿到的是一张图的 `data:image/png;base64,...`；`lib/generate-image.ts` 只在 Node 侧被 import，路由声明 `runtime = "nodejs"`、`maxDuration = 180`。
3. **提示词在服务端编译**：`buildSheetPrompt(character, angle)` 放进 `packages/pipeline`，与镜头提示词共用"人物 + 不许变"的固定串，避免两处描述漂移。产品文案不在客户端拼接。
4. **一次请求只出一格。** 客户端按正面 → 3/4 → 侧面 → 背面顺序逐格请求，每落一张写一条 `asset.updated`（新增事件类型，按 id upsert），界面把当前格标成"生成中"。
5. **锁定即冻结**：角色有已通过的 `Approval` 时，store 直接拒绝生成（不请求、不写事件），要重做先解锁（准则 P14）。
6. **没有持久化**。生成结果进内存里的项目与事件日志，刷新即回到示例项目；持久化与对象存储留到后面。
7. **不接参考图**。接口不收参考图（MODEL-GATEWAY 第九节），生成只靠提示词；四格之间的一致性还不保证。

## 理由

- **服务端路由是最小可行的密钥边界。** 换成"浏览器直连中转站"要把密钥发到客户端；换成"队列 + 轮询"要为一次性功能先建基础设施。一个 route handler 两头都不欠。
- **一格一请求**让失败只损失一格：第二格 429 时，第一格已经落库，重试从第二格继续；界面也能诚实显示进度。
- **`asset.updated` 而不是新表**：占位资产本来就有 id，生成只是补像素；换 id 会让 `Character.sheet` 与锁定记录全部失效。
- **锁定禁止重生成**是 ADR-0028 的延续：锁定是一份快照，覆盖它等于让下游引用的东西悄悄变了。

## 后果

**正面**
- 定妆台第一次能出真图：点"生成三视图"，四格依次出现，用时约 100 秒（实测四格 25s 左右一张）。
- 资产带 `provenance`（模型、提示词、时间），来源可查；示例项目不用改结构就能接。
- 路由与提示词都有单元测试（store 的三条：逐格写事件、锁定不生成、失败即停），浏览器实测一遍走通。
- 密钥约束没有松动：客户端只见到 data URI。

**负面**
- **四格不是同一个人。** 没有参考图，每格是独立采样；实测正面与 3/4、侧面、背面的脸明显不同。定妆闸门现在放行的是"四格都填了"，不是"像同一个人"（ADR-0028 已写）。
- 刷新即丢。没有持久化，生成结果只活在当前标签页；关掉重来要再花一次钱。
- 每张图约 2.4MB 的 data URI 进内存，四格一个角色约 10MB；角色一多会顶到内存与渲染的边界，迟早要换成对象存储 + URL。
- 费用没有进项目账本：`spent` 只统计 take，出图的钱目前不可见（H12 的下一步）。
- 同步请求占着连接两分钟，没有取消按钮；用户离开页面时请求仍在跑。

**跟进**
- 拿真实账单确认单价后，把出图成本记进 `CostLedger`，顶栏的"已花"才算全。
- 用对象存储换掉 data URI，并给生成加取消 / 重试。
- 有能收参考图的接口后，四格改为"第一格 + 参考图派生其余三格"，再把 intra-sheet 一致性检查接进闸门。
- 场景主镜、道具参考图复用同一条路由（提示词换成 `buildMasterPrompt` / `buildPropPrompt`）。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 浏览器直连中转站 | 密钥会进 bundle，违反"密钥只在服务端" |
| 先建任务队列再生成 | 为一次性功能引入基础设施；同步 + 一格一请求足够验证 |
| 一次请求出四格 | 中途失败损失全部；进度也只能显示"四格一起转圈" |
| 生成结果直接改 `Character.sheet` | 槽位 id 会变，锁定记录与既有引用全部失效 |
| 客户端拼提示词 | 描述与 pipeline 的镜头提示词漂移；产品文案不该散在组件里 |
| 生成后自动锁定 | 四格还不同人，自动锁死会把错误固化；锁定保留给人 |
