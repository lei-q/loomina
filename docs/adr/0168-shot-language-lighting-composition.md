# ADR-0168：镜头语言库、光影模板与构图模板（I1 + I2 + I4）

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：I1、I2、I4、I5、B7、B16、B17、准则 P3 / P4 / P15

## 背景

到这一刻，一镜的摄影信息分在两处：

| 字段 | 有什么 | 谁在用 |
| --- | --- | --- |
| `Shot.shotSize` / `Shot.camera` | 景别、机位角度、运镜、焦段 | 提示词里那一行技术参数 |
| `Project.look` | 光比、色温、质感、补充句 | 提示词最后一句 |

四个字段各是一个下拉，作者想拍「过肩」，得自己在心里翻译成
「中景 + 平视 + 固定 + 50mm」；想把这一镜改成台灯下的桌面戏，
没有地方写「光从哪来」——只能塞进 `description` 或 `promptNotes`，
那两处是给人读的叙事文字，混进技术意图之后就都读不清了。

构图也一样：三分、居中、框中框这些是短剧里反复出现的摆法，
现在完全没有字段，只能靠模型自己发挥。

## 决定

1. **I1：镜头语言库是一张表，不是新的 IR 字段**
   - `packages/pipeline/src/language.ts`：`SHOT_LANGUAGES`（十四套）分五组
     （建立 / 对话 / 反应 / 细节 / 氛围），每套 = 景别 + 机位 + 运镜 + 焦段
     + 一句用途说明。
   - 套用 = `shotLanguagePatch(language, current)` 生成补丁，写一条
     `shot.updated`，改的是**四个已经存在的字段**。库本身不进 IR。
   - 机位坐标（B13 的 `camera.placement`）从现值原样带过来：那是几何事实，
     换一套说法不该把已经摆好的机位抹掉。
   - `matchShotLanguage(shot)` 四个字段全对上才算「正好是这套」；
     不在库里时界面如实写「作者自己拼的一组」，不硬套一个最近的。

2. **I2：光影是 `Shot.lighting`，与 `Project.look` 分工**
   ```ts
   LightingSchema = { source, position, mood, note }
   ```
   - `source`：窗 / 台灯 / 顶灯 / 实用光源 / 月光（五选一）；
   - `position`：正面 / 侧面 / 逆光 / 顶光 / 底光；
   - `mood`：平（不塑形）/ 立体（明暗过渡）/ 剪影；
   - `note` ≤60 字。
   - **分工**：`Project.look` 说「这条片子偏冷、硬光」——整条片子的调子；
     `Shot.lighting` 说「这一镜的光从窗外来」——这一镜的光源。
     两个旋钮各管一件事，提示词里各写一句，不会互相覆盖。
   - 可选字段：没写就不带这一句，提示词与旧口径逐字一致。
   - 七套模板（窗光侧打 / 窗光逆光 / 台灯局部光 / 顶灯平光 / 实用光源 /
     月光冷调 / 底光）只是界面上的快捷入口，写进 IR 的是那四个字段。

3. **I4：构图是 `Shot.composition`**
   ```ts
   CompositionSchema = { rule, note }
   ```
   - `rule`：三分 / 居中 / 引导线 / 框中框 / 对角线 / 留白（六选一）；
   - `note` ≤60 字。
   - 六套模板同样只是快捷入口。构图只写意图，不写坐标——数值化的
     主体位置留给以后的版本，现在写了也校验不了。

4. **两条编译函数，位置固定**
   - `compileLighting(lighting)` → `光线：窗外自然光，侧光，明暗过渡清晰[，note]`
   - `compileComposition(composition)` → `构图：三分构图，主体偏一侧[，note]`
   - 两句都排在 `shotParts` 的**镜头参数之前**：先说怎么打光、怎么摆，
     再说用多大的镜头。没写就不 push，顺序不影响旧提示词。
   - 编译是纯函数，结果不进 IR；服务端用 `LightingSchema` / `CompositionSchema`
     解析，不合法就当没带（与 `parseLook` 同一策略：参数错不拦整张图）。

5. **事件与校验**
   - 三项都走已有的 `shot.updated`：`{ shotId, patch }`，`patch` 里
     `shotSize` / `camera` / `lighting` / `composition` 任意组合。
   - `applyEvent` 对 `lighting` / `composition` 用 schema 校验后才落库；
     `camera` 带 `placement` 时仍走 B13 的几何校验。
   - 清空写 `{ lighting: undefined }`——与 `setShotPerformance` 同一写法
     （属性值为 `undefined` 在 JSON 序列化时消失，回放就是「没写」）。

6. **界面：分镜页顶栏「语言」抽屉**
   - 上半：当前镜现在的四个参数 + 「正好是『X』」/「不在库里」，
     以及已经写上的光影 / 构图那两句（作者能当场看到会送出去的话）。
   - 中段：十四套说法按五组列出，每套右侧用小字标出四个参数。
   - 下段：光影七套、构图六套，各带「不指定」清空按钮。
   - 底部：全部镜头号，点一下就换到那一镜（不用关抽屉）。
   - 顶栏按钮上的点：当前镜**既对上了库里的说法、又写了光影与构图**时消失。

## 理由

- **库不进 IR**：一张表能改、能加、能删，写进项目就变成需要迁移的历史。
  真正决定画面的是那四个字段，库只是把它们拼成作者看得懂的说法。
- **坐标要保留**：B13 的 `camera.placement` 是走位里摆好的几何事实。
  换一套说法把坐标抹掉，等于让作者白摆一次位。
- **光影与风格分开**：风格是整条片子的调子，光影是这一镜的光源。
  合成一个旋钮就得二选一——要么整条片子都变成台灯戏，要么这一镜没法单独改。
- **构图只写意图**：现在没有能校验的坐标系统，写数值只会变成摆设。
  「框中框」这种说法模型听得懂，也验得了（有 / 没有）。
- **默认不带**：三项都可选，没写就一个字不加。旧项目重算的提示词逐字不变，
  已出图的溯源仍然对得上。

## 后果

**正面**

- 作者不用再在心里把「过肩」翻译成四个参数；一次点击。
- 光影第一次有地方写：桌面戏、窗外光、月光不再是 `description` 里的一句形容词。
- 构图第一次成为可选的显式意图，而不是全靠模型发挥。
- 全部纯函数 + 一条既有事件：不新增事件类型，不调模型，不花钱。

**负面 / 代价**

- 十四套说法是经验值，没有评测；可能不够覆盖某些戏（如打斗、追车）。
- 光影模板与 `Project.look` 的边界需要作者理解：风格偏冷 + 光影「月光冷调」
  是叠加的，不是覆盖。
- 构图只到「说法」这一层，没有具体的九宫格位置与占比。
- 清空光影 / 构图会各写一条事件（与清空表演设计一致），历史会多几条。

**不做**

- 自定义说法存进项目（库是代码里的表）。
- 按场批量套用一套说法 / 一套光。
- 灯位图与主辅光比例。
- 构图坐标的数值化与九宫格叠加显示。
- LUT 与胶片质感（I3）。
- 荷兰角等非常规机位（`CameraSchema` 里没有这个角度）。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 把「说法」存成新的 IR 字段（`Shot.languageId`） | 又多一处要维护的一致性问题；四个字段才是事实 |
| 套说法时把机位坐标一起重置 | 那是作者在走位里摆好的几何事实，抹掉等于白摆 |
| 把光影并进 `Project.look` | 风格是整条片子的，光影是这一镜的；合并就得二选一 |
| 光影只写进 `promptNotes` | 那是给人读的叙事文字，混进技术意图之后都读不清 |
| 构图给坐标（主体 x/y 与占比） | 现在没有能校验的坐标系统，写了也验不了 |
| 把编译结果存进 IR | 要配失效机制，而重算是毫秒级的事 |
| 默认给每镜一套说法 / 一套光 | 会改变所有旧项目的提示词，已出图的溯源对不上 |
