# ADR-0246：I9 评测素材库存人工标注，不存规则输出

- 状态：已采纳
- 日期：2026-11-15
- 决策者：用户 + Claude
- 关联：I9、I8、A13、DIRECTOR-GRAMMAR.md 第十一节

## 背景

I9 的第一、二档已经做完：28 条正反例覆盖 14 条规则，`pnpm eval:rules` 全绿。
但 DIRECTOR-GRAMMAR §十一 要的是 **30 个真实短剧片段**——用来标定阈值
（「同景别连续 ≤ 2」到底该是 2 还是 3），并核对规则在真实片子上会不会误报。
正反例只能证明「判定方向没写反」，证明不了这个。

## 决策

### 1. 素材格式：一段一个文件

```json
{
  "meta": { "id": "clip-a01", "source": "…", "license": "self-made", "genre": "…", "platform": "…" },
  "project": { "…": "整份 IR（ProjectSchema 校验）" },
  "expected": ["V6", "V13"]
}
```

- `meta.license` **必填**：没有授权的素材不进库（与 H7 授权登记同一口径）；
- `meta.id` 必须等于文件名：读素材时对不上就报错，避免「文件叫 a01、内容是 a02」；
- `project` 存**整份 IR**，不存截图、不存规则输出；
- `expected` 是人工标注：人看过这段，认为**确实该报**的规则编号（V1–V14）。

### 2. 跑分口径

`runCorpus` 每段跑一次 `analyzeStoryboard`，把命中的规则（去重）与人工标注比对：

| 指标 | 定义 |
| --- | --- |
| 违规率 | 规则命中总数 ÷ 镜头总数 × 100（与 rule-eval 同口径） |
| 景别熵 | 复用 `shotSizeEntropy` |
| 精确率 / 召回率 | 规则报了且人认为该报 / 规则报的；规则报了且人认为该报 / 人标注的 |

素材不足 30 段只报缺口，**不失败**；文件读不出来或格式不对才退出码 1。

命令行：`pnpm eval:corpus`（默认读 `apps/web/scripts/evals/corpus`，`--dir` 可换）。

## 理由

- **存人工标注而不是规则输出**：规则一改就得重跑，存输出等于把旧结论焊死在素材里，
  而且改规则后没法复核「新规则是不是更准」。
- **存整份 IR 而不是截图**：规则读的是结构字段（景别、机位、节拍、走位），
  截图里没有这些；IR 还能让 `analyzeStoryboard` 原样重跑。
- **精确率 / 召回率一起报**：只报「命中几次」看不出规则是太吵还是太哑；
  两个数放在一起，误报（规则吵）与漏报（规则哑）才分得清。
- **缺素材不失败**：30 段是长期活，挂进 CI 会让「还没收集完」变成红灯。

## 后果

**正面**

- 阈值标定有了入口：素材到位后直接跑，分布与误报清单从同一份数据出。
- 素材与规则解耦：换规则不用重标，换标注也能立刻重跑。

**负面**

- 标注是人工成本，一段素材要人看一遍并标规则。
- 30 段素材需要授权（自制或授权素材），这是外部依赖。

**跟进**

- 素材到位前，`I9` 保持「部分落地」，不标完成。
- 阈值具体怎么选（取分位数还是取人判）等第一批 5 段素材进来再定。

## 替代方案

1. **只存截图 + 人工打分**：最省事，但规则改了没法重跑，也无法解释「为什么这条该报」。
2. **存规则输出**：跑分最快，但规则一改就全部过期，且会把误报固化成「正确答案」。
3. **只做正反例、不做真实素材**：现在就是这个状态——阈值永远只能拍脑袋。

## 落地与第一次跑分（2026-11-15）

素材 5 / 30：用示例项目「夜班」的 5 个场次各切一段（`license: self-made`，
注明「不是真实短剧，只验链路」），人工逐段标注后跑分：

```
违规率 216.67 / 100 镜；景别熵 1.555 bit；精确率 71%，召回率 100%（误报 4，漏报 0）
```

**误报全部是摘录造成的**：V1（场首无建立镜头）2 次、V2（画外音）1 次、V7（切率）1 次。
从完整戏里切出来的片段天然缺建立镜头、允许画外音、切率基准也不同——
这不是规则错了，是**素材口径错了**。

由此定下两条口径：

1. 素材按**完整场次或单集**收，不切摘录；
2. 若必须收摘录，先给规则加「摘录模式」（关 V1 / V2 / V7），单独一个决策再做。

另外，第一轮标注也确认了：V5 / V10 在示例项目上全命中是**真缺口**
（节拍目的与表演设计确实没写），标成 `expected` 而不是误报。
