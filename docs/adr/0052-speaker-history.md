# ADR-0052 台词历史里记换人：换人也是一件发生过的事

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0044（台词版本）、ADR-0046（换人）、FEATURES A5

## 背景

台词下的「改过 n 次」只数文本改写。换过说话人，面板一无所知——ADR-0046 的负面清单里写着「版本列表不记录换人」，句子从周换成林、又换回周，页面上看不出发生过什么。换人事件本来就带 `lineId`，日志里一直有。

## 决策

1. **`DialogueHistory` 增加 `speakers: SpeakerRevision[]`**（`{ at, from, to }`，角色 id），从旧到新一条换人一条记录；`dialogueHistory` 从 `project.created` 快照里的 `characterId` 起算，遇到 `dialogue.speaker.updated` 就推一条并更新当前说话人。
2. **`original` 带上 `characterId`**：最初那版的说话人也是历史的一部分。
3. **有换人、没有改写也要展开**：面板的显示条件是「改写或换人至少有一件」；摘要写 `改过 n 次 · 换过 m 次人`，两部分各自独立计数。
4. **换人区单独一段**：文本版本之后、`最初`之前，一个小标题`换人`，倒序排列，每行 `时间 周 → 林`，配一个`换回`按钮。
5. **回退换人 = 再换一次**：`revertSpeaker` 调既有的 `changeSpeaker(line.id, from)`，写一条新的 `dialogue.speaker.updated`；锁定镜头、只读标签页、已经是 current 的那一行都不给按钮。

## 理由

- **换人是结构信息**：文本版本回答「说了什么」，换人回答「谁说的」；混成一个计数器会让「改过几次」说不清。
- **事件已经够用**：`from` 不存事件里，但从快照起逐条推一遍就能得到；不新增字段。
- **换回走同一条事件**：换人不是「撤销」，语义上就是再换一次；历史只增不减，与文本回退一致。
- **和文本版本共用面板**：一句台词的变化都在同一个折叠里，不用去两处找。

## 后果

**正面**
- SH-01 的摘要从 `改过 3 次` 变成 `改过 3 次 · 换过 1 次人`；展开后文本版本三行、`换人`一段 `20:30 周 → 林`，以及`最初`。
- 点`换回`：说话人回到周，摘要变成 `换过 2 次人`，多出一行 `20:51 林 → 周`；日志多一条 `dialogue.speaker.updated`，文本 2.6s、镜头 3.1s、全片 35.6s 都不动。
- 只有换人、没有改写的台词也能展开历史。
- 测试：web 124 条（新增 2 条：换人序列与最初说话人、别的台词不计入）；IR / gateway / pipeline 不变，合计 225。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：headless Chrome 展开历史、点`换回`；IndexedDB 第 28 条为 `dialogue.speaker.updated { lineId: "d-01", characterId: "c-zhou" }`。

**负面**
- **两套时间线并排**：文本版本和换人各排一列，先后关系只能看时间，不是严格的混排。
- **只记换人**：加句、删句、排序仍不进这一句的历史（加删句没有可回退的「那一句」，排序是镜头级的）。
- **换回不看台词内容**：不知道换人当时说了什么，只能看到谁换成了谁。
- **没有作者与备注**：谁换的、为什么换，日志里没有。
- **从未换过人的台词没有「换人」段**：面板结构和以前一样，换人记录只在发生过时出现。

**跟进**
- 排序（`shot.updated { dialogueIds }`）的变更记录，放在镜头级。
- 加 / 删句的历史（删除的句子可从事件里恢复）。
- 换人时备注原因。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 把换人算进「改过 n 次」 | 两种事实混成一个数，回看时说不出改的是文本还是人 |
| 在事件里存 `from` | 从快照逐条推得出来，多存一份反而可能不一致 |
| 换人另开一个面板 | 同一句台词的变化分散到两处，用户要多点一次 |
| 换回时直接改 `characterId` 覆盖 | 会抹掉事件历史，回放与计数都对不上 |
| 按角色批量换人的历史 | 这一刀只做单句；批量的历史等批量换人做出来再说 |
