# ADR-0040 提示词看得见：说了什么，送出去的就是什么

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0037 / ADR-0038（关键帧）、ADR-0039（一句话指令）、ADR-0032（服务端拼提示词）、H17

## 背景

一句话指令接上之后，界面上只有两个可见的变化：镜号那一行的"特写 · 仰拍"，和锚点上方的「补充」行。**真正送给出图模型的那段话，用户一次也没见过。**

这留下三个说不清的问题：

- 点「生成首帧 ¥0.12」时，我到底在让它画什么？
- 说了一句"太暗了"，它有没有进提示词、进成了什么字？
- 首帧和尾帧的提示词差别在哪——只有"起势 / 收势"一句吗？

提示词由 pipeline 拼（ADR-0032），服务端只收业务字段，所以浏览器这边完全拿得到同一段文字——不需要新接口。

## 决策

1. **提示词进读模型**：`StageShot.prompts = { first, last }`，由 `shotMaterial` + `buildKeyframePrompt` 现算，和真正发请求时用的是同一套函数、同一份原料。
2. **界面上一块折叠区**：「这一镜会送出的提示词」，默认收起，点开显示当前选中那一帧的完整文本；切换首 / 尾帧时跟着变。
3. **只读，不可编辑**：改提示词的入口是镜头描述与一句话指令；这里不提供第二个能改的地方，否则两处会打架。
4. **不显示请求体里的其它字段**（尺寸、模型名）：那是运维信息，不是创作内容。

## 理由

- **可解释性要落到字上**：说"太暗了"能看见"补充：整体提亮…"真的进了句子，才算这句话生效。
- **同源才有意义**：读模型与出图路由用同一个 `buildKeyframePrompt`，看到的就是送出去的；如果在这里另拼一段"给人看的提示词"，迟早两边不一致，预览就成了安慰剂。
- **折叠而不是常驻**：审片时画面和字幕是主角，提示词是一份"说明书"，需要时才看。
- **不给编辑**：提示词是镜头描述与补丁的产物。允许在这里手改，等于出现一个不经过 IR、不可回放的隐藏输入。

## 后果

**正面**
- 花钱之前能看到完整的提示词；"说得对不对"不再靠猜。
- 首尾两帧的差别一眼可见（起势 / 收势），不用读代码。
- 测试：读模型一条（两帧提示词都带补充与机位、互不相同）。
- 实测：展开后能看到"…补充：整体提亮，补足曝光，阴影保留细节…首帧画面，动作起势…"，切到尾帧同一位置变成"动作收势"。

**负面**
- 提示词很长（描述 + 人物锚点 + 场景 + 道具 + 机位 + 补充 + 画质），折叠区展开后占掉画面下方不少高度，小屏上要滚动。
- 只预览关键帧提示词；镜头提示词（`buildShotPrompt`，未来视频用）没有单独展示。
- 预览与真实请求之间仍有一个时差：点开预览后再改一句指令，预览会实时变（读模型现算），但已经发出去的请求不会变。
- 没有"复制提示词"按钮，想拿去别处试要手选。

**跟进**
- 视频接通后，同一块折叠区加一栏"视频提示词"。
- 提示词与生成结果的并排对照（生成完在预览下面贴一张图）。
- 复制按钮。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 新增 `/api/prompt` 让服务端回提示词 | 提示词是纯函数算出来的，多一次往返、多一处会漂的实现 |
| 常驻显示提示词 | 画面是主角；常驻会把审片台变成调试台 |
| 允许在预览里直接编辑 | 绕过 IR，改动不可回放，两处提示词会打架 |
| 只在生成完成后把提示词写进资产溯源里看 | 那是事后；花钱之前就该看见 |
