# ADR-0186：摄影指导面板第一档——四项手调，一处看全

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：I7、I1、I2、I4、I5、B13、ADR-0168

## 背景

I1 把景别 / 机位 / 运镜 / 焦段收成十四套「说法」，套一套就写一条 `shot.updated`。
快是快，但它只有「整组换」一个动作：作者觉得「这套挺好，只是 50mm 想拉到 85mm」，
只能去别处找一组接近的，或者让模型读一句话再猜。四个字段本身在 IR 里一直是
可写的（`shotSize`、`camera.angle`、`camera.movement`、`camera.focalMm`），
缺的只是一个让进阶用户直接够到它们的入口——这正是 I7「面向进阶用户的统一入口」。

## 决定

1. **不新增 IR 字段，也不新增事件类型**
   - 四项都是既有字段，写入仍走 `shot.updated`，`LOG_VERSION` 不动，旧项目无需迁移。
   - 光影（I2）与构图（I4）已经在同一个抽屉里，保持原位。

2. **新增一个 store 动作 `setShotCamera(shotId, patch)`**
   - 一次只改传进来的项；景别一项、机位三项（角度 / 运镜 / 焦段）另算。
   - `camera` 整份写回：只替换点到的角度 / 运镜 / 焦段，**机位坐标（B13）原样保留**——
     走位摆好的位置不能被改焦段洗掉。
   - 焦段只收 8–300mm 的有限数，四舍五入到整毫米；越界拒绝并写 `castError`，
     不写事件、不夹取（静默夹取会让作者以为改成功了）。
   - 已经是这个值、镜头锁定、页面只读、找不到镜头：都不写事件。
   - 一次改动一条 `shot.updated`，撤销按既有分组规则退，不需要新逻辑。

3. **界面：语言抽屉里加「手调参数」一块，位置在「现在这一镜」之下、说法之上**
   - 四行参数签：景别（全景 / 中景 / 特写 / 大特写）、机位（平视 / 仰拍 / 俯拍 / 顶拍）、
     运镜（固定 / 推近 / 拉远 / 横移 / 升降 / 手持）、焦段（14 / 24 / 35 / 50 / 85 / 135）
     ——取值**逐字对应 IR 枚举**，不另造词，避免界面能选、日志存不下。
   - 焦段另有一个自定义输入框（8–300），回车或失焦才写：边打字边写会把「1」写成 1mm。
   - 当前值高亮（`aria-pressed`），改完在同一张卡里回一句「改好了：…」；
     「现在这一镜」那行当场变成新组合，并照旧判断「正好是某套说法 / 作者自己拼的」。
   - 锁定 / 只读时整块禁用；十四套说法保持在上方，仍是快速路径。

## 理由

- **两条路各管一段**：说法解决「我不知道该用什么」，手调解决「我知道，只想改一个数」。
  把说法改成可编辑的万能表单，会把新手最需要的「一按就成」弄丢。
- **枚举照抄 IR**：现有 schema 只有 4 种景别、4 种机位、6 种运镜。界面若先放出
  「荷兰角 / 环绕」，日志会写不进去或要靠别名映射，等于两套词汇。
  要扩词汇，先改 IR 与提示词编译，再放按钮——顺序不能反。
- **一次一项**：作者改完景别通常还要看结果再决定机位；批量改会把一次误点放大成四改。
- **保留坐标**：B13 的机位坐标是几何事实，`shot.updated` 的 `camera` 是整份替换，
  所以这里必须先展开再写回，和 I1 的 `shotLanguagePatch` 是同一纪律。

## 后果

**正面**

- 任意合法组合都能直接调到，不再被十四套说法圈住。
- 「现在这一镜」一行同时是摘要与反馈，改完立刻能看见提示词那一行会怎么写。
- 全部本地计算，不调模型、不花钱，刷新后从事件日志回放。

**负面 / 代价**

- IR 的摄影词汇仍窄：荷兰角、环绕、变焦、轨道等都没有字段，界面如实没有这些按钮；
  扩词汇需要新的 schema 版本与提示词编译，不在这一档。
- 手调只影响这一镜；按场批量套用、摄影单（逐镜参数表）都还没有。
- 说法库仍是内置的十四套，不能把自己拼的组合存成项目内说法。

## 不做

- 摄影单 / 逐镜参数总表、按场或按项目批量套用。
- 自定义说法存进项目、说法版本化。
- 非常规机位与运镜（需要先扩 IR 枚举与编译）。
- 镜头语言与协作、模板市场（Phase 2 的「摄影指导面板完整版」）。
