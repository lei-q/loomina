# ADR-0078 道具签按场次筛选

- 状态：已接受
- 日期：2026-11-11
- 决策者：用户 + Claude
- 关联：ADR-0066（道具签）、ADR-0077（出场顺序）、FEATURES B8

## 背景

分镜页的 `道具` 一行列出**整个道具库**：一件不多时正好，等库里攒到二三十件，这一行会换好几行，把舞台往下挤。而大多数时候一个镜头只需要用这一场出现过的那几件——道具库里的其他东西在这个镜头里根本用不上。

场次页也没有"这一场用过哪些道具"的入口，用户只能凭记忆在长列表里找。

## 决策

1. **一个视图开关 `只列本场`**：放在 `道具` 标签旁边，虚线小签；点一下只列出这一场里出现过的道具，再点回到全部。默认**关**（与现在的行为一致，不让人一进来就以为道具没了）。
2. **"这一场用过" = 这一场所有镜头的 `propIds` 并集**：按场次归类（同一场里任意一镜用过的都算），不是只看当前镜——否则同一场切到下一镜，签会跳来跳去。
3. **只是视图，不写事件**：开关状态留在组件里，刷新回到"全部"；日志与项目不受影响。
4. **读模型加一个字段**：`StageShot.sceneId`（这一镜属于哪一场），分镜页据此算并集；顺带给以后的"按场筛选人物 / 按场统计"留了依据。
5. **空提示**：开着 `只列本场` 而这一场确实没用过道具时，签的位置写「这一场还没用过道具。点「只列本场」列全部。」
6. **只筛道具，不筛人物**：人物数量通常小，而且出场签还承担"谁在这一镜"的叙述；道具才是容易膨胀的那一排。

## 理由

- **默认关**：筛选是有损的——开着的时候，你想把一件"这一场还没用过"的道具点进来，得先关掉。默认值要让人看到全部。
- **按场不按镜**：用户在一场里连续看几镜，签的集合应该稳定；按镜筛会让每次切镜都重排。
- **不写事件**：这是"看"的方式，不是项目内容；写进日志会让重放多一个纯 UI 字段。
- **一行开关就够**：不需要"只列这一镜 / 只列本场 / 全部"三档——两个状态已经覆盖主要场景。

## 后果

**正面**
- 舞台上的 `道具` 行从一长排收敛到本场用过的几件；`只列本场` 是实线框时表示正在筛。
- 切到另一场，筛选后的集合跟着换成那一场的道具。
- 道具少时开关不碍事；一件道具都没有时不显示开关。
- 测试：web 210（新增 2：`sceneId` 归类与按场去重）、IR 94、gateway 17、pipeline 22，合计 343。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：定妆页新建「雨伞」（本场没用过）→ 分镜页 `全部` 有「雨伞」→ 点 `只列本场` 后只剩「搪瓷杯」「台灯」→ 再点回来「雨伞」回来；无报错。

**负面**
- **要加"本场没用过"的道具得先关筛选**：没有"在筛选态里也能新建 / 搜索"的入口。
- **不记忆**：刷新、切页回来都回到"全部"；每镜都开的话要重新点。
- **只列本场不等于"只列这一镜"**：想只给自己这一镜挑道具，还得在行里找。
- **人物不筛**：人物库大了以后同样的问题会出现。
- **没有计数**：开关上看不出"本场 3 件 / 全部 12 件"。

**跟进**
- 在筛选态里搜索 / 新建道具。
- 记住开关状态（按项目 / 按页）。
- 人物签也按场筛选，或两排共用一个开关。
- 开关上带计数。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 默认只列本场 | 想用场外道具的人第一眼会以为道具没了；默认值应无损 |
| 三档（本镜 / 本场 / 全部） | 多一个状态，收益小；本镜筛选会把签跳来跳去 |
| 折叠成下拉 / 搜索框 | 一排签的优势是"一眼看到、一点就用"；下拉要先展开再找 |
| 把筛选写进项目设置 | 这是看的偏好，不是项目内容，不该进 IR |
| 自动隐藏"没用过"的道具且不给开关 | 用户找不回来，等于把道具库藏起来 |
