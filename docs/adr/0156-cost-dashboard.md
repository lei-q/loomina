# ADR-0156：成本看板与单镜异常突增

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：H15、H4、H10、H16、ADR-0036、ADR-0106、ADR-0137、准则 P21

## 背景

H4 已经把「钱花在哪」拆到阶段与逐镜：`spendOf` 给项目合计，`spendByStage` 给故事 / 定妆 / 分镜 / 配音 / 成片五段，`shotLedger` 给每一镜的 take 数、已花与淘汰金额。H16 也有按模型看 S1 测绘通过率的走势。但 H15 要回答的四个问题还没有一个统一的读数：

1. 一条镜头平均花多少钱？
2. 第一版 take 有多少直接被采纳——重拍是不是常态？
3. 淘汰的 take 占多少条、浪费了多少钱？
4. 有没有哪一镜突然贵得离谱，值得先去看那一条？

这些都能从现有 IR 直接算出来，不需要新表、新事件或供应商接口。缺的只是一层把这些数摆在一起的派生读模型，以及一个能被作者看见的位置。

## 决定

1. 新建纯函数层 `apps/web/lib/cost-dashboard.ts`，只吃 `Project`，调用既有 `shotLedger`，不写 IR、不写事件、不调模型。
2. 读数口径：
   - **单镜均成本 / 中位数**只按「有花钱的镜」算，零花费的镜不摊薄；同时给出有花费的镜数。
   - **首次通过率**按每一镜按拍摄顺序的第一条 take 判：`approved` 算通过，`rejected` 算没通过，`draft` 说明还没表态，不计入分母。
   - **重试占比** = 淘汰 take 条数 / 全部 take 条数，并给淘汰 take 的金额合计。
   - **异常突增** = 某镜花费 ≥ 有花费镜中位数的 3 倍，且比中位数至少多 ¥1；有花费的镜少于 4 个时不下结论。`draft` 镜的 take 费用同样计入已花，不自作主张排除。
3. 界面放在顶栏「记账」抽屉里、四个总览数字下面，名为「成本看板」：三张读数卡（均成本 / 首次通过率 / 重试占比）、最贵的三镜、突增清单与口径说明。不新开页面、不加导航。
4. 全部只读：看板不改预算、不删 take、不触发重拍；异常只是提示，不是硬闸门。真正限制花费仍由 H10 的项目 / 单镜上限负责。

## 理由

- **复用既有账本**：`shotLedger` 已经处理了「take 的视频资产不重复计价」「首尾帧算进镜」「淘汰金额单独算」，再写一套会立刻分叉。
- **均值要诚实**：把零花费的镜算进分母会让「单镜成本」看起来很低，作者据此估预算会低估。分开报「有花费镜数」比一个漂亮的低均值有用。
- **首次通过率只认作者的表态**：`draft` 既不是通过也不是失败；把它算成失败会制造虚假的重拍率，算成通过又会掩盖问题。
- **突增是分布问题，不是绝对金额**：不同项目、不同模型、不同镜长下，¥3 可能很贵也可能很便宜。拿同一项目内有花费镜的中位数做参照，比设一个全局金额阈值更稳。
- **样本不足不报警**：三镜里有一镜贵，说明不了什么；4 镜起、3 倍与 ¥1 双条件，避免把一个略贵的正常镜头标成异常。
- **放在记账抽屉**：作者已经在这里看阶段与逐镜账；看板是同一份数据的另一种读法，不需要另找一个入口。

## 后果

**正面**

- H15 的四个指标都有可操作界面，且与 H4 账单同源，不会出现「账单 ¥10、看板 ¥8」。
- 未定价调用仍单独计数，不被当成 ¥0 摊进均值。
- 不新增依赖、不新增 API、不新增 IR 字段或事件；旧项目直接可用。

**负面 / 代价**

- 只在当前项目的「记账」抽屉里看，不做跨项目看板；跨项目合计仍看下方「这台设备」。
- 异常突增只看单镜内的花费，不识别「某阶段整体变贵」；后者要等按时间的账单切片。
- 首次通过率依赖 take 状态被及时更新；一直留在 `draft` 的镜不会进入分母。
- 没有历史曲线：看板是打开抽屉那一刻的快照。

**不做**

- 定时扫描、桌面 / 邮件告警、成本突增自动暂停生成。
- 跨项目成本排名、按时间 / 按月趋势、按模型拆成本。
- 从供应商账单反查单价；单价仍由作者在设置页填写或价目表提供。
- 把异常突增写进 IR 或作为导出前的硬闸门。
- 自动删除淘汰 take 或回收其费用。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 新建成本表 / 定时任务写快照 | 账本是 IR 与事件日志的函数；存下来就要配失效与迁移 |
| 用项目总花费除以全部镜数 | 零花费镜会稀释均值，作者会低估单镜预算 |
| 用绝对金额阈值判突增 | 不同模型与镜长差异太大，同一阈值在另一项目里失效 |
| 把 `draft` 算作首次未通过 | 作者还没看，不能算失败；会制造虚假重拍率 |
| 突增时自动停生成 | 看板是诊断，不是预算护栏；H10 已有上限与阻断 |
| 只在设置页做静态说明 | H15 要的是可看的数，不是又一段文字 |
