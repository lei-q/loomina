# ADR-0017 故事层作为结构化一等公民

- 状态：已接受
- 日期：2026-11-09
- 决策者：用户 + Claude
- 关联：P1、P16、A1/A2/A11、STORY.md

## 背景

平台的定位是"短剧生产线"，但从最初讨论到分镜，故事层一直以"一段文本"的形式存在：

- 生成能力强 ≠ 故事好；模型会在三个月内商品化。
- LLM 写出的故事"结构正确但平庸"，缺具体细节与真实冲突。
- 如果故事只以自然语言存在，剧本医生、分镜、生成、QA 无法共享同一份真相，也无法量化诊断。

短剧还有自己的语法（3 秒钩子、15–20 秒增量、结尾留钩、低认知负荷），不能直接套用电影三幕。

## 决策

把故事层做成**结构化、可诊断、可评分、可回滚**的数据，纳入 Project IR：

- `Premise`（题材/受众/基调/约束）
- `Project.logline`
- `CharacterArc`（want / need / wound / flaw / secret / agency / arc）
- `Beat`（hook / setup / escalation / turn / climax / endHook）
- `Hook`
- `ScriptDoctorReport`（12 维评分 + 触发条件 + 改写模式）
- `OriginalityReport`
- `StoryBible` 扩展

故事引擎固定为 8 步：前提选择 → Logline 评分 → 人物与关系 → Beat Sheet → 场次拆解 → 台词 → 剧本医生 → 原创性检查。

同时确立短剧的十条"物理定律"，作为所有故事功能的默认约束。

## 理由

1. **结构化才能被下游复用**：分镜、镜头时长、表演、生成提示词都要引用 Beat 与人物状态。
2. **可评分才能被改进**：剧本医生不是润色，而是按维度诊断 + 定向改写。
3. **可拍性必须前置**：人物 ≤ 5、场景 ≤ 3、台词 ≤ 15 字，是生成可行性与成本的硬约束。
4. **故事是差异化**：生成会商品化，结构 + 品味不会。

## 后果

**正面**
- 故事、分镜、生成共享同一份真相。
- 剧本质量可量化、可 A/B、可回归。
- 题材矩阵给出首发聚焦（都市情感 / 逆袭打脸 / 甜宠）。

**负面**
- 前期需要设计并维护剧本医生 rubric 与评分标定。
- 结构化可能让创作"太规整"，需保留自由文本与人的介入。

**跟进**
- 用 30 个短剧样本标定 rubric 权重与阈值。
- 建立 Beat 模板库（60s / 3min / 系列）。
- 原创性检查先做"标记"不做"阻断"。

## 替代方案

- **纯文本剧本 + 人工判断**：无法量化、无法与 IR 对齐，放弃。
- **直接让 LLM 端到端写分镜**：缺结构，失败无法定位，放弃。
- **套用电影三幕**：不符合短剧语法与竖屏观看，放弃。
