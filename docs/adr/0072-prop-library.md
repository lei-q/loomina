# ADR-0072 道具库：新建与改名

- 状态：已接受
- 日期：2026-11-11
- 决策者：用户 + Claude
- 关联：ADR-0071（人物库，同一套形状）、ADR-0030（道具引用即必锁）、ADR-0066（分镜页道具签）、FEATURES B8

## 背景

道具和人物一样，只能来自 `project.created` 的快照：定妆页能生成参考图、锁 / 解锁，不能新建、改名、写描述。示例项目里只有搪瓷杯、台灯；新戏要加"旧钥匙"时没有入口，剧本里写到的新道具只能借已有的名字。

人物库（ADR-0071）刚补上同一套"新建 / 改名 / 描述"，道具照同样的形状补，事件、store、界面三处都能对位。

## 决策

1. **两个事件**：
   - `prop.added { at, prop }`：带完整道具（`name / description / referenceImages`）；空名字、重复 id 拒绝。
   - `prop.updated { at, propId, patch }`：patch 只允许 `name` 与 `description`；空 patch、空名字、陌生 id 拒绝。
2. **store 两个动作**：
   - `addProp(name, description?)` → id；名字与描述去首尾空白；重名拒绝（「已经有一件叫「X」的道具了。」）；描述 200 字上限（整句进提示词，与地点 / 人物同一个理由）。
   - `editProp(propId, { name?, description? })` → boolean；重名、畸形、没改动都拒绝（「道具没改。」）。
3. **新建的道具从空白开始**：`referenceImages: []`；参考图随后在定妆页生成（ADR-0032），锁定闸门不变。
4. **不给删除**：删除要考虑 `shot.propIds` 的引用与已出的帧，单独一刀。
5. **界面在定妆页**：
   - `道具 · 参考` 标题右侧 `新建道具`：虚线内联表单，名字 + 描述（选填），回车 / 创建提交，Esc 取消；一件道具都没有时列表处写「还没有道具。上面新建一件，再到分镜页把它点进出场。」
   - 每件道具名旁 `改`：就地展开名字与描述，保存 / 取消；
   - 只读标签页不显示 `新建道具` 与 `改`。

## 理由

- **和人物、地点同一套形状**：库对象都是"新建 + 改名 / 描述 + 参考图 + 锁定"，读侧、日志与心智都不必学第三套。
- **描述整句进提示词**：道具描述已经随锚点进提示词（ADR-0030），新建时就能写清"长什么样"，比先建空壳再补更省事。
- **重名拒绝**：道具在分镜页与提示词里都按名字辨认，两件同名道具会让"出场"说不清是哪一件。
- **不做删除**：没有引用搬移规则之前，删除要么产生悬挂引用，要么悄悄改掉别人的镜头。
- **不自动生成参考图**：生成要花钱，由用户看到报价后点。

## 后果

**正面**
- 定妆页点 `新建道具` 填「旧钥匙 · 黄铜钥匙，齿口磨圆，用红绳串着」→ 道具列表多一张卡（`缺参考图`、`¥0.12` 报价）；分镜页的 `道具` 签立刻多出「旧钥匙」。
- 点 `改` 把名字改成「旧铜钥匙」并缩短描述 → 卡片跟着变，日志一条 `prop.updated`。
- 重名、空名字、超长描述被拒，错误贴在页头，不写事件。
- 测试：IR 88（新增 3：加道具、改名与描述、空名字 / 重 id / 陌生 id / 空 patch 拒绝）、web 186（新增 3：新建、拒绝三种、改名与重名 / 没改）；gateway 17、pipeline 22；合计 313。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：定妆页新建「旧钥匙」→ 出现在道具列表；`改` 改名「旧铜钥匙」；分镜页道具签为「搪瓷杯 / 台灯 / 旧铜钥匙」。

**负面**
- **不能删除道具**：试验道具只能留着（示例项目里留下了"旧铜钥匙"）。
- **不能直接改参考图列表**：参考图仍然只有"生成一张"这一条路。
- **没有描述 / 名字的历史回退**。
- **改名会让提示词变**：已经出的图按 `propIds` 判过期（ADR-0057），名字变化本身不额外标记。

**跟进**
- 删除道具 + 引用检查。
- 道具的参考图列表（多张、手动挂）。
- 名字 / 描述的历史回退。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 新建时同时生成参考图 | 生成要花钱，必须由用户看到报价后点 |
| 允许同名道具 | 分镜页与提示词按名字辨认，同名会让出场说不清 |
| 与人物共用一个 `entity.added` 事件 | 字段与读侧都不同；合并后每个 `switch` 都要分叉，收益为零 |
| 先只做改名不做新建 | 新建才是"新戏要加道具"的入口；改名是配套 |

## 附记（2026-11-11）

- 「跟进」里的删除道具已由 ADR-0073 落地：`prop.removed`；还有镜头用着它时拒绝。
