# ADR-0192：分镜接上一段——先重复上一段收势，再进新剧情（用户 C.6 / 功能 C19）

- 状态：已采纳（第一档：提示词接续；视频尾段输入待供应商能力）
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：C.6、C19、B3.1、E4、C12、ADR-0037、ADR-0107

## 背景

分段生成视频时，下一段常从「新动作」直接开始：上一段收在「她站在门口」，
下一段第一帧却在「她转身走开」——动作与声音都在接缝处断掉。用尾帧硬接
只能对上构图，对不上动作的惯性。

用户给的最佳方案是：**把上一段最后 3 秒的视频 + 下一段文字一起给模型**，
让模型先重复上一段的收尾动作，再进入本段剧情。

## 现状约束

- 网关的视频适配器目前只接受 `image_url`（首帧图），**没有视频参考输入**：
  请求体里没有 `video_url` / `reference_video` 一类字段，供应商能力也未确认。
- 因此这一档先做**提示词层的接续**：把「先重复上一段最后 N 秒的收势动作」写进
  视频提示词，并让作者逐镜开关、选时长。真正的尾段视频输入等供应商接口确认后
  再补，不改这一档的数据结构。

## 决定

1. **IR：`Shot.continuation?: { tailMs } | null`**
   - `tailMs` 是回头重复的时长，整数毫秒，500–5000，默认 3000。
   - 缺省 = 旧行为（硬接）；`null` = 作者明确选了硬接（保留记录，便于回看当时的决定）。
   - 走既有 `shot.updated` 的 patch，不新增事件类型；`applyEvent` 用
     `ContinuationSchema` 再校验一次，越界不进日志。

2. **「上一段」按观众看到的顺序找**
   - `previousShotOf(project, shotId)`：先按时间线 `startMs` 排序找前一段；
     这一镜还没排进时间线时，退回分镜数组的先后。第一段没有上一段。
   - 这样接续跟着成片顺序走，而不是跟着分镜页的排列走；重排时间线后
     「上一段」自动跟着变。

3. **提示词怎么写**
   - `shotMaterial` 在镜头开了接续、且确实有上一段时，补上
     `continuation: { previous: 上一段描述, tailMs }`；写不进去就不补。
   - `buildVideoPrompt` 在分镜内容之后、台词与「从首帧起势」之前追加一句：
     `接上一段：本段开头先重复上一段最后 3 秒的收势动作（上一段：…），再进入本段动作，不要直接切到新剧情`。
   - **只进视频提示词**：首帧 / 尾帧是静帧，不带这句（与台词同一处理，ADR-0107）。
   - 上一段描述为空时写「上一段结尾的动作」，不编造内容。

4. **界面放在分镜页的镜头语言抽屉**
   - 「接上一段」区：显示上一段是第几镜与它的描述；1–5 秒五个档位；
     「改成硬接」清回 `null`。
   - 开头那一镜显示「没有上一段可接」，按钮不出现；锁定 / 只读禁用。
   - 点了之后抽屉底部给出人话反馈，并说明「视频提示词会写上这一句」。

## 理由

- **先做能做的**：尾段视频输入是供应商能力问题，不是产品设计问题；
  提示词接续今天就能用、能验、不花钱，而且与将来的视频输入不冲突。
- **按时长显式记录**：3 秒是用户给的默认值，但片子节奏不同；写成毫秒而不是
  写死「3 秒」，将来接视频裁剪时可以直接用同一个数。
- **null 与缺省分开**：缺省是「没想过」，null 是「想过，就要硬切」；
  回看日志时能分清这两种状态，将来也能只对「没想过」的镜头给建议。
- **不碰音频轨**：声音衔接由音频轨与混音负责（C12）；这里只解决画面动作
  在接缝处断开的问题，避免两套机制互相猜。

## 后果

**正面**

- 每个接续镜头都能在提示词里写清「先收势、再进剧情」，不依赖尾帧碰巧对上动作。
- 接续跟着时间线走，重排后不用手工改「上一段」。
- 旧项目与不打开接续的镜头逐字节不变；无新事件、无日志版本升级。

**负面 / 代价**

- **真正的视频尾段输入还没做**：当前只是提示词要求，模型是否照做取决于模型；
  没有把上一段最后 3 秒的像素喂进去。
- 上一段只取一句描述，不是「最后 3 秒实际发生了什么」；描述写得笼统，
  接续句也笼统。
- 不检查前后两段的角色 / 服装 / 光线是否一致（那属于 B4 连续性监工）。
- 每个镜头要单独打开接续；没有「整场 / 整条片子一键接续」。
- 首帧仍用本镜自己的关键帧，不是上一段的尾帧；两套对齐方式可能同时存在。
