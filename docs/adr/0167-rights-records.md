# ADR-0167：授权记录（H7）

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：H7、G8、B2、C4、E4、准则 P15 / P16

## 背景

G8 的导出前预检里有一项「素材授权」，但它到这一刻只会说一句：

> `N 个上传 / 导入素材没有授权记录（H7 未做）：确认你有使用权再导出`

也就是说：它只能数出「有几个上传素材」，不能回答作者真正的三个问题：

- 我到底**缺哪一条**授权（这张脸？这段声音？这段音乐？）？
- 哪一条**已经过期**了？
- 凭证（合同 / 邮件 / 授权书）**放在哪**？

短剧最贵的两样东西是脸和声音。用真人参考图做角色、克隆一个音色配音，
没有留档的话，平台下架或权利方找上来时，作者手里什么都没有。

## 决定

1. **IR 新增 `Project.authorizations: RightsRecord[]`，默认 `[]`**
   ```ts
   { id, subject, kind: "portrait" | "voice" | "asset" | "music" | "other",
     targetId?, grantor, grantedAt, expiresAt, evidence, note }
   ```
   - `subject` 是人话名字（「林晚的肖像」），必填、≤60 字。
   - `targetId` 关联项目里的角色 / 道具 / 地点；对不上就留空。
   - `grantor` / `grantedAt` / `expiresAt` / `evidence` / `note` 默认空串；
     `expiresAt` 为空表示**不限期**。

2. **事件 `rights.updated` / `rights.removed`**
   - `rights.updated { record }`：按 id 幂等 upsert，`applyEvent` 用
     `RightsRecordSchema` 校验后落库。
   - `rights.removed { rightsId }`：只删这一条留档，不动角色与素材；
     指向不存在的记录直接抛错。
   - 新增事件类型必须同时在 `EVENT_TYPES` 与 `describeEvent` 里登记，
     否则编译失败（沿用 ADR-0077 的约定）。

3. **缺与过期是派生的，不写 IR**
   - `apps/web/lib/rights.ts` 的 `rightsReport(project, today)` 每次现算：
     返回 `gaps`（缺哪一条）、`expired`（哪一条过期）、`valid` / `total`
     与一句 `verdict`。
   - 判定口径**宁可少报**：
     - 角色的参考图或定妆三视图里**有上传 / 导入的图**，才要求肖像授权。
       纯模型生成的脸没有真人来源，不要求；
     - 上传 / 导入的素材要求一条素材授权（kind 为 `asset`，不挂具体对象）；
     - 声音**不自动判缺**：`voiceProfileId` 只写了个音色名，分不出是平台
       自带还是克隆音色。界面上明说「克隆音色要自己记一条」，不做猜测；
     - 音乐 cue 的授权走已有的 `licenseRef`，不在这里重复要求。
   - 过期判定只比日期部分：`expiresAt` 早于今天算过期，当天不算。

4. **合规预检接上它（G8 的「素材授权」一项）**
   - `rightsCheck(project, today)` 用 `rightsReport` 的结果拼 findings：
     缺一条一条 `rights-<kind>`，过期一条 `rights-expired-<kind>`，
     全部是 `review`（不是 block）：作者可能确实有权，只是没记。
   - 没有缺、没有过期时 `status: "pass"`，detail 写明「N 条授权记录，都在有效期」；
     一条记录都没有时沿用旧文案「全部素材由模型生成或来自内置库」。
   - 「今天」从 `preflightProject` 的 `at` 取，测试可注入。

5. **界面：定妆页与成片页顶栏「授权」抽屉**
   - 顶部一段结论：缺几条、哪几条（每条带「补一条」按钮，点了就按缺口
     预填类型与对象名），哪几条过期。
   - 「记一条授权」展开表单：类型、挂在谁身上（角色 / 道具 / 地点下拉）、
     授权对象、授权方、授权日、到期日、凭证在哪、备注。
   - 全部记录列表：类型标签、对象名、过期标记、改 / 删（删除两步确认）。
   - 顶栏按钮上的数字是缺的条数（含过期），补完就消失。

## 理由

- **留档而不是核验**：合同真伪、签名有效性都不是工具能判断的。工具能做的
  是把「有没有记、记的是谁、什么时候到期、凭证在哪」摆出来。
- **不进 IR 存「缺哪一条」**：缺是项目现状的函数（角色有没有上传参考图、
  素材是什么来源），存下来就要配失效机制，而重算一次是毫秒级的事。
- **宁可少报**：把「作者本来就没打算用真脸」报成缺授权，会让提示变成噪音，
  作者一旦习惯忽略它，真正缺的那条也会被忽略。
- **只标 review 不 block**：授权是法律事实，不是格式错误。工具不该替作者
  决定「这张图能不能用」，只该保证导出前他看见过这件事。
- **四类固定枚举**：肖像 / 声音 / 素材 / 音乐是短剧实际会遇到的全部；
  `other` 兜底。分类多了会让人犹豫该选哪个。

## 后果

**正面**

- 「素材授权」从一句「H7 未做」变成能点、能补、能看的台账。
- 过期授权第一次会被指出来——这是实际最常见的踩坑。
- 缺口能一键预填，补授权从「想想该写什么」变成「确认一下」。
- 全部本地、纯函数派生：不调模型、不花钱、离线可用。

**负面 / 代价**

- 授权要作者自己记，工具不替他去拿合同；忘了记就一直报缺。
- 声音不自动判缺，靠作者自觉——这是为了避免误报做的取舍，界面上写清楚了。
- `expiresAt` 是自由文本，只比日期前 10 位；写成别的格式（如「明年三月」）
  会被当成「不早于今天」而静默放过。
- 删除留档不删素材：删掉一条授权记录不会让角色或素材消失，这是刻意的
  （留档与资产是两回事），但需要作者理解。

**不做**

- 授权书的 OCR / 自动填表。
- 到期提醒与通知（H8 的告警体系将来可接）。
- 按授权状态拦生成或拦导出（只提示，不拦）。
- 多项目共享的授权库（每份项目各记各的）。
- 声音自动判缺（需要知道音色是不是克隆的，现在没有这个信息）。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 继续只数上传素材个数 | 作者还是不知道缺哪一条、有没有过期 |
| 把「缺哪一条」写进 IR | 要配失效机制，而重算一次是毫秒级的事 |
| 有音色就要求声音授权 | 平台自带音色没有权利方，误报会让提示变成噪音 |
| 缺授权时阻断导出 | 授权是法律事实，工具不替作者判断能不能用 |
| 只做记录，不接合规预检 | 导出前看不见，就等于没有 |
| 每类授权强制必填凭证 | 很多授权就是一句口头 / 微信同意，强填只会逼人编 |
