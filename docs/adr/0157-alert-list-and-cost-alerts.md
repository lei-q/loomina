# ADR-0157：告警清单与成本突增告警

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：H8、H11、H15、H10、ADR-0111、ADR-0156、准则 P21

## 背景

H11 已经在设置页做出一块健康检查：供应商状态、最近 24 小时按「模态 + 模型」的失败率、渲染队列。它同时维护一个 `alarms: string[]`，只在失败率达到 50% 时拼一句人话。H15 又把单镜成本、首次通过率、重试占比与单镜突增摆进了记账抽屉。

H8 要的是「监控与告警」本身：失败率与成本异常应该有一个统一的告警清单，而不是散落在两块的文字里；「留意」与「告警」要能分开看，不能只有 50% 才出现。但这件事仍不该引入常驻调度器、把告警写进数据库，或为了算成本让服务端读用户的项目。

## 决定

1. 新建 client-safe 的 `apps/web/lib/alerts.ts`，定义唯一的告警形状 `HealthAlert { id, level, kind, title, detail, at? }`：
   - `level`：`alarm`（告警）或 `watch`（留意）；
   - `kind`：`provider`（供应商）、`failure`（失败率）、`cost`（成本）。
2. 失败率告警放在 `health-events.ts` 的 `failureAlerts(groups)`：沿用 `summarizeFailures` 已有的判定——样本少于 3 次不下结论、≥20% 留意、≥50% 告警；每条带失败次数、样本数、最后一次失败码与时间。阈值只在一处定义，界面不再手写。
3. 供应商告警由 `health.ts` 生成：`down` 是告警、`degraded` 是留意。`GET /api/health` 多回一份结构化 `alerts`；旧的 `alarms: string[]` 保留，由同一份告警拼成，旧调用方不受影响。
4. 成本告警放在 `alerts.ts` 的 `costAlerts(events, current?)`，在浏览器里按本机事件日志现算：
   - 某镜花费 ≥ 有花费镜中位数的 3 倍且多花至少 ¥1 → 留意，复用 H15 的 `costDashboard`；
   - 项目已花超过自己的 `budgetCny` → 告警。
   当前项目由调用方直接传入：日志按 `project.created` 切段时，一次跨项目的「回到这里」会让最后一段的恢复目标落在段外、回放失败；当前项目不该因此漏掉成本告警。回放失败的其它段跳过，与账单口径一致。
5. `mergeAlerts` 合并服务端与本地告警，按 id 去重，告警在前、留意在后，同级按时间新 → 旧，最多 20 条。
6. 健康检查块顶部渲染统一告警清单：等级 chip、类别、标题、时间与一句原因；没有告警时显示「现在没有告警」并说明三条检查线。成本告警不依赖健康探测是否成功——探测失败时它仍然显示。
7. 告警只读：不写 IR、不写事件、不弹桌面通知、不自动停生成。预算超限后的行为仍由 H10 的 `onBudgetExceed` 决定。

## 理由

- **服务端不该读用户项目**：事件日志在浏览器（ADR-0088），成本告警只能在本地算。把它硬搬到服务端，要么上传项目，要么另存一份账，两者都违背数据边界。
- **阈值同源**：失败率的 20% / 50% 已在 H11 的汇总里；告警若再写一套，最容易出现「表里 40% 红着、告警说没事」。
- **结构化比字符串有用**：等级、类别、时间可排序、可筛、可加类别；旧的 `alarms` 字符串仍能满足一句话摘要。
- **成本告警复用 H15**：同一份中位数与突增规则，看板与告警不会互相矛盾；`spendOf` 保证已花口径与账单一致。
- **不做调度器**：目前只有作者打开设置页时才看告警；没有常驻进程、没有通知渠道。把「定时」限制写清楚，比假装有监控诚实。
- **告警不等于阻断**：预算是硬线，但阻断发生在生成入口；告警清单只负责让作者看见，不接管 H10 的行为。

## 后果

**正面**

- 失败率与成本异常共用一个清单：留意与告警一眼分开，带时间与原因。
- 供应商掉线、失败率升高、某镜突增、项目超预算都能在设置页看到。
- 不新增 API 端点、不新增依赖、不新增 IR 字段或事件；旧项目与旧健康报告都能打开。
- 成本告警完全在本地算，项目与账本不出浏览器。

**负面 / 代价**

- 告警只在设置页的健康检查块出现，不弹通知、不发邮件；作者不打开就看不到。
- 没有告警历史：清单是当下快照，关掉再开就没了。
- 成本告警只看本机日志；换设备后不会汇总另一台机器的项目。
- 项目超预算的告警在作者主动调低预算后立即出现，可能只是试算，不代表真的多花了。

**不做**

- 常驻调度器、桌面 / 邮件 / webhook 通知、告警静音与确认。
- 告警持久化、历史曲线、按告警触发自动暂停或降级。
- 服务端读取或上报用户项目事件；跨设备告警汇总。
- 成本告警的绝对金额阈值、按模型拆成本、按时间窗口看突增。
- 新增 `/api/alerts` 端点；告警随 `GET /api/health` 或本地计算返回。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 只保留 `alarms: string[]` | 无法分层级、类别与时间，界面上只能一段文字 |
| 服务端算成本告警 | 要读浏览器里的事件日志，等于上传项目或另存账本 |
| 告警写进 IR / 事件日志 | 告警是派生诊断，写进去要多事件、回放与失效 |
| 每次告警都弹通知 | 没有常驻进程，浏览器通知也要授权；先做可见清单 |
| 成本突增就自动停生成 | 违背 H10 的阻断边界；看板与告警不该替作者做花费决定 |
| 另开 `/api/alerts` | 数据源一个在服务端、一个在浏览器，合并只能在前端做；多一个端点没有收益 |
