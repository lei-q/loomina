# ADR-0060 调整场序：一场一位，镜号跟着重排

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0011（事件日志）、ADR-0043（剧本页）、ADR-0050（场头）、ADR-0058（场头历史）、ADR-0059（地点）、FEATURES A21

## 背景

剧本页从 ADR-0043 起就按 `Scene.index` 排序，读模型里「第 N 场」与 `SH-01` 都是排出来的，不是存的。但场序一直只能靠示例数据的顺序，用户挪不动一场戏的位置。ADR-0058 与 ADR-0059 的跟进里都写着这一条。

ADR-0050 明确说过「场号、场序属于结构，不在这里改」——`scene.updated` 只收内外景 / 日夜 / 地点。场序需要自己的事件，而不是把 `index` 塞进 `scene.updated`。

## 决策

1. **新事件 `scene.moved { at, sceneId, toIndex }`**：表示「这一场挪到第几位」。`toIndex` 从 0 数，必须落在现有场次范围内。
2. **`applyEvent` 怎么落**：按 `index` 排一遍现有场次 → 摘下目标场 → 插到 `toIndex` → 整排重写 `index = 0..n-1`。一次事件、一次重编号，不会出现两场同号。
3. **校验**：没有 `project.created`、目标场不存在、`toIndex` 越界（非整数 / <0 / ≥场数）、`toIndex` 等于当前位置，全部拒绝。
4. **store `moveScene(sceneId, direction)`**：只读直拒；按排好的顺序找位置，`up` / `down` 各挪一位；到边界写「已经是第一场。」/「已经是最后一场。」且不写事件；成功写一条 `scene.moved`。
5. **不碰镜头**：`Shot.index` 是场内镜序，跟场走；全局镜号（`SH-01`）由读模型按「场序 → 场内镜序」重算。台词、take、关键帧、场头历史全按 id 引用，重排不影响任何一条。
6. **界面**（剧本页）：场头行右侧 `n.ns · m 镜` 之后两个描边小钮 `↑` / `↓`，第一场的 `↑`、最后一场的 `↓` 置灰；只读标签页不显示。悬停写「上移一场：场号与镜号跟着重排」。

## 理由

- **场序是结构，单开事件**：`scene.updated` 的 patch 针对一场的场头；把另一场也要变的重排混进去，读模型与历史都会多一层特判。
- **存「挪到第几位」，不存「和前一场交换」**：位置是用户看到的东西；交换需要写两条事件，中途重放会有一瞬两场同号。
- **一次重编号**：`index` 只作为排序依据，整排重写后与数组顺序一致，`project.scenes` 里不再留空洞。
- **镜号不存**：镜号一直是读模型算的；如果把它存进 IR，重排就要同时改十二个镜头，日志里也会出现一堆「镜号变了」的事件。
- **与台词排序（ADR-0047）长得一样**：`↑` / `↓` 一次一位，边界置灰。用户在同一条片子里学一套就够。

## 后果

**正面**
- 第 2 场（桌边）点 `↑`：一条 `scene.moved { sceneId: "sc-2", toIndex: 0 }`，页面立刻变成「第 1 场 桌边 / 第 2 场 …」，原 SH-04 / SH-05 变成 SH-01 / SH-02，原 SH-01 起顺延成 SH-03。
- 场头历史跟着场走：sc-2 的「改过 3 次 · 上一版 …」还在它自己那一节，不因为换了位置而串到别场。
- 台词、take、关键帧、过期小签全按 id 挂，重排之后一条不丢。
- 测试：IR 69 条（新增 2 条：挪到末位 + 重编号 + 回放、四类拒绝）；web 151 条（新增 2 条：上移后场号与镜号重排、边界 / 陌生场次 / 只读）；合计 258。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：剧本页第 2 场 `↑` → 页面顺序变为桌边 / 阳台外沿 / 走廊 / 门口 / 桌边，SH 编号连续 01–05；IndexedDB 第 44 条为 `scene.moved { sceneId: "sc-2", toIndex: 0 }`。

**负面**
- **只有相邻挪动**：拖拽排序、直接输入目标位置都没做；长片要从第 8 场挪到第 2 场得点六次，每次都写一条事件。
- **场号不能手改**：重排后永远是 1..N 连续整数；影视里常见的 `2A`、跳号不支持——那需要一个显式的场号字段，与「排出来的场号」是两件事。
- **一次一位、一次一条事件**：连点三次就是三条事件；回放没问题，但日志里看得出「手抖」。
- **不重排时间轴上的引用**：分镜页胶片轨按新的场序重算镜号，但「当前选中的镜头」按 id 记，位置会跳。
- **不联动下游**：重排不改变任何一镜的画面输入，所以不会触发过期小签——这是对的；反过来，帧的过期判断也不看场序。

**跟进**
- 拖拽排序与「挪到某一位置」。
- 显式场号（`2A` / 跳号），与排出来的场号分离。
- 场号改动是否要进场头历史（目前场序不进历史，只进日志）。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 在 `scene.updated` 的 patch 里加 `index` | ADR-0050 的边界被破，而且重排要连写两条才不撞号 |
| 一次事件写「交换两场」 | 中途状态两场同号；`toIndex` 一条就够 |
| 把场号存进 `Scene`（如 `no: "2A"`） | 连续编号是现在唯一的口径；先做真正需要的场序，场号另开决策 |
| 用 `project.updated` 重写整个 `scenes` 数组 | 日志里看不出挪的是哪一场；与 ADR-0059 拒绝整表写的理由相同 |
| 拖拽代替 `↑` / `↓` | 拖拽要处理落点、滚动、触屏，成本远高于两枚小钮；先把「能挪」做出来 |
