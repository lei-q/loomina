# ADR-0110：自由工作台、按阶段收起的 UI 与确认后的硬锁

- 日期：2026-11-11
- 状态：已采纳
- 关联：F8、ADR-0023、ADR-0100、F2 / ADR-0109

## 背景

F8 已经落了七阶段的路由、底栏闸门与顶栏进度（ADR-0100），但当时明确留了三件没做：

1. **自由工作台切换**：ADR-0023 说「熟练用户可切到全部展开」，入口一直没做；
2. **按阶段隐藏无关 UI**：每个阶段页目前把记账、预算、导出、检查这些工具都摆在同一排，故事页和成片页看到的顶栏几乎一样；
3. **确认后的硬锁**：ADR-0100 当时把闸门做成纯提醒——确认之后还能随手改，只标「内容改过」。实践中这等于确认没有约束力，作者（包括我自己）会确认完继续改，下游按旧内容做的判断就静默失真。

## 决策

### 1. 两种模式，存在本机

`WorkbenchMode = "guided" | "free"`，存在 `localStorage["loomina.mode"]`，默认 `guided`。

- 顶栏右侧一个文字按钮切换：「自由工作台」↔「回到阶段式」，不弹窗、不解释一大段，靠名字和 title 说明。
- 自由模式下：阶段状态点、「下一步」、底栏闸门全部收起，标题旁挂一个「自由工作台」小签；阶段链接仍然可用（导航不消失，只是不再有向导语气）。
- 模式跨页面、跨刷新保持；两模式共享同一份 IR 与日志，切换不丢状态、不写事件（模式是界面偏好，不是项目内容）。

### 2. 按阶段收起工具

顶栏声明一张 `STAGE_TOOLS` 表，阶段式只露出本阶段用得上的：

| 阶段 | 工具 |
| --- | --- |
| 故事 | （无） |
| 剧本 | 导出 |
| 定妆 | 记账、预算 |
| 分镜 | 记账、预算、导出、预演、检查、表演、体检 |
| 关键帧 | 记账、预算、预演 |
| 声音 | 记账、预算、预演 |
| 成片 | 记账、预算、导出 |

自由工作台一律全开。理由：故事 / 剧本阶段还没开始出图，预算与记账只会让人提前焦虑；检查 / 表演 / 体检是分镜的工具，别的阶段摆着只会误点。撤销、历史、设置、模型切换是全局动作，任何模式都保留。

### 3. 确认后的硬锁

「确认」= 这一阶段定稿。阶段式下，已确认且确认之后没改过的阶段被锁住：

- **写状态的总闸口**：`workbench-store` 的 `set` 外面包了一层。凡是「在事件日志末尾接事件」的写入，先比一次各阶段的内容指纹（`stageSignature`）；某阶段确认时的签名与写入前一致、写入后变了，就拒绝这次写入，弹一条「「分镜」已确认：要改这里，先回退本阶段」的提示。
- **花钱前先拦**：生成是先请求、后落事件，等快照写回才拦就白花钱了。所以每个付费 / 调接口的动作（三视图、主镜、道具图、首帧尾帧、视频、配音、识别）开头单独过一次 `lockedStage`，被锁就一次请求都不发。
- **不锁的情况**：闸门自己的事件（`gate.confirmed` / `gate.reopened`）与全局回滚（`project.restored`）放行——它们本来就是用来动闸门的；已经「内容改过」的阶段不锁，改完重新确认即可；自由工作台不锁，全部展开就是拿来随手改的。
- **解铃**：底栏「回退本阶段」就是解锁，回退同时收起提示。被挡住的写入不写日志、不改项目，历史里查不到半截事件。

### 4. 自由工作台的时间线条

自由模式在分镜页底部多一条只读时间线条：每段显示序号、镜号、时长，点一段跳到那一镜，右侧「成片 →」。兑现 ADR-0023 的「分镜、预览、时间线同屏」——不新造一套编辑器，只把已有时间线读出来放在同一屏；初剪与换 take 仍在成片页。

## 后果

- 确认第一次有了实际约束：确认过的阶段不会在背后被改；想改必须显式回退，动作与代价都在底栏写着。
- 「内容改过」在阶段式下几乎不会出现（写入被拦，签名不会变），它主要出现在自由工作台改完之后切回来——这正是两种模式的分工。
- 代价：确认后再改多一步「回退本阶段」。这是有意的摩擦，和 ADR-0100「硬墙会逼人乱点确认」不冲突：墙只挡编辑，不挡导航，也不挡任何阶段的确认。
- 代价：硬锁依赖签名是完整的——不改变签名的字段（备注、预算、重试设置）照样能改，这是设计而不是漏洞：它们不属于那一段内容。
- 风险：按任意删除索引「放回」时若目标属于已确认阶段，补偿事件会被拦下并提示先回退（R44）。
- 与 ADR-0100 的关系：该 ADR 的「不做阶段硬锁、不做按阶段隐藏 UI」由本 ADR 取代，其余决定（签名口径、单镜预算、回退不级联）继续有效。

## 验证

- 单测 711 全过（IR 142 + gateway 28 + pipeline 51 + web 490）：新增 `stage-lock.test.ts` 8 条（拦截、自由模式放行、闸门事件放行、回滚放行、别的阶段不锁、stale 不锁、未确认不锁、`stageLockOf`）；`workbench-store.test.ts` 5 条（确认后写入被拦且日志不长、回退后可写且提示收起、自由模式可写且闸门转 stale、确认关键帧后生成一次请求都不发、自由模式改过再切回不锁）。
- `pnpm typecheck`、`next build` 全过。
- 浏览器（生产 3100）：阶段式顶栏 7 个状态点、底栏「可以确认 分镜」；确认分镜后跳到关键帧，回分镜底栏变「已确认 · 改内容要先回退本阶段」；在检查抽屉把节拍从 setup 改成 hook 被拦下、弹提示、历史仍只有 2 条事件；回退后再改成功；切自由工作台后状态点与底栏消失、出现「自由工作台」签与时间线条（2 段 / 0:06），改节拍直接生效；故事页阶段式下没有记账与预算，自由工作台下都有；刷新后模式仍记着。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 硬锁放在每个调用点 | 74 个写方法逐个加判断，漏一个就是一个静默后门；包一层 `set` 只有一处 |
| 确认后把页面变成只读 | 与「随时回退继续改」冲突；只读状态难以解释为什么按钮都灰了 |
| 模式存进项目 / 写事件 | 模式是视图偏好，不是创作内容；写进日志会让回滚与历史多出噪音 |
| 自由工作台新做一个合并编辑页 | 现有页面已经能做全部事，再搭一套编辑器是重复建设；先做「同一屏能看到」 |
| 锁只在 UI 层（禁用按钮） | 绕过 UI 的入口很多（快捷键、别人写的调用），锁必须落在写状态的唯一闸口 |
| 自由模式也锁 | 与「全部展开、随手改」直接矛盾；自由模式的价值就是可以乱来 |
