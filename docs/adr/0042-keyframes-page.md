# ADR-0042 关键帧页：一镜一张卡，首尾一眼看完

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0037 / 0038（首尾帧）、ADR-0041（锁定）、ADR-0026（审片台）、UX 5.5、FEATURES B2 / H21

## 背景

首帧、尾帧都接进分镜页了，但只能**一镜一镜看**：在胶片轨上点一格、切首 / 尾缩略格，才知道这一镜有哪几帧。十二镜的片要回答"哪些镜还没首帧"就得点十二次；顶栏导航里「关键帧」一直是个死链。

## 决策

1. **做一个整页纲览**：`/keyframes`，一镜一张卡（9:16 画面 + 两个按钮 + 一行小字），12 镜一屏看完。
2. **只读模型，不新开数据通道**：`toKeyframeView(project)` 内部就是 `toStageView`，卡片字段全部来自既有读模型（`keyframeUri` / `lastKeyframeUri` / `hasKeyframe` / `hasLastFrame` / `locked`）；组件不碰 IR。
3. **生成动作留在页面上**：每张卡两个按钮（首帧 / 尾帧），带价 `¥0.12`，直接调同一个 `generateKeyframe(shotId, frame)`——同一个 job key、同一条 `asset.updated` + `shot.updated`、同一个预算拦截。锁定的镜头按钮禁用并写明原因。
4. **点画面只切显示，不切生成目标**：两帧都有时点画面在首帧 / 尾帧之间切换；只有尾帧时优先显示尾帧。生成目标始终由按钮决定，避免"我点的是画面，花的是哪一帧的钱"。
5. **页头回答三个数**：首帧 n/12、尾帧 n/12、关键帧已花。已花只按 `a-keyframe-` / `a-lastframe-` 前缀的资产累加——这一页要回答的是"这两帧花了多少"，不是整片花了多少。没有价目的图单独计数（"无价目 n 张"），不当作零。
6. **导航接上**：「关键帧」从死链变成 `/keyframes`，当前页高亮。

## 理由

- **总览是这一阶段的真需求**：出图慢（实测 48–114 秒），一次只能做一帧，用户需要一边等一边看整体进度；逐镜翻页把"进度"藏起来了。
- **不新造状态**：卡片是读模型的投影，生成复用既有动作，事件日志不需要为这一页多写一个字。这也保证分镜页和关键帧页看到的永远是同一份项目。
- **价格放在动作上**：一页 24 个按钮，每个都标价，扫一眼就知道"全做满"要多少钱。
- **点和钱分开**：点画面是看，点按钮是花，两种点击不混。

## 后果

**正面**
- 十二镜的首尾帧进度一屏可见：页头 `首帧 1 / 12 · 尾帧 1 / 12 · 关键帧已花 ¥0.24`，卡片下方 `特写 · 仰拍 · 首✓ · 尾—`。
- 实测：在 SH-04 卡上点「首帧 ¥0.12」→ 遮罩"生成中…"，65 秒后真图替换剪影，页头变 `2 / 12`、`¥0.36`，顶栏 `¥19.32 / 60.00`，事件 13 → 15 条；刷新后图还在。
- 锁定的 SH-08 显示锁图标，两个按钮置灰。
- 测试：web 84 条通过（新增两条：卡片数量与首尾计数、关键帧已花只算两帧且无价目单列）；`pnpm typecheck`、`pnpm build` 通过。

**负面**
- **只能一帧一帧点**：没有"把缺的全补上"的批量队列；24 个按钮就是 24 次点击、24 次等待。
- **卡片按镜号排**：不能按"缺首帧 / 缺尾帧"筛，也不能重排；镜头多了以后仍要滚。
- **没有视频**：这一页只到两张静帧，图生视频接通后才会出现"由首尾帧生成"的入口。
- **关键帧的花费按 id 前缀认**：如果将来别的功能也用 `a-keyframe-` 前缀写资产，这个数会串。
- 切首 / 尾的显示状态是组件内的临时状态，刷新回到首帧（与分镜页一致）。

**跟进**
- 批量补帧队列（选缺的、排上队、一次跑完）。
- 按缺帧筛选 / 只看未完成。
- 卡片上直接进视频生成（等 B3 接通）。
- 关键帧的历史版本（重生成会覆盖同一资产位，旧图只留在事件日志里）。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 只加强分镜页的缩略条 | 进步是"这一镜有没有帧"，回答不了"整片还差哪些" |
| 新开一个 `keyframes` 事件 / 独立存储 | 关键帧就是 `Shot.keyframes` + `assets`，复制一份会让回放分叉 |
| 卡片上点画面即生成 | 看和花混在一起，误点就扣钱 |
| 页头复述整片已花 | 顶栏已经有整片数；这一页缺的是"为了两帧花了多少" |
| 一次生成全部缺帧 | 没有队列与并发控制，慢请求叠在一起会撞超时与预算，先做单帧 |

## 附记（2026-11-10）：按缺帧筛选

原方案的负面里写着"卡片只按镜号排，不能按缺首帧 / 缺尾帧筛"。补一排筛子：`全部 12 · 缺首帧 10 · 缺尾帧 11 · 两帧齐 1`，点哪个看哪个，计数就写在筛子上。

- 筛的是读模型投影：`filterKeyframeCells(cells, filter)` / `keyframeTally(cells)` 都是纯函数，不碰 IR、不写事件。
- 默认「全部」；筛选状态是组件内临时状态，刷新回到全部（与"看到哪一帧"一致，不写日志）。
- 空结果不装死：`两帧齐` 为空写"还没有两帧都齐的镜头"，缺帧档为空写"想看的帧都已经有了"。
- 计数与筛子同源，页头的 `首帧 n / 12` 仍是整片覆盖，两个数不会互相矛盾。

## 附记（2026-11-10）：批量补缺

原方案的负面第一条是"只能一帧一帧点"。补两个批量按钮：页头右侧 `补缺首帧 9 张 · ¥1.08` / `补缺尾帧 9 张 · ¥1.08`，点一下按镜号顺序把缺的这一帧补完。

- **顺序**：按整片镜号；**跳过锁定的镜头**（批量不是绕过闸门）；每张落地后进度 `补首帧 n / m` 加一。
- **失败即停**：任何一张失败（含超预算拦截）就把进度清掉停下来，不留"后面继续失败、继续花钱"的队列。错误仍走既有的一行人话。
- **停下**：进度旁边一个「停下」；**当前这张已经发出去了，停下在它结束后生效**，按钮随即显示"停下中…"。
- **不插队**：批量进行中，每张卡上的单帧按钮全部禁用；反之有单帧在跑时批量按钮也不可用（代码里以 `get().batch` 早退）。
- **不持久化**：批量状态在内存里，刷新 / 关页就停（已落地的图与事件都在）。
- **顺手修的 bug**：失败说明的镜号原本用 `shot.index`（场内序号），第二场以后会报错镜号——实测 SH-05 超时被说成「SH-02」。现在按整片顺序算，新增一条测试钉住。

**实测**：SH-01、SH-02 两张分别约 60 秒与 48 秒落地；第三张（SH-05）请求 170 秒超时中止，批量随即停下。首帧 2 / 12 → 4 / 12，关键帧已花 ¥0.36 → ¥0.60，事件 18 → 22 条，按钮变 `补缺首帧 7 张 · ¥0.84`。超时那张没有落图、没有事件，钱没花。

**负面（新增）**
- 不能挑哪几张，能补就是全补（靠锁定排除不想动的镜头）。
- 一张一分钟上下，九张要十几分钟；没有后台任务，切走或刷新就中断。
- 失败只保留最后一次的说明，批量里哪一张失败要从进度与缺口反推。
