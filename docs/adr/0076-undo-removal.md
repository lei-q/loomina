# ADR-0076 删除的撤销

- 状态：已接受
- 日期：2026-11-11
- 决策者：用户 + Claude
- 关联：ADR-0011（只追加事件日志）、ADR-0061（地点删除）、ADR-0067（镜头与场次删除）、ADR-0073（人物与道具删除）、FEATURES F2

## 背景

删除是真删：人物、道具、地点、场次、镜头删掉就没了，日志里只留一条 `*.removed`。误删一个写着三句台词的人物，只能重新建、重新取名、重新写清单，再逐镜重新挂——ADR-0073 / ADR-0075 都把"删除的撤销"记成了跟进项。

事件日志是只追加的（ADR-0011）：过去的事件不能被改写。所以"撤销"不能是"把那条 `removed` 从日志里删掉"，只能是"往后追加一条把东西放回来的事件"。

## 决策

1. **撤销 = 追加补偿事件，不回滚日志**：复用已有的 `character.added` / `prop.added` / `location.added` / `scene.added` / `shot.added`，加上 `dialogue.added` / `take.added` / `shot.updated`。IR 不新增事件类型，`applyEvent` 不改。
2. **只撤"最近一次还缺着的删除"**：新增读模型 `undoableRemoval(events, project)`，从日志末尾往回找第一条被删对象仍然不存在的 `*.removed`；已经被恢复过（对象又在了）的跳过。因此撤销天然按删除的逆序走，撤销之后再点一次就撤更早的那条。
3. **按删除之前那一份项目复原**：标签、场号、镜号、台词顺序都取 `rebuild(events.slice(0, index))`——删除事件之前的那份项目。
4. **各类型的复原规则**：
   - 人物 / 道具 / 地点：原样写回 `*.added`（id、名字、描述、「不许变」清单都在删除前的快照里）。
   - 场次：放回**空场**。删场本来就要求先把里面的镜头逐条删掉（ADR-0067），所以场次复原之后，它的镜头是另一条待撤销的删除。`index` 取删除前的场号，超出当前场数时放在末尾。
   - 镜头：先按原 `index`（不超过这场当前的镜数）放回，再按原 `dialogueIds` 逐条 `dialogue.added`，逐个 `take.added`，最后 `shot.updated { dialogueIds }` 复原句子顺序；选中跳到这一镜。镜头所在的场次也已经被删时**拒绝**，报「这一镜原来在第 N 场，那一场也删了：先撤销那一场。」
5. **资产不用管**：删除本来就不清理三视图、主镜、参考图（ADR-0061 / ADR-0073），引用一回来就重新看得见。
6. **界面**：页头错误下面一行「刚删掉人物「X」」+ `撤销`。定妆页只管人物 / 道具 / 地点，剧本页只管镜头 / 场次——两边各管各的，不相关的那一类不会冒出来。只读标签页不显示。撤销失败（比如场次没了）把原因写到页头。
7. **没有撤销栈**：只有"最近一条"，不记撤销本身的历史。再删一次，之前那条就撤不了了（对象仍缺着，但被新删除盖住）——恢复入口始终是"最后一条"。

## 理由

- **只追加**：回滚日志会让事件序号、时间与下游推导全部失去意义；补偿事件是日志本身能表达的动作。
- **不新增 IR 事件**：`character.removed` 的反面就是 `character.added`，信息完全够；新开一条 `character.restored` 只会让重放多一个分支。
- **取删除前的快照**：删除之后对象已不在项目里，名字、场号只能从日志前缀重建——读模型已经会算，store 直接用。
- **一步一条**：用户刚删错，点一下就能回来；不做多步撤销栈，是因为界面只有"刚刚删掉"这一行的位置，多步历史需要另一个面板，而 ADR-0071 已经规划了"用这版"的历史回退。

## 后果

**正面**
- 定妆页删「阿棠」→ 页头出现「刚删掉人物「阿棠」 撤销」→ 点 `撤销`，整行带着原 id、「不许变」清单与已出的图回来。
- 剧本页删 SH-01（含台词、take）→ 点 `撤销`，镜头回到原来的位置，台词按原顺序回来，页面选中跳到这一镜。
- 先删镜再删场：第一次 `撤销` 放回空场，第二次 `撤销` 放回镜头与出场——两步正好是删除的逆序。
- 日志里看得到完整的"删了又放回"：`*.removed` 后面跟 `*.added`，重放得到同一个项目。
- 测试：web 205（新增 9：store 4、读模型 5）、IR 94、gateway 17、pipeline 22，合计 338。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：定妆页新建「试撤销」再删 → 页头出现撤销行 → 点 `撤销`，人物回到列表；剧本页删 SH-01 → 页头「刚删掉 镜 SH-01」→ 点 `撤销`，镜头数从 2 回到 3，台词与出场随之回来。

**负面**
- **只能撤最后一条**：连续删三个人，只有第三个能撤；撤完第三个，第二个才轮到。
- **撤销写的是新时间**：日志里补偿事件的时间是点击时刻，不是当初创建的时刻；看日志会看到"人物后来才加的"。
- **场次复原是空的**：先删场的镜头再删场，要撤两次；不会一步把场和镜头都放回来。
- **镜头的场次没了就撤不了**：报错让用户先撤场次。
- **不做确认**：点 `撤销` 立即写事件，没有弹窗；撤销本身也可以再被删除。
- **只读标签页看不到撤销行**：只读标签页本来就不能删，没有要撤的东西，但一行提示也没有。

**跟进**
- 多步撤销 / 回收站（保留最近 N 条删除，跨页面列出）。
- 撤销后把对象高亮一下，让人确认"是这一个回来了"。
- 镜头的场次被删时，能不能自动连带把场次也放回来（现在要两次）。
- 孤儿资产回收：删除不清理资产的问题仍在（ADR-0073 跟进）。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 把 `*.removed` 从日志里截掉 | 违背只追加（ADR-0011），事件序号与时间线都会乱 |
| 新增 `character.restored` 等事件 | 与 `character.added` 语义重复，重放多一套分支 |
| 软删除（`archived` 标记） | 读侧、提示词、必锁统计都要认这个标记；改动面比补偿事件大 |
| 内存里的撤销栈 | 刷新就丢，与"日志是事实"的原则不一致 |
| 一步撤销把场次连同镜头全放回 | 删场时镜头是逐条删的，一次放回等于绕过删除规则，日志也对不上 |
| 撤销前弹确认 | 撤销是"回到刚才"，多一步确认反而打断；写错再删一次就好 |
