# ADR-0213：任选历史空间当「照设定开工」的来源（C22 第二档）

- 状态：已采纳
- 日期：2026-11-14
- 决策者：用户 + Claude
- 关联：C22、C15、A6、ADR-0197、ADR-0210

## 背景

ADR-0197 落地时把「只能照当前空间开工」写进了负面后果。但代码里那行下拉从一开始
就是 `workspaces.map(...)`，也就是**本机登记表里的所有空间**，并不只是当前那一个。
于是留下两处不一致：

1. 文档说「不能从任意历史空间挑」，实际能挑，作者不知道哪个是真的；
2. 归档的空间（ADR-0210 说归档就从复用清单里收起）照样出现在来源下拉里，
   而且它排在列表里、和别的空间长得一样。

此外还有两个小毛病：每行选项都重复一遍「带故事 / 演员 / 场景 / 道具，不带成片」，
下拉一展开就是五行同样长的字；选了一个空日志的空间，报的是 `rebuild` 的
「事件日志为空」，作者不知道是哪个空间的问题。

## 决定

1. **任选来源这件事正式成立**：下拉列出登记表里所有**未归档**的空间，顺序沿用
   登记表（最近打开在前）。选谁就是照谁的设定开工，与当前打开的是哪个空间无关。
2. **归档空间不能当来源**：`setupSourcesOf(metas)` 过滤掉 `archivedAt` 有值的。
   这与 ADR-0210 的「从复用清单里收起」是同一口径——归档就是暂时不想它再被取用。
3. **判定抽成纯函数**：`setupSourceProblem(metas, fromWorkspaceId)` 返回拒绝理由
   （找不到 / 已归档 / 不是问题）。顶栏下拉的过滤与 `createWorkspace` 的校验
   共用这一份，不在两处各写一遍。
4. **报错说清是哪个空间**：
   - 找不到：「找不到这个来源空间。」
   - 已归档：「「X」归档了，先取消归档再照它开工。」
   - 空日志：「「X」还没有任何内容，没有设定可以照。」——不再暴露 `rebuild` 的内部措辞。
5. **下拉文案收敛**：每行只写「照「{名字}」的设定开工（第 N 集）」，共同说明挪到
   下面一行：「照设定开工只带故事 / 演员 / 场景 / 道具 / 技能 / 风格，不带成片。
   可选 N 个；归档的空间不在里面。」

## 理由

- **能力本来就有，缺的是口径**：与其删掉这个能力去迁就文档，不如把它说清楚、
  补上该有的边界。作者开下一集时想照的往往是上一集或更早那一集，不一定是
  现在正开着的这一份。
- **归档要一致**：ADR-0210 把归档定义成「从复用清单里收起」，C16 / C20 / C21 /
  C22 / C23 / C24 都按这个口径过滤。来源下拉漏了它，归档就只挡了一半。
- **纯函数才好测**：store 的测试环境没有 IndexedDB，判定逻辑留在 store 里就只能
  靠浏览器实测；抽出来之后「找不到 / 归档 / 正常」三种情况都是单元测试。

## 后果

**正面**

- 文档与代码一致：任选来源是已做的事实，不再是「未做」。
- 归档的空间不会再被拿来开工，与别的复用入口口径统一。
- 下拉短了，一眼能看出有几个来源；空日志与归档都有专门的话。

**负面 / 代价**

- 仍然是**建空间那一刻的快照**：来源空间后来改了设定，已经建好的不会跟着变。
- 集序只在同系列里排：照一个别的系列的空间开工，新空间会进那个系列、排下一集，
  不会自动变成新系列的第一集（A6 的口径，改系列是另一档）。
- 来源列表只按「最近打开」排，没有搜索与分组；空间一多就要靠名字认。
