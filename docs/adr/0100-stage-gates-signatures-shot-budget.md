# ADR-0100：阶段闸门、内容指纹与单镜预算

- 状态：已采纳
- 日期：2026-11-11
- 关联：F8、F9、H10、A9、ADR-0023、ADR-0028、ADR-0035、ADR-0096、R37

## 背景

`UX.md` 从第一版起就写着「阶段式是默认路径」：顶部阶段条、每阶段只露该阶段要的东西、底部确认条、确认后可回退。但实现一直是散的：定妆页有自己的「没锁完不能进分镜」底栏，别的阶段没有确认概念，顶栏只有七个链接，作者不知道走到哪、下一站是什么、刚才确认过的东西后来有没有被改掉。

`FEATURES.md` 里 F8「阶段式创作流」与 F9「闸门确认组件」仍是「待设计」；H10 只做了项目级预算（ADR-0035），镜头级上限与重试上限没动；A9 的声音确认也没有落点。`ADR-0096` 把 Beat 与覆盖率的硬闸门留给 F8 / F9 之后再收紧。

现实约束：

- 单人开发，C 端用户，不能要求作者理解事件日志或签名；闸门必须一眼看懂。
- 阶段之间不是硬依赖（没有首帧也能先配音），把导航做成硬墙会挡住真实创作顺序。
- 确认之后内容会变，系统不能假装没发生，也不该静默把确认记录改掉。
- 单镜预算要能按住「反复重抽一镜」的浪费，但文本模型按 token 计价、单价未知（R28），只能对知道单价的图像 / 视频生成设硬上限。

## 决策

### 1. 七个阶段，固定顺序，与路由一一对应

`apps/web/lib/stage-flow.ts` 定义 `STAGE_META`：故事 `/story` → 剧本 `/script` → 定妆 `/cast` → 分镜 `/` → 关键帧 `/keyframes` → 声音 `/voice` → 成片 `/edit`。每阶段带中文名、确认按钮文案、「这次确认锁住什么」与「确认后再改的代价」。

顺序是叙事生产的默认路径，不是权限。任何阶段都能直接点进去，顶栏与底栏都不拦导航。

### 2. 确认记录进 IR：`Project.gates`

```ts
interface GateRecord {
  stage: "story" | "script" | "cast" | "storyboard" | "keyframes" | "voice" | "edit";
  signature: string;   // 8 位 hex，确认时这一阶段内容的指纹
  at: string;          // ISO 时间
  note: string;        // 作者备注，≤240 字，默认空
}
```

`Project.gates: GateRecord[]`，同一阶段只保留一条（确认即覆盖）。写入只走两条事件：

- `gate.confirmed { stage, signature, note? }`：签名必须是 `/^[0-9a-f]{8}$/`，备注裁到 240 字；按 stage upsert。
- `gate.reopened { stage }`：只删这一阶段的记录，不碰下游。

确认与回退都追加事件，不回滚日志；旧项目没有 `gates` 字段，zod 默认 `[]`，`LOG_VERSION` 仍为 1。

### 3. 内容指纹：只哈希这一阶段管的东西

每个阶段一个 `fnv1a(JSON.stringify(...))`：

- 故事：标题 + `Project.story` 全量。
- 剧本：场次结构、镜头的描述 / 时长 / `dialogueIds`、台词表。
- 定妆：角色外观与三视图、场景主镜、道具参考图，**外加 approvals**——确认的是「都锁好了」，解锁必须让确认失效。
- 分镜：场序、镜序、景别、机位、动作、人物 / 道具、时长。
- 关键帧：每镜首尾帧资产与全部 take 的资产 / 状态。
- 声音：每个角色的 `voiceProfileId` + 每句台词文本、时长与音轨资产。
- 成片：时间线 items、配乐、用到的 take 资产。

资产不整串进哈希：`assetStamp` 用 `id / costCny / provenance.createdAt / provenance.modelId / uri.length / uri 末 24 字符`。同一 id 覆盖写时 URI 尾部会变，足够判断「换过没有」，又不会把几 MB 的 data URI 拉进 JSON。

指纹只用于判断确认后有没有改过，不是内容校验、不是安全边界，也不跨项目比较。

### 4. 闸门是提醒，不是硬墙

每阶段三态：

- `none`：还没确认过；
- `confirmed`：有记录且签名一致；
- `stale`：有记录但签名对不上，显示「内容改过 · 需要再确认一次」。

准备度三档：`empty` / `partial` / `ready`，只有 `ready` 才能确认。未达条件时按钮灰掉并写明还差什么（例如「11 镜还没有首帧」「4 句还没有配音」），但**导航自由**：作者可以直接点去下一阶段，那里显示未确认。

顶栏每个阶段链接带一个 4px 状态点（已确认实心、改过用强调色、未确认空心），右侧固定「下一步 · X →」，指向第一个没确认（或确认后改过）的阶段。

每页底部 `<footer aria-label="阶段闸门">`：状态标签 + 一句现状 + 缺失项 / 确认日期 / 备注 + 操作。未确认时打开 `GateConfirm` 弹层，写清这次锁什么、确认后再改会影响什么、还差什么，备注可留；已确认时给「进入下一阶段 →」与「回退本阶段」。

确认后自动 `router.push` 到下一阶段；回退只写 `gate.reopened`，下游各自因为签名对不上显示「内容改过」，不级联删除任何确认。

### 5. 单镜预算：`Shot.budgetCny`

```ts
interface Shot {
  budgetCny?: number;   // 正数；不写就只受项目预算约束
}
```

- `shot.updated` 的 patch 可带 `budgetCny`；`≤0` 或非有限数在 applyEvent 里直接抛错，`undefined` 表示清除上限。
- `shotSpendOf(project, shotId)` 现算已花：该镜所有 take 的 `costCny` + 首尾帧资产的 `costCny`；take 引用的视频资产不重复计入（成本已经记在 take 上）。
- 生成前两道拦截：项目预算（原有）→ 单镜上限。图像 / 视频都在发请求之前算，超了直接返回 false 并写清「「SH-03 近景」超出这一镜的上限：已花 ¥2.74 + 本次 ¥0.12 > ¥0.50」，一次请求都不发。
- 分镜页每镜提示词下方一个「单镜上限 [ ] 元 · 已花 ¥x」，超了显示「已超上限」；空值表示清除，回车提交、Esc 还原。

文本生成（故事 / 剧本草稿）不设单镜上限：文本模型按 token 计价且单价未知，硬拦只能编一个假价格。重试次数上限与降级路径仍未做（见「不做的部分」）。

### 6. A9 收尾：声音确认就是 voice 闸门

声音阶段的准备度 = 每句台词都有 `audioAssetId` 且指向存在的 `audio` 资产。全部有声才 `ready`，才能确认；台词为空是 `empty`，部分有声是 `partial`。确认锁住的是「每句台词的音轨 + 每个角色的音色」，签名同时覆盖 `voiceProfileId` 与台词文本 / 时长 / 音轨资产，换音色或改台词都会让确认转为 `stale`。

定妆闸门取代了原页面底部的「定妆没锁完，分镜不开」：必锁锚点没锁完时确认按钮灰掉，但仍可直接进分镜，语义从硬墙改成提醒（与阶段闸门一致）。

### 7. 明确不做的部分

- 不做阶段硬锁、不做按阶段隐藏 UI（「自由工作台」入口仍未做，F8 只落了阶段底栏与顶栏进度）。
- 不自动重写下游：改故事不会自动重写剧本，只让下游标「内容改过」。
- 不做级联回退：回退本阶段不删除下游确认记录。
- 不做服务端强制：预算拦截在客户端 store，服务端渲染链路只按清单执行。
- 不做文本单镜上限、重试次数上限、超限降级（H10 剩余项）。
- 不把闸门接入导出预检：G8 的合规预检独立判断，不能用「阶段已确认」代替。

## 理由

- 确认记录必须是 IR 的一部分，否则换浏览器、清 IndexedDB、导出项目都会丢；事件化后可以回放、审计，也符合「日志是唯一事实来源」。
- 用内容指纹而不是 `updatedAt` 判断过期：只改别的阶段不该让这一阶段失效，改标题也不该让定妆失效。逐阶段签名让「哪一段真的变了」可解释。
- 资产戳不哈希整串 data URI：浏览器内存与哈希耗时都会随图片体积爆炸，而 id / 成本 / 来源 / 长度 / 尾部已经能区分覆盖写。
- 闸门做提醒而不是硬墙：真实创作会跳阶段（先配音再补画面），硬墙只会逼作者关掉检查或乱点确认。把「未确认」显示出来，比替作者做决定更诚实。
- 单镜上限只对有价目的模态生效：这是唯一能给出真实数字的拦截；对未知单价硬编一个数会制造假精确。
- 声音确认必须看音轨资产是否存在：只看 `audioAssetId` 字段会让失效引用也过关，准备度检查与签名都同时看资产表。

## 后果

**正面**

- 七个阶段可完整操作验证：分镜页确认 → 自动进关键帧；返回分镜显示「已确认 · 确认于 11-11 · 进入关键帧 → · 回退本阶段」；用一句话指令改一镜后立刻变「内容改过 / 重新确认」。
- 未满足条件时按钮灰掉并说明原因：关键帧「1 / 12 镜有首帧 · 11 镜还没有首帧」，声音「0 / 4 句有声 · 4 句还没有配音」。
- 单镜上限实测：设 `SH-03` 为 ¥0.5，页面显示「已花 ¥2.74 · 已超上限」；刷新后值仍在，IndexedDB 里是 `shot.updated { budgetCny: 0.5 }`。低于已花的生成会在请求前被拦。
- 顶栏状态点与「下一步」让作者随时知道走到哪；旧项目没有 `gates` 也能正常回放。
- 测试：IR 122 + gateway 28 + pipeline 30 + web 412 = 592 全过；`pnpm typecheck` 与 `next build` 全过。

**负面**

- 签名是启发式的：改了不影响这一阶段语义的字段（例如备注、界面状态）不会让闸门过期；反过来，重排同内容也可能改变指纹。它只回答「和确认时是不是同一份内容」，不回答「改得好不好」。
- 确认不会锁住编辑：作者确认后仍可改，系统只标「内容改过」，不阻止、不自动重做下游。
- 单镜上限只在客户端生效，绕过 UI 直接调接口不受约束；服务端渲染按清单执行，不做预算复核。
- 文本、配音、seedance 视频仍没有可靠单价，无法设单镜硬上限；R28 未解决前，H10 只能算部分完成。
- 资产戳取 URI 末 24 字符，理论上存在不同内容尾部相同的情况；概率极低，且闸门不是安全机制。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 确认状态只存 localStorage | 换浏览器、清缓存、导出项目就丢；无法审计「什么时候确认的」 |
| 用 `Project.updatedAt` 判断过期 | 改任何字段都会让全部阶段过期，作者会被无意义的「内容改过」淹没 |
| 每阶段存完整快照 | 体积随项目线性增长，且无法解释是哪一处变了 |
| 哈希完整资产 data URI | 大图会让签名计算卡顿、内存翻倍；尾部 + 元数据已足够 |
| 阶段硬锁，未确认不能进下一阶段 | 真实创作会跳阶段；硬墙会逼作者乱点确认，确认就失去意义 |
| 确认时自动锁定内容 / 禁止编辑 | 与「永远给再看看、可回退」冲突；也会让改一个字必须整段重来 |
| 回退时级联清除下游确认 | 下游可能已经基于旧内容做完，静默删除会丢信息；让它们显示「内容改过」更诚实 |
| 单镜上限对所有模态生效 | 文本按 token 计价未知，只能编假价；假精确比不拦更糟 |
| 服务端也强制预算 | 当前渲染链路按清单执行、没有生成调用，服务端强制没有落点；等生成服务化后再补 |
| 把阶段确认接进导出预检 | 阶段确认是创作节奏，合规预检是发布责任，两者不能互相替代 |
