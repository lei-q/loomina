# ADR-0055 恢复被删的台词：从删除事件里把那一句捞回来

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0045（删句）、ADR-0054（跨镜头挪台词）、ADR-0053（镜头级历史）、FEATURES A5 / A21

## 背景

台词能删，删了就没了。`dialogue.removed` 只带 `lineId`，正文没有了——想找回只能翻日志、手打回去（还没了原来的 id）。ADR-0051 / ADR-0052 / ADR-0053 已经给动作、换人、排序都做了「看得见、回得去」，删句是这条线上唯一的缺口；ADR-0045 的负面清单里也写着「删掉的句子找不回来」。

## 决策

1. **不新增事件**：正文从快照的 `project.dialogue` 与 `dialogue.added` 里按 id 找回；归属镜头从快照的 `dialogueIds`、加句事件的 `shotId`、之后的数组改写（排序 / 挪句）里跟出来。`dialogue.removed` 之后这一句从这两张表里划掉，于是每条删除记录记下的是「删那一刻的正文与镜头」。
2. **读模型 `removedLines(events, shotId?)`**：从旧到新返回 `{ at, lineId, shotId, text, characterId, durationMs }`；不给 `shotId` 就是全片。同一句删了又恢复又删，会有两条记录（历史只增不减）。
3. **store `restoreLine(lineId)`**：取这一句最后一次删除的记录，写 `dialogue.added`（原 id、原正文、原说话人、原时长）+ 一条 `shot.updated { durationMs }`（加回这一句）。拒绝：只读、这一句已经在项目里（`这句已经在台词里了。`）、没有删除记录、原镜头不在了、镜头锁定。
4. **回原镜队尾**：恢复不改位置，接在镜头现有台词之后——这是加句的语义，不是「回到原来的第几位」。
5. **界面**：镜头台词下方、顺序折叠之后，一行 `删过 n 句` 折叠；展开倒序，每行 `时间 删除线正文` + `恢复`。这一句已经恢复过的记录按钮置灰（`这一句已经恢复了`），锁定镜头置灰并说明。
6. **时长照旧加回**：恢复就是一次加句，`shot.durationMs + line.durationMs`，与 ADR-0045 对称。

## 理由

- **日志本身就是备份**：正文一直在快照或 `dialogue.added` 里，只是没人读。再建一张「回收站表」就有了第二个真相来源。
- **删除记录放镜头下**：用户是在某一镜里删的，找也在那一镜找；跨镜头挪过的句子记在挪完之后的镜头。
- **原 id 恢复**：这一句的改写历史、换人历史挂在 `lineId` 上；换新 id 等于让历史断掉。
- **队尾而不是原位**：原位要再记一个 index，而且期间别的句子动过之后原位已无意义；加句的语义用户已经熟悉。
- **恢复是一次新事件**：与所有回退一致，不抹掉「删过」这件事；所以 `删过 n 句` 的记录会一直在，只是按钮置灰。

## 后果

**正面**
- SH-03 删掉「门开着呢。」：台词 6 → 5 句、全片 35.6s → 34.1s、这一镜 3.9s → 2.4s；镜头下出现 `删过 1 句`。
- 展开点`恢复`：这一句原封不动回到 SH-03 队尾（同 id、同说话人、同 1.5s），镜头回到 3.9s、全片回到 35.6s、台词回到 6 句；`删过 1 句` 留着，`恢复` 置灰。
- 日志多两条（同一时间戳）：`dialogue.added` 带整句 + `shot.updated { durationMs }`；回放与刷新后一致。
- 测试：web 136 条（新增 5 条：删除记录取值、按镜头筛、删第二次两条记录；恢复与回放、四种拒绝）；IR / gateway / pipeline 不变，合计 237。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：headless Chrome 删 SH-03 一句、展开`删过 1 句`、点`恢复`；IndexedDB 第 35、36 条为 `dialogue.added` 与 `shot.updated`。

**负面**
- **触到 500ms 地板时不可逆**：删的时候若 `镜头 − 这一句 < 500`，镜头被抬到 500ms；恢复再加回整句时长，会比原来长。示例里就出现过一次（2400 → 500 → 2600）。这只有在镜头本来就短于「台词 + 500ms」时发生，属于已经不自洽的数据；但确实破坏了「删完再恢复 = 原样」。
- **恢复只能回原镜**：想「删掉再放到另一镜」要先恢复再挪，两步。
- **位置不保留**：回到队尾，原来在第几句没有记。
- **删除记录会一直堆**：`删过 n 句` 只增不减，恢复过的也不清理。
- **不记谁删的、为什么删**：只有时间与正文。
- **句子文本是删那一刻的**：删之前改过几次，折叠里只看到最后一版。

**跟进**
- 恢复后允许「放到指定位置」。
- 镜头级时间线把加句 / 删句 / 挪入 / 挪出 / 排序合成一条（ADR-0054 / ADR-0053 的跟进汇到这里）。
- 删除记录折叠合并同一句的多次删除。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 新建 `line.trash` 回收站 | 日志里已经有正文，再存一份会打架；`dialogue.removed` 也还要写 |
| 在 `dialogue.removed` 里存整句 | 改事件形状要升 `LOG_VERSION`，而正文可从快照 + `dialogue.added` 复原 |
| 恢复时新建 id | 这一句的历史（改写、换人）挂在旧 id 上，换 id 等于让历史断掉 |
| 恢复回原来的位置 | 需要额外记 index，期间别的句子动过之后原位已无意义 |
| 恢复即「撤销删除事件」 | 历史只增不减；抹掉删除记录会让「删过几次」说不清 |
| 只给最新一次删除一个按钮 | 同一句删过多次时，用户可能想回到更早那一版（更难，先记下时间与正文） |
