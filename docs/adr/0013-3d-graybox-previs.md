# ADR-0013 3D 灰盒场景板（Previs）作为空间与机位的依据

- 状态：已接受
- 日期：2026-11-09
- 决策者：产品 / 工程
- 关联：P3、P11、P13、B11、B13、L3、R25

## 背景

AI 生成是"逐镜独立想象"的：同一场戏，每个镜头都可能重新发明房间、人物位置和朝向。结果是：

- 人物左右关系跳变（越轴）；
- 同一空间在不同镜头里地理不一致；
- 机位与焦段靠猜，运镜不可控；
- 无法给关键帧提供结构约束。

2D 文字/参考图只能缓解"长什么样"，解决不了"在哪里、朝哪、从哪拍"。

## 决策

引入 **3D 灰盒场景板（gray-box previs）**：

1. 用简单几何体搭场景（房间、街道、办公室等模板）。
2. 人物用胶囊 + 朝向箭头表示，不追求写实。
3. 相机用真实焦距可视化视锥，直接得到机位、朝向、焦段。
4. 自动检查 180 度轴线；导出 `Blocking` 与 `CameraPlacement` 到 IR。
5. 可渲染 depth / edge / normal 参考图，作为关键帧生成的结构条件。
6. **自动优先**：系统先按剧本自动摆位与布机，用户只做调整，不强制手动搭场景。

## 理由

- 空间一致性无法靠提示词解决，必须有一个显式的空间模型。
- 3D 让"越轴"从审美判断变成可校验的几何错误（V3）。
- 机位/焦段可直接映射到 `CameraSpec`，减少"猜参数"。
- 结构条件（depth/edge）能显著提升关键帧的构图可控性。
- 与"摄影语言可量化"（P11）一致。

## 后果

**正面**
- 空间与轴线一致性大幅提升。
- 分镜可计算、可校验、可复现。
- 为后续虚拟制片/多机位复用打基础。

**负面 / 代价**
- 增加开发量（3D 编辑器、场景模板、相机推导）。
- 用户可能不想调 3D；必须自动生成初稿。
- 灰盒与最终画面的差距需要用户理解（明确标注"预演"）。

**跟进**
- MVP 只做**最小版**：5–10 个场景模板、自动摆位、机位视锥、轴线检查、depth 导出。
- 完整编辑（移动/旋转/路径/多机位）放 Phase 1。
- 评估 WebGL/WebGPU 在浏览器内的性能；必要时用 Three.js + 离屏渲染。

## 替代方案

- **2D 俯视图**：更简单，但无法表达机位高度、焦段、遮挡，否决为最终方案。
- **纯文字走位描述**：不可校验，否决。
- **写实 3D 场景**：成本过高，且与生成画面风格冲突，只做灰盒。
