# ADR-0037 首帧先落成一张图：分镜页能生成关键帧

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0029（锚点）、ADR-0032（出图路由）、ADR-0035（预算）、ADR-0033（成本）、B2、DATA-MODEL `Shot.keyframes`

## 背景

分镜页（审片台）到 ADR-0036 为止只能**审**不能**生成**：画面永远是剪影，重做按钮是灰的（`生成还没接通`）。视频生成本身被供应商配额挡住（`17003 AI token quota exceeded`），所以"点一下出一段视频"今天做不出来。

但视频之前的这一步是通的：图片接口 2026-11-10 已恢复，单张出图 20–45 秒、¥0.12。**首帧是关键帧里最便宜、也最能验证"这一镜长什么样"的一步**——先把它做成用户能点的动作。

## 决策

1. **`Shot.keyframes` 进 IR**：`{ firstAssetId?, lastAssetId? }`，zod 默认 `{}`。文档里早就写了这个结构（DATA-MODEL 第一节），实现补上。老日志靠默认值补齐，`LOG_VERSION` 仍为 1。
2. **首帧就是一条 `asset.updated` 加一条 `shot.updated`**：资产 id 固定为 `a-keyframe-<shotId>`，重生成按 id 覆盖，不堆垃圾；`shot.updated` 的 patch 只写 `keyframes: { firstAssetId }`，其余结构不动。
3. **提示词与镜头提示词同源**（`buildKeyframePrompt`）：把 `buildShotPrompt` 拆成"原料 → 句子"，两者共用同一段 `shotParts`，只多一句"首帧画面，动作起势，无字幕，无文字，无水印"。人物 `mustNotChange` 照旧原样带上。
4. **服务端仍只收业务字段**：`POST /api/asset` 新增 `kind: "keyframe"`，请求体是 `{ description, shotSize, camera, characters[], location?, props[] }`，**没有 id**（ADR-0032 的约束不变）。服务端用 `CameraSchema` 与 `shotSize` 校验机位参数。
5. **溯源记下锚点**：资产 `provenance.referenceAssetIds` 填这一镜已锁定的锚点资产 id（人在前、场景、道具），即使当前接口还不能带参考图送进模型——将来能送时，账已经在。
6. **界面：画面即首帧**。有首帧时画面位置显示真图，剪影退场；没首帧时显示"生成首帧 ¥0.12"，有首帧时显示"重生成首帧 ¥0.12"；生成中盖一层"生成中…"；镜头锁定时按钮换成"镜头已锁定 · 只读"。
7. **预算闸门复用**（ADR-0035）：首帧走同一条 `generateOne`，超预算一次请求都不发，报错里点名 `SH-03`。

## 理由

- **一步一个可点**：视频没通之前，首帧是唯一能让用户看到"我的镜头真的长这样"的闭环。先做它，分镜页才不是一张假界面。
- **首帧落到镜头上，而不是只落到资产库**：资产本身就是产物（ADR-0033），但"这一镜用哪张首帧"是项目结构，必须可回放——所以多一条 `shot.updated`。
- **重生成覆盖同一 id**：一条镜头只有一个首帧位置；堆多个资产会让"当前首帧是哪张"重新变成一个需要解释的问题。
- **提示词同源**：两处各写一套镜头描述，迟早漂移成两个镜头。
- **锚点进溯源**：现在带不进去，不代表不该记；ADR-0029 的锚点是这一镜生成的依据，溯源里缺了它，以后排查"为什么脸不像"就没有线索。

## 后果

**正面**
- 分镜页从"只能看"变成"能生成"：实测点「生成首帧」，48 秒出图，画面替换剪影，按钮变「重生成首帧 ¥0.12」，已花 +¥0.12，刷新后图还在（事件：`project.created, asset.updated, shot.updated`）。
- 首帧与人物固定串同源：实测生成的画面里是"米色风衣、齐肩黑发"的林，与定妆要求一致。
- 重生成不增资产：id 固定，`asset.updated` 覆盖。
- 测试：pipeline 两条（提示词含首帧语义、人物锚点原样、无 id）、store 四条（两条事件、溯源锚点、锁定不生成、超预算不发请求）、读模型两条（有图 / 无图）。

**负面**
- **只有首帧，没有尾帧**：`lastAssetId` 在 schema 里，界面上没有入口。尾帧对转场有用，但先做首帧。
- **还不是"图生图"**：提示词与锚点都在，但接口不收参考图（ADR-0029 的债），所以首帧与定妆四格不是同一个人这件事仍未解决——只是同一套描述。
- **首帧不参与 take**：take 仍是"视频"的概念，首帧不生成 `take.added`，所以审片台的留用 / 淘汰对首帧不生效。视频接通后，首帧应作为 take 的前置产物一起记账。
- **重生成没有二次确认**：点一下花 ¥0.12 并覆盖当前首帧。金额小、动作可逆（再生成），暂不拦。
- 出图是前台请求，48 秒占着页面；没有取消、没有队列，关页面请求仍在跑。

**跟进**
- 尾帧生成与"只换尾帧"（转场用）。
- 视频接通后：首帧 → `submit` → `poll` → `take.added`，并在 take 上记 `firstFrameAssetId`。
- 首帧的"重生成"接预算报价合并显示（现在按钮价与预算面板分开）。
- 能收参考图后，首帧改为"首帧 + 定妆四格"的图生图，一致性才真正有据。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 先等视频接通，首帧一起做 | 视频配额被上游挡住，等它等于分镜页长时间不可用；首帧当天就能做 |
| 首帧只写 `asset.updated`，用约定 id 找 | "哪张是首帧"要靠猜；项目结构必须显式 |
| 首帧生成多条资产供挑选 | 每一张都要钱与时间；一格一个位置，选放在重生成里 |
| 服务端接收 shotId，回查项目 | 服务端没有项目（ADR-0032），也不该有 |
| 客户端拼首帧提示词 | 与镜头提示词两处漂移；提示词属于 pipeline |
