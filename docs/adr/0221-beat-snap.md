# ADR-0221：节拍卡点只给建议，不动时间线（C5）

- 状态：已采纳
- 日期：2026-11-14
- 决策者：用户 + Claude
- 关联：C5、C4、C7、C10、E4、SOUND.md

## 背景

C5「节拍卡点自动剪辑」在 FEATURES 里只有一行：音乐 BPM → 切点建议。
但 IR 里**没有 BPM 字段**——`MusicCue` 只有标题、情绪、起点、时长、增益、ducking。
配乐是导入的（C4 没有生成供应商），作者知道这首歌多快，工具不知道。

SOUND.md 给这条需求定了调子，三条纪律里的第三条是：
**「卡点服务剪辑：BPM → 切点建议，但不要为了卡点破坏表演节奏。」**

所以这件事的难点不在算网格（60 秒 / BPM 是小学算术），而在**知道什么时候不该动**。

## 决定

1. **不往 IR 加 BPM 字段**。BPM 是「这一版配乐多快」，属于界面上的临时判断，
   不是项目约束——换一首歌就该换一个数，不值得进事件日志、不需要回放。
   放在成片页的本地 state 里。
2. **`beat-snap.ts` 纯函数**：
   - `beatGridOf({ bpm, offsetMs, division })`：BPM → 一拍多长、细分后多长；
     BPM 越界夹到 40–220，不抛错。
   - `snapCuts(cuts, grid, tolerance)`：每个切点离最近网格差多少、算不算踩上。
   - `cutsOfClips(items)`：从时间线片段起点取切点（开头那个不算）。
3. **容忍 40 毫秒**：小于它就算踩上，**不建议动**。40 ms 是听觉上「几乎同时」的量级，
   超过它观众能感觉到拖拍。这是「不要为了卡点破坏表演节奏」的具体落点。
4. **补切建议只在跨度足够大的地方给**：相邻切点跨度不到三格就不建议补——
   中间那一格离两边都太近，补进去只会把镜头切碎。
5. **只读、不写**：不改时间线、不写事件、不调模型。界面上点不出来「自动对齐」按钮，
   因为那正是 SOUND.md 说不要做的事。
6. **文案自带提醒**：有漂移时的那句话末尾固定写「挪不挪由你定——不要为了卡点把表演切碎」。

## 理由

- **不给 IR 加字段**：BPM 不是项目的一部分，是「这次配了什么歌」的瞬时属性。
  进 IR 会让旧日志的每条 music cue 都多一个没填的字段，回放还要处理默认值。
- **不给「一键对齐」**：这是最容易被做出来、也最容易毁掉片子的功能。
  一个镜头 2.3 秒，对齐到 2.5 秒会让表演的呼吸断掉；工具没有能力判断
  「这一镜该不该为卡点让步」，就不该替作者做。
- **容忍值而不是精确对齐**：精确到毫秒的卡点在数学上漂亮，在观感上未必更好。
  40 ms 的门槛把「已经很接近」的情况排除掉，只提示真的听得出拖拍的那些。

## 后果

**正面**

- 作者能看见「这一版切点踩得怎么样」，而不用一遍遍听。
- 补切建议只在真正有空间的地方出现，不会把镜头切碎。
- 纯函数、零依赖，成片页打开就算，不花钱。

**负面 / 代价**

- **BPM 要手填**：没有音频分析，作者得自己知道或去查这首歌多快。
  自动检测 BPM 需要音频处理，本次不做。
- 只用切点算，不看**画面内容**：一个切点落在拍上不代表切得对，
  表演的呼吸、动作的落点都不在这份建议里。
- 40 ms 容忍与「跨度三格才补切」都是经验值，没有样片标定。
- 不处理变速（音乐被拉伸 / 压缩过之后 BPM 会变）。
- 不做「按拍生成剪辑点」——那是另一个量级的功能，且与「不为卡点破坏表演」冲突。
