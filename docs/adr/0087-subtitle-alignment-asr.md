# ADR-0087 字幕对齐：断句留在本地，识别只做纠错建议

- 状态：已接受
- 日期：2026-11-11
- 决策人：用户 + Claude
- 关联：ADR-0085（配音）、ADR-0086（时间线 / 成片）、D1 / D2 / D3 / D4、准则 P5 / P20

## 背景

成片页已经能把整条片子排出来（ADR-0086），但字幕还是「一句台词一条」：台词长一点就把竖屏画面铺满，短一点又来不及读。D2 要的是按语义停顿断句、按字数分配时间；D1 要的是用识别把配音转成文字，帮用户把台词校回来。

两件事的依赖不一样：

- **断句不需要模型**。标点、引号层级、每行字数、时间按可见字数分配，全是确定性的。断句规则越稳定，预览、SRT 与导出越不容易各说各话。
- **识别需要模型**。2026-11-11 用本地生成的语音探测供应商：模型目录里有 `qwen-audio-3.0-asr-flash` / `-filetrans` / `-streaming`，但两种 ASR 请求都返回 `403 No authorized bound group supports this request`，和 TTS 的配额状态一样。也就是说 D1 的链路现在能搭，但真实调用还走不通。

同时本机 ffmpeg 已修好：`brew reinstall ffmpeg` 装到 9.0.2，测试编码 H.264 + AAC 与 `ffprobe` 读时长都通过。ADR-0086 里「ffmpeg 起不来」的前提不再成立，但服务端渲染管线仍未实现，这一条 ADR 不碰渲染。

## 决策

1. **断句与时间分配放在 `apps/web/lib/subtitle.ts`，不落 IR。** 台词仍是 `DialogueLine { text, durationMs }`；`toEditView(project, { maxChars })` 现算 `EditCue[]`，每句台词带 `cues`，视图再拍平成 `view.cues`。改每行字数只重算读模型，不写事件——断句是「怎么显示」，不是「说了什么」。
2. **断句规则（D2）**：先整理标点（全角化、去字间空格、折叠重复标点、`...` 归一成 `……`），再按句末 / 句中标点切小句；**引号与括号里面不切**，标点后紧跟的收尾引号一起收进同一小句。小句贪心合并到每行不超过 `maxChars` 个可见字（标点不计），超长小句硬切，硬切也优先落在停顿后；少于 3 个可见字的尾句并回上一句。
3. **时间分配**：按每行可见字数比例分这一句的时长，每行至少 600ms（这一句本身不足 600ms 时按实际总时长）；分不下就合并到能坐下为止。每条 `startMs / durationMs` 首尾相接，**总和严格等于台词的 `durationMs`**，不让后面的字幕整体漂移。
4. **每行字数三档（12 / 16 / 20，默认 16）**，成片页字幕区可切。切档只影响显示与导出，改回原档结果完全一致（纯函数，无随机、无模型）。
5. **网关增加识别适配器**（`TreecloudTranscriptionAdapter`）：`POST /v1/audio/transcriptions`，multipart 上传音频字节 + `model` + `language=zh` + `response_format=verbose_json`。模型取 `ASR_MODEL`；没配就抛 `asr_not_configured`（500），一个请求都不发。供应商给了 `segments` 就换成毫秒带出，没给就是空数组，**不拿整句时长去猜分段**。
6. **服务端路由 `/api/transcribe`**：GET 只回「有没有配识别模型」；POST 只收内嵌音轨（`data:audio/…;base64`，上限 8 MB），不接受 http(s) 地址——服务端不替用户去抓外部媒体，少一个 SSRF 口子。没配模型回 500，供应商失败回 502，参数问题回 400，错误原文截断后如实带回。
7. **识别结果只是建议，不自动改台词**：store 把结果放进内存里的 `asrResult`（只留最近一条），声音页显示「识别结果 + 模型 + 段数」，用户点「用这句替换」才写**一条** `dialogue.updated { text }`。**时长与镜头不动**——音轨才是时长的准（准则 P5），识别只负责把文字写下来。刷新即丢，不落日志。
8. **导出统一用断句后的字幕**：SRT、预览 HTML 的逐条字幕、发布包的 `subtitles` 都来自 `view.cues`；ASS 与烧进画面仍未做。

## 理由

- **断句派生而不是落库**：一旦把 cue 写进 IR，每换一次字数档位都要写一整条新事件，日志会被显示偏好塞满；而 cue 没有独立于台词的信息，重新算一遍既便宜又不会和台词失步。
- **规则可解释、可复现**：用户问「为什么断在这里」，答案是一条规则（引号内不切 / 不超过 16 字 / 停顿优先），不是一次模型调用的随机结果。断句错了可以改规则，全项目一起变好。
- **识别不抢方向盘的活**：ASR 会听错专有名词、会吞语气词。自动替换等于让模型悄悄改剧本；放在「建议 + 一次确认」里，错的成本只是一眼。
- **配置缺失要说人话**：`ASR_MODEL` 没配时返回 `asr_not_configured`，界面写「还没配识别模型：加上 ASR_MODEL 之后才能识别」，与 TTS 同一套处理，不把 403 伪装成「识别失败」。
- **只收内嵌音轨**：音轨本来就在浏览器本地日志里，走 data URI 不需要额外的上传通道；不收外部 URL 也避免服务端被当成代理去访问任意地址。

## 后果

**正面**

- 长台词在竖屏上被切成可读的短行，时间跟着字数走；改字数档位立刻重排，不需要重新生成。
- 断句、SRT、预览、发布包共用同一份 cue，不会出现「编辑器里断开了、导出的 SRT 没断」。
- D1 的链路（网关适配器、路由、store、界面、错误处理）已经完整；供应商配额一开，`ASR_MODEL` 一配，识别按钮就能用。
- 识别结果不写日志，试错不污染事件流；确认为替换时只写一条 `dialogue.updated`，回放仍是单一事实。
- 测试：IR 107、web 276（新增 18：断句 11、读模型 cue 1、SRT cue 1、store 识别 5）、gateway 24（新增 4：multipart、未配置、空音轨、403 透传）、pipeline 23，合计 430。`pnpm typecheck`、`pnpm test` 通过。

**负面**

- **识别真实调用仍未验证**：供应商两种 ASR 模型都回 403，当前只能验证到「没配模型 → 明确拒绝」「配了 → 请求形状正确」，听不出一句真话。
- **断句不是语义理解**：规则按标点与字数工作，没有词边界与语义模型；「的」「了」这类虚词仍可能被硬切，专有名词也可能被拆开。用户只能换档位，不能手动改某一行。
- **不能逐条编辑字幕**：cue 是派生的，改一行文字等于改整句台词；时间也不能单独拖。
- **识别结果不持久**：刷新页面就丢，需要重新识别；没有历史记录与置信度。
- **ASS / 烧进画面未做**：SRT 是纯文本，样式仍在播放器侧；所谓「字幕样式」不进入画面像素。
- **服务端识别超时按 60 秒**：整句音轨通常够用，长录音可能被掐断，界面会如实报错。

**跟进**

- 供应商 ASR 配额开通后做一次真机验证：中文短句、带停顿的长句、含专有名词的句子各一条，核对文字与 `segments`。
- 手动微调单条字幕（扩展 `subtitle.ts` 的入参或给读模型加 per-line override，仍不落 IR）。
- ASS 导出与 mp4 烧字幕：等服务端渲染管线接上 ffmpeg 后一起做。
- 识别置信度与多候选：供应商返回 `avg_logprob` 之类字段时再考虑，不先造。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 用模型做语义断句 | 当前 ASR 不可用；断句每改一次字数都要重算，模型调用既慢又不可复现 |
| 把 cue 存进 IR | 显示偏好会写进事件日志，回放与迁移都变重；cue 没有独立信息 |
| 识别后自动替换台词 | 模型听错会悄悄改剧本，且可能绕开锁定镜头的确认 |
| 服务端接受 http(s) 音轨地址 | 等于给服务端一个任意 URL 抓取入口，SSRF 风险不值这条便利 |
| 直接烧 ASS 字幕进视频 | 服务端渲染还没做，先做只能验证到文件的 SRT 与 HTML 预览 |
