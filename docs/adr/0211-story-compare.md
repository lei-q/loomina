# ADR-0211：取用前的故事对比（C23 第二档）

- 状态：已采纳
- 日期：2026-11-14
- 决策者：用户 + Claude
- 关联：C23、C1、C2、ADR-0198、ADR-0205

## 背景

跨空间取故事（ADR-0198）会**整份替换** Logline / 梗概 / 类型 / 受众 / 调性 / 两个钩子，
并把弧光与关系整组换成来源空间的。面板上只有一句摘要（logline 前几十字）与
「对得上 N 个角色 · 会跳过 M 条」，作者点下去之前**看不到会被覆盖掉什么**。

C14 收口时列过「取用前后的内容对比」为未做；ADR-0205 给版本库做了对比，
但取用这条路径还没有。

## 决定

1. **纯函数 `storyCompareOf(current, source)`**（`apps/web/lib/shared-stories.ts`）
   - 返回逐字段的行：`{ key, label, now, next, changed }`；
   - 字段与 `storyRestorePatch` 可写回的完全一致：五项文字、两个钩子、
     弧光条数、关系条数（弧光 / 关系按「几条」比，不逐条摊开——
     它们各自还有 7 个子字段，摊开会把面板撑爆）。
   - `changed` 只比文字：空白差异也算不同（trim 后比），因为写回会 trim。
2. **面板里每行多一个「对比」**
   - 点开在行下方列出「现在 → 取来之后」；有变化的字段标色，
     没变化的灰显但保留（作者要能确认「这项不会变」）；
   - 弧光 / 关系显示「N 条 → M 条」，并说明「只带同名同 id 的角色」；
   - 对比是只读的，不写 IR、不进日志、不花钱。
3. **不做**
   - 不做逐条弧光 / 关系的字段级 diff（那是版本对比的活，且面板空间不够）；
   - 不做「只取某几项」（整份替换是 ADR-0198 的口径，改成部分取要重新设计）。

## 理由

- **覆盖前先看见**：整份替换是这套机制的核心，也是它最大的风险点；
  对比是最低成本、最直接的对冲，且完全派生。
- **字段与写回同源**：行直接从 `storyRestorePatch` 的可写字段生成，
  不会出现「界面上说会改、实际没改」的漂移。
- **弧光按条数比**：逐条摊开信息密度过高，而作者真正关心的是
  「会不会少掉几条、跳过几条」——那已经在摘要里说了。

## 后果

**正面**

- 取故事前能看到每一项会被改成什么；不会「点了才知道覆盖了原来的梗概」。
- 不新增 IR / 事件 / 日志版本；对比完全派生。

**负面 / 代价**

- 弧光 / 关系只给条数，看不出具体哪一条被换掉。
- 对比不显示 `provenance` 与逐字原文（它们本来也不会被取用）。
- 面板变长：每行多一个可展开块，最长的字段（梗概）会折行。
- 没有「取用后撤销」之外的对照记录；日志里能查，界面上只有这一次对比。
