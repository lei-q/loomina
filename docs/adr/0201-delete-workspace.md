# ADR-0201：删掉一个工作空间（C15 第二档）

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：C3、C15、C22、ADR-0188、ADR-0197

## 背景

多工作空间（ADR-0188）只做了建 / 切换 / 改名。试着开一两集之后，
列表里会留下试验品：没有删除入口，作者只能一直看着它们，或者清整份本地库。

「删」在这个项目里是要紧事：事件日志是唯一事实来源（P2 / ADR-0011），
删掉就回不来；而素材文件是内容寻址、全机共用，可能还有别的空间在引用。
所以不能做成「清一下列表」。

## 决定

1. **弹层里每个空间多一个「删」**
   - 正在打开的那个显示灰色的「删」，`title` 写「先切到别的空间」；
   - 点一下变成「真删 / 算了」两个按钮，第二下才动手；
   - 动手后弹层里写一行结果：「删掉了「第三集」：8 条事件。素材文件不动，别处还在用。」

2. **`deleteWorkspace(id)` 只清这个空间自己的东西**
   - `events` 仓里 `workspaceId === id` 的行（老行的缺失字段按 `w-default` 算，
     所以删 `w-default` 也会把示例项目的引导行一起删掉）；
   - `meta` 里的 `log:<id>` 版本记录；
   - `workspaces` 登记表里的这一条。
   - **不动**素材文件、`templates`、别的空间的任何行。

3. **不能删正在打开的空间**
   - store 先拦这一句（与浏览器能力无关），`workspaceError` 写
     「不能删正在打开的空间：先切到别的空间，再回来删。」
   - 理由是整页加载的那一套：当前页仍握着这个空间的写锁与内存里的项目，
     删完不刷新会继续往一个不存在的空间写。让作者先切走，就没有这个中间态。

4. **不支持 IndexedDB 的环境如实说**
   - `hasWorkspaces()` 为假时返回 `undefined`，写「这个浏览器不支持多工作空间。」，
     不假装删成功。

## 理由

- **日志是事实**：删空间就是删日志。素材不是日志的一部分，也不是这个空间独有，
  混在一起删会误伤别的空间正在用的文件。
- **两步确认**：一次误点就把一整集的日志抹掉太贵；「真删 / 算了」是既有界面里
  最轻的确认方式（与删一拍 take 同一套写法）。
- **先切走再删**：比「删掉当前空间然后原地换成示例项目」简单，也避免写锁与
  内存项目跟已删日志对不上。
- **结果写事件条数**：作者能立刻判断删的是不是自己想删的那个空间
  （空空间 0 条、做过一集 8 条、出过片更多）。

## 后果

**正面**

- 试验空间可以清掉，列表只留真正在做的几集。
- 只删自己那一份日志；别的空间、模板、素材文件都不受影响。
- 删前能看到事件条数，删后能确认删了多少。

**负面 / 代价**

- 不可恢复：没有回收站、没有导出后再删。
- 不删素材文件：盘上的字节要另走「清理没人引用的文件」（H3）。
- 正在打开的空间不能删，要先去切一下。
- 删掉的 id 不会被记住；如果别处（例如浏览器历史里的 `?ws=` 直链）仍指向它，
  打开时会退回默认空间而不是报错。
- 没有批量删除，也不能归档（「留着但不出现在列表里」）。
