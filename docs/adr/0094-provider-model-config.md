# ADR-0094：供应商与模型配置、页面级切换

- 状态：已采纳
- 日期：2026-11-11
- 关联：H22、H11、H16、R28、R30、ADR-0031、ADR-0033

## 背景

在此之前，模型是写死在 `secrity.env` 里的：`BASE_URL` + `API_KEY` + 各模态一个模型名。用户要换默认模型必须改环境变量并重启服务，也没法在同一个部署里同时挂两家中转站。

2026-11-11 用户要求：

- 文本换 `deepseek-v4.1-flash-1017`，图像 `gpt-image-2-c`，视频 `minimax-h3`，音频 `seedance-2.0`。
- 增加配置功能：供应商（Base URL、API Key）与模型（文本 / 图像 / 视频 / 音频）都能自己配，可配多个供应商，每种模态可配多个模型但至少一个默认。
- 支持在页面里切换，例如「故事」页可在 `deepseek-v4.1-pro` 与 `deepseek-v4.1-flash-1017` 之间选；不选就用默认。

约束：单人、本机 `next start` 部署；密钥绝不能进浏览器；不引入数据库或额外常驻服务。

## 决策

### 1. 配置存在服务端文件

- 路径：仓库根 `.loomina/config.json`，可用 `LOOMINA_CONFIG` 覆盖。
- 目录 `0700`、文件 `0600`；写入走临时文件 + `rename`，避免半份配置。
- `.loomina/` 加进 `.gitignore`，密钥不会随仓库提交。
- 文件不存在时，从 `secrity.env` 生成**只读临时视图**（`saved: false`）；第一次保存才落盘，之后以文件为准。
- 临时视图不把 `API_KEY` 复制进供应商记录：密钥按供应商 id `env` 在调用时从环境变量回读，所以落盘文件里也没有密钥。

### 2. 形状与不变量

```ts
type ConfigFile = {
  version: 1;
  providers: { id; name; baseUrl; apiKey?; videoApi? }[];
  models: { id; providerId; modality; model; label; resolution?; voice? }[];
  defaults: Partial<Record<Modality, string>>;
};
```

- 模态固定五种：`text | image | video | tts | asr`；界面写「文本 / 图像 / 视频 / 配音 / 识别」。
- 供应商 id 小写字母、数字、连字符；模型 id 全局唯一，默认用 `<providerId>:<model>`。
- Base URL 只收 http(s)，不带账号、查询串、锚点，去掉结尾斜杠。
- 同一供应商、同一模态下的同一个真实模型不接受重复。
- 某模态有模型就必须有默认，且默认必须属于该模态；保存时不接受「有模型但不知道用哪个」。
- `apiKey` 缺省 = 沿用旧值，空字符串 = 清空；返回给浏览器的 `PublicConfig` 连字段都没有，只有 `hasKey` / `keyFromEnv`。

### 3. 页面级选择

- 顶栏在分镜 / 定妆 / 关键帧 / 声音页显示对应模态的下拉；故事页在页头显示文本模型下拉。
- 选择存 `localStorage`，键 `loomina.model.<modality>`，只影响当前浏览器。
- 不选时请求不带 `modelId`，服务端取该模态默认；选了才覆盖。
- 请求把 `modelId` 放进 JSON 体（`/api/story`、`/api/asset`、`/api/video`、`/api/voice`、`/api/transcribe`），价格接口用查询参数。
- 所选 id 不属于该模态时直接报错，不悄悄回落到默认；配置里已删除的 id 会被下拉自动清掉，避免死 id 一直跟着请求。
- 价目按所选模型读同一个 `ModelPrice` 表，不硬编码模型名。

### 4. 读写接口

- `GET /api/config`：脱敏配置 + 按模态分组的 `catalog` + 文件路径与 `saved`。
- `PUT /api/config`：整份保存，成功返回新的脱敏配置。
- `POST /api/config/probe`：对已保存供应商只读 `GET /v1/models`，10 秒超时，不触发生成、不花钱；回显文本先替换密钥再截断。
- 服务端每个生成入口通过 `resolveModel(modality, modelId?)` 拿到 `{provider, model, apiKey}`，再套进网关的模型槽位；其它模态保留各自默认。

## 理由

- 文件在服务端，密钥不进浏览器，也不需要数据库；单人本机部署足够。
- 环境变量继续可用：没保存过配置时行为与 ADR-0031 一致，已有部署不需要迁移。
- 每次请求重新读配置，改完不用重启；配置很小，读盘成本可以忽略。
- 选择存 localStorage 而不是事件日志：它是「这台机器用哪个模型」的偏好，不属于某个项目，也不该进 IR 或花掉事件版本。
- 默认是硬约束，避免空默认导致「有模型却生成不了」的中间态。

## 后果

**正面**

- 页面里可切换模型；实测故事页下拉选 `deepseek-v4.1-pro` 后，`POST /api/story` 的请求体带 `modelId: "env:deepseek-v4.1-pro"`，`localStorage` 同步记住。
- 配置页可增删供应商与模型、设默认、探测连通性；保存生成 `0600` 文件，目录 `0700`，文件内不含密钥。
- 密钥不出服务端：`GET /api/config` 的响应里没有 `apiKey`，只有 `hasKey`。
- 同一份代码可挂多个供应商；某个供应商临时不可用时可以切另一个，不必重启。

**负面**

- 配置文件是本机明文（0600），拿到本机文件系统的人仍能读；这不是多用户隔离方案。
- `PUT /api/config` 没有鉴权：仅适用于本机开发 / 单人部署；公网部署前必须加访问控制。
- 配置是进程内每次重新读盘，没有 watch 与缓存；手动改文件后下一次请求即生效，但页面下拉要刷新才更新。
- 页面选择只存在当前浏览器，换设备 / 清缓存后回到默认。
- 按项目固定模型、模型能力矩阵联动、价目表自定义仍未做。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 继续用环境变量 | 换模型要重启，不能在同一部署里挂多家供应商 |
| 配置写数据库 | 需要迁移与连接管理；单机文件足够，H3 云端存储仍暂缓 |
| 配置存 localStorage，请求带 Base URL / Key | 密钥进浏览器并随每个请求传输，违背「密钥只在服务端」 |
| 密钥加密后存浏览器 | 仍需要服务端解密与密钥管理，复杂度高于收益 |
| 每页选择写进项目事件日志 | 模型选择是机器偏好不是作品内容，会污染 IR 与回放 |
| 选中的 id 失效时自动回落默认 | 会掩盖配置错误，生成结果与用户选择不一致 |
| 引入配置热更新 / 文件监听 | 当前没有长驻配置需求；每次读盘已经保证改完即生效 |
