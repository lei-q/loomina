# ADR-0054 跨镜头挪台词：两条 shot.updated，一减一加

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0045（增删句）、ADR-0047（同镜排序）、ADR-0053（顺序历史）、FEATURES A5 / A21

## 背景

一镜里能改台词、能换人、能排序、能删句，但**句子不能换镜头**。可「这句其实该放在她推门的那一镜」是剧本里最常见的一刀；现在只能删掉再在另一镜里加一句——文本、说话人、时长全要重打一遍，日志里也变成一次删除加一次新建，看不出是同一句。IR 里 `Shot.dialogueIds` 是数组，跨镜头移动只是两个数组各改一处，没有新概念。

## 决策

1. **不新增事件**：移动 = 源镜一条 `shot.updated { dialogueIds, durationMs }` + 目标镜一条 `shot.updated { dialogueIds, durationMs }`，同一时间戳，先减后加。
2. **时长跟着走**：源镜 `max(500, durationMs - line.durationMs)`，目标镜 `+ line.durationMs`。全片总时长不变——这句本来就在项目里，只是换了归属。
3. **台词本身不动**：`DialogueLine` 的 id、文本、说话人、时长都不改，事件里只出现 `dialogueIds` 与 `durationMs`。于是这一句的改写历史、换人历史跟着它走，不会因换镜清零。
4. **store `moveDialogueTo(lineId, targetShotId)`**，拒绝：只读标签页、找不到台词、镜头里没有这一句、目标镜不存在、源即目标（`这句已经在这一镜里了。`）、源镜或目标镜锁定（`这一镜已锁定：要挪台词先解锁。`）。
5. **界面**：每句旁一个`移`；点了就地变成目标镜头下拉（`SH-03 · 第 1 场`），列出除本镜外的所有镜头，选完立刻生效并收起。锁定镜头占位、不给下拉。
6. **顺序历史收紧**（ADR-0053 附记）：挪句改了句子集合，不算一次「换顺序」；但会推进基线，之后的真排序照常比较。

## 理由

- **移动就是这个项目里的两次赋值**：`dialogueIds` 已经存在，加事件只为「移动」起个名字，会让回放多一份真相。
- **一条事件一个镜头**：`shot.updated` 的语义是「这一镜变了」；源镜和目标镜确实各变了一次，合成一条就得带两个 shotId，回放要特判。
- **时长不守恒是 bug**：句子还在项目里，页头总时长抖动就说明算错了。用 floor 500ms 与既有减句一致，不出现零时长镜头。
- **台词 id 不动**：历史挂在 `lineId` 上；换镜若换 id，用户会以为这是一句新台词。
- **下拉而不是拖拽**：拖拽要处理落点、误触、移动端；这一版最要紧的是「能挪、挪到哪说得清」。

## 后果

**正面**
- SH-02 的「门开着呢。」点`移`选 `SH-03 · 第 1 场`：这一句从 SH-02 消失、落到 SH-03 队尾；SH-02 技术行 5.4s → 3.9s，SH-03 2.4s → 3.9s；页头仍是 6 句台词 / 35.6s。
- 日志多两条 `shot.updated`（同一时间戳，先 `s-02` 后 `s-03`），各带 `dialogueIds` 与 `durationMs`；刷新后顺序、时长、归属都不变。
- 这一句原来「改过 3 次」的历史跟着它到新镜头，不清零。
- 挪句不再让「这一镜的顺序改过 n 次」+1；SH-02 仍是 3 次，SH-03 不出现顺序折叠。
- 测试：web 131 条（新增 2 条：跨镜头移动与回放；六种拒绝。顺序历史改一条：集合变化的写入不计入）；IR / gateway / pipeline 不变，合计 232。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：headless Chrome 点 SH-02「门开着呢。」旁的`移`、选 `SH-03`；IndexedDB 第 31、32 条为两条 `shot.updated`。

**负面**
- **两条事件不是原子的**：中途崩掉只写了源镜，这一句会短暂「不属于任何镜头」。没有事务，靠一次 `set` 里一起写进来缓解。
- **只能一句一句挪**：多句对调要挪两次，中间状态会出现在页面上。
- **没有拖拽**：不能在正文里直接拖句子，只能走下拉。
- **挪完不提示目标位置之外的事**：这一句进了新镜头，不会标记目标镜的关键帧 / 提示词过期，也不提示与新镜头景别、说话人是否冲突。
- **顺序历史里挪句是隐形的**：只看顺序折叠，看不出「这句什么时候进来的」——真正的原因要去翻日志。
- **目标镜下拉很长**：镜头一多，下拉就是几十项，没有搜索与分组。

**跟进**
- 多选挪台词 / 两句对调。
- 挪完标记目标镜下游产物过期。
- 在镜头级时间线里把「加句 / 删句 / 挪入 / 挪出」与排序合成一条，而不是现在这样分开。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 新增 `dialogue.moved` 事件 | 回放要在事件里重算两个镜头的数组，与 `dialogueIds` 成为两个真相来源 |
| 一条事件带 `fromShotId` / `toShotId` | `shot.updated` 只属于一个镜头；回放要特判，读模型也不能按 shotId 过滤 |
| 删掉再在新镜头里加一句 | 文本、说话人、id 全变；这一句的历史断成两截，日志读不出是「同一句换了位置」 |
| 时长按目标镜重算 | 台词没改字，重算会凭空改变总时长 |
| 拖拽排序 + 跨镜头拖拽 | 交互成本高、误触多；先用下拉把语义钉住 |
| 挪完自动重排目标镜时长 | 目标镜原有句子时长与顺序是用户的决定，自动重排会把编辑偷走 |
