# ADR-0080 显式场号与场次拖拽排序

- 状态：已接受
- 日期：2026-11-11
- 决策人：用户 + Claude
- 关联：ADR-0060（场序调整）、ADR-0068（中间插入）、ADR-0077（出场顺序）、FEATURES A21

## 背景

场号一直只有一种来源：`Scene.index`。界面上写「第 N 场」，导出、镜号、挪场次的选项全部按这个数算。这带来两个问题：

- **跳号与补拍写不出来**：真实片场常见「第 2A 场」「第 7 场之后接 9 场」，或者先写 1、3、5 场，2、4 场以后再补。现在只能删了重排，或者干脆让场号与实际剧本对不上。
- **挪场次要按很多下**：`↑` / `↓` 一次一位，`挪` 下拉能一步到位但要「点开 — 找 — 选」。场次一多，把最后一场挪到最前面仍不顺手；用户已经在别处习惯了拖拽。

## 决策

1. **`Scene.code` 进 IR**：`z.string().max(4).default("")`，老项目回放补空串，`LOG_VERSION` 不变。空串 = 按顺序编号，有值 = 显式场号。
2. **场号是名字，不是位置**：场次挪位后 `index` 重排，`code` 跟着这一场一起走。`2A` 挪到第二位仍写「第 2A 场」；没有场号的那一场按它**当时的位置**显示「第 3 场」。因此显式场号与顺序号可以数值上重复（第 2A 场后面跟第 3 场，前者也有一个「2」），这是刻意的：名字和位置是两件事。
3. **校验**：1–4 位字母数字（`/^[0-9A-Za-z]{1,4}$/`）；空白清掉即为空串；同一项目内非空场号不允许重复。IR 与 store 都校验，store 报人话（「场号只能是 1–4 位字母数字，比如 2A。」「已经有「2A」这一场了。」）。
4. **一处改，全处跟着换**：`scriptToText`、`挪到…` 下拉、跨镜头移台词的目标标签、删除撤销的标签，全部读 `ScriptScene.label`（`code || String(index + 1)`），不再直接拼 `no`。`no` 仍保留为整片顺序号，供镜号等用途。
5. **场号就地改**：场头行最左边「第 N 场」变成一个按钮，点开是输入框 + `存` / `取消`，`Enter` 保存、`Esc` 取消、点外面收起；失败原因贴在输入旁边，不挪到页头。只读标签页按钮不可点。
6. **拖拽排序**：场头行最左一个 `⠿` 手柄（HTML5 `draggable`），按住拖到另一场上松手 → `moveSceneTo(拖起的那一场, 目标位置)`；拖动中源场降透明度，目标场描一圈 `pick` 色。落地仍然只写**一条** `scene.moved`，不产生中间事件。只读或只有一场时不显示手柄。
7. **`↑` / `↓` / `挪` 都保留**：拖拽是快，键盘与触屏还是按钮稳；三套入口写的是同一条 `moveSceneTo`。

## 理由

- **`code` 而不是改 `index`**：`index` 同时决定排序、镜号与默认场号，让它跳号会把排序和镜号一起搞乱；单独一个显示名最小、最安全。
- **场号跟场走**：场号是剧本里的名字（「2A 场」指那场戏），不是排名。如果挪位后按位置重新编号，用户写的「2A」会在拖动后凭空变成「2B」，比不排序更糟。
- **空串而不是必填**：大多数项目就是顺序编号，不该强迫每个人都填一遍；空串默认值让老日志零改动。
- **上限 4 位**：`2A`、`12B`、`1001` 都够用；再长会在场头行挤掉地点与操作。
- **HTML5 拖拽**：场次是整块的大目标，不像出场签那样会换行、半行处没有落点；这里用原生拖拽实现最轻，落点就是「另一场」。

## 后果

**正面**
- 场头写「第 2A 场」，导出 `第 2A 场 · 内 · 夜 · 走廊`，`挪到…` 与跨镜移台词里也写 2A；后面没有场号的照旧按位置编号。
- 拖 `⠿` 把最后一场拖到最上面，一次到位；落地只写一条 `scene.moved`，撤销与历史读起来仍是「挪了一次」。
- 场号改了立刻反映在所有入口；清空输入即回到顺序号。
- 测试：IR 100（新增 3）、web 218（新增 4：store 2、读模型 2）、gateway 17、pipeline 22，合计 357。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：剧本页第 1 场点「第 1 场」→ 输入 `2A` → 场头变「第 2A 场」；再输入 `2A场` 被拒，输入框旁边红字给原因；拖第一场的 `⠿` 落到第二场，两场互换，`2A` 跟着这一场到第二位，另一场按位置显示「第 1 场」；无报错。

**负面**
- **显式场号不校验连续性**：可以写 `9`，也可以两场之间没有 `5`；跳号是需求，所以不检查「缺了哪一场」。
- **顺序号会被场号盖住**：设了 `code` 的场次在界面上看不到它排第几，只能看位置。
- **拖拽只在桌面可用**：触屏没有指针拖拽，仍要用 `↑` / `↓` / `挪`；键盘用户同样。
- **拖动没有「插到两场之间」的落点**：落到哪一场就留在那一场的位置，想放到中间要先想好落在谁身上。
- **`code` 仍是显示名**：IR 里场次排序、镜号、提示词都不读它；如果以后提示词要带场号，得再确认「2A」怎么写进指令。
- **撤销删除时场号能回来，但挪场次不能撤销**：`scene.moved` 仍是普通事件，没有「挪回去」入口。

**跟进**
- 触屏 / 指针拖拽（自定义 ghost 与自动滚动）。
- 场号连续性提示（只提示，不阻止）。
- 提示词 / 分镜锚点里带上场号。
- 场序调整的撤销。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 让 `index` 直接跳号 | 排序、镜号、默认场号共用一个数，跳号会一起乱 |
| 场号必填 | 多数项目按顺序编号；必填会把老日志与新建场次都变成要处理的分支 |
| 拖拽时按落点重新编号 | 用户写的场号会在拖动后凭空变化，与「名字」的语义冲突 |
| 只做拖拽、不做场号 | 跳号与补拍是真实剧本的常态，只排序解决不了 |
| 用指针事件自绘拖动 | 场次是整块目标，原生 HTML5 拖拽已经够；自绘要处理 ghost、自动滚动与命中测试 |
| 场号超 4 位 | 场头行会被挤爆；4 位足够覆盖 `2A` 到 `1001` |
