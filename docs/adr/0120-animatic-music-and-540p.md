# ADR-0120：预演带配乐，540p 复用草稿档

- 日期：2026-11-11
- 状态：已采纳
- 关联：E10、C4、ADR-0009、ADR-0084、ADR-0085、ADR-0118

## 背景

E10 的浏览器内预演已经能按镜头时长放画面、放字幕、放台词音轨。剩下三件一直挂在「未做」：

1. 配乐不响——`AnimaticView` 里根本没有音乐字段，成片页配好的床在预演里听不到。
2. 「540p 快速渲染」没有独立入口。
3. 「确认预演 → 锁分镜」这个闸门动作没有。

## 决策

### 1. 配乐进预演，与成片同一套参数

`AnimaticView` 多一个 `music: AnimaticMusic[]`（当前一条）：

```ts
{ id, title, mood, uri?, volume, loop }
```

- `volume` 由 `gainDb` 换算成线性（`10^(dB/20)`，夹在 0–1），与成片渲染同一口径，预演听到的响度关系就是导出的响度关系。
- `loop` 直接取自 cue，循环铺满的床在预演里也循环。
- 资产不存在（只有 cue 没有文件）时这条不出现——预演不编一个放不出来的音乐。

覆盖层里一个 `audio` 元素跟着 `playing` 走：暂停真停，继续从原处接上；右侧一个开关可以单独静音配乐（台词照放）。摘要多一行说明当前有没有配乐。

**不做 ducking**：成片渲染会在台词出现时压低音乐，预演不做。理由是预演是「听个大概」的地方，ducking 的实现依赖逐句时间与两遍响度归一，搬进浏览器要复刻一遍 `render-audio`，而它在这里不改变任何判断。

### 2. 540p 不另做一套渲染

成片页的「草稿」档就是 `540×960 / 24fps / ultrafast / CRF 30`——预演要的画质与用途正是它。再做一个「预演渲染」意味着：

- 同一份清单两条渲染路径、两套参数，改一处忘一处；
- 界面上「预演」与「导出草稿」两个按钮做同一件事，作者要猜该点哪个。

所以 E10 的「540p 快速渲染」直接指向既有草稿档，不新增代码。

### 3. 「确认预演 → 锁分镜」不做

分镜的确认已经由 ADR-0118 接住：硬缺口（没镜头 / 没描述）挡住，覆盖率不满要带条件确认。再加一道「必须看过预演」只会逼人点一遍预演按钮——看过与否无法从数据判断，只能记一个「点过」的标记，那个标记不产生任何判断。

预演是**看节奏**的地方，不是又一个闸门。P14 要求闸门设在昂贵步骤之前，分镜确认已经是那道闸门。

## 后果

- 预演里能听到完整的声音关系（台词 + 配乐），不用先导出草稿才知道音乐铺得对不对。
- 少一条渲染路径：改渲染参数只需要改 `RENDER_PROFILES`。
- 预演与成片的响度不完全一致（没有 ducking 与响度归一），摘要里如实写「这不是成片」。

## 验证

- 单测 783 全过（IR 155 + gateway 28 + pipeline 51 + web 549）。
  - `read-model.test.ts` 新增 1 条：配乐带 uri 与 `loop`、音量按 `gainDb` 换算（-18 dB ≈ 0.126）、资产缺失时 `music` 为空。
- `pnpm typecheck`、`next build` 全过。
- 浏览器（生产 3100）：成片页加入 `tone.mp3`（8 秒，授权「自己录制」），配乐区显示「tone · 8.0s · 循环铺满 · 全片 5.5s」；回分镜页开预演，右侧出现「配乐「tone」· 循环铺满」，覆盖层内两个 `audio` 元素（台词 + 配乐）；取消勾选后文案变「配乐「tone」· 循环（已静音）」，勾回即恢复。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 预演里也做 ducking 与响度归一 | 要复刻 `render-audio` 的两遍响度流程，而它在预演里不改变任何判断 |
| 新增独立的 540p 预演渲染 | 与草稿档完全重合，两条路径要同步维护，界面上两个按钮做同一件事 |
| 必须看过预演才能确认分镜 | 「看过」只能记成「点过」，那个标记不产生判断；分镜闸门（ADR-0118）已经够 |
| 配乐静音时连台词也停 | 静音配乐是为了听清台词，一起停反而没法用 |
