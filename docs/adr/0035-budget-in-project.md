# ADR-0035 预算写进项目，超限不提交

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：准则 P14 / P21、ADR-0011（事件日志）、ADR-0033（单价在服务端）、ADR-0034（本地持久化）、COST.md、H10 / H12

## 背景

准则 P14 与不变量 37 都写着"超过项目或镜头预算上限时不得提交新任务"，H10（预算护栏）与 H12（成本估算与报价）都是 P0。但到 ADR-0034 为止，实现里只有"已花"这个数：

- 预算是 `top-bar.tsx` 里写死的 `60`，不属于项目，刷新、重放事件日志都还原不出来；
- 没有任何地方拦。超了只是数字变红，生成按钮照样发请求；
- 用户在按钮上看不到"这一格多少钱"，只能生成完再去金额面板对账。

先把"护栏"做成一件真事：预算是项目的约束，超了不提交，提交前看得见价。

## 决策

1. **`Project.budgetCny`（默认 60）**：预算写进 IR，不写进界面。zod `.default(60)` 让老日志不需要迁移，`LOG_VERSION` 仍是 1——这也第一次验证了"schema 加默认值可以不动版本号"。
2. **新事件 `project.updated { budgetCny }`**：预算改了要留痕。只接受正数，`applyEvent` 收到非正数直接抛错，不写进日志。预算不变时不发事件。
3. **单价由服务端报**：新增 `GET /api/price` → `{ model, cny? }`，只读环境与价目表，不调模型、不花钱。客户端不复制单价（ADR-0033 的约束不变），每次进定妆页问一次。
4. **提交前拦**：`generateOne` 在发请求之前算 `已花 + 这一张 > 预算`。超了就**不发请求**，写一句人话：`「搪瓷杯」超出预算：这一张 ¥0.12，已花 ¥19.08 / 预算 ¥19.00。先提高预算再生成。`
5. **不知道单价就不拦**：`/api/price` 取不到、或价目表里没有这个模型时，`imageCny` 缺省，界面不显示价、也不阻断。报不出价的时候假拦，比不拦更让人困惑。
6. **按钮上先报价**：`生成三视图 ¥0.48`（四格 × 单价）、`生成主镜 ¥0.12`、`生成参考图 ¥0.12`；价目不知道时不显示。
7. **预算可改，改了就存**：金额面板里多一个输入框与「改预算」，写入 `project.updated`，刷新/重放后还是这个数。超预算时数字用 `pick` 色，展开里多一行「超出 ¥x.xx」。
8. **不做确认弹窗**：超限的处置是"先提高预算"这一句话，不是一次"确定要继续吗"。确认弹窗会让护栏变成一个点得动的橡皮章。

## 理由

- **预算属于项目，不属于页面**：换设备、刷新、重放日志之后，"这条片子最多花多少"必须还是同一个数。
- **拦在提交前，才有意义**：花出去再提示，等于只做了记账（ADR-0033 已做）。
- **单价在服务端**：客户端只接收一个数，两处价目不会漂移（不变量 39）。
- **不猜价、不假拦**：价目表是快照，可能没有新模型；拿不到就不显示价、不阻断，并在文档里写清这条边界。
- **留痕优于确认**：`project.updated` 让"预算什么时候从 60 变成 19 的"可回放；弹窗没法回放。

## 后果

**正面**
- 超预算的生成在客户端就被拦住，一次请求都不发；实测 `预算改成 19` 后点「生成参考图」，`/api/asset` 请求数为 0，页面写明差多少。
- 定妆页每个按钮上能看到这一次要花多少；三视图按格数算，不是固定一张。
- 预算跟着日志走：改到 19、再改回 60，刷新后仍是 60，事件里能看到两次 `project.updated`。
- 测试：ir 53 / gateway 17 / pipeline 10 / web 62，共 **142 条通过**；`pnpm typecheck`、`pnpm build` 通过。

**负面**
- **只拦了出图**。分镜页的"重做"目前还只记账、不真正提交视频生成；视频接通那天，同一条闸门必须接到那条路径上（`requoteShot` 已有报价，接得上）。
- **预算只有项目级**：没有镜头级上限、没有重试次数上限、没有"降级"路径，`Budget` 接口里的 `perShotLimitCny / maxAttemptsPerShot / onExceed` 仍未实现（H10 的另一半）。
- **已花包含已淘汰的 take**：`spendOf` 把 take 的 `costCny` 全算上，因为钱确实花了。这会让"重做很多次"的项目很快顶到上限——这是事实，不是 bug，但界面上还没解释。
- **报价不含重试**：按钮上的价是"一次成功"的价；失败不收费（供应商按成功计），以后若按提交计费，这里要跟着改。
- **`/api/price` 每次进页面问一次**：没有缓存到本地日志里；服务端不可达时页面只是不显示价。
- 顶栏金额仍然是"项目级数字"，没有按阶段分组（定妆 / 分镜 / 声音），片子长了只有一个总数。

**跟进**
- 视频生成接通时，把同一闸门（预算 + 报价 + 拒绝提交）接到 `decide`/重做路径上。
- 镜头级预算与重试上限（H10 剩余部分）。
- 账本按阶段分组，并把"已淘汰 take 的钱"单独标出来。
- 预算上限做成可选（`undefined` = 不设限），现在必须是正数。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 预算存 localStorage | 与项目脱钩：换设备、重放日志都不是同一个数；也进不了事件历史 |
| 客户端直接读价目表算价 | 单价进 bundle，两处价目早晚漂移（ADR-0033） |
| 超预算弹确认框 | 拦不住人，只多一次点击；"先提高预算"比"确定要继续吗"更清楚 |
| 等视频生成接通再一起做护栏 | 出图已经在花钱了，护栏晚一天就多一天无上限的重复生成 |
| 拦截时静默置灰按钮 | 用户不知道差多少、也不知道怎么解除；必须写出差额与预算 |
