# ADR-0062 删地点前先搬迁：把占着它的场次整批搬到别处

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0061（删除地点）、ADR-0056（场次地点）、ADR-0059（新建 / 编辑地点）、FEATURES B8

## 背景

ADR-0061 不允许删除仍被场次占用的地点，要求用户先手动把每一场改到别的地点。场多的时候这是逐场点击的苦差——而这件事机器完全可以一次做完：用户要的是「删掉这个地点」，搬迁只是手段。

## 决策

1. **`store.removeLocation(locationId, moveToId?)`**：被 `N` 场占用且给了 `moveToId` 时，先为每一场写一条 `scene.updated { locationId: moveToId }`，再写一条 `location.removed`。顺序固定：搬完再删，回放到任一前缀都不会出现悬挂引用。
2. **校验**：`moveToId` 必须存在且不等于被删的地点；否则写「搬不到这个地点。」不写任何事件。没给 `moveToId` 又确实被占用时，保持 ADR-0061 的拒绝与提示。
3. **不新增事件类型**：搬迁用已有的 `scene.updated`，删除用 `location.removed`；一次用户动作写成 `N+1` 条事件，日志里能看出搬到哪、删了谁。
4. **界面**：`删`不再对占用地点的禁用（只有在「被占用且没有别的地点」时才禁用）；点开后确认块里多一个「先搬到哪里」的地点下拉（默认第一个别的地点）与主按钮文案 `搬过去再删`；没有占用的地点仍是 `确认删`。

## 理由

- **用户意图是删，不是搬**：把搬迁做成删除流程的一步，比让用户先逐场改地点再回来删省得多，也不容易漏场。
- **顺序即正确性**：`scene.moved` 式的顺序约束在这里同样成立——先删后搬，日志中段就有一份场次指向不存在地点的项目。
- **不发明新事件**：搬迁就是改场头地点，与剧本页的下拉是同一条 `scene.updated`；再开一个 `location.reassigned` 只会让读模型多一条分支。
- **默认值可以改**：下拉默认第一个别的地点，是省一次点击；用户看得到，也能换。
- **没有别的地点时禁用**：搬迁无处可去，删了场次就悬空；禁用并写清「先新建一个地点」。

## 后果

**正面**
- 定妆页`阳台外沿`（被 1 场用）点`删` → 出现「这一地点还有场次，先搬到哪里」下拉（走廊 / 门口 / 桌边）与`搬过去再删` → 确认后地点消失，那一场的场头变成`内 · 夜 · 走廊`。
- 日志连续两条：`scene.updated { sceneId: "sc-1", patch: { locationId: "loc-corridor" } }`、`location.removed { locationId: "loc-mwarc3i6" }`；回放每一步都成立。
- 未被占用的地点仍是原来的两步确认，不多一个下拉。
- 测试：web 155 条（新增 2 条：搬迁 + 删除的 `N+1` 条事件与回放、搬到自己 / 不存在的地点拒绝）；IR 71、gateway 17、pipeline 21 不变，合计 263。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：`阳台外沿`点`删` → 选`走廊` → `搬过去再删` → 地点消失；剧本页第 2 场场头变 `内 · 夜 · 走廊`；IndexedDB 第 47 / 48 条为上述两条事件。

**负面**
- **没有撤销**：搬错了要逐场改回去；日志里有据可查，但没有「一键还原这次搬迁」。
- **一次写很多条事件**：场次多的地点会一次追加几十条；日志按条追加，刷新时逐条读回，目前没有问题，但没有批量写的事务保证。
- **搬过去的地点可能不是想要的**：下拉只列名字，不提示目标地点已有的主镜是否合适；主镜不会跟着搬。
- **不能只搬一部分场次**：要么全搬再删，要么不删；分批搬要回剧本页逐场改。
- **被删除地点的资产仍变孤儿**（ADR-0061 的负面照旧）。

**跟进**
- 搬迁的撤销（按事件日志整组回退）。
- 只搬部分场次的选择界面。
- 拖拽排序 / 挪到指定位置（ADR-0060 的跟进）。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 删除时自动挑第一个别的地点 | 替用户决定戏发生在哪，且没有任何提示；至少要让它看得见、改得了 |
| 新事件 `location.reassigned { from, to }` | 搬迁就是改场头，`scene.updated` 已经能表达；多一种事件会让 ADR-0058 的场头历史也要认它 |
| 先删再搬（两条事件顺序反过来） | 中间状态场次指向不存在的地点，任何在该前缀刷新都会渲染出「未命名场景」 |
| 删除对话框里列出每一场让用户逐场选 | 场多时是逐场点击的翻版；整批搬到一处已经覆盖大多数情况 |
| 保留 `location.removed` 里的「搬迁记录」字段 | 日志已经按顺序记下每一条 `scene.updated`；在删除事件里再抄一份是重复事实 |
