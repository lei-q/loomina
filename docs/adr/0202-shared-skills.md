# ADR-0202：跨空间取技能（C18 第二档）

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：C.5、C18、C16、C22、ADR-0191、ADR-0197

## 背景

技能（ADR-0191）是作者写好的固定要求：「不要现代物品」「袖口永远卷起」。
它按阶段拼进出图提示词，写进项目日志。

C18 收口时留下的缺口是「技能库导入 / 导出 / 跨空间共享」。一集里写好的技能，
下一集要重抄一遍；而技能正是那种**跨集合应该一样**的东西。

## 决定

1. **设置页技能区多一个入口**：「从别的空间取一条技能」。
   打开时才回放本机其它工作空间日志（`loadWorkspaceProjects`），
   列出所有技能：名字、阶段、内容前 90 字、来源空间。
   已经有一模一样一条的显示「已在用」并禁用。

2. **`sharedSkillsOf` 的判重口径**
   - 同一条 = 名字与内容**都 trim 后相同**；说明、阶段、启用状态不参与。
   - 同名不同内容算两条：作者可能在不同集里把同一句要求写细了，两条都该看见。
   - 同一批里重复定义的同一条只列一次（先出现的来源赢）。
   - 能取的排前面；同批内保持来源顺序（工作空间列表本来就是最近用过的在前）。

3. **`adoptSharedSkill(skill)` 抄成一条新技能**
   - 复用 `project.updated { skills }` 整块替换，不新增事件类型。
   - id 重新编（`sk-<时间戳>`，撞了补 `x`），`createdAt` 用现在；
     名字 / 说明 / 阶段 / 内容照抄。
   - **默认启用**：在来源空间里关着的技能取过来也是开的——
     「取过来」就是「我要用它」，要不要关由作者再点一下。
   - 同名同内容已在就拒绝（「这条技能已经在用了」），不写事件。
   - `readOnly` 拒绝；schema 校验失败如实报（复用 `ProjectSkillSchema`）。
   - 不调模型、不花钱、不改 `LOG_VERSION`。

4. **之后两边各改各的**
   - 抄的是内容，不是引用；改当前空间的一条不会动来源空间。
   - 没有「同步」「已取用来源」的标记：技能很短，作者看得出是不是同一条。

## 理由

- **技能是文本**：与故事、剧本不同，技能没有 id 引用、没有成片痕迹，
  抄一份就是全部语义；不需要像 C22 那样搬设定、像 C24 那样重编号。
- **按名字 + 内容判重**：只按名字会把「同名但写细了」的两条挤掉一条；
  只按内容会让改过名字的同一条看起来像新的。
- **默认启用**：取用的语义就是「这条我想用」；保留关闭状态会让作者取完发现没生效。
- **不复用 `addSkill`**：它只收 name / description / stage / body，
  会把 `enabled` 硬写成 true、`createdAt` 写现在——那正是这里要的，
  但 `addSkill` 还会把空名字当成错误路径走一遍；单独一个 `adoptSharedSkill`
  让「取用」与「新建」在日志上可区分（谁抄谁的，看事件时间就够）。

## 后果

**正面**

- 跨集固定要求写一次即可；设置页能看到别的空间都定了哪些规矩。
- 不新增 IR 字段、事件类型或日志版本。
- 取来后可立刻在同一个列表里改、关、删，与手写的技能没有区别。

**负面 / 代价**

- 只抄内容：来源空间后来改了那条技能，这里不会跟着变。
- 没有「这条从哪来」的持久标记（只在取用那一刻的对话框里看得到来源空间）。
- 同名不同内容会出现两条几乎一样的技能，作者要自己挑。
- 没有技能的导入 / 导出文件、没有技能库（跨机器）。
- 一次取一条，没有「把这个空间的技能全取过来」。
