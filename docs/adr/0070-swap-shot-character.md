# ADR-0070 这一镜里换人

- 状态：已接受
- 日期：2026-11-11
- 决策者：用户 + Claude
- 关联：ADR-0046（台词换说话人）、ADR-0054（台词换人）、ADR-0065（分镜页点名出场）、ADR-0057（人物变化让关键帧过期）、FEATURES A21 / B2

## 背景

「这一镜里换谁」现在有两处入口，各改一半：

- 分镜页的 `出场` 签能点亮 / 点灭人物（ADR-0065），但有台词的人点不灭——store 会拒绝，提示「先删掉或换人」。
- 剧本页的台词说话人小字能换人（ADR-0046），但只改一句台词，出场名单不动。

于是"这一镜本来是林在说，现在改成周"要做三步：先把林从出场里点掉（被拒）→ 逐句把台词换给周 → 再点掉林。写剧本时换人是很常见的改动（试角、改戏、同一场的备选），三步里每一步都可能忘，最后留下"人不在场上却在说话"或"人在场上却不说话"的矛盾状态。

## 决策

1. **一个动作换一个人**：store 新增 `swapShotCharacter(shotId, fromId, toId)`，同一个动作里：
   - `fromId` 必须在这一镜的 `characterIds` 里；
   - `toId` 必须是项目里的人物；
   - `shot.updated { characterIds }`：把 `fromId` 原位换成 `toId`；`toId` 本来就在这一镜里时并到第一次出现的位置，不出现重复；
   - 这一镜里 `characterId === fromId` 的每条台词各写一条 `dialogue.speaker.updated { lineId, characterId: toId }`。
2. **事件照旧、顺序固定**：先 `shot.updated`，再按 `dialogueIds` 的顺序逐条 `dialogue.speaker.updated`；所有事件同一个 `at`。不新增事件类型。
3. **拒绝的三种情况**：这一镜锁定（「这一镜已锁定，先解锁再换人。」）、人物不在这一镜的出场里（「这个人物不在这一镜的出场里。」）、目标人物不存在（「找不到要换上的人。」）。只读标签页不写事件。
4. **界面在剧本页**：每镜技术行下面一排 `出场`，把人名做成小签；点一下就地变成 `换下 林 →` 下拉，选完立刻换。没有出场人物时不显示这一排。锁定的镜头与只读标签页上这些签是灰的。
5. **分镜页的拒绝文案跟着改**：从「先删掉或换人」改成「先删掉，或去剧本页点他的名字换人，再把他从出场里拿掉。」——两处入口现在真的接上了。
6. **台词总时长、take、关键帧都不动**：换人只改"谁在场 / 谁在说"；已经出的帧仍按 ADR-0057 挂`过期`（`characterIds` 在画面输入里）。

## 理由

- **换人是"一个人换一个人"，不是两次独立的增删**：拆成两步必然出现中间态，而且台词必须跟着走，拆开就有一条规则没人管。
- **出场顺序就是提示词顺序**（ADR-0065）：原位替换保住"谁是主、谁是次"的信息；并到已在场的那一位，是因为重复点名没有意义。
- **先改名单、再改台词**：即使中途失败（理论上不会），场上也不会出现"林不在名单里、台词还归林"更糟的组合；事件按这个顺序读起来也自然。
- **放在剧本页而不是分镜页**：换人往往是因为台词要换人；在台词旁边动手最顺手，分镜页的签继续管"点名 / 不点名"。
- **不新增事件**：换人 = 一条 `shot.updated` + N 条已有的 `dialogue.speaker.updated`；所有读侧（过期判据、白名单、`switch`）都不用动。

## 后果

**正面**
- 剧本页 SH-03 的 `出场 林` 点开选周 → 出场变周，这一镜里林的那句台词说话人也变周；两条事件，一条 `shot.updated`、一条 `dialogue.speaker.updated`。
- 本来是两个人的镜头（林、周），把周换成林 → 出场并成一位林；台词照旧换过去。
- 分镜页再想把有台词的人点灭时，提示里指明了去哪儿换人。
- 测试：web 180（ADR-0070 新增 3：换人同时改出场与台词、并到已出场的人、锁定 / 不在场 / 陌生目标 / 只读不写事件）；IR 82、gateway 17、pipeline 22；合计 301。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：SH-01 加一句林说的台词（5.1s），剧本页点 `林` → 选周；出场与台词说话人同时变成周，镜头时长与 page 头总时长不变；分镜页把林点掉不再被台词挡住。

**负面**
- **一次只能换一个人**：一场三个人要换两个，得点两次（或多次撤销式操作）。
- **不能换成"不在这一镜的人"以外的新人物**：目前人物库只能改、不能新建，可换的人就是定妆页里已有的两个；人物库是后续的事。
- **换人不可撤销**：换错了要再换回来，受伤的是台词列表（会被再写一遍）。
- **已经出的帧不会自动重出**：`characterIds` 变了，帧挂`过期`，仍要手动再生成。

**跟进**
- 人物库（新建 / 改名 / 描述 / 参考图），换人下拉才有足够的候选。
- 一次换一组人（多选替换）。
- 换人的撤销：把上一次换人整组回滚。
- 换人时提示这一镜已出的帧会过期。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 保持两步：先点灭再点亮，台词逐句换 | 中间态矛盾，而且有台词的人点不灭，第一步就过不去 |
| 分镜页的签长按 / 右键换人 | 隐藏手势；剧本页的台词旁边本来就是"换人"的语境 |
| 换人时顺手删掉旧台词、按新人物重写 | 台词是内容，不该被换人动作改写；只换说话人 |
| 新增 `shot.character.swapped` 事件 | 换人拆开就是 `shot.updated` + 若干 `dialogue.speaker.updated`，多一种事件所有读侧都要跟着长 |
| 换人同时把 take / 关键帧标成过期 | ADR-0057 已经按 `characterIds` 管过期；换人只是写入，过期由读侧判定 |
| 换人后自动重新生成帧 | 生成要花钱，必须由用户点 |
