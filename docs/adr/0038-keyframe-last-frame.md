# ADR-0038 尾帧：一镜有起点也要有落点

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0037（首帧）、ADR-0029（锚点）、ADR-0032（出图路由）、ADR-0035（预算）、B2、DATA-MODEL `Shot.keyframes`

## 背景

ADR-0037 把首帧做通了，`Shot.keyframes` 里同时留了 `lastAssetId`，但界面上没有入口。一镜只有起点没有落点，审片时看到的是"这一镜从哪开始"，看不到"到哪结束"——而短剧里大量镜头是靠落点接下一镜的（门关上、戒指停住、人对视完眼神落下）。

同时，首帧的界面只有一个按钮，一旦有了两帧，"画面里现在看的是哪一帧"就成了必须回答的问题。

## 决策

1. **尾帧落到 `lastAssetId`**：资产 id 固定 `a-lastframe-<shotId>`，重生成按 id 覆盖；写一条 `asset.updated` 加一条 `shot.updated`，patch 里带完整的 `keyframes`（首帧已有时不被抹掉）。
2. **提示词与首帧同源**（`buildKeyframePrompt(material, frame)`）：共用 `shotParts`，首帧是"首帧画面，动作起势"，尾帧是"尾帧画面，动作收势"，其余不差。
3. **接口不新增 kind**：`POST /api/asset` 的 `kind: "keyframe"` 增加 `frame: "first" | "last"`（缺省 `first`），校验不变，仍然只收业务字段。
4. **界面：两帧并排选，大画面看选中的那一帧**。画面下方一条"首帧 / 尾帧"两格缩略条：已有图显示图，没有显示剪影与字样；点哪一格，大画面就显示哪一帧，下面的按钮也跟着变成「生成尾帧 ¥0.12」或「重生成尾帧 ¥0.12」。
5. **两帧可同时生成**：进度按 `<shotId>:<frame>` 记，所以生成尾帧不会把首帧的进度盖掉。
6. **两帧共用一条预算闸门**（ADR-0035）：尾帧同样在提交前拦。
7. **不做转场**：尾帧现在只是一张能看的静帧，不生成"首帧→尾帧"的过渡，也不作为视频接口的首尾参数送出。

## 理由

- **一镜的边界是可审的东西**：首尾两帧放在一起，才能判断这一镜的调度是否成立（起势与收势是否在同一空间、同一光线下）。
- **并排选比叠两个按钮清楚**：两个独立的"生成首帧 / 生成尾帧"按钮会让"我正在看哪一帧"靠记忆；缩略条把选择本身变成了画面的一部分。
- **同一 kind 才能共用校验与提示词**：尾帧不是另一种生成，只是同一提示词的不同一句话。
- **进度分帧**：出图是分钟级，用户完全可能在首帧还在跑时切到尾帧点生成；共用一条进度会让界面撒谎。

## 后果

**正面**
- 分镜页可以两帧都定：首帧起势、尾帧收势，切换即看。
- 尾帧复用首帧的全部机制（预算、锚点溯源、错误文案、锁定只读），没有第二套账。
- 测试：pipeline 一条（尾帧语义与首帧不同、无 id）、store 两条（尾帧写 `lastAssetId` 且不抹首帧、两帧进度互不覆盖）、读模型一条（尾帧 uri）。
- 实测：在分镜页生成尾帧，出图后选中尾帧即显示新图，已花再 +¥0.12，事件为 `asset.updated, shot.updated`，刷新后两帧都在。

**负面**
- **两帧各自是独立生成**：不保证首尾是同一镜头同一光线的两次采样，画面可能对不上。真正的解法是图生图（ADR-0029 的债）。
- **锚点仍不随图送进模型**：溯源里记了，接口还不收。
- **没有"两帧一起生成"**：想省一次点击要等批量生成。
- 缩略条占掉画面下方一点高度，小屏上更挤。
- 首尾帧都不进 take：留用 / 淘汰仍对视频 take 生效。

**跟进**
- 两帧一键生成（批量）。
- 视频接通后把首尾帧作为视频的首尾参数送出，并在 take 上记下来源。
- 图生图：尾帧以首帧为参考生成，保证同一次调度。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 再放一个"生成尾帧"按钮并列 | 两个按钮 + 一块画面，"现在看的是哪帧"要靠记忆 |
| 尾帧只写 `asset.updated`，不挂镜头 | "哪张是尾帧"又变成靠约定猜（ADR-0037 同理） |
| 新增 `kind: "lastframe"` | 同一套提示词与校验，多一个分支只会多一处漂移 |
| 一次生成两帧 | 两次计费、两次等待，且用户常常只想改其中一帧；先做单帧，批量留后 |
