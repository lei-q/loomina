# ADR-0023 任务流优先，时间线降级为进阶

- 状态：已接受
- 日期：2026-11-09
- 决策者：用户 + Claude
- 关联：P6、P10、P22、UX.md

## 背景

C 端短剧创作工具最容易做成"剪辑软件"：首屏是时间线与参数面板，用户不知道从哪开始。

但我们的用户是没做过视频的人（PRODUCT.md），目标是 30 分钟出片（P10），默认 AI 初稿、人只做改（P6）。专业界面不能让主路径变陡。

同时，专业用户确实需要精修能力，不能一刀切砍掉。

## 决策

1. **界面按任务组织，不按工具组织**：默认是一条六阶段向导（故事 → 分镜 → 预演 → 生成 → 成片 → 发布）。
2. **自由工作台作为进阶模式**：熟练用户可切换到全展开视图，两模式共享同一份 IR。
3. **时间线默认折叠**，放在"成片 → 精细调整"；语义编辑（F7）为主，轨道操作为辅。
4. **参数四层披露**：结果（L0）→ 意图（L1）→ 参数（L2）→ 提示词（L3），默认停在 L0/L1。
5. **四道闸门统一组件**：说清"确认什么、代价是什么、还能再看看"。
6. **双形态**：桌面 Web 主创作；手机只做审批、一句话修改、分享，不做时间线与分镜编辑。
7. **错误即诊断**：每个失败给出原因与下一步动作，不直出技术错误码。

## 理由

1. 向导降低首屏认知负荷，直接对应"30 分钟出片"的验收标准。
2. 渐进披露让专业能力存在但不挡路，满足 P10 与进阶需求。
3. 时间线是专业工具的心智负担，语义编辑能覆盖大多数 C 端修改。
4. 手机端只做"高频轻动作"，比塞一个缩小版编辑器更有价值。

## 后果

**正面**
- 主路径清晰，新用户不需要教程。
- 专业能力不被砍掉，只是分层。
- 桌面与手机职责清晰，避免两边都做成半成品。

**负面**
- 需要维护两套视图（向导 / 工作台）与同一 IR 的双向同步。
- 语义编辑的覆盖度决定时间线能否真的折叠；覆盖不足时用户仍会被迫用轨道。

**跟进**
- 语义编辑（F7）的指令集与覆盖度需要优先验证。
- 阶段流失率、闸门确认耗时纳入产品指标。
- 移动端审批流与推送在 S5 前设计。

## 替代方案

- **纯工作台/时间线**：专业但劝退 C 端，违反 P10，放弃。
- **纯聊天式**：不可控、不可精修，放弃。
- **桌面与手机同构**：两边都做不好，放弃。
