# ADR-0205：版本库与废片库的筛选、搜索、分页与对比（C14 第六档）

- 状态：已采纳
- 日期：2026-11-14
- 决策者：用户 + Claude
- 关联：C14、C2、F2、ADR-0187、ADR-0193、ADR-0204

## 背景

到 ADR-0204 为止，三处「从日志重建」的清单都加了写死的条数上限：

- 废片库只列前 40 条，且按种类 / 状态没有筛选，只有「淘汰 / 删掉 / 旧版」计数；
- 故事版本库一次列出全部版本，只有一句 logline 摘要；
- 剧本版本库只列 40 版，虽然能展开看整份文本与「多 / 少」差异，但没有搜索与分页。

日志越来越长之后，作者要找「那一版把走廊的动作改成什么」只能一页页翻。
C14 收口时留的缺口是「按种类统计 / 筛选 / 搜索 / 分页、版本对比 / 命名 / 锁定、
历史自动过期策略」。

## 决定

1. **共用纯函数 `apps/web/lib/library-filters.ts`**
   - `matchQuery(haystack, query)`：大小写无关，多个词用空格分开、全部命中才算；
   - `paginate(items, page, pageSize)`：页码从 0 数，越界自动收回最后一页，
     空清单也返回一页。全是界面状态，不写 IR、不进日志。
2. **共用 `apps/web/lib/text-diff.ts`**
   - 把剧本版本库里那一份 `textDiff` 抽出来：按行多重集比，
     `added` 是后者比前者多出来的行，`removed` 是前者有、后者没有的行。
     改一个字会同时出现在两栏——这是有意的，不做 LCS 逐行糊块。
3. **废片库（资产页）**
   - 种类按钮：全部 / 视频 / 关键帧 / 配音；状态下拉：全部状态 / 淘汰 / 删掉 / 旧版；
     搜索框查镜号 / 描述 / 模型 / 台词 / 资产 id；每页 20 条，有上一页 / 下一页与命中数。
   - 顶部「淘汰 n · 删掉 n · 旧版 n」仍是全量计数，不跟着筛选变（那是账目，不是视图）。
   - 原来「还有 N 条没列出：先取回或清理前面的」这句删掉：现在翻页就能看到。
4. **故事版本库（故事圣经）**
   - 搜索「改了什么 / logline / 梗概 / 调性」；每页 10 版；
   - 每版多一个「对比」：把这一版故事整份摊成行（五项文字、两个钩子、弧光、关系），
     与现在这一版比，列出多 / 少行各最多 6 条；「用这版」不变。
5. **剧本版本库（剧本页）**
   - 搜索「改了什么 / 动作 / 台词」（直接搜整份纯文本）；每页 10 版；
   - 展开仍看整份文本与既有行差异。
6. **明确不做：命名 / 锁定 / 历史自动过期**
   - 命名与锁定要往 IR 里加「版本元数据」实体与事件，日志是唯一事实来源（P2），
     凭空多一份与日志并行的元数据表会分不清谁说了算；本档不做。
   - 「历史自动过期」要删事件行，会破坏 `project.created` 前缀回放与回滚位置
     （ADR-0109 的 `toEventCount` 是日志下标），现有日志压缩（ADR-0177）只改地址不改条数，
     正是为了守住这条线；要清理历史得另开 ADR 设计「压缩后仍可回放」的格式。

## 理由

- **筛选放在视图层**：日志是事实，界面只看哪几条；把筛选结果写回日志没有意义。
- **共用而不是三份**：三处清单后续还会加，两个纯函数加测试一次说清口径。
- **不做命名 / 锁定 / 自动过期**：这三项都不是「界面怎么显示」，而是数据模型与
  日志生命周期的变更；本档不越过这条线。

## 后果

**正面**

- 长日志里能按种类、状态、文字找到那一版 / 那一拍；翻页取代写死上限。
- 故事版本也能看到与现在的行差异，剧本 / 故事 / 废片共用一套筛选口径。
- 不新增 IR、事件、日志版本；改动全在纯函数与组件。

**负面 / 代价**

- 筛选 / 搜索 / 页码都是组件本地 state：刷新、切页面后不保留。
- 搜索是整串包含匹配，不支持正则、字段限定或拼音。
- 故事版本对比按「可恢复字段」摊平，不显示 `provenance` 与逐字原文。
- 命名 / 锁定 / 自动过期仍缺；版本多了以后仍要靠搜索定位。
- 废片库顶部计数不随筛选变化，作者可能把它误读成「当前这一组的计数」。
