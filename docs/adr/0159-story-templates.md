# ADR-0159：模板剧本与冷启动输入

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：A7、A2、A19、A16、ADR-0096、ADR-0121

## 背景

故事页已经能做三件事：一句想法生成、整段导入（ADR-0089）、逐字导入（ADR-0154）。三视图、题材矩阵与六拍 / 三分钟 / 系列节拍表也都在。但第一次打开的人仍然面对一块空白输入框——A7 要的「模板剧本」就是降低这一步的门槛。

现有资产足够拼出模板：`GENRE_MATRIX` 有 12 个题材与可行性建议，`BEAT_SHEETS` 有 60 秒六拍结构，故事页的「一句想法」本来就是模型输入。缺的是几条**可读、可改、能直接填进表单**的开头，以及一个不建项目、不调模型的入口。

## 决定

1. 新建纯数据层 `apps/web/lib/story-templates.ts`，定义 `StoryTemplate`：
   `id`、`name`、`genreId` / `genre`、`logline`、`synopsis`、`cast`（2–3 个角色关系）、六拍 `beats`、`openingHook`、`endingHook`、`note`。
2. 首批六条，全部落在首发聚焦的室内、少人、对话驱动题材：逆袭、甜宠、都市情感、悬疑复仇、家庭伦理、职场。古装、萌宝、动作暂不放入默认模板，避免群演与一致性风险。
3. 题材必须能在 `GENRE_MATRIX` 里按 id 找到且名称一致；节拍表统一用 `60s`。`templateIssues()` 做这层自检，测试直接跑。
4. `templateStoryInput(template)` 把模板翻成故事页输入：想法 = 梗概 + 人物冲突 + 「开场钩子 / 结尾钩子」两行；题材 = 中文题材名；节拍表 = `60s`。这一刻还没有项目，钩子只能先写进生成输入，不写 IR。
5. 故事页「一句想法」下方加一个折叠区「模板剧本 · 六条能直接改的开头」：点模板即填想法、题材与节拍表，并展开这条模板的梗概、人物、六拍与两个钩子。只填表单，不建项目、不调模型、不落事件。
6. 点示例想法会清掉模板选中状态，避免界面同时说「这是模板」和「这是示例」。

## 理由

- **最便宜的冷启动**：模板是纯数据，没有新依赖、没有新 API、没有新 IR；作者点一下就能从「空白」变成「可改的一段」。
- **接上已有的真源**：题材用 `GENRE_MATRIX`，节拍用 `BEAT_SHEETS`，不在模板里另写一套题材可行性或时间窗。
- **钩子进提示词**：A19 的钩子设计器还没做；模板把开场 / 结尾钩子直接写进想法，生成时模型能看见，作者之后仍可在故事圣经里改。
- **作者仍决定生成**：模板不自动生成、不自动开工；与「推断不写 IR」的既有边界一致。
- **先给能用的六条**：不追求覆盖所有题材，先把首发四个 P0 题材与两个相邻题材做扎实。

## 后果

**正面**

- 第一次打开故事页的人有六个可操作起点，且每个都带人物、六拍与钩子。
- 模板与题材矩阵、节拍表同源；数据写错会在测试里当场失败。
- 不新增依赖、不新增 API、不新增 IR 字段或事件；旧项目不受影响。

**负面 / 代价**

- 六条模板是固定示例，可能显得套路化；作者需要自己改写。
- 模板只填想法与两项设置，不自动建角色、场景、分镜或三视图。
- 没有模板使用率、生成质量或 A/B 评测；模板好坏目前靠人工判断。
- 钩子只进生成输入，不进 `StoryBible` 的可编辑字段；生成后要作者自己搬过去（A19 再做设计器）。

**不做**

- 模型自动扩写模板、按题材生成新模板、模板市场 / 分享。
- 模板封面图、示例成片、角色三视图预置。
- 选模板即建项目或直接调用模型。
- 模板使用统计、通过率与 A/B 标定。
- 把模板写进 IR 或事件日志。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 选模板直接建一个完整项目 | 会假装分镜、角色、场景都已经设计好；作者还要删 |
| 模型按题材现生成模板 | 多一次调用、多一份不确定；冷启动需要的是稳定起点 |
| 把模板存进 IR / 事件日志 | 模板是输入辅助，不是项目事实；存了要配失效与回滚 |
| 复用「示例想法」三条 | 只有一句梗概，没有人物、六拍与钩子，撑不起冷启动 |
| 给每条模板配封面与样片 | 需要额外素材与评测，当前阶段收益低于成本 |
| 另做模板选择页 | 故事页已经是起点，多一个页面只会多一次跳转 |
