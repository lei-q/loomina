# ADR-0027 审片台的写回：本地事件日志先于服务端

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0011（事件日志）、ADR-0026（审片台）、H17、[DATA-MODEL.md](../DATA-MODEL.md) §4 / §7

## 背景

三带骨架已经接上 Project IR 读模型（`toStageView`），但只能看不能改：点格子没有反应，留用 / 淘汰是画出来的按钮。

要写回，先得回答三个问题：

1. **"当前看哪一格"算不算数据？** 如果算，每次点格子都要改 IR、写事件，日志会被浏览动作淹没。
2. **写回走什么路径？** 直接在组件里 `project.takes[i].status = "approved"` 最快，但 IR 是唯一事实源（P2），绕过事件日志会让重放对不上。
3. **服务端现在就做吗？** 还没有数据库写入、没有鉴权、没有并发，先建一套保存接口等于把没想清楚的东西固化。

## 决策

1. **选中不是事件。** `currentShotId` 只是界面状态，点格子不发事件、不动 IR。
2. **留用 / 淘汰写一条 `take.updated`。** 事件携带 `takeId` 与只含状态与元数据的 patch（`id` / `shotId` 不可改），由 `applyEvent` 算出新的项目；业务逻辑不直接改 IR 对象。
3. **前端状态由 Zustand 持有 `events` 与 `project`。** `events` 是事实，`project` 是它跑出来的结果，一起持有只是为了少算一次。刷新即回到示例项目。
4. **决策后自动前进**：跳到当前镜之后第一格还没定的；到末尾绕回开头找；全定完了就原地不动。
5. **锁定的镜头在审片台只读**：不显示动作按钮，改一个"已锁定 · 只读"。改锁定的内容要走解锁，不在这个界面发生。
6. **重做按钮先禁用并说明原因**（生成链路未接），不做假的进度条。
7. `take.updated` 指向不存在的 take 时抛错，不静默吞掉。

## 理由

- **事件日志是 ADR-0011 就定下的路径。** 审片是"判断"动作，本来就该留下一条可回放的决定记录；日后接服务端时，只要把"append 到内存数组"换成"持久化一行"，上层不用改。
- **选中不进事件**，日志才保持"只记决定"的可读性。示例项目 12 条 take，一次审片产生 12 条事件，而不是 40 条浏览记录。
- **状态放在 store 而不是 React state**：三带（顶带已花、中台画面、下带胶片轨）要一起变；`useState` 得把状态提升到页面再一层层传回调，store 让三件各自订阅需要的那一份。
- **锁定只读**把"锁"这个准则是真的落实在界面上，而不只是 schema 里的一个字段。

## 后果

**正面**
- 写回路径与既定架构一致，IR 始终由事件推出，可重放（有测试：`rebuild(events)` 深等于当前项目）。
- 组件拿到的是 `StageView` 与两个回调（`onSelect` / `onDecide`），不认识 IR 字段。
- 服务端化时的改动面被限定在 store 的 `decide` 里。

**负面**
- 状态不持久：刷新即回示例项目，演示时会被看到。
- 每次决策都重建整个 `project` 对象（12 个镜头的量级无所谓；镜头上百时要加记忆化或换结构共享）。
- `events` 与 `project` 两份状态有短暂不一致的可能（只在 `applyEvent` 抛错时），当前没有回滚逻辑。

**跟进**
- 接持久化：`decide` 改为"先写服务端、成功后 append 本地"，失败时不改本地。
- 一句话指令解析后应当产生 `shot.updated` 类的补丁事件，走同一条写回路径。
- 重做接生成后，`take.added` 会出现在同一条日志里，胶片轨版本数自然增加。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 组件里直接改 IR 对象 | 绕过事件日志，重放对不上；违反 IR 单一事实源（P2） |
| 每次点格子也写事件 | 日志被浏览动作淹没，回放失去意义 |
| 现在就把写回接上服务端 | 数据库、鉴权、并发都没定，会固化没想清楚的东西 |
| 引入 Redux / Immer 管理状态 | 这一个界面只有三个状态，Zustand 足够；多一层库不换来任何东西 |
