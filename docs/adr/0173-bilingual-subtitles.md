# ADR-0173：双语字幕（D5）

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：D2、D3、D4、D5、E6、G7、G9、ADR-0115、ADR-0171、准则 P5 / P14 / P20

## 背景

D4 之后，断句（D2）与版式（D3）都进了 IR，SRT / ASS 也从同一份 `view.cues` 出。
FEATURES 里 D4 一直挂着「双语未做（D5）」：片子要出海时，第二语言还得在剪辑软件里
另铺一条字幕轨，时间轴与断句都要重对一遍。

B14 / B18 已经确立「派生结论不进 IR」的口径；双语的关键是**把译文挂在那一句台词上**，
而不是再存一条独立的字幕轨。挂错了地方就会和 D2 的断句、E1 的字幕挪位互相漂移。

另外，实测时发现一个和 G9 同类的既有问题：当前选中平台的画幅规格没过时，
`report.ok` 一票否决了**所有**导出按钮——SRT、ASS、OTIO 和预览 HTML 明明与平台
画幅无关，也被锁死。G9 当时给多平台版本单独拆了内容侧闸门，但单版导出没一起改。

## 决定

1. **译文属于台词，不属于版式**
   - `DialogueLine.translation?: string`（≤400 字）：一句台词一行第二语言，
     不存语言代码——整片的目标语言是 `Project.subtitleTranslation.lang` 一个决定，
     逐句再记一次只会互相打架。
   - 断句成几条时，**每条 cue 带同一句译文**：译文按整句写的，硬切成几段英文读不通。
   - 没写译文的句子只出原文，不拿中文再放一遍，也不编一行假的。

2. **版式只管三件事**：`Project.subtitleTranslation = { enabled, lang, position }`
   - `enabled`：关掉时读模型与单语逐字一样，一条 `translation` 都不带；译文留着，随时能再开。
   - `lang`：第二行的语言名，只用于界面、文件注释与后续接翻译服务，不做语言代码校验。
   - `position`：`below`（默认）/ `above`，决定第二行在原文下面还是上面。
   - 三件事进 IR 是因为它们是创作决定：刷新、换设备、回放事件日志之后仍要是同一个版式。

3. **两条事件，都不碰 `LOG_VERSION`**
   - `subtitle.translation.updated { patch }`：开关 / 语言 / 位置，只收这三个键。
   - `dialogue.translation.updated { lineId, translation }`：`null` 清掉；
     空串也清掉——存一行空白会让导出多出一块看不见的字。
   - 事件白名单、历史文案、zod 校验与回放都补齐；缺省字段让旧日志照旧回放。

4. **四种输出共用同一份 `view.cues`**
   - **SRT**：一条 cue 两行，第二行按 `position` 排在前或后。
   - **ASS**：同一个 `Dialogue` 里用 `\N` 换行，第二行套 `Second` 样式
     （字号 78%、非粗体、浅灰），只在双语开着时写进 `[V4+ Styles]`。
   - **预览 HTML**：`.subtitle` 改成 flex 列，第二行是独立 `<span>`；
     `above` 用 `order:-1` 换位置，字号小一号。整块底边仍钉在安全区。
   - **成片 MP4**：`drawCue` 在透明全画幅 PNG 上画两行，原文按角色着色（D3）
     保持原样；**整块字幕的底边钉在 `bottomPct`，双行只会把块往上撑**，
     不会把第二行推出安全区。

5. **界面：成片页顶栏「双语」抽屉**
   - 逐句写 / 改 / 清第二行，Enter 保存，带「跳到这一句」。
   - 顶栏数字是**没译文的句数**（只在双语开着时显示），不是错误数。
   - 开关、第二行语言、上下位置都能改；关掉双语时明确写「译文还留着」。
   - 不调翻译模型：这一版只做写、改、清与导出，面板底部照实说明。

6. **顺带修单版导出的闸门（与 G9 同一条口径）**
   - 字幕 SRT / ASS、OTIO、预览 HTML 改挂**内容侧闸门**
     （`contentGateOpen` = 没有文案硬阻断 + 待确认已勾），不再看平台规格。
   - 成片、封面与发布包仍看完整 `gateOpen`：它们确实要按平台规格出。
   - 预检下方的说明分开写：「字幕、OTIO 与预览仍然可以导出（它们不看平台画幅）；
     成片、封面与发布包要等这一项过了。」
   - 理由：项目 16:9 选着抖音时，导出一份 SRT 去给翻译看，不该被抖音的 9:16 拦住。

## 理由

- **挂在台词上**：D2 的手改断句、E1 的字幕挪位都是围绕 `DialogueLine` 的；
  独立的双语轨会与这两件事漂移，还得写同步与迁移。
- **关掉就完全等于单语**：存量项目不需要迁移，旧测试与旧导出逐字不变；
  「双语」是叠加能力，不是改写既有字幕链路。
- **底边钉住安全区**：第二行若往下长，会压到平台底部操作栏（D3 已经量过 8%），
  所以两行一起往上排。
- **内容侧与平台规格分开**：G9 已证明一票否决会锁死本来能做的事；
  把同一条口径补到单版导出，避免一个功能里两套说法。

## 后果

**正面**

- 出海时直接在成片页逐句写第二行，SRT / ASS / 预览 / 成片四种输出同步带双语，
  不必在剪辑软件里重建时间轴。
- 断句改了、字幕挪了，译文跟着走；双语关掉即回到一行原文，译文不丢。
- 平台画幅规格没过时，字幕与 OTIO 仍可导出，作者不会再被锁死。

**负面 / 代价**

- 译文按整句翻：一句断成三条字幕时，三条都显示同一整句译文；读速压力比原文大，
  长句应先在 D2 里断好再翻。
- 只有一行第二语言，不做三语、不做逐词高亮、不做卡拉 OK 式时间轴。
- 第二行不会自动折行；超过画面宽度的长译文会被裁掉，界面提示最多 400 字，
  但真正的宽度检查没做。
- 双语开着但某句没译文时，那条字幕就是单语，导出里前后可能会一行 / 两行交替。
  面板照实列出「还有 N 句没译文」。

**不做**

- 自动翻译（调文本模型）、译文质量检查、配音与目标语言对齐。
- 独立的双语字幕轨实体与「台账式」译文表。
- 逐句语言代码、按角色给第二行配色、第二行单独设字号 / 位置。
- 平台按语言自动改标题 / 简介 / 话题。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 在 `SubtitleOverride` 里加 `translation` | 手改断句只有作者改过的句子才有覆盖，绝大多数句子走自动断句，漏掉大部分译文 |
| 新增 `SubtitleTrack` / 第二份 cue 数组 | 与 `view.cues` 两份时间轴，断句与挪位必然漂移 |
| 自动调模型翻译 | 译文是要给观众看的文案，不能悄悄写进项目；先把「写、改、清」链路做实 |
| 双语开着时把没译文的句子用原文补第二行 | 看不懂中文的人仍然看不懂，是假的双语 |
| 第二行往下长（原文不动） | 会压进底部安全区，挡住平台操作栏 |
| 字幕导出继续看平台规格 | SRT / ASS / OTIO 与画幅无关；16:9 项目选着抖音时被锁死（实测复现） |
