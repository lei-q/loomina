# ADR-0141 一句话指令的模型兜底：规则表先跑，作者点头才花钱

- 状态：已接受
- 日期：2026-11-12
- 决策人：用户 + Claude
- 关联：ADR-0039（一句话指令）、ADR-0094（供应商配置）、ADR-0111（健康检查）、H11、H19、H22

## 背景

H19 的两条「未做」：**对话式理解**、**补充的删除编辑**。

第二条其实早就有了：`promptNotes` 的每一条在锚点下方是一枚 chip，点 × 写一条 `shot.updated`，不需要模型也不需要新界面（ADR-0039 附记）。剩下的真问题是第一条。

ADR-0039 当时写得很清楚：「今天没有文本模型接入，所以这件事不该假装成自然语言理解」。它选了七类说法的规则表，并且**以此为荣**：可验证、不编参数、说不认识就不认识。现在文本模型已经在网关里（故事页、配音都在用），同一个输入框却仍然只认七句话——「这光脏得像地下室」「换个能看见她手抖的角度」都会回「没听懂」。这是**能力缺口**，不是设计选择。

难点不在于「接个模型」，而在于不能把 ADR-0039 的确定性拆掉：

- 规则表能稳定命中的句子，不该被模型改写；
- 模型不该在作者没要求时被调用（每次都花钱、还慢）；
- 模型输出的补丁必须和规则表落在同一套字段上，不能多出剧情、人物、场景；
- 模型读不出来时要能说「读不出来」，不能编一个假改动。

## 决策

1. **规则表永远先跑，模型是第二条路。** 输入框回车仍然只走 `parseInstruction`；只有它返回 null（「没听懂」）之后，输入框旁边才出现一个「让模型读一遍」按钮。**作者点它才发请求**，不发自动、不并发、不重试。
2. **一句话、一个补丁、一条事件。** `POST /api/instruction` 接收 `{ text, snapshot }`，返回 `{ patch, reason, model }`。前端把补丁合并进 `shot.updated`，成功才清空输入框；失败只写提示，不动 IR。
3. **模型只能填允许的字段。** 补丁 schema（严格模式）只有五项：`shotSize` / `cameraAngle` / `cameraMovement` / `durationMs`（1000–8000）/ `note`（≤60 字）。枚举与范围在服务端校验，多出来的键整条拒绝，不「尽力而为」地丢掉。
4. **空补丁 = 没听懂。** `{"patch":{}}` 与越界输出都返回 422「模型也没读出具体要改什么」，不写事件。模型说「和现在一样」时同样不写——与规则表的「这句没改动什么」一致。
5. **机位整份带过去。** 快照里给模型完整的 `camera`（含焦段与 B13 的机位坐标）；模型只被允许改角度 / 运镜，转回补丁时 `{ ...snapshot.camera, angle, movement }`，不会把坐标洗掉。
6. **提示词只带镜头公开字段。** 系统提示是固定模板，用户消息是「镜号 + 景别 + 机位 + 运镜 + 时长 + 已有补充 + 作者原话」。不带素材地址、不带密钥、不带人物隐私；也不把模型回复记进任何文件——`health-events` 只记模态与成败。
7. **一次请求算一次文本调用。** 成功 / 失败都记 `health-events`（`instruction_noop` 单独成码），H11 的失败率看板上能看出这个入口在连续失败。
8. **等的时候守住镜头。** 请求期间作者可能切镜、锁镜、换标签页：回来时按 shotId 重新取，镜头不在了 / 锁了 / 页面只读了就不写补丁。按钮置忙，防重复点击。

## 理由

- **确定性与覆盖面各归其位**：规则表负责它擅长的、可测试的七类；模型负责长尾。两者写同一套字段，界面与历史不需要区分「这句是谁读懂的」。
- **显式点击是成本闸门**：一句话指令是高频交互，自动调用模型会把「改个景别」变成每次都等 2–5 秒、每次都计费。点一下，作者知道自己在为什么付费。
- **严格 schema 比提示词可靠**：提示词里写「不要编字段」是请求，`strict()` 是保证。模型多写一个 `weather`，整条拒绝，不写进 IR。
- **失败要像失败**：把 `{"patch":{}}` 当成「没听懂」而不是「成功但无变化」，界面才能让作者换个说法，而不是以为自己改成功了。
- **模型不碰坐标**：B13 的机位坐标是几何事实，不是摄影意图；让模型重写整份 `camera` 只会丢字段。只允许它换角度与运镜。

## 后果

**正面**

- 规则表覆盖不到的句子有了第二次机会，且不牺牲原路径的确定性。
- 模型输出与规则表输出走同一条事件与同一个界面回执，历史里不必区分来源。
- 没有配置文本模型时按钮照常出现，点了给出「去设置页选一个」的明确提示，不静默失败。
- 单测 10 条覆盖：快照裁剪、提示模板、JSON 提取（含代码块）、schema 越界、空补丁、字段去重、机位保留、界面说明。
- 浏览器实测：一句规则表读不懂的话（见附记）→ 点「让模型读一遍」→ 提示条给出理解与改动，事件多一条 `shot.updated`。空补丁 / 越界这条拒绝路径由单测覆盖，没有在实机上强迫模型返回空补丁。

**负面**

- **多一次网络往返与一次计费**：模型读一遍比规则表慢，且按文本 token 计费。按钮文案与 `title` 已写明「一次请求只回一个补丁」。
- **模型仍可能理解偏**：严格 schema 保证的是「不改坏结构」，不保证「改对」。作者看得见回执与镜头变化，不满意可以用历史抽屉撤销。
- **只改当前镜头**：一句话不能跨镜头批量应用；批量改仍要去分镜页。
- **不记模型原话**：为了不把提示词与素材写进本地日志，只留成败；复盘「模型当时为什么这么读」需要重新请求。

## 附记（2026-11-12）：验证记录

- 服务端：`POST /api/instruction` 用 `resolveModel("text")` + `TreecloudChatAdapter`，`maxTokens: 600`，超时 45s；`ConfigError` → 500「还没配文本模型」，`TreecloudError` 429 → 「在限流」，空补丁 → 422。
- 浏览器（`/`，示例项目当前镜 SH-03 特写 · 平视）：输入「镜头凑到她的手指上，越近越好」→ 规则表回「没听懂这句……」，输入框旁出现「让模型读一遍」→ 点击后提示条写「模型这样理解：把景别从特写推到极特写，让镜头贴到手指上。（景别改为大特写）」，SH-03 上带变「大特写 · 平视」，事件 13 → 14，末条 `shot.updated{shotSize:"extreme-close"}`、`shotId: s-03`。
- 同一句再点一次：模型没有再推景别（已是大特写），改为追加补充「镜头进一步贴近她的手指……」，提示条如实写「补充「…」」，事件 14 → 15——模型仍给出**新的**补丁，所以不是空补丁路径；空补丁 / 越界拒绝由单测覆盖。
- 测试：`instruction-ai` 10 条；web 876 条全过，`tsc --noEmit` 与 `next build` 干净。
