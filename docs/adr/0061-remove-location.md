# ADR-0061 删除地点：还有场次占着就不删

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0011（事件日志）、ADR-0059（新建 / 编辑地点）、ADR-0060（场序）、FEATURES B8

## 背景

ADR-0059 把地点从「示例里只有三条」变成可以新建、改名，但建错了只能改名或者留着不用。它的负面第一条写着「没有删地点：已有场次指向它时删掉要处理悬挂引用，这一版不做」。这一条现在补上。

## 决策

1. **新事件 `location.removed { at, locationId }`**：整条地点从 `project.locations` 摘掉，其他字段不动。
2. **`applyEvent` 校验**：没有 `project.created`、地点不存在、**还有场次指向它**，全部拒绝。拒绝信息带场数（`还有 2 场在这个地点`），不静默摘掉让场次悬空。
3. **store `removeLocation(locationId)`**：只读直拒；未知地点写「找不到这个地点。」；被占用时写「还有 N 场在「地名」：先把场次改到别的地点再删。」，返回 `false`；成功写一条 `location.removed`。
4. **界面**（定妆页）：地点名旁 `改名` 之后一个`删`；被场次占用的地点这个钮置灰，悬停写「还有场次在「X」：先把场次改到别的地点再删」。点`删`先变成`确认删` / `取消`（与台词删句同一套，ADR-0045），不弹窗。只读标签页不显示。
5. **不动资产**：已经生成的主镜图留在 `assets` 里；地点行没了，图不再被引用，但事件日志与资产都不删——删数据必须由用户明确要求，且这一版没有「资产清理」的路径。

## 理由

- **占用就拒，而不是级联改场次**：级联把场次改到哪个地点都是替用户做决定；拒掉并说清「先把场次改到别处」，是一个用户可以自己完成的动作。
- **与删台词同构**：`dialogue.removed` 已有先例；地点删除同样是一条事件、确认两步、不弹窗。
- **不删资产**：`asset.updated` 是追加式的事实（ADR-0011）；「删图」会牵动预算账与历史，不在这一版。
- **禁用 + 说明**：按钮灰着比点下去报错更早地把规则讲清楚；store 的拒绝是最后一道闸，不是第一道。

## 后果

**正面**
- 定妆页新建`储物间` → 名字旁出现`改名` / `删`；点`删` → `确认删` / `取消`；确认后整行消失，日志尾两条为 `location.added` 与 `location.removed`（同一 id）。
- 已有场次的地点（走廊 / 门口 / 桌边 / 阳台外沿）的`删`始终置灰，悬停写清还有场次在用它。
- 删掉之后到剧本页看场头：地点下拉里不再有它，已有场次一条没少。
- 测试：IR 71 条（新增 2 条：删掉未占用地点 + 回放、被占用 / 不存在拒绝）；web 153 条（新增 2 条：删未占用地点、占用地 / 陌生 id / 只读）；合计 262。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：定妆页新建`储物间` → `删` → `确认删` → 行消失；IndexedDB 第 45 / 46 条为 `location.added { loc-mwarpk2b }`、`location.removed { loc-mwarpk2b }`。

**负面**
- **不能删被场次占用的地点**：要先逐个改场次，场多的时候要把每一场都改掉。
- **主镜图变孤儿**：资产还在、账还记着，但页面上再也找不到它。
- **不删参考图 / 定妆图**；`Location.referenceImages` 目前也没有写入路径。
- **删除不进任何历史**：日志里能查，界面上没有「删过哪些地点」的折叠。
- **不挡「删完再建同名」**：重名检查只看现存地点，删掉的同名可以再建；这是对的，但日志里要靠 id 才分得清两条。

**跟进**
- 批量改场次地点（删地点前的一键搬迁）。
- 资产清理与孤儿标注。
- 拖拽排序 / 挪到指定位置（ADR-0060 的跟进）。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 删地点时级联把场次改到第一个地点 | 替用户决定一场戏发生在哪，错了要逐场找回来 |
| 允许删除、场次显示「地点已删除」 | 场次的地点会成为可空字段，`scene.updated` / 主镜 / 提示词全要处理空值；这一版不做 |
| 软删除（`archived: true`） | 要加字段、加过滤、加历史；现在的日志已经能回答「它曾经存在」 |
| 删除时一并删掉主镜资产 | 资产是花了钱的物证；清理应当是一个显式的、带账的动作 |
| 不设确认，点了就删 | 删地点会让剧本页下拉少一项、定妆进度重算，值得两步 |

## 附记（2026-11-10）：被占用的地点也能删了

负面第一条「不能删被场次占用的地点」由 ADR-0062 补上：删之前先把这些场次整批搬到用户选的地点，再写 `location.removed`。本条其余决策（两个事件、不删资产、两步确认）不变；store 的 `removeLocation` 多收一个可选的 `moveToId`。
