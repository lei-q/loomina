# ADR-0113：项目版本按事件校准为「改到第几版」

- 日期：2026-11-11
- 状态：已采纳
- 关联：F1、ADR-0011、F2 / ADR-0109

## 背景

`Project.version` 从第一版就写在 IR 里，`DATA-MODEL.md` 说它「单调递增，配合版本快照」。实际只有两处会动它：`project.created` 带一个起始值，`runMinimalChain` 出片时 `+ 1`。于是用户改台词、换人物、确认闸门、加资产，日志一直在长，`version` 却不动——顶栏的 `v7` 徽标、剧本导出的 `标题-v7.txt`、发布包里的版本，全都停在很久以前。

`runMinimalChain` 那条 `+1` 还会在日后接进工作流时失真：它直接构造新项目对象，不经过事件，加一次只加一版，和「改了几次」没有关系。

## 决策

**版本跟着状态走，不跟着批处理走。** `applyEvent` 应用完一条事件后，除 `project.created` 外一律 `version + 1`。

### 1. 每一条事件都是一版

| 事件 | 版本 |
| --- | --- |
| `project.created` | 用事件里自带的起始版本，不加 |
| 其余所有事件（改台词、改人物、资产、take、闸门、发布记录……） | +1 |

理由：徽标要回答的是「现在这份项目是第几版」。改一句台词和换一张定妆图，对作者都是「又改了一版」，没有一种更值得计数的操作值得特殊对待——一旦引入「只有大改动才算一版」，就得先定义什么算大，而这个定义只会越来越武断。

### 2. 回滚也算一版

`project.restored` 由 `rebuildStates` 特殊处理（它指向前缀，单条 `applyEvent` 看不到），所以那里单独写：取回目标前缀的项目后，`version = 上一步的 version + 1`，而不是把旧版本号原样带回来。

回到旧内容也是一次状态变更。如果回滚让数字往回跳，徽标就会和日志的顺序对不上，「v9」可能是三天前，也可能是刚回滚——这个数字就没法用来指代任何东西。内容回到旧状态、版本继续往前，是唯一自洽的读法。

### 3. 日志长度才是真正的历史

`version` 是「改到第几版」，不是「日志里有几条」：`project.created` 不计、回滚计一次。两者不相等也不需要相等。要看精确的先后顺序、每一步做了什么，去历史抽屉读日志（F2 / ADR-0109）；要一个能写进文件名、能口头说的短标识，用 `version`。

### 4. 出片不再自己加版本

`runMinimalChain` 里那条 `version: project.version + 1` 保留原样，但它是直接构造 `Project`（探针与测试用），不经过事件总线，也不会和 `applyEvent` 叠加——工作流接进 UI 时，出片结果应该以事件形式落进日志，由 `applyEvent` 统一计数。这条边界写进代码注释，避免以后接错。

## 后果

- 顶栏徽标、导出文件名、发布包里的版本，从「几乎不动」变成「每改一步都动」，终于名副其实。
- 数字会涨得比过去快：一次自动重试记一条 take 就是 +1。这是「改到第几版」的正常代价；它是个可读的短标识，不是统计指标。
- 回滚后版本继续增大，但内容与目标前缀一致：版本大不等于内容新。要判断内容新旧，看时间戳与日志。
- `DATA-MODEL.md` 的口径随之改掉：从「每个保存点」改为「每应用一条事件」。
- 已有日志回放出来的版本号会变大（事件条数 - 1 + 起始版本）。版本号从不落盘成独立状态，每次都由 `rebuild` 算出，所以不需要迁移。

## 验证

- 单测 741 全过（IR 146 + gateway 28 + pipeline 51 + web 516）。`events.test.ts` 新增 4 条：`project.created` 不加版本；连续三条事件依次 +1；回滚后内容回旧、版本继续 +1；连续回滚版本只增不减。
- `pnpm typecheck`、`next build` 全过。
- 浏览器（生产 3100，成片页）：载入 `v7`；顶栏预算面板把 60 改成 75，徽标变 `v8`、预算显示 `75.00`；打开历史抽屉点「撤销」，预算回到 `60.00`，徽标变 `v9`——回滚确实也计一版。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 只在明显的内容改动上加版本 | 「明显」没有客观边界，越定义越武断；作者每次改动都值得记一版 |
| 回滚把版本号带回来 | 徽标会往回跳、与日志顺序对不上，同一个数字既能是旧内容也能是新内容 |
| 用日志长度当版本号 | 日志长度每加载都在变，且含 `created` 与回滚，和「改到第几版」语义不同；需要时直接读日志即可 |
| 把版本存在 IndexedDB 单独维护 | 版本可由 `rebuild` 完全推出，单独存一份只会多一个会漂移的事实来源 |
| 给版本加语义化（主 / 次 / 修订） | 单人创作没有发布分支的概念，三段数字没人会去维护 |
