# ADR-0158：跨项目孤儿检查与安全清理

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：H3、F4、H18、ADR-0128、ADR-0129、R49、R59

## 背景

ADR-0128 的本机资产库按内容寻址，一个文件可能被多个项目共用。清理接口 `DELETE /api/asset/store` 一直要求客户端带「还在用的地址」当白名单，但设置页只送**当前项目**的引用（`referencedUris(project)`）。在项目 A 里点清理，会把项目 B 还在用的文件当成孤儿删掉；R49 已经把这个缺口写在风险表里，缓解状态是「待补：多项目共用资产库时的引用清单」。

现在有两个条件让收口变简单：事件日志按 `project.created` 切段回放（ADR-0088 / H4），设置页本来就会 `hydrate()` 读整条日志；本机资产库的清单接口也已经在。缺的不是新存储，而是把「所有项目」的引用算进白名单，并且在没把握时不做破坏性动作。

## 决定

1. `asset-inventory.ts` 新增两个纯函数：
   - `referencedUrisOfProjects(projects)`：多个项目的资产地址并集，按地址去重；
   - `orphanAssets(files, keep)`：地址不在白名单里的文件才算孤儿，回 `{ orphans, count, bytes }`。
2. 设置页「本机资产库」在浏览器里算白名单：当前项目 + 所有能回放的 `projectSegments`。资产库是这台机器共享的，白名单必须是并集，不能只取当前项目。
3. `GET /api/asset/store` 除数量与字节外多回 `files: [{ uri, bytes }]`，供浏览器做孤儿清单。只回地址与大小，不回内容；`DELETE` 的形状不变，白名单仍由客户端送。
4. 新增只读的「跨项目孤儿检查」块：显示白名单项目数、地址数、孤儿个数与总字节，列出前 5 个地址。它只列不删。
5. **有日志段回放不了时，只列孤儿，清理停用**：那段日志引用了什么我们不知道，拿并集删就是赌。界面写明「宁可少删，不误删别的项目」，清理按钮禁用；不送部分白名单上去。
6. 老的两步确认保留：先 `dryRun` 问服务端会删几个，确认句改成「所有能回放的项目都没引用」，再真删。迁移与清理仍都是显式动作。

## 理由

- **资产按地址共享**：内容寻址意味着同一段字节只存一份，按项目判断归属本身就是错的；只能按「所有项目的引用并集」判断。
- **浏览器是唯一知道项目的地方**：项目在 IndexedDB（ADR-0088），服务端没有项目。白名单只能在本地算，服务端只负责按白名单删盘上的文件。
- **回放失败时最危险**：只知道部分项目就删，等于把未知当成没人用。停用清理比「可能删错」诚实；账单与看板早就用「回放不了的段跳过并如实报数」的方式处理同一问题。
- **只列不删先落地**：作者先看见孤儿数量与地址，再决定要不要清；不自动清理、不在页面打开时删。
- **接口只多一个字段**：不新增路由、不新增依赖；`files` 是本机库自己的清单，不涉及项目内容或密钥。

## 后果

**正面**

- 在项目 A 里清理不会再删项目 B 的素材；R49 的核心缺口关闭。
- 日志有坏段时界面明确说「只列不删」，清理按钮停用，不靠作者记住风险。
- 孤儿检查只读，打开设置页不会删任何东西。
- 纯函数可测：并集、孤儿计数、空白名单都有用例。

**负面 / 代价**

- 有回放不了的日志段时，清理功能整体不可用；要等日志修好或压缩后才能清。这是有意的保守。
- 白名单在浏览器里按整条日志回放，项目很多时设置页打开会多一次回放开销；结果按 `events` / `project` memo，不会每个输入都重算。
- 孤儿清单只覆盖本机资产库，不碰对象存储里的对象（R59 仍在）；也不提供回收站。
- `GET /api/asset/store` 现在会回本机库的全部地址；它本来就能被同一台机器读到，不扩大权限，但响应体比分页大。

**不做**

- 对象存储桶的孤儿对象清理界面、回收站、多项目分桶、分片上传。
- 自动清理、定时清理、按容量淘汰。
- 服务端读取用户项目或上传引用清单。
- 回放失败的日志段用「部分项目白名单」兜底删除。
- 日志压缩与旧事件里 data URI 的清理。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 继续只按当前项目当白名单 | 会删别的项目还在用的文件，R49 已经写明 |
| 服务端保存所有项目引用 | 项目在浏览器，上传项目违背数据边界 |
| 回放失败时用部分白名单继续删 | 未知引用会被当孤儿，正是最危险的误删 |
| 自动清理孤儿 | 刚生成未挂载、刚回滚的引用都像没人用；必须作者确认 |
| 清理时连对象存储一起删 | 桶里对象要另列、另确认；R59 明确只做本机库 |
| 新建 `/api/assets/orphans` | 白名单在浏览器，服务端算不了；多一个端点没有收益 |
