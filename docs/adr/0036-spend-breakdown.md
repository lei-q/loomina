# ADR-0036 已花的构成要看得见：分镜 / 定妆 / 已淘汰

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0033（资产成本）、ADR-0035（预算护栏）、COST.md、H4 / H12

## 背景

ADR-0035 把预算做成真的之后，一个副作用变得刺眼：**已花是一个黑箱**。

- 定妆页和分镜页都显示"已花 ¥19.08"，但一个数里混着分镜 take 的钱、定妆图的钱；
- 重做多次的项目很快顶到预算上限，用户看不出钱花在哪——是定妆图铺得太多，还是一镜做了八版；
- 其中"已淘汰 take 的钱"最反直觉：钱确实花了，但那一版已经不要了。它不该被藏进同一行，也不该被减掉。

## 决策

1. **`spendOf` 拆出构成**：`Spend` 增加 `takes` / `assets` / `rejected` 三个数，`spent` 仍是它们的和（资产部分）。都是现算，不新增字段、不新增事件。
2. **`StageView` 带上整个 `Spend`**：`spent` / `unpriced` 保持原字段（界面已经在用），另加 `spend` 给金额面板展示构成。
3. **金额面板显示构成**：`已花` 下面缩进三行——`分镜 take`、`定妆图`、`已淘汰 take`；为 0 的行不显示，免得刷屏。
4. **已淘汰的钱单独一行，不从总数里减**：总数回答"这条片子花了多少"，那一行回答"其中多少是白花的"。
5. **不做按阶段分组的完整账本**：现阶段项目只有定妆与分镜两个会花钱的阶段；等声音、剪辑接通，再把 `Spend` 扩成按阶段分组的数组。

## 理由

- **预算护栏需要可解释**：拦住生成的那一刻，用户要能立刻看出"是定妆图堆得太多"。否则护栏像一道说不清理由的墙。
- **淘汰的钱不能藏**：藏起来会让预算数字看起来"莫名变少"，减掉又会低估真实成本（钱确实付了）。单独一行是唯一诚实的做法。
- **现算，不落字段**：构成完全由 take 与资产推导得出，重放日志自动一致；写进快照就会多一套账本（ADR-0033 的理由）。
- **先只做三行**：按阶段分组的账本依赖还没接通的阶段，提前设计只会猜错分组。

## 后果

**正面**
- 金额面板能回答"钱花在哪"：分镜多、定妆多、还是废稿多。
- 没有新增事件、没有迁移：`Spend` 是读模型的派生结构。
- 测试：`spendOf` 构成两条（淘汰单独算、没有淘汰时为 0 而不是缺省）。

**负面**
- 阶段只有"分镜 / 定妆"两类，"定妆图"把角色三视图、场景主镜、道具参考图混在一起；再细要等按阶段分组的账本。
- 已淘汰 take 的判定靠 `take.status`：一个镜头先留用再改判，钱按最后一次状态算进"已淘汰"或"有效"，不是按时间线逐次算。
- 金额面板的行数在极端情况下会变多（已花 + 三行构成 + 重做 + 预算 + 超出），窄屏要换行。
- 定妆页也显示"分镜 take"这一行——那里没有分镜动作，只是一起展示，略显越界。

**跟进**
- 声音 / 剪辑接通后，把 `Spend` 扩成按阶段分组的数组（H4）。
- 镜头级预算接通后，构成按镜分组（H10 剩余部分）。
- 是否要给"已淘汰 take"一个提示性的措辞（如"废稿"），交给文案设计。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 只在分镜页显示构成 | 钱是在定妆页花出去的，那一页更需要知道 |
| 把淘汰的钱从已花里减掉 | 低估真实成本；供应商按成功收费，废稿也付过 |
| 新增 `CostEntry` 事件流 | 为展示多一套事实来源；派生足够 |
| 一次做完整的分阶段账本 | 声音与剪辑还没接通，分组只能猜 |
