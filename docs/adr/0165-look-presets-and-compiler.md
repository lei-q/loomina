# ADR-0165：画面风格与摄影参数（B7 + I5）

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：B7、I5、I1、I2、I3、I4、B2、准则 P3 / P4 / P15

## 背景

到这一刻，所有出图提示词的最后一句话都是**硬编码**的：

| 位置 | 那句硬编码 |
| --- | --- |
| `buildShotPrompt` / `buildVideoPrompt` / `buildKeyframePrompt` | `竖屏 9:16，实拍电影质感，自然光，轻微胶片颗粒` |
| `buildSheetPrompt` / `buildPropPrompt` | `竖屏 9:16，实拍电影质感，柔光棚拍` |
| `buildMasterPrompt` | 与镜头同句 |

这条句子定义了一条片子的画面风格，但它散在五个函数里。作者想把整条片子
调成冷调都市，只能去手改每一格提示词（ADR-0148 的手改提示词是逐格的），
改到第三格就已经不一致了；而且**跨格的一致性正是短剧最贵的东西**。

## 决定

1. **风格收敛成项目上的一组参数**
   - IR 新增 `Project.look`：`{ presetId, contrast, temperature, texture, aspect, note }`，
     全部带默认值，缺省时编译结果与旧提示词逐字一致。
   - 事件 `project.updated` 新增可选 `look?: Look`，**整块替换**：这几项一起
     决定提示词最后一句，分开改会让中间态读起来自相矛盾。
   - `applyEvent` 用 `LookSchema` 校验后才落库；`note` 上限 80 字。

2. **编译是纯函数，编译结果不进 IR**
   - `packages/pipeline/src/look.ts`：`LOOK_PRESETS`（五个预设）、
     `compileLook(look)`、`compileStudioLook(look)`、`isDefaultLook`。
   - IR 里只存参数。提示词是这些参数的函数，换一句写法不该变成一次项目改动，
     也不该为它配失效机制。

3. **编译规则**
   - 预设与逐项参数**一致**时用预设的整句（写得比拼接更像人话）；
   - 不一致时**整句按参数重编**，只保留预设的质感名词（「黑色电影质感」），
     技术项一律以参数为准——把「冷调」和「暖调」拼在一句里，模型拿到的是
     自相矛盾的指令；
   - 没选预设且三项都是默认值时，原样返回旧的那一句；
   - 作者手写的 `note` 永远排在最后。

4. **定妆与道具走棚拍口径**
   - `compileStudioLook`：默认档保持 `竖屏 9:16，实拍电影质感，柔光棚拍`；
     作者改过风格时才接上项目质感，但**仍以「柔光棚拍」收尾**——定妆照要
     看清脸，不该跟着片子的硬光与雨夜走。

5. **三条服务端请求各自带一份 look**
   - `POST /api/asset` 的 sheet / master / prop 三个分支各收 `look`，
     `parseLook` 不合法就当没带——风格参数错不该把整张图拦下来。
   - 关键帧与视频的 look 已经随 `shotMaterial(project, shot)` 走
     （`ShotPromptMaterial.look`），不需要额外字段。

6. **界面：定妆页顶栏「风格」抽屉**
   - 五个预设卡（实拍电影 / 冷调都市 / 暖调家庭 / 梦境柔焦 / 黑色电影）+
     「不用预设」；选预设会把它的默认参数一起填进表单，作者仍可逐项改。
   - 三项参数：光比（柔 / 标准 / 硬）、色温（暖 / 中性 / 冷）、
     质感（干净 / 颗粒 / 柔焦）。
   - 「补充风格句」输入框（80 字）。
   - 「提示词最后一句」实时预览：改任何一项，那句人话立刻变。
   - 「存风格」写一条 `project.updated`；「恢复默认」回到默认档。
   - 抽屉底部明写「风格只影响下一次出图：已经出的三视图、关键帧与视频不会
     自动重做。要换风格重做，回到对应的格子重新生成——那会再花一次钱」。

## 理由

- **一致性是一处定义**：五个函数各写一句，改一处漏四处是时间问题。收敛成
  参数后，风格只有一处，提示词永远从它派生。
- **编译进 pipeline 而不是 web**：提示词本来就是 pipeline 的产物，
  把编译放在同一个包里，服务端与客户端拿到的句子永远一致。
- **不进 IR 存提示词**：存了就要配失效机制，而重算一次是毫秒级的事。
- **不选预设也能用**：三项参数各自有意义，作者可以完全不碰预设。
- **默认档逐字不变**：旧项目重算的提示词与以前一模一样，`generationNotice`
  与已出图的溯源对得上。

## 后果

**正面**

- 一条片子的风格第一次有了单一出处：改一次，所有下一次出图都跟上。
- 提示词最后一句在界面上可读、可预览，作者能判断「这句会送出去」。
- 预设把「冷调都市 / 暖调家庭」这类短剧常用取向变成一次点击。
- 全部纯函数：不调模型、不花钱、离线可用。

**负面 / 代价**

- 已出的图不会自动重做：换风格要逐格重新生成，那会再花一次钱。界面已如实说明。
- 预设的措辞与逐项参数之间需要一条规则（一致用预设、不一致重编），
  作者可能觉得「我改了暖调，为什么『深阴影』没了」——抽屉里有预览可对照。
- 只有五个预设，没有按题材自动推荐；预设本身是经验值，未做评测（I9）。
- 定妆照只跟一半风格（质感跟、光不跟），这是刻意的，但需要作者理解。
- 画面风格仍不覆盖「单镜的机位 / 景别 / 构图」，那属于 I1 / I4。

**不做**

- 风格学习 / 参考片分析（I6）。
- LUT 与调色（I3 / E4）。
- 按题材自动挑风格、风格评分与评测集（I9）。
- 把编译结果写进 IR 或溯源。
- 单镜级的风格覆盖（会破坏跨镜一致性）。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 让作者逐格手改提示词（ADR-0148） | 改到第三格就不一致了；跨格一致性是短剧最贵的东西 |
| 把编译后的提示词存进 IR | 要配失效机制，而重算是毫秒级的事 |
| 只做预设，不做逐项参数 | 光比 / 色温 / 质感是作者最常想微调的三项 |
| 预设与参数冲突时保留两者 | 模型会拿到「冷调……暖调」这种自相矛盾的指令 |
| 风格也覆盖单镜 | 单镜各自调风格就回到了不一致的老路；机位与景别另有 I1 / I4 |
| 定妆照完全跟项目风格 | 硬光与雨夜会让脸看不清，定妆的首要任务是看清脸 |
