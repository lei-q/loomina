# ADR-0212：整本剧本一起取（C24 第二档）

- 状态：已采纳
- 日期：2026-11-14
- 决策者：用户 + Claude
- 关联：C24、C1、C23、ADR-0199、ADR-0211

## 背景

跨空间取一场剧本（ADR-0199）一次只能取一场。一部 5–8 场的短剧，
换集时要点七八次、每次都从同一个面板里找下一场；而且中途失败会留下「取了一半」的剧本。

## 决定

1. **纯函数 `sceneBatchOf(source, current, tag, at)`**（`apps/web/lib/shared-scenes.ts`）
   - 按来源空间的场序逐场调用现有的 `sceneImportEvents`；
   - **一场一场串行推进**：第 2 场是在「第 1 场已经取过来」的项目上算 id 与就绪度，
     不会出现同一批里 id 互撞；
   - 返回 `{ events, scenes, shots, lines, skipped: {sceneId, label, missing}[], missingProps }`；
   - 取不过来的场（缺人 / 缺地点）**跳过并记原因**，其余照取——
     整本拒绝会让「只有一场缺个配角」时什么都拿不到。
2. **store 动作 `adoptSharedScenes(source, sceneIds, name)`**
   - 一次把整批事件写进日志；同一批共用一个 `at`（撤销一步整本退回）；
   - 先在草稿上整批 `applyEvent`，全部通过才落状态；
   - 一场都没取成时不写事件，`castError` 说清每场缺什么。
3. **面板**
   - 顶部「整本取过来」：勾选要取的场（默认全选能取的），一次取；
   - 每行仍可单取（保留 ADR-0199 的行为）；
   - 结果写「取来 N 场 · M 镜 · K 句；跳过 J 场（缺…）」。
4. **不做**
   - 不做「替换已有场次」（取来的一律追加到末尾，与单场一致）；
   - 不做跨模板自动补人 / 补地点（那是 C17 的事，取用前先在定妆页取人）。

## 理由

- **串行而不是并行**：id 重编与就绪度都依赖「当前项目」，并行算必然撞 id。
- **部分成功优于全失败**：缺一个配角就整本拿不到，比「拿到 7 场、明确告诉你第 8 场缺谁」更糟。
- **共用 `at`**：整本取用是一次操作，撤销就该一步退回（与 F2 同口径）。

## 后果

**正面**

- 换集时一次把整本剧本搬过来，不用点七八次。
- 跳过的场有明确原因；其余场照常可用。
- 不新增 IR / 事件 / 日志版本。

**负面 / 代价**

- 追加而不是替换：同一本取两次会得到两份场次（作者要自己删）。
- 跳过的场不会自动重试；补人后要再点一次。
- 一次取很多场时，面板里没有预览（只有场数与镜数）。
- 整本共用一个 `at`，撤销会把整批一起退掉——想只退其中一场要用历史抽屉。
