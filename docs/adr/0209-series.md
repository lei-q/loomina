# ADR-0209：多集连载管理（A6）

- 状态：已采纳
- 日期：2026-11-14
- 决策者：用户 + Claude
- 关联：A6、A17、C.1、C15、C22、ADR-0104、ADR-0188、ADR-0197

## 背景

A6 一直挂着：跨集人物 / 世界观延续、结尾钩子管理。

到 ADR-0208 为止已有的东西：

- C15 多工作空间：一集 = 一个工作空间，各自一条日志；
- C22 照空间设定开新一集：建空间时把故事 / 演员 / 场景 / 道具 / 技能 / 风格带过去；
- A17 节拍表里有「系列」模板（每集一个小闭环 + 一个大钩子）；
- 故事圣经有 `hooks.opening` / `hooks.ending`，但**两集之间没有任何连接**。

所以「这是第几集」「上一集留的悬念接住了没有」现在只能靠作者自己记。

## 决定

1. **集序写在工作空间登记表，不进事件日志**
   - `WorkspaceMeta` 加两个可选字段：`seriesId?: string`、`episodeNo?: number`。
   - 新建空间时：来源空间有 `seriesId` 就继承，`episodeNo` 取该系列当前最大值 + 1；
     没有来源（从零开工）就以自身 id 作为 `seriesId`、`episodeNo = 1`。
   - 旧数据没有这两个字段：读出来按「单集」（`seriesId = 自身 id`、`episodeNo = 1`）显示，
     **不迁移、不改写 IndexedDB**。
   - 理由：一部剧有哪几集是**这台机器上的编排**，不是某一集的内容；
     写进 `Project` 会让每一集的日志都背一份「我是第几集」，跨集改集序还要写事件。
2. **连载概览是只读派生视图**（`apps/web/lib/series.ts`）
   - `seriesOf(spaces)` 把工作空间按 `seriesId` 分组，组内按 `episodeNo` 排；
   - 每集给出：集序、标题、场 / 镜 / 成片数、`hooks.ending`、`hooks.opening`、
     以及**钩子接力**：上一集结尾钩子 → 这一集开场钩子；
   - `hookLink` 给三态：`linked`（词面有交集）/ `weak`（两段都在但毫无交集）/ `missing`（某一侧空）。
     这是**启发式提示**，不阻断、不改内容（与 C13 静音可懂度同一口径）。
3. **设置页「连载」区**
   - 按系列分组，每集一行：集序 · 标题 · 场 / 镜 / 成片 · 结尾钩子摘要 · 接力状态；
   - 断链的行挂一句人话「上一集结尾说「…」，这一集开场说「…」，看不出接上」；
   - 「去这一集」直接切工作空间（整页加载，与 C15 同一条路）。
4. **顶栏空间菜单显示集序**
   - 登记表里有 `episodeNo` 时，空间名后面加 `· 第 N 集`。
5. **不做的事**
   - 不新增 IR 字段、事件类型、日志版本；不改 `Project`。
   - 不做「一键把上一集的结尾钩子写进这一集」（那是改内容，要作者自己决定怎么写）。
   - 不做跨设备同步（`seriesId` 只在这台浏览器里有意义）。

## 理由

- **编排与内容分开**：哪几集属于一部剧、谁排第几，是作者对本机素材的组织；
  和「这一集写了什么」是两回事。放进 `Project` 会让内容与编排互相绑架。
- **只读派生**：钩子接力能提示「这里可能断」，但「算不算接上」是创作判断；
  自动改写钩子会把作者的句子改坏（P6 默认 AI 初稿，但改写要作者点）。
- **沿用 C15 的切换路径**：连载里点一集就是切工作空间，整页加载，不引入第二套导航。

## 后果

**正面**

- 一部剧有几集、当前在第几集、钩子接没接上，一眼能看到。
- 不新增 IR / 事件 / 日志版本；旧数据不用迁移。
- 新建下一集时集序自动递增，不用手记。

**负面 / 代价**

- 集序只在这台浏览器里：换机器、清本地库后要重新排。
- 工作空间改名不影响集序；改集序本身没有界面（只能靠新建时自动递增）。
- 钩子接力是词面启发式：换了说法的接续会被标成 `weak`，作者要自己判断。
- 删掉某一集后集序出现空号（不自动重排，避免悄悄改动别的集的编号）。
- 不做「一部剧打包导出」；跨集复用仍走 C22 / C23 / C24。
