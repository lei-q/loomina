# ADR-0047 台词排序：不新增事件，换一次 dialogueIds

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0045（增删句）、ADR-0046（换人）、FEATURES A5

## 背景

增删句只能追加到末尾（ADR-0045）。台词的先后是剧情信息：「你先说」还是「他先说」不一样。IR 里顺序就是 `Shot.dialogueIds` 的数组顺序，剧本页按它渲染；要调顺序，只需要换这个数组。

## 决策

1. **不新增事件类型**：`shot.updated { patch: { dialogueIds } }` 已经允许替换整个数组，排序是一次镜头级改写，用它就够了。
2. **store `moveDialogue(lineId, "up" | "down")`**：找到所属镜头，在 `dialogueIds` 里和相邻的一项交换，写一条 `shot.updated`；到顶 / 到底、锁定镜头都不写事件。
3. **不改时长**：顺序不影响台词总时长，镜头时长不动。
4. **界面**：一镜里有两句以上才出现 `↑` / `↓`，到顶到底置灰；锁定镜头置灰。单句的镜头不显示箭头，避免一排灰按钮。

## 理由

- **顺序本来就存在镜头里**：另开 `dialogue.reordered` 会与 `dialogueIds` 两个事实来源打架，回放时谁对说不清。
- **一条事件一次动作**：交换两个 id 是一条镜头改写，不是两句台词各自变化。
- **箭头而不是拖拽**：拖拽要处理落点、触屏与键盘可达性；两句以内的微调，箭头足够，而且能被测试直接操作。

## 后果

**正面**
- SH-02 加了两句（「门开着呢。」「谁在那儿？」）后点第二句的 `↑`，顺序交换；台词总时长 35.6s 不变，日志只多一条 `shot.updated { dialogueIds: [...] }`。
- 单句镜头不显示箭头，界面不堆灰按钮。
- 测试：web 111 条（新增 2 条：下移换顺序与回放、到顶 / 锁定不写事件）；`pnpm typecheck`、`pnpm build` 通过。未改 IR，IR 测试数不变（60）。

**负面**
- **一次只能挪一位**：没有「拖到某一句之前」，长对话要连点。
- **没有跨镜头移动**：不能把一句台词从这一镜挪到另一镜，得删了重加。
- **顺序变化不进版本列表**：版本只记文本改写与换人之外的结构变化看不到；要回看只能翻日志。
- **箭头依赖鼠标**：虽然按钮可聚焦，但没做键盘快捷键（如 Alt+↑）。

**跟进**
- 拖拽排序 / 键盘快捷键。
- 跨镜头移动台词。
- 版本列表记录结构变化（换人、排序）而不只是文本。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 新增 `dialogue.reordered` 事件 | 与 `shot.dialogueIds` 重复，回放有两个事实来源 |
| 用 `dialogue.updated` 带 `order` 字段 | 顺序是镜头级的，写进单句事件会让「哪句在前」分裂到多处 |
| 拖拽排序 | 交互与可达性成本高，这一刀先给出能点、能测的最小形态 |
| 一次点击直接输入目标位置 | 两句的场景里下拉比箭头慢 |

## 附记（2026-11-10，ADR-0053）

上面「负面」里的「顺序变化不进版本列表」已由 ADR-0053 收口：镜头台词下方新增 `这一镜的顺序改过 n 次` 的折叠，倒序显示每个顺序版本，并可`用这版`写回；`setDialogueOrder` 用一条 `shot.updated { dialogueIds }` 完成回退，台词总时长不动。
