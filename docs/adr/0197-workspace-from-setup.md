# ADR-0197：照一个工作空间的「设定」开新一集（C22）

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：C.1、C15、C16、C17、C20、C21、ADR-0188、ADR-0194、ADR-0195

## 背景

用户清单 C.1 要求「故事、剧本、定妆素材（人物 / 场景 / 道具）、音频、视频都可加入资产库并复用，跨集直接复用同类场景、道具、演员，不再花钱生成」。

到 ADR-0196 为止，跨空间复用的入口是**逐个资产挑**：参考图（C16）、演员 / 场景 / 道具整套（C17）、一拍视频（C20）、一版配音（C21）。做下一集时仍然要：

1. 新建工作空间 → 拿到一份示例项目；
2. 在故事页把故事圣经重写一遍；
3. 演员 / 场景 / 道具重新登记，再一个个去别的空间挑定妆图与参考图；
4. 技能、风格、调色、画幅、字幕版式重新设一遍。

这些**设定**跨集基本不变，却要在每一集重新搬一次；作者真正要改的只是这一集的新故事与新分镜。

## 决定

1. **建空间时多一个来源选项**：`createWorkspace(name, fromWorkspaceId?)`
   - 顶栏「空间」菜单的新建表单多一行「新空间从哪里开工」：
     「示例项目（从零开工）」或「照「{当前空间名}」的设定开工（带故事 / 演员 / 场景 / 道具，不带成片）」。
   - 不选来源时行为不变（示例项目）。来源只在建空间这一刻选一次，
     之后不再同步——两个空间从此各自独立，不是「父子项目」。

2. **只搬设定，不搬成片**：`projectFromSetup(source, { id, title })`
   - **跟着走**：`story`（含弧光 / 关系 / 分集）、`skills`、`characters`、
     `locations`、`props`、`look`（风格）、`grade`（调色）、`frame`（画幅）、
     `brand`（品牌包）、`subtitleLayout` / `subtitleTranslation`，
     以及时间线的 `mix`（混音总线）。
   - **不跟**：`scenes`、`shots`、`dialogue`、`voiceTakes`、`takes`、
     `timeline.items / music / sfx`、`subtitleOverrides`、`approvals`、
     `gates`、`publishPackages`、`authorizations`。新的一集从空白故事板开始。
   - 版本号回到 `1`，`id` / `title` 用新的。

3. **资产只带被设定引用的那些**
   - `referencedAssetIds(source)` 收：演员定妆各角度、演员参考图、场景主镜与参考图、
     道具参考图、调色 LUT。成片 take、配音、封面等**不进**新项目。
   - 复用资产记 `source: "library"`（`generated` 的原样转成 `library`），
     `costCny` 与 `review` 不抄：这笔钱不是这一集花的，复核结论也不属于这一集的输出。
   - 上传 / 导入的保留原来源：授权仍是当初那一次。
   - 地址（`loomina://assets/<sha>` / `s3://`）不变，不复制字节。

4. **id 原样保留**
   - 新项目是一条独立日志，不会与来源项目撞 id；保留 id 才能让故事里引用的
     角色 / 场景 / 道具、场景主镜（`masterShotId`）、故事的弧光与关系继续有效。
   - 复制不是共享：`structuredClone` 之后改新项目不动来源。

5. **失败要说清楚**
   - 来源日志读不出来 / 校验不过：`workspaceError = "来源空间的日志读不出来。"`，
     不建空间、不落半份数据。
   - 同名、空名、过长、浏览器不支持多空间：沿用 ADR-0188 的拒绝。

## 理由

- **场景是「建空间」而不是「导入项目」**：用户要的是同时开多个完整流程（C.3），
  下一集本来就该是一个独立工作空间；把「带设定」放进新建这一步，比先建空空间
  再导一遍少一次往返，也不会留下「半导入」的中间态。
- **设定与成片分开**：定妆图、风格、调色是跨集资产；分镜和 take 是这一集的产出。
  把成片一起搬过来会让新空间的统计、闸门、审批全部继承旧集，等于复制了一集。
- **`library` 口径统一**：与 C16 / C17 / C20 / C21 同一种来源标记，
  「复用不花钱」这件事在账目上有一致的读法。
- **不做自动同步**：项目是单人 C 端工具，跨集同步会带来合并冲突与「改了哪一份」的
  困惑；需要新设定时作者再建一次空间即可。

## 后果

**正面**

- 开下一集从「重写一遍设定」变成「选一下来源」，演员 / 场景 / 道具的定妆与
  参考图、技能、风格、调色、画幅、字幕版式一次带全。
- 复用资产在账目上是 `library`：新空间不显示这笔花费，也不会被算成未定价调用。
- 来源空间完全不受影响；两个空间此后各走各的日志。

**负面 / 代价**

- 只是建空间那一刻的快照：来源空间后来改了设定，新空间不会跟着变。
- 只支持「照当前空间」开工；不能从任意历史空间挑（列表里选别的空间要再开一档）。
- 不搬 `authorizations`（授权记录）：复用资产仍按各自原来源追溯，新空间没有一张
  汇总的授权表。
- 不搬技能的分阶段启用差异之外的东西（技能本身原样复制，包括启用状态）。
- 资产地址指向本机 `.loomina/assets`：换机器后若没有对象存储，定妆图会显示不出来
  （与 C16 / C20 同一个已知限制）。
