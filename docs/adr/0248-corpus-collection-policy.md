# ADR-0248：评测素材按完整场次收，不做「摘录模式」

- 状态：已采纳
- 日期：2026-11-15
- 决策者：用户 + Claude
- 关联：I9、I8、A13、ADR-0246

## 背景

第一次跑分（ADR-0246 落地节）用示例项目的 5 个场次切出 5 段素材，误报 4 条全部落在
**V1（场首无建立镜头）、V2（画外音）、V7（切率）**。原因不是规则写错，而是素材口径：
从完整戏里切出来的摘录，本来就不一定有建立镜头、允许画外音、切率基准也不同。

于是有两条路：给规则加「摘录模式」，或者规定素材必须是完整场次。

## 决策

### 1. 素材单位 = 完整场次（或整集）

- 默认按场次切：`clipsByScene(project)` 一场一段；
- 需要整集口径时用 `--whole`，一份项目就是一段素材。

### 2. 不做「摘录模式」

理由：

1. V1 / V2 / V7 判的都是**场级事实**，规则本来就是为完整场次写的。
   给同一批规则加第二套口径，等于让「这条规则到底在判什么」出现两个答案。
2. 摘录模式一旦存在，素材收集会自然滑向「随手剪一段」，
   而阈值标定需要的恰恰是完整场次的分布。
3. 现在一条真实素材都还没有——先为一个还没有的用例加模式，是本末倒置。

如果将来真的需要按摘录收（例如只有授权片段），**另开 ADR**，并把「哪几条规则在摘录下失效」
写清楚，而不是在运行时偷偷关规则。

### 3. 导入路径：工作空间导出包 → 回放 → 按场切

收素材的卡点不是标注，是「怎么把项目变成素材文件」。做法：

```bash
pnpm eval:corpus:import -- \
  --in ~/Desktop/夜班-2026-11-15.json \
  --source "夜班（自制）" --license self-made
```

- 读 `loomina.workspace-export` 包（C15 顶栏「空间 ▾ → 导出」）；
- `migrateLog` 迁移到当前日志版本，`rebuild` 回放出项目；
- `clipsByScene` 一场一段，清空 take / 时间线 / 审批 / 闸门（它们引用被切掉的镜头）；
- `expected` **留空**：规则该不该报由人看过再标，工具不替作者下判断。

### 4. 授权必填

`--license` 缺失直接报错，与 ADR-0246 的 `meta.license` 必填同一条口径（H7）。

## 后果

**正面**

- 口径只有一套，阈值标定不会被摘录污染。
- 真实素材的收集路径被打通：导出 → 一条命令 → 人工标注。

**负面**

- 素材作者要能导出**包含完整场次**的项目；只留了一段片子的素材无法入库。
- 导入的 `expected` 是空的，仍然需要人工逐段看一遍。

## 替代方案

1. **摘录模式**：实现要动 `analyzeStoryboard` 的选项与四条规则的分支，
   而且会让「规则在判什么」分叉——否决。
2. **只按整集收**：更严格，但会让「一场戏」这种单元也用不上；
   场次已经是规则的自然单位，按场收足够。
3. **不做导入，靠手写 JSON**：太费劲，真实素材会一直停在 0 段。
