# ADR-0068 中间插入场次与镜头

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0064（新建只能加末尾）、ADR-0060（场序 / 镜号重排）、ADR-0067（删除）、FEATURES A21

## 背景

ADR-0064 把"新建"限制在末尾：`scene.added` 要求 `index === scenes.length`，`shot.added` 要求 `index === scene.shotIds.length`。这条限制当时是为了让校验简单——末尾插入不用重排任何东西。

但它把"想插在中间"变成了"先加到末尾，再一路挪"：场次要连点 `↑`，镜头根本没有挪的按钮（只有台词能挪）。写剧本时常常是"这场和这场之间还要一场"，末尾添加并不够用。

## 决策

1. **放开位置，保留语义**：`scene.added` 的 `scene.index` 允许落在 `[0, scenes.length]`，`shot.added` 的 `shot.index` 允许落在 `[0, scene.shotIds.length]`；落在末尾就是原来的行为。越界或负数拒绝（「位置越界」）。
2. **插入即重排**：`scene.added` 把新场插进按 `index` 排好的数组再整体重编号；`shot.added` 把新 id 插进 `scene.shotIds` 的指定位置，同场所有镜头的 `index` 按新的 `shotIds` 重算。这样"场号 / 镜号连续"这条不变量不用改。
3. **不新增事件**：还是 `scene.added` / `shot.added`，只是允许的位置变宽。日志里 `index` 已经写明了落点。
4. **store 加一个可选参数**：
   - `addScene(locationId?, afterSceneId?)`：给了 `afterSceneId` 就插在它后面，否则接在末尾；
   - `addShot(sceneId, afterShotId?)`：给了 `afterShotId` 就插在它后面，否则接在这一场末尾。
   - 指定的 id 不存在就拒绝，不写事件。
5. **界面**：
   - 每镜 `删这一镜` 右边加 `＋ 插一镜`：在这一镜后面插一镜；
   - 每场末尾 `＋ 加一镜` 右边加 `＋ 插一场`：在这一场后面插一场空场。
   - 两个新钮都是虚线描边，与实线 / 主按钮分得开；只读标签页不显示。
6. **新场默认值不变**：地点仍取第一个地点，内景、日；用户随后改场头（ADR-0050 / ADR-0056）。

## 理由

- **插入点就是"这一镜 / 这一场之后"**：人写剧本时想的是"在这句后面还要一镜"，不是"插到第 7 位"。界面用"插在后面"表达，事件里仍然是 index。
- **重排交给事件**：场号与镜号都是从 `index` 推出来的；插入时一次性重编号，读取侧（`orderShots`、`toScriptView`）不需要知道有"插入"这种操作。
- **不造 `scene.inserted` / `shot.inserted`**：同一件事（新增一个场 / 镜）多一种事件，会让 ADR-0057 的过期判据、事件白名单与所有 `switch` 都要多认一条，收益为零。
- **放在"删"旁边**：这一行已经是"这一镜的边界操作"，插入是删除的邻居，不用回场末找。

## 后果

**正面**
- 剧本页 SH-01 点 `＋ 插一镜` → 新镜成为 SH-02，原来的 SH-02 变成 SH-03；日志一条 `shot.added { index: 1 }`。
- 第 1 场末尾点 `＋ 插一场` → 新空场成为第 2 场，原来的第 2 场变成第 3 场；日志一条 `scene.added { index: 1 }`。
- 末尾添加的行为完全不变：不传插入点就接在最后。
- 测试：IR 82（新增 3：场次插到开头、镜头插到中间、越界 / 负数拒绝）、web 174（新增 3：插场、插镜、陌生插入点拒绝）；gateway 17、pipeline 22；合计 295。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：1 场 2 镜的剧本，SH-01 `＋ 插一镜` 后 3 镜、新镜为 SH-02；第 1 场 `＋ 插一场` 后 2 场，新空场为第 2 场、地点沿用第一个地点。

**负面**
- **不能选插入的场号 / 镜号**：只能"插在后面"，要插到第 5 位得先点到第 4 位。
- **插入会让后面的镜号全变**：正在别处说的"SH-07"可能变成 SH-08；台词与帧按 id 挂着，不受影响，但口头编号会漂。
- **没有撤销**：插错了只能删。
- **新场沿用第一个地点**：插在两场中间时，常常想沿用**前一场**的地点与日夜，现在还得手改场头。

**跟进**
- 新场默认沿用前一场的地点 / 日夜。
- 插入点选择器（插到第 N 场 / 第 N 镜）。
- 整组撤销最近一次插入。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 新增 `scene.inserted` / `shot.inserted` 事件 | 与 `added` 只差一个位置；多一种事件所有 `switch` 与白名单都要跟着长 |
| 保持只能加末尾，靠 `scene.moved` 挪 | 场次可以挪，镜头没有挪的操作；而且挪一次写一条事件，插入一次也是一条 |
| 插入时把后面的 id 重新编号（`s-02` → `s-03`） | id 是引用键，改 id 会打断台词、take、帧、时间线的引用；编号只能由 index 推 |
| 让用户填目标场号 / 镜号 | 多一个输入框与校验；"插在后面"已经覆盖绝大多数写剧本的动作 |
| 新场自动沿用前一场的地点与日夜 | 是个更细的默认值问题，独立处理更好追踪；这次先保持"第一个地点"的既有行为 |
