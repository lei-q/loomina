# ADR-0108：补上 V3 轴线、V7 切率、V9 尾帧与 V11 节拍顺序

- 状态：已采纳
- 日期：2026-11-11
- 关联：A11、A12、A13、B17、B12、ADR-0096、ADR-0103、ADR-0106

## 背景

ADR-0096 落地分镜检查时，只做了能可靠判断的 V1 / V2 / V4 / V5 / V6 / V8，面板底部老实写着「V3 轴线、V7 切率曲线、V9 模型能力还没查：需要 3D 走位与能力矩阵」。之后 B17 补了镜头内调度（`staging: left / center / right × foreground / midground / background`），B12 补了模型能力矩阵，条件已经具备一半：

- **V3** 没有 3D 坐标，但左右调度已经够判断「同一场相邻两镜里两个角色是不是换边了」；
- **V7** 不需要外部标定，每拍的平均镜长与全片平均一比，就能找出「该碎的拍不碎」；
- **V9** 运镜本来就只作为提示词提交，真正能判的硬能力是尾帧：网关没有尾帧字段，画了尾帧也不会送进视频；
- **A11** 一直缺一条：节拍可以标，但标完顺序对不对没人查。

这一轮只补校验，不改生成、不加硬闸门（ADR-0103 的取舍）。

## 决策

### 1. V3：用 B17 调度做轴线近似

只看**同一场相邻两镜**：

- 两镜都标了 `staging`，且至少共享两个角色；
- 任一共享角色对儿的左右差号翻转（左 / 右互换），就提示；
- 站 `center` 的角色、只在一镜出现的角色、跨场、没有调度的镜头都不参与；
- 文案说「像越过了 180° 轴线」，不说「已越轴」；severity 是 `warning`，不标红。

```ts
type StoryboardRule = "V1" | "V2" | "V3" | "V4" | "V5" | "V6" | "V7" | "V8" | "V9" | "V10" | "V11";
```

没有 3D 坐标就不声称精确：如果两镜之间插了中性镜，或角色真的在走动，启发式会漏判或误报。这是可接受的，因为结果只提示。

### 2. V7：每拍平均镜长与全片对比

`BeatSpan` 新增 `aslSeconds`（平均镜长）与 `cutsPer10s`（每 10 秒切几次），面板在每一拍下面直接显示 `3 镜 · 2.0s/镜 · 5.0 切/10s`。

提示条件：

- 只查该碎的拍：`hook / escalation / turn / climax / endHook`；
- 这一拍至少 4 秒；
- 只有一镜，或多镜但平均镜长 ≥ `max(3.5, 全片平均 × 1.6)`。

文案同时给出这一拍与全片的平均镜长，作者能判断是补反应镜还是拆镜。慢的拍（铺垫 / 收束）不查：短剧不是越快越好。

### 3. V9：只查尾帧，运镜如实说明

`StoryboardOptions` 新增 `videoAcceptsLastFrame`，默认 `false`。为 `false` 时，凡 `shot.keyframes.lastAssetId` 有值就把这些镜头汇总成一条提示：

> 第 1、4 镜已经画了尾帧，但当前视频模型只吃首帧（网关没有尾帧字段）：尾帧不会送进视频，落点与口型只能靠提示词。

- 不逐镜重复，一条汇总；
- 供应商补上尾帧字段后，调用方传 `true`，规则自然消失；
- 运镜没有「不支持」的问题——`CameraSpec` 一直编进提示词，所以面板底部写「运镜仅提示词」，不把它算成校验失败。

### 4. V11：节拍顺序

新增 `V11`，查三件事：

1. 全片第一镜不是 `hook` → 「前 3 秒先给一个能抓住人的画面」；
2. 最后一镜不是 `endHook` → 「结尾留一个新悬念」；
3. 同一场里相邻两镜的节拍序号往回走（例如 `climax → setup`）→ 「在倒退」。跨场重新起势不算，一轮新的冲突可以在下一场从铺垫开始。

只有一镜的项目不查首尾；没有显式标注的旧项目按镜序推断，推断序列本身不会倒退，所以不会凭空产生 V11。

### 5. 界面

分镜页「检查」抽屉：

- 每一拍多一行平均镜长与切率；
- V3 / V7 / V9 / V11 的问题和既有规则一样可以点「去 SH-xx」；
- 底部改成说明每条规则的边界：「V3 只看同一场相邻两镜的左右调度，没有 3D 坐标，只说『像』越轴，不标红；V7 拿每拍平均镜长与全片对比，查该碎不碎的拍；V9 只查尾帧」；
- 多一行当前视频模型能力：`首帧 ✓ · 尾帧 ✗ · 运镜仅提示词 · 单镜 1–8 秒`。

所有新规则都是 `warning`，不拦导出与生成。

## 后果

**好的一面**

- A13 的 V1–V11 都有了可执行版本，面板不再留一块「还没查」；
- V3 用的是作者刚刚在 B17 面板里填过的调度，改完立刻能在检查里看到结果；
- V7 的指标是真实算出来的，不是形容词；作者能看到全片与单拍的差距；
- V9 把「尾帧只是参考」这件事说清楚，避免作者以为模型会照着尾帧落；
- V11 补上 A11 的顺序合理性，节拍不只是标签。

**代价与风险**

- V3 是启发式：真实走动、中性镜、三人都换边都可能误报或漏报；文案因此只说「像」，不阻断；
- V7 的阈值（4 秒、1.6 倍、3.5 秒）是本项目当前的经验值，还没有 I9 评测集标定；
- V9 只覆盖尾帧，不覆盖供应商实际执行运镜的程度；
- 规则变多后，旧项目可能一次出现很多提示；这些提示不阻塞任何操作，但会增加面板长度。

## 验证

- 单元测试：V3 翻边 / 只共享一人 / 有人站中 / 跨场；V7 单长镜、多镜偏慢、3.9 秒不提示、拍级统计；V9 有尾帧 / 模型支持尾帧；V11 首尾顺序、场内倒退、跨场重起势、单镜不查。
- 浏览器：在分镜检查抽屉里改节拍与调度，能立刻看到 V3 / V7 / V11 的出现与消失；拍行显示 `n 镜 · x.xs/镜 · y.y 切/10s`；底部显示当前视频模型能力。
- `pnpm typecheck`、`pnpm test`、`pnpm --filter @loomina/web build` 全过。
