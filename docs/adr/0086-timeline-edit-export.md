# ADR-0086 时间线、初剪与导出：先让整条片子排得出来，再谈渲染

- 状态：已接受
- 日期：2026-11-11
- 决策人：用户 + Claude
- 关联：ADR-0001（OTIO 交换）、ADR-0004（不自建 NLE）、ADR-0008（AI 标注）、ADR-0021（发布是底线）、ADR-0083（多 Take）、ADR-0085（配音）、E1 / E2 / E3 / E6 / D3 / G1

## 背景

分镜、首尾帧、视频 take、配音都已经能走通，但「整条片子」还只存在于预演里：预演按镜头时长铺，不落时间线，也不能换 take。IR 里早就有 `TimelineItem { shotId, takeId, startMs, durationMs }` 与「take 必须属于该镜」「片段不得重叠」两条不变量，但没有一条事件能改它——`timeline` 只能靠 `project.created` 的快照带进来。

导出这边的地基也不平：ADR-0004 定的是「浏览器内预览 + 服务端 ffmpeg 渲染」，但这台机器的 `/opt/homebrew/bin/ffmpeg` 现在起不来（缺 `libx265.216.dylib`），服务端渲染管线也还没写。也就是说，这一刀不能假装能出 mp4。

## 决策

1. **一条 `timeline.updated` 整条替换时间线**（`packages/ir/src/events.ts`）。初剪、换 take 都写这一种事件，参数是完整的 `items` 数组。applyEvent 当场校验：id 不重复、镜头与 take 存在且 take 属于该镜、起点非负整数、时长为正整数、片段不重叠——与 `validateProject` 的两条不变量同口径，读写两个方向都不放坏数据进来。
2. **自动初剪（E2）按剧本顺序选 take**：场次顺序 → 场内镜序；每一镜优先取最后一条「留用」，没有留用就取最后一条没被淘汰的；一条可用的都没有就跳过，并把镜号报出来。片段 id 固定 `tl-<shotId>`，时长直接读 `shot.durationMs`（它已经被台词与音轨校正过，准则 P5），起点接着上一段累加。
3. **换 take（E3）只换这一镜的版本**：必须是同一镜头、且不是 `rejected`。换的时候整条 `timeline.updated` 重写，起点与其它片段不动；两版完全相同就不写事件。
4. **成片读模型 `toEditView`**：片段按起点排，画面依次取「这一 take 的视频 → 这一 take 的图片 → 首帧 / 尾帧 → 空」；台词按片段起点换算成整条片子的绝对时间，音轨从 `DialogueLine.audioAssetId` 取。读模型同时给出全长、没画面的片段数、有配音的镜头数、还没进时间线的镜头数。
5. **成片页 `/edit`**（顶栏「成片」可达）：左侧 9:16 播放器 + 字幕 + 安全区参考线；右侧时间线轨道（按片段时长分宽，点哪段跳哪段）、当前片段的所有 take（点一下就是换版本）、导出区。播放用 50ms 一跳的自维护进度，视频静音播放（对白音轨另放），无头环境解不开视频也不影响界面状态。
6. **字幕样式（D3）先做两档模板**：`默认` 与 `大字`，字号用 `cqw`（相对画面宽度）、离底边 14% / 18%，外加 8% / 6% 的安全区参考线。样式作用于预览与导出，不烧进视频（还没有视频渲染）。
7. **导出四件事**（E6 / G1，全部本地生成、不经过服务器）：
   - **自包含预览 HTML**：把片段、字幕、音轨内嵌成一页，带播放 / 暂停 / 重来 / 进度条，双击就能看。这是准则 P20「自包含导出」在当前能力下的 L1 形态。
   - **OTIO JSON**：`Timeline.1`，V1 画面轨 + A1 对白轨，素材地址原样带出；剪辑软件可以接着剪。
   - **SRT 字幕**：按初剪的绝对时间，一句一条。
   - **发布包 JSON**：平台、标题、简介、话题、封面（首帧）、时长、AI 标注（显式 + 隐式，写死为 `AI生成`）、字幕、镜头清单，以及 `warnings`（没画面 / 没配音 / 还有镜头没进时间线）。**`video` 字段如实为 `null`**，`videoNote` 说明缺的是渲染这一步。
8. **mp4 渲染不做假**：本机 ffmpeg 缺 dylib，服务端渲染未实现，因此界面、导出包与文档都直说「mp4 还没做」。不生成指向不存在文件的路径，也不把预览 HTML 说成成片。

## 理由

- **整条替换比逐项增删更可核对**：时间线的价值在片段之间的关系（顺序、起点、不重叠）。逐项 `timeline.item.added/moved/removed` 回放时需要一堆小事件拼出同一件事，出问题时很难指出是哪一步把关系弄坏的。
- **初剪的规则要能被解释**：「优先留用，其次最新草稿，跳过全淘汰」一句话说得清。若按「生成时间最新」一刀切，会把用户已经明确留用的版本换掉。
- **换 take 属于成片决定**：在分镜页改 take 状态是「评价这一版」，在成片页换 take 是「这条片子用哪一版」。放在时间线上，观众看到的顺序就是事件里的顺序。
- **先出能看的文件**：没有 mp4 的时候，自包含 HTML 已经能让人完整看一遍节奏、字幕与配音；OTIO 则把「去剪辑软件出片」变成一条真实可走的路。等 ffmpeg 修好，服务端渲染接上同一条时间线即可。
- **AI 标注不能靠用户记得勾**：准则要求发布包必须有标注，导出的地方直接写死显式 + 隐式，避免「忘了勾」变成「没标」。

## 后果

**正面**

- 整条片子第一次有了可保存、可回放、可换版本的时间线；刷新后仍在本地事件日志里。
- 初剪一条命令铺满全片，跳过与缺口都看得见（镜号 + 原因），不是静默丢镜头。
- 换 take 不动其它片段，起点与总长保持稳定。
- 不依赖服务器就能导出四份文件；预览 HTML 在没有网络、没有播放器的机器上也能打开。
- 测试：IR 107（新增 4：整条替换、take 归属、重叠 / 重复 id、非法时长）、web 258（新增 16：初剪 3、读模型 3、导出 6、store 5，含 1 条改写）、gateway 20、pipeline 23，合计 408。`pnpm typecheck`、`pnpm test`、`pnpm --filter web build` 通过。

**负面**

- **没有 mp4**：本机 ffmpeg 起不来（`libx265.216.dylib` 缺失），服务端渲染未实现；发布包的视频位是空的。
- **没有转场、调色、变速**：片段首尾直接硬切（E4 / E5 未做）。
- **字幕只有两档模板**：没有逐字动画、描边粗细 / 位置微调、说话人样式；样式也不烧进画面。
- **预览播放是自维护计时**：50ms 一跳，长片可能积累几十毫秒漂移；视频静音，对白音轨按台词起点触发，没有混音与音量。
- **不能删片段 / 调顺序 / 拖起点**：换 take 之外的时间线编辑还没有；顺序仍由剧本决定。
- **发布包只落成文件**：IR 里的 `publishPackages` 还没有对应事件，导出不会写回项目，也没有合规检查（`ComplianceCheck`）。
- **OTIO 里 data URI 会很大**：素材仍内嵌在 IR，导出文件随视频体积膨胀；对象存储（H3）接上后应改为 URL。

**跟进**

- 修 ffmpeg（重装 / 固定 x265 依赖）并实现服务端渲染：草稿 540p、定稿 1080×1920，直接吃这份 `timeline.updated`。
- 时间线编辑：删片段、拖起点、调顺序、片段内裁切（需要新事件或扩展 `timeline.updated` 的语义）。
- 字幕逐字动画、位置 / 字号微调、按角色分样式（D3 余下部分）；字幕烧进视频。
- 发布包写回 IR（`publishPackages` 事件）、合规检查与发布台账（G1 余下、G10）。
- 多比例适配（E5）、转场与 LUT（E4）。
- 真实浏览器里用带音轨的片段听一遍：无头环境只能验状态。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 逐项增删事件（add / move / remove） | 回放要拼关系，出错时定位不到是哪一步破坏了顺序与不重叠 |
| 初剪一律取最新 take | 会把用户明确「留用」的版本换掉；留用是决定，不是时间戳 |
| 把时间线存在组件状态里，不落事件 | 刷新就丢，和「日志是事实」的架构相反 |
| 直接上 ffmpeg 渲染 mp4 | 本机 ffmpeg 起不来，服务端管线未写；先做能验证的导出，假装能出片更糟 |
| 预览 HTML 引用外部文件 / 服务器 | 违背自包含导出（P20）；换机器、断网就打不开 |
| 发布包里放一个假的视频路径 | 导入平台时才发现文件不存在，比明说「还没渲染」更浪费人时间 |
| 字幕样式做成自由拖拽 | 当前没有渲染管线承接自由布局；先给两档能落地的模板 |
