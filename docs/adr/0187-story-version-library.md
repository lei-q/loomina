# ADR-0187：故事版本库——每一次改字都留一版（C2 第二档）

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：C2、C14、A1、A16、A18、F2、ADR-0185、ADR-0123、ADR-0109

## 背景

故事是花过钱生成的东西：一次生成要跑 40–100 秒的文本模型，之后作者还会反复改
logline、梗概、钩子、弧光与关系。现在只有事件日志里留着旧字，界面上能看到的
是最新一版；改错一句想回到上一版，只能去历史抽屉里翻一条 `story.updated` 的 patch，
作者得自己看懂 patch 才能判断该退哪一步。

C2 的要求是：生成过的故事 / 剧本不要删，进版本库，之后能取回。故事层的字段全是
文字，旧版就在日志里，缺的只是**按版本读出来**的入口。

## 决定

1. **版本从事件日志派生，不新增字段**
   - 初版 = `project.created` 里的 `story`；之后每一条 `story.updated` 都是一版。
   - `storyVersionsOf(events)` 按 `applyEvent` 的同一套语义（trim、钩子、整组弧光 /
     关系）重放到每一版，输出 `{ eventIndex, at, story, changed }`。
   - 写回同样的字（`changed` 为空）不记一版：日志里有一条空改动，版本库里不该多一格。

2. **恢复 = 一条整份 `story.updated`**
   - `storyRestorePatch(current, target, characters)` 把那一版的五项文字、两个钩子、
     整组弧光与整组关系拼成 patch；`provenance`（这份故事从哪来）不动。
   - 指向**已删角色**的弧光与关系带不回来：硬写会让 `story.updated` 校验失败、
     整个恢复作废；先在 patch 里过滤掉，并如实返回 `droppedArcs` /
     `droppedRelationships` 条数，界面写「其中 n 条指向已删角色，没有带回来」。
   - 与现在完全一样时返回 `null`：不为一次空点击写事件。
   - 恢复不调模型、不花钱；一条事件，撤销 / 回滚按既有规则退。

3. **store 动作 `useStoryVersion(eventIndex)`**
   - 版本用 `eventIndex` 定位（不是数组下标）：日志只追加，位置稳定。
   - 只读、找不到那一版、已经是那一版：都不写事件，如实写 `castError`。
   - 成功写 `storyNotice`（一句回执，恢复带回来的条数在这里说）。

4. **界面：故事圣经底部一个「故事版本库 · n 版」折叠块**
   - 新 → 旧排列；每行写「时间 · 改了什么」+ 两行摘要（logline 优先，其次梗概）。
   - 最新一版标「现在这一版」，不出按钮；其余点「用这版」立即恢复。
   - 折叠块里写明：旧版从事件日志重建、恢复不重新生成、指向已删角色的条目不带回来。

## 理由

- **日志就是版本库**：另存快照会让「日志是事实」多出第二份真相，撤销、回滚、
  导出与日志压缩都要各维护一遍。派生一次的成本是几十条事件，可以忽略。
- **按 `eventIndex` 定位**：版本列表是派生数组，用下标会在多一条事件后整体错位；
  日志只追加，位置就是稳定 id。
- **过滤而不是失败**：删角色是正常操作，恢复旧故事也是正常操作；两者相遇时
  应该尽量恢复、并说清少了什么，而不是整次拒绝。
- **恢复也算一版**：恢复动作本身写了一条 `story.updated`，版本库里看得见「什么时候
  退回了哪一版」，这比悄悄把当前版抹掉更符合留痕原则。

## 后果

**正面**

- 改错一句可以点回上一版；弧光 / 关系一起回来，不用逐条重填。
- 版本、撤销、回滚、导出用的是同一份事件日志，没有额外同步问题。
- 不新增 IR 字段、不改 `LOG_VERSION`、不花钱。

**负面 / 代价**

- 每版都存整份故事快照（内存里重建时），长项目版本多时会占一点内存；
  界面上没有分页（目前故事版本数量级是几十条）。
- 只覆盖故事层：剧本页的逐镜动作 / 台词仍靠单条历史与撤销，没有「整份剧本版本」。
- 已删角色的弧光与关系无法从旧版恢复（角色本身要先建回来）。
- 故事生成的费用仍记在开工那一条上，版本本身不记钱——版本库保内容，不做账单。

## 不做

- 剧本 / 分镜的整份版本快照 UI（后续档）。
- 版本对比（并排 diff）、命名版本、锁定某一版。
- 历史版本的自动清理 / 保留策略。
- 跨项目 / 跨集复用故事（C1、A6）。
