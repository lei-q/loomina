# ADR-0198：跨空间取一版故事（C23）

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：C.1、C1、C2、C16、C17、C22、ADR-0187、ADR-0189、ADR-0197

## 背景

用户清单 C.1 要求「故事、剧本……都可加入资产库并复用」。到 ADR-0197 为止：

- 参考图（C16）、演员 / 场景 / 道具（C17）、视频（C20）、配音（C21）都能跨空间取；
- 「照空间设定开新一集」（C22）在建空间时把故事一起带过去；
- 但**已经开着的空间里**要把另一空间的故事拿过来，只能去故事版本库里翻，
  而版本库只覆盖本空间——故事是花过钱生成的东西，重建一份就是再花一次钱。

## 决定

1. **故事页多一个入口**：故事圣经底部「从别的空间取一版故事」。
   打开时才回放本机其它工作空间的日志（`loadWorkspaceProjects`），
   列出**有字**的故事：Logline / 梗概 / 类型 / 受众 / 调性 / 钩子 / 弧光 / 关系
   任意一项非空才出现；空故事不列。

2. **取用 = 一条 `story.updated`**
   - 复用 `storyRestorePatch`（C2 / ADR-0187）的整份写回语义：
     Logline / 梗概 / 类型 / 受众 / 调性 / 两个钩子整组替换，
     弧光与关系整组替换，`provenance` 不动。
   - 与现在完全一致时不写事件（`storyImportPatch` 返回 null，按钮显示「就是现在这版」）。
   - 不调模型、不花钱、不新增事件类型、不改 `LOG_VERSION`。

3. **角色按「同名同 id」认**
   - 不同空间各自用 `c-01` 指不同人是可能的，只对 id 会把弧光安到别人身上。
   - 只有本空间存在**同一个 id 且同一个名字**的角色，才带走指向他的弧光与关系；
     两端任一不存在的关系整条跳过。
   - 跳过的条数在挑之前就写在行里（「对得上 N 个角色 · 会跳过 M 条」），
     取用后 `storyNotice` 再说一遍。
   - `matchedCharacters` 只列真正被故事点过名、又对得上的角色。

4. **不带的东西说清楚**
   - `provenance`（这份故事从哪来）不跟：`story.updated` 本来就不收它。
   - `sourceDocument`（逐字导入的原文）不带：schema 规定它只能随 `project.created` 进来。
   - 不搬场次 / 分镜 / 台词：那是剧本，不是故事（见「未做」）。

## 理由

- **故事与剧本分开走**：故事是文字与人物设定，接过来不会与现有场次结构冲突；
  剧本带 id 引用，跨空间合并要先解决场 / 镜 / 台词的重编号，是另一件更大的事。
- **不合并不猜测**：不做「同名但 id 不同」的模糊匹配——猜错一次就是把别人的
  弧光安到自己的角色上，而且很难被发现。对不上就跳过并计数，作者自己补。
- **复用既有写入口**：`storyRestorePatch` 已经在版本恢复里处理了弧光去重、
  关系两端校验与「没变化不写事件」，取用与恢复是同一种写回，不需要第二套语义。

## 后果

**正面**

- 下一集沿用上一集的世界观时，故事、人物弧光、关系张力一次取完，不重新生成。
- 取用后可立刻在「故事版本库」里看到新的一版（日志本身就是版本库）。
- 与 C16 / C17 / C20 / C21 / C22 共用同一套「打开才读别的空间」的加载方式。

**负面 / 代价**

- 只覆盖故事层：场次、镜头、台词不会跟过来。
- 名字对不上就带不过来；改名过的角色要作者手写弧光。
- 逐字导入的原文与生成来源不跟，作者要自己留档。
- 清单是一次性读取：两个空间同时开着时，取到的可能是打开面板那一刻的版本。
- 没有故事内容的对比视图（不知道会被替换掉哪些字）。
- 坏日志的空间被静默跳过，界面上不提示「有一个空间读不出来」。
