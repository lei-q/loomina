# ADR-0092：成片渲染的远端素材受控下载

- 状态：已采纳
- 日期：2026-11-11
- 关联：ADR-0091（成片 MP4）、R27、E6.1

## 背景

ADR-0091 的成片渲染只收 data URI。供应商生成的视频是 `http(s)` 链接，浏览器无法直接读出字节塞进清单，于是带真实视频的项目只能渲到首帧或占位图（R27）。

两条路：

1. 接 H3 云端对象存储，生成后先转存，再让渲染读本地对象。
2. 渲染路由自己按白名单下载远端素材。

H3 被用户明确推迟（「先存在本地」）。当前阶段需要让真实视频能进成片，同时不能把渲染路由变成任意 URL 的下载器。

## 决策

渲染清单允许片段与音轨带 `remote`：

- 片段：`{ durationMs, remote, mediaKind, fallback }`，`fallback` 必填，是 `data:image/...` 的兜底图。
- 音轨：`{ remote, startMs }`。

服务端行为：

- 域名必须在环境变量 `RENDER_ALLOWED_HOSTS` 里（逗号分隔，支持 `host:port`、裸域名、`*.example.com`）。为空则一个都不下载。
- 只接受 `http:` / `https:`；重定向后的最终 URL 再查一次白名单，防止 302 绕过。
- 20 秒超时、单件 30 MB 上限（先看 `Content-Length`，下载后再查实际字节）、`Content-Type` 必须与用途匹配（视频 / 图片 / 音频）。
- 任何一项不满足都「跳过」而不是报错：片段退回 `fallback`，音轨直接略过，整条片子仍然渲得出来。
- 响应头 `X-Loomina-Remote-Skipped` 与 `X-Loomina-Placeholders` 如实计数，界面原样显示。

## 理由

- 白名单把 SSRF 面收窄到「运维显式信任的素材域名」；不是通用代理。
- 兜底图让单件下载失败不拖垮整条渲染。用户拿到的是「能看、但有几段是占位」的片子，比 500 更有用。
- 超时与大小上限防止一条慢链接占住 240 秒渲染窗口。
- 与 H3 不冲突：以后接了对象存储，把存储域名加进白名单即可，清单格式不用改。

## 后果

**正面**

- 供应商远端视频可以直接进成片；本地已验证白名单内视频 + 音频下载并编码成功。
- 不在白名单、类型不符、超大文件都按同一路径降级，行为可预期。
- 计数通过响应头回传，界面不需要猜。

**负面**

- 供应商链接过期或需要鉴权时仍会跳过；当前不支持自定义请求头与签名 URL 之外的鉴权。
- 白名单是部署配置，本地开发要手动设 `RENDER_ALLOWED_HOSTS`；没设时行为与 E6 相同（全部跳过）。
- 下载发生在渲染请求内，最长会多等 20 秒；并发仍由 H2 收口。
- 远端素材不会留在本地，下一次导出要重新下载。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 任意 URL 直接下载 | SSRF：能打内网、读云元数据；渲染路由不该有这个能力 |
| 只信任清单里的 `fallback`，不下载 | 就是 E6 的现状，真实视频永远进不了成片 |
| 先接 H3 转存 | 用户已明确暂缓；且转存解决的是持久化，不是「这次导出能不能用」 |
| 下载失败整条报错 | 一段坏链接会让 60 秒的片子完全导不出，体验更差 |
| 用 `Content-Disposition` 文件名决定类型 | 远端可控，不可信；类型只看 `Content-Type` 与实际用途是否匹配 |
