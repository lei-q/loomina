# ADR-0230：模板可改名与加说明，存之前先查重（F3 第二档）

- 状态：已采纳
- 日期：2026-11-14
- 决策者：用户 + Claude
- 关联：F3、ADR-0180、ADR-0207

## 背景

模板从 ADR-0180（班底）与 ADR-0207（镜头）落地后只能「存、用、删」。I7 的未做项里
一直写着「模板改名与参数编辑（只能删了重存）」。

「删了重存」看着只是麻烦，实际有代价：重存会换 `id`、把 `createdAt` 重置成今天、
把 `from`（这份模板从哪个项目来的）改成当前项目。也就是说**改一个错字会丢掉这份
模板的来历**。另外作者常常忘了存过，列表里出现两份一模一样的班底。

## 决定

1. **新建 `apps/web/lib/template-edit.ts`**，纯函数：
   - `renameProjectTemplate` / `renameShotTemplate`：只动 `name`，`id` / `createdAt` /
     `from` 原样保留；
   - `withProjectTemplateNote` / `withShotTemplateNote`：写说明，空串等于删掉字段；
   - `templateNameProblem` / `templateNoteProblem`：名字不能空、最多 40 字；
     说明可空、最多 200 字。
2. **两个模板类型加可选 `note`**：说明是「这套班底 / 拍法适合什么」，不参与去重比较。
3. **保存前查重**：`findSameProjectTemplate` / `findSameShotTemplate` 在已有列表里找
   同一套参数；找到就不存，并告诉作者「已经存过了：『X』」。
4. **「同一套」的定义**：结构比较，忽略 `id` / `name` / `note` / `createdAt` / `from`
   ——那些是「这份模板是谁」，不是「这套参数是什么」。班底比人物 / 地点 / 道具 /
   资产 / 风格 / 调色 / 画幅 / 品牌；镜头比景别 / 机位 / 运镜 / 焦段 / 光影 / 构图。
5. **设置页行内编辑**：每份模板一个「改」，展开后是名字 + 说明两个输入，存 / 算了。
6. **顺手补登记**：`shot-template.ts` 从 ADR-0207 起一直没进 `modules.yaml`
   （落在 `web.root` 不受约束），这次连同新文件一起归到 `web.state`。

## 理由

- **改名不该重置来历**：`from` 与 `createdAt` 是这份模板的历史记录，
  只改一个显示名却把它们抹掉，等于用编辑功能做了删除 + 重存。
- **去重是结构比较而不是名字比较**：作者往往会给同一套东西换个名字再存一次；
  按名字判重会漏，按参数判重才对得上「同一套」这个说法。
- **不自动删重复项**：发现重复只提示，让作者自己决定留哪份——名字与说明可能不同，
  工具不该替他选。
- **说明字段不参与去重**：两份同参数、说明不同的模板，是同一套参数的两个备注，
  存一份就够；说明随时可以改。

## 后果

**正面**

- 改名 / 加说明不再丢 `createdAt` 与「从哪来」。
- 重复保存被拦住，列表不会因为「忘了存过」而变长。
- `shot-template.ts` 终于进了地图，模块边界开始管到它。

**负面 / 代价**

- **没有「参数编辑」**：班底模板里换一个角色、镜头模板里改焦段，仍然要重新存一份。
  那需要一套「编辑模板内容」的界面，是另一个量级。
- 去重按 JSON 全等比较：同一套参数但在数组顺序上不同（比如人物顺序换了）会被判为不同。
- **实测踩到一个 React 批处理坑**：两个输入框在同一次任务里 `onChange`，
  用 `{...editing, 字段}` 的写法会让后一个更新用到过期状态、把前一个覆盖掉；
  改成函数式 `setEditing(prev => ...)` 才对。
- 模板导入与跨机器同步仍未做。
