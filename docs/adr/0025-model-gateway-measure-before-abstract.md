# ADR-0025 真实模型接入：先测绘，再抽象

- 状态：已接受
- 日期：2026-11-09
- 决策者：项目负责人 + AI 助手
- 关联：P8、P21、H12、H13、F8

## 背景

S0 用假适配器证明了链路和契约能跑通。接真实模型时，供应商是第三方中转站（`api.jtreecloud.com`），只公布了 `GET /v1/models` 的规范，图片和视频接口没有文档，错误信息是唯一的契约来源。

同时 `docs/COST.md` 里的单价是行业假设值，没有实测依据。没有真实单价和首次通过率，成本模型就是纸上功夫。

## 决策

1. **把「能力测绘」当成第一个真实迭代（S1），而不是先做完整抽象层。**
   先用 8–20 个典型镜头跑一遍，产出三件事：真实单价、首次通过率、失败维度分布。报告落到 `artifacts/s1/`，结论回写 `docs/MODEL-GATEWAY.md` 与 `docs/COST.md`。
2. **适配器内部吃掉协议怪异，业务代码只看到 `ImageAdapter` / `VideoAdapter`。**
   图生视频用 `content[].image_url.url`、任务式轮询、两种错误体、429 退避、超时——全部收在 `packages/gateway/src/treecloud.ts`，不往上漏。
3. **只把「能换算成每秒 / 每张」的模型放进价目表。**
   按 token 计价且无公开公式的模型（seedance 系列）不进入估算路径。拿不到价就返回 `undefined`，让调用方显式处理「不知道多少钱」，而不是猜一个数。
4. **探针自带预算护栏。** 预估超预算直接中止；实际花费超预算立即停止。`P21` 要求成本是设计参数，不是事后账单。
5. **密钥只存在于进程内存。** env 文件只做纯文本解析（不 source、不 eval），错误信息过滤密钥，报告不写密钥。

## 理由

- 在不知道真实通过率之前做重试策略、双档渲染、点数定价，全是拍脑袋。先测，再设计。
- 中转站协议随时可能变。抽象层如果按「我们想象的协议」设计，第一次真实调用就会返工；按「实测协议 + 明确的未知清单」设计，才是可演进的。
- 单价低于假设（¥2.12 vs 假设 ¥3.9 每镜头），说明**成本瓶颈在重做次数，不在单价**。这会改变产品策略：优化重点从「选便宜模型」转向「提高首次通过率」。

## 后果

正面：
- 成本模型有了实测锚点，`COST.md` 的假设可以被证伪。
- 失败维度分布直接指向该改提示词、改镜头设计，还是改模型。
- 换供应商只改一个文件。

负面：
- 真实契约靠试探得来，样本少；视频成功返回体的字段名尚未确认，适配器做了多字段兜底。
- 探针会真实花钱（8 镜头约 ¥19），且失败请求也可能占用预授权额度。
- 测绘期间配额告罄（429），测绘被迫中断，S1 进度取决于账号额度。

跟进：
- 拿到一个成功的视频任务后，把 `videoUriOf` 的兜底收敛成单一路径。
- 补齐 `MODEL-GATEWAY.md` 第六节的未知项。
- 用实测数据重算 `COST.md` 的基线场景。

## 替代方案

- **先等官方文档 / 换有文档的供应商**：会阻塞 S1，且不解决「单价与通过率未实测」这个根本问题。
- **直接按 OpenAI 标准协议写适配器**：视频接口不是 OpenAI 协议，必然返工。
- **把价格硬编码进业务层**：供应商调价就全错，且违反 P8。
