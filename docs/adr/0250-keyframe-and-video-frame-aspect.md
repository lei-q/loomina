# ADR-0250：关键帧按 9:16 出，视频首帧提交前对齐画幅

- 状态：已采纳
- 日期：2026-11-15
- 决策者：用户 + Claude
- 关联：B2、B3、E5、P4、ADR-0249

## 背景

ADR-0249 打通图生视频后发现一条连锁事实：**视频的输出比例跟随首帧**。
而关键帧一直是 1024×1536（2:3）出的，于是成片也是 2:3——
端到端实测：1024×1536 键帧 → 782×1174 成片，而平台要的是竖屏 9:16。

同时实测出图像模型的尺寸约束：`1080x1920` 被拒（`width and height must both be
divisible by 16`，1080 不行），`720x1280` 可以。

## 决策

1. **关键帧出图尺寸改为 720×1280**（`KEYFRAME_SIZE`，精确 9:16、宽高都能被 16 整除）。
   定妆三视图 / 场景主镜 / 道具参考**维持 1024×1536**：它们不是成片首帧，
   2:3 对参考图更宽松。
2. **视频提交前统一对齐首帧**（`fitVideoFrame`）：等比放大铺满 720×1280 →
   居中裁切 → 压到首帧体积上限（原始字节约 768 KB，base64 后不超 1 MB 的 part 限制）。
   这样旧项目里 2:3 的键帧也能出竖屏成片，不要求作者重出图。
3. **不把 1080×1920 当作出图尺寸**：供应商只收能被 16 整除的宽高；
   将来要更高分辨率，用 1088×1920 之类的合法尺寸，而不是硬写 1080。
4. 没有 ffmpeg 时**原样发**（退回原来的比例），不假装对齐过。

## 验证

- ffmpeg 滤镜实测：1024×1536 的键帧 → 720×1280 / 57 KB。
- 供应商实测：720×1280 首帧 + `size=720x1280` → 成片 **720×1280**。
- 单测：`reference-fit` 新增两条（9:16 且能被 16 整除；1080 不能被 16 整除）。

## 后果

**正面**

- 竖屏短剧的成片比例从源头对齐，不靠导出时再裁。
- 旧项目的 2:3 键帧不用重出，提交时自动对齐。

**负面 / 跟进**

- 对齐用**居中裁切**：2:3 → 9:16 会切掉左右约 16% 的画面，边角内容可能丢。
  键帧已经按 9:16 出时这一步近似无操作。
- 16:9 / 1:1 项目仍按 9:16 出视频（`Look.aspect` 还没接进视频请求），
  多比例适配依旧由 E5 在导出时处理。
- 1080p 视频的 1080×1920 尺寸与首帧的 720×1280 不是同一分辨率；
  供应商按首帧比例出片，分辨率以实际回执为准。

## 替代方案

1. **把出图尺寸直接写成 1080×1920**：供应商 400，不可用。
2. **依赖请求里的 `size` 强制比例**：实测不生效——首帧是 2:3 时给
   `size=720x1280` 仍然出 782×1174，比例跟着图走。
3. **不裁切、只压缩**：体积问题解决，但比例还是错的。
