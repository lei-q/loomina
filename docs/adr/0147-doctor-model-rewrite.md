# ADR-0147 剧本医生第二档：模型改写与「采用」

- 状态：已接受
- 日期：2026-11-12
- 决策人：用户 + Claude
- 关联：ADR-0123（剧本医生设计）、ADR-0141（模型兜底）、A18、A2

## 背景

ADR-0123 把剧本医生分了两档。第一档是本地报告：12 维里 10 维按词法与结构可算，六种改写模式只给方向，不改字。第二档原计划 `POST /api/doctor` 让模型一次一个模式返回建议，作者点「采用」才落事件。

第一档落地之后，缺口很具体：报告告诉你「钩子偏弱」，但作者还是得自己想怎么改；短剧对白又短又密，一句一句重写最费时间。文本模型已经在网关里（H19 用上了），这条路可以接。

## 决策

1. **一个模式一次调用，作者先点。** 六种模式是按钮；不会自动调用、不会在打开抽屉时预跑。模型只回答「按这个模式怎么改」，不做全面评审。
2. **快照只带创作内容。** `doctorSnapshotOf` 把标题、故事层五个文本字段、场 / 镜 / 动作 / 台词、以及本地报告里与这个模式相关的提示压成 JSON；动作截到 400 字、台词 160 字，不含素材地址、资产与密钥。模型看到的是剧本，不是项目文件。
3. **回复过严格 schema。** 最多 3 条，每条只能是：
   - `dialogue`：`lineId` + 新台词（≤120 字）
   - `shot`：`shotId` + 新动作描述（≤160 字）
   - `story`：`logline | synopsis | genre | audience | tone` + 新文本（≤400 字）

   多出来的键、未知字段、空数组都按「没读懂」处理（422，不写事件）。
4. **未知 id 逐条丢掉，不整条拒绝。** 模型偶尔编一个 `d-99`；采用本来就要作者点，丢掉引用不存在的条目比让一次调用白花更合理。丢完一条不剩才算没读出。
5. **采用走既有写入口。** 台词 → `editDialogue`（按字数重估镜头时长）、动作 → `editAction`（锁镜拒绝）、故事层 → `editStory`。不新造一条「模型改写」事件：采用的结果就是一次普通编辑，日志与撤销都按普通编辑理解。
6. **一条建议一条事件。** 没有「整批采用」：三条建议可能互相矛盾，作者该逐条看。
7. **结构只建议、不执行。** 减人物 / 减场景模式只允许改写台词与动作（比如把两个人合并成一个人说），不允许模型删角色、删场次、删镜头；结构是作者的决定（与 ADR-0123 一致）。
8. **建议不进 IR。** 关掉抽屉就没了；同一模式再点一次会重新调模型。存下来要配失效机制，且没有跨会话引用价值。

## 理由

- **模型只在明确请求时出手**：与 H19 同一原则（ADR-0039 / ADR-0141），确定性优先，模型是可选工具。
- **snapshot 而不是整份项目**：项目里有资产地址、时间线、审批记录，模型不需要；发得越少，越不可能把无关信息写进改写。
- **字数上限是产品约束**：120 字的台词在 9:16 竖屏里已经接近两行；400 字的梗概再长就不是短剧了。
- **走既有入口比新写入口可靠**：锁镜、时长重算、空文本拒绝都是已经存在且被测过的规则；再写一份「采用」逻辑等于把规则复制一遍。
- **丢掉未知 id 不丢整条**：模型编 id 是常见失败模式；只要能用的条目还在，作者就能用。

## 后果

**正面**

- 「钩子偏弱」从一句诊断变成一个可以直接替换的改写。
- 采用之后与手动改一模一样：事件、撤销、时间线、字幕、后续提示词全部跟着走。
- 一次调用有明确的成本上限（3 条、固定字数），不会因为模型话多而失控。

**负面 / 代价**

- 模型可能给出「正确但平庸」的改写；报告不评价好坏，采用与否仍是审美判断。
- 一次只能改三条；想大改要多次调用，每次重新发快照。
- 快照是调用时的状态：模型读的时候作者又改了剧本，采用的就是旧上下文——建议卡片上不锁定原文，作者得自己看一眼。
- 改写没有「撤回这一条建议」，只有采用之后用撤销 / 版本回退。

**边界**

- 没有多轮对话（「再狠一点」）——再点一次同一个模式，是重新要一版，不是接着聊。
- 不能整批采用、不能比较两个模式的建议。
- 不能改人物弧光、关系张力、场景头、镜头时长（那些有各自的编辑入口）。
- 模型不可选：用设置页里的默认文本模型。

## 验证

- `doctor-ai.test.ts` 9 条：快照包含全部镜与台词、超长截断、提示词写清模式与上限、合法回复拆型、未知 id 丢弃、空结果 / 字段越界 / 超长 / 围栏 JSON 的处理。
- `workbench-store.test.ts` 5 条：台词 / 动作 / 故事三种采用各写对应事件、原文不变返回 false、只读拒绝。
- 全仓 1247 条测试全过（IR 214 / gateway 28 / pipeline 98 / web 907）；`tsc --noEmit` 与 `next build` 干净。
- 浏览器（真模型）：打开「医生」→ 点「强化钩子」→ 模型返回 3 条建议（两条台词、一条故事梗概）→ 点第一条「采用」→ 日志 40 → 41，新增一条 `story.updated { logline }`，卡片变「已采用」并提示「已按这条改写写进剧本」。
