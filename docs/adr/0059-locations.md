# ADR-0059 新建 / 编辑地点：先有地点，场次才挂得上去

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0011（事件日志）、ADR-0028（定妆台）、ADR-0056（场次地点）、ADR-0058（场头历史）、FEATURES A21 / B8

## 背景

ADR-0056 让场头能改地点，ADR-0058 让场头改动可回退；但地点本身一直只有示例项目里的三条，用户没法加新的。剧本页的地点下拉写死为「已有地点」，想去一个还没建的地方，就只能先假装在那里拍。ADR-0058 的跟进里写着这一条。

`Location` 在 IR 里只有 `{ id, name, templateId?, referenceImages, masterShotId? }`，没有任何事件能新增或改名。

## 决策

1. **两个新事件**（`packages/ir/src/events.ts`）：
   - `location.added { at, location }`——整条地点进日志；重名与否由调用方判断，IR 只拦空名字与重复 id。
   - `location.updated { at, locationId, patch: Partial<Pick<Location, "name" | "templateId">> }`——只收名字与模板。主镜走 `asset.updated`（ADR-0032），参考图同理，不在这条事件里。
2. **`applyEvent` 校验**：没有 `project.created` 拒绝；空名字拒绝（「地点总得有个名字」）；重复 id、指向不存在的地点、空 patch 都拒绝，与 `scene.updated` 同一套口径。
3. **store 两个动作**（`workbench-store.ts`）：
   - `addLocation(name, templateId?)`：只读直接拒；名字 trim 后为空或与已有地点重名时写 `castError` 并返回 `undefined`；id 用 `loc-<base36 时间戳>`，撞了补 `x`；写一条 `location.added`，返回新 id。
   - `editLocation(locationId, patch)`：只读直接拒；名字 trim / 非空 / 不与他人重名；只把真正变了的字段放进 patch，一项都没变就写「地点没改。」并返回 `false`；成功写一条 `location.updated`。
4. **定妆页 UI**（`cast-screen.tsx`）：
   - `场景 · 主镜` 标题右侧一个`新建地点`，点开一条虚线框内联表单：名字输入 + 模板下拉（走廊 / 门口 / 桌边 / 门厅）+ `创建` / `取消`，Esc 收起；下面一行小字说清下一步（「建好后到剧本页把它挂到场上」）。
   - 每一行地点名旁一个`改名`（只读标签页不显示）：点开把名字变成输入框 + 模板下拉 + `保存` / `取消`，Esc 收起。
   - 还没挂场次的地点：状态词写`未挂场次`、副标题写`主镜 · 还没挂场次`，不冒充必锁项。场次一挂上，它立刻变成`缺 主镜`并计入应锁数。
5. **读模型**：`CastLocationView` 多带一个 `templateId`，改名表单据此回填模板；`art` 仍按模板映射剪影。
6. **`EVENT_TYPES`**（`apps/web/lib/event-log.ts`）同时补上两个新类型——漏一项，整份日志会在读回时判废（ADR-0034 的教训）。

## 理由

- **地点是结构，不是镜头属性**：先有地点，场次才指向它；把新增塞进 `scene.updated` 会让「加地点」只能借某一场发生。
- **只收名字与模板**：模板只决定还没出图时的剪影，不参与生成；主镜与参考图已经有资产那条路，事件里再放一次会两处打架。
- **重名挡在 store 而不是 IR**：IR 回放时不该知道「用户眼前有几条地点」这种界面语义；但空名字是数据本身不成立，IR 必须拦。
- **模板下拉用业务词**（走廊 / 门口 / 桌边 / 门厅）而不是 `corridor` / `doorway`，与定妆台已有的三个示例地点对齐。
- **只读标签页不显示入口**：不是生成完再拒，而是根本不递出这个按钮——与锁定资产的处理一致。

## 后果

**正面**
- 定妆页 `新建地点` → 输入`阳台`、选`走廊` → 一条 `location.added`，页面多一行 `阳台 · 未挂场次 · 主镜 · 还没挂场次`，主镜待生成。
- 行内`改名`改成`阳台外沿`、模板换`门口` → 一条 `location.updated { name, templateId }`；再点`保存`不改任何东西时写「地点没改。」且不写事件。
- 剧本页场头下拉立刻多出`阳台外沿`（顺序按 `project.locations`，新地点在末尾）；选中后写一条 `scene.updated { locationId }`，场头历史多一版。
- 场次挂上之后回到定妆页：应锁数从 7 变 8，`阳台外沿`的状态词从`未挂场次`变`缺 主镜`——地点是不是必锁，跟着场次走，不靠人手勾。
- 测试：IR 67 条（新增 3 条：新增 + 回放、改名 / 换模板、五类拒绝）；web 149 条（新增 4 条：新增 + 回放、空名 / 重名 / 只读、改名 + 换模板、没变 / 重名 / 陌生 id / 只读）；合计 254。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：定妆页新建`阳台`（模板`走廊`）→ 改名`阳台外沿`（模板`门口`）→ 剧本页第 1 场场头下拉出现`阳台外沿` → 选中后写第 43 条事件 `scene.updated { locationId: "loc-mwarc3i6" }`；IndexedDB 日志 43 条，读回正常。

**负面**
- **没有「删地点」**：加错了只能改名或不用它；已有场次指向它时删掉要处理悬挂引用，这一版不做。
- **重名按完全一致判断**：`阳台` 与 `阳台 ` 会被 trim 后挡住，但`阳台外沿`与`阳台 外沿`是两个名字——不做归并。
- **模板与名字的关系不校验**：可以把「门口」叫成「桌边」；名字是给人看的，模板只管剪影。
- **改名会改历史里的称呼**：场头历史显示的是地点**现在**的名字（ADR-0058 已知负面），所以改名之后旧版本也会跟着改口。
- **id 用时间戳**：同一毫秒内连加两个地点靠后缀 `x` 避重，可读性差；真要引用的地方都只存 id，不靠人读。
- **不改 `masterShotId`**：新建地点没有主镜；主镜要靠定妆页的`生成主镜`补，生成链路未通时那一格一直显示`待生成`。

**跟进**
- 删地点（含悬挂引用处理）。
- 地点参考图（`referenceImages` 目前没有任何写入路径）。
- 场号与场序调整（ADR-0058 的跟进，仍未做）。
- 模板从「写死的四个」变成可扩展的模板库（与 B8 场景 / 道具参考库一起）。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 只允许在剧本页新建地点（借场头下拉加一项「新建…」） | 定妆页才是管地点资产的地方；剧本页该专心写戏 |
| 新地点自动建一个空场次 | 场次是戏的结构，不该由建地点顺带生成 |
| 把全部地点放进 `project.updated` 一起写 | 每次改名都要重写整张表，日志里看不出「改的是哪一个」 |
| 地点改名走 `asset.updated` 之类的既有事件 | 地点不是资产；事件类型与领域对象一一对应，别为了省一条分支混用 |
| 名字允许重复，靠模板区分 | 剧本页下拉里两条`门口`无法选择，人也说不清「哪一版门口」 |
| 模板让用户自由输入 | 剪影只有三张图，自由输入等于给一个画不出来的承诺 |
