# ADR-0029 生成链路接资产锚点：参考图从三视图与主镜来

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0014（多层一致性）、ADR-0028（资产层与定妆闸门）、B2、B3、[CONSISTENCY.md](../CONSISTENCY.md)

## 背景

ADR-0028 把资产层建起来了，但生成链路还在按旧方式工作：

```ts
// packages/pipeline/src/index.ts（改之前）
referenceAssetIds: shot.characterIds,   // 把"人"当"图"
```

三个问题：

1. **参考图是人物 id，不是图片 id。** 适配器拿到的 `c-lin` 不是任何一张能看的图。
2. **提示词没有人物锚点。** `buildShotPrompt` 只写镜头描述与机位，`mustNotChange`（痣、疤、发型）根本没进提示词。
3. **锚点缺了没人管。** 三视图没齐、场景没主镜，链路照样生成——生成的每一帧都在赌。

## 决策

1. **新增纯函数 `shotAnchors(project, shot)`**（`packages/ir/src/anchors.ts`），由资产层装配这一镜的参考图，不落库、不缓存。
2. **选格按景别与人数**：
   - 单人镜头取正面 + 3/4（两张脸的角度最有用）；
   - 多人同框每人只取正面，把名额留给场景；
   - 场景主镜始终占一个名额；
   - 总数上限 **4 张**，超了先丢人物、不丢空间（CONSISTENCY.md：参考图 2–4 张，过多互相干扰）。
3. **锁定优先**：目标有已通过的 `Approval` 时，只用 `lockedAssetIds` 里的资产；锁定之后新增的图不算数，并按缺失上报。
4. **缺锚点拒绝生成**：`shotAnchors.missing` 非空时，`runShot` 抛 `AnchorError`，在任何模型调用之前；`runMinimalChain` 整条链路直接失败。
5. **提示词编译固定人物串**：`buildShotPrompt(project, shot)` 带上人物名、`appearance`、`mustNotChange` 与场景名，措辞固定，不因镜头改写（CONSISTENCY.md 第三层）。
6. **`runShot` 改签名**：`runShot(project, shot, options)`。镜头离开项目没有意义，锚点、提示词、场景都需要项目上下文。S1 探针同步补了占位三视图。
7. **适配器契约携带参考图，但请求体不擅自加字段**。`ImageInput.referenceAssetIds` 进契约与 provenance；当前中转站图片接口只接受 `model / prompt / size / n`，参考图还没有验证过任何可用字段——不猜。

## 理由

- **"人 → 图"这一步必须显式发生在装配里。** 把它留在 `runShot` 一行 `characterIds` 里，三视图就永远只是文档里的概念。
- **上限 4 张是经验约束，不是拍脑袋。** 参考图越多，模型越容易被互相冲突的细节拉扯；2–4 张是 CONSISTENCY.md 已写的口径，代码要跟文档一致。
- **场景保留名额**：同一场所有镜头共享同一张主镜，这是空间一致性的根；两张脸挤掉它，反而让每个镜头重新想象房间。
- **缺锚点就失败，比生成一张"另一个人"便宜。** 一次视频生成的钱够补好几张三视图；错帧还会污染审片判断。
- **提示词固定串**：身份漂移一半来自每次换措辞。名字、外貌、不许变的特征原样带上，至少让模型每次听到同一句话。

## 后果

**正面**
- 链路里不再出现"拿人当参考图"；`anchorAssetIds` 随 `ShotRunResult` 返回，可核对。
- 缺锚点的情况下，模型一次都不会被调用（有测试）。
- 审片台当前画面下方直接显示这一镜带进生成的锚点（`林 · 正面 / 林 · 3/4 / 走廊 · 主镜`），生成依据变成可见的。
- 示例项目与 S1 探针都补了占位资产，同一套规则能跑通。

**负面**
- 图片接口不通，锚点目前只影响提示词与溯源，**还影响不到像素**；真正把参考图送进生成要等一个能收图的接口。
- 上限 4 张、单人 2 张、多人 1 张是启发式，没有在真实样片上标定；接入后要按通过率调。
- `AnchorError` 会让整条链路停下，没有"跳过这一镜继续"的选项；批处理需要时再加。
- 锁定后新增的图按缺失处理，用户会看到"缺背面"但其实图在——这是刻意的：锁定是一份快照，改快照要先解锁。

**跟进**
- 找到可用的图片编辑 / 主体参考接口后，把 `referenceAssetIds` 映射进去，并记录适配器对张数、尺寸、格式的限制。
- 锚点选择参数（每角色几张、上限）移到模型能力矩阵，按模型标定。
- 审片台接分维度 QA：身份相似度对比的就是这些锚点。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 继续用 `characterIds` 当参考图 | 传过去的是人不是图，下游无法使用 |
| 四格全带上，不设上限 | 参考图互相干扰，且多数镜头用不到背面 |
| 缺锚点时生成并打警告 | 用户看到的是一张错的图，警告没人读；错帧成本高于补图 |
| 把参考图 id 直接塞进没验证过的请求字段 | 中转站契约靠实测，不靠猜；422/静默忽略都更糟 |
| 锚点结果写回 IR | 它能从项目推出，落库会带来同步问题；需要时再加记忆化 |
