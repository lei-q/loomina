# ADR-0132：生成结果的人工复核进 IR

- 日期：2026-11-12
- 状态：已采纳
- 关联：H6、G8、H7、ADR-0095、ADR-0105、ADR-0131

## 背景

H6 一直标着「部分落地（提示词层）」。ADR-0105 把**发出去之前的那句话**扫干净了，但它明确写了边界：

> 这不是像素级审核。画面出来之后的脸、手、构图与真实内容仍需人工看；模型审核服务（H6 剩余部分）与审核结果落库仍未做。

剩下的两件事现在要回答：

1. **像素与视频谁来审**？供应商没有审核接口，网关也没有能调的多模态审核模型（`docs/MODEL-GATEWAY.md` 的「还没搞清楚的」一节里，连内容审核拒绝的错误码集合都还没测绘）。
2. **审过的结论存在哪**？现在「这张图我看过了」只活在作者的记忆里，换台设备就没了。

## 决策

### 1. 不做模型审核，做人工复核

不引第三方审核服务、不假装网关有审核能力。像素这一层的判断由作者做，系统负责的是：

- 把**会进成片的每一条生成结果**摆到一处，不用翻九个页面找；
- 让「看过 / 不能用 / 还没看」三种状态可写、可回放；
- 让「不能用」真的拦住导出。

写清这条边界不是谦虚：模型审核能做的是**兜底**，不是**替代**。单人项目里，作者本来就是终审。

### 2. 只审会进成片的东西

`reviewSubjectsOf(project)` 只列三类：

| 来源 | 为什么算 |
| --- | --- |
| 画面轨上的 take | 直接进成片 |
| 首尾帧 | 没有视频的镜头会拿它当画面 |
| 台词配音 | 混进成片音轨 |

定妆三视图、参考图、场景主镜**不审**：它们影响的是下一次生成，不是这一次发布。把它们塞进来只会让清单变长、让人麻木。

### 3. 三种状态，语义各不相同

```ts
interface AssetReview {
  status: "passed" | "rejected";
  at: string;
  note?: string;   // 标「不可用」时写原因
}
```

- **没有记录** = 还没看。进「待确认」，导出前要在预检里勾一下。
- **`passed`** = 看过，没问题。
- **`rejected`** = 不能用，**硬阻断**导出。`note` 说清为什么（「多了一只手」），下次看到能想起来。

「还没看」不硬拦是有意的：示例项目与刚生成的结果一上来全是没看，硬拦会让「导出」按钮在第一天就点不动。但它进「待确认」，所以也不会静默放行。

### 4. 单独一条事件，不复用 `asset.updated`

```ts
{ type: "asset.reviewed"; at; assetId; status: "passed" | "rejected" | null; note? }
```

`asset.updated` 是**合并**语义（`{ ...item, ...event.asset }`）。`undefined` 过 JSON 会消失，所以「收回复核」在合并语义下根本删不掉字段——资产会永远停在上一次的复核状态。第一版就是这么写的，store 测试当场抓到。

`null` 在这里明确表示「回到还没看」，handler 里解构掉整个 `review` 字段。

### 5. 缺资产的条目单独算一类

`reviewSubjectsOf` 会列出引用了**不存在资产**的条目（`exists: false`）。它们：

- 不算「没看」（看不了），也不算「看过」；
- 界面上按钮禁用、写明「资产不存在」；
- 进「待确认」：成片里那一格会是空的，得有人认下来。

第一版把它们算进 `missing` 但既不拦也不提醒，摘要还写「11 个生成结果都复核过了」——一条都没看却说全看过，是这次实现里最该被记住的错。

### 6. 预检多一项 `review`，五项检查

`preflightProject` 的 `checks` 从四项变五项：`ai-label` / `safety` / `review` / `rights` / `spec`。

复核的结论进 `findings`，三种 `ruleId`：

- `review-rejected`（block）：被标不可用
- `review-pending`（review）：还没看
- `review-missing`（review）：资产不存在

所以它和别的合规项走同一套指纹与确认机制：改一条复核结论，指纹变，之前的「确认」自动失效。

## 为什么不做的部分

- **模型审核服务**：网关没有可用的多模态审核模型，测绘也没做过。等 `docs/MODEL-GATEWAY.md` 里「内容审核拒绝的具体错误码集合」补上之后再评估。
- **供应商侧审核结论落库**：视频失败时 `error.message` 可能是「内容审核不通过」，现在原样记进失败原因，没有结构化字段。等错误码测绘完再定。
- **审核结果导出到发布包**：发布包记的是作品数据，复核是过程记录。要给别人看的是「这条片子过了什么检查」，那是 `compliance` 的事。
- **申诉与人工复审流程**：单人项目里作者就是复审，没有第二个人。
- **按角色 / 按场批量复核**：当前清单最长 12 条，逐条看比批量勾选更不容易漏。

## 后果

- `Asset.review?: AssetReview` 进 IR。可选字段，`LOG_VERSION` 不用升。
- 新事件 `asset.reviewed`；`EVENT_TYPES` 必须加（2026-11-10 的教训）。
- 历史抽屉显示人话：「复核通过：视频 a-video-1」「标为不可用：图片 a-keyframe-s-03（多了一只手）」「收回复核：…」。
- 导出前检查面板多一栏「逐条复核」，**全部条目都列出**（不可用 → 没看 → 看不了 → 已看）。第一版把已看的藏起来，导致「已看」撤不掉——藏起来的东西没法再点。
- 示例项目的 10 条画面资产本来就不存在，所以第一次打开会看到 10 条「资产不存在」+ 1 条配音待复核。这不是 bug，是示例项目的真实状态被如实报出来了。
