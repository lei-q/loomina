# ADR-0107：台词进视频提示词与下游过期标记

- 状态：已采纳
- 日期：2026-11-11
- 关联：A5、A21、ADR-0044、ADR-0083、ADR-0106

## 背景

ADR-0044 落地台词改写时留下一条明确的负面：**改台词不会重算分镜提示词、字幕、配音**。之后版本、回退、增删、换人、排序、跨镜头移动都补上了，但"改完之后下游还对不对"始终没有答案：

- 视频提示词里**根本没有台词**。首帧定住画面后，供应商只拿到动作、表演与机位，口型没有依据；改了台词，下一次出片的提示词一个字都不变。
- 已出的 take 与已配的音轨留在项目里，界面照常显示"有声 / 有片"，用户看不出它们是不是按现在这句做的。

这一轮补的是**同步与标记**，不是自动重做：

1. 台词写进视频提示词——改台词，下一次出片的提示词就是新的；
2. 用已有的溯源判断哪些 take / 音轨还是旧的，在剧本、分镜、声音三处如实标出。

## 决策

### 1. 台词只进视频提示词

`ShotPromptMaterial` 新增可选 `dialogue: { speaker, text }[]`：

```ts
export function buildVideoPrompt(material: ShotPromptMaterial): string {
  const parts = shotParts(material);
  if (material.dialogue?.length) {
    parts.push(`台词（口型对齐）：${lines.map((l) => `${l.speaker}「${l.text}」`).join("；")}`);
  }
  parts.push("从首帧起势，动作连贯，镜头平稳，保持人物一致");
  parts.push(LOOK);
  return parts.join("。");
}
```

- `shotMaterial(project, shot)` 按 `shot.dialogueIds` 的顺序取台词，说话人翻成名字，不带 id；
- **首帧 / 尾帧 / 镜头提示词不加台词**：静帧不烧字幕，也不要求口型；`shotParts` 不读这个字段，只有 `buildVideoPrompt` 读；
- 台词因此自动进入 H6 的提示词审核范围：改出一句违规台词，下一次出片在提交前就会被硬阻断；
- `/api/video` 的入参 `parseShotMaterial` 收最多 8 句、说话人 40 字、文本 160 字；只收名字与文本，不收 id。

### 2. 过期判断只看已有的溯源，不猜

新增 `downstreamGap(project, shotId)`：

```ts
type DownstreamGap = { lines: number; takes: number; voices: number };
```

- **take**：`take.provenance.prompt` 里缺任何一句当前台词，就算"提示词没跟上"。没有提示词的导入片无从判断，不计入；
- **配音**：音轨资产的 `provenance.prompt !== line.text` 就算"念的是旧词"。没有 provenance.prompt 的旧音轨同样不冒充；
- 没有台词的镜头三项都是 0，不说"已同步"这种空话；
- 同一套判断进 `StageView`：`StageTake.stalePrompt`、`StageShot.staleTakes / staleVoices`、`VoiceLine.stale`。

**明确不做**：不改写 take / 音轨，不自动重跑，不删除旧物料；标记只回答"它是不是按现在这句做的"。

### 3. 三处界面提示

- **剧本页**：每镜技术行下面多一行 `下游还没跟上这段台词：1 条 take 的出片提示词里没有当前台词 · 1 句配音念的是旧台词。去分镜页重拍或去声音页重配就会用上新台词。` 没有未跟上的项就不显示；
- **分镜页**：take 签上多一枚 `旧词`，下方一句 `n 条 take 的出片提示词里没有当前台词，口型可能对不上；重拍才会用上新台词。`；"这一镜会送出的提示词"里视频那栏已经能看到 `台词（口型对齐）：…`；
- **声音页**：音轨是按旧台词念的那一行挂 `旧台词` 小签，悬停写"重配才会对上现在这句"。

三处都只提示，不拦操作：重拍、重配本来就是用户自己的决定。

## 后果

**好的一面**

- 改台词到下一次出片之间不再是断的：提示词、审核、口型依据都跟着新台词走；
- 旧的 take / 音轨有了诚实的标记，用户不用自己记哪句改过；
- 判断全部来自既有字段，不新增事件、不改 IR、不需要迁移。

**代价与风险**

- 旧 take 的提示词里没有台词，会被标成"旧词"——这是事实，但在完成一次重拍前会一直在；导入片没有提示词，不会标；
- 音轨只比对文本，换了音色但台词没变不会标过期；
- 台词长度受 160 字 / 句、8 句 / 镜限制，超出的部分不进提示词（与短剧单句 ≤ 15 字的约束一致，正常创作碰不到）；
- 提示词变长会略微增加视频请求的 token，但不改变计费口径。

## 验证

- 分镜页 SH-03：视频提示词出现 `台词（口型对齐）：林「知道了又怎样。」`，首帧提示词不含该句；take 1 的提示词是旧版，签上显示 `旧词`，下方写"1 条 take 的出片提示词里没有当前台词"。
- 剧本页 SH-01 把 `你早就知道，对吧。` 改成带「（改）」的版本，镜头时长 3.1s → 4.1s，台词版本记 1 次；该镜唯一的 take 没有提示词（导入/旧数据），因此不冒充旧词，计数为 0。
- 测试 667 全过（IR 137 + gateway 28 + pipeline 51 + web 451），`pnpm typecheck` 与 `next build` 全过。
