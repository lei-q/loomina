# ADR-0083 视频生成与多 Take

- 状态：已接受
- 日期：2026-11-11
- 决策人：用户 + Claude
- 关联：ADR-0011（只追加日志）、ADR-0029（锚点）、ADR-0037 / 0038（首尾帧）、ADR-0041（锁定）、ADR-0033 / 0035（价目）、FEATURES B3 / B5

## 背景

关键帧已经能出、能重生成、能标过期（ADR-0037 / 0038 / 0057），但「让它动起来」这一段一直没有接上：审片台的「重做」按钮从第一版起就是禁用的，鼠标悬停只写「生成还没接通」；关键帧页只有首帧 / 尾帧两个计数。网关里的 `TreecloudVideoAdapter`（提交、轮询、按需切 treecloud / litellm 路由）早就写好了，缺的是业务侧的一次完整接线。

另外三件事同时要定：

- **多 Take**：同一镜多拍几条、逐条留用 / 淘汰，是分镜审片的基本动作；数据模型里 `takeIds` 与 `take.added` 已经支持，界面只显示「当前用的是第几版」。
- **供应商不稳定**：视频接口的配额与路由此前反复没通（S1 探针），一次真实的键帧→视频链路未必能立刻跑通。
- **价目不全**：当前 `MODEL_NAME` 是 seedance 系列，按 token 计价，公开价目表里故意没有它（ADR-0033），所以「这一拍多少钱」大概率报不出来。

## 决策

1. **关键帧先行，视频只补运动**：`packages/pipeline` 新增 `buildVideoPrompt(material)`——与镜头提示词同源（动作、人物与「不许变」、场景、道具、机位），再补一句「从首帧起势，动作连贯，镜头平稳，保持人物一致」，**不带**「首帧画面 / 尾帧画面 / 无字幕」这些静帧指令。首帧已经定住画面，这里重复描述人物会被模型当成要重画一镜。
2. **一次路由等出片**：`POST /api/video` 收 `{ shot, firstFrame, durationMs }`，`runtime = "nodejs"`、`maxDuration = 300`；服务端提交任务后用 `TreecloudVideoAdapter.wait` 轮询（4 秒一次，最长 240 秒），成功才返回 `{ uri, model, prompt, durationMs, cny? }`。客户端一次请求拿一个地址，不需要自己存任务 id；失败如实回一句人话 + 供应商原因。
3. **事件照旧，两件套**：一拍视频落两条事件——
   - `asset.updated`：`kind: "video"`、`source: "generated"`、`uri`、`durationMs`、`costCny`（供应商给了就用，没给就缺省）、`provenance`（`referenceAssetIds` 记首帧资产）；
   - `take.added`：`status: "draft"`、`costCny`（同上）。
   **不覆盖旧资产**：每拍新占一个 `a-video-${shotId}-${n}`，第 n 拍对应 `take-${shotId}-${n}`。旧 Take 的地址、状态、钱都留在日志里，可回放。
4. **贴视频地址导入**（兜底）：`attachVideo(shotId, uri)` 收 `http(s)://` 或 `data:video/`（上限 12 MB），落 `asset.updated`（`source: "upload"`、`modelId: "import"`、`costCny` 缺省）+ `take.added`（`costCny: 0`）。配额不通、或手上已经有成片时，多 Take 的审片流程照样能走完。
5. **预算闸门按秒算**：`/api/price` 在原有出图字段旁加一层 `video: { model, resolution?, cnyPerSecond? }`（顶层字段不变，旧调用方不必改）。客户端用 `cnyPerSecond × 这一镜秒数` 报价并在提交前拦超预算；**报不出价就不拦**，与出图同一原则（ADR-0035）。
6. **锁定即只读**：锁定的镜头不生成视频、不收导入地址；要拍先解锁（ADR-0041）。
7. **界面**：
   - 审片台大画面多一档「视频」：有片时出现视频格，`<video controls playsInline loop poster={首帧}>`；多 Take 时下面有一排 `TAKE n` 签，点哪一拍看哪一拍；
   - `ReelBar` 的「重做」接上 `generateVideo`：有首帧才可点，报价按秒算；轨道条有片子的格子右下角标 `▶`；
   - 关键帧页每格多一个「出视频 / 重拍视频」按钮，页头多一个 `视频 n / 12` 计数，缩略图右上角标 `▶`。

## 理由

- **关键帧先行仍是底线**（P4）：首帧是画面一致性的锚，也是这一拍能被重看、被比较的封面；纯文生视频只在探针里用过。
- **同步等待放在服务端**：客户端不需要存任务 id、不需要轮询逻辑，也不会因为关页面把任务丢掉；代价是路由要活到出片，`maxDuration = 300` 是对供应商等待时间的预算。
- **多 Take 用追加而不是覆盖**：日志只追加（ADR-0011）；覆盖资产会让「上一拍花了多少钱、当时长什么样」消失，而审片恰恰要比较。代价是项目里的视频资产会越攒越多，清理留给后面的回收站 / 资产治理。
- **导入也是一条正常 take**：不给导入单开一条旁路，`take.added` 一视同仁，留用 / 淘汰 / 锁定闸门全都能用；`modelId: "import"` 让溯源一眼能分出哪一拍不是生成的。
- **价目表不补 seedance**：按 token 计价没有公开公式，硬写一个每秒价就是编造（P21）；界面上显示「价目未知」并让 `spendOf` 把它计入「无价目」，比假装知道更诚实。

## 后果

**正面**

- 关键帧 → 视频 → take 的链路在界面上闭合：可以出片、重拍、多拍对比、留用、淘汰、锁定。
- 供应商配额不通时，贴地址导入仍能把多 Take 流程跑通；贴进来的片子和生成的片子走同一套留用 / 淘汰。
- 每拍的模型、提示词、首帧引用与花费都进日志；`videoUri` / `hasVideo` 由读模型统一算，轨道条、关键帧页、审片台口径一致。
- 测试：IR 100、web 233（新增 7：读模型 1、store 6）、gateway 17、pipeline 23（新增 1：视频提示词），合计 373。`pnpm typecheck`、`pnpm test`、`pnpm build` 通过。

**负面**

- **同步等待**：一次出片最多占住一条路由 5 分钟；同时点多了会撞上路由并发，真实生产要靠任务队列（H2，未做）。
- **视频不落对象存储**：生成的 `uri` 由供应商给，导入的地址也可能是别人家的；链接失效就没有片子了（H3，未做）。
- **seedance 无价目**：真实花费只能看供应商回执；没有回执时 take 记 0，资产进「无价目」，预算闸门对这类模型不生效。
- **多 Take 只会越攒越多**：没有删除单拍、没有回收站；`decide` 只作用于最新一拍，早先的拍只能看、不能在这里改状态。
- **首帧必须是可访问地址**：data URI 直接塞给供应商，链路是否接受取决于上游；不接受时只能走导入兜底。
- **没有片长校验**：导入的片子多长就是多长，与这一镜 `durationMs` 不一致时不提示。

**跟进**

- 任务队列（H2）替代同步等待：提交即返回 take 占位，出片后补事件。
- 对象存储（H3）：生成/导入的视频统一转存，避免外链失效。
- 单拍删除 / 淘汰后回收站；按拍结算与对比（时长、花费、留用记录）。
- 出片进度回报（供应商一般只给排队 / 生成中两档）。
- 音轨：视频自带声或后续 TTS 合轨，等 N2 / N3。

## 附记（2026-11-11）：视频格常驻

落地验收时发现一处入口死角：视频格原本写成「有片子才出现」，而「贴视频地址导入」又只在视频格被选中时渲染——于是第一拍视频既生成不出来（配额不通时）也贴不进来，导入兜底形同虚设。改为缩略条最左的视频格**一直摆着**（没片子时虚线框、悬停写「出视频，或贴一条地址」），点进去就能出片、贴地址；大画面空态本来就写好了「这一镜还没有片子」。同时把出片失败的红字改成先给人话的结构：`「SH-03」没出片：<供应商原因（截断 240 字）>。可以先「贴视频地址导入」顶上，或稍后再试。`；视频播放时字幕上移 16%，让开原生控件。

## 替代方案
| 方案 | 未采用的原因 |
| --- | --- |
| 路由只提交、客户端轮询 | 客户端要存任务 id、处理刷新与关页；当前没有队列，同步等更简单 |
| 纯文生视频（不要求首帧） | 丢一致性锚点，且与「关键帧先行」的既有决策相反 |
| 新一拍覆盖同一资产 id | 旧拍的地址与花费消失，违背可比较、可回放的初衷 |
| 发明 `video.generated` 事件 | 读模型与校验都要特判；`asset.updated + take.added` 已经表达完整 |
| 把视频 base64 写进事件日志 | 日志会被几十 MB 的视频撑爆；只收地址，生成的交给供应商，导入的限 12 MB |
| 给 seedance 编一个每秒价 | 编出来的价会误拦预算、误报花费（P21） |
| 导入单独建一个「外部片段」列表 | 会绕开留用 / 淘汰 / 锁定，审片流程分叉 |
