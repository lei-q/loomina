# ADR-0067 删一场、删一镜：级联与事件顺序

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0045（删台词）、ADR-0061 / ADR-0062（删地点与先搬后删）、ADR-0064（新建场次与镜头）、ADR-0057（过期）、FEATURES A21

## 背景

ADR-0064 之后能新建场次与镜头，但建错了没有退路：剧本页只能改，删不掉。这比只能加不能删更糟——一场写废了，整条片子的镜号与时长都被它拖着。

删除比新建难在**引用**：一个镜头挂着台词、take、关键帧、时间线项；一场挂着镜头。项目里还有锚点、审批、资产等引用。删错一处，重放事件就会得到悬挂引用。

已有一条现成的先例：删地点时，若还有场次占着，**拒绝**，由界面先把场次整批搬走再删（ADR-0061 / ADR-0062）。删除的账要在日志里逐条看得见。

## 决策

1. **事件**：新增 `scene.removed { sceneId }` 与 `shot.removed { shotId }`，不新造"级联删除"事件。
2. **`shot.removed` 自己带走从属物**：这一镜的台词、take，以及引用这一镜（或它的 take）的时间线项，一并从项目里摘掉；镜头从所属场的 `shotIds` 里去掉，同场后面的镜头 `index` 往前补，保持连续。理由：台词、take、时间线项没有各自独立的界面，也没有"删 take""删时间线条目"的事件；为它们逐个造事件只会让日志变长而不增加信息。
3. **`scene.removed` 只删空场**：场的 `shotIds` 非空时拒绝（「还有 N 镜在这场」）。界面删一场时，按镜序写 N 条 `shot.removed`，最后一条 `scene.removed`，全部一次写进日志。回放到任一前缀都不会有镜头挂在不存在的场上，日志里也留下"这一场原来有几镜"。
4. **资产不删**：take 引用的资产、关键帧资产留在 `assets` 里（孤儿）。资产可能同时被别处引用（同一张图既是参考又是帧），没有引用计数就不做回收；存储清理另行处理。
5. **锁定挡住删除**：锁定的镜头不能删（「这一镜已锁定：先解锁再删。」）；一场里只要有锁定的镜头，整场不删（「这一场里的第 N 镜（SH-0N）已锁定：先解锁再删这一场。」）。与"锁定即冻结"一致（ADR-0041）。
6. **界面两步确认**：场头 `删` 变成 `确认删 N 镜` / `取消`，镜下 `删这一镜` 变成 `确认删` / `取消`；被拒的原因贴在那一场 / 那一镜下面（`pick` 色），不塞进别的编辑器。
7. **空项目不崩**：删光后分镜页写「还没有镜头。去「剧本」页加一场…」，剧本页写「还没有场次。下面加一场…」；两页都不再假设至少有一镜。
8. **选中挪位**：删掉分镜页当前这一镜时，选中挪到下一格；没有下一格退回上一格；删一场时同理落到下一个待定的镜头。

## 理由

- **从属物跟着走**：台词的 `dialogueIds`、take 的 `shotId`、时间线项的 `shotId` 都是"挂在这个镜头上"的关系，不是独立实体。镜头不存在，它们没有意义。
- **场只删空的**：镜头的删法已经有一个明确的事件（`shot.removed`）且会级联自己的从属物；场再单独级联镜头，等于两套级联规则并存，回放与调试都要多想一层。
- **顺序即正确**：先删镜头、再删场，任何前缀都合法；反过来先删场就必然出现悬挂引用。
- **资产不删**：引用计数是另一件事；现在删掉反而可能误删别处正在用的图。孤儿资产比悬挂引用安全。
- **锁定挡住**：删除是这一套操作里最不可逆的；锁定本来就是为了防手滑，不能只在改动作时生效。
- **两步确认而不弹窗**：与地点删除、台词删除同一套手感；确认按钮本身带上"确认删 N 镜"，不用另写一段话。

## 后果

**正面**
- 剧本页第 1 场（2 镜）点 `删` → `确认删 2 镜` → 确认后：场少一场、镜少两镜、页头数字与场号一起变；日志两条 `shot.removed` + 一条 `scene.removed`。
- 删一镜：这一镜的台词、take 与时间线项消失；同场后面的镜号往前补；分镜页镜数减一，选中落在下一镜。
- 锁定镜头上的 `删这一镜` 置灰；删含锁定镜头的场时场头下面出现红字说明，场与镜都不动。
- 删光所有场次：剧本页出现「还没有场次…」，分镜页出现「还没有镜头…」；再加一场一镜即恢复正常。
- 测试：IR 79（新增 3：删镜级联与回放、删场必须先空与回放、陌生 id 拒绝）、web 171（新增 3：删镜、删场、锁定 / 陌生 / 只读）；gateway 17、pipeline 22；合计 289。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：第 3 场（1 镜）两步确认后场数 6→5、镜数减一；SH-01 `删这一镜` 后 13→12；锁定的场被拒并显示「这一场里的第 2 镜（SH-02）已锁定」；全部删光后两页都显示空态且无报错。

**负面**
- **删一场写 N+1 条事件**：一场 12 镜就是 13 条；日志变长，但每一步都看得见。
- **不能撤销**：没有"撤销删除"或整组回退；误删只能重新加场加镜，台词要重写。
- **资产变成孤儿**：删掉的镜头与 take 对应的图仍占本地/对象存储，没有回收。
- **不能删单独一条 take 或一个时间线条目**：仍只能整镜删。
- **中间插入仍未做**：只能加在末尾；想插到中间要删了重加。
- **删场前要逐镜解锁**：一场里有一个锁定镜头就整场删不动，要先到分镜页解锁。

**跟进**
- 撤销删除（至少整组撤销最近一次 `scene.removed` / `shot.removed`）。
- 孤儿资产回收（按引用扫描，而非在删除事件里顺手删）。
- 空白项目引导：从故事 / 剧本重新开始。
- 指定位置插入场 / 镜。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| `scene.removed` 在 `applyEvent` 里级联删镜头 | 两套级联规则并存；日志里看不出删了哪些镜；回放时"先删场后删镜"的顺序约束也就白写了 |
| 新增 `take.removed` / `timeline.item.removed` 事件，逐条删 | 这些从属物没有界面、没有独立生命周期；为它们造事件只会让日志变长 |
| 有引用就拒绝（像删除地点） | 几乎每个镜头都有台词或 take，等于删不掉；删除地点拒绝是因为场次可以搬到别处，台词 / take 搬不到别处 |
| 软删除（标记 `deleted`，不真删） | 整个项目是 append-only 事件日志，软删除要在每个读模型里过滤；先做真删，撤销另开一条路 |
| 删除时顺手回收资产 | 资产可能被多处引用，没有引用计数就删会误伤；孤儿资产无害 |
| 允许删锁定镜头 | 锁定就是为了防手滑；删掉整镜比改一个字更该挡 |
