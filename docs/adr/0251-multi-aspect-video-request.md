# ADR-0251：16:9 / 1:1 接进视频请求

- 状态：已采纳
- 日期：2026-11-15
- 决策者：用户 + Claude
- 关联：B2、B3、E5、ADR-0249、ADR-0250

## 背景

ADR-0250 把键帧与视频首帧统一成 9:16，但项目本身支持三档画幅（E5 `Project.frame.aspect`：
9:16 / 16:9 / 1:1）。视频的输出比例跟随首帧，如果首帧永远是 9:16，
横屏与方形项目就只能靠导出时裁切。用户要求把 16:9 / 1:1 接进视频请求。

## 决策

1. **画幅来源是 `Project.frame.aspect`**（E5），不是 `Look.aspect`——
   后者只写进提示词，让模型按竖构图作画；画幅是产物规格。
2. **三档尺寸，短边固定 720、宽高都能被 16 整除**：
   9:16 → 720×1280、16:9 → 1280×720、1:1 → 720×720（`frameSizeOf`）。
3. **键帧按画幅出**：关键帧请求带 `aspect`，出图尺寸跟着换
   （定妆 / 场景 / 道具仍是 1024×1536，它们不是成片首帧）。
4. **首帧在提交前对齐画幅**：`fitVideoFrame` 按目标尺寸等比铺满 + 居中裁切，
   旧项目里 9:16 的键帧在横屏项目里也会被裁成 16:9。
5. **请求显式带 `size`**：网关 `VideoInput.size` 优先于按 `resolution` 推导的尺寸；
   `seconds` 仍是整秒字符串。

## 验证

- 供应商实测：`size=1280x720` + 1280×720 首帧 → 成片 **1280×720**（2 秒 / ¥1.20）。
- 9:16 仍为 720×1280（ADR-0250 已验）。
- 单测：`frameSizeOf` 三档（可被 16 整除）、网关「显式 size 覆盖推导尺寸」。
- 全仓测试：ir 260 / gateway 37 / pipeline 158 / web 1481；`pnpm -r typecheck` 通过。

## 后果

**正面**

- 三种画幅从键帧到成片一条链，不再依赖导出时裁切。
- 画幅只改 `Project.frame.aspect` 一处，键帧与视频同时跟上。

**负面 / 跟进**

- **对齐用居中裁切**：跨画幅切换（例如项目从 9:16 改成 16:9）会切掉边角，
  需要重出键帧才不损失构图。
- 1080p 输出没做：供应商只收短边 720 这一档的合法尺寸（`1080x1920` 被拒），
  要更高分辨率得换模型或等供应商放开。
- 视频提示词仍不拼技能（C18 的四种构建器不含 `buildVideoPrompt`）——是否要让技能
  作用于视频，是产品口径问题，另议。

## 替代方案

1. **用 `Look.aspect` 当画幅**：它只影响提示词，和成片规格会错位——否决。
2. **前端先裁好再上传**：与 `fitVideoFrame` 重复，且浏览器端没有 ffmpeg。
3. **只传 `ratio` 字段**：文档里 `ratio` 与 `size` 二选一，`size` 更精确——用 `size`。
