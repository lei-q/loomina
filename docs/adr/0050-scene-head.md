# ADR-0050 场头：内 / 外景与日夜进 IR，一条 scene.updated

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0043（剧本页）、ADR-0049（动作改写）、FEATURES A21

## 背景

剧本页的场头只有「第 n 场 · 地点」。可一页剧本最先要回答的是「屋里还是屋外、白天还是晚上」——光线、道具、提示词都从这里分叉。IR 的 `Scene` 之前只有 `id / index / locationId / shotIds`，这两个信息根本没有落点；A21 的负面清单里写着「内 / 外景与日夜未做」。

## 决策

1. **`Scene` 加两个带默认值的字段**：
   - `space: "int" | "ext"`，默认 `"int"`；
   - `timeOfDay: "day" | "night" | "dawn" | "dusk"`，默认 `"day"`。
   老日志按 schema 默认值补齐，**不升 `LOG_VERSION`**（与 ADR-0037 加 `keyframes` 同一先例）。
2. **新增事件 `scene.updated { sceneId, patch: Partial<Pick<Scene, "space" | "timeOfDay">> }`**：只允许改这两个字段；地点、场号是结构，不在这里改。`applyEvent` 校验场次存在、patch 非空。
3. **store `editScene(sceneId, patch)`**：只读标签页、陌生场次、无实际变化都拒绝；有变化才写一条事件，时间戳一次。
4. **界面**：场号后面一个 `内 · 夜` 小签（`外 · 夜` 等），点一下就地变成两个下拉（内外景 / 日夜），边改边生效；点编辑器外面收起。只读标签页置灰。
5. **导出跟着变**：`scriptToText` 的场头写成 `第 1 场 · 内 · 夜 · 走廊（10.9s · 3 镜）`。
6. **示例项目写明意图**：五个场都填 `space` / `timeOfDay`（门口那场是 `ext`），不靠默认值猜。

## 理由

- **场头是剧本的基本单位**：小说可以慢慢交代时间地点，剧本不行；内 / 外与日夜错了，后面的光线、声音、道具全错。
- **只开两个字段**：场的地点已经是 `locationId`，场号是 `index`；再开「气氛 / 服化道 / 时间线」会把这一个下拉变成一张表单，留给后面的场次编辑。
- **一个事件一个场**：改内 / 外景和改日夜都落 `scene.updated`，回放时场的形状只在一处变。
- **默认值而不是必填**：老日志没有这两个字段，必填会让整份日志判废；默认「内 · 日」是最常见、也最不奇怪的猜法。
- **点外面收起**：只靠 blur 不够——下拉没拿过焦点时，点外面不会触发 blur，面板会一直挂着；用 `pointerdown` 监听编辑器外面更可靠。

## 后果

**正面**
- 场头从 `内 · 日` 改成 `内 · 夜`：页面立刻更新，页头 5 场 / 12 镜 / 6 句台词 / 35.6s 不动，日志只多一条 `scene.updated { timeOfDay: "night" }`。
- 第 2 场从 `内` 改成 `外`：日志多一条 `scene.updated { space: "ext" }`；导出文本的场头同步变成 `第 2 场 · 外 · 夜 · 桌边`。
- 点编辑器外面收起，select 不会再挂在页面上。
- 测试：IR 63 条（新增 3 条：改写与回放、默认值、两种非法输入）；web 119 条（新增 4 条：白名单认得场头事件、读模型场头标签、导出场头、store 改写与边界）；合计 220。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：headless Chrome 逐场改到与示例意图一致（四场 `内 · 夜`、门口 `外 · 夜`），IndexedDB 日志逐条核对 `scene.updated`；导出 `.txt` 里五个场头都带内 / 外与日夜。

**负面**
- **老日志一律显示 `内 · 日`**：`project.created` 快照里没有这两个字段，schema 只能补默认值；示例项目「夜班」在已有日志里最初就显示成白天，得手动改（这次就是这么把演示数据调回夜的）。不做迁移——给真实项目猜「夜」比显示默认值更危险。
- **只有两个维度**：没有「傍晚 / 黎明」之外的时间词，也没有「内外过渡」（如门廊）。
- **场次本身仍不能编辑**：地点、场号、场顺序都不能改。
- **不联动镜头**：改了日夜，镜头的光线描述、提示词不会跟着变，也不会标记下游过期。
- **不联动示例的照明字段**：IR 里没有场景级照明，这一刀没碰。

**跟进**
- 场次地点 / 场号的编辑（`scene.updated` 扩字段或换事件）。
- 场头改动标记该场镜头的关键帧、提示词过期。
- 时间词扩展（黄昏 / 清晨的细分）与场级照明。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 把内 / 外景放进每个镜头 | 同一场里内外景通常一致，逐镜写会重复且容易打架；场是它的自然归属 |
| 必填字段 | 老日志没有值，必填会让 `parseEvents` 整份判废，等于把用户的项目清掉 |
| 复用 `shot.updated` | 场不是镜头，改场头要动全部镜头，事件语义也不对 |
| 一次改完两个字段才算一次 | 用户可能只想改日夜；逐字段提交更细，日志也读得懂 |
| 在外面点靠 blur 收起 | 下拉没拿过焦点时 blur 不触发，面板会一直挂着 |
| 升 `LOG_VERSION` 做迁移 | 没有可迁移的信息，迁移只能猜；默认值已经能安全回放 |
