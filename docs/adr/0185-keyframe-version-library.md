# ADR-0185：关键帧版本库——重生成不覆盖旧图（C2 第一档）

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：C2、C14、B1、B2、B5、ADR-0037、ADR-0038、ADR-0142、ADR-0144

## 背景

首尾帧从 ADR-0038 起就是「一帧一个资产位，重生成按 id 覆盖」。省事，
但每次重生成都把上一张付费出的图从项目里抹掉：IR 里那一格的 `uri` 换成新的，
旧的图只剩在事件日志的 `asset.updated` 里，界面上看不到、也选不回来。
本机资产库按引用清孤儿时，旧图还会被判成没人用。

用户的要求（C.2）很直接：生成过的关键帧是花了钱的资产，淘汰或被覆盖也不要删，
进版本库，之后能取回或作参考。B1 的四格历史（ADR-0142）已经证明这条路走得通：
旧版从事件日志回放，点「用这版」只写一条 `asset.updated`，不重新生成、不花钱。

## 决定

1. **重生成前先复制一份旧图，挂进镜头的历史**
   - `Keyframes.history?: { first: Id[]; last: Id[] }`（可选，旧日志无此字段照常解析）。
   - 复制件 id 为 `a-kfhist-<shotId>-<first|last>-<时间戳>`，字段照抄原资产
     （uri / mime / provenance / createdAt），**唯独不抄 `costCny`**：
     钱记在资产位上（既有口径），复制件再记一次会把同一笔花销数两遍。
   - 按 **uri 去重**：同一张图已经在历史里就不再复制；每帧最多 20 版。
   - 只在旧图真的换掉时才动历史：生成失败、旧图本来就空、同一张图重复生成，
     都不产生历史条目。

2. **当前版仍占原来的资产位**
   - `Shot.keyframes.firstAssetId` / `lastAssetId` 不变，仍是 `a-keyframe-<shotId>` /
     `a-lastframe-<shotId>`。所有按 id 认帧、按 id 算钱、按 id 做溯源的代码不用改。
   - 生成成功写两条事件：`asset.updated`（历史复制件，若有）+ `shot.updated`
     （新帧挂回 + 历史）。一条生成仍然只花一次钱。

3. **「用这版」把内容写回资产位，不换指针**
   - `useKeyframeVersion(shotId, frame, archiveId)`：把选中旧图的 uri / 溯源写回
     标准资产位，**保留当前资产位上的 `costCny`**；现在这一版先复制进历史。
   - 不重新生成、不花钱；换过去之后还能换回来（当前版已进历史）。
   - 锁定的镜头不让换；旧图已不在资产库时如实拒绝。

4. **历史版本是项目在用的素材，不是孤儿**
   - `referencedAssetIds` 与资产库使用标签都收录历史 id，清库不会把它们删掉；
     资产页把它们标成「第 N 镜 首帧旧版」，而不是「未使用」。
   - 历史复制件与当前帧是内容寻址的同一份字节：复制的是资产记录，不复制文件。

5. **界面：每格下面一排旧版缩略图**
   - 关键帧页每格在当前这一帧（首 / 尾）下面显示「旧版 N」，缩略图 + 出图时间，
     点一张即换回；锁定时禁用。切换首尾帧时，历史跟着当前看的那一帧走。
   - 「重生成」的按钮提示改成「现在这一版会进历史，不会丢」。

## 理由

- **不动资产位**：外部引用、计价、过期判断都按标准 id 写死了；换指针会让这些
  逻辑一起改，收益却只是 id 好看一点。
- **复制件不记钱**：`spendOf` 是「资产记录上的钱」，同一笔花销只能落在一个记录上。
  历史上限 20 版，避免一张图把项目体积撑大。
- **内容寻址**：历史复制件与原图分享同一份本机字节；删历史也只是删一条记录。
- **可选字段**：`history` 不进默认值，旧日志、旧测试与手写项目都不用补字段。

## 后果

**正面**

- 重生成不再毁掉上一张付费图；不满意可以换回，也可以拿旧版做参考。
- 旧图留在项目里，清库不会误删。
- 与 B1 四格历史的交互一致：点图换回、当前版自动进历史。

**负面 / 代价**

- 花费仍只记在当前资产位上：重生成两次，`spent` 只算最新那一次（改动前也是
  这个口径）。要让历史版本也进账单，得把花费从资产记录里拆成独立的生成台账，
  不在这一档做。
- 历史只留 20 版；超出后最早的记录被挤掉（不是删除文件，但界面上找不到）。
- 首尾帧的历史分别存，切换首尾看的时候历史不合并展示。
- 这一档只覆盖关键帧：视频 take 早已多版并存；故事 / 剧本的旧版目前只在事件
  日志里可回放，还没有「文本版本库」界面。

## 不做

- 全局「废片库」页面（把被淘汰的 take、旧关键帧、旧故事稿汇到一处）。
- 故事 / 剧本 / 分镜的文本版本快照 UI。
- 跨项目 / 跨集复用（C1、C.4）。
- 历史版本的自动过期 / 清理策略（只做数量上限）。
