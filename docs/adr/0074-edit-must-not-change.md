# ADR-0074 编辑「不许变」清单

- 状态：已接受
- 日期：2026-11-11
- 决策者：用户 + Claude
- 关联：ADR-0071（人物库）、ADR-0028（`mustNotChange` 进 IR）、ADR-0031（三视图提示词）、FEATURES B1

## 背景

`Character.mustNotChange` 从 ADR-0028 起就是"监工重点"：痣、疤、发型分缝、耳饰这些每一张图都必须原样带上的细节，编译提示词时原样拼进去（`generateSheet` 的请求体里就有它）。但它只在 `project.created` 的快照里出现，界面只能看、不能改——想补一条"左耳后一颗小痣"就得改示例数据。

## 决策

1. **不新增事件**：`character.updated` 的 patch 从 `name | appearance` 扩到 `name | appearance | mustNotChange`（ADR-0071 留的口子）。
2. **整份替换**：`mustNotChange` 一次写回整个数组，不做"加一条 / 删一条"两种事件。清单短（上限 20 条），一条一条记只会让日志更长。
3. **校验放在 IR**：空条目、重复条目、单条超过 60 字、超过 20 条都拒绝。`applyEvent` 与 store 各拦一次（重放是安全网，store 负责说人话）。
4. **store 两个动作**：`addMustNotChange(characterId, text)`、`removeMustNotChange(characterId, text)`，都写一条 `character.updated`。
   - 空 → 「这一条是空的。」
   - 重复 → 「已经有一条「X」了。」
   - 过长 → 「这一条太长了：60 字以内。」
   - 超过 20 条 → 「「不许变」最多 20 条：再多会把镜头指令挤掉。」
5. **界面在定妆页人物卡**：`不许变` 列表每条右侧一个 `×`（悬停写"划掉「X」：从之后的每一张图里去掉了"），列表下一个 `＋ 加一条` → 单行输入（回车保存、Esc 取消，60 字上限）；空清单时补一句「还没写：痣、疤、发型分缝这些必须原样带进每一张图。」只读标签页不显示 `×` 与 `＋ 加一条`。
6. **不追溯已出的图**：改清单不把三视图标过期。它改的是提示词输入，但已出的图按 ADR-0057 只认镜头画面输入；清单的过期规则留到"人物图过期"那一刀统一做。

## 理由

- **整份替换最小**：清单是纯文本数组、没有独立 id；加一条就是"新清单 = 旧清单 + 一条"，一个 patch 写得下。
- **60 字 / 20 条**：清单整段进三视图提示词，不设上限就会把"正面全身、白背景"这类画面指令挤掉；两条限制都直接对着提示词的预算。
- **就地编辑**：清单是这一张卡的一部分，弹窗或独立页会把"这张脸长什么样"和"哪些不许变"拆开看。
- **不标过期**：三视图的过期规则还没设计（人物图缺少像镜头那样明确的画面输入事件），先不发明一个只对清单生效的特例。

## 后果

**正面**
- 定妆页给「林」点 `＋ 加一条` 写「耳后一颗小痣」→ 清单多一行，日志一条 `character.updated { mustNotChange }`；再点 `×` → 那一条消失。
- 重复、空、超长、超过 20 条都被拒，错误贴页头，不写事件。
- 测试：IR 94（新增 3）、web 192（新增 3）、gateway 17、pipeline 22，合计 325；`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：`＋ 加一条` → 输入「耳后一颗小痣」→ 回车，清单出现；点 `×` 消失，均无报错。

**负面**
- **没有历史回退**：划掉一条就找不回来（日志里有，界面没有"用这版"）。
- **不追溯已出图**：清单改了，已生成的三视图不带新细节，也不会自己标过期。
- **不能编辑顺序**：清单按加入顺序排，不能拖动（顺序会进提示词，但目前影响很小）。
- **单条不能换行**：一行输入，写长句只能靠 60 字上限约束。

**跟进**
- 清单的历史回退（与名字 / 外形一起做，ADR-0071 跟进）。
- 人物图过期：清单或外形改了之后给已出的三视图挂 `过期` 小签。
- 清单条目的排序。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 单独开 `mustNotChange.added` / `.removed` 事件 | 清单没有 id，删一条只能按文本匹配；两种事件的校验与界面都更绕 |
| 放进 `character.updated` 时拆成两个 patch 事件 | 同一次编辑写两条事件，日志更长，没有收益 |
| 清单改成对象数组（`{ text, note }`） | 现在只需要一句话；结构留到真的需要"为什么不许变"时再改 |
| 允许重复条目 | 重复条目进提示词就是重复描述，白占预算 |
