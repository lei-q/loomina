# ADR-0057 过期标记：出图之后又改了画面，这一帧就不算数了

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0037 / 0038（首尾帧）、ADR-0042（关键帧页）、ADR-0049（动作改写）、ADR-0050 / 0056（场头）、FEATURES B2

## 背景

关键帧可以是图生图的前置（B2），也是这一镜「长什么样」的答案。可它一旦出出来，就与之前的输入脱钩了：改完动作、换完景别、把场头从 `内 · 夜` 改成 `外 · 日`，页面上那一帧仍然好好挂着，没有任何东西说「它已经对不上这一镜了」。用户要么自己记得改过什么，要么花第二次钱重生成还不知道该不该。

事件的形状已经够用：每次改写都有 `at`，每张图也有 `createdAt`。比时间就能回答。

## 决策

1. **读模型 `staleFrames(events, project)`**：对每一镜算「最后一次画面改动的时刻」，再与它首 / 尾帧资产的 `createdAt` 比；资产更早 → 这一帧过期。返回 `Map<shotId, { first?, last? }>`，值是那次改动的时刻。
2. **什么算画面输入**（镜头级）：`description`、`promptNotes`、`shotSize`、`camera`、`characterIds`、`propIds`；**场头级**：`scene.updated` 的任何一项（内外景 / 日夜 / 地点），作用于这一场的所有镜头。
3. **什么不算**：台词改动（`dialogue.*`）不改变一张静止画面；时长、排序、锁定也不改变画面。`asset.updated` 本身是修复，不是原因。
4. **快照是基线**：只从 `project.created` 之后的事件起算，快照里的帧按快照算——否则老项目一打开就全是过期。
5. **界面**：关键帧页每帧画面左下角挂`过期`小签（悬停写「<首 / 尾>帧出图之后，这一镜的画面在 HH:MM 改过，建议重生成」）；页头多一个 `过期 n 帧`（pick 色）；生成按钮悬停改成「画面改过，这一帧已对不上：重生成」。重生成后资产的 `createdAt` 变新，小签自然消失。
6. **`toKeyframeView` 收 `events`**：过期信息写进 `KeyframeCell` 的 `staleFirst` / `staleLast`，格子自己知道。

## 理由

- **只比时间，不比内容**：比内容要存出图时的提示词再逐字 diff，重生成恰好一样的提示词也会被判「没变」；时间是最便宜也最诚实的判据。
- **画面输入而不是「一切输入」**：把台词算进来，会让一句台词让全部帧过期，用户反而学会忽略这个小签。
- **场头算进来**：日夜与内外景直接决定光线；地点换了就是另一个空间。
- **快照当基线**：把「昨天出的图、今天才开始的日志」判成过期毫无信息量。
- **标记而不是自动重生成**：钱是用户的；标记把决定权交回去。

## 后果

**正面**
- SH-01 出完首帧后回剧本页把动作从「走廊尽头，灯管闪了一下」改成「…，又灭了。」：关键帧页 SH-01 画面左下角出现`过期`，页头 `过期 1 帧`，首帧按钮悬停是「画面改过，这一帧已对不上：重生成」；别的镜头不受影响。
- 只改场头（日夜 / 内外景 / 地点）时，这一场有帧的镜头全部过期——这是对的：光变了。
- 只改台词、改时长、锁定镜头，都不产生过期。
- 重生成后 `asset.updated` 的 `createdAt` 晚于改动，小签消失。
- 测试：web 141 条（新增 4 条：改动作 / 场头 / 台词的区分、重生成后不再过期、`toKeyframeView` 写入格子）；IR 64、gateway 17、pipeline 21 不变，合计 243。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：headless Chrome 在关键帧页为 SH-01 生成首帧（¥0.12，已花 ¥19.08）→ 回剧本页改动作 → 回关键帧页看到`过期`与 `过期 1 帧`。

**负面**
- **只到「过期」，不说是哪里过期**：看到小签还得自己回想改了动作还是场头。
- **只覆盖关键帧**：图生视频的 take、配音、成片都没有这个标记；提示词预览也不标。
- **时间判据有假阳性**：把动作改回去（内容与出图时一模一样）仍判过期；改一个字也判过期。
- **不覆盖资产被外部替换**：`asset.updated` 若晚于改动，就视为已修好，不管内容对不对。
- **锁定的镜头照样显示过期**：标记照实说，但按钮是灰的，要解锁才能修。
- **分镜页那一格没有标记**：只有 `/keyframes` 有，两处看到的东西不一致。
- **默认不拦**：过期不阻止导出、也不阻止后续生成视频；它是提示，不是闸门。

**跟进**
- 分镜页（stage）的关键帧缩略条也挂小签。
- 过期原因（改了哪一项）记账，悬停写「动作、场头」。
- 把同一判据推广到 take / 配音 / 成片。
- 过期是否阻止「发布 / 导出」按闸门（ADR-0028）的规矩再议。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 存「出图时的提示词」再逐字比较 | 要再加一份快照；提示词同名改动也要 diff，成本高且解释不清 |
| 任何事件都算过期 | 台词、时长、锁定与画面无关，全算会让标记失去可信度 |
| 自动重生成过期帧 | 花钱的决定不能替用户做，尤其是批量补帧 |
| 新增 `keyframe.stale` 事件 | 过期是推导出来的状态，不是发生过的事；存下来会与日志打架 |
| 在生成时就锁死这一镜 | 锁定是闸门（ADR-0041），要求先留用 take；不该为了帧强行锁镜 |
| 只在资产上记来源时间 | 已经有 `createdAt`；缺的是「改动时刻」的聚合，属于读模型的事 |
