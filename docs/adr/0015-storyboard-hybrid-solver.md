# ADR-0015 剧本→分镜采用「规则引擎 + LLM」混合约束求解

- 状态：已接受
- 日期：2026-11-09
- 决策者：产品 / 工程
- 关联：P1、P11、A3、A10、I1、I5

## 背景

把剧本变成分镜，有两种极端做法：

A. **纯 LLM 一次性生成**：快，但输出不可控。常见问题：全是中景、轴线乱、时长超模型上限、台词没落到镜头上、预算爆炸。
B. **纯规则模板**：可控，但死板。无法理解"这场戏的情绪是压抑的""这句话是反讽"。

分镜本质是**在叙事意图、空间几何、模型能力、成本预算之间求可行解**。

## 决策

采用混合架构：

1. **LLM 负责创意选择**：Beat 分析、覆盖率方案、镜头目的、表演/情绪描述、台词分配建议。
2. **规则引擎负责合法性**：轴线（180 度）、时长区间、覆盖率完整性、景别轮换、模型能力、预算。
3. **所有输出必须符合 IR schema**，LLM 不能输出自由文本作为最终结果。
4. **校验失败时自动修正或提示**，而不是接受非法输出。
5. 规则库是可版本化、可测试、可被用户覆盖的产品资产（导演语法库）。

流程：

```
剧本 → LLM：Beat + 覆盖率草案
     → 规则引擎：摆位/机位/时长/预算校验
     → 3D 板：轴线与空间验证
     → 校验报告：通过 / 自动修正 / 提示
     → 结构化 Shot[] → 关键帧 → Animatic
```

## 理由

- 分镜不是"写得好"，而是"拍得出来、接得起来、花得起"。
- 规则引擎把"审美经验"变成可执行的约束，LLM 把"上下文理解"变成选择。
- 结构化输出才能驱动 3D 板、提示词编译器、成本估算与自动校验。
- 规则库是护城河：它可积累、可评测、可被用户自定义。

## 后果

**正面**
- 分镜可解释、可校验、可复现。
- 避免 LLM 的典型偏差（单调、越轴、超长）。
- 规则库可持续积累，形成产品差异。

**负面 / 代价**
- 规则库需要维护与调参，初期覆盖不足会限制创意。
- 规则过严会扼杀风格化表达，需要"高级用户可关闭"的逃生口。
- LLM 与规则的边界需要持续调优。

**跟进**
- 规则库与样例库同步维护（每条规则配正例/反例）。
- 提供"严格/平衡/自由"三档校验强度。
- 用 Animatic 与人工评分持续校准规则。

## 替代方案

- **纯 LLM**：不可控，否决为默认。
- **纯规则**：死板，无法处理语境，否决为默认。
- **人工分镜**：质量高但不可规模化，只作为兜底与高端选项。
