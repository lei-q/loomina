# ADR-0096：Beat、覆盖率与分镜校验（A11 / A12 / A13 第一版）

- 状态：已采纳
- 日期：2026-11-11
- 关联：A11、A12、A13、A3、P13、P15、ADR-0015、ADR-0088

## 背景

`STORYBOARD.md` 把「场次与 Beat 分析 → 覆盖率规划 → 分镜校验」写成完整管线，`DATA-MODEL.md` 的目标形状里也有 `Shot.beatId` 与 `Shot.purpose`。但当前落地只有生成层：

- A3 生成的草稿有 10–14 镜、景别 / 机位 / 运镜 / 台词，却没有「这一镜属于哪一拍、承担什么功能」。
- 分镜页能看画面、改出场与提示词，但没有地方回答「这一拍讲清楚了吗」「这几镜是不是连续同景别」「整片重做会不会超预算」。
- 旧项目与手工项目没有 Beat 数据。直接加必填字段会让现有事件日志回放失败，也会把作者没标过的内容伪装成事实。
- P15 把覆盖率列为硬约束，但完整硬闸门还依赖 3D 走位（V3）、能力矩阵（V9）与阶段闸门（F8 / F9），这一轮不具备条件。

用户要求一个功能一个功能地做，每做一个都能在 UI 上操作验证。因此这一版的目标是：**先把叙事层的数据、读模型与人工检查做出来，并让生成结果开始带 Beat；不假装已经完成 P15 的全部硬约束。**

## 决策

### 1. Beat 与镜头目的进 Shot，但都是可选字段

`packages/ir/src/schema.ts` 增加：

```ts
type BeatKind =
  | "hook" | "setup" | "escalation" | "turn"
  | "climax" | "resolution" | "endHook";

type ShotPurpose =
  | "establish" | "information" | "emotion"
  | "reaction" | "transition" | "hook";

Shot.beat?: BeatKind;
Shot.purpose?: ShotPurpose;
```

不新建独立的 `Beat` / `CoveragePlan` 实体：

- Beat 是镜头的一个属性，不是跨镜头共享的对象；`beatId` 需要另一张表与生命周期，当前没有读者。
- 覆盖率是读模型算出来的结论，不是需要回放的事实；把它写进 IR 会让「镜头改了但覆盖率没改」成为可能。
- 可选字段保证旧日志原样回放。`beat` 不标就是不知道，不用默认值伪造。

`STORYBOARD.md` 里的 `inciting`（打破平衡的事件）这一版并入 `escalation`：两者在 60–180 秒短剧里经常是同一段。等 Beat 检测由模型独立完成、需要区分「诱因」与「升级」时再加枚举值，并按 ADR 记录迁移。

### 2. 生成时让模型直接给，解析时不认识的词留空

`packages/pipeline/src/story.ts`：

- 生成提示词第 7 条要求每一镜标 `beat` 与 `purpose`，给出枚举与「每拍至少一个信息镜头 + 一个情绪 / 反应镜头」的约束，JSON 示例里带 `beat: "escalation", purpose: "information"`。
- 解析同时认英文枚举与中文别名：钩子 / 铺垫 / 升级 / 转折 / 高潮 / 收束 / 尾钩；建立 / 信息 / 情绪 / 反应 / 过渡 / 钩子。
- 不认识的词映射为 `undefined`，不猜、不取第一个枚举值。作者可以在分镜检查里补。
- `projectFromStoryDraft` 只在有值时写字段，没值就不写，保持「未标注」与「标了某个值」的区别。

### 3. 推断只发生在读模型

新增 `apps/web/lib/storyboard.ts`，纯函数、不依赖浏览器：

- `planShots(project)` 按场次顺序与场内镜序排出全片镜号，给每镜算出 `beat` / `purpose`、来源（`shot` / `inferred`）、起始时间与时长。
- 没标 Beat 时按全片位置兜底：首镜 `hook`、末镜 `endHook`，中间按 34% / 60% / 80% 分位落到 `setup` / `escalation` / `turn` / `climax`。
- 没标目的时按可观察信息推断：首镜 `hook`；有台词的特写 / 大特写是 `emotion`，其他有台词镜头是 `information`；全景是 `establish`；无人物的镜头是 `transition`；上一镜有台词、这一镜有人物则是 `reaction`；其余 `information`。
- 推断值**不写回 IR**。只有作者在检查面板里改了，才写一条 `shot.updated`。这样刷新、回放、换设备后不会出现「系统替我做了创作决定」。

### 4. 覆盖率按「拍」统计，定义写死

`groupBeats(plans)` 把同场、连续的同一 Beat 合成一段 `BeatSpan`：

- 跨场不合并，即使两场都是 `setup`；场是空间与光线的边界。
- `hasInformation`：段内至少一个 `establish` 或 `information` 镜头。
- `hasEmotion`：段内至少一个 `emotion` 或 `reaction` 镜头。
- 覆盖率 = 同时具备两者的拍数 / 总拍数，四舍五入到整数百分比；没有镜头时为 0，不除零。

这是 `STORYBOARD.md` 第 ② 步原则 1 的可计算版本。它只回答「叙事功能齐不齐」，不评价故事好坏、不评价镜头美不美。

### 5. 校验第一版只做能可靠判断的六条

`validateStoryboard` 输出 `error` / `warning` 两级：

| 规则 | 判断 | 级别 |
| --- | --- | --- |
| V1 | 每场至少一个 `establish` 目的或全景镜头 | warning |
| V2 | 有台词的镜头里，说话人必须在 `characterIds` 中 | warning |
| V4 | 单镜 1–8 秒（模型安全区间） | error |
| V5 | 每一拍有信息镜头、有情绪 / 反应镜头，缺一项一条 | warning |
| V6 | 同场连续 3 个同景别 | warning |
| V8 | 整片重做一遍的报价超过 `Project.budgetCny` | warning |

`V3`（180° 轴线）需要 3D 走位；`V7`（切率曲线）需要节奏模型与更多样片标定；`V9`（模型能力）需要 B12 / H16 能力矩阵；`V10`（引用存在且已锁定）已有零散的写入时校验，还没汇进这份报告。这些在面板底部如实写「还没查」，不留假通过。

V8 只在价目表能算出 `requoteAll.totalCny` 时检查；算不出就不报——未知价格不是 0 元。规则顺序固定：先错误后提示，同级按 V 编号排。

### 6. 分镜页的「检查」抽屉

- 顶栏「预演」左边新增「检查」；有错误或提示时按钮上带数量，颜色用 `pick`。
- 右侧抽屉 `aria-label="分镜检查"`：
  - 顶部四格：覆盖率、已覆盖拍数 / 总拍数、错误数、提示数；
  - 当前镜的节拍与镜头目的两个下拉，选项带一句人话任务；值来源是推断时写一行「还没有手动标注」；
  - 节拍列表：按场次列出每一拍、镜号区间、时长、`信息 + 情绪` 或缺哪一项；点一行跳到那一拍第一镜；
  - 校验列表：规则编号、人话说明、`去 SH-xx` 跳转；多镜问题写共几镜；
  - 底部写清未做的 V3 / V7 / V9 与覆盖率的定义。
- 改下拉调用 `setShotPlan(shotId, patch)`：只读时拒绝；找不到镜头拒绝；`shot.locked` 时拒绝并给「这一镜已锁定，先解锁再改节拍或镜头目的」；值没变不写日志。写入是一条 `shot.updated`，与改景别、机位走同一条事件。
- 抽屉打开时不响应分镜页的 ← → 换镜快捷键；Esc 与遮罩点击关闭。

### 7. 这一轮不做

- 不把覆盖率做成导出或生成前的硬闸门。P15 仍是目标，当前是可见的检查与人工修改；硬闸门等阶段闸门（F8 / F9）与能力矩阵（B12 / H16）一起接。
- 不做自动补镜、自动拆分超长镜头、自动降级预算。规则先如实报告，改法是作者的事。
- 不做独立的 `Beat` / `CoveragePlan` 实体、Beat 摘要生成、Beat 级成本估算与覆盖率模板库。
- 不做 V3 / V7 / V9 / V10 的完整校验。
- 不做 Beat 时长目标（如 hook 2–4 秒）的提示：样片标定不足，先不制造假精确。

## 理由

- 把 Beat 与目的放在 Shot 上，是当前读者最少、改动最小的形状；独立实体等有第二个读者时再拆。
- 可选字段 + 读模型推断，让旧项目立刻能用新面板，又不把推断伪装成作者意图。
- 覆盖率定义写死为「信息 + 情绪 / 反应」，与 `STORYBOARD.md` 一致，避免每个开发者各算一套。
- 只实现能可靠判断的规则，并在界面写明未做的规则，比给一个「全绿」的假报告更符合「如实说」的准则。
- 生成提示词直接要求模型标 Beat，能让新项目从源头带结构；解析留空而不是猜，给作者保留修正空间。

## 后果

**正面**

- 新生成项目每一镜带 `beat` / `purpose`；旧项目打开检查面板就能看到推断结果与 15 条左右的改进提示。
- 改一个镜头的目的，覆盖率与提示数会立刻变化；刷新后仍在。实测：示例项目 `SH-01` 目的改为「信息」后提示 15 → 14；节拍改为「铺垫」后覆盖率 0% → 11%（1/9），提示 12；点「去 SH-04」跳到第 2 场。
- 锁定镜头改不动，原因写清楚；值没变不产生噪声事件。
- 所有推断与校验都是纯函数，单测覆盖 15 条（含跨场不合并、V1–V8、预算未给不查、空项目不除零）。

**负面**

- 旧项目覆盖面可能很低（示例项目为 0%），因为推断只读镜序与景别，不读描述语义；这是提示作者补标的入口，不是质量评分。
- 生成模型仍可能给出不合理的 Beat 顺序（例如高潮后接铺垫）；V5 只查每拍功能是否齐全，不查顺序是否合理。
- 规则是启发式：V6「连续 3 个同景别」在刻意重复的蒙太奇里也会报；V1 把全景当作建立镜头，可能误判。
- 分镜检查不是硬闸门，作者可以带着 0% 覆盖率继续生成与导出。

- `pnpm typecheck`、`pnpm test`（IR 110 / gateway 28 / pipeline 30 / web 333，共 501）、`next build` 全过。
- 新增 `apps/web/lib/storyboard.test.ts` 15 条；`workbench-store.test.ts` 增加 5 条 `setShotPlan`（写入、组合改、无变化不写、锁定拒绝、找不到镜头）；pipeline 草稿测试补 Beat / 目的别名与未知词。
- 无头 Chrome 打开 `/`：顶栏「检查 15」，抽屉显示 12 镜 / 10 拍 / 覆盖率 0% / 0 错 15 提示；当前镜 `SH-03` 显示推断提示。跳 `SH-01` 后把目的改为「信息」，提示 15 → 14；节拍改为「铺垫」后覆盖率 11%（1/9）、提示 12、第一拍显示「信息 + 情绪」。
- 点校验里的「去 SH-04」跳到第 2 场第 1 镜；刷新后重开抽屉，`SH-01` 仍是「铺垫 / 信息」，推断提示消失；随后还原为「钩子 / 钩子」，覆盖率回到 0%。
- 跳 `SH-08`（已锁定）时两个下拉都禁用，下方写「这一镜已锁定：先解锁再改节拍或镜头目的」。
