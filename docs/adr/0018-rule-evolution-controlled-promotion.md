# ADR-0018 导演语法规则的自动发现与受控晋升

- 状态：已接受
- 日期：2026-11-09
- 决策者：用户 + Claude
- 关联：P17、I8/I9、DIRECTOR-GRAMMAR.md、RULE-EVOLUTION.md

## 背景

导演语法库首批 37 条规则是专家经验。长期看，规则需要持续补充：

- 新模型上线会改变可行性规则。
- 新题材需要专属规则。
- 真实使用数据里存在专家没预料到的模式。

但"自动补充"有两个风险：
1. 规则膨胀与互相冲突；
2. 风格趋同——所有作品变成一个味道；
3. 黑盒漂移——没人知道规则为什么变了。

## 决策

采用**自动发现、受控晋升**：

- **自动发现**：四个信号源（失败挖掘、用户覆盖、参考片分析、专家/社区），按触发阈值生成候选规则。
- **受控晋升**：
  - `must` 级：人工确认 + 结构回归零失败 + 至少 2 名评审；
  - `should` 级：A/B 人类偏好胜率 ≥ 5%，成本增幅 ≤ 10%，p < 0.05，持续 2 周；
  - `may` 级：可自动进入风格包，默认关闭。
- **防膨胀**：活跃规则 ≤ 60 条，90 天未触发归档，冲突检测，作用域限定，风格与结构分离。
- **可追溯**：每条规则记录证据、正反例、适用范围、版本、评审人；指标恶化自动回滚。

## 理由

1. 规则是产品 IP，必须可控，不能成为自我修改的黑盒。
2. 数据能发现专家没想到的模式，但数据也会过拟合、会放大偏见。
3. 分级晋升让低风险规则快速迭代，高风险规则慢下来。
4. 冷启动阶段（<100 项目 / <10,000 镜）只收集数据、不自动晋升。

## 后果

**正面**
- 规则库可持续进化，且有质量门槛。
- 用户覆盖被正确区分：纠错进全局规则，偏好进 `StyleProfile`。
- 版本化 `grammar@x.y` 支持灰度与回滚。

**负面**
- 需要评测集、A/B 基础设施与人工评审流程。
- 冷启动期规则增长慢。

**跟进**
- 建立 golden set 与结构回归测试。
- 定义 `RuleCandidate` / `GrammarVersion` 的存储与发布流程。
- 前 100 个项目只埋点，不自动晋升。

## 替代方案

- **纯人工维护**：质量高但慢，跟不上模型与题材变化。
- **全自动晋升**：快，但会膨胀、趋同、漂移，放弃。
- **只按用户偏好调整**：会把个别风格误当全局规则，放弃。
