# ADR-0063 场景描述：这地方长什么样，进主镜提示词

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0028（主镜闸门）、ADR-0032（主镜出图）、ADR-0059（新建 / 编辑地点）、FEATURES B8

## 背景

主镜提示词此前只有地点名字：

```
场景主镜，空镜：走廊。无人入画，广角，交代空间结构、陈设与光源方向。…
```

模型不认识「走廊」在任何具体房子里长什么样。同一部片子的走廊会被每张主镜画成不同的墙、不同的灯——而主镜的全部意义是让同一场的所有镜头共用一份空间与光线。道具早就有 `description` 并进提示词（`buildPropPrompt`）；地点缺这一格。

## 决策

1. **`Location.description: string`**，默认 `""`。旧项目回放时 schema 补空串，不报错、不改日志。
2. **改描述走 `location.updated` 的 `patch.description`**，与名字、模板同一条事件；不新增事件类型。`location.added` 也带这一格。
3. **上限 200 字**（`LOCATION_DESCRIPTION_MAX`）。超了拒绝并写「场景描述太长了：200 字以内。」，不写事件。这句会整句进提示词，太长会把镜头指令挤掉。
4. **提示词**：`buildMasterPrompt(location)` 收 `{ name, description }`，描述非空时插在名字后面、镜头指令前面；空串不留空句（与 `buildPropPrompt` 同一条写法）。
5. **服务端**：`/api/asset` 的 `master` 请求体收 `description`，按 200 字截断；浏览器把 `location.description` 一并送过去。
6. **界面**：定妆页地点行中间那栏从一句固定的解释文案，变成「描述 + 解释」两层——有描述时直接显示，没有时显示 `＋ 写一句这地方长什么样`；点一下就地变成三行文本框 + `保存` / `取消`（Esc 收起），下面一行小字写清「整句进主镜提示词：空间、陈设、光线，200 字以内」。只读标签页只显示文字，不可点。`新建地点` 表单多一个描述框（选填），建好即带上。

## 理由

- **把「房间不许每镜重新想象」落到能写的地方**：主镜的闸门价值取决于提示词里有没有具体空间；名字给不了这个信息。
- **复用已有的 patch**：`location.updated` 已经是「改地点自己的字段」的那条路；描述不是资产、不是场景关系，不该另开事件。
- **200 字而不是不限**：提示词是一串指令，不是文章；不设限会让一段散文挤掉景别、光线、画幅这些真正控画面的词。
- **空串不进提示词**：与道具描述一致，避免出现「。」连「。」的空句。
- **描述不自动失效主镜**：改描述说明「这地方应该是另一副样子」，但已经出的主镜不会因此打过期小签——过期判据只看画面输入（ADR-0057），地点描述属于主镜自己的输入，重出即可。

## 后果

**正面**
- 定妆页`走廊`点 `＋ 写一句这地方长什么样` → 写「老楼走廊，声控灯，墙皮起了卷」→ `保存`，这一行直接显示这句；日志一条 `location.updated { locationId: "loc-corridor", patch: { description: "老楼走廊，声控灯，墙皮起了卷" } }`。
- `新建地点` 填 `楼梯间` + 描述 → 一行建出来，状态 `未挂场次`，描述已显示；`location.added` 里带着这一格。
- 主镜提示词从此多一句具体空间；同一场的镜头共用的是有内容的锚点。
- 测试：IR 73 条（新增 2 条：改描述只动这一格、旧项目补空串）；pipeline 22 条（新增 1 条：描述进主镜提示词）；web 159 条（新增 2 条：改描述的 `location.updated` 与回放、超限 / 新建带描述）；gateway 17；合计 271。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：`走廊`写描述 → 保存 → 行上显示；`新建地点` 带描述建 `楼梯间` → 行上显示；IndexedDB 对应两条事件。

**负面**
- **不会自动重出主镜**：描述改了，旧主镜还是旧描述画出来的；要么手动重出，要么就一直旧着。没有「描述改了，主镜过期」的小签。
- **只有一段文字，没有结构**：空间、陈设、光线、时段混在一句里；想按项控制得靠用户自己写清楚。
- **200 字上限是硬切的**：服务端截断，界面超限拒绝；粘一段长文会悄悄丢掉后半段（截断）或直接被拒（界面）。
- **不进主镜历史**：`改名` / `换模板` 也不进，描述沿用同一口径；改坏了只能凭记忆写回去。
- **没有从剧本 / Story Bible 自动抽取**：地点描述目前纯手写（A4 未做）。

**跟进**
- 描述改动时给已出的主镜挂`过期`小签。
- 把描述拆成结构化字段（时段 / 陈设 / 光源），提示词按项拼。
- 从场次正文自动起草一句描述。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 新事件 `location.described` | 描述就是地点的一个字段；`location.updated` 的 patch 已经能表达 |
| 把描述塞进 `Shot.promptNotes` 或场次正文 | 描述属于空间，不属于某一场或某一镜；同一地点的所有场都该共用 |
| 不设长度上限 | 一段长文会挤掉景别、光线、画幅这些真正控画面的指令 |
| 描述改了自动重出主镜 | 自动花钱、自动换图；出图是用户按按钮的动作 |
| 只放在 `新建地点` 表单里 | 已有地点（示例里的走廊 / 门口 / 桌边）永远写不上描述 |
