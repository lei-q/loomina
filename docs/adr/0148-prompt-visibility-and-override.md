# ADR-0148 模型提示词可见与手改

- 状态：已接受
- 日期：2026-11-12
- 决策人：用户 + Claude
- 关联：ADR-0040（提示词可见）、ADR-0105（生成前提示词审核）、ADR-0144（四格资产位）、I12

## 背景

到这时为止，提示词只有两处能看见：分镜页一个只读的「这一镜会送出的提示词」折叠块（ADR-0040），以及出片后写在 take 溯源里的那一段。故事、定妆、关键帧、声音四个阶段都在调模型，作者却看不到代码到底把项目内容拼成了什么；想微调一句「冷白路灯」只能去改外形 / 场景描述，连带影响所有镜头。

短剧的提示词是创作的一部分：同一个角色换一个角度的三视图、同一镜换首帧或尾帧、同一句换一种念法，想说的东西不一样。只让作者改结构化字段，改不动「这一次」的措辞。

## 决策

1. **每一处生成按钮旁边都能展开「提示词 · 可改」。** 展示的是**这一次真正送出去的那一段**，不是示意：
   - 故事：系统提示词 / 用户消息两条，各一个页签；
   - 定妆：角色的四格按角度分页签，主镜、道具参考图各一段；
   - 关键帧：首帧 / 尾帧两个页签（关键帧页与分镜页同一套键）；
   - 分镜 / 出片：视频提示词一段（与首尾帧并列成三个页签）；
   - 声音：随台词发给配音模型的 `instructions` 一段（没写就只把台词送出去）。
2. **默认提示词在浏览器里用同一批构造器算出来。** `buildSheetPrompt` / `buildMasterPrompt` / `buildPropPrompt` / `buildKeyframePrompt` / `buildVideoPrompt` / `storyMessages` / `importStoryMessages` 本来就在 `@loomina/pipeline` 里、读模型已经引用；界面不需要多一个「取提示词」接口，也不会出现界面显示与服务器实际发送不一致。
3. **手改按目标存键，不写事件、不进 IR。** `promptOverrides: Record<string, string>` 键形如 `sheet:c-lin:front`、`keyframe:s-03:first`、`video:s-03`、`voice:d-01`、`story:user`。它描述「这一次想怎么说」，不是项目事实；刷新、重开项目、重来一遍都清空。改回与默认相同或点「恢复默认」时删除该键。
4. **生成时优先送出改后的版本。** store 在发请求时带上 `prompt`（声音是 `instructions`）；服务端确认非空后**完全替换**默认提示词，不再拼接。故事阶段带 `prompt.system` / `prompt.user`，逐条替换。
5. **审核发生在最终提示词上。** H6 的 `assertPromptAllowed` 仍在调用供应商之前跑；作者改出硬阻断内容，一样在计费前停下并回 400。提示词上限 4000 字（故事单条 8000 字、配音 300 字），超长直接 400，不在服务端偷偷截断。
6. **溯源记最终提示词。** 出图 / 出片 / 出音的 `provenance.prompt` 是实际发出去的那一段；take 的「提示词里没有当前台词」判断不变——如果手改后把台词删了，仍会如实标出。
7. **新项目与「重来一遍」清空手改。** 键里带项目内的 id，带过项目只会错位。

## 理由

- **可见性比新参数重要**：作者先要知道模型在读什么，才谈得上调。把默认提示词摆出来本身就是文档。
- **复用构造器**：另写一份「预览用」提示词必然与真实请求漂移；读模型已经证明这些构造器能在浏览器里跑。
- **不进 IR 是对的**：手改是试写，不是版本；进 IR 就要有失效、合并、回滚与跨镜引用规则，收益远小于成本。真要保留一句措辞，应该回到结构化字段（外形、场景描述、补充要求）。
- **整段替换而不是追加**：追加会让「改一句」变成「在长提示词末尾再叠一句」，模型行为不可预期；作者看到的文本必须就是送出的文本。

## 后果

**正面**

- 五个阶段都能看见并微调提示词，改完直接生成，不用改结构化字段去猜。
- 界面显示与请求内容同源；溯源里能查到当时到底发了什么。
- 审核、预算、锁镜、关键帧先行等既有闸门全部不变。

**负面 / 代价**

- 手改不持久：刷新就回到默认。想要的措辞要么记住，要么写回结构化字段。
- 四格 / 首尾帧 / 系统用户消息各有多段，页签增加了操作步数。
- 作者可以改出与项目设定冲突的提示词（比如把不存在的角色写进画面），系统不会拦——它只保证「送出的就是你看到的」。

**边界**

- 不做提示词模板库、变量插值、版本历史、跨项目复用。
- 不提供「对比两版提示词」；重生成会覆盖同一资产位（take 不覆盖，出片仍保留多拍）。
- 不改模型参数（分辨率、时长、seed）；这些有自己的入口或尚未支持。
- 服务端不判断提示词与项目是否一致。

## 验证

- `prompt-override.test.ts` 5 条：缺省 / 空白 / 非文本 / 去空白 / 超限与故事上限。
- `workbench-store.test.ts` 4 条：四视图只替换手改的那一格、关键帧带上与恢复默认后不再带、出视频用视频提示词、配音手改替代表演参数拼出的 `instructions`。
- 全仓测试与 `tsc --noEmit`、`next build` 干净。
- 浏览器逐阶段展开、改一段、生成后核对 take / 资产溯源里的 `prompt` 是改后的文本。
