# ADR-0079 参考图多张与手动挂

- 状态：已接受
- 日期：2026-11-11
- 决策者：用户 + Claude
- 关联：ADR-0028（`referenceImages` 进 IR）、ADR-0032（参考图生成）、ADR-0071 / ADR-0072（人物 / 道具库）、ADR-0078（道具签）、FEATURES B1 / B8

## 背景

`Character.referenceImages` 与 `Prop.referenceImages` 从 ADR-0028 起就在 IR 里，但界面几乎没用上：

- 人物只能看到四格三视图；IR 里那张 `a-lin-expr`（表情表）在任何地方都不显示。
- 道具的参考图永远是 `referenceImages[0]`：生成一次覆盖一次，第二张没处放，也没处挂。
- 没有任何"手动挂一张图"的入口——用户手里有现成的剧照、服装参考、道具实拍，挂不进来。

## 决策

1. **参考图是数组，不是单张**：
   - 人物：三视图四格不变，`referenceImages` 单独一排 `参考`，从 `ref 1` 数。
   - 道具：第一张仍占大图位（`ref 1`），其余排在旁边；没有参考图时大图位显示「待生成」。
2. **生成改成"往后挂"**：`generateProp` 不再覆盖 `referenceImages[0]`，而是新建资产 id 并追加；一条 `asset.updated` + 一条 `prop.updated { referenceImages }`。人物三视图的生成逻辑不变（四格是固定角度，各自覆盖自己那一格）。
3. **手动挂**：两排 `参考` 都有 `＋ 挂一张` → 单行输入，贴图片地址：
   - 接受 `http(s)://…` 或 `data:image/…`；空白、别的协议拒绝（「参考图要先有地址：http(s):// 或 data:image/ 开头。」）；
   - 地址上限 400 KB（data URI 可能很长）；
   - 同一对象下重复地址拒绝（「这张图已经挂过了。」）；
   - 每条上限 8 张（`REFERENCE_IMAGES_MAX`），生成与手挂共用这个上限；
   - 写入两条事件：`asset.updated`（`source: "upload"`，mime 从 data URI 头里读）+ `character.updated` / `prop.updated { referenceImages }`。
4. **摘掉**：每张参考图右上角一个 `×`（只读不显示），写一条 `*.updated { referenceImages }` 把 id 摘掉；**资产不删**，图还在资产表里，可以再挂回来（与删除不清理资产一致）。
5. **IR 校验**：`character.updated` / `prop.updated` 的 `referenceImages` 拒绝重复、超过 8 张、指向不存在的资产——重放是安全网，store 负责说人话。
6. **读模型**：`CastCharacterView.references` / `CastPropView.references` 给出 `{ assetId, uri? }[]`；道具的 `referenceAssetId` / `referenceUri` 仍然等于第一张。

## 理由

- **先贴地址，不做上传**：项目还没有对象存储（上传需要后端落盘、签名、清理），但"挂一张现成的图"这件事本身现在就能做。贴地址是最小的一步；以后接上存储，`source: "upload"` 的资产形状不用变。
- **追加而不是覆盖**：覆盖意味着"每生成一次就丢掉上一张"，而参考图的价值恰恰在多张（正面 + 侧面 + 实拍）。追加也让"删除不清理资产"有了回收的可能。
- **上限 8**：参考图会进锚点与提示词（`cast.ts` / `anchors.ts`），不设上限会把镜头指令挤掉；8 张足够覆盖表情与服装变体。
- **与三视图分开**：四格有角度语义（正面 / 3-4 / 侧面 / 背面），`referenceImages` 没有；混在一排会让"这张算什么角度"变成新的问题。

## 后果

**正面**
- 人物的 `参考` 排在四格下面，IR 里已有的表情表（示例 `a-lin-expr`）终于看得见。
- 道具可以挂多张：生成一张再挂一张实拍，`ref 1` / `ref 2` 并排；生成不再冲掉手工挂的图。
- 手动挂一张 data URI 后立刻出现缩略图，`×` 可摘；摘掉后资产还在。
- 测试：IR 97（新增 3）、web 214（新增 4：store 3、读模型 1）、gateway 17、pipeline 22，合计 350。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：定妆页「林」`＋ 挂一张` → 贴一张 `data:image/svg+xml` → `ref 1` 出现红图；再挂一张 → `ref 2`；点 `×` 摘掉 → 回到一张。「台灯」同样挂上显示；无报错。

**负面**
- **没有真上传**：只能贴地址；本地文件得先自己转成 data URI 或传到图床。
- **地址不校验可达性**：贴一个 404 的地址也挂得上，缩略图是破图；没有"测试这张图"。
- **摘掉不删资产**：孤儿资产继续累积（与删除的资产回收是同一个问题）。
- **参考图不进生成请求**：接口仍只收名字 / 描述 / 清单，挂上的图是给人看的锚点素材，不是图生图的输入——图生图仍是后续。
- **顺序不能调**：参考图按挂上的先后排，`ref 1` 就是第一张；不能拖。
- **人物生成不追加**：三视图仍是四格固定角度，`生成三视图` 只刷新那四格。

**跟进**
- 真正的上传（对象存储 + 签名 URL），把 `source: "upload"` 接上。
- 图生图：把参考图作为请求里的 reference images。
- 参考图的顺序调整与"设为主图"。
- 孤儿资产回收（删除、摘图都不清理资产）。
- 挂图时校验可达性 / 尺寸，失败给一句人话。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 先做文件上传 | 需要对象存储、签名、清理，属于基础设施；贴地址已经能验证"多张 + 手动挂" |
| 生成覆盖第一张（保持原状） | 与"多张"直接冲突，手工挂的图会被下一次生成冲掉 |
| 手动挂只收 asset id | 用户看不到资产 id，等于没有入口 |
| 摘图时连资产一起删 | 同一张图可能被别处引用；资产回收要统一想清楚 |
| 参考图并入三视图四格 | 四格有角度语义，参考图没有；混排会让"这是哪一格"说不清 |
| 无上限 | 参考图进锚点与提示词，必须给预算一个数 |
