# ADR-0227：混响按对白轨应用，不按场切整条流（C11 第二档）

- 状态：已采纳
- 日期：2026-11-14
- 决策者：用户 + Claude
- 关联：C11、C7、C12、ADR-0226、SOUND.md §八

## 背景

ADR-0226 把「每场用哪套混响」定下来了，但渲染侧故意没接。当时写的理由是：
**按场切滤镜需要 `atrim` + `concat`，接缝处容易爆音。**

这个判断需要重新审视。混音命令的结构是这样的：

```
每条对白轨 → aresample → adelay → [增益] → atrim → dlygN
                                                     ↓
                                              amix → 对白总线
```

**对白本来就是一条一句、各自独立的输入流**。也就是说，「按场切」这个问题
在混音这一层根本不存在——每一句已经天然知道自己在哪一段。

## 决定

1. **混响加在对白轨上，不加在整条混音流上**：
   每条对白的滤镜链变成 `aresample → adelay → [增益] → [aecho] → atrim`。
   - 不需要 `atrim` + `concat`，**没有接缝**；
   - 混响尾巴自然延伸进下一句（`adelay` 之后、统一 `atrim` 之前），
     这正是真实房间里该有的行为。
2. **混响跟场走**：`toEditView` 给每个 `EditClip` 算 `reverbId`（按 `Scene` 的
   场地与内外景，复用 ADR-0226 的 `reverbPresetOf`），同一场的每句都用它。
3. **清单只传预设 id，不传滤镜串**：`RenderAudio.reverb` 是 `ReverbPreset` 的 id，
   服务端用 `REVERB_IDS` 白名单校验，再从固定表解析成滤镜。
   传裸滤镜串等于把任意 ffmpeg 参数暴露给请求体，那是注入面。不在表里的 id 当没有。
4. **`in_gain` / `out_gain` 都是 1.0**：湿度只由三个 decay 系数决定。
   早先按 `wet` 压 `out_gain`，实测把干声整体拉低 2–3 dB——混响不该顺带改音量，
   整片响度由 `loudnorm` 统一管。
5. **干声预设返回空串**：不挂滤镜，与旧命令逐字节同构，旧项目重渲结果不变。

## 验证（本地 ffmpeg 实测）

用 2 秒粉噪跑六档，测**源停止后 1 秒**的平均音量（尾巴）：

| 预设 | 尾巴（源已停） |
| --- | --- |
| 干声 | 无声（无输出） |
| 室外 | −45.2 dB |
| 小房间 | −43.2 dB |
| 走廊 | −40.0 dB |
| 大厅 | −39.2 dB |

整体平均音量也单调递增（−34.6 → −33.1 dB），说明「房间越大、尾巴越长」在听感上成立。
另外用正弦信号测时走廊档异常偏低，原因是 440 Hz 与短延迟相消——**粉噪才是合适的
测试信号**，这一条记下来供以后测混响参考。

## 理由

- **顺着已有结构做，而不是改造结构**：对白一条一轨是现状，按轨加滤镜是最小的改动，
  且天然避开接缝问题。当初判断「必须 atrim+concat」是想当然了。
- **只传 id**：清单是跨进程边界的数据，任何能直接影响 ffmpeg 参数的字段都该是枚举，
  不该是自由字符串。
- **不改音量**：混响是空间感，不是音量工具。让它顺带改电平会让「同一场听起来
  忽大忽小」，那正是 C12 在做的事。

## 后果

**正面**

- 混响第一次进成片，且**没有接缝爆音风险**。
- 旧项目不带 `reverbId`，渲染结果与以前一致。
- 尾巴自然延伸，不需要额外处理淡出。

**负面 / 代价**

- **只作用于对白**：配乐与音效不加混响。这两条是整轨输入（可能跨场），
  按场切就得回到 `atrim`+`concat`。当前判断是「对白的空间感最要紧」，其余留待以后。
- **每条对白一个 `aecho` 实例**：几十句就是几十个滤镜，渲染 CPU 略增。
- 参数仍是用 `aecho` 近似，不是真实房间脉冲响应。
- 混响尾巴在片尾会被统一 `atrim` 截断（片子结束，可以接受）。
