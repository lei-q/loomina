# ADR-0071 人物库：新建与改名

- 状态：已接受
- 日期：2026-11-11
- 决策者：用户 + Claude
- 关联：ADR-0070（这一镜里换人，需要更多候选）、ADR-0059 / ADR-0063（地点的新建 / 改名 / 描述）、ADR-0028（定妆闸门）、FEATURES A9 / B1

## 背景

分镜页与剧本页都按 `characterIds` 点名人物，但人物只能来自 `project.created` 那一次快照：定妆页只能生成三视图、锁 / 解锁，**不能新建、不能改名、不能改外形描述**。示例项目里只有林、周两个人，ADR-0070 的换人下拉因此只有彼此可换；新建一集要加人时，没有任何入口。

地点在 ADR-0059 / ADR-0063 已经有一套"新建 / 改名 / 写描述"的做法，人物是同一类东西（被场次与镜头引用、下游要锁定），可以照同样的形状补上。

## 决策

1. **两个事件**（不新增别的）：
   - `character.added { at, character }`：带完整人物（`name / appearance / sheet / referenceImages / mustNotChange`）；重名 id 拒绝，空名字拒绝。
   - `character.updated { at, characterId, patch }`：patch 只允许 `name` 与 `appearance`；空 patch、空名字、指向不存在的人物都拒绝。
2. **store 两个动作**：
   - `addCharacter(name, appearance?)` → id；名字与外形去首尾空白；与现有人物重名拒绝（「已经有一个叫「X」的人物了。」）；外形 200 字上限（整句进提示词，和地点描述同一个理由）。
   - `editCharacter(characterId, { name?, appearance? })` → boolean；与别人重名拒绝；没改动拒绝（「人物没改。」）。
3. **新建的人物从空白开始**：`sheet: {}`、`referenceImages: []`、`mustNotChange: []`；三视图随后在定妆页逐格生成（ADR-0031），锁定闸门不变。
4. **改名不连坐资产**：`sheet` 与参考图按资产 id 挂着，名字只是提示词里的称呼；改名后已出的三视图不标过期（外观没变）。外形描述属于提示词内容，改名 / 改描述后已出的帧按 ADR-0057 的既有规则处理（`characterIds` 是画面输入；描述文本本身目前不在过期判据里）。
5. **不给删除**：这一刀先只做新建与改名。删人物要考虑"他还在镜头里 / 还有台词 / 还有帧"，和地点删除一样需要一个搬移规则，单开一刀。
6. **界面在定妆页**：
   - `人物 · 三视图` 标题右侧 `新建人物`：虚线表单，名字 + 外形描述（选填），回车 / 创建提交，Esc 取消；
   - 每个人物名字旁 `改`：就地展开名字与外形描述两个字段，保存 / 取消；
   - 只读标签页不显示 `新建人物` 与 `改`。

## 理由

- **和地点同一套形状**：都是"被引用的库对象"，新建 / 改名 / 描述三件事拆成同样的两个事件，读侧与心智都不用学第二套。
- **名字与外形放进同一个 `character.updated`**：它们都是提示词输入，一次表单提交就是一次改动；分成两个事件只会让日志变长。
- **外形描述 200 字**：它整句进提示词（`appearance` 已在锚点与提示词里），长了会把镜头指令挤掉——与 ADR-0063 给地点定的上限一致。
- **不做删除**：没有搬移规则之前，删除要么产生悬挂引用，要么悄悄改掉别人的镜头；先不开口子。
- **不自动生成三视图**：生成要花钱，新建后由用户点 `生成三视图` 并看到报价。

## 后果

**正面**
- 定妆页点 `新建人物` 填「阿棠 · 齐耳短发，灰毛衣」→ 人物列表多一张卡，四格待生成，`¥0.00` 报价；剧本页的换人下拉立刻多出「阿棠」。
- 点 `改` 把名字改成「阿棠（改）」→ 卡片标题跟着变，日志一条 `character.updated`；改回「阿棠」再写一条。
- 重名、空名字、超长外形被拒，错误贴在页头，不写事件。
- 测试：IR 85（新增 3：加人物、改名字与描述、空名字 / 重 id / 陌生 id 拒绝）、web 183（新增 3：新建、拒绝三种、改名与重名 / 没改）；gateway 17、pipeline 22；合计 307。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：定妆页新建「阿棠」→ 出现在人物列表；`改` 改名后标题变化；分镜页点出林、剧本页打开换人下拉，候选为「周 / 阿棠」。

**负面**
- **不能删除人物**：试验人物只能留着。
- **不能编辑 `mustNotChange`**：新建的人没有"不许变"清单，目前只能改名字与外形。
- **不能新建声音档案**：`voiceProfileId` 仍是空的，声音确认（A9）没接。
- **没有外形 / 名字的历史**：`character.updated` 留痕，但界面没有像场头那样的「改过几次 / 用这版」。
- **改名不改台词里的称呼**：台词文本按原文保存，不会跟着改；说话人按 id 引用不受影响。

**跟进**
- 删除人物 + 引用检查 / 搬移。
- 编辑 `mustNotChange`（监工重点）。
- 外形与名字的历史回退（对齐场头 ADR-0058）。
- 道具库的新建 / 改名 / 描述（同一套形状）。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 人物也走 `project.updated` 整份覆盖 | 事件的粒度应当是"改了什么"，整份覆盖会让日志里每一次改动都像重写整个项目 |
| 改名与外形拆成两个事件 | 同一次表单提交的两种输入，拆开只是多一条事件 |
| 新建时同时生成三视图 | 生成要花钱，必须由用户看到报价后点 |
| 允许删除，引用一并清空 | 悄悄改掉别人的镜头，违背"删除要显式"的方向；先不做 |
| 把人物列表放到剧本页 | 定妆页是"库"的所在地（人物 / 地点 / 道具都在这里），镜头侧只做引用 |
