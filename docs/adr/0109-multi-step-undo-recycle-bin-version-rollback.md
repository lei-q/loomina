# ADR-0109：多步撤销、回收站与全局版本回滚

- 日期：2026-11-11
- 状态：已采纳
- 关联：F2、ADR-0011、ADR-0034、ADR-0076、ADR-0081、ADR-0082

## 背景

F2 已经做过三块「撤销」：

- 删除的撤销（ADR-0076）：页头「刚删掉 X」+ `撤销`，追加补偿事件把人物 / 道具 / 地点 / 场次 / 镜头原样放回；
- 换人的撤销（ADR-0081）：只在内存里留最近一次，换回来出场顺序与说话人；
- 按版回退（ADR-0082）：人物 / 道具 / 地点的名字与描述「用这版」整版写回。

但**多步撤销、回收站、全局版本回滚**一直没做——只能撤最近一次删除，撤错了不能往前再走；任何一次改动的整组内容也撤不回来。用户做完一长串编辑后想回到某一步，唯一办法是刷新重来（示例项目）或手动反向编辑。

本项目是「一次成型」的短剧创作，作者频繁试错：改一镜动作、改一场场序、删一镜重来。每一类改动都是一条事件，日志天然就是一份可回放的历史。缺的只是把这份历史读出来、让人能跳到任意一步。

## 决策

### 1. 日志里加一类 `project.restored` 事件

```ts
| { type: "project.restored"; at: string; toEventCount: number; label?: string }
```

- `toEventCount` 是「前缀长度」：1 表示只留下 `project.created`，N 表示回放到第 N 条事件之后。**不携带快照**。
- 为什么不带快照：项目里每张定妆图是约 2.4MB 的 data URI（ADR-0034）。每撤销一次都抄一份完整项目，一个正常项目几十兆，撤销几次就把本地库撑爆。而日志只追加、从不删改，前缀的回放结果永远相同，存一个位置就够了——这正是 ADR-0011「日志是事实、项目是它跑出来的结果」的直接好处。
- `label` 是给人看的一句话（「撤销：改 SH-03 的 take：状态」「回到预算 ¥100」），历史抽屉里原样显示。

### 2. `rebuild` 改为逐步回放

`rebuild(events)` 原本只是 `events.reduce(applyEvent)`。新增 `rebuildStates(events)` 返回**每一步**之后的项目（结构共享，数组本身占用很小），遇到 `project.restored` 就直接取前缀那一步的结果。好处：

- 历史读法、回收站名字、回滚定位都靠这份数组；
- 被删掉的东西也能按「删除之前」那一份项目算它当时的名字，不会退化成一串 id；
- 同一毫秒写出的多条事件能精确归到同一次操作。

`project.restored` **不能**用 `applyEvent` 单条应用——它看不到前缀，猜不得。单条 apply 它直接报错，逼调用方改用 `rebuild`，避免静默地从错误前提继续回放。

### 3. 多步撤销：一次退一整组

`undo()` 找到当前位置之前最近一条「非回滚」事件，再沿同一毫秒往前扩到操作起点（删一场会写「逐镜删除 + 删场」，必须整组退，否则留下半场空镜），然后 `restoreTo(起点, label)`。

时间戳是关键：原本每处用 `new Date().toISOString()`。同一毫秒里连点两次（测试里尤其常见）会被误认成一组。新增 `stamp()`：每次操作一个时间戳，且严格递增（必要时 +1ms）。这样「一次操作」与「同一步历史」的边界稳定。

⌘Z / Ctrl+Z 绑定在顶栏（输入框里的撤销交给浏览器，不抢）；点格子 / 翻镜的导航不拦。

### 4. 历史抽屉 + 回收站

顶栏「历史」打开右侧抽屉（和「检查 / 表演 / 体检」同一套）：

- **下一步撤销**：显示退回去是哪一步，整组事件数；「撤销」按钮。
- **每一步 · 最新的在前**：整条日志的人话版本。每条带时间戳、类型标记、人话标签；当前位置标「现在」；任意一条都能「回到这里」。
- **回收站**：日志里所有「删掉了、现在还没回来」的对象，最新在前，每条可单独「放回」（复用 ADR-0076 的补偿逻辑，按删除之前的快照写回，不顺手撤掉之后别的改动）。

人话标签由 `describeEvent(before, event)` 生成：删人物显示名字、删镜头显示 SH-xx、改分镜列出具体字段（景别 / 机位 / 表演…）、阶段确认显示「确认『分镜』阶段」……名字按事件发生之前的项目算，删掉的东西也还能按当时的叫法显示。

### 5. 回滚的边界

- 末尾已经是回滚时，`historyPosition` 按回滚目标算，再撤销不会停在同一个地方；
- 「回到这里」正好是当前步时不写多余的回滚事件；
- 只读（另一个标签页在编辑）时撤销 / 回滚 / 放回全部禁止；
- 坏日志（回滚目标越界、缺引导事件）读不出来，历史读成空列表也不让界面崩。

## 后果

- 优点：历史再长，本地库只多出一条小事件，不复制图片资产；回滚不删日志，想往前再走一步也行——「后悔」是廉价的。
- 代价：回滚之后若继续编辑，会叠出更长的日志。这是预期的——它保留了完整可回放的历史，符合 ADR-0011。
- 不改动的：ADR-0076 / 0081 / 0082 三块原撤销逻辑保留并复用（回收站就是它们的「按任意删除索引找回」版本）。
- 风险：人话标签是尽力而为的自然语言，错了也不影响回放正确性（回放看的是前缀长度，不看标签）；同一毫秒多事件归组依赖 `stamp()` 递增，已用单测锁住。
