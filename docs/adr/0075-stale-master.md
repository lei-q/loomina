# ADR-0075 场景描述改动后主镜挂「过期」

- 状态：已接受
- 日期：2026-11-11
- 决策者：用户 + Claude
- 关联：ADR-0063（场景描述）、ADR-0057（关键帧过期）、ADR-0032（主镜生成）、FEATURES B8

## 背景

场景描述整句进主镜提示词（ADR-0063）。改了描述之后，已经出的主镜还是旧描述画的，界面上却和"刚出的"长得一模一样——用户以为空间锚点没变，下游按它出的镜头就会对不上。镜头有 `过期` 小签（ADR-0057），主镜没有。

## 决策

1. **读模型算，不写事件**：新增 `staleMasters(events, project)`，与 `staleFrames` 同一个形状（`{ at, reasons }`）。
2. **只认一种改动**：`location.updated` 里带 `description` 的事件。改名字、换模板不算：主镜提示词里只有名字与描述（`generateMaster` 的请求体），模板只决定界面剪影。
3. **比时间，不比内容**：改动晚于主镜资产的 `createdAt` 才算过期；重生成之后自然消失。
4. **界面**：主镜缩略图左下角挂 `过期`（与关键帧同一套样式），悬停写「主镜出图之后改过：场景描述（HH:MM），建议重生成」。资产位存在就挂，哪怕示例素材没有真图。
5. `toCastView(project, events?)`：不传日志时不计算过期，保持既有调用与测试的形状。

## 理由

- **不写事件**：过期是"日志与资产时间的比较"，不是事实；写进 IR 就等于把推导结果存成事实，重放时还要维护它。
- **只认描述**：提示词没变就不算过期——把"改了名字"也标过期，会让小签变成噪音。
- **和关键帧同一套**：用户已经在镜头那边学会了这个标记；主镜用同一个词、同一个位置，不用学第二套。

## 后果

**正面**
- 定妆页改「门口」的描述 → 它的主镜左下角出现 `过期`，悬停看到改动时刻；再点 `生成主镜`，重生成后小签消失。
- 改名字、换模板不挂小签。
- 测试：web 196（新增 4）；IR 94、gateway 17、pipeline 22；合计 329。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：改场景描述后小签出现，标题为「主镜出图之后改过：场景描述（22:24），建议重生成」。

**负面**
- **人物三视图没有过期**：外形描述或「不许变」改了，已经出的四格不会提醒（留到人物图过期那一刀）。
- **只看描述**：引用别的字段（比如以后描述拆成结构化字段）要跟着扩展。
- **没有页头计数**：关键帧页有「过期 n 帧」，定妆页只有卡上的小签。
- **模板改动不算**：现在模板只影响剪影；哪天真进了提示词，这里要补一项。

**跟进**
- 人物三视图 / 道具参考图的过期（外形、描述、清单改动）。
- 定妆页页头的「过期 n 张」。
- 描述拆成结构化字段后，逐项算过期。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 改描述时写一条 `asset.stale` 事件 | 把推导结果存成事实，重放与撤销都要维护它 |
| 改名字也标过期 | 名字不进提示词，标了就是噪音 |
| 只显示"描述已改"，不挂小签 | 与镜头那边不一致，用户要学两套说法 |
| 自动重生成主镜 | 生成要花钱，必须由用户点 |
