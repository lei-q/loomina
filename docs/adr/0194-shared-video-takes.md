# ADR-0194：跨空间取一拍视频（用户清单 C.1 / 功能 C20）

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：C1、C16、C17、C20、B5、ADR-0083、ADR-0189、ADR-0190

## 背景

用户的清单 C.1 是「故事、剧本、定妆素材、音频、视频都可加入资产库并复用，
跨集直接复用同类场景、道具、演员，不再花钱生成」。

现状已经覆盖：

- 参考图跨空间挑（C16 / ADR-0189）；
- 演员 / 场景 / 道具整块复用（C17 / ADR-0190）；
- 项目技能（C18）、接上一段（C19）。

**视频还没有入口**。视频是单价最高的一项：同一段走廊、同一个动作在第二集
还要用，现在只能重新生成，或者把地址手工贴过来（还得知道地址）。

## 决定

1. **复用现成的跨空间清单，只换种类**
   - `sharedAssetsOf(spaces, ["video"])` 本来就能按 `kind` 筛；
     C16 的默认值仍是 `["image"]`，老调用方逐字节不变。
   - 打开面板时才 `loadWorkspaceProjects()` 回放各空间日志；
     传给清单前先滤掉当前空间——不从自己这里「取」。

2. **取用仍走「登记资产记录 + 加一拍」**
   - `attachVideo(shotId, uri, source?)` 多一个可选 `source`，默认 `upload`
     （贴地址导入的旧行为不变）。
   - 从别的空间取来的视频传 `source: "library"`：
     - 不触发素材授权检查（不是这次上传的）；
     - 不算未定价调用（不是这次生成的）；
     - 只登记地址，不复制字节——素材库本来就按内容寻址，一份字节只存一份。
   - `provenance.modelId` 写 `library`（贴地址导入仍写 `import`）：
     回看时能分清「拿过来的」与「这次导入的」；原资产的模型 / 提示词不跟过来。

3. **挂上就是这一镜新的一拍**
   - 与贴地址、出视频同一条路：`asset.updated` + `take.added`，
     状态 `draft`、`costCny: 0`；原来的拍不受影响，也不改首尾帧。
   - 同一镜里地址已经挂过就拒绝，避免重复的拍把 take 列表撑乱。
   - 锁定镜头、只读窗口、关键帧阶段闸门都按既有规矩拒绝。

4. **界面在分镜页「视频」格**
   - 视频格下面多一个「从素材库取一拍」，打开网格：视频缩略图（静音、
     只取元数据）、来源空间、在那个空间里用在哪（「第 3 镜 take」）。
   - 已经挂在这一镜的地址置灰「已在这一镜」；最多列最新 60 条。
   - 取用成功后面板关闭，新的一拍立刻出现在 take 列表里。

## 理由

- **视频是最该复用的**：一张图几毛，一拍视频几块；跨集复用的收益主要在这里。
- **同一套清单与口径**：C16 已经证明按 uri 去重、合并使用处、滤掉当前空间这套
  做法够用；再写一份视频专用的清单只会多一套要维护的规则。
- **`library` 是诚实的来源标记**：这段字节不是这次花的钱，也不是这次上传的；
  记成 `upload` 会触发授权检查、记成 `generated` 会算成未定价调用，两者都错。
- **不改 IR**：`Asset.source` 已有 `library`，take 结构不用动，旧日志不用迁移。

## 后果

**正面**

- 第二集可以拿第一集已经出好的片子当一拍，不重新生成、不花钱、不复制字节。
- 取用记录与贴地址导入区分得开：素材页能看出「这段是拿过来的」。
- 视频、参考图、实体三条跨空间入口共用一套日志回放与去重逻辑。

**负面 / 代价**

- **只拿了视频**：故事、剧本、音频（配音 / 配乐）的跨空间取用还没有入口。
- 取来的只是文件与一拍记录，不跟原 take 的留用状态、时间线位置、提示词过期标记。
- 面板没有搜索 / 按空间筛选，最多列 60 条；素材多了要先在来源空间整理。
- 对象存储未配置时，`s3://` 地址的视频缩略图显示不出来，但地址本身仍可挂。
- 同一段视频挂进多个空间后，任何一处删除资产记录都不影响别处（地址仍在），
  但「资产页删除」仍需要各自处理。
