# ADR-0064 新建场次与新建镜头：只能往末尾加

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0011（事件日志）、ADR-0050（场头）、ADR-0059（新建地点）、ADR-0060（场序）、FEATURES A21

## 背景

到目前为止，场次与镜头只能改、不能加：`scene.updated` / `shot.updated` 改已有对象，`dialogue.added` 只能加台词。新建地点之后没有新场次可挂，改写剧本时多出来的戏无处安放——要么改示例数据，要么把两场挤进一场。

## 决策

1. **两个新事件**：
   - `scene.added { scene }`：只能加在末尾（`scene.index === scenes.length`），新场 `shotIds` 必须为空。
   - `shot.added { shot }`：只能加在所属场次末尾（`shot.index === scene.shotIds.length`），不允许夹带 `dialogueIds` / `takeIds`——台词和 take 各有自己的添加事件，从这里带进来等于绕过它们。
2. **校验**：场次 / 镜头的 id 不得重复；`scene.locationId` 必须存在；`shot.sceneId` 必须存在；`scene.index` / `shot.index` 必须是「下一个」。任何一条不满足就拒绝，日志里不留半成品。
3. **写路径是单一的**：`applyEvent` 里 `shot.added` 同时把镜头挂进 `scene.shotIds`，两处引用一步写齐；不变式 `SCENE_SHOT_BIDIRECTIONAL` / `SHOT_INDEX_CONTIGUOUS` 天然成立。
4. **默认值**（`store.addScene` / `store.addShot`）：
   - 新场：地点取项目第一个地点（可传 `locationId` 指定），`space = int`、`timeOfDay = day`（schema 默认），无镜头。
   - 新镜：`durationMs = 3000`、`shotSize = medium`、`camera = { eye, static, 35 }`、描述为空、无人物 / 道具 / 台词 / take、未锁定。
5. **界面**：剧本页每场末尾一个虚线 `＋ 加一镜`，整页末尾一个通栏虚线 `＋ 加一场`；只读标签页都不显示。新场立刻以 `第 N 场 内 · 日 地点 0.0s · 0 镜` 出现，场头照旧可点改；新镜显示 `（这一镜还没有动作描述）`，点一下就能写。
6. **不新增改名 / 删除**：本刀只做「加」。删场、删镜要处理 take、关键帧、时间线引用，单独开决策。

## 理由

- **只能往末尾加**：中间插入要重排后面所有场号与 `index`，等于「加」+「重排」两条语义混在一条事件里；末尾加与 `scene.moved` 配合已经能到达任何位置。
- **新场不带镜头**：场次与镜头是两种对象，一次建两层会让「这场戏还没想清楚」与「这一镜还没写」混成一个动作。
- **新镜带默认景别机位**：空白下拉在提示词里无处可去；`中景 · 平视 · 35mm` 是一个能出图的起点，改起来也只需点一下。
- **默认 3 秒**：短剧里空镜 / 反应镜的常见长度；有台词后时长会按字数重算。
- **不夹带台词与 take**：`dialogue.added` 要同步镜头时长，`take.added` 要挂资产与成本；从 `shot.added` 带进来会绕过这两条规则。

## 后果

**正面**
- 剧本页 `＋ 加一场` → 第 6 场出现（`内 · 日 · 走廊`，0 镜）；`＋ 加一镜` → `SH-13` 出现，`中景 · 平视 · 3.0s`；页头从 `场 5 镜 12` 变成 `场 6 镜 13`、时长加 3 秒。
- 日志两条：`scene.added { index: 5, shotIds: [] }`、`shot.added { sceneId, index: 0 }`；回放每一步都通过 `validateProject`。
- 新场可以接着 `挪`（ADR-0060）挪到任何位置，场号、镜号自动重排。
- 测试：IR 76 条（新增 3 条：加场 / 加镜 + 回放 + 不变式、四类拒绝）；web 162 条（新增 3 条：加场、加镜、陌生场次与只读）；gateway 17、pipeline 22；合计 277。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：`＋ 加一场` → 第 6 场 0 镜；`＋ 加一镜` → SH-13；页头 `场 6 镜 13 时长 38.6s`；IndexedDB 第 45 / 46 条为上述两个事件。

**负面**
- **只能加在末尾**：想在两场之间插一场，得先加再 `挪`；中间插入本身没有一步到位的操作。
- **新场默认「第一个地点 · 内 · 日」**：多半不是用户想要的，得再点场头改三项。
- **删不了**：加错了只能留着或靠以后的删除决策；目前没有 `scene.removed` / `shot.removed`。
- **新镜是「空壳」**：没有人物、没有台词、没有画面描述，分镜页会把它当一镜普通镜头计入进度与预算。
- **一次只能加一镜**：连加五镜要点五次，写五条事件。

**跟进**
- 删场 / 删镜（含 take、关键帧、时间线引用的级联规则）。
- 在指定位置插入场次 / 镜头。
- 新场的默认地点取「上一场的地点」，少改一次下拉。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 复用 `scene.updated` 加 `shotIds` 来「加场」 | 场次对象本身不存在，patch 无从落笔 |
| `shot.added` 允许任意 `index`，由 applyEvent 重排 | 一条事件里混了「加」与「重排」两种语义；重排另有 `scene.moved` |
| 新场一次性带 N 个空镜头 | 一次建两层；大多数新场先写动作再决定分几镜 |
| 新镜默认 `wide` / `top` 等更「安全」的景别 | 短剧的主力景别是中景；默认值应该是常见值，不是最保守值 |
| 新镜不写 `durationMs`，等有台词再算 | `durationMs` 是必填正数；没有时长就无法计入页头时长与预算 |
| 在 `shot.added` 里允许带 `dialogueIds` | 台词插入要同步镜头时长，绕开 `dialogue.added` 就会让时长与台词不一致 |
