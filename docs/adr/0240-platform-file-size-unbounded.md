# ADR-0240：区分「官方未设上限」与「没核过」（G2 补完）

- 状态：已采纳
- 日期：2026-11-15
- 决策者：用户 + Claude
- 关联：G2、G7、ADR-0112、ADR-0214

## 背景

ADR-0214 核到 B 站 16 GB 与快手 2 GB，其余七个平台仍写「未核验」。
这次继续核，本机网络下的结果：

| 平台 | 可达性 | 结果 |
| --- | --- | --- |
| 抖音 | ✅ 开放平台文档可达 | **官方列了文件要求，但没有文件大小上限** |
| 快手 | ✅ 帮助中心可达 | 已有 2 GB（App 相册导入口径） |
| 小红书 | ❌ 网络风险拦截 / 需登录 | 核不了 |
| 视频号 | ❌ 需登录 | 核不了 |
| TikTok / YouTube / X | ❌ 站点超时 | 核不了 |

关键发现是抖音：它的官方 SDK 文档逐条列了「文件要求」——格式（mp4 / YUV420P）、
时长（≤60 分钟）、尺寸（短边 <2160、长边 <4096）——**唯独没有文件大小上限**。

这暴露了一个此前没表达出来的状态：**核过了，但官方确实没设上限**。
它与「没核过」是两件不同的事，而界面上原来都写成「未核验」。

## 决定

1. **`PlatformSpec` 增加 `maxFileUnbounded`**：`{ url, checkedAt, quote }`，
   与 `maxFileSource` 同形状。有 `maxFileBytes` 时它不生效（有上限就用上限）。
2. **三种状态分开说**：
   - 有上限 → 「上限 16.0 GB（2026-11-14 核：…）」+ 超限硬拦；
   - 核过但官方没设 → 「官方未设上限（2026-11-15 核：…）」，不标「参考」；
   - 没核过 → 「没有可引用的公开上限（未核验）」，标「参考」。
3. **抖音填上 `maxFileUnbounded`**，出处是官方 SDK 文档的「文件要求」原文。
4. **`maxFileNote` 写清口径**：「官方列的是格式 / 时长 / 尺寸，没有文件大小上限；
   按体积判断没有意义」。
5. **测试守住互斥**：一个平台不能同时有 `maxFileBytes` 与 `maxFileUnbounded`。

## 理由

- **「核过、没有」和「没核」对作者的意义完全不同**：前者可以放心，后者要继续查。
  都写「未核验」会让作者以为抖音也有个未知的上限。
- **不编一个数**：抖音没有官方上限，就不填。填「4GB」之类的二手说法违背 ADR-0112 的立场。
- **不标「参考」**：`reference: true` 的意思是「这个值平台可能改，只提示」。
  官方没设上限不是「一个会变的值」，是一个结论。
- **复用 `maxFileSource` 的形状**：两件事都是「某个结论 + 出处 + 复核日期」，
  用同一种结构，将来界面也能用同一种方式渲染。

## 后果

**正面**

- 抖音从「未核验」变成「官方未设上限」，作者知道不必为此担心。
- 三种状态在界面上一眼可辨，不用猜「未核验」是没查还是查不到。
- 测试保证两种结论不会同时出现在一个平台上。

**负面 / 代价**

- **仍有 5 个平台核不了**（小红书 / 视频号需登录或网络拦截，TikTok / YouTube / X 站点超时）。
- 「官方未设上限」只覆盖**分享 SDK** 这一条路径；开放平台的上传接口如果有别的限制，
  这次没查到（文档目录里没有那个页面）。
- 抖音的时长上限（60 分钟）与现有规格表里的 15 分钟不一致，这次没动——
  那是另一件事（规格表按短剧口径定的，不是照搬平台上限）。
- 界面文案变长了一截。
