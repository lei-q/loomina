# ADR-0181：胶片质感与导入 LUT（I3）

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：I3、E4、E5、H3、H9、F4、ADR-0128、ADR-0169、ADR-0177、ADR-0180

## 背景

E4 的调色只有四个旋钮：对比三档、饱和三档、色温三档、暗角开关。
它回答的是「这条片子统一成什么倾向」，够用，但回答不了作者嘴里那句
「我要一点胶片的味道」——那种味道来自**胶片曲线**与**颗粒**，不是把 contrast 调高一点。

`FEATURES.md` 里 I3 只有一行：「LUT 与胶片质感 · 内置 + 可导入」。ADR-0169 当时
明确把 `.cube` 推到 I3，理由是「真正的 LUT 是另一层」。现在补上这一层。

## 决定

1. **两层新东西，都挂在 `Project.grade` 上**
   - `film`: `none | warm-film | cool-film | faded | mono`，内置五种胶片取向；
   - `grain`: 0–100 的颗粒强度，0 表示不加；
   - `lutAssetId` / `lutName`：导入的 `.cube`，指向资产库里的一份文件。

   全部带默认值（`none` / `0` / 空串），旧日志回放后导出与以前逐字节同构。

2. **内置胶片不引入任何第三方 LUT 文件**
   五种取向用 ffmpeg 已有的 `curves` / `colorbalance` / `hue` / `eq` 拼出来。
   理由：LUT 文件有授权问题（市面上的「柯达 2389」大多不能随软件分发），
   而内置的目标只是「一眼看出是胶片」，不是复刻某一支胶片的精确响应。
   作者要精确响应，就导入自己的 `.cube`。

3. **导入的 `.cube` 是资产，不是项目字段**
   - `AssetKind` 新增第四种 `lut`；文件按内容寻址进本机资产库 / 对象存储
     （`application/x-cube` ↔ `.cube`），IR 里只存 `lutAssetId` 与显示名。
   - 不把表内容写进 `Grade`：那是几万行文本，写进事件日志等于把 H3 与
     ADR-0177 的成果一次性还回去。
   - 调色表被 `grade` 引用，所以算「有人在用」：孤儿检查、跨项目清理的白名单
     必须包含它（`referencedAssetIds` / `assetUsageLabels` 已补）。

4. **渲染时的顺序：LUT → 逐项调色 → 胶片 → 颗粒 → 暗角**
   - LUT 是「换一套色彩空间」，应该先做；后面的逐项调色是在它之上微调。
   - 颗粒放在最后（暗角之前）：先加噪会被后面的对比 / 饱和一起放大，
     作者给 40 会得到比 40 重得多的噪点。`grain × 0.6` 映到 `noise` 的 0–100。
   - 滤镜链仍然是纯函数 `gradeFilters(grade, { lutPath })`；路径来自清单里的
     `lut.uri`，由渲染路由落到临时目录再交给 ffmpeg。

5. **LUT 文件缺失时只跳过 LUT**
   - 预览 / 面板：没有路径就编译不出 `lut3d`，其余调色照常显示。
   - 导出：清单里带了 `lut.uri` 而文件读不到，整条渲染失败并说清楚
     「重新导入一份，或先换成内置胶片」——不能悄悄少一层调色，
     作者拿到的成片会和预览不是同一条。

6. **清单里单独带 `lut: { uri, name }`**
   只靠 `grade.lutAssetId` 服务端无法把 id 映射回文件（清单里没有资产表），
   所以由成片页把 `editView.lut` 一带带上；服务端校验 MIME 必须是
   `application/x-cube`、体积 ≤ 2 MB，并计入素材总量。

7. **界面在调色面板里，紧接着逐项微调**
   胶片做成五个 chip + 颗粒滑杆；导入区显示当前表名、「换一份」「不用这份」。
   导入只落资产、不自动启用：作者点「存调色」才写 `project.updated { grade }`，
   与面板里其它改动同一个保存动作。
   CSS 预览对胶片只做近似（去色 / 褪色 / 偏暖 / 偏冷），对 LUT 不做——
   CSS 没有 `lut3d`，界面上如实写「以导出为准」。

## 理由

- **胶片与 LUT 是「导出层」**：它们不改提示词、不需要重出图，改完只重渲一遍。
  和 `look`（生成层）分开，是 E4 定下的边界，这一版继续守。
- **内置用滤镜而不是 LUT 文件**：`package.json` 一个包没加，仓库里也没有
  来路不明的二进制 / 文本表；`curves` 的 preset 在 ffmpeg 里长期稳定。
- **`.cube` 进资产库**：换机器、清缓存、把项目导出再导入，地址仍然指向同一份
  内容寻址的文件；与 F3 班底模板「只存地址」同一个道理。
- **失败就失败**：静默降级会让「导出的片子和预览不一样」变成一个查不出来的 bug。

## 后果

**正面**

- 调色从「四个旋钮」变成「预设 + 逐项 + 胶片 + 颗粒 + 自己的 LUT」，
  仍然全部只影响导出、不花钱。
- 资产库页能把调色表单独算一类（「调色表 1 个 · 1 KB」），孤儿检查不会误删。
- 旧项目零迁移：所有新字段都有默认值，`LOG_VERSION` 不变。

**负面 / 代价**

- 内置胶片是「近似」，不是精确胶片模拟；要和参考片对齐仍需自己导入 LUT。
- 导入的 `.cube` 只在能读到资产库的机器上有效（与其它素材一致）。
- 胶片 + 颗粒会显著提高编码复杂度，成片体积可能变大；渲染档位不变。
- 预览看不到颗粒与 LUT 的真实效果，只有胶片取向的大致方向。

## 不做

- 内置 LUT 文件市场 / 在线下载（授权与供应链问题）。
- 按镜头单独调色（调色仍是整片一份；逐镜调色会打破「统一」这个前提）。
- 把 `.cube` 转成预览用的 CSS / WebGL 实现（等真的需要逐帧预览再说）。
- 自动从参考片提取 LUT（属于 I6 风格学习）。
