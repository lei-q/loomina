# ADR-0039 一句话指令：把"太暗了""换个角度"变成可回放的补丁

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0011（事件日志）、ADR-0026（审片台）、H17、UX 5.5、DATA-MODEL `Shot.promptNotes`

## 背景

审片台下带一直摆着一个输入框——"说哪里不对：太暗了 · 换个角度 · 她笑得太早了"——从 H17 做到现在都没接。界面在暗示一个能力，点了没反应，比没有这个框更糟。

讨论里早就把它的范围收窄过：**先解析"太暗了""换个角度"两条，接到重做报价**。今天没有文本模型接入，所以这件事不该假装成"自然语言理解"。

## 决策

1. **先做规则表，不冒充语义理解**：`parseInstruction(text, shot)` 是一个纯函数，覆盖七类说法（暗 / 过曝 / 换角度 / 靠近 / 拉远 / 手持 / 稳住）。说不认识就不认识，界面直说"没听懂"，不写事件、不花钱。
2. **能落到结构化字段的就落**：「换个角度」改 `camera.angle`（平视 → 仰拍 → 俯拍 → 平视），「靠近 / 拉远」改 `shotSize` 紧一档或松一档，「手持 / 稳住」改 `camera.movement`。
3. **落不到字段的进 `Shot.promptNotes`**：「太暗了」不是镜头结构，是一句对画面的补充要求。新增 `promptNotes: string[]`（zod 默认 `[]`），提示词里作为"补充：…"原样带上。老日志靠默认值补齐，`LOG_VERSION` 仍为 1。
4. **一次指令一条 `shot.updated`**：patch 里只放这次真的改了的字段（`shotSize` / `camera` / `promptNotes`），可回放；同样的补充不重复追加。
5. **界面上看得见改了什么**：镜号那一行显示景别与机位（"特写 · 平视"），锚点下方多一行「补充」列出已记下的补充要求；输入框回车或 ⌘⏎ 提交，成功才清空，失败的说明出现在舞台上沿。
6. **不动报价**：七类说法都不改时长，所以重做报价不变。等有了"快一点 / 慢一点"再接时长与报价。

## 理由

- **规则表可以验证**：每条说法对应哪个字段、写成什么字，测试能一条一条钉住；模型解析做不到今天这个确定度，还会把"她笑得太早了"编成一段假参数。
- **补充要求必须进 IR**：只放在界面状态里，刷新就没了，重放日志也还原不出来——"我明明说过太暗"会变成一场争论。
- **不重复追加**：同一句"太暗了"点两次，长两个一样的词，提示词会越来越吵。
- **看得见才会用**：改完只更新内部状态、界面不动，用户会以为没生效，然后一直点。

## 后果

**正面**
- 输入框从摆设变成动作：回车即改，改动可回放（`shot.updated`），刷新后补充要求还在。
- 提示词同源：`shotParts` 带上补充，首帧、尾帧、以后的视频提示词都跟着变。
- 测试：pipeline 五条（各条规则的字段走向、没听懂返回 null、补充进提示词且不重复）、store 两条（写一条 `shot.updated` 且界面状态跟着变、没听懂不写事件）、读模型一条（景别机位与补充进读模型）。
- 实测：输入"太暗了"回车 → 锚点行下方出现「补充 整体提亮，补足曝光，阴影保留细节」，事件多一条 `shot.updated`，刷新后还在；输入"换个角度" → 机位从平视变仰拍。

**负面**
- **只认七类说法**：写得随意一点（"这光不行"）就听不懂。这不是理解，是查表。
- **一个词只走一条规则**："太亮"和"太暗"同时出现时按先后匹配，语义上矛盾的话不做仲裁。
- **补充只增不减**：说了十次就记十条，没有"划掉某一条"的界面。
- **不接报价**：改景别、改机位都不改价，按钮上的价还是那么多。
- **锁定的镜头不能改**（与生成一致），要改先解锁。

**跟进**
- "快一点 / 慢一点"改时长，接重做报价。
- 补充要求的删除与编辑（点一下划掉）。
- 有文本模型后，规则表当兜底：模型给出的补丁必须先过同一套 schema 校验。
- 指令历史：现在只能从事件日志里看，界面上没有。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 直接调文本模型解析 | 今天没有可用的文本接口；而且"她笑得太早了"会被编成假参数 |
| 只改界面状态，不写事件 | 刷新即丢、重放无法还原；"我说过"没有证据 |
| 把"太暗了"写进 `description` | 描述是观众看到什么，不是对生成的要求；两者混在一起就分不开 |
| 指令直接触发重做生成 | 视频还没接通，而且改参数与花钱应该是两步 |
| 每一句都硬塞进提示词（不区分理解与否） | 提示词会变成垃圾桶，且用户不知道哪些话生效了 |

## 附记（2026-11-10）：补充要求可以划掉

原方案里「补充只增不减」是当时接受的代价。补上一条最小的回路：锚点上方每条补充是一个虚线小签，右侧一个 `×`，点一下写一条 `shot.updated { promptNotes: 过滤后的数组 }`，可回放。锁定的镜头不显示 `×`（与生成、指令一致）。仍然不能编辑某一条的字——要改就划掉再说一遍，避免出现"改了一半、说不清是哪个版本"的状态。

## 附记（2026-11-10）：快一点 / 慢一点

原方案的负面里写着"不接报价：七类说法都不改时长"。补上时长这一条：`parseInstruction` 现在也认快慢，一档 0.5 秒，最少 1 秒、最多 8 秒。

- **先说"太快 / 太慢"**：「太快了」是放慢，「太慢了」是加快，方向不能只靠字的先后猜。
- 能到边界的说法不硬改：已经 1 秒还说"快一点"、已经 8 秒还说"慢一点"，返回 null，走既有的"这句没改动什么"。
- 改的是 `Shot.durationMs`，写进同一条 `shot.updated`，可回放；**重做报价立刻跟着变**（时长 × 每秒单价 + 首帧）。
- **提示词不变**：时长是播放属性，不是画面内容，`buildKeyframePrompt` 不带它。预览里看不出快慢，看镜号行后面的秒数与「重做」的价格。
- 一次指令可以同时改时长和其它字段（"快一点，换个角度"），patch 里只放真的变了的。
