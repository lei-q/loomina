# ADR-0019 表演以关键帧与微动作为主，不做端到端表演生成

- 状态：已接受
- 日期：2026-11-09
- 决策者：用户 + Claude
- 关联：P18、P13、B3.1、PERFORMANCE.md

## 背景

分镜定下"拍什么"之后，还剩一个空档：**人在画面里怎么演、怎么动。**

当前视频模型的能力分布很不均匀：

- 静态外观与姿态：较好（参考图/首尾帧可控）。
- 微表情：弱，默认中性脸。
- 长动作与多人互动：差，容易漂移、穿模、换人。
- 视线：容易飘。
- 手部：经典短板。

如果按真人拍摄的思路写长表演、复杂调度，失败率会很高，成本不可控。

## 决策

**表演以"关键帧 + 微动作 + 反应镜头 + 剪辑"为主，不依赖端到端表演生成。**

具体：

1. 每个镜头有 `PerformanceSpec`：一个 objective、一个情绪转折、起/转/落三段 beat、显式 `GazeTarget`。
2. 首帧定情绪起点，尾帧定情绪终点，中间只做微动作与运镜。
3. 需要两段情绪时用"三帧法"，切两段生成、剪辑接起来。
4. 情绪翻译成**具体微动作**（下颌收紧、眨眼变慢、视线下移），而不是形容词。
5. 情绪越强，动作越小；一个镜头只做一件调度动作。
6. 台词镜头优先拍"听的人"；口型只在特写启用。
7. 超出模型能力的动作，拆段或改设计，不赌长镜头。

## 理由

1. **模型演不了"大"，但能演"准"。** 小动作的稳定性远高于大动作。
2. **关键帧是最便宜的控制点。** 在 image 阶段锁表情和姿态，比在 video 阶段反复抽卡便宜一个数量级（P4）。
3. **反应镜头用剪辑换表演。** 短剧本身就是快切，观众靠剪辑补全情绪。
4. **可量化、可 QA。** 有了 `PerformanceSpec`，才能判断"这段表演对不对"。

## 后果

**正面**
- 表演可控、可诊断、可重试粒度小。
- 与短镜头/覆盖率（P13）、关键帧优先（P4）天然一致。
- 竖屏构图与"脸+手+道具"的表演方式匹配。

**负面**
- 复杂情绪需要更多镜头数，剪辑与生成成本上升。
- 需要建立"情绪 → 微动作"的语法库并持续标定。

**跟进**
- 建立表演语法库（意图 → 可生成动作 → 避免项）。
- 表演 QA 接入一致性 QA 管线（B4/B14）。
- 用样片标定各景别的表演强度阈值。

## 替代方案

- **端到端表演生成（文本直接演）**：当前不可控、不可复现，放弃。
- **只靠运镜掩盖表演**：观众看的是脸，掩盖不了，放弃。
- **全程口型同步**：成本高、只特写有意义，降级为可选。
