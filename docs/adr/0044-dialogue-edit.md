# ADR-0044 台词改写：一条事件，时长重估，镜头跟着挪

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0011（事件日志）、ADR-0034（本地落库）、ADR-0043（剧本页）、PRINCIPLES P5、FEATURES A5

## 背景

ADR-0043 把剧本页做成只读。但台词是剧本里最常改的东西：一句太长、一句不顺、换一个字，都要能当场改。IR 里 `DialogueLine` 有 `text` 与 `durationMs`，可没有对应的事件类型；`shot.durationMs` 又必须与台词时长加余量对得上（不变量 `SHOT_DURATION_VS_DIALOGUE`）。只改文本不改时长，项目当场自相矛盾。

A5 原本写的是「人工覆盖层 + 触发下游提示词同步」，那是整块。这一轮只做最小的、可操作 UI 验证的一刀：**改一句台词，留一条事件，时长重估，镜头跟着挪**。

## 决策

1. **新增事件 `dialogue.updated`**：`{ type, at, lineId, patch: Partial<Pick<DialogueLine, "text" | "durationMs">> }`。只允许改文本与时长；说话人不可改——换人等于换一句台词，应当新增而不是覆盖。空文本、非正时长、找不到的台词，`applyEvent` 直接抛错。
2. **时长按字估**：`estimateDialogueMs(text)` 约 0.3 秒 / 字（不含空白），四舍五入到 0.1 秒，下限 0.8 秒。P5 说镜头时长服从配音，但 TTS 还没有；把旧时长留在那里装作还对得上，比估一个更糟。
3. **镜头跟着挪**：同一次保存里再写一条 `shot.updated { durationMs: shot.durationMs + Δ }`，只挪差值，不动别人写进去的表演余量。两条事件同一时间戳，一次 `applyEvent` 折叠——与「留用并锁」同一先例（ADR-0041 附记）。
4. **文本没变就不写事件**：只给一句「台词没改」。历史时长未必是按这个口径估出来的，不能顺手改掉。
5. **锁定镜头只读**：`shot.locked` 为真时拒绝改写（与指令、生成一致），提示先解锁。
6. **UI 在剧本页就地编辑**：每句台词旁一个「改」，点开是文本框 + 保存 / 取消，⌘↩ 保存、Esc 取消；保存后台词行与镜头技术行的时长同步变化，页头总时长跟着变。

## 理由

- **一次编辑一条事实**：文本与时长必须一起落地，否则回放到一半就违反不变量。
- **事件而不是快照**：改过哪句、改成什么，日志里查得到；A5 的「版本」先由日志兜底。
- **估时长要明说**：界面上写「按 0.3 秒 / 字重估」，配音落地后以音频为准。
- **两条事件一个动作**：已有先例，回放确定性由事件本身保证。

## 后果

**正面**
- 剧本页从只读变成可改台词：SH-01「你早就知道，对吧。」→「你早就知道了。」，台词 2.6s → 2.1s，镜头 3.1s → 2.6s，全片 32.6s → 32.1s 一屏可见。
- 日志里两条事件（`dialogue.updated` + `shot.updated`）带同一时间戳；刷新后改动还在，回放结果与界面一致。
- 测试：IR 55 条（新增 2 条：改写与重放、三种非法输入）；web 99 条（新增 4 条：时长估算、改写落事件与可回放、锁定拒改、空 / 未改不写事件）。

**负面**
- **时长是估的**：0.3 秒 / 字是示例项目的口径，不是配音实测；改了文本之后报价会跟着变，但真实成片可能要再对齐。
- **没有版本视图**：能翻日志，界面上还看不到「这句改过几次、上一版是什么」。
- **没做下游同步**：改台词不会重算分镜提示词、封面字幕、配音；A5 原本说的「触发下游提示词同步」还没做。
- **只能改文本**：说话人、台词条数（增删句）都不能在界面上改。
- **一条台词一条动作**：两句一起改会产生四条事件，不能批量。

**附记：事件白名单漏登记，整份日志被判废**
- 首次上机验证时，新事件写进了 IndexedDB，但 `event-log.ts` 的 `EVENT_TYPES` 是手抄的 `Set`，漏了 `dialogue.updated`。刷新后 `parseEvents` 判无效 → 当成第一次打开 → 用示例项目覆盖了整份日志（此前累计的定妆图、锁、关键帧事件全没了）。
- 修复：白名单改成 `Record<ProjectEvent["type"], true>`，事件联合类型多一种、这里少一行就编译不过；`Object.hasOwn` 判存在。补了一条回归测试，确认 `dialogue.updated` 能原样读回。
- 教训写在这里而不是悄悄修掉：**新增事件类型时，落库白名单与验收必须一起过**；「判无效就覆盖」是个伤人的兜底，但现在没有更便宜的替代——先让它编译期就不容易漏。

**跟进**
- A5 版本视图：按 `lineId` 折叠事件，给「上一版 / 改过几次」。
- 台词增删与说话人变更（新增事件类型）。
- 下游同步：改台词后标记分镜提示词、字幕、配音过期。
- 配音落地后，用实测音频时长替换估算。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 只改文本、时长不动 | 不变量当场破，报价与时间线全错 |
| 让用户手填时长 | 用户没有依据；估算至少给一个能对齐的起点 |
| 把时长重算塞进 `dialogue.updated` 的 `applyEvent` 里 | 隐藏耦合：事件本身看不出改了镜头，日志阅读与排查都更难 |
| 做成「台词覆盖层」表，与 IR 分离 | 现有 IR 已经是事实来源，再开一层必然分叉 |
| 这次连版本 UI 一起做 | 先把改得动做实；版本是读日志，下一刀不返工 |

## 附记（2026-11-10）：台词版本

ADR-0044 落地时留下的负面是「没有版本视图：能翻日志，界面上还看不到上一版」。这一刀把日志读出来。

**做法**
- 读模型加 `dialogueHistory(events, lineId)`：最初一版从 `project.created` 快照取，之后每条 `dialogue.updated` 是一版（带 `at`、新文本、估出的时长）；只改时长不换文本的事件不算一版。
- `previousDialogueText(history)`：改过一次就是最初那版，改过多次是倒数第二版的文本。
- 剧本页在台词下面折叠一行：`改过 n 次 · 上一版「…」`；展开是按时间倒序的版本列表（`20:18 你早就知道了吧。 2.4s`），最后一行 `最初`。
- 不另建版本表：日志已经是事实，版本是它的投影。

**验证**
- 测试：web 102 条（新增 3 条：最初一版与改写顺序、上一版两种情形、没改过与别人的改写不算）；`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：SH-01 连改两次 → `改过 2 次 · 上一版「你早就知道了。」`，展开见 `20:18 / 20:15 / 最初`，时长 2.4 / 2.1 / 2.6s；镜头与全片时长同步变化（2.9s / 32.4s）。

**负面**
- 版本列表只有文本与时间，没有作者与操作类型；回退（改回上一版）要自己重新输入。
- 只认 `dialogue.updated`；以后若出现「只调时长」的事件，它不会出现在列表里。
- 时间显示到分钟，同一分钟内的两次改动看不出先后。

## 附记（2026-11-10）：用回某一版

台词版本的下一步是回退。不新增事件类型：回退也是一次改写。

**做法**
- `DialogueHistory.original` 从字符串改成 `{ text, dur }`：最初那版的时长在引导事件的快照里，回退要连它一起还原，不能按字数重新估。
- store 抽出 `commitDialogue`（`dialogue.updated` + 时长变化时的 `shot.updated`），`editDialogue` 与 `restoreDialogue` 共用：前者只比文本、时长按字数估；后者连时长一起写回、文本与时长都与现值相同才算「没改」。
- 剧本页的每一版（含 `最初`）后面一个「用这版」；与当前文本相同的行置灰。回退成功不换 URL、不跳页，列表里多一条新版本。

**验证**
- 测试：web 103 条（新增 1 条：回退还原文案与当时时长、镜头挪回原位、可回放、重复回退不写事件）；`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：SH-01 两版之后点「最初」的「用这版」→ 台词 2.6s、镜头 3.1s、全片 32.6s，列表变成 `改过 3 次`，最新一行是 `20:23 你早就知道，对吧。`，与「最初」两行的按钮同时置灰。

**负面**
- 回退是「追加一条」而不是「抹掉」：列表会越来越长，与当前文本相同的旧版本仍留在日志里。
- 只按文本判断「已经在这一版」：若同一句文本但时长不同，按钮也会置灰。
- 回退只影响台词与所属镜头时长，不会把配音、字幕、已生成的 take 一并退回。
