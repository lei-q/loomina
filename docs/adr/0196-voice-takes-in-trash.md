# ADR-0196：废片库补上配音 take（C14 第四档）

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：C14、C9、C21、ADR-0124、ADR-0193

## 背景

C14 的废片库（ADR-0193）收了视频 take 与关键帧旧版，但**配音 take 还不在里面**。
试听台删一版（`voice.take.removed`）之后：

- 资产还在项目里（removeVoiceTake 明确不删资产），但界面上没有入口再找到它；
- 配音按字计费，删掉的那一版也是花了钱的；
- 用户 C.2 要求「淘汰或覆盖也不删，之后可取回」。

## 决定

1. **废片库多一种 `voice`，状态只有 `removed`**
   - `trashOf(project, events)` 扫 `project.created` 与 `voice.take.added` 记下原记录，
     扫 `voice.take.removed` 记下删除时间；项目 `voiceTakes` 里已经没有、
     资产与台词都还在的，才列出来。
   - 每项带：哪一镜（有的话）、台词原文、时间、原音轨、模型；
     没有对应镜头的台词写「配音」。
   - 资产没了 / 台词没了的不列：点不动的空卡片比没有更糟。

2. **取回 = 按原记录重新 `voice.take.added`**
   - `restoreVoiceTake(takeId)` 从日志找回原 take（先看 `project.created`，
     再看 `voice.take.added`），写一条新事件把它放回试听台。
   - **不自动采用**：台词当前音轨（`dialogue.audioAssetId`）不动；
     作者要去配音页点「用这版」才换成它。删除时「正采用的不能删」这条规矩，
     在恢复时不能反过来变成「恢复就采用」。
   - 不重新配音、不花钱、不复制字节；readOnly、配音阶段闸门、
     已存在、找不到、台词 / 资产缺失都拒绝。

3. **界面仍在那一个「废片库」区**
   - 缩略位写「音」，标签写「配音」，描述显示台词原文；
   - 按钮「取回」（关键帧才是「换回」），点完提示
     「回到试听台，不会自动采用；要用再去配音页点『用这版』」。

## 理由

- **同一种钱、同一种簿**：视频、关键帧、配音都是生成出来的花费，
  废片库按同一种方式列出来，作者不必记「哪种废片去哪找」。
- **恢复与采用分开**：恢复只是让这一版重新可选；自动采用会悄悄改掉当前音轨，
  与「删除时不许删正采用的」自相矛盾。
- **仍不新增事件类型**：`voice.take.added` 本来就允许同一个 id 在删除后重新加入，
  日志天然可重放，不需要「反删除」。

## 后果

**正面**

- 试听台删掉的配音能在资产页看见、点回来；不重新配音、不花钱。
- 配音与视频 / 关键帧共用一套废片口径与界面，不用记两套规则。

**负面 / 代价**

- 取回只回到试听台，不恢复「当时是否被采用」；作者要自己再点一次。
- 不恢复台词音轨的时长校正、表演参数之外的状态（表演参数本身在 take 里，会跟着回来）。
- 恢复后没有「这一版取自哪次删除」的对比视图；日志里能查，界面上没有。
- 日志被压缩掉 `voice.take.added` 后，那一版就找不回来了。
- 废片库计数把视频、配音都算进「删掉」，没有分种类统计。
