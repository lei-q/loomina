# ADR-0180：班底模板（F3）

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：F3、H14、A7、B15、H3、H9、H18、ADR-0009、ADR-0034、ADR-0088、ADR-0128、ADR-0174、P2、P7

## 背景

F3「模板复用」一直是一行字：「项目模板、镜头模板」。而实际做短剧的人，
第二集开始真正重复的是**同一套人、同一个走廊、同一套落款**——
每开一集都要重新建人物、贴定妆图、重配画幅与品牌包，十几分钟全花在复制上一集。

项目里已经有几种「模板」，但都不是这一层：

- A7 模板剧本：给的是**故事开头**（六条室内、少人、对话驱动的钩子），不给人；
- B15 场景模板：给的是**一个地点的几何**，不给整个班底；
- I5 / B7 风格预设：给的是**画面参数**，已经是 `Project.look`，只是不会跨项目带走。

缺的是「把这一集的班底存下来，下一集直接开工」。

## 决定

1. **模板 = 班底，不等于项目**
   - 带走：人物（含 `sheet` 四格与参考图 id）、地点、道具、它们引用到的资产记录、
     `look` / `grade` / `frame` / `brand`。
   - 不带：故事、场景、镜头、台词、take、时间线、闸门、发布记录、授权记录。
   - 理由：模板回答的是「还是这批人、还是这个地方」，不是「第二集讲什么」。
     把故事带过去会让作者第一件事就是删掉上一集的分镜。

2. **模板只存地址，不复制素材**
   - `assets` 里只保留人物 / 地点 / 道具直接引用的那几条（`castAssetIdsOf`），
     `uri` 原样（`loomina://` / `s3://` / `data:`）。
   - 内容寻址让同一张定妆图在两个项目里是**同一份文件**：开工不该花一次复制，
     也不该让磁盘翻倍。

3. **模板住本地 IndexedDB 的 `templates` 仓，不进事件日志**
   - 库 `loomina` 升到第 3 版，多一个 `templates` 仓（主键 `id`）；事件与 meta 两仓原样保留。
   - **不进日志**：模板不是某个项目的历史。写进日志会让每个项目的回放多一条
     与它无关的记录，也会让「删掉模板」变成一条要保留的创作事实。
   - 读回来的东西先过 `looksLikeTemplate` 再交给界面：旧版本写的、手改坏的数据
     宁可当没有，也不让设置页崩掉。

4. **开工 = 一条新的 `project.created`**
   - 与「从故事开工」「逐字导入开工」同一个写法（ADR-0088）：日志末尾追加，
     旧项目仍留在本地，界面只从这一条开始回放。
   - `projectFromTemplate` 走 `ProjectSchema.parse`：模板可能是几个月前存的，
     缺省字段靠 schema 补齐，与旧日志回放同一个规矩。
   - 片名用一个输入框问（默认「模板名」）；不传或空白就用模板名。

5. **界面在设置页「班底模板」区**
   - 一行摘要：当前项目 `N 人 / M 地点 / K 道具`。
   - 「把现在的班底存成模板」：名字默认 `片名 · 日期`。
   - 「存下的模板」列表：名字、班底数、从哪个项目来、日期；每行「用这个开工」「删」。
   - 开工后跳到 `/cast`：先确认脸对不对，再去写故事。

## 理由

- **按「跨集重复的东西」划模板边界**：重复的是人、地方、质感、落款；
  故事与分镜恰恰是每集最不该重复的部分。
- **只存地址是内容寻址的自然结果**：复制素材会让「同一张图」变成两份，
  以后清理孤儿、日志压缩、跨项目白名单全都要重新处理「看起来一样的两份」。
- **不进日志**：模板是工具不是创作事实；它也不该被撤销 / 回滚影响
  （在 A 集里撤销几步，不该把 B 集开出来的模板一起撤掉）。
- **新库版本只为多一个仓**：`openDb` 已经在 `event-log.ts` 里，升级路径只有一处；
  这是 ADR-0034「本地只有一个库」的延续，避免为模板再开一个 IndexedDB。
- **开工复用既有写法**：不新增事件类型、不改 IR，`rebuild` 与闸门全都不用动。

## 后果

**正面**

- 第二集开工从「重建十几样东西」变成点一下；实测：存模板 → 刷新仍在 → 填片名开工，
  新项目 `2 人 / 3 地点 / 2 道具 / 14 个资产`，`scenes 0 / shots 0` 从零开始。
- 模板与项目解耦：删模板不影响正在用的项目；项目被重置也不影响模板。
- 不增加 IR 实体，不增加事件类型，`LOG_VERSION` 不变。

**负面 / 代价**

- **模板只在这台浏览器**：换机器、清缓存就没了；H9 的数据包也只导当前项目，
  不含模板（以后要的话得单独导）。
- 模板不带镜头模板（F3 原文里的「镜头模板」没做）：景别 / 运镜 / 光影这套
  已经有 I1 / I2 / I4 的模板，跨项目复用要先设计「镜头级模板」的载体。
- 模板里的资产地址可能失效（库里文件被清掉）：开工后定妆页会显示文件缺失，
  与正常项目遇到的情况一样，不额外处理。
- 同名模板不合并：存两次就是两份，作者自己删。
- 模板里的 `id` 不重新生成：人物 / 地点 / 道具 id 原样带进新项目。
  同一个浏览器里两个项目的 id 会重合，但目前它们互不相干（日志按段回放），
  真要合并项目时得先设计 id 映射。

**不做**

- 镜头模板、场景模板（B15 已有）、故事模板（A7 已有）。
- 模板的编辑（改名 / 增删其中的人）：这一版只有「存 / 开工 / 删」，
  要改就重新存一份。
- 模板的导出 / 导入 / 同步、模板市场。
- 从模板开工时保留上一集的预算与模型固定（用当前项目的预算，模型跟本机默认走）。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 模板 = 整份项目副本 | 故事与分镜跟着过去，作者第一件事是删；也说不清「模板」和「另存为」的区别 |
| 把模板写进事件日志 | 每个项目回放都多一条无关记录；删模板也要留痕；撤销语义混乱 |
| 模板复制素材字节 | 同一张定妆图存两份，磁盘翻倍，清理要处理「看起来一样的两份」 |
| 模板只存人物名与描述，不带图 | 班底的核心就是那张脸；没有图的模板等于重新生成，等于没复用 |
| 新建一个 IndexedDB 库 | 两个库、两套升级、两套错误处理；ADR-0034 的「本地只有一个库」没必要破 |
| 在故事页加一个模式 | 故事页已经有生成 / 逐字 / 模板剧本三种模式，再加一种会让「开工」这件事更绕 |
| 开工时保留上一集的预算与模型 | 预算属于项目约束（P14），新一集该按当前设置来；读上一集的数反而意外 |
