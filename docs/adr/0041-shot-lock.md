# ADR-0041 镜头锁定：能点了

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0028（定妆闸门）、DATA-MODEL（`shot.locked`、`take.updated`）、ADR-0037 / 0039、H17

## 背景

`Shot.locked` 早就在 IR 里，读模型、审片台、生成、一句话指令全都照着它做只读处理——**唯独没有地方能把它打开**。示例项目里锁着的镜头是种子数据写进去的；真实项目里锁定是一段没人能走进去的分支。

DATA-MODEL 写过："锁定的镜头在审片台只读；要改必须先解锁，解锁本身要留痕。"同一条 `shot.updated` 事件就是留痕的地方，缺的只是入口。

## 决策

1. **锁定是"这一镜定了"**：只有已经留用过一条 take 的镜头才可以锁。没有 take 就锁，会把一个空白镜头冻住——生成按钮消失、一句话指令不可用，而这正是用户要做的事。
2. **一次一条 `shot.updated { locked }`**，锁与解锁都写。不解锁不留痕的分裂状态。
3. **界面上是下带的第四个动作**：「留用」右边一个描边的「锁定」，不可锁时置灰并在 `title` 里说清原因（"先留用一条 take"）。
4. **锁住之后**：动作整排换成「已锁定 · 只读」加一个「解锁」；舞台按钮变成"镜头已锁定 · 只读"；一句话指令输入框禁用；补充的 `×` 不显示。
5. **解锁不弹确认**：解锁本身可回放、可再锁；弹窗只会让这道闸门变成一次点击就能拆的纸门。

## 理由

- **闸门要有入口**：只读分支没有入口，等于这个状态只存在于种子数据——工程上"实现了"，产品上不存在。
- **先留用再锁**：锁定表达的是"这条 take 就它了"，没有 take 的锁定只是在赌气。
- **同一条事件**：项目结构的变化只走 `shot.updated`，不新增事件类型，重放天然一致。
- **不弹确认**：确认框拦不住误点，只会多一次点击；留痕 + 可解锁才是真的可恢复。

## 后果

**正面**
- 锁定从数据变成动作：留用 → 锁定后，分镜页的生成 / 指令 / 补充全部只读，下带只剩「解锁」。
- 实测：留用 SH-03 后点「锁定」，动作排换成「已锁定 · 只读 / 解锁」，舞台按钮变"镜头已锁定 · 只读"，输入框禁用，事件多一条 `shot.updated{"locked":true}`；点「解锁」恢复原样，事件再多一条。
- 测试：store 三条（没留用不许锁、锁与解锁都留痕且可回放、锁定后拒绝生成与指令）；web 82 条通过。

**负面**
- **留用会把选中挪到下一格**（既有行为），所以刚留用的镜头要回到胶片轨上再点锁定——多一次点击，体验上有点绕。
- **锁定只锁单镜**：没有"整段锁定"或"锁到某一阶段"。
- 解锁后没有任何提示说明这条镜头曾经锁过；要看历史只能翻事件日志。
- 锁定与定妆的 `approval.updated` 是两套机制：前者在 `shot.updated` 里，后者有独立的 Approval 表。将来做"锁定 = 确认"的统一账本时，这两处要合并考虑。

**跟进**
- 留用后不下移选中（或留用即锁定的一键动作）。
- 胶片轨上给锁定镜头一个可见的锁标。
- 锁定镜头的历史提示。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 任何时候都能锁 | 能锁住一个空镜头，把用户要做的下一步藏起来 |
| 锁定写成 `approval.updated` | 那是定妆资产的闸门，目标类型不同；混进去会让 `castReadiness` 算错 |
| 解锁弹确认 | 拦不住误点，多一次点击；可回放才是恢复手段 |
| 只有一个"锁定"开关，不区分留用 | 用户要能表达"这一镜定了"和"这条 take 好"两层意思 |

## 附记（2026-11-10）：留用并锁，一个按钮

原方案的负面里写着"留用会把选中挪到下一格，刚留用的镜头要回到胶片轨上再点锁定——多一次点击"。补上一条最小回路：**同一个「锁定」按钮，在最新 take 还不是 `approved` 时改叫「留用并锁」**，点一下写两条事件——`take.updated { status: "approved" }`，再 `shot.updated { locked: true }`，顺序固定、都可回放。已是 `pick` 的镜头按钮仍叫「锁定」，只写一条 `shot.updated`。

- 没有 take 的镜头仍然不可点，悬停里说"先留用一条 take"（锁定必须有留用的 take，这条不放松）。
- 动作结束后选中照常挪到下一格还没定的镜头——与「留用」一致；定下来的镜头不挡路。
- 不解锁就不撤销：`take.updated` 已经写进去了，恢复原状要自己解锁、再改 take 状态。这是"一步动作 = 两条事实"的代价，换来的是回放时两条都在。
- 「留用」按钮仍然单独存在：只想留用、不锁的流程不受影响。
