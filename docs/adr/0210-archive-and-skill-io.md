# ADR-0210：空间归档与技能导入导出（C15 / C18 小补）

- 状态：已采纳
- 日期：2026-11-14
- 决策者：用户 + Claude
- 关联：C15、C18、A6、ADR-0188、ADR-0201、ADR-0202、ADR-0209

## 背景

两处收口时留下的「未做」：

- **C15**：删工作空间（ADR-0201）之后，列表里只剩「留着」或「彻底删掉」；
  试完不想留、但又不想删的集没有去处。另外删掉的 id 被直链打开时静默退回默认空间。
- **C18**：技能跨空间取（ADR-0202）只覆盖本机；换机器、备份、给同事都没有出口。

## 决定

1. **空间归档（`WorkspaceMeta.archivedAt?: string`）**
   - 归档 = 从主列表隐藏，事件日志、素材引用一律不动；随时可「取消归档」。
   - 归档的空间**不进**跨空间取用清单（C16 / C20 / C21 / C22 / C23 / C24）、
     **不进**连载概览（A6）：归档的语义是「这一集先放一边」。
   - 归档用两步确认（与删除同一套「先点一下、再确认」），因为它会改变列表可见性。
   - 当前正在打开的空间不能归档（与不能删除同一条理由：写锁与内存项目还挂着）。
2. **直链兜底**
   - 记住的空间 id 在 `hydrate` 时如果读不出日志，**退回默认空间**并写一句
     `storageError`：「上次打开的工作空间找不到了，已回到默认空间。」
   - 不做「自动新建一个空空间」：那是猜，猜错比退回更糟。
3. **技能导入 / 导出（文件）**
   - 导出：一个 JSON 文件 `{ format: "loomina.skills", version: 1, skills: [...] }`，
     只含名字 / 说明 / 阶段 / 内容 / 启用状态，**不带 id 与 createdAt**（换机器要重编）。
   - 导入：读文件 → 逐条 `ProjectSkillSchema` 校验（id 重编、createdAt 用现在、
     默认按文件里的启用状态）→ 走 `project.updated { skills }` 一次写一批。
   - 判重与跨空间取用同一口径（名字 + 内容都 trim 后相同），已存在就跳过并计数。
   - 文件上限 200 KB、最多 100 条；超了如实拒绝，不截断。
4. **不做**
   - 不做云端同步、不做空间级权限、不做批量导入多个技能包。
   - 不做「归档 = 冻结」：归档的空间仍可打开、仍可编辑。

## 理由

- **归档是可见性，不是数据操作**：删掉太狠、留着太吵，中间态就是隐藏；
  不碰日志意味着随时可逆，也不影响任何引用。
- **归档不进复用清单**：作者把它收起来就是不想它出现在「从别的空间取」里；
  把它留在清单里等于「归档了还在眼前」。
- **技能文件不带 id**：id 是本机生成的，带过去只会撞车；
  导入时重编，与 C23 / C24 跨空间取用的口径一致。
- **直链兜底不猜**：静默退回默认空间 + 一句人话，比自动建空空间更容易理解。

## 后果

**正面**

- 试验集可以收起来而不删，列表与复用清单都干净。
- 技能可以导出备份、换机器带走；导入时坏数据逐条拒绝、不污染项目。
- 直链失效不再无声无息。

**负面 / 代价**

- 归档只在这台浏览器里生效（与集序同一限制）。
- 归档的空间仍占 IndexedDB 空间，也不会被「清理没人引用的文件」特殊对待。
- 技能导入不做跨文件合并策略：一次只导一个文件，同名同内容跳过、其余追加。
- 导出不含 id，重新导入后原有引用（没有引用技能的地方）不受影响，
  但「这条技能从哪来」的记录没有了。
- 直链兜底会静默切换空间；作者如果没注意 `storageError`，可能以为数据没了。
