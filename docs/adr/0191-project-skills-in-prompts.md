# ADR-0191：项目技能——可复用的提示词要求（用户清单 C.5 / 功能 C18）

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：C.5、C18、B7、I5、ADR-0148、ADR-0165、ADR-0190

## 背景

用户要「支持集成 skill，通过 skill 生成提示词或指导模型完成特定任务」。
现状是：作者的固定要求（「不要出现现代物品」「雨夜质感」「只要老式钨丝灯」）
只能每次手改提示词，或者重复写进每条描述里；改提示词又不写进项目，
刷新、换设备、回放都不在。

## 决定

1. **技能 = 项目里的一条提示词要求**
   - `Project.skills: ProjectSkill[]`，字段：`id`、`name`（≤40）、`description`
     （≤200，只给人看）、`stage`、`body`（≤2000，真正进提示词的那段）、
     `enabled`、`createdAt`。
   - 写进 IR 而不是 localStorage：技能会改变出图提示词，属于项目约束（准则 P2），
     刷新、换设备、回放日志都得在。
   - 事件复用 `project.updated { skills }`，**整块替换**（与 `look` / `grade` /
     `frame` 同一套做法）；校验 id 不重复、字段长度、阶段枚举。

2. **阶段决定加在哪一类提示词后面**
   - `stage`：`all` / `sheet`（定妆）/ `master`（主镜）/ `prop`（道具）/
     `keyframe`（关键帧）。`all` 与同阶段生效；`enabled: false` 只是不加，不删记录。
   - `packages/pipeline/src/skills.ts`：`skillsForStage` 负责筛选，
     `compileSkills` 按作者排的顺序拼成
     `技能「名字」：内容；技能「名字 2」：内容`。
   - 拼在**风格那句之前**：`look` 编译出的最后一句始终是提示词的最后一句
     （B7 / I5 / ADR-0165 的既定约定）。作者以句号结尾时去掉末尾句号，
     避免与提示词分句的连接符叠成「。。」。

3. **四条出图路径都走同一份函数**
   - `buildSheetPrompt` / `buildMasterPrompt` / `buildPropPrompt` /
     `buildKeyframePrompt` 各多一个可选 `skills` 参数；不传时输出与原来逐字节相同。
   - 浏览器里的「提示词 · 可改」预览、真实请求、服务端 `/api/asset` 解析后
     用的都是同一份编译函数——预览看到的就是要发出去的。
   - `/api/asset` 用 IR 的同一套 schema 再校验一次，最多 20 条；
     手改过提示词（ADR-0148）时以手改版为准，技能不再拼进去。

4. **界面放在设置页「技能」**
   - 列表显示生效状态、名字、阶段、说明与正文；「生效中 / 已关」一键切换；
     「删」只从当前项目移除（事件日志仍留着历史）。
   - 新建表单：名字、阶段、说明、正文（带字数）；只读窗口全部禁用。
   - 已经出的图不会因为加技能自动重做；界面明写这一点。

## 理由

- **技能是数据不是代码**：作者要的是「这条片子的规矩」，不是装插件。
  进 IR 才能跟着项目走，也才能解释「这张图为什么是这么生成的」。
- **按阶段分**：定妆要棚拍口径、关键帧要构图与光线，同一条要求往往只适用于其中一类；
  一刀切会污染不该改的提示词。
- **整块替换**：技能顺序有意义（谁在前谁先被模型读到），增删一条就写整份，
  回放时不会出现「中间态」与最终提示词对不上。
- **预览与请求同一函数**：这是 ADR-0148 的延续；技能如果只在服务端拼，
  作者就看不到自己写的要求有没有生效。

## 后果

**正面**

- 固定要求写一次，所有后续出图都带；换项目、换设备、回放都在。
- 预览当场能看到技能拼进去的位置（风格之前），关掉后预览立刻消失。
- 不传技能时四种提示词逐字节不变，旧项目与旧测试不受影响。

**负面 / 代价**

- 技能只是「提示词片段」，不会自己执行任务、不调模型、不校验输出；
  真正的「让模型按技能跑一个流程」还没有。
- 没有技能库的导入 / 导出 / 跨项目共享，也没有版本对比；
  要复用只能手动再写一遍（跨空间复用实体见 ADR-0190，技能不在其中）。
- 同一阶段的多条技能按数组顺序拼接，长技能会挤占提示词长度；
  目前只有单条 2000 字上限，没有总量上限与冲突检测。
- 手改过提示词时技能不生效，作者需要自己把手改版恢复默认才能重新带上技能。
