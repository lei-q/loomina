# ADR-0161：爽点密度曲线与逐场节奏诊断

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：A2、A18、A15、ADR-0123、ADR-0147、准则 P15

## 背景

A18 的剧本医生给了一张 12 维报告：钩子、前提、拍密度、反转、台词效率……每一项回答的是「结构上缺不缺」。但短剧作者真正盯着改的是另外两件事：**这一分钟的爽点够不够密、这一场是不是太慢或太平**。A2 要的就是这两块：爽点密度曲线、节奏诊断与逐场改写建议，按短剧语法而不是三幕套话。

A18 已经能点模式让模型改写，但模型改写贵且慢，不能当「扫一眼」的工具。作者需要的是打开抽屉立刻看见：兑现集中在哪几段、哪一场平均镜长拖了后腿、这一场该加哪一种动作。这些都能从现有分镜、拍子与台词里算出来，不需要再调一次模型。

## 决定

1. **在 `apps/web/lib/script-doctor.ts` 里加纯函数，不新建模块。** 曲线与节奏是同一份 `analyzeScript(project)` 报告的延伸，共用镜头计划、拍子与台词；拆成第二份报告会让作者在抽屉里读两个互相不知道对方的结论。
2. **一镜的兑现权重 = 拍子权重 + 目的加成 + 兑现词数。**
   - 拍子：hook 1.5、setup 0.5、escalation 1.5、turn 2.5、climax 3、endHook 2；resolution 不计。
   - 目的：`emotion` / `reaction` 加 1。
   - 词：动作与台词里命中「打脸、反转、揭露、真相、反击、拒绝、跪下、道歉、当场、揭穿、夺回、翻盘……」各计 1，单项最多 3。
   - 词表故意不放大「不是」「原来」这类高频词，避免每句话都被算成爽点。
3. **曲线按约 5 秒一段、最多 18 段。** 每段取落在段内的镜头权重合计，按全片最高段归一到 0–100；给峰值段一个秒数标签。全片没有镜头或没有权重时 `flat: true`、`windows: []`，**不画一条假波形**。
4. **逐场诊断看三件事：均镜长、镜头数、兑现合计。**
   - 没有镜头 → `flat`，「先拆成 1–3 个能拍的镜头」。
   - 均镜长 ≥ 5 秒 → `slow`，「把解释压成一个动作，或拆出反应镜头」。
   - 均镜长 < 1 秒 → `rushed`，「给关键动作留一个反应镜头」。
   - 有镜头但兑现为 0 → `flat`，「加一次拒绝、揭露或反击」。
   - 其余 → `issue: null`，「节奏与爽点都正常；优先改别的场」。
5. **界面放在剧本医生抽屉「十二维」之后、「发现」之前。** 曲线用一排色块，峰值段标秒数；每场一行显示时长 / 镜数 / 均镜长 / 兑现权重、问题签与一句建议；「去这一场」跳到该场第一镜（沿用既有的 `onSelectShot`，关闭抽屉并滚到那一镜）。
6. **只提示，不写 IR、不进事件、不阻断生成。** 和 A18 一样，报告是当前项目的派生结果，改一镜就重算；曲线与节奏不是剪辑标准，界面明写「快慢要跟着戏走」。

## 理由

- **短剧的「爽」有可观察的形状**：打脸、揭露、反击、认亲这些动作能被词表认出来；高潮拍的权重天然高于铺垫。用规则算出来，作者看得懂、能反驳，也能自己决定不改。
- **不调用模型**：打开抽屉就出结果，零成本、可离线、可测试；模型改写仍然留给 A18 第二档，前者负责「看哪里」，后者负责「怎么写」。
- **不新增 IR**：权重、曲线、均镜长都是镜头与拍子的函数，存下来只会多一份失效机制；项目回放后自动一致。
- **与 A18 共用一份报告**：12 维说「hook 偏弱」，曲线说「钩子之后 20 秒没有兑现」，节奏说「第 2 场均镜长 4.2 秒」——三句能对得上，作者才知道先改哪。
- **flat 不伪造**：没有镜头就直说画不出来，避免一条全零曲线被误读成「节奏很稳」。

## 后果

**正面**

- 作者能在剧本页直接看见兑现分布与拖后腿的场，改一镜就重算。
- 「去这一场」把诊断和修改连起来，不用自己找镜号。
- 纯函数、零依赖、零调用；旧项目打开就能用，不迁移、不补字段。
- 规则与边界都有单测：权重随拍子 / 兑现词上升、无镜头不画曲线、偏慢 / 偏碎 / 偏平三种结论各有断言。

**负面 / 代价**

- 词表是人工维护的：反讽、语气、画面外的信息它看不见；不同题材的黑话可能漏判。
- 均镜长阈值（1 秒 / 5 秒）是通用经验，不按题材、平台或镜头景别校准；快切动作片会被判「偏碎」。
- 5 秒一段的粒度回答不了「第 37 秒那个反转够不够响」；峰值只说明权重高，不说明拍得好。
- 曲线和 12 维可能给出重复提示（反转过少既扣分也在曲线上显平），作者要自己合并判断。

**不做**

- 模型打分、模型自动改剧本、按曲线自动重排镜头。
- 把权重、曲线或节奏结论写进 IR、事件日志或导出前的硬闸门。
- 按题材 / 平台 / 景别校准阈值，或做评测集标定。
- 爽点历史趋势、跨项目对比、A/B 测试。
- 自动补镜、自动改时长、自动生成反应镜头。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 让文本模型读一遍给爽点打分 | 每开一次抽屉就花一次钱、结论不可复现，也解释不了「为什么这一段平」 |
| 单独建 `payoff-report.ts` | 要重复解析镜头、拍子与台词，还和 12 维报告各说各话 |
| 按镜画曲线而不是按时间 | 一镜 5 秒和一镜 1 秒会占同样宽度，看不出观众实际等多久 |
| 把曲线写进 IR 或事件 | 它是当前剧本的函数，存下来要配失效与迁移，没有跨会话引用价值 |
| 均镜长一刀切「越短越好」 | 短剧也有停顿与反应；只标偏慢 / 偏碎，把判断留给作者 |
| 自动按诊断改镜头 | 改写是创作决定；A18 第二档也只给建议，点「采用」才落事件 |
