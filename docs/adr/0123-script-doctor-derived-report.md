# ADR-0123：剧本医生报告是派生的，改写建议要人点「采用」

- 日期：2026-11-11
- 状态：已采纳
- 关联：A18、A2、A15、A16、A11、A12、ADR-0017、ADR-0088、ADR-0104、ADR-0118

## 背景

STORY.md 第七节把剧本医生定义成「结构诊断 + 定向改写」：12 个 1–5 分的维度、9 条触发条件、6 种改写模式。ADR-0017 把它列为故事层的一等公民，ADR-0088 落地 Story Bible 时明确**没有**把它放进 IR，理由是「需要各自的评分标定，先不造空壳」。

现在手上已经有一批可读的事实：`scoreLogline`（A15，本地六维）、`Project.story` 的弧光与关系（A16）、`groupBeats` 的节拍与覆盖率（A11 / A12）、`validateStoryboard` 的 V1–V11（A13）。剧本医生缺的不是数据，是**把数据读成诊断**的那一层。

同时有两个坑要先避开：

1. **报告存进 IR 会过期。** 分数是当前剧本的函数，改一句台词就该变。存下来就得配一套失效机制（像闸门的内容指纹那样），而它并不比现算便宜。
2. **「不达标就重写」不能做成墙。** 9 条触发条件里有 8 条是启发式判断，全部硬拦会把主路径堵死，违反 P14（闸门设在昂贵步骤之前，不设在便宜步骤之后）。

## 决策

### 1. 报告是纯函数，不进 IR

`packages/pipeline/src/script-doctor.ts` 新增：

```ts
analyzeScript(project: Project, options?: { loglineScore?: LoglineScore }): ScriptDoctorReport
```

与 `analyzeStoryboard` / `analyzeConsistency` 同一类：只读、可单测、不写事件。界面每次打开抽屉现算，改一个字立刻变。

### 2. 12 维里 10 维本地可算，两维如实标未测

| 维度 | 来源 | 读什么 |
| --- | --- | --- |
| hook | local | 首镜是否 `beat: hook` 且 ≤3s；前 15 秒内有无 turn / escalation |
| premiseClarity | local | 复用 `scoreLogline` 的冲突 / 代价两维 |
| desireObstacleStakes | local | `story.arcs` 的 want / need / flaw 填写率 + 有无张力关系 |
| beatDensity | local | `groupBeats` 的拍数 ÷ 总秒数（< 1/20s 触发） |
| reversal | local | 有无 turn 或 climax 拍 |
| characterAgency | local | `arcs[].agency` 填写率 + 主角是否出场 |
| relationshipTension | local | 关系数、`tension` 非空率 |
| dialogueEfficiency | local | 平均字数（> 15 触发）、单镜 > 2 句的镜数 |
| emotionalPayoff | **model** | 需要模型判断，第一版标「未测」 |
| endHook | local | `story.hooks.ending` 非空 + 末拍是 endHook |
| feasibility | local | 场 ≤ 3、人 ≤ 5、镜 ≤ 14、总时长 60–180s |
| originality | **unmeasured** | 等 A8（相似度检查） |

每个维度带 `source: "local" | "model" | "unmeasured"` 与 `score: number | null`。**没算出来的不写 0 分**——0 分是「很差」，未测是「不知道」，两者在界面上必须分开（与 ADR-0033「未知不是免费」同一条原则）。

hook 这一维要写清楚它是**结构代理**，不是审美判断：它只回答「开场是不是一个钩子、够不够短」，回答不了「这个钩子抓不抓人」。界面上这句原话要写出来。

### 3. 不设硬闸门，并入剧本闸门的可豁免缺口

ADR-0118 已经建好「可豁免缺口」这个机制。剧本医生的 warn 级发现直接进 `script` 阶段的 `waivable`：确认弹层里列出「剧本医生：3 项偏低」，作者勾「我知道」才能带条件确认。

`block` 级留给真正的结构错误（没有场次、没有镜头），这些现在由分镜闸门的 `missing` 承担。**DATA-MODEL 里不变量 17 / 18 的硬拦口径改为「并入闸门可豁免缺口」**，理由与 ADR-0118 相同：分数是启发式的，不该拥有否决权。

具体改法：`readinessOf("script")` 的 `waivable` 数组补一条「剧本医生：n 项偏低」，现有 `GateConfirm` 的勾选框与 `gate.confirmed { override: true }` 已经能承接，不需要新事件。

### 4. 6 种改写模式：第一档给本地建议，第二档才调模型

| 模式 | 目标 | 落地方式 |
| --- | --- | --- |
| 强化钩子 | 首镜 / 首拍 | 第一档：指出首镜时长与目的，给改写方向；第二档：模型重写这一镜描述与首句台词 |
| 加反转 | 25–40s 处 | 第一档：指出该位置落在哪一拍；第二档：模型给一个认知变化方案 |
| 删解释 | 台词效率最低的 3 句 | 第一档：列出超长句；第二档：模型改写成行动或更短的对白 |
| 锐化冲突 | 张力最弱的一对关系 | 第一档：指出关系；第二档：模型重写 `tension` |
| 减人物 / 减场景 | 结构 | **只建议，不自动删**：删实体牵动镜头、台词、take，工具不替作者做 |
| 重写结尾 | 末拍 / endHook | 第一档：指出末拍；第二档：模型重写结尾钩子 |

第二档走 `POST /api/doctor`：一次调用、一个模式、一个目标，返回**建议**（`{ mode, target, before, after, rationale }`），不写事件。作者点「采用」才落到正常事件：`story.updated` / `dialogue.updated` / `shot.updated`。

**不做「一键全部改好」**：改写是创作决定，全自动应用违反 P7（人工覆盖层）与 P6（人只做「改」——但「改」的方向得由人定）。

### 5. 界面

剧本页顶栏新增「医生」抽屉：

- 顶部总分（12 维里已测部分的均值）与「已测 10 / 未测 2」。
- 每维一行：条形 + 分数 + 来源签（本地 / 模型 / 未测）+ 一句理由。
- 发现按严重度排：warn 在前，info 在后。
- 6 个模式按钮；第一档直接出建议，第二档标「用文本模型改一版（约 1 次调用）」，未配文本模型时禁用并说明原因。

## 理由

- **派生优于存储**：报告没有跨设备、跨会话的引用价值，存下来只会制造「这份分数是什么时候算的」这个问题。
- **未测要说未测**：把 emotionalPayoff 硬算成 3 分，作者会拿它当结论；写「未测」才会去等 A8 或自己判断。
- **建议优于自动**：6 种模式里有 4 种会改到作者写过的字。自动应用一次改错的代价，比让作者多点一次「采用」高得多。
- **闸门复用**：ADR-0118 的 `waivable` 就是为「做完了但不够好」准备的，剧本医生正是这一类。

## 后果

**正面**

- 不写一条事件就有一个可诊断的剧本视图，改一个字立刻重算。
- 12 维里有 10 维完全本地、可单测、零成本。
- 模型改写只在作者明确要求时发生，成本可见。

**负面**

- 10 维本地分是启发式，可能和人的判断不一致；界面上每维都写了它读的是什么。
- emotionalPayoff 与 originality 在第一版是空的，报告看起来「不完整」——这是诚实的代价。
- 第二档依赖文本模型配置，未配置时只能看建议。

**跟进**

- A8 落地后补 originality，并把 `unmeasured` 换成真实分数。
- 等有评测集后给 12 维做标定（I9），再看哪些维度值得交给模型。
- 不变量 17 / 18 的口径变更要在 DATA-MODEL 里同步写清。

## 成本

| 项 | 估计 |
| --- | --- |
| 第一档（本地报告） | 0 元；每次打开抽屉 CPU 开销可忽略 |
| 第二档（模型改写） | 每次 1 次文本调用，按 token 计价；价目表未收录文本单价（R28），界面只记调用次数、不写金额 |
| 工程 | 本地报告 2–3 天；`/api/doctor` 与建议预览 2 天 |

## 验证（设计阶段口径）

- 固定 fixture（示例项目 + 一份故意不合格的项目）跑 `analyzeScript`，逐维断言分数与 `source`。
- 9 条触发条件逐条命中；未测维度返回 `null` 而不是 0。
- 采用建议后的事件形状与现有 `story.updated` / `dialogue.updated` 一致，回放结果等于界面所见。
- 浏览器：剧本页开抽屉 → 12 行、2 行标未测 → 改一句超长台词 → 重开抽屉，dialogueEfficiency 分数变化。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 报告存进 IR | 分数是当前剧本的函数，存下来要配失效机制，且没有跨会话引用价值 |
| 12 维全用模型打分 | 贵、不可单测、同一份稿两次结果不同；本地能算的没必要花钱 |
| 未测维度填默认分 | 0 分是「很差」，与「不知道」混淆，会让作者按错误信息改稿 |
| 触发条件做成硬闸门 | 8/9 条是启发式，硬拦会堵死主路径，违反 P14 |
| 一键应用全部改写 | 改写是创作决定，自动应用违反 P7；工具只提供建议与一键采用单条 |
| 减人物 / 减场景自动执行 | 删实体牵动镜头、台词、take，误删代价高，只给建议 |

## 落地（A18 第一档：本地报告，2026-11-12）

### 1. 一个纯函数模块，一个抽屉

| 文件 | 做什么 |
| --- | --- |
| `apps/web/lib/script-doctor.ts` | `analyzeScript(project, { loglineScore? })`、12 维定义、6 种模式的本地建议 |
| `apps/web/components/doctor-panel.tsx` | 剧本页「医生」抽屉：总分、12 维、发现、改写方向 |
| `apps/web/lib/stage-flow.ts` | `script` 阶段的 `waivable` 补一条「剧本医生：N 项偏低」 |

报告不进 IR，也不缓存：抽屉每次打开现算，改一句台词重开就变。

### 2. 空项目不是「未测」

空项目里钩子、结尾钩子、可拍性这些维度**确实能判定为不合格**，所以给低分（总分 1.6、结论「偏低」），而不是把整体写成 `null`。只有两项保持 `null`：

- `emotionalPayoff`：要模型判断爽点 / 泪点，第一版不调模型；
- `originality`：等 A8 的相似度检查。

「没有台词」同理是 `dialogueEfficiency: null`，理由写「没有可算的内容」——默片不算差。这是 ADR 正文「未测不写 0 分」的准确读法：**没有数据**才写 `null`，有数据判定为不合格就该给低分。

### 3. `overall` 只按已测维度平均

`overall = 已测维度均值`（一位小数），`measured` / `total` 同时给出。界面上写「已测 10 / 12」，总分旁标 `/ 5`。不把未测当 0 参与平均——那会把一份没接 A8 的稿子算低。

### 4. 六种模式只给方向

`DoctorSuggestion = { mode, label, target, direction, applicable, shotIds }`。`target` 指到具体镜号 / 关系 / 结构数字，`direction` 写「往哪个方向改」，不写成品句子。例如：

- 强化钩子 → 「首镜 6.0s，太长：压到 3 秒内，先给冲突或悬念，别先交代环境。」
- 减人物 / 减场景 → 「超出可拍范围：先合并同地点的场…工具不会替你删——删角色会牵动镜头、台词与 take。」

`applicable` 表示这一条现在用不用得上（已经写了结尾钩子就不必再「重写结尾」），界面据此显示「用得上 / 现在不用」，但六条永远都列出来，作者能看到全貌。

### 5. 闸门接法：可豁免缺口，不新增事件

`readinessOf("script")` 在结构缺口（没有场次 / 没有镜头）为空时，把 `analyzeScript(project).summary.warn` 写成 `剧本医生：N 项偏低` 塞进 `waivable`。结构缺口还在时不重复报——那本来就不可确认，多一条只是噪音。

确认弹层沿用 ADR-0118 的「我知道」勾选与 `gate.confirmed { override: true }`，**不新增事件类型**。

### 6. 验证

- 单测 **887** 全过（IR 172 + gateway 28 + pipeline 67 + web 620），新增 14 条：`script-doctor.test.ts` 12、`stage-flow.test.ts` 2。`pnpm typecheck`、`next build` 全过。
- 浏览器（生产 3100）：剧本页顶栏「医生」带徽标 **5**；打开抽屉显示「已测 10 / 12」「总分 2.8 / 5 · 偏低 · 5 项偏低 · 1 项提示 · 32.6s」，12 行维度各带来源签与理由；把第一句台词改成长句后，台词效率从 **4 降到 3**（平均 7.3 → 13.8 字），总分 2.8 → 2.6，徽标仍是 5；点「去这一镜」抽屉关闭并滚到 `shot-s-01`；剧本阶段确认弹层出现「剧本医生：5 项偏低」，带「我知道这些缺口」的勾选。
- **没验到的**：第二档模型改写（未实现）、9 条触发条件在真实生成稿上的命中率（只有单测与示例项目）。

### 7. 已知缺口

- 第二档 `POST /api/doctor` 与「采用」没做：现在只能看方向，改字要作者自己去剧本页改（A2 一起做）。
- 分数没有评测集标定（I9）：阈值（15 字、每 20 秒 1 拍、3 场 / 5 人 / 14 镜）抄自 STORY.md，没有用真实短剧验证过。
- `hook` 与 `reversal` 只看节拍标签，不看内容：把「门口有人」标成 `turn` 就算有转折。标签由生成或作者给，标签错了结论也错。
- 报告不进 IR 也意味着没有历史：看不到「上次开抽屉是多少分」。
