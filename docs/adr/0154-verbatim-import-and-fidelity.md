# ADR-0154：逐字导入、章节拆分与保真对照

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：F6、ADR-0089、ADR-0011、准则 P2 / P7 / P12

## 背景

F6 原先只有「改编剧本 txt」一条路径：模型把原文压成 60–90 秒单集草稿，界面明确写「不是逐字导入」（ADR-0089）。这条路径解决的是冷启动，不解决作者手里已有定稿、只想先把某一章原样带进项目核对的需求。2026-11-11 的路线说明把「逐字导入、章节拆分、保真校验、原文对照」列为未做。

ADR-0089 不接收全文进 IR 的理由仍然成立：把两万字小说塞进 `provenance.prompt` 会撑大事件日志，还会让每次改写分不清「原文」与「模型补的台词」。但「不进 provenance」不等于「不能有一个专门的原文槽位」。若作者明确选了一章、明确声明权利、并看到逐字报告后主动开工，这一章就是项目事实，应该按 P2 进 IR，而不是只留在浏览器内存里刷新即丢。

## 决策

1. `/story` 增加第三个标签「逐字导入 / 对照」，与「从想法开始」「改编剧本 txt」并列。ADR-0089 仍然只管第二个标签；本次不改写、不废弃那条历史决策。
2. 新增纯函数层 `packages/pipeline/src/import-verbatim.ts`：
   - `splitChapters(source)`：按「第 N 章 / 第 N 集 / 中文数字编号」切候选片段；认不出就整篇叫「全文」，不猜。
   - `excerptOf` / `verbatimExcerpt`：只按 `[start,end)` 精确截，不 `trim` 作者写的空格与换行。
   - `fidelityOf`：把对照稿与原文对应区间逐行比，给出 `exact`、字符数、行数与改动行号；逐字相等才算通过。
   - `compareLines`：给界面画「原文 / 对照稿」并排行。
   - `documentFingerprint`：8 位 FNV-1a，用来在项目里复核这一份原文没被改坏；不是安全哈希，不防篡改。
3. 「逐字」的口径写进界面：只把 CRLF / CR 统一成 `\n`，其余字符一个不动。报告比较的也是归一后的原文；不偷偷修剪首尾空格，不把章节标题吞掉。
4. `StoryBible` 增加可选 `sourceDocument`：章节标题、章节序号 / 总数、原文、来源文件名、全文字数、导入时间、指纹。它是**只读参考槽位**：`story.updated` 白名单不收它，模型生成路径也不读它。旧项目没有这个字段，由 zod 缺省补齐，不升 `LOG_VERSION`。
5. 作者先选章节，再看逐字报告与并排对照；对照稿可以改着试，但只有 `exact: true` 且勾选权利声明、原文不超过 2 万字时才能「用它开工」。改动行会标出来，一键「恢复原文」回到逐字状态。
6. 开工走新的 store 动作 `startProjectFromVerbatim`：写一条新的 `project.created`。项目是**最小骨架**：一个待定地点、一场、一镜、零台词，镜描述只写「逐字稿已挂在项目里」，不把小说 disguised 成分镜。`story.sourceDocument.text` 保存选中的那一章；`provenance.prompt` 仍只写「逐字导入（未调用模型）」这类短摘要，`modelId` 写 `local:verbatim` 表示没调供应商。
7. `/script` 在存在 `sourceDocument` 时显示「逐字原文」面板：章节标题、指纹复核、全章原文、当前剧本纯文本对照。复核不通过就红字说「这份原文和导入时的指纹对不上」，不静默修复。面板不提供编辑原文；要换章节就回 `/story` 重新开工。
8. 这一条路径不调用任何模型，不发网络请求，不写服务端文件；原文只进本机事件日志（IndexedDB）。权利声明仍是用户声明，不是版权核验。

## 理由

- **原文是一等事实**：逐字导入的目的就是「一个字都不改」，把它留在会话内存里违背 P2 与 P7；刷新、回滚、换页之后还应在项目里看得到。
- **和改编彻底分叉**：改编进 `StoryDraft`、逐字进 `sourceDocument`；两者不共用展示、不共用确认按钮，也不会把模型补的台词误标成原文。
- **不假装会分镜**：小说的一章不是 10–14 个镜头。给一个空镜骨架，作者在剧本页自己写，比自动拆成错场次更诚实。
- **保真可核对**：字符数、行数、改动行号与指纹都是纯函数算出来的，不依赖模型自检；作者能看到是哪一行不一样。
- **事件日志不失控**：只存选中的一章、最多 2 万字，且放独立可选字段；不会像把整本小说塞进 `provenance.prompt` 那样让每条事件都带一份副本。
- **零供应商依赖**：章节识别、对照、指纹、落项目都在浏览器与本地 pipeline，供应商 403 / 配额 / 密钥都不影响这条路径。

## 后果

**正面**

- F6 的四个欠账都有可操作界面：章节按钮、逐字报告、并排对照、项目内原文面板。
- 原文不发给文本供应商，不产生模型费用；`provenance` 明确标 `local:verbatim`。
- 旧日志、旧项目、示例项目不受影响；`sourceDocument` 是可选字段。
- 报告永远先于写入：有改动就禁用开工，不靠提示词承诺「不改字」。
- 剧本页可以长期对照原文写台词，指纹复核能发现本地数据被改坏。

**负面 / 代价**

- 选中的一章会完整进本机事件日志，项目文件变大；刷新、回滚、导出项目时都要带上它。云端同步仍未做，跨设备看不到这份原文。
- 逐字项目开出来只有一空镜，离可发布成片还很远；这是刻意保留的「未改编」状态，界面必须写清。
- 章节标题是启发式正则：认不出就整篇一段；奇异标题要作者自己截一段。
- CRLF 会归一成 `\n`；严格到字节级一致的场景不适用，界面已写明口径。
- `documentFingerprint` 不是安全哈希，只用于发现误改，不能证明没人改过。
- 权利声明仍然不是版权审核；全章原文留在本机也要求本机访问控制跟上（R60）。

**不做**

- 不把整本小说自动切成多集写进一个项目；一次开工只带一章。
- 不自动把原文解析成人物 / 场次 / 台词；那属于改编，仍走 ADR-0089。
- 不给 `sourceDocument` 开 `story.updated` 编辑；换章节通过新的 `project.created`。
- 不上传原文、不接对象存储、不做云端同步、不做字符级 diff / 版本树。
- 不改 ADR-0089 的历史结论。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 继续只放浏览器内存，刷新即丢 | 作者要的是「带进项目」，不是临时预览；违背 P2 |
| 把原文塞进 `provenance.prompt` | 每条溯源都变重，且与「模型实际收到的提示」语义冲突 |
| 逐字文本直接生成 `StoryDraft` | 场 / 镜 / 台词都要发明，已经是改编；会伪造成「原文」 |
| 新开 `/import` 页面 | `/story` 已有导入输入、权利声明与开工确认，两个页面会让文案分叉 |
| 用 Web Crypto SHA-256 做指纹 | 需要异步 API 与更多序列化；这里只要 8 位「内容变没变」提示，FNV-1a 与阶段闸门同口径 |
| 不校验，只相信界面没改字 | 一个空格的漂移也会让「逐字」失真；必须有可执行的报告与写入前复核 |
| 多章批量建项目 | 当前一次只开一个项目、单集 60–180 秒；先把一章的闭环做实 |
