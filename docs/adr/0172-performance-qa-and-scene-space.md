# ADR-0172：表演 QA（B18）与场景空间板（B11）

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：B18、B11、B14、B16、B17、B13、ADR-0097、ADR-0103、ADR-0126、准则 P5 / P14

## 背景

B16 / B17 之后，表演设计（`Shot.performance`）与调度（`Shot.staging`）都进了 IR，
提示词也写进去了。但写进去不等于写得对：

- 一镜特写，`surface` 只写了「她很难过」——没有微表情，模型只能画一张平脸；
- 视线写着「看周决」，这一镜的 `characterIds` 里没有周决——画面里没人可看；
- 起转落只写了起——四秒的镜头里，动作停在半路；
- 相邻两镜林晚从画面左换到画面右——观众立刻出戏。

这些错都不需要看画面就能发现，全靠设计文本内部的矛盾。同时 B14（一致性体检）
已经确立了「结构化检查、不假装看过画面」的立场（ADR-0097），表演与空间应该
沿用同一条线。

B11 原本在 DATA-MODEL 里写成一个 `SceneState` 实体（`positions` / `facing` /
`wardrobe` / `props` / `screenDirection`）。B13 落地后，位置与朝向其实已经有真身：
`Shot.blocking`（米制坐标）与 `Shot.staging`（画面左中右 × 前中后景），道具在
`Shot.propIds`。再存一份台账就是同一件事写两处。

## 决定

### B18 表演 QA：查设计，不查画面

1. **纯函数，不落库**
   `analyzePerformanceQa(project)` 返回 `{ shots, summary, attention }`，与
   `analyzeConsistency` 同构：只读项目、不写事件、不进 IR、不缓存。

2. **按景别定「这一镜靠什么演戏」**
   `performanceFocusOf(size)`：特写 / 大特写 → 微表情；中景 → 姿态；其余 → 调度。
   阈值随景别走，不用一套标准套所有镜头。

3. **五类规则，两种严重度**
   - `fail` 是**自相矛盾**：视线看的人 / 道具不在这镜里；特写连微表情都没写（面瘫）；
     表演全空。
   - `review` 是**建议**：中景没写姿态、全景没写调度；强度副词（「极度崩溃」）
     代替具体表情；`hook` / `climax` 强度低于 3 或 `setup` / `resolution` 高于 5；
     起转落只有一拍、动作落在 60% 之前、动作写在「起」或「落」拍上；
     同一场相邻镜强度从 ≥4 掉到 ≤2 且这一镜不是反应 / 过渡。
   - `unknown`：没写表演设计的镜头不算失败，单列一档，避免存量项目满屏红。
   - 视线方向与站位方向相反（`direction: "left"` 而 `side: "right"`）只是 `review`：
     可能是有意回头看。

4. **明确不做 VLM**
   不抽帧、不做表情识别、不做视线检测。面板底部照实写：「没有抽帧，也不做表情或
   视线识别——演得好不好仍然要人看片。」报告只说设计里缺了什么、哪里自相矛盾。

### B11 场景空间板：台账是投影，不是实体

5. **不新增 `SceneState`，台账由现有字段派生**
   `analyzeSceneSpace(project)` 从 `Shot.staging` / `Shot.blocking` / `Shot.propIds`
   现算。好处：改完分镜立刻是新的，不会出现两份说法，不需要迁移与同步；
   坏处（如实承认）：没有「台账自己的备注」——要留话就写进 `staging[].note`。

6. **只判同一场的相邻两镜**
   跨场换位置是正常的（换地点、换时间），不判。四类问题：
   - 左右翻面：两侧都非居中且换了边 → `review`；
   - 前后景跳变：`DEPTH_ORDER` 差 ≥2（前景 → 后景）→ `review`；
   - 朝向翻转：两侧都有 `facingRad`、折到 0–π 后差 >120° → `review`；
   - 道具丢失：上一镜 `propIds` 有、下一镜没有 → `review`。

7. **判不了就写「判不了」**
   地点没有 `space` 几何时明说「只按画面左中右判，朝向与真实距离判不了」；
   这一场没有出场人物时明说没有可比的走位。没写左中右的地方不猜。

8. **未进场次的镜头也进台账**
   没有 `sceneId` 挂靠的镜头归到一行「未进场次」，而不是从表里消失。

### 界面

9. **两个抽屉，与既有抽屉互斥**
   分镜页顶栏新增「演检」（`performanceQa`，带待改计数）与「空间」（`space`，
   带问题计数）；打开任一个都关掉其它抽屉，Esc 关闭。
   - 演检：四格汇总（通过 / 建议改 / 会出问题 / 未写）、当前镜结论与逐条修改建议、
     「要改的镜头」列表、「去改这一镜的表演」直达表演抽屉、按景别看什么的对照。
   - 空间：场次选择、跨镜对照表（人物 × 镜头，格子里写左中右 + 前中后景 + 朝向，
     道具行写有 / ·）、相邻镜问题（可跳前一镜 / 后一镜 / 调这一镜的走位）、
     判不了的说明。

10. **顺带修掉一个会挡住 B11 的既有 bug**
    表演抽屉的保存以前先检查 `objective`，没写 `objective` 的镜头连左右位置都存不进去。
    现在把两件事拆开：`objective` 只决定要不要写 `performance`，调度照写；
    提示语分开说「调度更新了，表演设计还空着」。

## 理由

- **结构化检查优先**：这几类错在文本里就是矛盾的，不需要模型；引入 VLM 会把
  「没看出问题」和「没问题」混为一谈（与 B14 同一条）。
- **投影优先于实体**：B13 的坐标、B17 的站位已经是真身；再存一份必然漂移。
  投影还能让「台账」随着作者改分镜自动正确，不需要任何同步动作。
- **阈值随景别走**：特写里没写微表情是硬伤，全景里没写微表情是正常的——
  一套阈值会把后者报成错，作者很快就学会无视提示。
- **只判相邻镜**：跨镜比对全场会让报告变长、命中率变低；相邻两镜才是观众
  真正会察觉的地方。

## 后果

**正面**

- 表演设计里的自相矛盾（看的人不在、特写没表情、动作没写完）在导出前就能看到，
  并且给出具体改法，不是一句「表演可能有问题」。
- 空间连续性问题（翻面 / 跳景 / 转身 / 丢道具）在一张表里逐镜可查，
  点一下就能跳到对应镜头或走位抽屉。
- 存量项目不需要迁移：没写表演的镜头是「未写」，没写站位的格子是「—」。
- 修掉 objective 挡住调度保存的 bug，没写表演的镜头也能先把走位定下来。

**负面 / 代价**

- 不做画面判断：演得僵不僵、视线对不对眼，仍然要人看片。面板如实说明。
- 没有真实坐标时，「朝向与真实距离」判不了；只有 `staging` 的画面左右可判。
- 道具丢失只在 `propIds` 层面判：道具换了手、被放下，都不算丢失，也不会报。
- 报告只覆盖同一场相邻两镜，跨场连续性问题不在这条里。

**不做**

- 视频抽帧 / 表情识别 / 视线检测（VLM）。
- 新增 `SceneState` 实体与「台账备注」字段。
- 自动修改表演或走位（只给建议与跳转）。
- 跨场连续性、镜头内位置变化、遮挡与轴线（轴线归 B13 的 `checkAxis`）。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 用 VLM 抽帧判断表演好坏 | 当前仓库没有该能力；「没看出问题」与「没问题」无法区分，分数会骗人（同 ADR-0097） |
| 新增 `SceneState` 实体并双向同步 | 与 `staging` / `blocking` 必然漂移，还要迁移与冲突合并；投影天然一致 |
| 一套阈值套所有景别 | 全景不写微表情是正常的，全报出来作者会无视提示 |
| 表演 QA 与 B14 体检合并成一个抽屉 | 两者关注点不同（演得好不好 vs 前后一致），合并后结论会互相稀释 |
| 相邻镜问题自动改回上一镜的站位 | 翻面可能是有意的（换边 / 插中性镜）；自动改会抹掉作者意图 |
