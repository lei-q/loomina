# ADR-0134：触屏拖动场次与场号连续性提示

- 日期：2026-11-12
- 状态：已采纳
- 关联：A21、ADR-0080、ADR-0060

## 背景

ADR-0080 做了场次拖拽排序（`⠿` 手柄 + HTML5 `draggable`），并在「不做」里写清：

> - **拖拽只在桌面可用**：触屏没有指针拖拽，仍要用 `↑` / `↓` / `挪`。

A21 一直挂着这一句。另外它还有一句：

> 触屏 / 指针拖拽与场号连续性提示未做

## 决策

### 1. 触摸走指针事件，鼠标仍走原生拖拽

HTML5 `draggable` 在触屏上**根本不触发**（要按住再拖，浏览器把它当成滚动）。所以手柄的 `onPointerDown` 里判断 `pointerType !== "mouse"` 才接管：

- `pointermove` 时用 `document.elementFromPoint(x, y).closest("[data-scene-id]")` 找落点，命中就高亮那一场；
- `pointerup` 落在另一场上就 `moveSceneTo(源, 目标位置)`，落在自己身上就什么都不做；
- 手柄加 `touch-none`，否则浏览器会先把触摸解释成页面滚动，`pointermove` 收不到。

**鼠标不接管**：原生拖拽有现成的 ghost、`dragover` 跨元素落点与 `dataTransfer`，自绘一套只会多一份要维护的命中测试，而且拿不到系统级的拖拽光标。两条路都落到同一个 `dropSceneOn`，写同一条 `scene.moved`。

用 `elementFromPoint` 而不是预先算每场矩形：手指比鼠标粗，直接读指针底下的元素更准，也自动跟着滚动走。

### 2. 场号不重排，只解释

场号有两种（ADR-0080）：**显式场号**（`2A`）是这一场戏的名字，跟着场走；没写的按位置显示顺序号。拖动之后两者可以对不上：把第 2A 场拖到最前面，页面上依次是「第 2A 场」「第 1 场」「第 3 场」。

ADR-0080 已经决定**不按位置重新编号**——「2A」会在拖动后凭空变成「2B」，比看起来不连续更糟。所以 A21 的「场号连续性」做成**一句说明**，不是自动修正：

```
场号跟着场走：「第 2A 场」排在第 1 位。没写场号的场按位置显示顺序号，
所以编号和位置可以不一致；想让它们对齐，把场号清空就回到按位置编号。
```

- 只对**带数字的显式场号**判错位：`A` 这种纯名字没有位置含义，拿它比位置是无意义的；
- 跳号（1、3）也算「对不上」，因为提示是在解释而不是报错——作者删了第 2 场时正好需要这句话；
- 超过三场只列前三场，并说「等 N 场」；
- 全都对得上时不显示。一行常驻的说明会变成噪音。

### 3. 不打断拖动：提示只出现、不弹窗

提示是一条页面顶部的说明条，不进 `note`、不弹窗、不阻止拖动。拖完立刻看到它，就知道发生了什么；不想看可以无视，它也不影响任何操作。

## 为什么不做的部分

- **拖动时自动滚动**：长剧本里把最后一场拖到最上面要滚很久。自动滚动需要按指针靠近边缘的速度持续滚，还要处理「滚的时候落点跟着变」，这一轮不做——`挪` 下拉可以直接选目标场号，长距离换位有更稳的路。
- **自绘拖动 ghost**：触摸拖动时源场只降透明度，不跟一个浮层。手指底下已经能看见目标场的高亮，浮层是额外的视觉噪音。
- **落点插在两场之间**：沿用 ADR-0080 的语义——落到哪一场就留在那一场的位置。
- **按位置重新编号场号**：见决策 2，明确不做。
- **拖镜头（不只是拖场）**：镜头已经在自己的场里按镜序排，跨场拖镜头要先回答「时长、台词、时间线项跟不跟过去」，那是另一件事。

## 后果

- 手柄多一个 `onPointerDown` 与 `touch-none`；场 `<section>` 多一个 `data-scene-id` 供命中测试。
- 新增 `apps/web/lib/scene-numbering.ts`（纯函数 `sceneNumberingOf`），6 条单测。
- 剧本页在页头下面多一条说明条，只在场号与位置对不上时出现。
- 无新事件、无 IR 变化。
