# ADR-0233：音效按场加混响，配乐故意不房间化（C11 第三档）

- 状态：已采纳
- 日期：2026-11-14
- 决策者：用户 + Claude
- 关联：C11、C7、ADR-0226、ADR-0227、SOUND.md §六 / §八

## 背景

ADR-0227 把混响加到了**对白**上（对白一条一句、天然没有接缝）。
剩下的两条音频是配乐与音效，都是**整轨输入**——一条 cue 可能横跨好几场，
所以「按场切」要 `atrim` + `concat`，接缝处容易爆音。这是当初没做的原因。

SOUND.md 给了判断依据：

- §六：**音效**「空间感：混响必须匹配场景。卧室不该像大厅，街道不该像录音棚。」
- §八：空间混响「同场景同一套 reverb 参数」。

两条说的都是**场景里的声音**，不是配乐。电影声音的常规做法也是：
对白与音效属于「场景空间」，配乐是独立的一层，不做房间化——
否则一场戏从卧室走到走廊，配乐也跟着换混响，听起来像音乐本身在移动。

## 决定

1. **音效按场加混响**：`EditSfx.reverbId` 由 `toEditView` 按**音效起点落在哪一镜**
   算出（环境声这类跨场的，跟着起点那一场走，不按长度切段）。
2. **配乐不加混响**：`MixMusic` / `RenderMusic` 没有 `reverb` 字段。
   不是遗漏，是决定——理由写进代码注释与 ADR。
3. **只传预设 id**：`RenderSfx.reverb` 用 `REVERB_IDS` 白名单校验，
   服务端从固定表解析成滤镜；不在表里当作没有（旧客户端不带这个字段）。
4. **滤镜位置与淡入淡出一致**：`atrim → asetpts → [afade] → [aecho] → adelay → 增益`。
   放在 `adelay` 之前，那时时间轴还从这一段自身算。
5. **界面只读显示**：「混响 走廊」这样标出这一条音效用的哪套，不在卡片上改——
   改的是场景的地点，不是这一条音效。

## 验证（本地 ffmpeg 实测）

1 秒粉噪音效，测**源停止后 1.0–1.5 秒**（即尾巴）：

| 预设 | 尾巴 |
| --- | --- |
| 干声 | 无声 |
| 走廊 | −39.5 dB |
| 大厅 | −38.2 dB |

`render-audio.test.ts` +3 条：不带混响无 `aecho`、`aecho` 在 `adelay` 之前、
配乐即使带 `reverb` 字段也不加 `aecho`。

## 理由

- **按起点定场而不是切段**：音效大多很短，跨场的多是环境声。
  给环境声按长度切成两段、各加一套混响，接缝处的相位跳变比「跟着起点」更明显。
  更简单、更好听、也更容易解释。
- **配乐不房间化**：这是有意的取舍，不是没做完。写进 ADR 是为了以后不会被
  当成遗漏又「补」一遍，反而破坏听感。
- **只读显示**：音效的混响来自场景空间，作者改地点就该跟着变；
  在音效卡上单独改会让「同一场两个空间」重新出现。

## 后果

**正面**

- 音效第一次跟房间走：关门声在走廊里有尾巴、在卧室里没有。
- 配乐保持干净的一层，换场不会「音乐跟着换房间」。
- 与对白、淡入淡出共用同一套滤镜位置约定。

**负面 / 代价**

- **跨场的长环境声只按起点那一场**：一条雨声从室内铺到街道，全程都是室内混响。
  要精确就得切段，那是下一档。
- 配乐完全没有空间处理——如果某条片子确实需要「音乐也在这个房间里」，
 现在做不到（要单开一个开关，本次不做）。
- 音效混响不可单独覆盖：改场景地点才会变。
- 每条音效多一个 `aecho` 实例，渲染 CPU 略增（最多 8 条）。
