# ADR-0174：片头 / 片尾与品牌包（E9）

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：E9、E6、E5、G9、G7、D5、D4、H5、ADR-0086、ADR-0091、ADR-0138、ADR-0171、准则 P5 / P14 / P20

## 背景

E9 一直挂在 FEATURES 里没动：片子做完了，片名、集号、落款、「下一集」这些
每一集都要补的东西，还得进剪辑软件再铺一次。G9 之后一条片子能出好几个平台版本，
手工加的头尾卡一旦写死在剪辑软件里，每出一版都要再对一次。

真正要定的是**它放在哪一层**。时间线（`TimelineItem`）是「这一段放哪一镜的哪一条 take」，
头尾卡没有镜头、没有 take、没有台词；把它塞进时间线会逼着换 take、镜头清单、
初剪、锁定这些地方到处判空。反过来，把它放到时间线之外，所有按时间排的东西——
字幕、配音、配乐、平台时长校验——都得跟着整体后移，这件事必须只在一个地方算。

另外实测撞到一个既有问题：渲染清单里的内容指纹（H5 / ADR-0138）是客户端按**读模型**
算的，服务端按**清单**重算；头尾卡进了清单却不在读模型里，两边算出来不一样，
`POST /api/render` 直接 400「内容指纹与清单对不上」。

## 决定

1. **卡片不是时间线里的镜头**
   - 读模型里单独一份 `EditView.cards: EditCard[]`（`role` / `startMs` / `durationMs` / 标题 / 副标题）。
   - `EditClip` 一个字段都不加：卡片不是片段，不该出现在换 take、镜头清单、锁定、删片段这些地方。
   - `Project.timeline.items` 也不动——时间线仍然是「事实」，卡片是导出时加的。

2. **品牌包进 IR**：`Project.brand`
   - `name`（落款，≤40）`handle`（账号 / 期数说明，≤60）`color`（卡片底色，`#RRGGBB`）。
   - `intro` / `outro` 各一张：`enabled` / `title` / `subtitle` / `durationMs`（500–10000，整数毫秒）。
   - 进 IR 是因为这些是创作决定：刷新、换设备、回放事件日志之后还得是同一张卡、同一个时长。
   - **关掉不删字**：`enabled: false` 之后标题仍在，再打开就是同一张卡。
     卡片是叠加能力，不是「删了再加」。

3. **一条事件 `brand.updated { patch }`，不碰 `LOG_VERSION`**
   - 顶层三个字段逐个收；`intro` / `outro` 里给的字段逐个合并——只改时长不该把标题清掉。
   - 空 patch、空卡片 patch、坏颜色、越界时长、超长文字都由 `applyEvent` 拒。
   - 事件白名单、历史文案、zod 校验与回放都补齐；缺省字段让旧日志照旧回放。

4. **时间偏移只在一个地方算：读模型**
   - `EditView.brandOffsetMs` = 开着的片头卡时长。
   - 画面片段、台词、字幕 cue、配乐 cue 的绝对时间**一起**加这个偏移；
     相对位置一处都不变，所以断句、挪字幕、转场接缝都不用改。
   - `totalMs` = 画面末尾 + 片尾卡时长；时间线里一镜都没有时不插卡（空片不该多出两秒黑屏）。
   - 不在时间线里加偏移：那样时间线的含义就变了，初剪、拖动、锁定全都要重算。

5. **一张图走遍四路：`apps/web/lib/card-image.ts`**
   - `drawBrandCard(ctx, art, size)` 是唯一画法：底色铺满 → 标题 → 细线 → 副标题 → 左下角落款 + 短竖线。
   - 字色按底色亮度自动取（深底浅字），作者只挑一个颜色——挑错了就是看不见的字。
   - 折行按画布宽度量，中文逐字断；标题 `width*0.72`、副标题 `width*0.68`，长标题折行不会跑出画面。
   - `cardImage()` 画成 PNG data URI，给四处共用：
     成片清单（`media` + `mediaKind: "image"`）、预览 HTML（`still`）、OTIO（`target_url`）、
     界面（抽屉预览与舞台）。
   - 没有 DOM 时（服务端渲染、Node 测试）返回 `undefined`，调用方退回占位；
     **时长照样对**——导出环境不同不会让时间轴错位。

6. **顺带修清单的内容指纹（H5）**
   - 客户端改成按**这份清单自己的片段**算（`materialOfManifest({ title, totalMs, clips })`），
     与服务端的重算规则一致。
   - 之前按读模型算，加两张卡就对不上；现在结构与规则对齐，加多少段都不会漂。

7. **界面：成片页顶栏「品牌」抽屉**
   - 品牌：落款、账号说明、底色（带「字色自动换成浅 / 深色」的说明）。
   - 两张卡各一段：开关、标题、副标题、时长（秒，0.5–10）、保存；右边是**同一张图**的实时预览。
   - 时间线首尾多两段可点的「片头 / 片尾」格子，点开就是这张抽屉。
   - 播放头落进卡片窗口时，舞台显示的就是那张卡（不是第一镜的画面）。
   - 抽屉顶部写清楚「2 张出片 · 成片 9.5 秒」，底部说明限制。

## 理由

- **卡片不进片段数组**：`EditClip` 是「一镜一条 take」的读模型，解锁 / 锁定、换 take、
  镜头清单、删片段都围着 `shotId` 与 `takes` 转。塞一张没有 shotId 的卡进去，
  每个用到片段的地方都要加判空——这是把便利建立在每个调用点的防御上。
- **偏移算在读模型**：时间线是事实（P5）。导出要的是「成片里第几毫秒」，
  这件事本来就在读模型里做（台词换算成绝对时间）。卡片只多一个源头，不该再加一套坐标。
- **一张图四处共用**：D5 已经证明「预览一套、导出另一套」会在两处同时改、也同时忘。
  卡片只有一张静帧，用 Canvas 2D 画一次、PNG 交给所有出口，界面上看到什么，导出就是什么。
- **字色自动**：让人手动挑第二个颜色，最坏的结果是黑底黑字；亮度算一下是几行代码。
- **关掉不删字**：和 D5 的译文一样——关掉是「这一版不出」，不是「不要了」。

## 后果

**正面**

- 每集不用再进剪辑软件补片名 / 下一集 / 落款；出片流程少一段手工。
- 卡片在成片、预览 HTML、OTIO、界面里是同一张图，不会再「界面上好看、导出里错位」。
- 字幕、配音、配乐、平台时长校验全部按含卡片的成片算——SRT 拿去对成片，时间是对的。
- 清单指纹改成按清单算，以后再加任何一段画面都不会与服务端对不上。

**负面 / 代价**

- **卡片计入平台时长**：实测 5.5 秒的片子加了两张卡变 9.5 秒，抖音下限 15 秒那一项
  仍按 9.5 秒判。卡片能帮忙够到下限，也能把片子推过上限——界面把它们算进「全长」，
  但不会提示「这张卡让你超了」，预检里只有平台那一行。
- **片头卡是静音的**：配乐整体后移，从第一镜才进来。真要在卡上铺音乐，
  得让配乐相对成片起点落，而不是相对画面——这一版没做。
- 只有上下两张卡，数量固定；没有多张卡、没有卡内图片 / 视频、没有动效。
- 预览 HTML 与 OTIO 里的卡是**同一张 PNG**，但 OTIO 的 `target_url` 是 data URI，
  整份文件会因此变大（剪辑软件一般能读，只是不轻）。
- 读模型的时间偏移意味着：拿导出的 SRT 去和「没有卡片的版本」对表，差一个片头时长。
  这是对的，但要让作者知道；抽屉里已经写了「时间都按 X 秒后移」。

**不做**

- 动态 logo / 逐帧动画卡片（留给 E8 关键帧动画）、卡内视频、模板市场。
- 按平台输出不同的卡（G9 的多平台版本共用同一份品牌包）。
- 卡片里放图片素材（`AssetStore` 里的 logo）：这一版只有字与底色。
- 自动从剧本标题生成卡片文案；卡片文案进编译器的任何一环。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 把卡片做成 `timeline.items` 的一种 | 没有镜头 / take / 台词，换 take、镜头清单、锁定、初剪全要判空；时间线的含义被改掉 |
| 把卡片做成 `EditClip` 的一种（加 `kind`） | 所有围着 `shotId` / `takes` 的 UI 与逻辑都要加分支，代价比单独一份大 |
| 卡片在渲染时由服务端画 | 成片、预览 HTML、OTIO、界面就要各画一遍；服务端字体会与浏览器不一致 |
| 卡片画成 SVG 字符串 | Canvas 已经在成片链路里（字幕、占位图），多一套图形栈只多一类不一致 |
| 字色也让作者挑 | 挑错了就是看不见的字；亮度自动取是几行代码 |
| 关掉卡片时清空文字 | 再打开要重写一遍；关掉是「这一版不出”，不是「不要了」 |
| 内容指纹继续按读模型算 | 卡片进了清单却不在读模型里，服务端重算必然对不上（实测 400） |
