# ADR-0137：文本与配音按用量计价，账单跨项目汇总并导出

- 日期：2026-11-12
- 状态：已采纳
- 关联：H4、R28、R39、ADR-0033、ADR-0036、ADR-0106、ADR-0088

## 背景

H4 的记账一直只覆盖「有价目表的东西」：图像按张、视频按秒，`packages/gateway/src/pricing.ts` 里查得到单价。文本（故事生成）与配音（逐句出声）两路调用**只记了次数、没记钱**，成片阶段的本机 ffmpeg 渲染也只是在界面底部写了一句「不按文件计费」。抽屉里「剧本 / 成片显示 ¥0.00 表示未记账，不是免费」——这句话诚实，但它不是账。

结果是三条说不通的地方：

1. **花得最多的两路没有数字。** 一次故事生成实测约 1 万 completion tokens；20 句台词配 3 版就是 60 次 TTS 调用。这两路的账单只能去供应商后台看。
2. **没有跨项目的数。** 本地日志是只追加的流水，开新项目就是在末尾再写一条 `project.created`（ADR-0088）。抽屉只算当前项目，问「这台设备一共花了多少」没有答案。
3. **账单出不去。** 想拿去对账、贴进表格、发给合作方，只能对着屏幕手抄。

## 决策

### 1. 文本与配音的单价由作者填，不猜

`/v1/models` 不给 chat 与 tts 的价格（R28 / R39），公开资料里也没有可离线换算的 token / 字数公式。**不编一个「差不多」的价**——准则 P21：预估不出来的价格不是价格，是猜测。

所以给 `ModelRecord` 加一个可选字段：

```ts
unitPriceCny?: number   // 文本：元 / 百万 token；配音：元 / 千字
```

设置页里每个文本 / 配音模型多一个「单价」输入框，空着就是「未知」。填了就是**作者按真实账单填的估算**，不是系统推断出来的价格；能力矩阵里这一栏标「作者按账单填写」，与价目表里查到的单价分开说。

「元 / 百万 token」「元 / 千字」这两个口径是供应商账单最常见的写法，也是唯一能让作者照着账单直接抄的写法。换成「元 / 千 token」会多一步心算，多一步就多一处填错。

### 2. 用量记事实，金额记推算

`Provenance` 加两个可选字段：

```ts
costCny?: number
usage?: { units: number; unit: "tokens" | "chars" }
```

- **用量是供应商给的事实**：文本取 `usage.prompt_tokens + completion_tokens`，配音取发出去那句去空白后的字数。
- **金额是用量 × 单价算出来的**，两个条件缺一个就不写：没有用量（供应商没报）或没有单价（作者没填）。

两者都记，因为只留金额的话，事后想核「这个数怎么来的」就无从查起；只留用量的话，账单页要每次重算一遍，而单价是会被改的。

配音的金额同时写进 `Asset.costCny`（音轨是资产，`spendOf` 本来就会把它算进「已花」）和溯源里。这不是重复：资产上是「这一条音轨值多少钱」，溯源上是「这一次调用花了多少、念了多少字」，两个问题不一样。

### 3. 故事生成的钱跟着「开工」进项目

故事草稿**不写 IR**（ADR-0088）：一次生成产出草稿，作者看过之后点「用它开工」才落成项目。所以这笔钱在生成那一刻只存在于浏览器内存里，一刷新就没了。

解决办法是把 `costCny` / `usage` 从 `/api/story` 的响应带到 `startProjectFromStory`，写进新项目的 `story.provenance`。**钱跟着项目走，而不是跟着页面走**：换设备、重放日志之后，这笔账还在。

代价是「生成过但没开工」的那几次调用永远进不了账。这是对的——那些草稿没有落成项目，本来就不属于任何一条片子；把它们摊进下一个项目反而是错的账。作者要看这部分，只能看供应商后台。

### 4. 本机渲染只记机器时间，不折成钱

`PublishPackage` 加 `renderMs?: number`。导出成片时记下从提交到拿回文件的毫秒数，账单的「成片」阶段显示「最近一次渲染 42.5s 机器时间」。

**不折成钱**：本机 ffmpeg 没有单价，一台机器跑一小时值多少钱取决于这台机器怎么算折旧，那是另一个问题。把机器时间写成一个假的金额，比不写更糟——作者会拿它去和供应商账单相加。

这一条也回答了原来界面那句「不按文件计费」：不按文件计费不等于没有成本，只是这个成本不以「元」计价。

### 5. 跨项目汇总 = 按 `project.created` 切段重放

不需要另一张表。日志里每一条 `project.created` 就是一个项目的起点，切段、`rebuild`、各自 `spendOf`、相加，就是「这台设备上一共花了多少」。

```ts
projectSegments(events) → { segments: [{ project, fromEvent, toEvent }], skipped }
spendReport(events)     → { rows, total, unpricedCalls, unpriced, skipped }
```

**回放不了的那一段跳过并计数**，不连累整份账单：那几段可能是在旧版本里写的，少算一个项目比一个数都给不出来好。界面上要如实写「有 N 段日志回放不了，没算进合计」。

### 6. 账单导出 CSV，两段表

`billCsv(events)` 拼三段：项目合计、逐镜明细、按阶段明细，中间空行分隔。用 CSV 而不是 Excel / JSON：表格软件双击就能开，脚本也好读。带 UTF-8 BOM，Excel 才不会把「夜班」显示成乱码。

导出按钮在记账抽屉右上角，一次导出整台设备的全部项目——这正是「导出账单」与「看当前项目」的分工。

## 为什么不做的部分

- **自动从供应商拉单价**：`/v1/models` 没有这个字段，LiteLLM 口径的 `output_cost_*` 单位未确认（MODEL-GATEWAY.md 已记），拿它改写人民币价目表会把账做歪。等拿到真实账单对上了再说。
- **「生成过但没开工」的草稿也记账**：见决策 3。
- **本机渲染折成钱**：见决策 4。
- **多设备汇总**：本地日志只在这一台设备上，跨设备要先把日志同步到服务端，那是另一个架构决定。
- **账单按时间筛选 / 按月汇总**：当前项目数是个位数，全量导出已经够用；按月汇总要先有「这些项目属于哪个月」的可靠口径。
- **把单价写进项目而不是配置**：单价属于「这台设备怎么配置供应商」，不属于某一条片子；写进项目会让同一条片子在换配置之后出现两个价。

## 后果

- `ProvenanceSchema` 加 `costCny` / `usage`；`PublishPackageSchema` 加 `renderMs`；`ModelRecord` 加 `unitPriceCny`。**都是可选字段，`LOG_VERSION` 不升**：旧日志读回来照样合法，缺省就是「不知道」。
- 新增 `apps/web/lib/metered-price.ts`（换算与口径）、`apps/web/lib/spend-report.ts`（切段汇总与 CSV）。
- `Spend` 多出 `text` / `voice` / `unpricedCalls`；`spendByStage` 多出 `story` 阶段，`edit` 阶段显示渲染耗时。
- 记账抽屉顶部「未定价」从「张数」改成「次数」（图与视频也按次算），因为文本 / 配音没有「张」这个单位，混在一个数里作者会以为漏算的是定妆图。
- 设置页每个文本 / 配音模型多一个单价输入框；能力矩阵的单价栏能显示这两种模态。
- 故事页的生成结果行显示这一次花的钱（或「未定价 + 用量」）。
- 记账抽屉多「这台设备」一栏与「导出账单」按钮。
