# ADR-0046 换说话人：一条事件，别的都不动

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0044（台词改写）、ADR-0045（增删句）、FEATURES A5

## 背景

ADR-0044 规定 `dialogue.updated` 不能改说话人——换人等于换一句台词，应该新增。ADR-0045 落地后，界面上加错人只能删了重加，一次误点会留下四条事件。剧本里「这句其实是她说」很常见，得能直接改。

## 决策

1. **新增事件 `dialogue.speaker.updated { lineId, characterId }`**：只换 `characterId`，文本与时长不动。
2. **校验在 `applyEvent` 里**：台词要存在、角色要存在、不能换成原来那个人（没变化就别写事件）。
3. **store 的 `changeSpeaker`**：锁定镜头拒改；不存在的角色、同一个人都返回 false 并给一句说明；一次只写一条事件。
4. **界面**：说话人小字变成可点的按钮，点了就地换成下拉，选完立刻生效、失焦收起；锁定镜头不可点。
5. **不加时长联动**：换人不改文本，配音时长不变；真要变，用户自己再改文本或删了重加。

## 理由

- **一条事实一条事件**：换人不是改写，混进 `dialogue.updated` 会让「改过几版」把换人也算成一版。
- **说话人是结构不是文本**：语音、口型、分镜里的人物都跟着 `characterId` 走，单独事件更容易被下游订阅。
- **就地改**：多一层「换人」按钮与保存，代价大于收益；下拉选完即生效，取消就是选原来的。

## 后果

**正面**
- SH-01「你早就知道，对吧。」从周改成林：说话人、日志一目了然，文本 2.6s、镜头 3.1s、全片 32.6s 都不动；日志只多一条 `dialogue.speaker.updated`。
- 加错人的修正从「删 + 重加（四条事件）」变成「换人（一条事件）」。
- 测试：IR 60 条（新增 2 条：换人与重放、三种非法输入）；web 109 条（新增 2 条：换人落一条事件、锁定 / 同人 / 陌生人不写事件）。

**负面**
- **版本列表不记录换人**：`改过 n 次` 只数文本改写；换过谁、什么时候换的，要翻日志。
- **说话人只在角色表里选**：不能临时写一个没有定妆的角色名。
- **换人不改时长**：一句长台词从张三换给李四，配音语速不同也不会重估。
- **没有「谁说的」批量替换**：整场换人只能一句一句点。

**跟进**
- 版本列表把换人也算进去（显示「周 → 林」这类结构变化）。
- 按角色批量换人（整场 / 整条片子）。
- 换人后标记配音、字幕、口型相关产物过期。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 放开 `dialogue.updated` 接受 `characterId` | 版本列表会把换人算成一次改写；事件语义变混 |
| 删了重加 | 四条事件、id 变了，引用这版的别处会断 |
| 换人时顺便重估时长 | 文本没变，重估只会制造与被换前不一致的时长 |
| 做成「换人 + 保存」两步 | 小改动多一次确认，划不来 |
