# ADR-0204：剧本 / 分镜整份版本快照（C14 第五档）

- 状态：已采纳
- 日期：2026-11-14
- 决策者：用户 + Claude
- 关联：C14、C2、F2、ADR-0187、ADR-0109、ADR-0193

## 背景

C14「生成过的东西都是资产」到 ADR-0200 为止有：关键帧旧版、故事版本库、
视频 / 配音废片库。缺的是**剧本 / 分镜的整份快照**：作者改过一版分镜动作、
删过一场、把台词挪来挪去之后，只能翻历史抽屉一条条看事件，看不到
「那一版整份剧本长什么样」，也没法把某一版的字拿回来。

故事版本库（ADR-0187）证明「日志就是版本库」可行：不另存快照、不新增事件类型。
但剧本比故事多两件麻烦：

1. **结构有 id 引用**：场 → 镜 → 台词，还挂着 take、关键帧、配音、时间线片段；
   整份替换会把已经出的画面与声音一起弄成悬挂引用。
2. **剧本事件夹在别的事件里**：`shot.updated` 同时服务关键帧、锁定、接续、
   表演、光影、裁切焦点；不是每一条都算「改了剧本」。

## 决定

1. **新增纯函数 `apps/web/lib/script-versions.ts`**
   - `scriptVersionsOf(events)`：用 `rebuildStates` 拿到每一步的 Project，
     只把「剧本事件」收成版本；**同一毫秒的一组事件合成一版**（与 F2 撤销同口径），
     版本点落在组里最后一条事件之后。`project.created` 算初版。
   - 剧本事件白名单：`scene.*`（加 / 删 / 挪 / 改）、`shot.added` / `shot.removed`、
     `dialogue.*`（加 / 删 / 改文本与时长 / 换说话人）、以及 `shot.updated` 里
     patch 含剧本字段的那些。`dialogue.updated` 只在改 `text` / `durationMs` 时算；
     配音、字幕偏移、表演参数、译文不算。`keyframes` / `takeIds` / `locked` /
     `focus` / `budgetCny` 等成片与导出字段不算。
   - 每版带：时间、人话标签（复用 `describeEvent`，同组去重）、
     **整份纯文本快照**、场 / 镜 / 句计数、`eventIndex`。
   - 若日志最后是 `project.restored` 等「非剧本事件改变了剧本内容」，
     补一条「现在这一版」的合成版本，保证列表里总有当前状态。

2. **剧本页「剧本版本库」折叠区**
   - 新→旧列版本；当前版标「现在这一版」，其余可展开看整份文本、
     与现在的行差异（按行多重集比，列多出来的行与少掉的行，最多各 6 条）。
   - 最多列 40 版，明说「还有 N 版没列出」。
   - 读模型全是派生：不写 IR、不调模型、不花钱。

3. **恢复路径一：「用这版写回」（新增 `restoreScriptVersion(eventIndex)`）**
   - `scriptRestoreEvents(current, target, at)` 生成一批事件：
     `scene.updated`（内外景 / 日夜 / 地点）、`shot.updated`（动作、补充要求、
     景别、机位三参数、时长、节拍、目的、光影、构图、接续）、
     `dialogue.updated`（文本 + 时长）、`dialogue.speaker.updated`。
   - 只改**当前仍存在**的场 / 镜 / 句；旧版有而现在没有的结构不重建、
     现在多出来的结构不删。台词语序 `dialogueIds` 不自动重接，
     出场人物 / 道具 / 走位 / 调度 / 表演设计等带 id 引用的字段不自动恢复
     （避免悬挂引用与几何冲突）；可选模板只补不撤（schema 没有「清空」的写法）。
   - 锁定的镜头整条跳过并计数；地点 id 当前不存在就跳过该项。
   - 先在草稿上整批 `applyEvent` 回放，全过才写进状态；同批共用一个 `at`，
     撤销一步退回。与现在一致时不写事件。不调模型、不花钱。

4. **恢复路径二：「整份回到这里」**
   - 直接调既有 `restoreTo(eventIndex + 1, label)`：追加一条 `project.restored`，
     整份项目回到那一版（**包括** take、关键帧、配音、审批、时间线）。
   - 按钮要二次确认，文案写清「别的阶段也会一起回到当时」；
     这不是剧本专属恢复，而是复用 F2 的全局回滚，不在日志里复制快照。

5. 不新增 IR 字段、事件类型，不改 `LOG_VERSION`。

## 理由

- **看得见整份，改得保守**：作者要的是「那一版写了什么」，快照给整份；
  真要写回时，默认只动当前结构里还认得的剧本字段，不把已出片的引用弄坏。
  要连画面声音一起回去，还有明确标注的全局回滚。
- **同毫秒一组**：加一场常同时写 `scene.added` + `shot.added` + `dialogue.added`，
  按事件列会把一次操作拆成三版；与 F2 的撤销口径一致才不会自相矛盾。
- **白名单而不是黑名单**：`shot.updated` 的字段还会继续增加，
  黑名单会把将来的成片字段误判成剧本改动。
- **不另存快照**：日志是唯一事实来源（P2），快照文本现算，改多少版都不涨体积。

## 后果

**正面**

- 剧本页能看任意一版的整份纯文本、知道与现在差在哪几行。
- 「用这版写回」一批事件、一次撤销可退，不动花钱的生成物。
- 「整份回到这里」给想彻底回退的作者一条已有的、可回滚的路。

**负面 / 代价**

- 轻恢复不重建已删的场 / 镜 / 句，也不删后来新增的；不是严格意义上的整份替换。
- 不恢复台词顺序、出场人物 / 道具、走位 / 调度 / 表演设计、场号、可选模板的清空。
- 锁定镜头整条跳过，可能造成「这一版只恢复了一半」，靠计数与提示如实说明。
- 行差异是多重集比较，不是逐行 diff：改了一个字会同时出现在「多 / 少」两栏。
- 版本列表最多 40 版，没有分页 / 搜索 / 命名。
- `project.restored` 之后如果没有新的剧本事件，会出现一条「现在这一版」合成版；
  它不可再回滚（本来就在当前位置）。
