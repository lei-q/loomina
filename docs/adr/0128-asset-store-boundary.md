# ADR-0128：资产先落本机资产库，S3 兼容存储排在依赖确认之后

- 日期：2026-11-11
- 状态：已采纳
- 关联：H3、F4、B1、B2、B3、C1、C4、E7、G1、ADR-0028、ADR-0034、ADR-0085、ADR-0093、ADR-0099、R36、R40

## 背景

`Asset.uri` 现在是「一个字符串」：生成的图与视频是供应商回的 `https://` 地址，用户导入的素材是 `data:` URI。ADR-0085 明确写着「音轨存在 IndexedDB 的 data URI 里，一句 8 MB，长片段的音频会把本地配额顶满」，配乐是 18 MB，视频导入是 12 MB。ADR-0122 之后日志可以整份重置，但**正常使用时日志只会越来越大**：

- 一张定妆图约 2.4 MB 的 data URI（`event-log.ts` 的注释原话）；
- 四个角色 + 主镜 + 道具 + 关键帧，一个正常项目几十兆；
- 每次 `reset` / 回滚 / 撤销都在这份大日志上做前缀操作；
- 渲染时清单里带着这些 data URI，`render-jobs.json` 也跟着变大（R40）。

H3 一直挂着「S3 兼容」，而用户此前定的是**先存在本地**。所以 H3 缺的不是一个 S3 客户端，是**一个能换实现的存储边界**。

## 决策

### 1. 先定接口，两个实现

```ts
// apps/web/lib/asset-store.ts
export type StoredAsset = {
  /** 稳定地址，进 IR 的就是它 */
  uri: string;
  bytes: number;
  sha256: string;
  mime: string;
};

export interface AssetStore {
  /** 读：把地址解析成服务端可读的字节或本地路径 */
  read(uri: string): Promise<{ bytes: Uint8Array; mime: string } | null>;
  /** 写：把字节存进去，返回地址（内容相同则复用） */
  put(input: { bytes: Uint8Array; mime: string }): Promise<StoredAsset>;
  /** 删：只删没人引用的；调用方保证引用已清 */
  remove(uri: string): Promise<void>;
}
```

两个实现：

| 实现 | 地址形态 | 依赖 | 用途 |
| --- | --- | --- | --- |
| `LocalAssetStore` | `loomina://assets/<sha256>.<ext>` | 无（node `fs`） | 本机运行，当前默认 |
| `S3AssetStore` | `s3://<bucket>/<key>` | **待确认** | 部署到云端时 |

`LOOMINA_ASSET_STORE=local|s3` 选实现；缺省 `local`。**IR 只存地址字符串**，不存实现细节——换实现时 `Asset.uri` 的形状变了，但引用方（`Shot.keyframes`、`DialogueLine.audioAssetId`、`Take.assetId`）都不受影响。

### 2. `LocalAssetStore` 是第一刀，零依赖

- 目录 `.loomina/assets/`（0700），文件 `<sha256>.<ext>`（0600），与 `config.json` / `render-jobs.json` 同一处。
- **按内容寻址**：同一段配乐加两次只存一份；`sha256` 也是去重的依据。
- 单个文件上限 200 MB（视频 take 的合理上限）；超过直接拒绝，不写半个文件。
- `.loomina/` 已在 `.gitignore` 里，不需要改。

这一刀立刻解决的问题：

- 事件日志里不再有 base64。一个 40 MB 的项目日志会降到几百 KB——`reset`、撤销、回滚、`rebuild` 全部变快。
- 体积上限从「一句 8 MB / 配乐 18 MB」变成「单文件 200 MB」。
- 渲染清单不再带 base64；`render-jobs.json` 从几十兆降到几 KB（R40 缓解）。
- 预览（E7.2 的代理）与将来 depth 导出有地方放文件。

### 3. 不引入 SDK，S3 只做「预签名 PUT / GET」

`S3AssetStore` 不引 `@aws-sdk/client-s3`（压缩后约 1 MB、依赖树大）。只需要两件事：

1. **预签名 PUT**：浏览器直接把字节 PUT 到对象存储，不经本机服务；
2. **预签名 GET**：读的时候生成短期 URL。

SigV4 预签名是 Node `crypto` 的 HMAC-SHA256 加一段规范化请求，约 80–120 行，有公开测试向量可对照。**这是一项待确认的决定**：自写签名代码与引一个小库（如 `aws4`，约 3 KB）都能做，前者零依赖但要对；后者多一个依赖但要维护。

按 CLAUDE.md「未经确认，不引入重型依赖或自建基础设施」，**S3 适配器不在本次实现**，先把接口与本地实现做出来，签名方案单独确认。

### 4. 地址解析：三处入口都要认 `loomina://`

| 位置 | 现状 | 改为 |
| --- | --- | --- |
| 浏览器 `<img>` / `<video>` / `<audio>` | 直接吃 data URI | `loomina://` → `GET /api/asset/<hash>.<ext>`（服务端读盘流式返回，带 `Cache-Control: immutable`） |
| 渲染路由 `writeAsset` | 只认 data URI | 加 `loomina://` 分支：直接给本地路径，不再 base64 解码 |
| 导出包 / 发布包 | 带 data URI | 保持带字节（自包含是 P20 的要求），但由服务端从资产库读，不从日志读 |

`parseDataUri` 的调用点保持不变：遇到非 data URI 时走新分支，**旧项目的 data URI 继续可用**。

### 5. 迁移是显式动作，不是自动的

设置页「本地项目」区多一行：

> 素材 12 个 · 其中 9 个还在日志里（38.4 MB）。[把素材搬进资产库]

点下去：逐个 `data:` 资产 → `put()` → 写一条 `asset.updated { uri: "loomina://…" }`。**旧事件里的 data URI 不动**——日志只追加，重放时后面的 `asset.updated` 覆盖前面。日志文件本身不会因此变小，这一点要说清：界面写「搬完之后新素材不再进日志；旧事件里那份 base64 还在，要等日志压缩（未做）」。

不做自动迁移：一次几十兆的读写 + 几十条事件，自动跑会在作者没准备的时候卡住整个页面。

### 6. 垃圾回收只做「列出来」，不自动删

`asset.uri` 不被任何 `Shot.keyframes` / `Take.assetId` / `DialogueLine.audioAssetId` / `MusicCue.assetId` / `Character.sheet` / `referenceImages` / `Location.masterShotId` / `Prop` 引用时，记为「未引用」。

设置页列出未引用资产的数量与总大小，附「清理」按钮（两步确认）。**不自动删**：一个刚生成还没挂上去的 take、一次刚回滚掉的引用，都可能让它暂时看起来没人用。自动删会把作者刚花钱生成的东西删掉。

### 7. 授权与密钥

- S3 的 endpoint / bucket / region / AK / SK 只从 `.loomina/config.json`（0600）读，或从服务端环境变量读；**不回传前端、不进日志、不进 IR**。
- 能力接口 `/api/capability` 只说「对象存储：已配置 / 未配置」，不回任何凭据或 bucket 名。
- 预签名 URL 的 TTL 默认 10 分钟，最长 1 小时；URL 本身可以被转发，所以不用于长期引用。

## 理由

- **边界比实现重要**：S3 什么时候接、接哪家（OSS / COS / MinIO）都还没定，但「素材不写在日志里」这件事现在就能做，而且收益立刻兑现。
- **零依赖先跑**：本地实现只用 `fs`，不碰任何需要确认的东西。
- **不引 SDK**：只需要预签名，不需要 SDK 的对象模型、重试、分片上传。1 MB 的依赖换 100 行签名，在单人项目里不划算——但这条要用户点头。
- **迁移显式**：几十兆的读写必须在作者知情时发生。
- **回收不自动**：误删已花钱的资产，代价远高于多占一点磁盘。

## 后果

**正面**

- 日志回到「只记事实」的体积，撤销 / 回滚 / 重放全部变快。
- 素材体积上限从 MB 级提到 200 MB，音轨、配乐、视频导入的硬上限可以放宽。
- 渲染清单与队列状态文件不再带 base64。
- S3 接入时只换一个实现，IR 与界面不动。

**负面**

- **本机资产库不是备份**：清缓存、删 `.loomina/` 就没了，与现在一样。界面上要写「素材存在这台机器上，没有云端副本」。
- 浏览器读素材从「内存里直接拿」变成「一次 HTTP 请求」，首屏图会多一个往返（本地服务，代价很小）。
- 日志文件不会因迁移变小；真正的缩小要等日志压缩（未做）。
- 迁移期间可能同时存在 data URI 与 `loomina://` 两种地址，代码必须两条路都通。
- 导出包仍带字节，体积不变。

**跟进**

- 确认签名方案后做 `S3AssetStore`，并用 MinIO 做一次本地端到端验证。
- 日志压缩（把前缀折叠成快照）是独立议题，本次不做。
- 资产库的备份 / 导出成 zip 属于 F4 的后续。
- 代理视频（E7.2）与 depth 图（B13.3）落地后直接进资产库。

## 成本

| 项 | 估计 |
| --- | --- |
| 本地实现 | 0 元 |
| S3 存储（若接） | 标准存储约 ¥0.12 / GB / 月；一条 60 秒片子的素材按 200 MB 估，**约 ¥0.024 / 项目 / 月**；下行流量另计（预览与渲染下载） |
| 工程 | 接口 + 本地实现 2 天；三处入口改造 2 天；迁移与设置页 1 天；S3 适配器待确认后 2–3 天 |

## 验证（设计阶段口径）

- 单测：同一段字节 `put()` 两次得到同一个 `sha256` 与同一地址；超过 200 MB 被拒且不留残文件；`read()` 对不存在的地址返回 `null` 而不是抛错。
- 渲染：一份带 `loomina://` 素材的清单能渲染出成片，且不再触发 30 MB 的下载上限。
- 迁移：示例项目 12 个资产里 9 个是 data URI → 点迁移 → 资产 `uri` 全部变成 `loomina://` → 刷新后图还在 → 日志条数增加 9 条 `asset.updated`。
- 回收：删掉一条 take 后，它的视频资产出现在「未引用」列表里，但**不自动消失**。
- 浏览器：设置页显示素材数量、日志内体积、未引用大小；迁移后同一张定妆图仍能显示。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 直接上 S3，不做本地实现 | 部署方式未定、凭据未定；本地实现零依赖就能兑现大部分收益 |
| 引入 `@aws-sdk/client-s3` | 只需要预签名，不需要 SDK 的对象模型与分片上传；依赖体积与维护成本不成比例 |
| 素材继续放日志里 | 日志几十兆，撤销 / 回滚 / 重放都慢，体积上限被 base64 放大 33% |
| 自动迁移 data URI | 几十兆读写与几十条事件会在作者没准备时卡住页面 |
| 自动清理未引用资产 | 刚生成未挂载、刚回滚掉的引用都会看起来「没人用」，误删的是花了钱的东西 |
| 用 IndexedDB 存二进制代替文件 | 仍是浏览器内存储，服务端渲染读不到；且清缓存一样丢 |
| 把地址存成签名 URL | URL 会过期，IR 里存会变成「昨天能看今天不能看」 |

## 落地（H3.1 本机资产库，2026-11-12）

### 1. 两个新模块，职责分开

| 文件 | 跑在哪 | 做什么 |
| --- | --- | --- |
| `apps/web/lib/asset-uri.ts` | 浏览器 + Node（纯函数） | 地址解析与生成、mime ↔ 扩展名、`assetHref()` |
| `apps/web/lib/asset-store.ts` | 只在 Node | `AssetStore` 接口与 `LocalAssetStore` |

`asset-uri.ts` 必须是纯函数、不碰 `node:fs`：组件要 `assetHref()` 把地址换成 `/api/asset/…`，路由要解析地址读盘，两边共用同一套正则。

### 2. 扩展名与 mime 一一对应

`audio/webm` 落成 `.weba`，`webm` 留给视频。按扩展名反推 mime 是唯一的路径（`/api/asset/<hash>.<ext>` 的 `Content-Type` 只能这么来），所以一个后缀不能对应两种类型。

### 3. 生成路径按体积分流

`persistAsset()`：data URI 超过 **128 KB** 先进资产库，小图留在日志里。理由是收益与成本的比例——一个 HTTP 往返换几 KB 的 base64 不划算，而一张 2.4 MB 的定妆图值得。

写不进去**不抛错**：退回 data URI 仍然可用。刚花钱生成的东西不能因为资产库写失败而丢。

设置页的显式迁移用 `{ force: true }`：那里的承诺是「日志里的都搬走」，不该因为一张小图没到阈值就留在原地。

### 4. 渲染路由的 30 MB 上限要补一次

清单校验只算 data URI 的体积（资产库地址记 0，因为字节不在请求里）。`writeAsset` 读到本地文件后要再查一次 `stat().size`，否则资产库里的 500 MB 文件能绕过清单上限进 ffmpeg。

### 5. 导出仍自包含

预览 HTML、OTIO、发布包在导出前跑 `hydrateView()`：把 `loomina://` 读回字节换成 data URI。读不回来的**保留原地址并计数**，提示里写「有 N 个素材没读回来」，不假装导出包完整。失败按**地址**数而不是按引用次数数——同一段素材被四处引用时，坏一次只说「一个没读回来」。

### 6. 清理的两步确认由服务端给数

`DELETE /api/asset/store` 带 `dryRun: true` 只回「会删几个、多少字节」；界面把这两个数写进确认句，而不是拿客户端算出来的数字。清理白名单是**当前项目**里所有被引用的资产库地址。

### 7. 验证

- 单测 **837** 全过（IR 160 + gateway 28 + pipeline 51 + web 598），新增 21 条；`pnpm typecheck`、`next build` 全过。
- 接口：写入回 `loomina://assets/<sha256>.png`；读取 200 + `immutable`；不存在 404；目录穿越 400。
- 浏览器：定妆页挂参考图 → 设置页「还在日志里 3 个 · 182 KB」→ 迁移 → 「已进资产库 3 个」→ 定妆页 `src` 变 `/api/asset/66c1….png`、`naturalWidth` 96×96；孤儿文件清理确认句写「会删掉 1 个（约 6 B）」。
- 渲染：`loomina://` 素材提交后 `done`，ffprobe 540×960 / h264 / 1.000s，抽帧可见素材本身。
- **没验到的**：预览 HTML 与 OTIO 的读回字节——示例项目时间线上的素材还没有地址，导出物里没有素材，这一步只有单测覆盖。

### 8. 已知缺口

- 多项目共用同一个 `.loomina/assets/`，但清理白名单只来自当前项目。换项目后清理会删掉别的项目还在用的文件（记在 R49）。
- 文件被手工删掉时，界面只显示裂图，没有「这个素材丢了」的提示。
- 日志不会因为迁移变小；真正的缩小要等日志压缩。
