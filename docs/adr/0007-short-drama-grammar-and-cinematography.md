# ADR-0007 竖屏短剧语法与可量化摄影语言作为一等公民

- 状态：已接受
- 日期：2026-11-09
- 决策者：产品
- 关联：P1、P11、A2、I1–I5

## 背景

"故事好不好"是 AI 短剧的生死线，但照搬电影/长剧的叙事方法并不适配：

- 竖屏、单集 60–180 秒、移动端观看、强竞争的前 3 秒；
- 观众的耐心极短，需要高频信息增量；
- "光影"若只停留在提示词形容词，既不可复现，也无法形成产品能力。

## 决策

把两件事做成**产品内显式的一等公民**，而不是藏在提示词里：

### 1. 竖屏短剧语法
- 前 **3 秒钩子**（冲突/悬念/反差）。
- 每 **15–20 秒**一个信息增量或情绪转折。
- 结尾 **留钩**（下集/完播）。
- 竖屏构图规则：主体居中偏上、近景/特写为主、字幕安全区。
- 剧本医生（A2）按此语法诊断，而非三幕套话。

### 2. 可量化摄影语言
- 每个镜头由结构化参数描述：景别、机位、运镜、焦段、光圈、构图、光比、色温、实用光、LUT、颗粒。
- 参数由 **I5 编译器**转为模型提示词；也可反向从参考片抽取。
- 提供预设库（I1–I4），并允许用户自定义保存。

## 理由

- 这是《织光机》名字的承诺，也是与通用工具的核心差异。
- 参数化才能复用、对比、教学与自动化；形容词不能。
- 短剧语法决定了完播率，直接决定内容是否有分发价值。

## 后果

**正面**
- 生成结果更稳定、可解释。
- 形成可积累的"风格资产"（预设库、模板）。
- 剧本层与画面层有共同语言。

**负面 / 代价**
- 需要维护语法库与参数映射，工作量不小。
- 参数过细会吓退 C 端用户，必须收进"进阶"（准则 P10）。

**跟进**
- 先做最小参数集（景别/机位/运镜/光比/色温/构图），再扩展。
- 建立"参数 → 效果"的对照样例库，用于验证编译器质量。

## 替代方案

- **纯提示词风格控制**：不可复现、不可组合，否决。
- **完整电影摄影参数体系**：过于专业，背离 C 端，部分采纳。
