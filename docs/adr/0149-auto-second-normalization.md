# ADR-0149 成片响度自动二次归一

- 状态：已接受
- 日期：2026-11-12
- 决策人：用户 + Claude
- 关联：ADR-0099（混音与响度）、ADR-0143（分段响度）、C12

## 背景

ADR-0099 定了两遍 loudnorm：先量混音、再用 `measured_*` 线性归一到 −14 LUFS，输出后复核集成响度、真峰值与相位，偏离 ±1 LU 或真峰值 > −1 dBTP 即 fail 且不交付。

真实片子里复核不过并不少见：AAC 编码抬真峰值、混音前后素材电平差异大、loudnorm 的线性模式在 LRA 与目标差得远时会退回动态模式。每次不过，作者只能改配乐音量、重导一遍——而偏差其实只是几分之一 dB。

## 决策

1. **复核不过时先补一遍再判失败。** 渲染流程在第一次复核 `fail` 时计算修正量，够大就做一次「二次归一」，补完重新量响度与相位，用新结果出结论；仍不过才如实失败，错误写明「二次归一后响度仍不合格」。
2. **修正的是整片的线性增益，不是再跑一遍 loudnorm。** `correctionGainDb` 取「把集成响度拉到目标需要的 dB」与「真峰值还有多少余量」里更小的那个：响度不能靠顶破峰值换来。按 0.1 dB 取整，夹在 −12 … +6 dB。
3. **已经合格就不补。** 响度在 ±1 LU 内、真峰值 ≤ −1 dBTP 时返回 `null`，不为 0.05 LU 去重编码一遍。静音（≤ −70 LUFS）与量不到的值同样不补：没有可修的东西。
4. **只重编码音轨。** `secondPassAudioArgs` 对第一遍的成品做 `-c:v copy`、`-af volume=…dB`、AAC 重编码，容器元数据从输入继承（AI 标识、内容指纹不受影响）。整段重编码视频既慢，又会让已经压好的画面二次损失。
5. **结果如实记录。** `LoudnessReport.passes` 记 1 或 2；界面沿用现有的响度块，判定仍是 pass / review / fail 三态。

## 理由

- **失败应当留给真的修不好的情况**：几分之一 dB 的偏差不是作者的错，也不该让作者去猜「配乐是不是太响」。
- **峰值优先**：抖音 / 快手等平台会对过响的片子再做一次压制，顶破上限换响度反而更糟。
- **画面 copy**：二次归一的目的只是响度，画面没有任何理由再编一遍。
- **上限要有**：只补一次。再补就可能出现「响度达标、峰值又破，来回拉扯」的循环；一次补不动，说明素材本身有问题（削波、长时间静音），应该人来看。

## 后果

**正面**

- 轻微偏差不再导致整片作废，作者不用改配乐重导。
- 修正量、是否补过都记在报告里，复核结论可以追溯。

**负面 / 代价**

- 失败的成片多花一次音轨重编码（几秒级）。
- 如果偏差来源是配乐压得太狠，二次归一会把底噪一起抬上来；报告只说「补过一遍」，不判断听感。
- 修正量是线性估计：loudnorm 报的集成响度与真实主观响度不完全一致，补完可能仍差 0.1–0.3 LU（在容差内即可）。

**边界**

- 不做多声道 / 5.1、音效总线、句内压缩或限制器。
- 不重做第一遍的 loudnorm 参数选择（动态 / 线性），只做整体增益。
- 相位复核不过（反相 > 500ms）仍是 review，不触发二次归一——那是内容问题，不是响度问题。

## 验证

- `render-audio.test.ts` 新增 5 条：偏轻往上补 / 偏响往下压、峰值不足时以峰值为准、已达标与静音不补、修正量夹取、二次归一的命令只 copy 画面。
- ffmpeg 实测（2026-11-12）：−52.35 LUFS / −47.62 dBTP 的测试片补 +32 dB 后 −20.35 LUFS；补 +38.3 dB 后 −14.05 LUFS / −8.67 dBTP，画面仍为 360×640 h264。
