# ADR-0117：手改单条字幕（按整句覆盖断句）

- 日期：2026-11-11
- 状态：已采纳
- 关联：D2、ADR-0087、ADR-0115、ADR-0116

## 背景

字幕一直是**派生**的：`subtitleCues(line.text, line.durationMs, { maxChars })` 按标点断句，读模型现算，不落 IR（ADR-0087）。这对「换档位看效果」很好，但对**断句本身错了**的场景无能为力：

- 一个长句按标点切出来，中间那条只有两个字，一闪而过。
- 作者想要的是一个词组一行，自动断句按字数切在了词中间。
- 某句要强调，希望单独占一条。

原来唯一的办法是改台词原文加标点——这会连带改时长、改镜头，代价太大。

## 决策

### 1. 覆盖按「整句」存，不按单条 cue 存

新增一条事件：

```ts
{ type: "subtitle.updated"; at: string; lineId: Id;
  cues: { text: string; durationMs: number }[] | null }
```

`cues: null` 表示恢复自动断句。落到 `Project.subtitleOverrides: SubtitleOverride[]`，同一句只保留一条（重复写即覆盖）。

**为什么不按单条 cue 存**：cue 的 id 是 `${lineId}-${序号}`，序号是自动断句的产物。作者手改一条之后，如果又去改每行字数档位，自动断句的条数变了，序号与覆盖就对不上——覆盖会漂到别的字幕上。整句覆盖没有这个耦合：只要这句话被手改过，整句都以覆盖为准，档位不再影响它。

### 2. 覆盖里的时长是相对权重，不是绝对时间

作者改断句时并不知道每条该显示多久，让他手填毫秒是没必要的负担。界面按**字数**给初值，读模型再按比例缩放到整句的真实时长：

```ts
function fitCues(cues, totalMs) {
  const scale = totalMs / cues.reduce((sum, c) => sum + c.durationMs, 0);
  // 前 n-1 条按比例取整，最后一条吃掉舍入误差
}
```

- 整句时长是**事实**（来自台词 `durationMs`，它又决定镜头时长），手改字幕不能改它。
- 最后一条吃误差，保证 cue 时间之和严格等于 `line.durationMs`，与自动断句同一口径。
- 结果：SRT / ASS / 预览 / 渲染叠加层读的都是同一份 `view.cues`，改一处四处一起变。

### 3. 台词被删时，它的覆盖一起摘掉

`dialogue.removed` 除了摘台词与镜头引用，也过滤掉指向它的 `subtitleOverrides`。留着就是悬空数据：读模型按 `lineId` 查不到，但 `validateProject` 会多一条没人能修的孤儿。

### 4. 界面：点字幕条打开手改，拆 / 并 / 恢复

字幕条上每条字幕都可点：跳到那一句并打开手改面板。面板里：

- 每条一个字输入框，`拆` 从中间切成两条，`并` 把这条并进上一条。
- 「保存断句」写一条 `subtitle.updated`；「恢复自动断句」写 `cues: null`。
- 手改过的字幕在字幕条上带一个 `·` 前缀，title 里写「（手改过）」。

空字、没改动、本来就没覆盖时点恢复，都不写事件，`castError` 给一句话说明。

## 后果

- 断句不对时改字幕，不再需要改台词原文。
- 手改过的句子对字数档位免疫：切 12 / 16 / 20 只影响没改过的句子。
- 时间总和永远等于整句时长，时间线、渲染清单的硬校验不受影响。
- 一句话要回到自动断句，点一下就行，覆盖不留残渣。

## 验证

- 单测 773 全过（IR 154 + gateway 28 + pipeline 51 + web 540）。
  - IR 新增 5 条：整句覆盖不叠加、`null` 恢复、空字与非正时长被拒、指向不存在的台词被拒、删台词连带摘覆盖。
  - `edit.test.ts` 新增 4 条：时间按比例缩放且首尾相接、改档位不影响手改句、舍入误差落在最后一条、无覆盖时无 `manual` 标记。
  - `workbench-store.test.ts` 新增 5 条：写事件可回放、`null` 恢复、同内容不重复写、空字被拦、不存在台词与只读模式不写。
- `pnpm typecheck`、`next build` 全过。
- 浏览器（生产 3100，成片页，清空 IndexedDB 后重新播种示例）：字幕条 1 条「你早就知道，对吧。」；点开出现「手改断句 · 周 / 整句 2.6s」与 1 个输入框；改短后点「拆」变 2 行；「保存断句」后版本 v3 → v4，字幕条变 2 条且都带手改标记；再点开「恢复自动断句」→ v5，标记回到自动。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 按单条 cue id 存覆盖 | cue 序号随断句档位变，改档位后覆盖会漂到别的字幕上 |
| 覆盖里存绝对毫秒 | 作者无从知道该填多少；整句时长是事实，缩放到它上面就够了 |
| 手改时直接改台词原文 | 会连带改时长与镜头，为了断句动整条时间线，代价过大 |
| 把断句结果整体落进 IR（不再派生） | 改档位就得批量重写所有句子；派生 + 局部覆盖既保留了改档位的便利，又留了手改的出口 |
