# ADR-0130：字幕版式进 IR，导出三处共用一份

- 日期：2026-11-12
- 状态：已采纳
- 关联：D3、E6、D4、ADR-0086、ADR-0091、ADR-0117、R26

## 背景

ADR-0086 决策 6 定的是「字幕样式先做两档模板」：`默认` 与 `大字`，字号用 `cqw`、离底边 14% / 18%，并明确把「位置 / 字号微调」列进「未做」。

模板档位够用，但作者很快会遇到两种情况：

1. **画面本身有东西**：主角坐在画面下方三分之一，字幕压上去正好糊在脸上。
2. **平台界面**：底部操作栏、进度条、评论入口各平台高度不同，14% 在某些平台上仍然被挡。

这两件事都不是「换一档模板」能解决的，因为它们取决于这一条片子的具体画面。

## 决策

### 1. 版式进 IR，但只存「改过的项」

```ts
interface SubtitleLayout {
  preset: "default" | "large";
  fontSizeCqw?: number;
  bottomPct?: number;
  strokeCqw?: number;
}
```

三个数值都可选。缺省表示「跟着 preset 那档模板走」。

这样做的理由：如果把三个数值都存成实际值，那么**换档位就等于什么都没发生**——作者点「大字」，字号还是原来那个数，因为每一项都被旧值覆盖了。反过来只存改过的项，换档位时没调过的项跟着新档位一起变，调过的项留在原处。这是作者的心智模型，也是「模板」这个词的意思。

### 2. 越界拒绝，不夹取

字号 2–12 cqw、离底边 2–45%、描边 0–3 cqw。越界时 `applyEvent` 抛错，界面把原因显示出来。

夹取（`Math.min(max, value)`）看起来更友好，实际更糟：作者在表单里填了 200，界面静默改成 12，下次打开发现「我明明填的是 200」。填错了要看得见。

### 3. 清空用 `null`，不用 `undefined`

`subtitle.layout.updated { layout: { fontSizeCqw: null } }` 表示这一项回到模板值。`undefined` 过 JSON 会消失，写进事件等于「什么都没改」。

这条与 ADR-0124 里 `patch.performance = null` 是同一个理由，只是那次是清整块、这次是清单项。

### 4. 导出三处共用同一份

预览 HTML、ASS 字幕、成片 MP4 的叠加层，原来各自从 `SUBTITLE_STYLES[styleId]` 取。现在统一走 `EditView.subtitleStyle`：

```
Project.subtitleLayout ──┐
                         ├─→ subtitleStyleOf(preset, layout) → EditView.subtitleStyle
SUBTITLE_STYLES[preset] ─┘                                          │
                    ┌───────────────────────────────────────────────┼──────────────┐
                    ↓                                               ↓              ↓
           buildPreviewHtml                                    buildAss      subtitleOverlays
```

导出函数仍接受 `SubtitleStyleId | SubtitleStyle`：传字符串就是那一档模板，传对象就是算好的样式。旧调用点（测试与外部脚本）不用改。

### 5. 发布包记下实际值

`PublishPackage.subtitleLayout` 写的是**实际画出来的三个数**，不是「改过的那几项」。发布包是给外部看的结果，读者关心的是「这条片子的字幕多大、离底边多远」，不是「作者改过哪几项」。

## 为什么不做的部分

- **自由拖拽定位**：ADR-0086 当时把「字幕样式做成自由拖拽」列进「不做」，理由是「当前没有渲染管线承接自由布局」。现在渲染管线有了（ADR-0091），但拖拽定位需要一套坐标系统、吸附规则、多行换行后的重排，收益对单人项目不成立。滑块的粒度已经覆盖真实需求：避开脸、避开操作栏。
- **按角色分样式**：两个角色同时说话时区分样式，是配音与字幕都要改的事，归 C 系列后续。
- **逐字动画**：归 E8（关键帧动画）。

## 后果

- `LOG_VERSION` 从 2 升到 3。`v2ToV3` 是空实现：`subtitleLayout` 有 zod 默认值，旧日志不用改形状。
- 新增事件类型 `subtitle.layout.updated`。`EVENT_TYPES` 必须加，否则旧日志读回来整份判废（2026-11-10 漏 `dialogue.updated` 的教训）。
- 历史抽屉里显示人话：「字幕版式：字号 6.4、离底边 22%」「字幕版式：模板「大字」」。
- 同一个值不重复写事件：拖滑块时每一步都记一条，日志会被噪声灌满。
