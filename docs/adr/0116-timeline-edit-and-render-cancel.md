# ADR-0116：时间线删段 / 换位，与渲染任务取消

- 日期：2026-11-11
- 状态：已采纳
- 关联：E1、H2、ADR-0086、ADR-0093、ADR-0106

## 背景

- **E1**：时间线能初剪、能换 take，但**删不掉一段、也挪不动顺序**。自动初剪出来的顺序不对，只能整条重来。
- **H2**：队列能排队、能重启恢复，但**取消不了**。点错了导出、或者发现参数不对，只能等它跑完。

两条都缺「收回」的能力。

## 决策

### 1. 时间线的起点永远由顺序推出，不给自由拖拽

渲染清单有一条硬校验：片段累计时长必须等于全长（`validateRenderManifest`）。自由拖起点会留空隙，导出直接 400。所以时间线的一切改动都走同一个重排函数：

```ts
function restack(items: TimelineItem[]): TimelineItem[] {
  let cursor = 0;
  return items.map((item) => {
    const next = { ...item, startMs: cursor };
    cursor += item.durationMs;
    return next;
  });
}
```

- **删这一段**：摘掉后整体前移。
- **← 前移 / 后移 →**：与相邻段交换位置后重排。

两者都只写一条 `timeline.updated`（整条替换，与初剪、换 take 同一套事件）。边界上（第一段前移、最后一段后移）按钮直接禁用，不写事件。

**为什么不做自由拖拽**：真正的自由时间线意味着允许空隙与重叠，那就得先决定「空隙渲染成什么颜色、重叠谁盖谁、导出的全长怎么算」——这些是 NLE 的语义，不是 60 秒竖屏短剧需要的。当前模型下，「顺序对了，片子就对了」。

### 2. 删一段不等于删 take

时间线上的一段是「这一镜用哪一拍」。删掉它，take 还在镜头里，重新初剪能排回来。这与 B5 的「删这一拍 take」是两件事，界面上分开：分镜台删的是拍，成片页删的是段。

### 3. 取消渲染：排队中摘掉，正在跑杀掉 ffmpeg

新增 `DELETE /api/render?job=`：

| 状态 | 处理 |
| --- | --- |
| `queued` | 从队列里摘掉，不启动 |
| `running` | 杀掉正在跑的 ffmpeg（`activeChild.kill`），清掉工作目录 |
| `done` / `error` | 409，取消一个已经结束的任务没有意义 |

关键细节：**取消不能写成「渲染失败」**。失败分支里查一个 `cancelled` 标记，命中就写「已取消 · 没有交付半成品」，否则才是 ffmpeg 的真实报错。否则历史里会留下一堆看起来像 bug 的失败。

客户端：`exportMp4` 多一个 `onJob` 回调，拿到任务号就存进组件状态；渲染中出现「取消渲染」按钮。取消后轮询会收到 `status: "error"` 与「已取消」文案，正常收尾。

### 4. 断点续渲仍然不做

ffmpeg 中途被杀或进程退出，已经编出来的部分不是合法 MP4 的完整帧序列，续渲需要分段编码 + 拼接，是另一套架构。当前做法保持：重启后 `queued` 恢复排队，`running` 明确标「重启中断 · 没有交付半成品」。**取消**是作者主动收回，**断点**是系统能力，两者不混。

## 后果

- 自动初剪顺序不对时，不用整条重来：挪两下、删一段就行。
- 渲染点错了能立刻收回，队列不会堵着一条不想要的任务。
- 取消与失败在历史里分得清：一个是「我不要了」，一个是「它没成」。
- 时间线仍然不允许空隙：这是有意的约束，写在按钮 title 与本文里。

## 验证

- 单测 757 全过（IR 149 + gateway 28 + pipeline 51 + web 529）。
  - `workbench-store.test.ts` 新增 4 条：删片段后首尾相接、挪片段交换顺序且重排、边界不写事件、删不存在的片段返回 false。
- `pnpm typecheck`、`next build` 全过。
- 浏览器（生产 3100，成片页）：时间线两段 SH-01 / SH-02；选中第一段，「← 前移」禁用、「后移 →」「删这一段」可用；点后移 → 顺序变 SH-02 / SH-01、版本 v10 → v11；删这一段两步确认后只剩 SH-02、版本 → v12。
- `DELETE /api/render?job=nope` → 404；缺任务号 → 400。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 允许自由拖动起点 | 会留空隙，渲染清单校验直接失败；要支持就得先定义空隙渲染成什么，超出 60 秒短剧的需要 |
| 删段时连 take 一起删 | 删段是「这条时间线不要它」，删拍是「这一版不要了」；混在一起会让重新初剪排不回来 |
| 取消也记成 `error`，不区分 | 历史与面板会把「主动取消」读成「渲染失败」，看起来像 bug |
| 做断点续渲 | 需要分段编码 + 拼接，是另一套架构；重启恢复排队已经覆盖大部分场景 |
