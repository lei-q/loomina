# ADR-0066 这一镜里有哪些道具：道具点名进 `propIds`

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0030（道具引用）、ADR-0029（锚点）、ADR-0040（提示词可见）、ADR-0057（过期）、ADR-0065（人物出场）、FEATURES B2 / B8

## 背景

`Shot.propIds` 与 `characterIds` 一样，是「这一镜里有什么」的一部分：它决定提示词里写哪件道具、锚点带哪张道具参考图、出图后改它会不会挂 `过期`。但和人物此前的情况一样，它只存在于示例数据里——两件道具、两个镜头写着它，界面没有任何地方能改。ADR-0064 新建出来的镜头道具为空，用户无从下手；拍一场「杯子一直在」的戏，只能回去改数据。

人物签（ADR-0065）已经证明「点名即出场」这个做法在这个舞台上成立：点一下、提示词与锚点立刻变。道具与人物结构相同（都是 `shot` 的 id 数组，都进锚点与提示词），没有理由两套交互。

## 决策

1. **`store.toggleShotProp(shotId, propId)`**：一件道具一枚签，点一下加入或移出 `shot.propIds`，写一条 `shot.updated { propIds }`。加入时追加到末尾——**道具顺序就是点名的顺序**，先点的排在提示词前头。
2. **校验**：
   - 镜头不存在 / 道具不存在 → 拒绝并命名（「找不到这一镜。」/「找不到这件道具。」）。
   - 镜头已锁定 → 拒绝：「这一镜已锁定，先解锁再改出场道具。」
   - 与人物不同，**没有任何「不能拿掉」的约束**：道具没有台词，拿掉它只影响画面与参考图，不会留下自相矛盾的东西。最后一件也拿得掉。
3. **界面**：`出场` 行下面再一行 `道具`，同样的小签（未出场描边灰、出场实底），位置仍夹在提示词折叠区与 `锚点` 之间。锁定的镜头与只读标签页置灰，悬停说明原因。道具没有「全部列出」以外的筛选——现在就两件，多了再说。
4. **不新增事件类型**：道具是镜头自己的字段，`shot.updated` 已够（同 ADR-0065）。
5. **不联动场景 / 道具库**：这里只决定「这一镜有没有它」，不改道具本身的名字、描述、参考图（那是定妆页的事）。
6. **`propIds` 已经在 ADR-0057 的画面字段表里**：改道具与改人物一样，会让已出的帧挂 `过期`，这次的界面自然接上。

## 理由

- **与人物同一套**：同一位置、同一手感、同一事件语义；用户学会一个就会两个，代码也只多一个分支。
- **道具不受台词约束**：人物被台词挡住是因为「画面里没人、字幕里有话」；道具没有这个对应物，挡住只会让操作变烦。
- **顺序有意义**：提示词按 `propIds` 顺序列道具，先点的主道具排在前面，和人物签一样能调主次。
- **锚点紧挨着**：签是输入、锚点是结果；`搪瓷杯 · 参考图` 就在下一行，点完立刻能核对，而不用去定妆页找。
- **锁定即冻结**：与动作、台词、机位、人物一致（ADR-0041）。

## 后果

**正面**
- 分镜页 SH-01 点 `搪瓷杯` → 签点亮，提示词多出「道具：搪瓷杯，白底蓝边搪瓷缸，杯沿有一道旧磕痕」，`锚点` 行出现 `搪瓷杯 · 参考图`；日志一条 `shot.updated { propIds: ["p-cup"] }`。
- SH-02 点掉 `台灯` → 提示词与锚点同步减少；没有「还有台词」一类的阻挡。
- SH-05（已锁定）上两枚签都是灰的，悬停写「这一镜已锁定，先解锁再改出场道具」。
- 改完道具后，已出的帧挂 `过期` 小签（ADR-0057 早已认 `propIds`）。
- 测试：web 168 条（新增 3 条：点道具 + 提示词 / 锚点 / 回放；拿掉道具不受台词约束；锁定 / 陌生 / 只读拒绝）；IR 76、gateway 17、pipeline 22；合计 283。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：SH-01 点 `搪瓷杯` → 锚点出现 `搪瓷杯 · 参考图`，提示词里出现道具句；IndexedDB 多一条 `shot.updated { propIds }`。

**负面**
- **不能新建道具**：道具库仍只有示例的两件，要加只能改数据；人物有定妆页、地点能新建，道具还没有。
- **没有道具自己的页**：名字、描述、参考图都不能在界面上改。
- **能点的道具不限场次**：所有道具都列在每一镜上，镜头多了以后一排签会长；没有按场景筛选或搜索。
- **两排签把舞台撑高了**：1440×900 下要往下滚 62px 才看得全 `道具` 与 `锚点` 两行。
- **锁定后要解锁才能改道具**：与人物一致，一笔修正也是两条事件。

**跟进**
- 道具库：新建 / 改名 / 描述 / 参考图（与地点 ADR-0059 / ADR-0063 同构）。
- 道具签按场景筛选（比如只列这一场用过的）。
- 出场顺序拖动（人物与道具一起）。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 新事件 `shot.props.updated` | 道具就是镜头字段，`shot.updated` 已经够；多一种事件让 ADR-0057 的过期判据也要多认一种 |
| 与人物共用一行「出场」，用图标区分 | 小人头与杯子混在一排，读起来先要想「这是什么」；分成两行各自有标签更直接 |
| 道具签放定妆页，按道具反查镜头 | 用户在这一镜上想的是「这一镜有没有杯子」，跨镜的道具视角解决不了 |
| 拿掉道具时检查锚点预算 | 拿掉只会减少引用，不会超预算；没有理由挡 |
| 只允许加到「这一场用过的道具」 | 现在没有「场次用道具」的概念，硬造一个筛选会把简单的事变复杂 |
