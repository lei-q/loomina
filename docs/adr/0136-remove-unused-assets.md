# ADR-0136：没人引用的资产可以删

- 日期：2026-11-12
- 状态：已采纳
- 关联：F4、H3、ADR-0128、ADR-0132

## 背景

F4 的资产库页面（ADR-0128 落地节）明确写了：

> **只列不删**。删素材是花钱买来的东西，得有一个明确的删除入口与两步确认，那属于「批量删除」的下一步；这里先把「看得见」做出来。

于是出现一个说不通的状态：设置页有「清理没人引用的文件」，会把盘上的孤立文件删掉；但项目里的**资产记录**删不掉。清理之后资产库页面会把这些条目全部标成「文件缺失」，因为它们还挂在 IR 里，地址却已经没文件了。

## 决策

### 1. 一条 `asset.removed`，只删记录

```ts
{ type: "asset.removed"; at; assetId }
```

handler 删 `assets` 里那一条。盘上的文件**不在这里删**——两件事分开：

- 删记录：改的是项目内容，可回放、可撤销（撤销删除还没接，见下）；
- 删文件：动的是磁盘，不可回放，走设置页那个显式动作（`DELETE /api/asset/store`，带 `keep` 白名单）。

如果合并成一个动作，就会出现「文件删了、记录还在」或「记录删了、文件还在」的半截状态，而两种状态都会让「文件缺失」这个提示失去意义。

### 2. 只在确实没人引用时允许

`referencedAssetIds(project)` 逐个引用点查过才写事件，handler 里不再查（它拿不到引用关系）。store 先拦、给出人话：

> 这条资产还在用：先把它从引用它的地方摘掉，再删。

这条检查是**必须的**，不是保险：刚生成还没挂上的资产、刚回滚掉的引用，在「没人用」这个判断下看起来完全一样。批量删除的入口正建立在「没人用」这个筛选上，一旦这里放过，就会删掉作者刚花钱生成、还没来得及挂的东西。

### 3. 两步确认，与删场 / 删镜同一规矩

界面上没人用的行末尾出现「删」，点一下变成「确认删 / 取消」（ADR-0067 的做法）。确认后回执说清两件事：

> 删掉了 a-orphan-test。盘上的文件还在：「清理没人引用的文件」会把它一起清掉。

这句话不是客套：不说的话，作者会以为删记录就等于释放了空间。

### 4. 单条删除，不做批量

资产库页面的筛选已经把「没人用」收窄到通常 0–3 条。批量删除要先有「选中多条」的交互，而当前清单最长十几条，逐条点比勾选更不容易误删。等真的出现几十条孤儿再谈批量。

## 为什么不做的部分

- **撤销删除**：`asset.removed` 是纯删除事件，回收站（ADR-0109）目前只认 `character / prop / location / shot / scene` 五种。要把资产加进去，得先回答「恢复一条资产记录时，它原来的引用关系要不要一起回来」——记录本身没有引用方，回来的只是一条没人用的资产，意义有限。当前用「重做一次」代替。
- **批量删除**：见决策 4。
- **删记录时顺手删文件**：见决策 1。
- **日志压缩**：`asset.removed` 之后旧事件里的 `asset.updated` 还在，日志不会因此变小。压缩是另一件事（F2 的范围）。
- **删除已发布包引用的资产**：`referencedAssetIds` 把发布包算作引用点，所以这类资产删不掉——这是对的：发布记录是历史事实，不能因为清理素材而指向空。

## 后果

- 新事件 `asset.removed`；`EVENT_TYPES` 必须加（2026-11-10 的教训）。
- `LOG_VERSION` 不升：纯新增事件类型，旧日志里没有它，读回来照样合法。
- 历史抽屉显示人话：「删掉没人用的图片 a-orphan-test」。
- 资产库页面的没人用行末尾多一个「删」，两步确认。
- 设置页的「清理没人引用的文件」与这里的「删记录」是配套的两步：先删记录，再清文件，资产库页面才不会留下「文件缺失」。
