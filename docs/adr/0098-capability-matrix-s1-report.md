# ADR-0098：模型能力矩阵与 S1 测绘报告（B12 / H16 第一版）

- 状态：已采纳
- 日期：2026-11-11
- 关联：B12、H16、H11、B6、R22、R28、ADR-0025、ADR-0094、ADR-0097、MODEL-GATEWAY.md、COST.md

## 背景

`ARCHITECTURE.md` §6 和 `OPERATIONS.md` §5 都要求一张模型能力矩阵：时长、分辨率、首尾帧、参考图、运镜、并发、延迟、单价、商用条款，并说明它「直接决定网关路由与降级链」。

现实是：仓库能确定的东西只有三类。

1. **代码实际发送的字段**。视频适配器把首帧放进 `content[].image_url`，`seconds` 取整、不传 seed、没有尾帧字段；图像适配器只发文本，不收参考图；文本适配器只带 `model / messages / max_tokens`；配音只带音色与 mp3 格式；识别用 multipart 上传音频。
2. **已保存配置里的值**。分辨率、音色、供应商与模型名。
3. **价目表与 S1 测绘**。`packages/gateway/src/pricing.ts` 只收能换算成每秒 / 每张的模型；`artifacts/s1/probe-*.json` 记录真实尝试、通过、花费与失败码。

供应商侧的能力、并发、延迟、商用条款，代码测不出来。S1 至今只跑过三次，分别被 `deadline_exceeded`、`503`、`429` 挡住，没有一次成功样片。把「应该支持」写成「支持」，就是在拿猜测冒充测绘。

因此这一版只做**能如实做到的部分**：把代码能力、配置值、价目和最近测绘放在一张只读矩阵里；测不出来的明确写「未测」，查不到的价写「未知」，没写的商用条款标「未确认」。

## 决策

### 1. 能力矩阵只写三类来源

新增 `apps/web/lib/capabilities.ts`，纯函数 `buildCapabilityMatrix(config, probes)`。每条能力带 `source`：

| source | 含义 | 例子 |
| --- | --- | --- |
| `code` | 当前网关 / 适配器实际发送或明确不发送 | 首帧支持、尾帧不支持、1–8 秒、无 seed |
| `config` | 来自已保存的模型配置 | 分辨率 768p、音色「小满」 |
| `unknown` | 没测过或供应商说了算 | 并发、延迟、上下文窗口、音频格式 |

按模态列出的事实：

| 模态 | code 能确定 | 明确未测 |
| --- | --- | --- |
| 视频 | 首帧作为 `content[].image_url`；无尾帧；无多参考图；1–8 秒按整秒提交；运镜只进 prompt；不传 seed；无音频输入 | 并发、延迟 |
| 图像 | 只走文本生成，不收参考图；不传 seed；一次一张；尺寸由服务端 `IMAGE_SIZE` 决定 | 并发、延迟 |
| 文本 | JSON + zod 校验；故事生成 `max_tokens` 16000，其它调用不设；不传 temperature；未用流式 | 上下文窗口 |
| 配音 | 音色、mp3 输出；请求里没有语速 / 情绪；不提供声音克隆 | 长文本上限 |
| 识别 | multipart 上传音频；请求 `verbose_json`，供应商不给分段就空数组；默认 `zh` | 支持的音频格式 |

这些是「管线实际怎么发」，不是「模型理论上能做什么」。例如供应商文档说支持 seed，但网关没传，矩阵就写不支持——因为从本产品发出去的视频确实没有 seed。

### 2. 单价只从唯一价目表取，查不到就写未知

- 视频：`videoPrice(model, resolution)`；图像：`imagePrice(model)`。
- 有价目时显示「¥0.50 / 秒 · minimax-h3 @ 768p」或「¥0.12 / 张 · gpt-image-2-c」。
- 没填分辨率、分辨率不在表里、按 token 计价（seedance 系列、文本）都返回 `{ kind: "unknown", reason }`，界面直接显示原因。
- 不在前端复制价目，也不把 token 模型换算成「大约多少钱」。估不出来的价格不是价格（准则 P21）。

当前配置 `minimax-h3 @ 720p` 就查不到——价目表只有 768p / 2k。矩阵会如实写「价目表里没有 minimax-h3 @ 720p」，而不是借 768p 的价格。

### 3. S1 报告只读汇总字段

新增 `apps/web/lib/probes.ts`：

- 默认读 `LOOMINA_PROBE_DIR` 或仓库 `artifacts/s1`，只接受 `probe-*.json`。
- 每份报告收敛成 `{ file, startedAt, videoModel, imageModel, videoApi, resolution, attempts, passed, passRate, totalCny, avgCnyPerShot?, failureCodes }`。
- **不返回** `config.baseUrl`、逐镜 `error.message`、任何密钥。
- 解析失败的文件跳过；按 `startedAt` 倒序取最近 5 份。
- `passed` 不超过 `attempts`；通过率与单镜均价由读取端重新算，不盲信文件里的值。

匹配规则：视频按真实模型名匹配，分辨率相同才算 `exact`；不同则仍显示报告，但用醒目文字写「报告是 768p，本模型配的是 720p」。图像只按模型名匹配。文本 / 配音 / 识别没有 S1 产物，直接写「还没有报告」。

### 4. 商用条款是配置里的一条人工备注

`ModelRecord` 增加可选 `terms?: string`（240 字以内），设置页每个模型多一个「商用条款 / 备注」输入框，保存进 `.loomina/config.json`，能力矩阵原样显示。

- 写了就显示原文，例如「商用需单独申请，2026-11-01 已邮件确认」。
- 没写就显示「未确认 · 需人工核对供应商条款」，并在矩阵顶部计数。
- 这不是自动核验，也不改变 R22 的状态；它只是把已经知道的事实留在一个下次还能看到的地方。

### 5. 一个只读接口与设置页区块

- `GET /api/capability`（Node runtime，`no-store`）：从已保存配置生成矩阵，附最近 S1 报告。响应里只有供应商 `id / name`，没有 `apiKey` 与 `baseUrl`。
- 设置页底部新增「能力矩阵（B12 · H16）」：按模态分组，每个模型一张卡，显示单价、能力事实、商用条款、匹配到的 S1 报告；下方列出最近 5 次测绘。
- 区块明确写「读的是已保存的配置」「供应商侧没验证过的标未测」「不参与路由或降级」。保存配置后自动重新拉取。

### 6. 矩阵暂不参与生成决策

`ARCHITECTURE.md` 的最终目标是「矩阵决定路由与降级链」。这一版**不做**：

- 不按矩阵自动选模型；
- 不按失败率自动降级；
- 不在生成前用矩阵拦请求；
- 不把并发 / 延迟 / 真实通过率写回配置。

原因：S1 没有成功样片，失败码只有 `deadline_exceeded` / `503` / `429` 三种外部阻塞，没有足够数据支撑任何自动决策。先让人看见已知与未知，再谈自动路由。

## 非目标

- 供应商侧能力探测（首尾帧、参考图、运镜是否真的生效）。
- 并发、延迟、上下文窗口、音频格式的标定。
- token 计价模型的单价换算。
- 商用条款自动核验或法务判断。
- 按能力矩阵路由、降级、拦预算。

## 理由

- **诚实优先**：矩阵的价值是让人知道「哪些是确定的、哪些还没测」，不是把所有格子填满。把 unknown 填成「支持」会在出片失败时误导排障。
- **单一来源**：价目继续只存在于 `packages/gateway/src/pricing.ts`；S1 继续只写 `artifacts/s1`；能力矩阵只是读，不产生第二份真相。
- **低成本可逆**：`terms` 是可选字段，旧配置文件不需要迁移；接口与页面只读，删掉也不影响生成链路。
- **为下一步留接口**：报告读取与能力形状已经独立成纯函数，将来把真实通过率写回 `ModelPrice` 或路由表时，不需要重做界面。

## 后果

- R22（商用条款不明确）继续「未处理」，但现在有一个地方记录已确认的条款，并在未确认时计数。
- R28（token 计价未知）在文本 / 配音 / seedance 视频上继续存在；矩阵显示「未知」而不是估值。
- 设置页变长；能力矩阵在「模型」之后、页脚之前，读的是已保存配置，未保存的改动不会出现在矩阵里。
- `terms` 会写进本机配置文件并出现在 `GET /api/config` 的 `models` 里；它是用户主动填写的公开备注，不应放密钥。
- 视频分辨率不进价目表时，矩阵会持续提示「单价未知」。这是配置与价目表不一致的真实信号，不是读取 bug。

## 验证

- `pnpm typecheck` 全仓通过。
- `pnpm test`：web 363 个测试通过，其中新增 `capabilities.test.ts` 9 个、`probes.test.ts` 6 个，`app-config.test.ts` 增加 1 个条款备注用例；pipeline 30 个通过。
- `pnpm --filter @loomina/web build` 通过，路由表出现 `/api/capability`。
- `GET /api/capability` 实测：5 个模型、3 份 S1 报告、5 个条款未确认；`gpt-image-2-c` 显示 ¥0.12 / 张；`minimax-h3 @ 720p` 显示价目表没有；视频报告标出 768p 与配置 720p 不一致。
- 无头 Chrome 打开 `/settings`：能力矩阵按文本 / 图像 / 视频 / 配音 / 识别分组，5 张卡与 3 行报告都在；每个模型行有「商用条款 / 备注」输入框，输入后受控值保留；页面截图 `/tmp/capability-top.png`、`/tmp/capability-reports.png`。
