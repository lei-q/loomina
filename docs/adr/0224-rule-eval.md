# ADR-0224：规则评测集先做正反例回归，不做阈值标定（I9 第一档）

- 状态：已采纳
- 日期：2026-11-14
- 决策者：用户 + Claude
- 关联：I9、I8、I11、A13、ADR-0216、DIRECTOR-GRAMMAR.md §十一

## 背景

DIRECTOR-GRAMMAR.md §十一 定义了完整的评测方法：30 个真实短剧片段、每条 must 规则配
2 正 2 反、五项指标（违规率 / 人类偏好 / 景别多样性 / 成本 / 生成成功率）。

问题在于**素材**：30 个片段需要授权素材或自制拍摄，单人项目当前没有。
如果等素材齐了再做，规则库就一直处在「写了但没验过」的状态。

但有一件事不需要素材就能做：**验证每条规则的判定方向没写反**。
「连续三个同景别该报」这条，是报了还是没报，构造一个小项目就能测。

## 决定

1. **`rule-eval.ts` 三件套**：
   - `EvalCase`：一个小项目 + 期望命中 / 不该命中的规则编号 + `kind: positive | negative`；
   - `runCase`：跑 `analyzeStoryboard`，逐条比对期望，失败时写清「期望什么、实际什么」；
   - `runEvalSuite`：跑全套，算指标与缺口。
2. **`EVAL_CASES` 放在生产代码里**（不是测试文件）：CLI 要能引用它，
   测试只做断言。用例的构造工厂 `makeProject` 默认值刻意挑成「什么都不违规」。
3. **给每条 must 规则配一正一反**：V1 建立镜头、V2 台词承载、V3 轴线近似、V4 镜头时长、
   V6 同景别连续、V11 节拍顺序——六条全覆盖，`rulesMissing` 为空。
4. **三项指标**：
   - **违规率**（每 100 镜命中数）：反例项目里该规则命中数 / 总镜头 × 100；
   - **景别熵**（香农熵，以 2 为底）：全同一种景别为 0，四种均匀为 2；
   - **用例通过率**与**规则覆盖数 / 缺口**。
5. **`pnpm eval:rules` CLI**：打印摘要与失败详情，有失败时退出码 1，可直接挂 CI。
6. **不做的**：阈值标定（「同景别连续 ≤ 2 还是 ≤ 3」）、人类偏好 A/B、真实片段素材。

## 理由

- **先验方向，再标阈值**：方向写反是低级错误但代价极高（规则库整个失效），
  用零素材就能测；阈值标定需要真实片段，是另一档的事。
- **用例进生产代码**：CLI 是给作者用的工具（「我的规则库还自洽吗」），
  不是只给 CI 看的测试。测试文件里的常量没法被 CLI 引用。
- **一正一反而不是只有反例**：只测「该报的报了」会漏掉「不该报的乱报」——
  后者在真实使用里更烦人（作者被误报淹没后就不看检查结果了）。
- **景别熵用香农熵**：文档说「不低于参考片」，但参考片没有；先给出可计算的数，
  将来有了参考片段再定阈值。

## 后果

**正面**

- 六条 must 规则有了回归保护：改动判定逻辑时，方向写反会立刻被 `pnpm eval:rules` 抓到。
- 指标可计算、可对比（改规则前后跑一次就知道变化）。
- **CLI 一跑就暴露了缺口**：第一次运行报「V3 是 must 但还没有用例」，
  补上后才清零——这正是评测集该有的作用。

**负面 / 代价**

- **只有 6 / 12 条规则有用例**：V5 / V7 / V8 / V9 / V10 / V12 是 should 或需要外部输入
  （报价、网关能力），没配。
- **没有阈值标定**：违规率 27.27 / 100 镜这个数没有对照基准，只能前后比。
- 景别熵 1.58 bit 同理，不知道「多少算好」。
- 用例的项目都是构造出来的小样本，不代表真实片子的分布。
- 人类偏好 A/B 完全没做——那需要真实片段与评分者。
