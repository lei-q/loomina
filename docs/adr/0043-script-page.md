# ADR-0043 剧本页：先把写过的东西读顺

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：DATA-MODEL（Scene / Shot / DialogueLine）、ADR-0026（审片台）、UX 5.9、FEATURES A21

## 背景

顶栏「剧本」一直是死链。项目的场次、镜头动作、台词都在 IR 里，但从界面只能一镜一镜在分镜页看；想在整条片子的尺度上读一遍"写了什么"，没有地方。分镜页给的是审片视角（画面、take、报价），不是阅读视角。

## 决策

1. **做一个只读剧本页** `/script`：按场次、场内镜序摊平，每镜依次是动作、台词、景别 / 机位 / 时长。
2. **只读模型的投影**：`toScriptView(project)` 复用 `toStageView` 的整片镜号与景别翻译，从 IR 的 `scenes` / `shots` / `dialogue` / `characters` / `locations` 组装；组件不碰 IR。
3. **不写事件、不提供编辑**：这一页没有输入框，没有保存按钮。台词编辑（A5）会是另一条带事件的动作，届时复用同一份读模型。
4. **版式照着剧本的阅读顺序**：场头（`第 n 场 · 地点 · 时长 · 镜数`）、镜号缩窄列、动作正文、台词缩进带说话人小字、底部一行技术信息（景别 · 机位 · 时长）。
5. **页头给四个数**：场、镜、台词条数、总时长——回答"这条片子的体量"。
6. **导航接上**：「剧本」从死链变成 `/script`，当前页高亮；「故事」「声音」「成片」仍是死链，等各自的页面。

## 理由

- **先有阅读，再谈编辑**：读不顺的剧本，编辑界面只会是表单堆。
- **同一份 IR**：不在页面里维护第二份剧本格式；分镜页改了时长、机位，剧本页刷新就跟着变。
- **只读是诚实的边界**：现在没有台词 / 动作的编辑事件类型，按钮点了只能改界面状态、刷新即丢——不如不放。

## 后果

**正面**
- 顶栏第二个阶段从死链变成页面：五场、十二镜、四条台词、32.1 秒一屏读完；动作与台词按镜序排，整片镜号（SH-05 不会因为第二场第一镜而变成 SH-01）。
- 台词带说话人（周 / 林），下方技术行说明景别与机位；分镜页改过的时长（SH-06 3.7s）在这里同步。
- 测试：web 92 条通过（新增两条：场次 / 镜序 / 说话人 / 台词计数、没有台词的镜头不编台词且镜号用整片顺序）；`pnpm typecheck`、`pnpm build` 通过（路由表出现 `/script`）。

**负面**
- **只读**：不能改动作、改台词、加场次；要改只能回分镜页说，或者等 A5。
- **场头信息薄**：只有地点名，没有"内 / 外景、日 / 夜"；Location 还没有这些字段。
- **台词没有配音**：只显示文字与时长，声音与字幕要等 C1 / D3。
- **没有导出**：不能打印、下载成文本 / PDF；导出按钮仍是摆设。
- **长片会很长**：没有折叠场次或按场跳转。

**跟进**
- A5 台词编辑：给 `DialogueLine` 一个 `dialogue.updated` 事件，依然是"一条动作一条事件"。
- 场头加内 / 外景与时间（Location / Scene 字段）。
- 剧本视图折叠、按场跳转、导出纯文本。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 在分镜页里加"剧本模式"开关 | 审片与阅读是两种视角，挤在一页会让两边的动作都变挤 |
| 把台词与动作放到新的存储里 | IR 已经是事实来源，复制一份必然分叉 |
| 这一轮顺便做台词编辑 | 没有 `dialogue.updated` 与校验，做出来只是界面上的假编辑 |
| 用富文本 / Markdown 渲染 | 现在的内容是结构化的镜与台词，不是自由文本；富文本会丢掉与镜号的对应 |
