# ADR-0085 配音：一句一条音轨，时长以音轨为准

- 状态：已接受
- 日期：2026-11-11
- 决策人：用户 + Claude
- 关联：ADR-0003（音频先行）、ADR-0044（台词时长）、ADR-0084（默片预演）、C1、C8

## 背景

预演（ADR-0084）已经把画面与字幕连起来播了，但没有声音。ADR-0003 把配音定为音频先行：对白的节奏、停顿与情绪是这条片子成立不成立的一半，字幕判断不了。

供应商这边目前只有 `qwen-audio-3.0-tts-*` 一类 TTS 模型，实测 `POST /v1/audio/speech` 返回 403 `No authorized bound group supports this request`——**模型列得出来，分组没授权**。也就是说：链路可以写，但现在很可能念不出声。另一方面，无头 Chrome 连 PCM WAV 都解不开，自动化验收只能验到元素与状态。

所以这一刀要同时解决两件事：把「一句台词 ↔ 一条音轨」的关系、存储与时长校正做扎实；供应商不通时让人能用自己的录音把流程走完。

## 决策

1. **一句台词一条音轨**：`DialogueLine.audioAssetId?: ID` 指向 `kind: "audio"` 的 Asset；资产 id 固定为 `a-voice-<lineId>`。重配换掉这一句的旧音轨，不累积成 take——take 是「同一镜的多种演法」，配音的多种演法眼下不值得进数据模型。
2. **网关按 OpenAI 兼容写法**：`TreecloudSpeechAdapter` 调 `POST /v1/audio/speech {model, input, voice, response_format}`，拿二进制音频；`TreecloudClient.requestBytes` 负责收字节与 MIME。模型来自 `TTS_MODEL`，默认音色来自 `TTS_VOICE`；**两者都没配时适配器直接报 `tts_not_configured`，不发请求**，界面据此说「还没配配音模型」，而不是「生成失败」。
3. **音色按角色走**：`Character.voiceProfileId` 现在可以改（`character.updated` 的 patch 增加这个字段），空串表示用回默认音色。出声时把角色的音色带给网关；没设就用 `TTS_VOICE`。
4. **时长以音轨为准（准则 P5）**：网关不猜音频时长；音轨挂上后浏览器读 `loadedmetadata`，由 `fitLineToAudio` 写一条 `dialogue.updated { durationMs }` + 一条 `shot.updated { durationMs }`（镜头按差值挪） + 一条 `asset.updated`（补记 `durationMs`）。差值小于 40ms 不写，避免每次挂音轨都往日志里塞抖动。
5. **两条入口**：`出声`（供应商 TTS）与 `贴音轨`（`http(s)://` 或 `data:audio/` 导入）。后者是配额不通、或用户想用自己的录音时的兜底，和视频的「贴视频地址导入」同一个理由（ADR-0083）。
6. **声音页**：`/voice`，顶栏「声音」可达。按镜头顺序铺开每一句，带角色音色输入、每句的播放器与两个动作；页头如实写有没有配 TTS 模型。
7. **预演放音轨**：`toAnimaticView` 为每一镜带出 `clips`（这一镜已配好的台词音轨，按顺序），预演按台词顺序播；暂停时音轨真停，切镜从新一镜的第一句念起。一句都没配时仍是默片预演，右栏改口说「有配音的镜头 n 个」。
8. **失败说人话**：路由与 store 把供应商原文截到 240 字并前置一句人话，再提示「可以先贴一条音轨顶上」。

## 理由

- **时长不能有两个来源**：字幕、预演、之后的时间线都读 `durationMs`。如果预演按音轨、剧本按估算，用户会看到两套节奏；把音轨量出来的真实时长写回 IR，所有下游自动对齐。
- **资产位固定而不是新增 take**：一句台词的音轨没有「比较」的需求，只有「换了没有」；固定 id 让重配是覆盖，日志小、界面简单。
- **没配模型要说没配**：把「没配置」伪装成「生成失败」会让人反复重试一个永远不会成功的动作。`tts_not_configured` 是一个可判断的状态，界面能据此禁用按钮并给出下一步。
- **导入兜底不是临时补丁**：素材来源（自己的录音、外部 TTS）本来就是正当来源，`source: "upload"` 与生成走同一条挂载路径。
- **预演先有声音比先有音乐重要**：对白节奏是判断「这条片子成不成立」的第一变量，音乐与混音（C2 / C12）随后。

## 后果

**正面**

- 台词与音轨一一对应，刷新、换设备、回放之后都在（本地事件日志）。
- 音轨真实时长会校正镜头，预演、字幕与将来的时间线共用同一个数。
- 供应商不通时，贴一条自己的音轨就能把配音流程走完、并按真实时长校正镜头。
- 测试：IR 103（新增 3）、web 242（新增 7：读模型 2、store 5）、gateway 20（新增 3）、pipeline 23，合计 388。`pnpm typecheck`、`pnpm test` 通过。

**负面**

- **供应商 TTS 目前 403**：`POST /v1/audio/speech` 的分组没授权，出声路径无法端到端验证，只能验到 403 的人话提示。
- **无头环境解不开音频**：自动化验收看不到波形、听不到声音，也读不到 `loadedmetadata`，所以「量时长 → 校正」这一段只能靠代码与单测保证，真实播放要人在浏览器里听。
- **没有音量、混音与多角色同时说话**：一人一句顺序播；重叠对白、ducking、−14 LUFS（C12）都还没有。
- **音轨存在 IndexedDB 的 data URI 里**：现在的上限是一句 8 MB，长片段的音频会把本地配额顶满；对象存储（H3）接上后要改成地址。
- **重配是覆盖**：换掉的旧音轨不再能取回，历史里只留事件。
- **预估时长仍按 0.3 秒 / 字**：没挂音轨的句子还是估算值。

**跟进**

- 拿到 TTS 分组授权后补一次端到端探针，把真实模型与音色写进 `docs/MODEL-GATEWAY.md`。
- 旁白 / 字幕朗读（C8）、音效（C11）、音乐与情绪曲线（C10）、对白优先混音（C12）。
- 批量「补缺配音」：现在一句一句点；供应商稳定后按镜号顺序补。
- 音轨进对象存储（H3），IR 里只存地址。
- 预演按音轨实际长度播放，而不是仍按 `durationMs`（量过时长后两者应一致，但多句拼接与静音间隙还需要真实计时）。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 每条音轨都是一个 Take | 配音没有「比较」需求，只会让 `takes` 混进两种语义 |
| 服务端用 ffprobe 量音频时长 | 又要引入 ffmpeg；浏览器本来就会读 metadata，量到的就是播放时的真实值 |
| 网关估时长（字数 × 常数） | 估出来的数写进 IR 之后，字幕与音轨会错位，且很难发现 |
| 音轨直接存成文件 / 对象存储 | 对象存储（H3）还没接；本地日志先用 data URI，接口形状不变 |
| 没配 TTS 就把「出声」藏起来 | 「为什么这里没有声音」需要答案；禁用并说明原因，才知道该去配什么 |
| 预演里把音轨拼成一个连续缓冲再播 | 拼接要在浏览器里解码重编码，无头环境不可靠；逐句播已经够判断节奏 |
