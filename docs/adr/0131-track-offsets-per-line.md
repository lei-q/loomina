# ADR-0131：配音与字幕按句偏移，不建独立轨

- 日期：2026-11-12
- 状态：已采纳
- 关联：E1、E6、E7、D2、D3、ADR-0086、ADR-0087、ADR-0116、ADR-0130

## 背景

E1 的名字是「时间线（视频 / 音频 / 字幕轨）」，但落地以来只有画面轨真正在 IR 里：配音与字幕都是按片段起点**派生**出来的（ADR-0087），作者改不了它们的落点。

实际剪辑里最先遇到的三个问题都不是「换 take」能解决的：

1. **配音抢拍**：这一镜画面里人物还没开口，音轨先响了 200ms。
2. **配音拖后**：动作结束了声音才出来，晚半秒。
3. **字幕跟不上**：字幕比声音早一截，观众读完了声音还没到。

这三个都是**一句一句**的问题，不是整条轨的问题。

## 决策

### 1. 偏移挂在句子上，不建轨表

```ts
interface DialogueLine {
  // …
  voiceOffsetMs?: number;      // 整数毫秒，|x| ≤ 30000
  subtitleOffsetMs?: number;   // 整数毫秒，|x| ≤ 30000
}
```

不新增 `Timeline.audioTracks` / `subtitleTracks` 之类的结构。理由：

- **画面轨必须首尾相接**。渲染清单要求片段时长之和严格等于 `totalMs`（`validateRenderManifest` 硬校验）。一旦允许音频轨与画面轨各自排布，就会出现「音频比画面长 3 秒」的成片，渲染清单要么拒收、要么补黑帧——两种都是错。
- **没有转场与叠画**，画面是一条连续线。在这种结构下，「独立音轨」和「按句偏移」表达的是同一件事，后者少一层概念。
- 作者的心智模型也是按句的：他听到的是「这句话早了」，不是「第 3 轨早了」。

### 2. 两条轨独立

配音与字幕各有自己的偏移。字幕挪了，声音不动；声音挪了，字幕不动。这是剪辑台的基本预期，也是这两件事经常需要分别调的原因（字幕要迁就阅读，配音要迁就口型）。

### 3. 增量，不是目标值

`shiftLineTrack(lineId, track, deltaMs)` 收的是**增量**，store 自己读当前值再加。

第一版收的是目标值（`line.voiceOffsetMs + delta`），界面在连点时出过 bug：React 闭包里拿到的 `line.voiceOffsetMs` 还是上一次渲染的值，连点两次「字幕前挪」都算成 `0 → -100`，第二次被「值没变就不写」短路吃掉，作者看到的是「点两下只挪一步」。收增量把「当前值是多少」这件事交回 store，它永远读得到最新的。

### 4. 越界拒绝，读模型夹取

写入侧：非整数毫秒、或绝对值超过 30 秒，`applyEvent` 抛错。理由同 ADR-0130：填错了要看得见。

读取侧：`toEditView` 把起点夹进 `[0, totalMs - durationMs]`。这里**必须夹**，因为渲染清单只收落在成片里的叠加层：作者把一句挪到片尾之外，IR 里留着这个数（那是他的操作事实），但预览、SRT、ASS、叠加层都按夹过的位置走，否则导出会直接失败而界面还显示得好好的。

两处口径不同是有意的：**写入侧拒绝的是不可能的数**（非整数、超过 30 秒这种手滑），**读取侧夹取的是可能的数但不该出片的位置**。

### 5. 不新增事件类型

走既有 `dialogue.updated` 的 patch：

```ts
{ type: "dialogue.updated", lineId, patch: { voiceOffsetMs: 300 } }
{ type: "dialogue.updated", lineId, patch: { voiceOffsetMs: null } }  // 归零
```

`undefined` 过不了 JSON，所以「不改」靠字段缺席、「归零」靠 `null`——与 ADR-0124 的 `patch.performance = null` 同一口径。

不新增事件的理由：偏移是**一句台词的一个属性**，和文本、时长、音色是同一层的东西。新增 `dialogue.track.updated` 会让「改一句台词」散在两种事件里，历史抽屉和撤销都要各写一遍。

## 为什么不做的部分

- **真正的独立音频轨**（多条音轨、各自不跟画面）：需要时间轴与画面解耦，而当前的渲染管线（ADR-0091）按片段拼画面。等 E1 支持转场、或 B 系列需要画外音铺满整段时再开。届时多半不是加轨，而是加「叠加音效层」，与配乐床（C4）同一层。
- **拖拽时间线定位**：偏移目前用 `‹ ›` 按钮（100ms / Shift 500ms）调。拖拽需要吸附规则、与片段边界冲突时的处理，收益不如先把数值调准。
- **按角色分轨**：两个角色抢话时的分轨混音，归 C 系列。
- **变速 / 拉伸音轨**：调时长而不是挪位置，是另一件事（会改音高或需要时间拉伸算法）。

## 后果

- `DialogueLine` 多两个可选字段，`LOG_VERSION` 不用升（zod 可选字段，旧日志读出来就是缺省）。
- `dialogue.updated` 的 patch 类型要显式排掉这两个键再交叉（`Omit<…, "voiceOffsetMs" | "subtitleOffsetMs">`），否则 `number | undefined` 会把 `null` 吃掉，类型上过不去。这是个容易踩的细节，写在这里。
- 读模型 `EditLine` 多四个字段：`audioStartMs`、`cueStartMs`、`voiceOffsetMs`、`subtitleOffsetMs`。播放、SRT、ASS、预览 HTML、渲染清单、OTIO 六处都改读 `audioStartMs` / `cueStartMs`，不再用 `startMs` 当叠加层起点。
- 历史抽屉显示人话：「配音后挪 300ms、字幕归位：「你早就知道，对吧。」」
- 字幕条改成按绝对时间定位（原来是按顺序平铺），挪过的字幕在条上能看见它离开原位。
