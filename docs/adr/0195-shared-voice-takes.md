# ADR-0195：跨空间取一版配音（用户清单 C.1 / 功能 C21）

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：C1、C16、C20、C21、C9、ADR-0085、ADR-0194

## 背景

用户清单 C.1 要求「音频也可加入资产库并复用，跨集直接复用，不再花钱生成」。
现状：

- 参考图能跨空间挑（C16）、演员 / 场景 / 道具能整块复用（C17）、
  视频能取一拍（C20）；
- **配音还没有入口**。同一句台词在第二集要重录，就得再按字付一次钱；
  贴音轨又只收 `http(s)://` / `data:audio/`，本机资产库里的
  `loomina://assets/…` 根本贴不进去。

## 决定

1. **`attachVoice` 多一个可选来源，并放开资产库地址**
   - `attachVoice(lineId, uri, source?)`，默认 `upload`，旧行为不变。
   - 地址白名单从 `http(s)://` / `data:audio/` 扩到
     `loomina://assets/` 与 `s3://`：本机库 / 对象存储里的音轨本来就能播，
     以前只是入口没收。长度上限仍是 8 MB（内联地址的限制）。
   - 从别的空间取来的传 `source: "library"`：
     不触发素材授权检查、不算未定价调用；`provenance.modelId` 写 `library`
     （贴地址导入仍写 `import`）。
   - 取用仍写 `asset.updated` + `dialogue.updated { audioAssetId }`：
     挂上就是这句台词当前采用的音轨；旧音轨的记录留在日志与资产里，不删。

2. **界面在配音页每一句下面**
   - 「从别的空间取一版」按钮，打开面板才回放各空间日志；
     清单用 `sharedAssetsOf(spaces, ["audio"])`：按 uri 去重、合并使用处、
     新 → 旧排，滤掉当前空间，最多 60 条。
   - 每行：可播放的音轨、在那个空间里的用处（「配音「你早就知道，对吧。」」）、
     来源空间、「取这一版」；这句已经在用的地址置灰「已采用」。
   - 只读窗口不渲染入口；锁定镜头里的台词由 store 拒绝。
   - 贴音轨输入框的提示补上「本机资产库」：入口与能力对齐。

## 理由

- **配音和视频同一种问题**：都是按量计费、都能内容寻址反复使用；
  用同一套 `library` 口径，素材页与账本才不会被同一种字节记成两种来源。
- **不做「配音版本库」**：试听台（C9）已经记了同一句试过哪些；
  跨空间取用只改当前采用的那一版，不往试听台里塞别家的版本。
- **放开本机地址是修缺口，不是扩权**：音轨地址本来就存在资产里，
  播放器认这些协议；只收 http/data 让「取来的素材」根本用不上。

## 后果

**正面**

- 第二集可以拿第一集已经录好的同一句，不重新配音、不花钱、不复制字节。
- 素材页能分清「这段音频是拿过来的」与「这次贴进来 / 生成的」。
- 视频、参考图、实体、配音四条跨空间入口共用同一套日志回放与去重逻辑。

**负面 / 代价**

- **只拿了音频**：故事、剧本的跨空间取用还没有入口。
- 清单把所有 `kind: "audio"` 都列出来，配音、配乐、音效混在一起；
  只能靠「用处」标签分辨，没有按类筛选。
- 取来的是音轨文件，不带原台词的表演参数、试听台版本与时长校正记录；
  挂上后如果要按真实时长调镜头，仍要点一次「按音轨对齐」。
- 同一句重复取不同版本会覆盖当前采用的那一版；旧记录只在日志里，界面上没有对比。
- 对象存储未配置时，`s3://` 音轨能挂但播不出来（浏览器拿不到字节）。
