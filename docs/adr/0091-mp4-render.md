# ADR-0091 成片 MP4：浏览器排版，服务端 ffmpeg 编码

- 状态：已接受
- 日期：2026-11-11
- 决策人：用户 + Claude
- 关联：ADR-0004（浏览器预览 + 服务端渲染）、ADR-0086（时间线与导出）、ADR-0090（AI 标识）、E6 / D3 / G1

## 背景

成片页已经能导出预览 HTML、OTIO、SRT 与发布包，但发布包的 `video` 一直是 `null`。验收标准 5 要求「导出 MP4（1080×1920，H.264），带 AI 标识」，这是 MVP 唯一还没满足的硬指标。

本机 ffmpeg 已修好（9.0.2，libx264 / aac 可用），但它**没有编进 `drawtext` 与 `subtitles` 滤镜**：容器里的中文无法交给 ffmpeg 排版。这意味着两条路：

1. 给 ffmpeg 装一套字体与字幕渲染链（brew 重编、libass、字体路径），把中文字幕交给滤镜。
2. 让浏览器继续负责它已经做得不错的事——按现有 `SUBTITLE_STYLES` 排版——把字幕、占位与角标画成透明 PNG，服务端只做拼接与编码。

项目一直的原则是「不在服务端复制一份已有逻辑」（ADR-0086 的预览与导出同源）。字幕断句、字号、安全区已经在浏览器里；再在 ffmpeg 里写一遍 drawtext 排版，会得到两套不同的字距与换行。

## 决策

1. **新增 `POST /api/render`，输入是一份渲染清单，不是项目。** 浏览器把已经排好的片段、叠加层与音轨发上来；服务端不读 IndexedDB、不持有项目状态、不落发布记录。清单形状与上限在 `lib/render-manifest.ts` 里定义并在两端共用。
2. **浏览器负责排版：字幕、占位图、AI 角标都先画成 1080×1920 的透明 PNG。**
   - 字幕用与预览一致的 `SUBTITLE_STYLES`（字号按画面宽度的 `cqw`、离底边 14% / 18%、黑色描边）。
   - 没有视频也没有首尾帧的片段画一张斜纹占位图，写 `SH-xx 还没有画面`。
   - 「AI 生成」角标单独画一张全画幅透明 PNG，贴右下角，全程叠加。
   - 这样中文排版只存在一份，且不依赖服务端字体。
3. **服务端只做确定性编码。** 图片按 `loop + trim` 定长，视频按 `scale/pad/fps/tpad/trim` 统一成 1080×1920 / 30fps，`concat` 拼接，`overlay` 按 `enable='between(t,…)'` 叠字幕与角标，音轨 `adelay + amix + apad + atrim` 对齐到全长。输出 H.264（veryfast / crf 20 / yuv420p）+ AAC 128k，`+faststart`，并写 `title` 与 `comment=AI生成` 两个容器元数据。
4. **只收 data URI，不收远端地址。** 服务端不会替用户去 GET 任意 URL（SSRF），也不会因为供应商链接过期而渲染到一半失败。远端视频 / 音轨在浏览器侧被跳过并计数，界面如实说「n 个远端素材没下载」；视频片段改用首帧或占位图。
5. **上限是硬门槛，不偷偷截断。** 全长 ≤180 秒、≤60 个片段、单个素材 ≤30 MB、整份 ≤200 MB。缺一段、时间对不上、没有 AI 标注都直接 400，并把原因说清楚。
6. **渲染结果不落盘。** 临时目录里写素材与输出，请求结束即删；客户端拿 `video/mp4` 直接下载。项目与事件日志不因为导出而改变。
7. **成片页把「导出成片 MP4」放成主按钮。** 渲染中写阶段文案；完成写文件大小、分辨率、占位片段数与远端跳过数；失败把 ffmpeg 的最后几行原样带回来。

## 理由

- **一份排版逻辑**：字幕在预览、播放器与成片里应该是同一套字距与位置；浏览器已经做了，服务端再写一遍只会漂移。
- **不新增依赖**：不需要 libass、字体包或新服务，ffmpeg 只用已有的 scale / pad / concat / overlay / amix。
- **安全边界清楚**：只收 data URI，路由不成为任意 URL 的代理。
- **可验证**：清单是纯数据，校验可单测；编码结果可用 `ffprobe` 与抽帧直接看。
- **诚实**：远端视频不下载就说「没下载」，用占位图也说「用占位图」，不把 5.5 秒的占位片说成完整成片。

## 后果

**正面**

- 验收标准 5 在本地路径上成立：1080×1920、H.264、AAC、带烧进画面的「AI 生成」角标与容器元数据。
- 预览、播放器与成片共用同一套字幕样式；改样式不用改两处。
- 渲染清单可单测；服务端无状态，失败不会留下半份发布记录。
- 5.5 秒示例片实测约 4 秒渲完；2.5 秒音视频混合片（视频 + 图片 + 延迟音轨）时长与音量都正确。
- 没有新增依赖，临时文件请求结束即清。

**负面**

- **远端视频不渲染**：供应商返回的 `http(s)` 视频不会进成片，只能用首帧或占位图。要支持必须先有受控下载（H3 对象存储转存或域名白名单）。
- **整份清单在内存里**：200 MB 上限是为了不把 Node 进程顶爆；大项目仍要分段导出。
- **一次请求没有进度**：只能显示「通常 20–90 秒」，不能像队列那样报百分比；服务端超时 240 秒。
- **没有并发控制**：两个标签页同时点导出会并行跑两个 ffmpeg，CPU 会抢。任务队列（H2）接上后要收口。
- **字幕是烧死的**：成片里的字幕不可关、不可切轨；要可切换字幕得输出独立字幕轨或另出无字幕版。
- **没有真实视频素材时的成片仍是占位**：示例项目能导出，但画面是斜纹与镜号，不是「能发的片」。
- **音频只有对白**：没有配乐、没有响度归一化（C4 / C12 未做）；多条音轨直接相加，可能削顶。
- **颜色与平台规格未校验**：固定 1080×1920 / 30fps / H.264，尚未按抖音等平台规格做码率与封面校验（G7）。

**跟进**

- 远端素材转存：H3 接上后，生成/导入的视频先落到对象存储，再由渲染路由读本地对象，不再需要浏览器传 data URI。
- 任务队列（H2）：把渲染变成可查询进度的任务，限制并发，失败可重试。
- 无字幕版与字幕轨：发布到支持外挂字幕的平台时，烧死的字幕反而是负担；需要两种输出。
- 配乐与响度（C4 / C12）：混音、ducking、−14 LUFS。
- 平台规格（G7 / G8）：按平台输出不同码率与封面，导出前跑合规预检。
- 真实视频路径的端到端验证：本轮只验了本地 data URI 视频与图片，没有验供应商远端视频。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 用 ffmpeg `subtitles` / `drawtext` 烧字幕 | 本机 ffmpeg 没编进这两个滤镜；补 libass 与字体是另一套排版逻辑，会和预览漂移 |
| 服务端读 IndexedDB / 项目文件 | 项目在浏览器本地，服务端没有事实来源；把项目复制到服务端会形成第二套状态 |
| 服务端直接 GET 远端视频 | SSRF 风险，且供应商链接会过期；下载失败会让整条片子渲不出来 |
| 浏览器 WebCodecs 直接编码 | 兼容性与音频封装复杂，且只能拿到能跨域读取的素材；ffmpeg 已可用 |
| 只导出无字幕的纯画面 | 与预览、发布包的承诺不一致；用户还要自己再烧一遍字幕 |
| 把渲染结果存回项目 | 会改变事件与发布语义；当前导出是「下载」，不是「发布」 |
| 不限长度、不限素材大小 | 一次请求会把内存与临时盘顶满；180 秒/MVP 体量已经够用 |
