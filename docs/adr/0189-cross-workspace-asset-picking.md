# ADR-0189：跨工作空间取素材——挑图面板（C4 / C16）

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：C4、C16、C15、H3、ADR-0034、ADR-0128、ADR-0188

## 背景

ADR-0188 把工作空间做成了各自独立的事件日志，素材文件按内容寻址全机共用：
同一张图在两个空间里被引用时，盘上只有一份字节。当时留了一个缺口——
**界面上看不到别的空间用过什么，也就拿不过来**。资产库页只列当前项目的资产记录。

用户的要求是「每个工作空间共享资产库，随时取用」。字节已经共享了，缺的是
「找得到 + 挂得上」这一步。

## 决定

1. **按需读别的空间的日志，不在启动时扫**
   - 打开挑图面板时才 `listWorkspaces()` → 逐个 `indexedDbLogFor(id).load()` →
     `migrateLog` → `rebuild`，拿到别的空间的 `Project`。
   - 这是显式动作，不挂在正常编辑 / 启动路径上：多开几个空间不会拖慢打开项目。
   - 某一份日志坏了就跳过它，不让一个坏空间把整个面板拖死。

2. **清单按地址去重，使用处合并**
   - `sharedAssetsOf(spaces, kinds = ["image"])` 是纯函数：同一 `uri` 在五个空间
     出现也只列一次，`usedBy` 合并成「参考图「林」」「定妆「周」正脸」这类人类可读的
     用处；`workspaceName` 记第一次见到它的空间（同机共享，标一个来源就够）。
   - 默认只列图片：面板目前只服务参考图（人物 / 场景 / 道具的「＋ 挂一张」旁）。
   - 没有 `uri` 的占位资产不进清单——拿过去也没东西可看。

3. **取用 = 在当前项目登记一条资产记录，地址不变**
   - 选中后调已有的 `makeReferenceAsset(uri)`：新建一条 `Asset`（`source: "upload"` ——
     这张图是「挂进来的」，不是本空间生成、也不带本空间的 `costCny`），
     再写进参考图列表；日志是 `asset.updated` + 引用方的 `*.updated` 两条。
   - 不下载、不复制字节、不重新生成、不花钱。同一排参考图里已经有同一地址时
     拒绝（「这张图已经挂过了」）。
   - `makeReferenceAsset` 为此放开了 `loomina://` 与 `s3://`：以前只收 `http(s)://`
     与 `data:image/`，别的工作空间存下来的图恰好是这两种前缀。

4. **面板写明代价**
   - 顶部一句话：「文件还是同一份：不复制、不重新生成、不花钱」。
   - 已经在当前这排里挂过的图置灰标「已挂」，点不动。

## 理由

- **读日志而不是读素材盘**：素材盘只有字节、没有语义；「这是谁的参考图」只在
  项目 IR 里。要给出能认人的清单，只能回放日志。
- **按需**：跨空间扫描的成本随空间数线性增长（每个空间都要重放整条日志）。
  放到面板打开时，等于只在用户真的想找图时付一次。
- **只复制记录**：字节本来就是同一份。复制资产记录让当前项目的日志自洽
  （回放时知道这张图被谁引用、花了多少钱——`source: "library"` 的记录不抄
  `costCny`，因为它没有在这个项目里花过钱），而盘上不会出现第二份。

## 后果

**正面**

- 第二集可以直接用第一集的定妆参考，不必重新生成。
- 清单能看出「这张图在哪个空间、当初拿来干什么」。
- 老日志、坏日志、空空间都不影响当前项目。

**负面 / 代价**

- 空间多、日志长时，打开面板要等几百毫秒到几秒；界面有「正在读…」占位。
- 只覆盖图片。故事 / 剧本 / 音频 / 视频的跨空间复用还没做（C1 / C4 后续）。
- 别的空间删掉引用之后，清单里可能仍有这张图（读的是历史状态），
  但地址仍然有效——文件按内容寻址不会因为没人引用就消失。
- `s3://` 地址跨空间可用，但需要同一套对象存储配置；换机器 / 换桶后
  这些地址会失效，界面只能显示占位图。
