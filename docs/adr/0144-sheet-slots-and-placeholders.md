# ADR-0144 四格资产位与占位资产

- 状态：已接受
- 日期：2026-11-12
- 决策人：用户 + Claude
- 关联：ADR-0028（三视图闸门）、ADR-0031（定妆出图）、ADR-0071（新建人物）、ADR-0142（四格过期与历史）、B1、B8

## 背景

用户在建好的项目里新建人物，点「生成三视图」，界面回一句：

> 这个角色还没有三视图的资产位，先建四个格子

然后就没有然后了——界面上没有任何地方能「建四个格子」。这是一条死路：

- `addCharacter` 把人写成 `sheet: {}`，四格一个 id 都没有；
- 出图逻辑只对 `character.sheet` 里已有的角度逐格生成，空 `sheet` 直接拒绝；
- `character.updated` 的 patch 里也没有 `sheet`，事件层补不了；
- 故事草稿落项目（`projectFromStoryDraft`）同样是 `sheet: {}`，所以「从故事一键成片」进来的角色也都卡在同一句提示上。

示例项目 `demo-night-shift` 之所以能用，是因为它的种子数据里手写了四个资产 id。真实路径一直是断的。

## 决策

1. **四格的 id 是确定的，不随机。** `sheetSlotsOf(characterId)` 生成 `a-sheet-<characterId>-<angle>`；同一个角色无论什么时候补格子，得到的都是同一组 id，事件日志不会因为补格子而分裂出两套地址。
2. **新建人物时连资产一起建。** `sheetSlotAssets(characterId, at)` 给出四个 `Asset`，带 `placeholder: true`、没有 `uri`。`addCharacter` 先写四条 `asset.updated`，再写 `character.added`——IR 的不变量要求 `sheet` 里的 id 都指得到资产，顺序不能反。一共五条事件。
3. **占位资产不算「有图」。** `Asset.placeholder` 是新增的可选字段；`castReadiness` 只看没有这个标记的资产，所以新建人物不会被误判成「四格已齐」。`asset.updated` 写进 `uri` 时如果没有显式带 `placeholder`，合并后自动把这个标记摘掉——占位只是「还没出图」的临时身份。
4. **`character.updated { sheet }` 整份替换。** 事件层补上这个 patch 字段，校验两条：角度必须在 `SHEET_ANGLES` 里、资产 id 不能是空串。整份替换而不是按角度合并，避免「删一格」需要另一个事件。
5. **旧项目点一下就自愈。** `generateSheet` 发现缺格子时，先用确定性 id 把缺的补上（占位资产 + 一条 `character.updated { sheet }`），再对四格逐一出图；作者换过的格子 id 原样保留。界面上不再有那句死路提示。
6. **故事草稿同样带格子。** `projectFromStoryDraft` 用 `sheetSlotsOf` / `sheetSlotAssets` 落 `sheet` 与资产，"从故事一键成片"进来的人也能直接出三视图。

## 理由

- **资产位是数据，不是生成结果。** 四格在 IR 里一直是「四个指向资产的槽」；把「槽存在」和「槽里有图」拆开，闸门、过期判断、历史回退都能分别处理这两件事。
- **确定性 id 让补格子幂等。** 同一角色补两次得到同一组地址，日志重放、导出、回退都不会因为「格子是哪次建的」而不同。
- **顺序是硬约束。** `REF_ASSET` 不变量是真的（story 测试曾经因为它红过）；「先建资产再建人」不是风格选择，是唯一合法的写序。
- **占位标记比「uri 为空」更明确。** 读模型、闸门、界面都不需要各自解释「空 uri 是没图还是坏图」；一个布尔标记写明意图。
- **自愈而不是迁移。** 旧项目的日志不改写（ADR-0001 的事件日志只追加）；第一次出图时补一条事件，比写一次性迁移脚本更符合「日志是唯一事实来源」。

## 后果

**正面**

- 「新建人物 → 生成三视图」这条路第一次真正通到出图；示例项目不再依赖手写种子。
- 故事草稿进来的角色同样可用。
- 旧项目不用迁移，点一次就补上；作者改过的格子 id 不受影响。
- 闸门不会再因为占位格子误判「四格已齐」。

**负面 / 代价**

- 新建一个人多写四条 `asset.updated`，事件条数变多；这是「资产位也是数据」的直接后果，读取时按 id 索引没有额外成本。
- `Asset.placeholder` 是一个新字段；导出 / 老日志里没有它是正常的（可选），读模型要按 `!== true` 判断。
- 补格子会写 `character.updated`，`castTextHistory` 之类按 `character.updated` 统计「改过几次」的读模型需要确认不会被这类补格子污染——本 ADR 的补格子只带 `sheet`，文本历史只看 `name` / `appearance` / `mustNotChange`，不受影响。

**边界**

- 「删掉某一格」仍然没有独立事件；要清空格子得整份替换 `sheet`，界面上也还没有入口。
- 占位资产会占资产库的位置；资产回收（B1 剩余项 / H3）还没做，空占位目前只有几十字节的元数据，可以忽略。
- 老项目里如果 `sheet` 指向的资产已经不在 `assets` 里（历史脏数据），补格子不会修它——本 ADR 只处理「缺角度」，不处理「悬空 id」。

## 验证

- IR 新增：确定性 id、占位资产不计入闸门、有图的资产计数（`cast.test.ts`）；`character.updated { sheet }` 应用与重放、未知角度 / 空串拒绝、`asset.updated` 写 uri 时摘掉占位标记（`events.test.ts`）。
- pipeline：故事草稿的 `sheet` 与占位资产（既有 story 测试继续过）。
- web store：`addCharacter` 写五条事件且四个 id 正确；旧角色点「生成三视图」先补 `character.updated` 再发四次请求（`workbench-store.test.ts`）。
- 全量 1223 条测试、`tsc --noEmit`、`next build` 通过。
- 读模型：占位格子不参与过期与「四格模型不一致」判断（`read-model.test.ts` 新增 1 条）——否则刚建的格子会被标成「名字改过」的过期图。
- 浏览器：给项目灌一个 `sheet: {}` 的旧角色 → 点「生成三视图」→ 四条 `asset.updated` 占位 + 一条 `character.updated { sheet }`，四格逐一出图，四张都拿到 `uri`、占位标记全被摘掉，角色状态变「可锁定」，页面上没有过期点、没有错误提示；按钮价目从 ¥0.00 变为 ¥0.48 后仍可再次生成。
