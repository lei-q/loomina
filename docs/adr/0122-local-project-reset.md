# ADR-0122：本地项目的重置入口

- 日期：2026-11-11
- 状态：已采纳
- 关联：H18、F4、H3、ADR-0034、ADR-0109

## 背景

H18 的本地持久化从 ADR-0034 起就完整：事件日志逐条落 IndexedDB，刷新不丢，坏日志整份丢弃，`LOG_VERSION` + `migrateLog`，Web Locks 保证单写者。但界面上**没有重置入口**。

想重来一遍只能开 devtools、找到库名 `loomina`、删掉它。这是产品缺口：作者不该为了「重新开始」去动浏览器开发者工具。

## 决策

### 1. 放在设置页，不放在顶栏

顶栏是创作动线（撤销 / 历史 / 记账），重置是一次性的破坏性动作，混进去会误点。设置页是「关于这套东西怎么跑」的地方，「本地项目」区放在能力矩阵下面，与配置项分开。

### 2. 两步确认，文案说真话

第一次点「重置为示例项目」展开确认条，写清「N 条事件一起消失，撤销也找不回来」；第二次点「确认重置」才真重置。

**不说「仍在历史里可以回滚」**：`reset` 走的是 `log.replace(bootstrap(project))`，整份覆盖写回 IndexedDB。旧事件是真的没了，`project.restored` 也只能指回仍然存在的前缀。第一版文案写了「仍在历史里」，实测后改掉——工具可以要求作者接受代价，但不能把代价说错。

### 3. store 的 `reset` 加只读守卫

另一个标签页正在编辑时（Web Locks 拿不到写权），这一页是只读的。原来的 `reset` 没有守卫，会直接改内存并触发覆盖写——那是把别人的项目抹掉。现在 `readOnly` 时直接返回，界面按钮同时禁用，双保险。

### 4. 设置页必须 `hydrate()`

**这一条是这次发现的真 bug。** 设置页原来只读配置与能力矩阵，从不调用 `hydrate()`。store 的初始状态是内存里的示例项目，`events` 只有一条引导事件，`ready` 为 `false`——而写盘订阅器在 `ready` 为 false 时直接返回。

于是第一次实现的重置按钮：点下去内存变了、界面提示「已重置」，但 IndexedDB 里那条真实日志**一个字节都没动**。回故事页刷新，原来的编辑全在。

修法是设置页的 `useEffect` 里补 `void hydrate()`。修完之后重置才真的落到本地库。

这个 bug 只有靠「重置后回别的页面看内容有没有变」才能发现；只看设置页的提示文案，会以为成功了。**验证一个写操作，要看写出去的东西，不看它自己的回执。**

## 后果

- 作者能自己重来一遍，不用动开发者工具。
- 重置的代价被说清：不可撤销，旧日志整份换掉。
- 只读标签页不会误删别人的项目。
- 设置页现在也参与 `hydrate`，与其它页面同一套初始化。

## 验证

- 单测 798 全过（IR 160 + gateway 28 + pipeline 51 + web 559）。
  - `workbench-store.test.ts` 新增 3 条：重置清掉所有编辑只留引导事件、只读标签页不能重置、重置后能继续写且 `rebuild(events)` 等于内存项目。
- `pnpm typecheck`、`next build` 全过。
- 浏览器（生产 3100）：故事页改 logline 使日志涨到 8 条 → 设置页「本地项目」显示「8 条事件」→ 点重置出现确认条 → 点「算了」回到初始 → 再点重置并确认 → 显示「1 条事件」与「已重置」→ 回故事页，logline 变回「还没填」。**这一步是修复 `hydrate` 之后才通过的**；修复前重置后回故事页，logline 仍是改过的值。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 一步确认直接重置 | 删的是作者的全部编辑，误点一次代价太大 |
| 文案写「仍在历史里可以回滚」 | 与事实不符：`reset` 是整份覆盖，旧事件不在日志里了 |
| 放在顶栏 | 顶栏是创作动线，破坏性动作混进去容易误点 |
| 重置时不查 `readOnly` | 会把另一个标签页正在编辑的项目覆盖掉 |
