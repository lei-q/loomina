# ADR-0097：一致性体检与视频失败重试（B14 / B6 第一版）

- 状态：已采纳
- 日期：2026-11-11
- 关联：B14、B6、B3、B5、B12、R16、R31、CONSISTENCY.md、ADR-0029、ADR-0083、ADR-0096

## 背景

`CONSISTENCY.md` 把一致性拆成八个维度，并给出 `ConsistencyReport` 的目标形状：身份、服化道、场景、光影、空间、表演、动作、风格，靠人脸 embedding、VLM、pHash、3D 走位等量化。`FEATURES.md` 的 B14 因此一直停在「待设计」。

当前仓库没有任何视觉推理链路：没有 ArcFace / InsightFace，没有多模态模型调用，也没有 3D 灰盒。若照着目标形状直接产出「身份 87 分」，那是在假装看过画面。B6 同样遇到边界：`CONSISTENCY.md` 的第一修复手段是「固定 seed / 换模型」，但 `VideoInput` 与 treecloud 提交体都没有 seed，能力矩阵（B12）也还没做，自动换模型没有可靠依据。

这一版要做的是两件**能如实做到**的事：

1. B14 先查**生成前的结构化锚点**与**生成后的溯源**：定妆三视图、角色表情 / 服装参考、场景主镜、道具参考、take 的模型与引用记录。它回答「生成需要的东西在不在」「出了问题能不能查」，不回答「脸像不像」。
2. B6 只对**确定没在跑、重交安全**的失败自动重试，最多 3 次；超时与轮询中断不自动重交，避免一条任务还在跑时又提交一条、重复计费。

## 决策

### 1. 体检的五个可测维度与权重

新增 `apps/web/lib/consistency.ts`，纯函数 `analyzeConsistency(project)`：

| 维度 | 查什么 | 权重 |
| --- | --- | --- |
| 身份 | 每个出场角色在 `shotAnchors` 里拿到几张身份参考；单人要 2 张、多人每人 1 张；需要三视图的景别缺格扣分 | 35 |
| 服化道 | 有 `mustNotChange` 的角色是否有表情 / 服装参考；这一镜的道具是否有参考图 | 20 |
| 场景 | 场次能否找到地点，地点是否有可用的主镜 | 20 |
| 风格 | 最新 take 的模型是否与全片主用模型一致 | 15 |
| 溯源 | 最新 take 是否记录了 `referenceAssetIds` / `prompt` / `seed` | 10 |

- 维度只在**这一镜有可测内容**时参与：没有人物不评身份，没有道具与清单特征不评服化道，没有 take 不评风格与溯源。
- 总分 = 可测维度按权重重新归一，四舍五入。不可测维度显示「—」，不按 0 分拉低。
- 没有 take 的镜头只算锚点准备度，结论是 `unknown`（未出片），不冒充「通过」。
- 通过线按景别收紧：全景 / 中全 80，中景 85，近景 / 大特写 90（`CONSISTENCY.md` 的「特写严、全景松」）。`overall ≥ 通过线` 为 pass，`≥ 60` 为 review，其余 fail。

权重是产品判断，不是标定结果。等有自有样片与视觉验收链路后再调，调的时候按 ADR 记录。

### 2. 溯源单独成维度，且明确它不是一致性

`Provenance` 里已有 `seed?`，但 treecloud 视频提交体没有 seed，图像适配器也不支持。因此：

- 有 `modelId` 记 40 分，有 `referenceAssetIds` 加 30，有 `prompt` 加 20，有 `seed` 加 10。
- 缺参考图时写「这一拍没有记录参考图：无法复核生成时用了哪些定妆锚点」，建议重拍；重拍会写入首帧引用。
- 缺 seed 时如实写「供应商接口目前不支持固定 seed，身份漂移时没法靠复现 seed 修」，**不给假的修复按钮**。
- 示例项目的 12 条老 take 都只有 `modelId`，因此每条溯源 40 分；这是真实的记录缺口，不是评分 bug。

### 3. 未测维度写进报告，不混进总分

`lighting` / `spatial` / `performance` 三项固定标为未测，并写明原因：

- 光影：没有 LightingSpec 与画面比色；
- 空间：没有 3D 走位与机位参数；
- 表演 / 动作：没有视频动作分析。

面板底部再写一次：这里查的是结构化锚点与溯源，不是人脸或像素相似度，分数不评价画面好不好。

### 4. 分镜页顶栏的「体检」抽屉

- 顶栏「检查」左边新增「体检」；有 review / fail 时按钮带数量，颜色用 `pick`。
- 右侧抽屉 `aria-label="一致性体检"`：
  - 顶部四格：平均分、通过、待复核、不达标；有未出片镜头时补一行说明；
  - 当前镜：总分 / 通过线、五个维度分数条、这一镜的问题与修复建议；
  - `需要看的镜头`：review + fail 按分数从低到高，点一行跳到那一镜；
  - `未测`：三项与原因；底部写清体检范围。
- 体检是只读的，不写事件。它与「检查」抽屉互斥：打开一个会关掉另一个；抽屉打开时不响应 ← → 换镜，Esc 或点遮罩关闭。

### 5. B6 的重试只信服务端的 `retryable`

`generateShotVideo` 抛 `VideoGenerationError(message, code, retryable)`，`/api/video` 把它转成 `{ error, code, retryable }`：

| 阶段 | code | retryable | 理由 |
| --- | --- | --- | --- |
| 提交时 429 / 5xx | `submit` | 是 | 任务没建立，重交安全 |
| 提交时其他 4xx | `submit` | 否 | 参数 / 鉴权问题，重试不会变好 |
| 供应商明确 `failed` | `provider_failed` | 是 | 这一条已结束，重交不会覆盖在跑的任务 |
| 轮询超时（queued / running） | `timeout` | 否 | 任务可能还在跑，重交会多花一笔 |
| 提交成功后轮询 / 取片报错 | `poll` | 否 | 任务已经在了，重交同样多花一笔 |
| `ConfigError` | `config` | 否 | 配置缺失 |

客户端 `generateVideo`：

- 最多 3 次；只对 `retryable === true` 重交，间隔 1.2 秒、3 秒；
- 重试期间页面顶上一行写「第 n 次没出片：<原因>。正在重试（n+1/3）…」，出片中的状态带「第 n 次尝试」；
- 网络连接断开不自动重交：请求可能已经到了供应商，先去后台确认有没有任务；
- 成功仍按原逻辑新增一拍 take，不覆盖旧 take；失败不动已有 take；
- 最终失败写「试了 n 次没出片：<原因>」，仍保留「贴视频地址导入」兜底。

### 6. 这一轮不做

- 不做人脸 embedding、pHash、VLM 比对、抽帧，也不产出「身份 87」这类视觉相似度分数。
- 不做光影 / 空间 / 表演 / 动作的自动检查；不做 3D 走位与轴线。
- 不做自动补图、自动重出首帧、自动换模型或自动降级。体检只报告与建议；改法是作者的事。
- 不因为体检不通过而阻止生成或导出。它还不是硬闸门，等 F8 / F9 与 B12 / H16 再收紧。
- 不自动改 seed / 提示词 / 模型：网关接口不支持 seed，能力矩阵未完成，自动换模型的代价与效果都无法保证。
- 不记录重试次数到 take 溯源：`Provenance` 没有这个字段，加字段需要迁移；这一版只在界面与错误信息里如实显示。

## 理由

- 结构锚点与溯源是当前系统**确实拥有**的数据；先把「该有的图有没有、生成时用了什么」查清楚，比给一个假的视觉分数有用。
- 把「未测」写进报告，符合作品准则里的「如实说」；也给后续接视觉验收留了明确的空位。
- 重试的安全性比次数重要。供应商任务可能还在跑时自动重交，用户会为同一条片子付两次钱；宁可让作者确认一次。
- 通过线按景别分级直接来自 `CONSISTENCY.md`，不是临时发明；权重是显式常量，日后可调、可记录。
- 只读体检不写事件，和「检查」抽屉一样不会污染项目日志；也避免把系统的推断伪装成作者的决定。

## 后果

**正面**

- 分镜页顶栏出现「体检」，示例项目显示平均 90、通过 10、待复核 2；`SH-07` 84 / 90、`SH-05` 89 / 90，问题直接指向「周」缺表情 / 服装参考与老 take 缺参考图记录。
- 缺三视图、缺场景主镜、缺道具参考、模型漂移、溯源不全都能量化，并给出具体到页面的修复建议。
- 视频失败时，可安全重交的错误会自动再试，失败原因与次数在界面上看得见；超时则明确劝住，避免重复计费。
- 全部逻辑是纯函数或 store 内可测路径，单测覆盖分数、阈值、缺图、模型漂移、溯源、无 take、空项目。

**负面**

- 分数只反映「锚点齐不齐、能不能查」，不能预测观众会不会觉得「不是同一个人」。真正的视觉一致性仍未验收。
- 通过线 80 / 85 / 90 与权重 35 / 20 / 20 / 15 / 10 没有样片标定，可能过松或过严；示例项目的 90 平均分不代表画面质量。
- 老 take 的溯源普遍偏低（示例 40），会让整片看起来「待复核」；这是历史数据缺口，只能靠重拍逐步补齐。
- 重试仍可能产生未知费用：供应商明确 failed 是否计费取决于供应商条款，客户端无法确认；界面只报告尝试次数，不承诺「失败不扣钱」。
- 没有 seed 与能力矩阵，B6 的「换 seed / 换模型」两条降级路径仍然缺失。
