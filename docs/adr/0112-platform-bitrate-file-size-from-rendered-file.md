# ADR-0112：码率与文件大小按实际成片体积核对，不给目标码率

- 日期：2026-11-11
- 状态：已采纳
- 关联：G7、ADR-0099、H13 / ADR-0101、G1 / ADR-0102

## 背景

G7 的规格表把码率与文件大小标成「参考」，一直没有真正核过：`bitrateMbps` 只写在表里、从没读出来用；`maxFileBytes` 一个平台都没填；渲染用 CRF 质量档，不给目标码率，所以**码率在导出之前根本不知道**。结果是平台规格面板里这两项永远是一句「导出后再核对」，等于没做。

## 决策

### 1. 码率只从实际成片算

`bitrateMbpsOf(fileBytes, durationMs) = 字节 × 8 ÷ 秒`，没有文件就没有码率。渲染仍是 CRF 质量档，不改成目标码率：

- 目标码率等于承诺一个体积，和 CRF 的「同画质同观感」相反；
- 草稿档（540×960 / CRF 30）与定稿档（1080×1920 / CRF 20）本来就该给不同体积，加一个码率旋钮只会多一个要解释的概念；
- 平台真正在意的是上传后不被二次压缩，判断依据只能是实际文件。

### 2. 超出参考区间只提醒

平台表里的 `bitrateMbps`（抖音 / 快手 / TikTok 2–8 Mbps）原样使用：

| 情况 | 状态 |
| --- | --- |
| 没有导出过 | 通过 · 参考值，写「导出后按实际体积核算」+ 区间 |
| 实际值落在区间内 | 通过 · 写出实际 Mbps 与体积 |
| 实际值低于或高于区间 | 复核 · 说明「平台多半会再压一次」 |
| 平台没有区间（B 站、小红书等） | 通过 · 如实写「没有可引用的公开码率区间」 |

不把码率升级成硬拦：区间本身来自公开资料、平台随时会改，而且一个 46 KB 的草稿被测出 0.1 Mbps，不代表这条片子有问题——它是草稿。硬拦留给画幅、时长上限、编码与**已知上限**的文件大小。

### 3. 文件大小能硬拦，但只在有上限时

`maxFileBytes` 只有在逐条复核过平台文档后才填。目前**一个都没填**：与其填一个猜的数，不如让面板说「没有可引用的公开上限（未核验）」。哪天复核出上限，填进去就自动变成硬阻断，校验代码不用改。

有体积时面板写实测值（`formatSize`：不到 1 MB 用 KB），不再出现「0.0 MB」这种看不清的写法。

### 4. 体积从哪来：最近一次导出

- 成片页：`lastRender.bytes` 进 `validatePlatform`，码率与文件大小两行随导出结果即时更新；`lastRender` 是组件状态，刷新页面后回到「导出后再核」。
- 发布包：`options.video.bytes` 进同一套校验，`platformChecks` 里带上实际体积与码率，随包落盘。
- 导出前预检：`PreflightOptions.fileBytes` 可选，有就传，没有就按「未导出」处理。

三处共用 `validatePlatform`，不另写一套判断。

## 后果

- 码率与文件大小第一次有了真实数字，且数字只有一处来源（导出后的文件），不会和渲染档位的理论值打架。
- 草稿常会被标「复核 · 超出参考区间」，这是预期：草稿不是给平台看的，定稿再按区间看一次。
- 平台上限仍然空着：这是诚实，不是遗漏；`maxFileBytes` 是留给复核的接口。
- 发布包里的 `platformChecks` 多两行有效信息，旧包格式不变（只是 `checks` 数组多一项 `bitrate`）。

## 验证

- 单测 737 全过（IR 142 + gateway 28 + pipeline 51 + web 516）：`platforms.test.ts` 新增 8 条（码率公式与非法输入、未导出时只给区间、区间内写实测值、高于 / 低于区间都只复核、平台无区间时如实说、体积实测值、`formatSize` 的 KB / MB）。`edit.test.ts` 新增 1 条（发布包按 90 MB 成片核出体积与码率）。
- `pnpm typecheck`、`next build` 全过。
- 浏览器（生产 3100，成片页）：平台规格面板出现「码率 · 参考 2–8 Mbps · 导出后按实际体积核算」；切到「通用」变成「没有可引用的公开码率区间」；导出一版草稿后，码率行变「0.1 Mbps（46 KB / 5.5 秒）· 参考 2–8 Mbps：超出参考区间」，文件大小行变「46 KB；TikTok 没有可引用的公开上限（未核验）」。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 渲染改成目标码率 | 和 CRF 的质量口径冲突；一个旋钮还要解释「为什么同一条片子定稿更大」 |
| 码率超区间就硬拦 | 区间是公开资料、随时会改；草稿天然低码率，拦了只会挡住正常使用 |
| 给所有平台填一个文件大小上限 | 没有逐条复核过的数字会变成假确定；空着并在界面说明更诚实 |
| 用渲染档位估码率（比如「定稿约 6 Mbps」） | 估出来的数会与真实文件不符，作者拿它做判断就直接错 |
| 把体积写进 IR / 事件日志 | 体积是导出产物的事实，不是创作决定；发布包与界面各取一次即可 |
