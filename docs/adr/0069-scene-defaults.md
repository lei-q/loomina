# ADR-0069 新场沿用前一场的地点与日夜

- 状态：已接受
- 日期：2026-11-11
- 决策者：用户 + Claude
- 关联：ADR-0068（中间插入，本 ADR 修订其第 6 条）、ADR-0064（新建默认值）、ADR-0050 / ADR-0056（场头可改）、FEATURES A21

## 背景

ADR-0064 给新场定的默认值是「第一个地点、内景、日」，ADR-0068 插入场次时沿用了它。写剧本实际是这样的：第 3 场还在桌边、内、夜，要加第 4 场，多半还是这场戏的延续；插在两场中间，也几乎总是紧跟前一场。每加一场都去场头把地点和日夜重新拨一遍，是纯粹的手工税。

ADR-0068 的「负面」里已经记了这条：「插在两场中间时，常常想沿用前一场的地点与日夜，现在还得手改场头。」这次补上。

## 决策

1. **默认值改取"插入点前面那一场"**：`addScene` 先算出新场的 `index`（插在 `afterSceneId` 之后就是它后面一位，否则是末尾），取 `ordered[index - 1]` 作为 `previous`，新场的 `locationId / space / timeOfDay` 依次取 `previous` 的值。
2. **没有前一场才退回旧默认**：新场插在第 1 位（`index === 0`）或项目里还没有场次时，`previous` 为空，地点仍是第一个地点，内外景 `int`，日夜 `day`。这条保证「从头开始写」的行为不变。
3. **显式传入的 `locationId` 优先**：调用方给了地点就用它，只继承内外景与日夜。目前 UI 没有传，留给以后「在某个地点下加一场」之类的入口。
4. **地点不存在时拒绝**：沿用来的地点如果已经不在项目里（理论上不应发生），照旧报「找不到这个地点」，不写事件。
5. **只改默认值，不改事件**：仍是 `scene.added`，写进去的就是继承后的完整场次；日志读起来没有"继承"这个概念，回放也是确定的。
6. **不改场头历史**：沿用只是新场的初始值，不算对上一场的修改；场头「改过几次」不受影响。

## 理由

- **"下一场就是这一场的延续"是最常见的写法**：一场戏常常跨多个场次（同地点、同时间），默认沿用能把大多数"加一场"变成零修改。
- **按位置取前一场，而不是按时间取最后一场**：插在中间时，"前一场"是观众上一眼看到的那场，这才是写作者脑子里的上下文。
- **默认值归默认值**：不新增事件、不动场头历史，所有既有回放与过期判据都不受影响。
- **显式参数优先**：以后要「在地点 X 下新建一场」时不用再改一次这个函数。

## 后果

**正面**
- 桌边 · 内 · 夜的第 2 场后面点 `＋ 加一场` → 新第 3 场直接是桌边 · 内 · 夜，不用拨场头。
- 第 1 场（走廊 · 内 · 日）后面点 `＋ 插一场` → 新第 2 场是走廊 · 内 · 日，原来的第 2 场后移成第 3 场。
- 「从头开始」不变：项目里没有场次时加的第一场仍是第一个地点 · 内 · 日。
- 测试：web 177（ADR-0069 新增 3：末尾沿用最后一场、插在第 1 场后沿用第 1 场、显式地点优先但日夜仍继承）；IR 82、gateway 17、pipeline 22；合计 298。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：把第 2 场拨成 桌边 · 外 · 夜 后点 `＋ 加一场`，新第 3 场为 桌边 · 外 · 夜；第 1 场（走廊 · 内 · 日）后面点 `＋ 插一场`，新第 2 场为 走廊 · 内 · 日，原第 2 场变成第 3 场。

**负面**
- **想换地点时仍要改场头**：新场沿用得太"聪明"的时候，用户得手动拨地点，这和以前手动拨的地点/日夜是对称的税。
- **插在第 1 位没有前一场可继承**：只能退回第一个地点，这是合理解，但用户可能以为它会学第 1 场。
- **"沿用"在日志里不可见**：只看事件流看不出这个值是默认来的还是用户拨的；不影响回放，但调试时要读代码。

**跟进**
- 在某个地点下新建一场的入口（传 `locationId`，已支持）。
- 场次模板（记住最近一次手拨的内外景 / 日夜组合）。
- 插入点选择器（插到第 N 场 / 第 N 镜）。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 沿用"时间上最后一场" | 插在中间时取到的是整部戏的结尾，不是观众上一眼看到的那场 |
| 记住用户最近一次手拨的组合 | 需要额外的偏好状态，且跨项目迁移时没有意义；按位置取更直接 |
| 给 `scene.added` 加"继承"标志，读取时再展开 | 事件应当记录结果；回放时还要维护继承链，复杂且脆弱 |
| 直接复制前一场的镜头 | 新场默认是空的（ADR-0064）；复制镜头是另一件事（分镜模板） |
| 弹出表单让用户先填地点 / 日夜 | 多一次交互；默认沿用已经把大多数情况变成零输入 |
