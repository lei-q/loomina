# ADR-0081 换人时提示帧过期与换人撤销

- 状态：已接受
- 日期：2026-11-11
- 决策人：用户 + Claude
- 关联：ADR-0057（帧过期）、ADR-0070（这一镜里换人）、ADR-0076（删除的撤销）、FEATURES A21 / F2

## 背景

在剧本页点出场签换人（ADR-0070）是"改画面输入"里最容易点错的一种：它不只换出场，还会把这一镜里被换那位的台词说话人一起改过去。两个问题：

- **换了之后已经出的帧悄悄过期**：`staleFrames` 早就把 `shot.updated { characterIds }` 算进「人物」原因（ADR-0057），关键帧页会挂 `过期`，但换人的当下没有任何提示。用户点完就走，回到关键帧页才发现两张图对不上，却想不起是哪次操作把它们打旧的。
- **换错了只能再换一次**：换回原人要求原人还在库里、还得手动把每句台词的说话人改回去。点错一个下拉，代价是四五步。

## 决策

1. **换之前提示**：这一镜已经出过首帧或尾帧时（`ScriptShot.hasFrames`），换人下拉旁边写一行小字「换人后已出的帧会挂过期」。没有帧的镜头不显示——没有东西会过期，提示只会变成噪音。
2. **换之后给撤销**：换人成功后，这一镜的出场行下面多一行「刚把「林」换成「周」」+ `撤销`；有帧时后面再补一句「已出的帧挂了「过期」」。
3. **撤销写补偿事件，不回滚**：
   - 一条 `shot.updated { characterIds }` 把**交换之前的整组出场**写回（顺序原样，不是只把两个人换回来）；
   - 对这次换人改过说话人的每一句，再各写一条 `dialogue.speaker.updated` 改回原说话人；
   - 客户端只留在内存里记「最近一次换人」：`lastSwap = { shotId, fromId, toId, prevCharacterIds, lineIds }`，刷新即失。
4. **撤销的边界**：
   - 只读、镜头已锁定 → 拒绝（「这一镜已锁定，先解锁再撤销换人。」）；
   - 这一镜已经不在了、或者换上来的人已经不在出场里 → 拒绝并清掉这条撤销（「撤不回这次换人。」）；
   - 换完之后那句台词又被别人改过说话人 → 这一句不动，只写出场（撤销只撤"这一次换人"，不覆盖后来的编辑）；
   - 只留最近一条：再换一次，上一条就撤不回来了。
5. **撤销不写撤销栈**：与删除的撤销（ADR-0076）一致，只有一个入口，撤销完 `lastSwap` 清空。

## 理由

- **提示放在下拉旁边**：用户正在做这个决定，提示必须出现在决定的那一刻；关键帧页的 `过期` 是事后账，不适合当提醒。
- **`hasFrames` 进读模型**：剧本页不看关键帧，但"这一镜有没有已出的帧"一句话就能算（`keyframes.firstAssetId || lastAssetId`）；不为此把整个关键帧读模型搬进剧本页。
- **整组出场写回**：换人时如果换上来的人本来就在场，两人会并成一位（ADR-0070）；只把 toId 换回 fromId 只能还原出一个人。存交换前的数组最准。
- **撤销留在内存**：这是"刚点错了"的即时动作，不是历史功能。写进日志反而要定义"撤销的撤销"，与 ADR-0076 的取舍同一套。
- **后来改过的句子不动**：撤销的目的是回到换人之前，不是回到"上一次任何编辑之前"；覆盖别人的编辑会制造新的惊吓。

## 后果

**正面**
- 有帧的镜头换人前能看到「换人后已出的帧会挂过期」，换完能看到「已出的帧挂了「过期」」，关键帧页那一镜的首帧挂着 `过期`。
- 换错人点一下 `撤销`：出场顺序、说话人一起回到换之前。
- 没有帧的镜头只显示撤销行，不出现过期提示。
- 测试：IR 100、web 222（新增 4：store 3、读模型 1）、gateway 17、pipeline 22，合计 361。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：剧本页点「周」→ 选「林」→ 出场变「林」，行下出现「刚把「周」换成「林」 撤销」；点 `撤销` 回到「周」「林」「试撤销」的原来顺序。有首帧时换人下拉旁出现「换人后已出的帧会挂过期」，换完撤销行补「已出的帧挂了「过期」」，关键帧页 SH-01 挂 `过期`（验证时临时往本地日志放了一张首帧，验完已清掉）。

**负面**
- **撤销刷新即失**：换完切页或刷新，撤销入口就没了。
- **只撤最近一次**：连续换两个人，只有第二次能撤。
- **撤销会写两条以上事件**：出场一条、每句改过说话人的台词各一条；日志里看到的是"撤销"而不是一条 `swap.undone`。
- **不改关键帧**：撤了换人，帧仍然挂着 `过期`（它确实比换人操作旧），要重新生成才消失。
- **提示只说"会过期"**，不说是哪几张、也不给"换完就去重生成"的捷径。
- **换人下拉仍是一次换一位**：没有"把两个人对调"的批量操作。

**跟进**
- 撤销入口跨页保留（sessionStorage）或做成真正的 swap 撤销事件。
- 过期提示里带上"首帧 / 尾帧"与生成时间。
- 换人后直接给「去重生成这一镜」的入口。
- 出场签的批量编辑（多人对调）。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 换人前弹确认框 | 换人本身是高频轻操作，弹窗会打断；一行提示 + 可撤销更轻 |
| 提示放在关键帧页 / 页头 | 决定发生在剧本页，事后再报没有帮助 |
| 撤销写回滚（删日志） | 违背只追加（ADR-0011） |
| 撤销把后来改过的说话人也覆盖 | 会抹掉用户之后的编辑 |
| 只把 toId 换回 fromId | 换上来的人本来在场时会并成一位，只回一个人还原不了原数组 |
| 撤销持久化到日志 / 本地存储 | 要定义"撤销的撤销"与跨会话的生命周期；这是即时动作，先不做 |
| 没有任何提示，只靠关键帧页的过期 | 用户很难把"过期"与刚才那次换人联系起来 |
