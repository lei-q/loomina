# ADR-0139 封面出图：抽一帧、排好标题、带上标识

- 状态：已接受
- 日期：2026-11-12
- 决策人：用户 + Claude
- 关联：ADR-0086（导出物）、ADR-0090 / ADR-0138（AI 标识与角标）、ADR-0129（服务端切帧）、ADR-0130（字幕版式）、G6 / E6

## 背景

发布需要一个 9:16 的封面（G6）。在此之前发布包里的 `cover` 只是「某一镜的一张静态图」：没有标题、没有排版、没有标识，作者得自己拿剪图软件再做一张。E6 的「未做」因此一直挂着一条「封面自动生成」。

这件事看起来小，但有三个坑：

1. **画面从哪来**：成片素材在资产库里（本机或对象存储），浏览器读视频帧既受解码限制又受 CORS 限制；预览切帧那条路（`/api/preview/frame`）已经解决了，但它的宽度上限当时只为预演定的 720。
2. **标题怎么排**：封面不是字幕，不能把一整段话铺上去；平台信息流里只看得见一两秒。
3. **标识怎么办**：封面也是要发出去的 AI 生成内容，不能只有成片上带「AI 生成」。

## 决策

1. **封面是导出物，不进 IR。** 项目里不存 PNG 也不存「用哪一帧」——它和预览 HTML、OTIO 一样是派生物。代价是刷新后要重新生成；换来的是 IR 不出现二进制、也不出现「封面与剪辑对不上」的缓存问题。发布包 JSON 里记 `coverArt`（文件名、字节数、第几镜、第几毫秒、尺寸、平台、生成时间），事后能说清这一张是怎么来的。
2. **画面复用服务端精确切帧。** 视频 take 走 `GET /api/preview/frame`（ffmpeg `-ss` 在 `-i` 之前，精确到帧），封面请求 1080 宽；为此把 `FRAME_MAX_WIDTH` 从 720 提到 1080（预演默认仍取 360，大图只在封面这条路上用）。静态图直接读入画布。两样都取不到时出**纯标题封面**（渐变底 + 标题 + 角标），不拿占位图冒充画面。
3. **排版按「一眼读完」定。** 标题最多两行、每行 9 个全角字，优先切在标点后面；字号跟着最长一行缩（宽度的 7.8%–11.5%，夹在 56–140 px）。标题块贴左下、留出 `SAFE_AREA` 的左右 6% 与底边 14%；上方一条 `#E0442E` 色条；简介第一行当钩子（最多 18 字），排在标题上方。底部压一层渐变，免得标题压在亮画面上读不清。
4. **封面带「AI 生成」角标，位置与成片同一张表。** 读 `badgePlacementOf(platform)`（H5 / ADR-0138）：竖屏信息流左上、X 右上、通用右下。三处（成片、预览、封面）不再各摆各的。
5. **标题 / 平台改过就明说过期，不偷偷重画。** 封面是作者看过才下载的；改了标题却悄悄换一张图，作者会拿旧图去发布。界面在预览旁写「标题或平台改过了，重新生成才会带上新的」。
6. **PNG 由浏览器出、浏览器下。** 画布 1080×1920 → `toDataURL("image/png")` → Blob 下载，不经过服务器；文件名沿用项目标题的清洗规则 + 「-封面.png」。
7. **排版是纯函数，绘制走公共接口。** `coverTitleLines` / `coverFontSizeOf` / `coverHookOf` / `coverArtOf` / `dataUrlBytes` 都能单测；`drawCover(ctx, …)` 只调 2D 上下文的公共方法，测试用一个记录调用的假上下文断言「画了什么、画在哪」。

## 理由

- **不进 IR**：封面是「这一次发布」的物料，不是作品状态；存成资产还要处理清理、引用、回滚，收益对不上成本。
- **复用切帧而不是在浏览器解码视频**：同源 JPEG 不会污染画布，也不需要 WebCodecs；裁切与排版的输入就是一张图。
- **纯标题封面是兜底而不是失败**：没有画面时仍能发一条带标题的片子；比拿占位斜纹图当封面诚实。
- **角标进封面**：封面在信息流里是第一屏，标识不能只在视频第二秒才出现。

## 后果

**正面**

- 成片页一键拿到 1080×1920 的封面，标题、钩子、角标都按平台摆好；E6 的「未做」清空，G6 第一档落地。
- 发布包 `coverArt` 与下载的 PNG 字节数一致，能核对「发的就是这张」。
- 抽帧复用 E7.2，没有新增 ffmpeg 调用路径；切帧宽度上限 1080 对预演无影响。

**负面**

- **刷新要重出**：封面不在项目里，重开页面后预览与下载都要再点一次。
- **720p 素材会放大**：源片只有 720 宽时，封面是 1.5 倍上采样；要更好得先有 1080 的 take。
- **只有一种版式**：没有模板选择、没有人物抠图、没有贴纸 / 多行副标题；标题过长只保留两行。
- **标题按字数切**：没有做逐字的字宽测量，英文与数字混排时折行位置可能不如专业排版。
- **角标位置仍是参考值**：与成片一样跟着平台表走，平台改版要改表。

## 未做

- 封面模板（不同题材的配色 / 字体 / 布局）。
- 人物抠图与背景替换。
- 按平台输出不同封面尺寸（当前统一 1080×1920）。
- 封面存进项目 / 资产库、历史封面回滚。
- 多版本封面 A/B。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 发布包继续只带一张原帧 | 没有标题与标识，作者还得自己再做一张 |
| 把封面 PNG 存成资产并写进 IR | 二进制与派生状态进 IR，清理 / 回滚 / 引用都要另外处理，收益不匹配 |
| 浏览器解码视频取帧 | 解码与 CORS 都不稳，画布还可能被污染；服务端切帧已经现成 |
| 用 SVG 生成封面再转 PNG | 中文字体在 SVG 转 PNG 时依赖环境，画布直接画字更可控 |
| 封面不加「AI 生成」角标 | 封面是第一屏，标识不该从视频第二秒才开始出现 |
| 标题按 CSS 宽度折行 | 中文标题短，断在词中间比按字数切更难读 |

## 附记（2026-11-12）：验证记录

- 浏览器（`/edit`，通用规格，示例项目补两条带图资产）：封面区列出「第 1 镜 · 1 版 / 第 2 镜 · 1 版」；静态图不显示取帧滑杆（写「静态图 · 不切帧」）→「生成封面」→ 预览 1080×1920、612 KB → 改平台为抖音 → 预览旁出现「标题或平台改过了，重新生成才会带上新的」。视频切帧走 E7.2 已验证的同一条路由，本次浏览器里用的是静态资产。
- 下载：`夜班-封面.png` 落盘 626599 B，与预览的 data URL 一致；打开确认画面铺满、标题在左下、角标在右下（通用规格）。
- 发布包：`夜班-发布包.json` 带 `coverArt: { fileName: "夜班-封面.png", bytes: 626599, shotNo: 2, atMs: 1440, width: 1080, height: 1920, platform: "generic", … }`。
- 单测：`lib/cover.test.ts` 15 条（折行、字号、钩子、文件名、data URL 字节数、cover-fit、纯标题兜底、角标四角）；`preview-frame` 宽度上限 720 → 1080 同步更新 2 条断言。
