# ADR-0151：自定义媒体单价

- 状态：已采纳
- 日期：2026-11-12
- 相关：H22、H12、H16、R28

## 背景

价目表（`@loomina/gateway/pricing`）只收公开、能换算成「每张 / 每秒」的模型。走 token 结算的视频模型（seedance 系列）和部分图模型没有公开公式，代码只能说「不知道」：按钮不标价、预算拦不住、账上只数次数。

S1 测绘能给出「每镜实测花费」，但那是「图 + 视频一镜」的总数（H16），不是模型的秒价，自动回写会把两种口径混在一起。作者手里真正可靠的是供应商账单：按账单填一个元 / 秒或元 / 张，就能把报价、预算与记账补齐。

## 决定

1. `ModelRecord` 新增两个可选字段：
   - `perImageCny?: number`：图像模型的元 / 张；
   - `perSecondCny?: number`：视频模型的元 / 秒。
2. 校验时按模态收字段：`perImageCny` 只在 `modality === "image"` 时保留，`perSecondCny` 只在 `video` 时保留；必须是有限、非负数，否则当没填。`unitPriceCny` 继续只管文本与配音。
3. 取值优先级：
   - 报价（`/api/price` → `imagePrice` / `videoPriceInfo`）：自定义单价 > 价目表 > 不知道；
   - 记账（生成返回的 `cny`）：供应商回执的真实花费 > 自定义单价 > 价目表。
4. 能力矩阵的单价一栏显示「作者填的自定义单价」，与价目表来源区分。
5. 设置页每个图像 / 视频模型多一个输入框：「单价（元/张）」或「单价（元/秒）」，占位符写「用价目表」。

## 理由

- **作者有账单，代码没有**：与其等供应商公开公式，不如让最了解成本的人填一个数；不填就维持现在的「不知道」，不编造。
- **报价与记账同源**：预算拦截用的秒价和最终记的金额来自同一份配置，不会出现「按 0.6 拦、按 0.66 记」。
- **供应商回执优先**：真实花费永远比估算准；自定义单价只补「回执没给钱」的那一段。

## 代价

- 配置里多两个字段，旧配置读进来没有它们，行为不变。
- 填错单价会直接反映到预算拦截与账上；界面用 hint 写清「按账单或测绘实测填」。
- 只覆盖图像与视频；文本 token 与配音字价仍走 `unitPriceCny`。

## 不做什么

- 不做按分辨率 / 时长的多维价目：一个模型一个价，复杂表留给后续。
- 不从 S1 测绘自动写回：口径不同（见 H16）。
- 不做价目表编辑：这是配置，不是共享价目库。
