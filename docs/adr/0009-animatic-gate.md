# ADR-0009 Animatic 作为强制闸门

- 状态：已接受
- 日期：2026-11-09
- 决策者：产品 / 工程
- 关联：P6、P14、L1、E10、A2

## 背景

视频生成是整条链路里最贵、最慢、最不可逆的一步。如果直接在文本层面确认剧本、然后烧钱生成视频，典型失败是：

- 故事不成立、节奏拖沓，但钱已经花了；
- 台词太长，镜头时长对不上；
- 分镜之间接不上，只能重写。

影视工业早就用 **animatic / previs**（动态分镜）解决：分镜图 + 配音 + 临时音乐，先剪成一个低成本的"预告片"，确认节奏后再实拍。

## 决策

在视频生成之前，强制（可跳过但默认执行）产出 **Animatic**：

1. 用关键帧（静态图，必要时加轻微推拉）铺满时间线；
2. 配 TTS 对白 + 临时音乐；
3. 加字幕与转场；
4. 以 540p、低码率快速渲染（分钟级）；
5. 用户确认后，才解锁视频生成；确认动作同时**锁定**分镜、时长、资产。

## 理由

- 成本约为视频生成的 1/20–1/50，却能在早期暴露绝大多数叙事问题。
- 它把"故事层"和"画面层"解耦：先用便宜手段验证前者。
- 本身就是产品功能：用户能先看到"动态分镜"，心里有底再渲染。
- 与准则 P6（AI 初稿 + 人工修改）和 P14（低成本闸门）一致。

## 后果

**正面**
- 大幅降低无效视频生成（对应 R12）。
- 用户更早建立信任：看到的是"节奏"，不是"抽卡"。
- 为自动初剪提供可靠基线。

**负面 / 代价**
- 多一个步骤，用户可能觉得慢；需要"一键生成 animatic"把摩擦降到最低。
- Animatic 的静态感可能让用户误判成片质量；需要明示"这是预演"。

**跟进**
- Animatic 渲染必须足够快（< 2 分钟），否则用户会跳过。
- 允许"跳过闸门"，但跳过时显示预计成本，并记录选择。

## 替代方案

- **直接生成视频**：成本高、反馈晚，否决为默认。
- **只看文字剧本**：无法判断视听节奏，否决。
- **只做关键帧拼图（无音频）**：判断不了时长与对白节奏，不够。
