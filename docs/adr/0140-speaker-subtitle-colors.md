# ADR-0140 按角色给字幕着色

- 状态：已接受
- 日期：2026-11-12
- 决策人：用户 + Claude
- 关联：ADR-0087（断句）、ADR-0130（字幕版式）、ADR-0091（成片烧录）、D3

## 背景

D3 的两条「未做」里，第二条是「按角色分样式」。短剧里两个人来回接话，字幕全是白色时，观众得靠自己数「谁说的」；把角色名加进字幕又会把每行撑长，竖屏本来就只有 16 个字的宽度。

颜色是更省地方的做法：同一个角色每句同色，换人换色，不需要认识字也能跟上对话。

## 决策

1. **样式差异只做颜色。** 不做按角色换字体 / 字号：多套字体在竖屏里会变成排版噪音，字号又和「版式微调」打架。颜色只改 `fillStyle`，行高、描边、位置全部共用。
2. **颜色按角色在项目里的顺序取，不按哈希。**
   `speakerPaletteOf(project.characters.map(c => c.id))` 按顺序套固定色板（六色：琥珀 / 天蓝 / 粉 / 绿 / 薰衣草 / 珊瑚）。按哈希取模时两个角色有 1/6 的概率撞同一个颜色，按顺序取在六个角色以内一定不撞；超过六个从头轮回——超过六个人说话，问题在剧本不在颜色。
3. **颜色不进 IR，开关进 IR。** `Project.subtitleLayout.speakerColors?: boolean`：缺省开，显式 `false` 是全白，`null` 清掉覆盖回到默认。颜色是派生值（角色顺序 + 固定色板），存下来只会在角色变动时变成一份要同步的旧数据。
4. **四处同源。** 读模型在断句时就给每条 `EditCue` 带上 `speakerColor`，编辑页播放器、预览 HTML（每条 cue 的 `color`）、ASS（行内覆盖 `{\c&HBBGGRR&}`）、成片 MP4 的 canvas 叠加层都读这一份。关掉开关后 cue 上就没有颜色，四处一起回到白色。
5. **没有说话人的句子回到白色。** 旁白、没标角色的台词没有「说话人颜色」，用 `#FFFFFF`，不硬塞一个色板颜色。
6. **发布包记下这一版有没有着色。** `subtitleLayout.speakerColors` 跟着字号 / 底边 / 描边走，下载的发布包能回答「这一版是按角色着色的吗」。

## 理由

- **颜色比名字省地方**：竖屏一行 16 个字，加「林：」就少两个字；颜色不占位。
- **按顺序不按哈希**：哈希的均匀分布是给「很多键」用的，一两条片子里只有两三个角色，撞色就是 100% 的坏体验。
- **开关进 IR 是为了可逆**：作者可能把片子交给平台让平台自己加字幕，这时全白更干净；存一个 `false` 就能回到纯白，而不是删掉角色重来。
- **色板是亮色**：字幕始终带黑色描边（D3），亮色在深色描边上对比足够；深色在夜景画面上会糊成一片。

## 后果

**正面**

- 多人对话一眼看出谁在说，不用名字前缀，也不加长字幕。
- 编辑页、预览、ASS、成片四处一致；关掉开关四处一起变白。
- 发布包能回答这一版是否着色。

**负面**

- **颜色跟着角色顺序走**：调换 `project.characters` 的顺序会换色（当前没有排序界面，代价很小，但要说清楚）。
- **第七个角色开始轮回**：两个角色可能同色；六色是刻意的上限。
- **不能自定义颜色**：想按角色改品牌色得另做，当前只有色板。
- **依赖描边**：关掉描边（描边 0）时亮色压在亮画面上会难读，这是作者自己的版式选择。
- **ASS 用行内覆盖**：剪辑软件里改样式时，逐条的行内颜色会盖过样式表颜色；这是 ASS 的语义，不是 bug。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 字幕前加角色名 | 竖屏一行 16 字，前缀吃掉两个字；连续对话里每行都重复又啰嗦 |
| 按 `characterId` 哈希取色 | 角色少时撞色概率高（1/6），撞了就是两个人同色 |
| 每个角色在 IR 里存颜色 | 颜色是展示层派生值，存下来要同步；角色换了还要迁移 |
| 按角色换字体 / 字号 | 竖屏里多套字体是噪音，字号还和版式微调冲突 |
| 只做预览、不进成片 | 预览与成片不一致比没有这个功能更糟 |
| 固定每个角色一种高饱和色 | 高饱和色在夜景与肤色上抢眼，亮色 + 黑描边更稳 |
