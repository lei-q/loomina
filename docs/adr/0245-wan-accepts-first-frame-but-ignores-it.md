# ADR-0245：wan3.0 收下首帧但不用它——图生视频仍未打通

- 状态：已采纳（诊断结论）
- 日期：2026-11-15
- 决策者：用户 + Claude
- 关联：B3、P4、ADR-0242、ADR-0243（被本 ADR 取代）

## 一、为什么要重验

ADR-0243 的结论是「供应商两侧的尺寸窗口不存在」——大图被代理 1024 KB / part 挡住，
小图被 `minimax-h3` 判「没有 content」。但那一轮只测了 `minimax-h3`。
同一天 `wan3.0-video-unfiltered` 被验证可用（ADR-0244），它从没试过首帧。
「换个模型也许就通了」是当时唯一没排除的变量，所以必须验。

## 二、实验一：真实探针（首帧 + 真实画面）

```bash
pnpm probe:s1 --shots 1 --budget 5
```

| 环节 | 结果 |
| --- | --- |
| `POST /v1/images/generations`（`gpt-image-2`，1024×1536） | 200 |
| `POST /v1/videos`（`wan3.0-video-unfiltered`，720p，4 秒，带首帧） | **200** |
| 轮询到 `completed` + `GET /v1/videos/{id}/content` | 200，视频 `video/mp4` |
| 产物 | h264 **720×1280**、4.04 秒、120 帧、3.2 MB，带 AAC |
| 耗时 / 花费 | 150.9 秒 / **¥2.52**（通过 1/1） |

**表面上全绿。** 但把参考首帧和视频第 0 帧并排看：

- 参考首帧：女人抬头看向画面外，门框夹在左右两侧；
- 视频第 0 帧：同一个人、同一件风衣（连左肩水渍都在），但**低头、构图不同**；
- 视频 3.5 秒：电梯门正在合拢，脸夹在两扇门之间——反而更像参考图的构图。

同一个人、同一句提示词，`gpt-image-2` 与视频模型都能画出来——
这不能证明「首帧被用了」，只能证明「两边都照着同一句提示词画」。

## 三、实验二：判定性实验（合成首帧）

真实素材会骗人（同提示词 → 相似画面）。改用**一眼能认出的合成图**：

1. ffmpeg 生成纯洋红 `720×1280` PNG（画面里除了洋红什么都没有）；
2. 直接 `POST /v1/videos`：`wan3.0-video-unfiltered`、`resolution=480p`、`seconds=4`、
   `content[].image_url.url` 塞这张图，提示词要求「保持在首帧的构图与颜色」；
3. 轮询到 `completed`，取回视频。

结果：

| 观察 | 结果 |
| --- | --- |
| 请求 | 200，任务完成，视频 854×480、4.04 秒 |
| 视频第 0 帧 | **一座书房**，没有一丝洋红 |
| 输出画幅 | **854×480 横屏**（输入是 720×1280 竖屏） |

**结论：`content[].image_url` 被接受、被转交，但没有参与生成。**
在这个路由上 `wan3.0-video-unfiltered` 是**纯文生视频**；
`480p` 还会把画幅锁成横屏，竖屏短剧用不了。

## 四、决定

1. **不宣称「关键帧 → 视频」打通**。B3 主路径仍然不通，P4 的「先图后视频」没有落地。
2. **保留首帧压缩实现**（`fitVideoFrameBytes` + `runShot` 的 `compressFrame` 钩子）：
   换到真正吃图的模型时立刻可用，且它已经让「大图被 part 限制挡住」这个错误不再出现。
3. **验证口径改成看产物**：以后判断模型能力，不看 HTTP 200，要看
   「塞进去一张合成图，出来第 0 帧是不是它」。
4. **下一步**：在 `minimax-h3` 之外找真正吃图的路由。候选：
   - `minimax-h3` 换字段 / 换交付方式（ADR-0243 里它拒收小图，原因未查清）；
   - seedance 系列（任务能建立，但**单价未知**，验之前要先问价，受 R39 约束）；
   - 供应商侧是否提供独立的 i2v 端点（`/v1/videos` 之外的路径）——待确认。

## 五、教训

- **HTTP 200 是传输层，不是能力层。** 同一个 200，第一轮看起来「通了」，
  用合成图一测就露馅。
- **判定实验要用「不可能巧合」的输入。** 洋红画面只要出现一次就说明用上了；
  真实素材反而会把「同提示词相似」误读成「首帧生效」。

## 六、边界

- 只测了 `wan3.0-video-unfiltered` 在 litellm 路由下的行为；`720p` 出竖屏正常，
  `480p` 出横屏，其他分辨率未测。
- 没有测 seedance / minimax 的替代字段，也没有测「首帧当作尾帧」这类语义。
- 两次实验共花 **¥3.72**（¥2.52 + ¥1.20）。
