# ADR-0220：表演语法库做成可版本化目录，接进 V10（I11 第一档）

- 状态：已采纳
- 日期：2026-11-14
- 决策者：用户 + Claude
- 关联：I11、I8、B16、B17、A13、ADR-0216、PERFORMANCE.md

## 背景

`PERFORMANCE.md` §五 已经写好了「AI 可生成的表演语法」：把情绪翻译成**模型能稳定生成的
具体动作**，而不是形容词。七组意图（压抑的愤怒 / 心虚 / 震惊 / 亲密 / 决绝 / 轻蔑 / 崩溃）
各自列出了可生成的手段与要避开的东西，还有一条铁律：**情绪越强，动作越小**。

`PerformanceSpec` 的字段也齐了（objective / emotion / beats / gaze / intensity / avoid）。
缺的是两件事：

- **目录**：那七组语法只活在文档里，代码里没有一份可查询的表；
- **检查**：V10 只查「有没有写 objective」，不查写的东西与语法对不对得上。
  一镜标了强度 5 却写「大喊着扑过去」，工具不会说话。

## 决定

1. **新建 `apps/web/lib/performance-grammar.ts`**，`PERFORMANCE_GRAMMAR_VERSION = "2026-11"`，
   与导演语法库（ADR-0216）同一写法。
2. **七组意图逐条登记**：`micro`（微表情）/ `body`（姿态与手）/ `avoid`（要避开的）/ `intensityHint`。
   内容与 PERFORMANCE.md §五 一一对应，不新增没写过的说法。
3. **`INTENSITY_ACTION_SCALE`**：强度 1–5 各写清可用的动作幅度，第 5 档是
   「只有微表情，身体几乎不动」。
4. **`intentOf(text)`**：按意图名与常见同义词认，只做词面匹配（与 H19 一句话指令同一口径），
   认不出就返回 undefined，不猜。
5. **`performanceAdvice(...)`** 只判两件能确定的事：
   - **强度 4–5 却写了大动作**（跑 / 跳 / 扑 / 砸 / 大喊 / 嚎哭 / 挥 / 跪…）；
   - **认出意图但 `avoid` 没写**——不写清楚，模型会按字面把表情演过火。
   返回 `problems`（人话）与建议的 `avoid`。
6. **接进 V10**：分镜检查的 V10 在「有没有写 objective」之后，再跑一遍 `performanceAdvice`，
   命中就各报一条。仍然是 `warning`，不拦生成。
7. **目录与文档同步**：`director-grammar.ts` 里 V10 的 `checks` / `fix` 补上这两条新判定。

## 理由

- **与 I8 同一套方法论**：先有目录、再有检查、最后才是自动建议。这一步只做前两步，
  边际成本最低，且立刻能用。
- **只判能确定的两条**：表演是创作，工具不该判断「这个演得好不好」。
  但「强度 5 配大喊」是文档里写死的矛盾，「没写 avoid」是缺件——这两条可以判。
- **不做自动填充**：认出「心虚」就自动把 `avoid` 写进去是替作者做决定。
  `advice` 只给出建议列表，写不写由作者点。
- **词面匹配而非模型**：与 H19 一致；模型兜底那条路已经存在，不必在这里再造一次。

## 后果

**正面**

- 七组表演语法从文档变成可查询、可版本化的资产。
- 分镜检查多两条判定：强度与动作幅度冲突、缺 `avoid`。
- 将来做「一键套用某组语法」时，目录已经就位。

**负面 / 代价**

- 同义词表是手写的，覆盖有限；说「像被踩了一脚」仍然认不出。
- 「大动作词」列表（跑 / 跳 / 扑…）是启发式，正常语境下也可能误报
  （比如「她跑过去」在强度 5 的镜里确实是问题，但在强度 2 里不是——这条已经按强度门控）。
- 只做建议不做自动填充，作者仍要自己抄一遍。
- 表演的**画面**效果（微表情是否真的演出来了）仍然无法验证，要等视觉模型。
