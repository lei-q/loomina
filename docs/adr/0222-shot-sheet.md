# ADR-0222：摄影单是全片参数总表，只读不评判（I7 第二档）

- 状态：已采纳
- 日期：2026-11-14
- 决策者：用户 + Claude
- 关联：I7、I1、I2、I4、B11、ADR-0186

## 背景

I7 第一档（ADR-0186）做的是「手调参数」：在镜头语言抽屉里逐项点景别 / 机位 / 运镜 / 焦段，
一次一项、一条 `shot.updated`。这是**改**的入口。

但作者还有另一类需求：**看全片**。分镜页一次只看一镜，于是：

- 想知道「整条片子的景别是不是太单一」，得从头翻一遍；
- 想知道「哪几镜忘了写光影」，得逐镜点开看；
- 想把这一版镜头参数发给摄影师或留档，没有出口。

I7 的未做项里第一条就是「摄影单 / 逐镜参数总表」。

## 决定

1. **`shot-sheet.ts` 纯派生**：`shotSheetOf(project)` 按场分组、场内按镜序，
   每行给景别 / 机位 / 运镜 / 焦段 / 光影 / 构图 / 时长 / 锁定，全部翻成中文。
2. **未挂进场次的镜头进「未进场次」组**，不丢——与走位台账同一口径。
3. **`summary` 只陈述事实**：各景别镜数、各机位镜数、用到的焦段（去重升序）、
   没写光影 / 构图的镜数、平均镜长。**不做评判**。
4. **`shotSheetText` 一句话摘要**：写「3 镜 · 全景 1 / 中景 2 · 平均 2 秒 · 2 镜没写光影」，
   不写「景别太单一」——是不是单一要看片子，工具不该替作者判。
5. **`shotSheetTsv` 导出 TSV**：表头齐全，粘进 Excel / 飞书自动分列。
6. **接进镜头语言抽屉**：顶部一个可折叠的「摄影单」，点镜号能选中那一镜，
   「复制表格」把 TSV 写进剪贴板。
7. **只读**：表里不能改任何参数。改参数仍然走第一档那套「一次一项、一条事件」的入口——
   表格里就地编辑会绕过校验与报价重算。

## 理由

- **「看全片」和「改一镜」是两个动作**：混在一个入口里，要么表格变成表单（重、容易误改），
  要么抽屉只服务单镜（看不全）。分开做，两边都简单。
- **不评判是刻意的**：`analyzeStoryboard` 已经在查「连续同景别 ≤ 2」（V6），
  摄影单不该重复一次判断。这里只把数据摊开，判断留给规则和作者。
- **TSV 而不是 CSV**：粘贴到表格软件时 TSV 最稳（中文逗号不会误分列）。
- **不做按场批量套用**：批量改一整场的参数需要「改哪些、保留哪些」的交互设计，
  是另一个量级；这一档先把「看得见」做出来。

## 后果

**正面**

- 全片镜头参数一屏看完，不用逐镜翻。
- 「哪几镜没写光影 / 构图」有明确数字。
- 能导出成表格，便于留档或给协作者。
- 点镜号能跳回那一镜，看细节仍然走原入口。

**负面 / 代价**

- **只是看得见，不能批量改**：想改一整场仍要逐镜点。
- 光影只显示主光方向，不显示光源与塑形（表格太宽会挤掉更重要的列）。
- 构图只显示规则名，不显示补充说明。
- 导出的 TSV 不含台词与时长以外的内容，不是完整的分镜表。
- 没有「按焦段排序」「只看没写光影的镜」这类筛选，镜数一多仍要自己找。
