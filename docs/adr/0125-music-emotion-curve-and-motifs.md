# ADR-0125：音乐情绪曲线是派生的，主题动机（leitmotif）进 IR

- 日期：2026-11-11
- 状态：已采纳
- 关联：C10、C4、C12、C5、A11、A12、ADR-0099、ADR-0120、ADR-0020

## 背景

SOUND.md 第五节给了两条规矩：**每个 Beat 对应一个音乐状态，只做进 / 转 / 出三件事**；**给角色、关系、地点各一个短动机，重复与变奏**。还给了三条纪律：留白、不盖对白、卡点服务剪辑。

现状（ADR-0099 / ADR-0120）：`Timeline.music` 是一组 `MusicCue`，每条 = 一个音频资产 + 起止 + 增益 + ducking + 授权备注。它是**一条从头铺到尾的床**——`edit-screen` 里一次只加一段，`render-manifest` 最多收 4 条。Beat 与音乐之间没有任何关系，leitmotif 连字段都没有。

也就是说：作者能放音乐，但系统不知道哪一拍该响、哪一拍该静，也不知道这段音乐代表谁。

## 决策

### 1. 情绪曲线是派生的，不存进 IR

`analyzeMusicCurve(project)` 与 `analyzeStoryboard` / `analyzeScript` 同类：只读、可单测、不写事件。

每个 `BeatSpan`（A11 的 `groupBeats`）算出一个建议状态：

| Beat | 建议状态 | 理由（SOUND.md 第五节） |
| --- | --- | --- |
| hook | `enter` | 进来就要有，或故意留白制造不安 |
| setup | `bed` | 低存在感铺底 |
| escalation | `build` | 加层 / 加节奏 |
| turn | `drop` | 突变或抽空 |
| climax | `peak` | 最强点 |
| resolution | `resolve` | 收住 |
| endHook | `unresolved` | 留一个未解决的和声 |

输出：每拍的建议状态、当前有没有 cue 覆盖、留白区间与总时长、cue 与拍边界不对齐的列表、覆盖率百分比。

**建议不是指令**：它只是把 SOUND.md 的表格变成一排色块，作者可以完全不理。

### 2. `MusicCue` 加 `role` 与 `motifId`

```ts
role: z.enum(["bed", "hit", "transition"]).default("bed"),
motifId: Id.optional(),
```

- `role` 回答「这一段在音乐结构里干什么」，用于曲线显示与复盘；旧日志读出来是 `bed`。
- `motifId` 指向下面第 3 条的动机。带 `motifId` 的 cue 在曲线上标出名字。

**不新增 `silence` 角色。** 留白就是「这一段没有 cue」，加一个什么都不存的空 cue 只会让「忘了铺」和「故意留白」看起来一样，而它并不能让作者少做一步。

### 3. 主题动机进 IR

```ts
export const MotifSchema = z.object({
  id: Id,
  /** 人话名字，例如「林晚的灯」 */
  label: z.string().min(1).max(40),
  /** 代表谁 / 哪对关系 / 哪个地点 */
  targetKind: z.enum(["character", "relationship", "location"]),
  targetId: Id,
  /** 动机音频：一段可循环的短素材 */
  assetId: Id,
  /** 授权来源，与 cue 同一口径：没有它不许存 */
  licenseRef: z.string().min(1).max(240),
  note: z.string().max(200).default(""),
});
```

`Project.motifs: Motif[]`（默认 `[]`）。校验写在 `applyEvent`：

- `assetId` 必须存在且 `kind === "audio"`；`licenseRef` 非空。
- `targetId` 必须存在于对应集合（角色 / 关系用 `from->to` 编码成 id / 地点）。
- **同一个 target 只能有一个动机**：重复定义时后写的覆盖？不——直接拒绝，让作者先删。同一目标两个动机，界面上没法决定用哪个。

事件：`motif.updated { motif }`（整条新增或替换，按 id 幂等）、`motif.removed { motifId }`。两者补进 `event-log.ts` 的 `EVENT_TYPES`；`LOG_VERSION` 不需要升（`role` 与 `motifs` 都有默认值）。删除动机时把引用它的 cue 的 `motifId` 一起清掉（不删 cue 本身，音乐还在）。

### 4. 关系类动机的 targetId 编码

关系没有自己的 id，两端是 `fromCharacterId` / `toCharacterId`。用 `${from}->${to}` 作为 `targetId`（有向，与 A16 的 relationship 一致）。校验时检查这一对确实在 `story.relationships` 里。

这是刻意的取舍：不为关系新造实体 id，因为关系的身份本来就是这一对。代价是角色被删时，指向它的关系动机一起失效——所以 `character.removed` 的补偿逻辑要顺手清理引用它的动机（与现有「删人前先清出场与台词」同一处）。

### 5. 界面：成片页的配乐区加一条曲线

- cue 列表上方一条横条：按 `BeatSpan` 分宽的色块（按建议状态着色），下面叠 cue 的实占区间；没有 cue 的拍标「留白」并写时长。
- 每拍一行：`钩子 · 3.0s · 建议 enter · 已有「tone」`。点一行可把选中的素材铺到这一拍（写一条 `timeline.music.updated`，整条替换）。
- 「按曲线铺一遍」按钮：对**没有 cue 覆盖**的拍，用当前选中的素材建 cue，边界对齐拍的起止。只在至少有一个带授权的音频资产时可用；结果最多 4 条（渲染清单上限），超出时提示「先合并相邻的拍」。
- 动机区：新建 / 删除动机，列表显示「林晚的灯 · 林晚 · 8.0s · 已用 2 处」。新建时选音频 + 选目标（人物 / 关系 / 地点下拉）+ 填授权来源。
- cue 的编辑表单多一个「动机」下拉（可空）。

### 6. 不做自动选段与 BPM 卡点

- **自动选段**：需要曲库与情绪标注，当前只有作者自己导入的素材（C4 的生成也还没做）。系统没有可选的东西，不造一个假装在选的按钮。
- **BPM 卡点（C5）**：需要节拍检测（新增依赖）与剪辑点重排；它属于 C5，不在 C10 里顺手做。
- **变奏**：leitmotif 的「变奏」需要音频处理（变速 / 变调 / 重配器），本机只有 ffmpeg。第一版动机只做「同一段素材重复出现」，变奏留到 C4 生成音乐之后。

## 理由

- **曲线派生**：曲线是 beat 的函数，beat 改了曲线就该变；存下来要配失效机制，而它没有跨会话引用价值。
- **动机必须存**：它记录的是创作决定（「这段音乐代表林晚」），无法从任何数据推出来。这是本次唯一新增的 IR 实体。
- **留白不建实体**：空 cue 不承载任何事实，只会让「忘了」与「故意」长得一样；曲线把留白显示出来，作者看一眼就知道。
- **不假装自动选段**：手上只有作者导入的素材，系统的「自动」只能是随机挑一条，比让作者自己选更慢。

## 后果

**正面**

- 音乐第一次和 Beat 建立关系：哪一拍该响、哪一拍该静，一眼能看到。
- leitmotif 有了位置，跨集复用时能按角色找回同一段动机（A6 连载的基础）。
- 不改渲染路径：cue 还是 cue，只是多了两个字段。

**负面**

- 曲线是启发式的（按 beat 类型查表），不知道具体剧情；作者可能觉得「这一拍该静」而系统说该进。
- 动机的「变奏」没有实现，只能原样重复，听久了会腻。
- 渲染清单仍是 4 条上限，曲线铺满 7 拍时要合并。
- 关系动机用 `from->to` 编码，角色改名不影响、删角色要联动清理。

**跟进**

- C4 音乐生成落地后，动机可以从生成结果里挑，并支持「同一动机的变奏版本」。
- C5 做 BPM 卡点时，曲线可以直接给出切点建议。
- 曲线状态可以进 `edit` 阶段的可豁免缺口（像 ADR-0118 那样），但要等真实片子验证误报率之后再定。

## 成本

| 项 | 估计 |
| --- | --- |
| 曲线分析 | 0 元，纯本地 |
| 动机 | 0 元，复用已导入的授权素材 |
| 工程 | schema + 事件 1 天；曲线条与逐拍行 1.5 天；动机区 1 天；「按曲线铺一遍」0.5 天 |

## 验证（设计阶段口径）

- 单测：`analyzeMusicCurve` 在示例项目上给出拍数、覆盖率、留白总时长；cue 跨拍边界时被点名；没有 cue 时覆盖率 0%、留白 = 全片。
- schema：`role` 缺省为 `bed`；动机指向不存在的资产 / 非音频 / 空授权被拒；同一目标重复定义被拒；关系动机的两端必须存在于 `story.relationships`。
- 事件：`motif.updated` 幂等替换；`motif.removed` 清掉 cue 的 `motifId` 但保留 cue；删角色时引用它的关系动机被清理。
- 浏览器：成片页加一段 `tone.mp3` → 曲线显示拍数、留白与覆盖率 → 点「按曲线铺一遍」→ cue 数增加且每条起点落在拍边界 → 选一个角色建动机 → 列表显示「已用 0 处」→ 把某条 cue 指到该动机 → 曲线上出现名字。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 曲线存进 IR | 它是 beat 的函数，beat 一改就过期，且没有跨会话引用价值 |
| 新增 `role: "silence"` 的空 cue | 不承载任何事实，只会让「忘了铺」与「故意留白」看起来一样 |
| 动机按角色名匹配 | 改名即失效；targetId 是稳定身份 |
| 为关系新建实体 id | 关系的身份就是这一对，新造 id 要额外维护生命周期 |
| 自动按情绪选段 | 手上只有作者导入的素材，系统的「自动」只能是随机挑一条 |
| 顺手做 BPM 卡点 | 需要节拍检测依赖与剪辑点重排，属于 C5，且未确认引入依赖 |
| 动机支持变奏 | 需要音频处理链路，等 C4 生成音乐后再做 |
| 把曲线做成硬闸门 | 启发式判断不该拥有否决权（同 ADR-0118 / 0123 的口径） |
