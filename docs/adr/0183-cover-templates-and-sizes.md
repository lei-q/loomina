# ADR-0183：封面版式、按平台尺寸与封面进资产库（G6 第二档）

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：G6、E6、G9、H5、H14、ADR-0139、ADR-0168

## 背景

G6 第一档（ADR-0139）把封面做成「抽一帧 + 标题排版 + 角标」，但只出得了
一种样子：固定 1080×1920、固定左对齐、固定一条品牌色条；封面出完只能下载，
刷新就没了；下一集要用同一张封面得重新剪一遍画面。

抖音与快手要 9:16，小红书要 3:4，B 站与 X 要 16:9。现在所有平台都拿到同一张
竖图，作者要么自己裁，要么接受平台裁。三种「上一集用过的封面」也接不上：
封面不是资产，只是导出物。

## 决定

1. **尺寸跟着目标平台走，不再固定 9:16**
   - `platformSpecs.coverRatio` 是唯一来源：9:16 → 1080×1920，3:4 → 1080×1440，
     16:9 → 1920×1080。
   - 短边固定 1080：够清楚，又不会让一张 PNG 大到几十兆。
   - 非 9:16 的下载文件名带上比例（`…-封面-3x4.png`），两张封面不会互相覆盖。
   - 预览框的宽高比与显示宽度跟着比例变，作者换平台前就能看出构图变化。

2. **四种版式，不做设计工具**
   - 剧照（左色条 + 左对齐，红）、杂志（暖金条 + 左对齐）、
     极简（无装饰 + 居中）、黑白（灰细条 + 居中）。
   - 版式只决定点缀色、对齐与是否画色条，标题折行 / 字号 / 安全区 /
     角标规则全部沿用 ADR-0139，不因版式分叉。
   - 认不出的 `styleId` 退回「剧照」，旧封面记录（没有 `styleId`）也走这一条。

3. **封面可以存进资产库**
   - 新增 `saveCoverAsset`：PNG 走 `persistAsset`（内容寻址、同一张图不重复存），
     记一条 `asset.updated`，同时写 `provenance`（`modelId: "loomina.cover"`、
     标题与尺寸进 prompt），资产来源是 `generated`。
   - 资产 id 用 `a-cover-<ts>`，与生成视频 / 关键帧的命名区分开；
     资产库里按「封面」辨识，下一集直接取用，不用重新出。
   - 「存进资产库」成功后按钮变成「已存进资产库」，避免连点存出多份；
     改标题或换平台后要重新生成再存——不让旧图顶着新标题进库。

4. **封面仍然是导出物，不进 IR**
   - 沿用 ADR-0139 的边界：`Project` 里没有二进制；发布包的 `coverArt`
     继续只记文件名 / 字节数 / 镜号 / 时刻 / 尺寸 / 平台 / 生成时间，
     再加 `styleId` 记这一张是用哪种版式出的。
   - 「存进资产库」是**另存一份资产**，不是把封面挂回项目；
     资产库里能查到它被谁引用（asset-inventory 的既有机制）。

## 理由

- **平台差异是硬约束**：发布前平台按自己的尺寸裁图，竖图进 16:9 会被裁掉
  大半张脸。让封面在出图阶段就按目标平台构图，比发布时补救便宜。
- **四种版式够了**：封面的任务是一秒读完标题；选项越多，作者在封面上花的时间
  越接近剪片本身。真要更细的排版，属于设计工具，不在短剧生产线的范围里。
- **封面入资产库 = 复用**：系列剧每集封面同一套视觉，第二集开始直接拿第一集的
  版式与素材改字，而不是从零再画一张。这也是「生成过的东西都是资产」
  这条准则（C.2）在封面上的第一次落地。
- **不进 IR**：封面是「某一帧 + 文字」的派生物，存进 IR 只会让事件日志变大，
  且引入「封面与剪辑对不上」的缓存问题（ADR-0139 已论证）。

## 后果

**正面**

- 一次生成就能拿到符合目标平台比例的封面；换平台时尺寸与文件名一起变。
- 四种版式覆盖剧照 / 杂志 / 海报 / 黑白，系列剧可以固定一套。
- 封面成为可复用资产，下一集 / 下一个项目直接取。

**负面 / 代价**

- 换平台后旧封面不自动重出，只提示「标题或平台改过了」；作者要再按一次。
- 封面资产是普通图片资产，资产库不会自动把「哪张是封面」与别的图片分开，
  只能靠来源 `loomina.cover` 与文件名辨认。
- 版式只有四种且位置固定，不能拖标题、不能换字体；需要这些属于设计工具。

## 不做

- 多版本封面 A/B（要发布数据回流才有意义，H14 一并考虑）。
- 人物抠图 / 主体分离（依赖分割模型，供应商能力）。
- 自定义字体上传与文字拖动排版。
- 封面与发布包的一键回滚（封面不属于 IR；要回滚重出一张即可）。
