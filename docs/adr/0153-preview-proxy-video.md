# ADR-0153：540p 预览代理视频

- 状态：已采纳
- 日期：2026-11-12
- 相关：E7、ADR-0127、ADR-0129、H3、H13

## 背景

E7.1 的时间轴与 E7.2 的帧级找点都已落地，但预演 `<video>` 一直播 1080p 原片。拖动时浏览器要从最近关键帧之后解码，片长与码率越大越卡；ADR-0127 §3 把「代理生成」列为帧级能力的前置条件，后来 E7.2 改用服务端 ffmpeg 切帧（ADR-0129），代理这条线没有继续做。

## 决定

1. 新增 `GET /api/preview/proxy?asset=<loomina://…|s3://…>`：第一次请求用 ffmpeg 把原片转成 540×960 / 24fps / CRF 30 / ultrafast / 无音轨 / faststart 的 H.264，落 `.loomina/assets/proxies/`（0700 / 0600），之后直接命中缓存。
2. 只认资产库地址（`loomina://` 与 `s3://`）。`data:` 过大且本就该先迁库；`https://` 要走受控下载，另开路径再说。
3. 支持 `Range`：`<video>` seek 时只回它问的那一段（206 + `Content-Range`），不把整段代理反复回给浏览器。
4. 并发去重：同一地址的多个请求共用一个转码 Promise；先写临时文件再 `rename`，半份代理不能冒充缓存。
5. 预演加「540p 代理」开关：只在当前镜有资产库片子时可勾；代理出错或转不出来就自动回原片并写明原因。导出继续走原片与 `/api/render`，代理永远不进 IR、不参与清单、不算资产。
6. 代理是可删缓存：删掉 `proxies/` 目录会按需重建，不需要迁移或事件。

## 理由

- **预览只回答节奏问题**：540 宽与 `RENDER_PROFILES.draft` 同规格，竖幅预演框最高 620px，再高看不出差别。
- **不改 IR**：代理是派生物，不是项目事实；写进事件日志会让每次回滚、迁移与清理都多一个假资产。
- **不新开渲染路径**：转码只是把一条已有片子缩小，产物只给预演；成片仍由 ffmpeg 渲原片（ADR-0120 的同一条不变量）。
- **按需生成**：项目里 12 镜大多还没有片子，预先批量转码会白占 CPU 与磁盘。

## 代价

- 第一次勾开关要等一次转码（本地 3 秒片子约 1–3 秒），界面写明「第一次会转一小会儿」。
- 代理目录额外占磁盘；没有自动清理，作者可随时删目录。
- 一个地址一个缓存名，换了转码参数不会自动失效；当前文件名带 `.540.` 区分规格。

## 不做什么

- 不做 WebGPU 合成（E7.3 仍按 ADR-0127 暂缓）。
- 不做浏览器内导出，不做代理上传对象存储。
- 不做代理预生成、批量队列或容量上限；这些等真实项目里出现磁盘压力再设计。
