# ADR-0218：音效按角色自动响度归一（C7）

- 状态：已采纳
- 日期：2026-11-14
- 决策者：用户 + Claude
- 关联：C7、C12、ADR-0099、ADR-0184

## 背景

C7 的音效层（ADR-0184）已经能加、能调增益、能试听，但**增益是作者填的固定值**
（默认 −12 dB）。同一段素材放进项目，无论原始音量多大，都按 −12 播。

对白早就不是这样了：C12（ADR-0099）逐句量 LUFS、按 −18 归一，最多 ±12 dB。
音效却一直没跟上，后果是：

- 从不同来源拿的音效（自录、音效库、模型生成）响度差很远，作者得一条条试听再手调；
- 环境声（应该垫在后面）和重音（应该跳出来）用同一个默认值，要么环境太吵，要么重音听不见；
- 渲染报告里只有对白的增益，看不出音效到底被怎么处理了。

## 决定

1. **`sfxGainDb(inputLufs, role, maxDb)`**：与 `segmentGainDb` 同一个口径——
   量不到（null / 非有限 / 静音 −70）就不动，结果按 0.1 dB 取整。
2. **目标位按角色分**，不是一刀切：

   | 角色 | 目标 | 理由 |
   | --- | --- | --- |
   | 拟音 `foley` | −20 LUFS | 贴近动作，比环境响、比重音轻 |
   | 重音 `impact` | −18 LUFS | 要跳出来 |
   | 环境 `ambience` | −30 LUFS | 垫在后面，不能抢对白 |
   | 转场 `transition` | −22 LUFS | 过渡用，略低于重音 |

3. **单条最多 ±15 dB**：比对白的 12 dB 宽一点（音效来源更杂），但仍有上限——
   超过 15 dB 多半是文件本身有问题，不该拿增益硬修。
4. **叠加而不是替换**：归一结果是**加在作者写的 `gainDb` 之上**的增量，
   手动压过的那一档仍然有效，最后仍夹在 IR 的 −40–0 dB 区间里。
5. **渲染清单带 `role`**：`RenderSfx.role` 可选，解析时按白名单校验；
   不带就按拟音。`render-client` 从 `SfxCue.role` 原样传下去。
6. **报告记下来**：`LoudnessReport.sfxGainsDb` 记每条音效叠加了多少，
   成片页与对白增益并排显示（「音效按角色归一：3 条，叠加增益 +4.2 / −1.0 / 0.0 dB」）。
7. **量不出来就不动**：远程音效下载失败、素材缺失都不影响其它条——
   与对白逐句量的失败处理一致。

## 理由

- **对白已经这么做了**：同一套方法论（先量再归一，量不到就不动）在 C12 验过，
  音效沿用不需要新的判断，也不会出现「对白归一、音效不归一」的半截状态。
- **按角色分目标位是必要的**：这是音效与对白最大的区别——对白只有一种角色，
  音效有四种用途，用同一个目标位等于放弃「环境垫底、重音突出」这个基本混音常识。
- **叠加而不是替换**：作者手动写 −6 dB 是有意的（比如这条音效就是要轻），
  归一不该把它抹平。自动归一解决的是「不同来源响度不一致」，不是「作者不会调」。
- **±15 dB 而不是无限**：抬得太多会把底噪一起放大，这是 C12 已经写过的道理。

## 后果

**正面**

- 音效不用一条条试听手调：从任何来源拿来的素材，进来就落在合理响度。
- 环境声不再盖住对白，重音能跳出来——这是 C7 最初想要的「三路平衡」的另一半。
- 渲染报告能查到每条音效实际叠加了多少，出问题可追溯。

**负面 / 代价**

- 每条音效要多跑一次 `measureLoudness`，渲染时间略增（音效最多 8 条）。
- 目标位（−20 / −18 / −30 / −22）是经验值，**没有用样片标定过**；
  与 `SFX_MAX_GAIN_DB = 15` 一样，属于「先用着、将来按实际听感调」的默认值。
- 只按角色归一，不按**场景**归一：同一场里两条环境声仍可能不一致。
- 不做淡入淡出、不做按场景切混响——这些仍在 C7 的未做项里。
