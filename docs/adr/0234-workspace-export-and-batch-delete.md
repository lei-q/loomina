# ADR-0234：删空间前可导出日志，已归档的可以一次清掉（C15 补完）

- 状态：已采纳
- 日期：2026-11-14
- 决策者：用户 + Claude
- 关联：C15、ADR-0188、ADR-0201、ADR-0210

## 背景

C15 的未做项里有两条挨着：「批量删除」与「删除前导出」。

现状是**删了就没了**：`deleteWorkspace` 会把这个空间的事件行、日志版本与登记
一起清掉（素材文件不动，但「这个空间里发生过什么」永远查不到了）。而删空间
只能一个个点，归档后想清理也得逐个操作。

这两条要一起做才有意义：没有导出，批量删除就是把一堆不可恢复的操作打包；
有了导出，批量删除才敢做成一步。

## 决定

1. **`workspace-export.ts` 纯函数**：`workspaceExportOf` 拼出
   `{ format: "loomina.workspace-export", version, exportedAt, workspace, log, note }`，
   `workspaceExportFileName` 生成 `<名字>-<日期>.json`。
2. **明确写了「这不是备份格式」**：`note` 字段与 ADR 都写清——不含素材文件本身，
   **没有任何导入功能会读它**，它只用来事后查。
3. **store 返回 JSON、组件负责下载**：`exportWorkspace(id)` 返回
   `{ fileName, json } | undefined`，不碰 DOM——这样这段逻辑可测。
4. **批量清理只针对归档空间**：`deleteArchivedWorkspaces()` 只删
   `archivedAt` 有值的，且排除当前打开的空间（它本来就不能归档）。
   返回删掉的空间数；一个都没有时返回 0 且不报错。
5. **界面上都是两步**：单个删除原本就是「删 → 真删/算了」；
   新增的「清理已归档（N）」同样先展开确认、再点「真清」。
6. **每个空间多一个「导出」按钮**：删之前至少能留个底。

## 理由

- **先给出口，再给批量**：批量删除的破坏力是单个的 N 倍，配一个导出出口，
  作者在按下「真清」之前至少有一次机会把日志留下来。
- **不叫「备份」**：叫备份会让人以为能导回来。它没有导入端，
  名字与说明都必须诚实（与项目一贯的「没做就说没做」同源）。
- **store 不碰 DOM**：下载要 `Blob` / `URL` / `<a>`，这些在测试环境里没有；
  把 JSON 与文件名交给组件，store 侧就能用纯断言覆盖「找不到空间 / 无 IndexedDB」。
- **只清归档的**：想留的会取消归档，归档本身已经是「暂时不想看到它」的明确信号。
  只删这一类，不需要多选界面，也不会误删正在用的。

## 后果

**正面**

- 删空间第一次有出口：日志能留底，不是「手快就没了」。
- 归档空间能一次清掉，不用逐个点。
- 导出格式自带 `note`，拿到文件的人不会误以为能导回去。

**负面 / 代价**

- **不能导入**：导出只是留底，要恢复得自己照着日志重做（本次不做导入）。
- **不含素材字节**：素材是全机共用、按地址引用的；换机器后导出包里的地址可能失效。
- 批量清理没有「勾选其中几个」的精细控制——只按「归档」这一个状态批量处理。
- 工作空间级权限与分享仍未做。
