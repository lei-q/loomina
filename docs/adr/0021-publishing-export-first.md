# ADR-0021 发布以导出为底线，三层能力，不做逆向

- 状态：已接受
- 日期：2026-11-09
- 决策者：用户 + Claude
- 关联：P9、P20、ADR-0006、PUBLISHING.md

## 背景

"一键发布到多平台"是最初的产品设想之一，但落地时会撞上现实：

- 各平台开放 API 程度差异极大，部分需要企业资质与审核；
- 小红书等平台没有公开的发布 API；
- 逆向登录、模拟点击、Cookie 注入属于违规，账号与法律风险高；
- 平台规格（画幅/码率/时长/封面/标题）各不相同且会变化；
- AI 生成内容标识与内容安全是上线前置条件，不是可选项。

如果产品把"代发"当核心能力，任何一个平台改规则都会让功能失效。

## 决策

**发布采用三层能力，L1 导出为底线，明确不做逆向自动化。**

1. **L1 导出包（P0，永远可用）**：按 `PlatformSpec` 渲染符合规格的成品 + 封面 + 标题 + 简介 + 话题 + 字幕 + `AILabel`，自包含、可手动上传。
2. **L2 官方 API（P2）**：OAuth 授权后代发；按平台逐个接入，需资质与审核。
3. **L3 移动端分享扩展（P1）**：系统 Sharesheet / Share Extension，用户主动一键分享；覆盖无 API 平台。
4. **明确禁止**：逆向登录、模拟点击、批量养号、绕过平台审核、爬取平台数据。
5. **合规内建**：AI 标识在渲染阶段写入；内容安全四个检查点；每个素材必须有授权记录。

## 理由

1. **导出不依赖任何平台政策**，是唯一稳定的能力。
2. **分享扩展合规且覆盖广**，是"一键发布"最现实的形态。
3. **逆向的收益短期、风险长期**，对单人项目是不可承受的。
4. **合规是上线前提**（P9），必须在管线里，而不是发布时补。

## 后果

**正面**
- 平台规则变化不会让产品"不能发片"。
- 合规检查前移，减少下架与返工。
- 发布包自包含，用户随时可手动发。

**负面**
- "全自动一键发布"的体验打折扣，需要在话术上诚实。
- 需要维护 `PlatformSpec` 版本表与授权台账。
- L2 接入受资质与审核周期限制。

**跟进**
- 建立平台规格表与定期校验任务。
- 建立授权台账与发布前阻断。
- 移动端分享扩展方案在 S6 前确认（iOS/Android 各自实现）。

## 替代方案

- **只做 API 代发**：覆盖窄、受资质限制、平台一改就废，放弃。
- **逆向自动化**：违规、封号、法律风险，放弃。
- **只做导出**：体验差，但作为底线保留，再叠加 L2/L3。
