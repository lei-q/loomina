# ADR-0034 事件日志落在浏览器本地，刷新不丢

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0011（事件日志）、ADR-0027（本地写回）、ADR-0031 / ADR-0032（出图）、ADR-0033（成本）、H18

## 背景

到 ADR-0033 为止，项目状态只活在当前标签页里：刷新一下，刚锁的定妆、刚生成的图、刚记的成本全部回到示例项目。

这不只是"体验不好"。生成一张定妆图要二十到四十秒、要花钱，四格是一百秒；用户切走再回来、误触刷新、换个页面再点回来，钱就白花了。一个会丢东西的编辑器，用户不敢认真用。

## 决策

1. **存事件日志，不存项目快照**：日志是事实，项目是它跑出来的结果（ADR-0011）。追加一条很便宜，回放一次就得到当前项目，也不用为每种改动写序列化。
2. **落点是 IndexedDB**（库 `loomina`，对象仓 `events`，`seq` 自增），不是 localStorage：一张定妆图约 2.4MB 的 data URI，四个角色就顶破 localStorage 的 5MB 额度。
3. **启动时恢复，只恢复一次**：`hydrate()` 读本地日志 → `parseEvents` → `rebuild`。恢复之前不写存储，否则示例项目会盖掉已存的内容。
4. **`parseEvents` 是硬闸门**：类型不认识、没有 `project.created`、快照过不了 `ProjectSchema`、资产过不了 `AssetSchema`、`rebuild` 跑不通——任何一条不满足就整份丢弃，回到示例项目。宁可从零开始，也不要拿半截日志跑出一个坏项目。
5. **同步按差别走**：`diffEvents(prev, next)` 判断是"只在末尾多了几条"（逐条 `append`）还是"重来一遍"（整份 `replace`）。一次留用决策不该重写上百 MB 的图片。
6. **写入失败要让人看见**：`storageError` 进 store，顶栏显示"未保存"（悬停看原因）。界面照常可用，但用户不能以为已经存住了。
7. **只存浏览器本地，不做多端同步**。同一个浏览器同一份数据，换设备就看不到——这与"还没有服务端"一致。

## 理由

- **日志优先是这套架构一直的路线**（ADR-0011、ADR-0027）。如果这里存快照，就会出现"事件日志"和"快照"两套事实，早晚对不上。
- **逐条追加**不只是省字节：IndexedDB 一次写入的事务只包含一条记录，图片再多也不会卡住主线程。
- **宁可丢弃也不修复**是刻意的：坏日志能跑通一次 `rebuild` 说明不了它对，后续每个事件都会落在错误的前提上，用户看到的是"莫名其妙变了"。
- **失败可见**：静默失败比崩溃更糟——崩溃至少让人知道出了事。

## 后果

**正面**
- 刷新、切页、重开浏览器都能回到刚才的进度；花过钱的图不再丢。
- 没有引入依赖，也没有引入服务端：IndexedDB 是浏览器自带的，代码不到两百行。
- 存储实现可替换（`setEventLog`），以后换成服务端或云端队列只改一行。
- 实测：进定妆页写 1 条引导事件 → 锁一个道具 → 库里 2 条 → 刷新后仍是 2 条，界面显示"1 / 7 已锁定"。

**负面**
- **没有版本迁移**：`ProjectSchema` 一旦改动，旧日志可能整份判废。现在靠 schema 的默认值兜底；真正需要迁移时要写 `schemaVersion` 与迁移函数。
- **多标签页会互相覆盖**：两个标签页各自持有内存状态，后写的覆盖先写的。要解决得用 `BroadcastChannel` 或锁。
- **本地即真相**：清浏览器数据就等于删项目，没有云端备份；"重置"目前也没有二次确认。
- 图片以 data URI 存在 IndexedDB 里，一个角色四格约 10MB；十个角色就是 100MB，迟早要换对象存储（H3）。

**跟进**
- 日志加 `schemaVersion` 与迁移函数，别让一次 schema 改动废掉用户的项目。
- 多标签页：写入前比对 `seq`，或加 `BroadcastChannel` 让其他页只读。
- "重置示例"加确认，并明确"会删掉本地全部进度"。
- 对象存储接通后，日志里只存 assetId，图存在服务端。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| localStorage | 5MB 额度，两三张图就满；同步写还会卡主线程 |
| 只存快照 | 与事件日志形成两套事实；每次改动都要重新序列化整个项目（含全部图片） |
| 建服务端与数据库 | 用户还没登录体系，为"别丢"先建后端是本末倒置 |
| 用 IndexedDB 库（idb / Dexie） | 需要的只有 `getAll` / `add` / `clear`，原生 API 够用（准则：不引入重型依赖） |
| 日志坏了就地修补 | 修出来的项目可能"看起来能跑"，错得更隐蔽 |
