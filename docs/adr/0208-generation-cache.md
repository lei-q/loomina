# ADR-0208：结果缓存与复用（H14）

- 状态：已采纳
- 日期：2026-11-14
- 决策者：用户 + Claude
- 关联：H14、B2、C2、C16、C22、ADR-0162、ADR-0185、ADR-0206

## 背景

H14「结果缓存与复用」一直挂在待设计。真实的浪费是：**同一套输入第二次生成**。
最常见的是点两次生成、刷新后重来、批量补缺把已经出过的又跑一遍；
一次出图 ¥0.12 起，视频一次几元，重复跑就是在烧钱。

已有的复用能力都在「跨空间 / 跨集」：C16 挑图、C22 照设定开工、C2 关键帧历史。
没有一处回答「这次要生成的输入，是不是已经出过」。

## 决定

1. **缓存键 = 模型 + 最终提示词 + 参考图内容指纹**
   - 提示词必须是**服务端实际会发出去的那一段**：把 `plan()` 从
     `generate-image.ts` 抽到 `lib/image-plan.ts`，服务端与客户端共用
     （各写一遍必然漂，缓存就会把一张不对的图当成命中）。
   - 参考图用**内容指纹**（内容寻址地址里已含 sha256），不是资产 id：
     同一张图换了 id 也算同一张。
   - 两侧的参考图 id 列表都用 `referenceAssetIds`（出处里记的那一份），
     不用「真发出去的 references」——后者会过滤掉没地址的图，两边列表不同。
   - 本机没固定 / 没选定模型时，模型这一项**跳过比对**：两次都落到服务端的
     同一个默认模型（否则键永远对不上）。
2. **缓存不另存一份**
   - 命中的是项目资产里 `source === "generated"` 且有地址、有 `provenance.prompt` 的图；
     键从出处现算，不新增 IR 字段、不新增 IndexedDB 仓。
   - **不排除「这一格自己」**：重生成同一格时，这一格上一次出的图正是要复用的对象；
     排除它会让缓存永不命中（开发时踩过）。
3. **复用 = 一条 `asset.updated`**
   - 资产位写同一个地址，`source: "library"`；**不抹 `costCny`**——那是这一格
     当初真花过的钱（`asset.updated` 是浅合并，事件不带就保留原值），
     与 C2 关键帧历史复制件同一口径。
   - 去掉 `review`：复核结论属于当初那张输出，不属于这次复用。
   - 溯源保留「当初是哪个模型、什么提示词」，界面据此说「复用了哪一次」。
   - 不发请求、不花钱；`after` 回调照常执行（首帧挂回镜头等结构事件不能丢）。
4. **开关**
   - `reuseCache` 默认开，存 `localStorage`（跨页面、跨刷新），**不进事件日志**：
     它是「这台机器这次要不要省钱」，不是项目事实。
   - 设置页「结果缓存」区可一键开关；关掉时按钮文案写「关着：每次都真去生成」。
5. **命中时说清楚**
   - `generationNotice` 写「复用了同一套输入已经出过的那张图（模型 X）：
     没有重新生成，也没花钱。想换一张就关掉「结果复用」再生成。」

## 理由

- **键必须与「实际发出的东西」一致**：缓存最危险的失败不是没命中，而是**错命中**——
  作者改了提示词却拿到旧图，会以为模型没听懂。所以键里放的是最终提示词，不是原始输入。
- **不另存快照**：日志是唯一事实来源（P2）；资产本身就在项目里，键现算即可。
- **默认开**：省钱是默认行为；需要抽卡的人自己关。
- **保留花费**：抹掉会让「这一格花了多少钱」的账面变小，而钱确实花过。

## 后果

**正面**

- 重复生成不再花钱；批量补缺、刷新重来都受益。
- 不新增 IR / 事件 / 日志版本 / IndexedDB 仓。
- 命中与未命中都能从回执看出区别。

**负面 / 代价**

- 只覆盖**出图**：视频、配音、文本不在这一档（各自的成本与去重口径不同）。
- 键只认模型 + 提示词 + 参考图内容：改风格参数若不影响最终提示词就不会触发重生成
  （本来也不该），但作者可能以为「我改了风格」。
- 关掉开关是全局的：想只对某一镜抽卡，得先关、再开。
- 资产 `source` 变成 `library` 后，资产页会显示为「素材库」来源；
  作者看到的是「复用」而不是「生成」，需要靠回执与溯源理解。
- 缓存按项目内查找：跨项目复用仍走 C16 / C22 那几条显式路径。

## 替代方案

- **服务端缓存**（按请求体哈希存一张表）：要新增持久层与失效策略，
  而答案其实已经躺在项目资产里。
- **按输入 JSON 哈希**：输入里含 `skills`、`look` 等结构化字段，
  序列化顺序一改键就变；用最终提示词更稳。
