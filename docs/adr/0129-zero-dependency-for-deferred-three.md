# ADR-0129：三条被推迟的依赖，全部不引：用平台 API 与已有 ffmpeg

- 日期：2026-11-12
- 状态：已采纳
- 关联：E7.2、B13.3、H3、ADR-0126、ADR-0127、ADR-0128、R48、R19

## 背景

零依赖的 P0 条目已经全部落地。剩下三条功能各自卡在一个依赖决定上，ADR-0126 / 0127 / 0128 都写着「单独确认」：

| 功能 | 原计划的依赖 | 卡在哪 |
| --- | --- | --- |
| E7.2 帧级预览 | mp4box.js（约 100 KB）+ WebCodecs | 浏览器没有原生 MP4 解封装 API |
| B13.3 depth / edge 导出 | WebGL / Three.js（约 600 KB） | 平面 SVG 画不出 depth |
| H3 S3 适配器 | `@aws-sdk/client-s3`（约 1 MB）或 `aws4`（3 KB） | 需要 SigV4 预签名 |

CLAUDE.md：「未经确认，不引入重型依赖或自建基础设施」。现在是确认的时候。

## 决策

### 1. E7.2：不引 mp4box.js，改用服务端 ffmpeg 切帧 + 浏览器 Canvas

原设计的链路是「浏览器解封装 → WebCodecs 解码 → 画布」，mp4box.js 是解封装那一环。但项目已经有一条更强的路：**本机装了 ffmpeg，渲染路由已经在用它**（ADR-0091）。

改成的链路：

```
GET /api/preview/frame?asset=<uri>&at=<ms>  →  ffmpeg -ss <at> -i <src> -frames:v 1 → JPEG
```

- 浏览器只拿一张 JPEG，`<img>` 就能显示，**不需要 WebCodecs**。
- 帧级精度由 ffmpeg 的 `-ss` 保证（精确 seek，不是关键帧近似）。
- 单帧 60–120 KB，本地服务，一次往返约 20–60 ms；连续拖动时由前端做 60ms 节流 + 请求去重。
- 没有新依赖：ffmpeg 是运行环境的前提（渲染已经要求它），`spawn` 是 Node 自带。

**代价**：这是「服务端出图」，不是「浏览器本地解码」。断网、或者把页面部署到没有 ffmpeg 的机器上，帧级预览就不可用。所以保留能力探测：拿不到就用 E7.1 的近似（ADR-0127 §6 的降级口径不变）。

### 2. B13.3：不引 WebGL / Three.js，用 ffmpeg 的 `zscale` / `depth` 思路换成 2D 深度图

原设计要 WebGL 是因为「必须真实渲染几何体」。但 depth 导出的产品目的不是「好看的结构图」，而是**给关键帧当结构参考**：作者要看的是「人在画面的哪个位置、离机头多远、前后景怎么叠」。

用 Canvas 2D 就能画出来，而且更可控：

- 俯视 / 立面已有的坐标 → 透视投影（一个 4×4 矩阵，纯数学）；
- 人物画成按深度着色的简笔柱子（近亮远暗），家具画成按深度着色的矩形；
- 输出一张**深度色图**（近处暖、远处冷）叠一张线框，喂给图像模型当参考图。

这不是「渲染」，是「结构示意」。ADR-0126 已经定过口径：灰盒与成片差距要让人理解，不假装它是 previs 渲染。同理，这张图在界面上叫「结构参考图」，不叫「depth 渲染」。

**不引入 GPU 的另一个理由**：E7.3（合成加速）也推迟了。两条都吃 GPU，一起等 E1 支持转场时再评估渲染层——现在引入，是为一个还不存在的需求固化渲染抽象层。

### 3. H3 S3：自写 SigV4，不引 SDK 也不引 `aws4`

ADR-0128 §3 给的两个选项是「自写 80–120 行」与「引 `aws4`（3 KB）」。选**自写**：

- `aws4` 已经多年不更新，而 SigV4 的规范化规则是冻结的（AWS 公开文档 + 官方测试向量），不存在「跟着上游升级」的维护成本；
- 自写可以用 AWS 官方的测试向量做单测，正确性是可验证的，不是「相信库」；
- 3 KB 的库也要进依赖树、要审 license、要跟着 Node 版本走——对一段一年改不了一次的纯函数，不划算。

实现范围限定在**预签名 PUT / GET**，不做 SDK 的对象模型、分片上传、重试。这一点 ADR-0128 已经定过。

### 4. 三条的共同口径

- **能力探测照旧**：拿不到就降级，界面写清当前在哪一级（ADR-0127 §6）。
- **都不是导出路径**：预览帧、结构图、S3 都只是「看一眼」与「存一份」，成片仍以 ffmpeg 导出为准（ADR-0127 §5 / P20）。
- **依赖清单不变**：`package.json` 一个包都不加。这是本次确认最重要的结果。

## 理由

- **能用已有的就不引新的**：ffmpeg 已经在跑、Canvas 已经在画、`node:crypto` 已经在用。三条功能都能靠这三样完成，引依赖只是换一种写法。
- **正确性可验证**：SigV4 有官方测试向量；ffmpeg seek 有确定行为；Canvas 投影是纯数学。都能写单测，而「相信一个库」不能。
- **推迟 GPU 是克制的**：只有硬切的时间线用不上 GPU 合成，depth 也用不上真 3D。等 E1 支持转场时，两条需求一起评估。

## 后果

**正面**

- 三条功能都能开工，且 `package.json` 不动。
- E7.2 的精度比原设计更好：ffmpeg 精确 seek，不受 GOP 限制。
- 结构参考图走 Canvas，可以在浏览器里实时跟着拖动重画，不需要服务端往返。

**负面**

- **E7.2 依赖服务端**：没有 ffmpeg 的环境降级到 E7.1；这是新的运行环境要求（渲染本来就有，不算新增）。
- **B13.3 不是真 depth**：没有逐像素深度，只有按深度着色的示意。喂给图像模型时是「构图参考」，不是「几何约束」。
- **SigV4 要自己写对**：规范化请求的坑不少（URI 编码、头排序、空 payload 的哈希）。用官方测试向量锁住，但边界情况（中文 key、特殊字符）要单独测。

**跟进**

- E7.2 落地后补一次真实设备的拖动性能标定（R19）。
- B13.3 的图要在真实关键帧生成里验证「有没有用」——不是「好不好看」。
- S3 用 MinIO 做一次端到端（ADR-0128 已列）。

## 落地（E7.2 帧级找点，2026-11-12）

### 1. 路由：`GET /api/preview/frame`

`apps/web/app/api/preview/frame/route.ts`，Node 运行时，只读：

- `?probe=1` → `{ tier: "frame", ffmpeg: "9.0.2" }` 或 `{ tier: "approx", reason }`。探测 `ffmpeg -version`，进程内只探一次。
- `?asset=<loomina://…>&at=<ms>&w=<px>` → 一张 JPEG。

切帧参数（`frameArgsOf`，在 `lib/preview-frame.ts` 里，纯函数、有单测）：

```
ffmpeg -v error -ss <at/1000, 3 位小数> -i <src> -frames:v 1 -an -sn -dn \
       -vf scale=<w>:-2 -f image2 -vcodec mjpeg -q:v 4 pipe:1
```

- `-ss` 放在 `-i` **之前**：现代 ffmpeg 会先按索引跳到附近再解码丢弃，结果仍是精确到帧的，比放在后面快得多。
- 高度 `-2` 让 mjpeg 拿到偶数高度（mjpeg 不收奇数）。
- 输出走管道，不落临时文件：一帧 60–120 KB，直接进内存。
- 单帧上限 8 MB、时限 15 秒；超了杀进程并如实报错。

### 2. 只认本机资产库

`parseFrameRequest` 只接受 `loomina://assets/<sha256>.<ext>`：

- `data:` 的片子有几十 MB，塞不进查询串，而且它本来就该先迁进资产库（ADR-0128）；
- 远端地址要另开一条受控下载的路（渲染路由已有 `RENDER_ALLOWED_HOSTS`），不在这一层重复。

### 3. 浏览器侧：节流 + 去重

`lib/preview-frame.ts` 全是纯函数（22 条单测）：

- `frameUrlOf` / `frameKeyOf` / `frameMs` / `stepFrame`；
- `createFrameThrottle()`：立刻发第一次，之后 60ms 内的请求合并成一次（尾随）；同一处不重复发；`forget()` 让失败的地址能重试；`cancel()` 在换镜时丢掉待发的。
- `probeFrameCapability()`：问一次 `?probe=1`，结果缓存 5 分钟。

### 4. 界面：预演里的一个开关

预演覆盖层右侧加「帧级找点」：

- 勾上 → 暂停播放，画面上换成切出来的那一帧，头部签从「到镜准确 · 镜内近似」变成「帧级找点 · ffmpeg 9.0.2」。
- 「‹ 一帧 / 一帧 ›」按 33ms 步进（源片帧率不进 IR，按渲染用的 30fps 估）；键盘 `,` / `.` 同样。
- 拖动底部时间轴 → 镜内位置变 → 60ms 节流后重新切帧。
- **按播放就退出帧级找点**：切帧最快 60ms 一次，冒充不了播放。这一步写成一个 `togglePlay` 动作，不写成「playing 变真就关掉」的 effect——打开帧级找点那一瞬 playing 还是真，两个 effect 会互相抵消，勾上立刻弹回未勾（第一次实测就是这个现象）。
- 换到没有片子 / 片子不在资产库的镜头，开关自己关掉，不留一个勾着却用不了的控件。

### 5. 顺手修的

`attachVideo` 原来只收 `http(s)://` 与 `data:video/`，本机资产库的片子贴不进来——而帧级找点只认资产库地址，两条路合不上。现在也收 `loomina://assets/`；导入框的 placeholder 同步改成三种地址。

### 6. 验证

- 单测 **979**（IR 184 + gateway 28 + pipeline 82 + web 685），本轮新增 `preview-frame.test.ts` 22 条、`workbench-store.test.ts` 1 条。`pnpm typecheck`、`next build` 全过。
- 接口：`?probe=1` 回 `{"tier":"frame","ffmpeg":"9.0.2"}`；同一段 4 秒素材 `at=0` 与 `at=2000` 切出两张不同的 360×640 JPEG（17.6 KB / 16.9 KB，0.04–0.12 s）；`at=9000`（超过片长）回 422「这个时刻没有画面：多半已经超过片子的时长」；`data:` 地址回 400；不存在的哈希回 404。
- 浏览器（生产 3100，CDP）：关键帧页把本机 `.loomina/assets/` 里那段 mp4 贴成 SH-02 的一拍 take → 预演跳到 SH-02 → 勾「帧级找点」→ 画面换成切出来的帧、头部签变「帧级找点 · ffmpeg 9.0.2」→ 点「一帧 ›」地址从 `at=0` 变 `at=33` → 拖时间轴到 4600ms → 切帧地址变成 `at=1500`（SH-02 起点 3100ms 之后的第 1500ms）→ 点播放，开关自动取消、签变回「到镜准确 · 镜内近似」→ 跳到 SH-03（没片子），开关置灰并写「这一镜没有片子」。
- **没验到的**：真实生成片子的拖动跟手感（示例素材是一段 4 秒的测试图，只有 SH-02 有）；同一毫秒两次请求的响应一致性（HTTP 缓存会兜住，但没专门测）。

### 7. 边界

- 依赖服务端 ffmpeg。没有 ffmpeg 的环境降到 E7.1，界面写明原因，不假装。
- 逐帧步进是 33ms 的估步：源片 24fps 时一步会落在两帧之间，ffmpeg 取该时刻所在的那一帧。
- 一帧一次 HTTP 往返。本地 20–60 ms，远端部署会明显变慢——这条在 ADR-0129 决策时已知，真到部署阶段要评估是否加代理视频（E7.2 原设计的 540p 代理仍然值得做）。

## 落地（H3 对象存储 SigV4，2026-11-12）

### 1. 签名自己写，对着官方向量锁

`apps/web/lib/s3-sigv4.ts`，只做预签名：

| 函数 | 职责 | 易错点 |
| --- | --- | --- |
| `uriEncode` | AWS 的 URI 编码 | 只保留 `A-Z a-z 0-9 - _ . ~`；空格是 `%20` 不是 `+`；`*` `!` 也要转义 |
| `canonicalQueryString` | 规范化查询串 | **先编码再排序**，同名按值排 |
| `canonicalRequest` | 规范化请求 | 头名小写排序、头值压空白、路径**只编码一次** |
| `signingKey` | 四层派生密钥 | 漏一层不报错，只是签名对不上 |
| `presignUrl` | 拼整条 URL | 载荷用 `UNSIGNED-PAYLOAD`，不是空串的 sha256 |

单测 28 条，其中三条是 AWS 官方文档里的完整示例，逐字比对：

- **GET Object**：规范化请求的 sha256 `7344ae5b…`、签名 `f0e8bdb8…`；
- **PUT Object**：载荷 sha256 `44ce7dd6…`、签名 `98ad7217…`；
- **预签名 GET**：整条 URL（含 `X-Amz-Signature=aeeed9bb…`）与文档一致。

这三条的意义不是「我们和文档一样」，而是「任何第三方实现（botocore、SDK）算出来的也是这个值」——测试里用的是文档公开的示例凭据，不是任何真实账号的密钥。

### 2. 存储实现只做四件事

`apps/web/lib/s3-store.ts`：`putS3Object` / `readS3Object` / `removeS3Object` / `listS3Objects`，全部走预签名 URL 再 `fetch`。没有 SDK 的对象模型、没有重试、没有分片上传——200 MB 上限内的单次 PUT 够用。

- key 形状 `<prefix>/<前两位>/<sha256>.<ext>`：内容寻址，同一段字节只存一份；`HEAD` 判存在，命中就不重传。
- 列桶用 ListObjectsV2，按 `continuation-token` 分页，最多 100 页。
- 上传前的 `HEAD` 也用预签名 URL，**方法必须写 HEAD**（第一版写成 GET，服务端收到 HEAD 但签名里是 GET，直接 403）。

### 3. 地址与读取路径

| 场景 | 怎么做 |
| --- | --- |
| IR 里存什么 | `s3://<bucket>/<key>`，与其他两种地址并列，引用方不改 |
| 浏览器显示 | `assetHref()` → `/api/storage?uri=…`，服务端签一条短期 GET 再流回字节 |
| 渲染 / 切帧 | `materializeAsset()` 先拉到 `.loomina/assets/cache/`，同一个 key 只下载一次 |
| 导出（自包含） | `hydrateView()` 走 `/api/storage?uri=` 读回字节换成 data URI |

**不把预签名 URL 直接给 `<img src>`**：URL 十分钟就过期，而地址要能长期引用；服务端代读多一次本机往返，换来的是一条稳定的地址。

### 4. 凭据边界

- 只从 `.loomina/config.json` 的 `storage` 段（0600）或服务端 `LOOMINA_S3_*` 环境变量读。
- `/api/config` 回 `endpoint` / `endpointHost` / `bucket` / `region` / `pathStyle` / `source` / `active`，**没有 AK/SK**。
- endpoint 在校验时就不许带账号密码与查询串，所以它本身不是凭据，可以完整回传给表单预填。
- 设置页的 Secret 输入框是 `type=password`，已配置时占位符写「已保存」，保存后拿不回来。

### 5. 端到端跑出一个单测看不见的 bug

`objectUrlOf` 把 key 编码成 `%E9%A1%B9…`，`canonicalRequest` 又编码一次变成 `%25E9…`。单测里两边都调同一个函数，所以「算得对」——但 MinIO 按单次编码重算，签名对不上，**中文 key 的 PUT 直接 403**。

修法：`objectUrlOf` 同时返回 `path`（原始，进规范化请求）与 `encodedPath`（编码后，进 URL），调用方不许混用。补了两条回归：URL 里不许出现 `%25`，规范化请求第一行必须是单次编码。

这条记在这里的理由是它说明**单测与端到端测的不是同一件事**：单测锁「实现自洽」，端到端锁「服务端认不认」。

### 6. 验证

- 单测 **1050** 全过（IR 184 + gateway 28 + pipeline 98 + web 740，另 4 条 e2e 默认跳过）。
- MinIO 端到端（`LOOMINA_S3_E2E=1` 开启）：写 / 读 / 列 / 删、同一段字节写两次地址不变、中文与特殊字符 key、不存在的对象读回 null、过期签名被服务端拒绝。
- 接口：`PUT /api/storage` 存配置并脱敏回传；`?probe=1` 列桶报 2 个对象 33 KB；`/api/config` 序列化里搜不到 AK/SK。
- 浏览器：设置页「对象存储」区显示 `127.0.0.1:9000 / loomina-assets · us-east-1`，探测写「连通 · 2 个对象 · 33 KB · 1 ms」；表单预填 Endpoint / 桶 / 区域，AK 与 SK 为空且 SK 是密码框。
- 渲染：带 `s3://` 图片素材的清单提交后 `done`，ffprobe 1080×1920 h264 1.000s，抽帧就是桶里那张图。
- 帧级找点：SH-02 的 take 换成 `s3://` 片子后开关可用，勾上切出 360×640 彩条，逐帧步进 0 → 33 → 66。
- **没验到的**：真实云厂商（AWS / OSS / COS）的桶——本地只有 MinIO；`virtual-hosted` 寻址在 MinIO 上不成立，只做了单测；>5 GB 的分片上传（不做）。

### 7. 边界

- **对象存储不是项目同步**：项目仍在浏览器 IndexedDB 里，桶里只有素材。换机器能拿回素材，拿不回项目。
- 桶里的孤儿对象没有清理界面：本机库的「清理没人引用的文件」只动 `.loomina/assets/`，不冒充桶的回收站（`removeS3Object` 已实现，只差界面）。
- 缓存目录 `.loomina/assets/cache/` 不自动清：按内容哈希命名，同一个对象只下载一次，删 `.loomina/` 时一起删。
