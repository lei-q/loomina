# ADR-0150：项目固定模型

- 状态：已采纳
- 日期：2026-11-12
- 相关：H22、H16、ADR-0094、ADR-0148

## 背景

模型选择此前只存在浏览器的 `localStorage`（`loomina.model.<modality>`）：换浏览器、换设备、清缓存，同一个项目就会换一个模型。对长篇项目这不是小事——故事的文风、定妆的画风、成片的运动质感都会变，而事件日志里只留下每次调用各自的 `provenance.modelId`，读者看不出「这个项目本来打算一直用哪个模型」。

H22 的原始条目里写着「按项目固定模型」。同时 S1 测绘与能力矩阵已经按模型给出了通过率与实测价，作者有理由把一个项目钉在某个模型上，而不是每次打开页面都重新确认。

## 决定

1. **固定值进 IR**：`Project.models` 是 `{ text?, image?, video?, tts?, asr? }`，值是本机配置里的模型 id。形状与 `Modality` 一一对应，缺省 `{}`。
2. **走 `project.updated`**：事件新增可选 `models?: Partial<Record<Modality, string | null>>`。传某个模态的非空字符串表示固定；传 `null` 表示取消；不传的模态保持原样。`applyEvent` 拒绝空串、纯空白与不认识的模态。
3. **取值优先级**：项目固定 > 本机 `localStorage` > 服务端默认。生成、报价、加价（`/api/price`）与故事入口全部走同一个 `modelIdFor(modality, project.models)`。
4. **界面**：模型下拉旁多一个「钉住 / 已钉住」开关。下拉改的是当前生效的层：钉住时改下拉就是改项目（写事件），没钉住时只改本机；钉住状态下选回「默认」等于取消钉住。
5. **只读标签页不能钉**：与其它写操作一致，`readOnly` 时按钮禁用。

## 理由

- **模型是项目约束，不是设备偏好**：预算和重试上限都已经进 IR，同一个道理。换设备打开同一个项目应该得到同一套创作条件。
- **不校验 id 是否存在**：IR 不知道本机配置。固定的模型被删掉后，网关会给出明确的「模型不存在」，作者可以在下拉里换掉；IR 仍保留原值，重放日志不丢历史。
- **覆盖 localStorage 而不是替代它**：没固定时仍然保留「这台机器上先试试另一个模型」的自由，固定是显式升级，不是强制迁移。

## 代价

- `Project` 多一个字段，所有手写项目字面量要补 `models: {}`（示例项目走 `ProjectSchema.parse`，自动带默认值）。
- 固定到当前配置里不存在的 id 时，生成会在网关处失败；界面目前只在文档里说明，没有提前高亮。
- 报价缓存按模型 id 作键，固定变化后需要重新拉价；三个使用价目的页面已把 `project.models` 放进 effect 依赖，改钉立刻重拉。

## 不做什么

- 不做云端同步或多用户隔离：固定值跟着事件日志走，日志目前只在本机 IndexedDB。
- 不做「按阶段分别固定供应商」：固定的是模型 id，供应商由配置决定。
- 不把固定值回写到 `.loomina/config.json` 的默认模型：项目选择和本机默认是两件事。
