# ADR-0241：抖音时长上限 15 分钟没有出处，如实标未核验

- 状态：已采纳
- 日期：2026-11-15
- 决策者：用户 + Claude
- 关联：G2、G7、ADR-0099、ADR-0240

## 背景

ADR-0240 核抖音文件上限时，官方 SDK 文档写了一句：
**「单视频及视频总时长最大值为 60 分钟。」**

但规格表里抖音的 `durationMs.max` 是 `900_000`（15 分钟），而且它是**硬拦**——
超过 15 分钟的成片会被挡住导出。

查 15 分钟这个数的来历：

- ADR-0099 只写了「抖音 15s–15min」，没给出处；
- 抖音帮助中心（`douyin.com/help`）只有播放类问题，没有发布时长；
- 开放平台文档目录里没有「上传视频」接口页；
- 官方 SDK 文档写的是 60 分钟。

结论：**15 分钟这个硬拦值没有官方出处**。

## 决定

1. **给 `durationMs` 加 `durationSource` / `durationNote`**，与文件上限同一套口径：
   有出处就填出处，没有就如实说明。
2. **保留 15 分钟的硬拦**，但把真相写进 `durationNote`：
   「下限 15 秒有依据；上限 15 分钟未核验——官方 SDK 文档写的是『单视频及视频总时长
   最大值为 60 分钟』，按 60 分钟发长片可能可行，本工具不为此背书」。
3. **`durationSource` 不填**——这正是「知道它没依据」的表达，不是遗漏。
4. **面板显示「时长口径：…」**，与「文件上限的口径」并列。
5. **测试守住两件事**：抖音的 note 必须包含「未核验」与「60 分钟」；
   只有抖音有 `durationNote`（其余平台没有歧义，不啰嗦）。

## 为什么不直接把上限改成 60 分钟

- **60 分钟是分享 SDK 的口径**，不是「发布到抖音」的口径。分享 SDK 是
  「第三方 App 把视频交给抖音 App」，与创作者中心的发布流程不是同一条路径。
- **短剧不会超过 15 分钟**：P1 的产品定义是 60–180 秒的竖屏短剧。
  放宽到 60 分钟对这个产品没有实际收益，却会让「超过 15 分钟」从硬拦变成放行，
  而放行的依据只覆盖了一条不同的路径。
- **保留硬拦 + 写出真相**是最诚实的做法：作者看到「15 分钟未核验、官方写 60 分钟」，
  自己判断要不要试；工具不假装知道。

## 理由

- **硬拦一个没有出处的数，代价是作者白删内容**：如果他有一条 20 分钟的片子，
  工具说「超过上限」、他删到 15 分钟，而平台其实收——这是工具造成的损失。
  至少要让他知道这个数的地位。
- **与 ADR-0240 同一口径**：「核过、没有」与「没核」要分开说。
  这里是第三种情况：**有一个值、但没有出处**，所以标「未核验」而不是「官方未设」。
- **不编数字，也不删功能**：直接去掉上限会让「发错了才发现」；保留 + 说明是折中。

## 后果

**正面**

- 抖音时长上限第一次有了明确的地位说明，作者不会被一个无出处的数误导。
- 面板上「时长口径」与「文件上限的口径」并列，两种核验状态一眼可辨。
- 测试保证 note 里必须写出官方的 60 分钟，不会退化成含糊的一句话。

**负面 / 代价**

- **没有解决「到底能发多长」**：60 分钟那条是分享 SDK 的口径，
  创作者中心的实际上限仍未核到（需要登录或换网络）。
- 15 分钟的硬拦仍在，只是加了说明——作者要发 20 分钟的片子还是会被挡住。
- 如果将来核到创作者中心也是 60 分钟，这个 note 要再改一次。
- 只处理了抖音；快手等平台的时长同样没有逐条核过，但它们的下限更宽松、歧义更小。
