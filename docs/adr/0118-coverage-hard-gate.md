# ADR-0118：覆盖率硬闸门与带条件确认

- 日期：2026-11-11
- 状态：已采纳
- 关联：A12、A13、P13、P14、P15、ADR-0096、ADR-0100、ADR-0108

## 背景

覆盖率（A12）从 ADR-0096 起就是一个**检查**：分镜检查抽屉里算出「几拍齐、几拍缺」，缺的拍上写「缺信息 / 缺情绪」。它一直明确写着「不是硬闸门」。

问题在于这条检查**没有人必须看**。分镜确认（F9）只看两件事：有没有镜头、镜头有没有动作描述。作者可以一路确认到关键帧、出图、出视频、渲染，全程没有人提醒「这条片子十拍里十拍都只有一种镜头」。等成片出来发现节奏单薄，返工成本已经是整条链路。

P15 把覆盖率列为**硬约束**，P14 说闸门要设在昂贵步骤之前。所以这里要把它从「提示」升级为「闸门」，但不能升级成「墙」。

## 决策

### 1. 分成两类缺口：硬缺口与可豁免缺口

`StageState` 原来只有一个 `missing`，语义是「还没做」。现在加一个 `waivable`，语义是「做了但不达标准」：

| 字段 | 含义 | 能不能绕过 |
| --- | --- | --- |
| `missing` | 还没有镜头 / 还没有动作描述 | 不能，按钮直接灰 |
| `waivable` | 覆盖率不满（A12） | 能，勾一下「我知道」 |

分界线是**事实与判断**：没写动作描述是「这件事还没做」，没有第二种解释；覆盖率不满是「这样做行不行」——有些片子就是故意一整拍只用一种镜头（一段沉默的反应长镜、一个纯信息蒙太奇）。工具不该替作者断定它错。

### 2. 覆盖率只在硬缺口清空后才查

还有镜头没写动作描述时，覆盖率必然也不满，两条一起报只是同一件事说两遍。所以 `readinessOf("storyboard")` 里先看 `missing`，为空才算覆盖率。这样确认弹层永远只说一件真正需要决定的事。

### 3. 带条件确认写进事件，不写进备注

`gate.confirmed` 多一个可选 `override`，`GateRecord` 多一个 `override: boolean`（默认 false）。确认弹层在 `waivable` 非空时多一块「可以带条件确认」：列出缺口，一个复选框，按钮文案变「确认分镜，进入关键帧（带条件）」，没勾时按钮是灰的。

**为什么不塞进 `note`**：备注是给人看的一句话，`override` 是给机器读的标记。之后要做「哪些片子是带条件过的、后来补上了没有」这类查询时，从自由文本里抠不出来。历史抽屉里显示成「确认「分镜」阶段（带条件）」，一眼能看出这次确认的性质。

### 4. 闸门仍然是提醒，不是墙

- 导航不受限：不勾也能直接点去关键帧，那里会显示「未确认」。
- 回退随时可用，回退后再确认可以不带条件。
- 自由工作台完全不摆闸门，这条约束在那里不存在（F8 的既有语义）。

## 后果

- 覆盖率从「一个可看的数字」变成「确认时绕不过去的一句话」。
- 故意的单镜头拍不会被挡住：勾一下就能过，且记录里留下痕迹。
- 硬缺口与软缺口的区分让弹层只说一件事：要么「还没写」，要么「写完了但要不要这样」。
- 旧的 `gate.confirmed` 日志没有 `override`，读出来是 false，不需要迁移。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 覆盖率不满直接挡住确认 | 故意的单镜头拍会被误伤；工具不该替作者断定「这样拍不对」 |
| 只提示，不加闸门（现状） | 检查没人必须看，返工成本在整条链路末端才暴露 |
| 把 override 塞进备注文本 | 备注是给人读的一句话，机器查询时抠不出来 |
| 覆盖率与硬缺口一起报 | 没写描述时覆盖率必然不满，同一件事说两遍，弹层变成噪音 |
