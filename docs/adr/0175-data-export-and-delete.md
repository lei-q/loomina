# ADR-0175：数据导出与删除（H9）

- 状态：已采纳
- 日期：2026-11-13
- 决策者：用户 + Claude
- 关联：H9、H3、H18、H22、F4、R7、ADR-0034、ADR-0128、准则 P14 / P20

## 背景

H9 一直只有一行「用户数据可携带」。项目其实是**这台浏览器里的一条事件日志**
（H18 / ADR-0034），素材在 `.loomina/assets/`（H3 / ADR-0128）或用户自己的对象存储里，
密钥在 `.loomina/config.json`。这三样东西分开存在三个地方，没有任何一处能回答
「我的东西到底有哪些、怎么拿走、怎么删干净」。

风险表 R7（个人信息与数据安全）把它列为缓解手段，但它本身没落地。
这一版要做的不是「一键上云」，而是把边界说清楚，并且真的能做两件事：
**装走一份完整的记录**、**删掉这台机器上的东西**。

## 决定

1. **导出 = 一个 JSON，不内嵌素材字节**
   - `{ format: "loomina.export", version: 1, app, exportedAt, logVersion, project, events, assets, totals, notes }`。
   - `project` 是回放到底的当前状态，`events` 是每一步——两个都给，因为「当前长什么样」
     和「怎么变成这样的」是两种问题。
   - `assets[]` 每条只记 `id` / `kind` / `placement`（inline / store / remote / none）/
     `uri` / `href` / `referenced` / `inlineBytes`，**没有 `bytes`**。
   - 理由：一段 30 MB 的视频编成 base64 会让这份文件大到打不开；素材本来就在你自己的盘或桶里，
     给地址比给副本有用。
   - `totals.storeFiles` / `storeBytes` 取 `/api/assets` 的清单；取不到就是 `null`，
     不编一个 0——「没取到」和「是空的」是两件事。
   - `notes` 把边界写进文件本身，而不是只写在界面上：拿到这份文件的人（可能是几个月后的作者）
     要能知道素材没在里面、以及这一版不能导入。

2. **删除 = 只删这台机器上的两样东西**
   - 服务端 `DELETE /api/data` 清 `.loomina/assets/` 里的文件（内容寻址的扁平目录，逐个 `remove`）；
     浏览器随后把项目日志重置成示例项目。
   - **不碰**：对象存储里的对象、`.loomina/config.json`（密钥与供应商配置）、用户导出到别处的文件。
   - 必须显式确认：请求体里 `confirm` 要等于「删除」两个字，否则 400。
     这个按钮不可撤销，误点一次的代价是把花钱生成的东西删掉。
   - **配了对象存储时直接拒绝（409），界面上按钮也禁用**。桶可能是多台机器、甚至别人一起用的，
     一个「删除本机数据」的按钮不该有清空桶的能力。

3. **导出与删除都在设置页的「数据」区**
   - 导出按钮 + 一句「项目 IR + 整条事件日志 + 资产清单；素材字节不内嵌」。
   - 删除区先写清会删什么、不删什么，再是确认输入框与按钮；
     输入不对时按钮禁用，`title` 说明为什么。
   - 导出的文件名 `夜班-数据包-2026-11-13.json`：片名 + 日期，去掉文件名不能用的字符。

4. **不做导入**
   - 这一版没有 `import`。文件里明写「这一版没有导入：这份文件是备份、迁移与清点用的完整记录」。
   - 导入要处理 schema 版本、素材地址重写、事件日志校验、冲突合并——那是另一个功能，
     半做的导入比没有更危险。

## 理由

- **给地址不给副本**：素材的字节已经在用户自己的存储里；再复制一份进 JSON 只是让文件变重，
  并且会让「导出了一份」听起来像「备份好了」，实际上素材那份没动。
- **两个数分开**：`storeFiles: null` 与 `storeFiles: 0` 必须能分辨。前者是「这次没问到」，
  后者是「库是空的」；混成一个数会让用户以为素材丢了。
- **删除只清本机**：这是唯一能保证正确的作用域。对象存储的对象删除需要逐条确认引用，
  而且要处理别的项目 / 别的机器；本机文件是内容寻址的，删了不会破坏任何引用
  （引用还在 IR 里，但字节没了，界面会照实显示文件缺失）。
- **显式确认词**：和「重置为示例项目」的两次点击不同，删除连日志一起清，
  撤销找不回来；要一个需要动手输入的动作，而不是顺手一点。
- **有对象存储就拒绝**：拒绝比「猜用户想删哪个」安全；界面把原因写在按钮旁边。

## 后果

**正面**

- 「我的数据有哪些」第一次有一个能装走的答案：项目、每一步、每个资产放在哪、有没有人用。
- 删除的作用域写死在代码里（本机资产库 + 浏览器日志），不会误伤桶与密钥。
- R7 的「可导出删除」从一句话变成可操作的按钮；数据包本身就是给合规看的一份记录。

**负面 / 代价**

- **没有导入**：导出的是备份记录，不是可恢复的备份。素材字节也不在里面，
  真要恢复得自己按 `href` 把文件捞回来。
- 删除后项目日志变成示例项目：原来那份**不可恢复**（日志不在服务端，也没有回收站）。
- 配了对象存储的人拿不到「一键删除」：得去对象存储那边删，这一版不给工具。
- `href` 对 `s3://` 地址是 `/api/storage?uri=…`，需要本机服务在跑且预签名有效；
  过几个月再打开这份 JSON，那些链接多半已经失效——`uri` 本身才是长期有效的记录。
- 只导出当前项目：多项目 / 多日志段（`projectSegments`）里别的段没有单独装走。

**不做**

- 导入 / 合并、增量导出、加密压缩包、直接传到云盘。
- 删除单个资产、按日期删除、回收站。
- 对象存储侧的批量删除工具。
- 账号体系下的「删号」——现在没有账号。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 素材字节也 base64 进 JSON | 几十兆的视频会让文件打不开；用户自己的存储里本来就有 |
| 只导 `project`，不导 `events` | 丢掉了「怎么变成这样的」；回放、撤销、审计都要事件 |
| 导出成 zip | 浏览器里要引打包依赖，而且素材不在里面，zip 只是把 JSON 包了一层 |
| 删除只清浏览器日志 | 素材会变成孤儿文件，越积越多；用户以为删干净了 |
| 删除连对象存储一起清 | 桶是多机 / 多人共享的，删错一次无法恢复 |
| 删除不需要确认词，点两次就行 | 和「重置示例项目」太像，误点代价不可逆 |
| 这一版顺手做导入 | schema 版本、素材地址重写、冲突合并都要设计；半做的导入更危险 |
