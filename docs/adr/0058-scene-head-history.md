# ADR-0058 场头历史：改了哪几次、上一版长什么样

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0050（场头）、ADR-0051（动作历史）、ADR-0056（场次地点）、FEATURES A21

## 背景

ADR-0050 与 ADR-0056 的负面都写着同一条：「没有场头历史，改过几次、上一版是什么，页面上看不到」。动作（ADR-0051）、台词（ADR-0044 / 0052）、台词顺序（ADR-0053）都已经有折叠的版本列表，唯独场头是改完就忘。

场头三项（内外景 / 日夜 / 地点）挤在同一条 `scene.updated` 里，所以历史不能像动作那样「一次改写一条文本」，而要回答「那一版长什么样」。

## 决策

1. **读模型 `sceneHeadHistory(events, sceneId)`**：从 `project.created` 快照取最初一版；按顺序把每条 `scene.updated` 的 patch 叠到当前场头上，每条事件存一份改完之后**完整的**场头 `{ space, timeOfDay, locationId }`。返回 `{ original?, edits }`，`edits` 从旧到新。
2. **`previousSceneHead(history)`**：改过一次就是最初那版，改过多次是倒数第二版——与 `previousActionText` / `previousDialogueText` 同一套。
3. **不新增事件、不加字段**：历史完全从已有日志推导；`scene.updated` 的 patch 本来就只写有变化的项（ADR-0056），叠起来就是每一版。
4. **界面**：场头一行下面多一个折叠 `改过 n 次 · 上一版 内 · 夜 · 走廊`；展开是按时间倒序的版本列表（`21:09 内 · 夜 · 桌边`），每行一个`用这版`，与当前场头相同的那一版置灰。`最初`单独一行。恢复写一条 `scene.updated`（只带有变化的字段），不抹掉历史。
5. **地点名从 `project.locations` 取**；旧日志里指向已不存在的地点时写「（地点已不在库里）」，不假装它还在。

## 理由

- **存「整版」而不是「改项」**：用户在历史里问的是「上一版是什么」，不是「上次动了哪个下拉」。三项拆开写三行会读成三个版本。
- **叠 patch 就是回放**：`event-log` 已经保证 `scene.updated` 只写变化项；读模型叠一遍与 `applyEvent` 的口径一致，不会出现「历史里有这一版、当前项目里却没有」。
- **恢复也是一次编辑**：与动作、台词回退同一套——追加事件，不修改历史；`用这版` 之后折叠里多一条，而不是少一条。
- **跟别的历史同一套样式**：都在标题下一个 9px 小字折叠，用户已经在动作、台词上学过一次。

## 后果

**正面**
- 第 1 场改过「夜 → 日」「走廊 → 桌边」两轮后，场头下面写 `改过 2 次 · 上一版 内 · 夜 · 走廊`；展开看到 `21:09 内 · 夜 · 桌边`、`20:44 内 · 夜 · 走廊`、`最初 内 · 日 · 走廊`。
- 点`最初`那行的`用这版`：场头回到 `内 · 日 · 走廊`，折叠变成 `改过 3 次`，最新一条就是刚写的那条；日志只多一条 `scene.updated { timeOfDay: "day", locationId: "loc-corridor" }`，`space` 没变所以不写。
- 与当前场头相同的那一版按钮置灰，悬停「场头已经是这一版」；只读标签页不显示按钮。
- 测试：web 145 条（新增 3 条：叠 patch、上一版、别的场与无关事件不混入）；IR 64、gateway 17、pipeline 21 不变，合计 247。`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：剧本页第 1 场展开折叠 → 点`最初`的`用这版` → 场头三位小签变 `内 · 日`、折叠变 3 次、IndexedDB 第 41 条为 `scene.updated`。

**负面**
- **只有场头三项**：场号、场序、这一场包含哪些镜头仍不进历史——它们现在也还改不了。
- **不显示「谁改的」**：单人项目没有作者字段，只记时刻。
- **时间只到分钟**：同一分钟内连改两次，列表里看起来一样，只靠先后顺序区分。
- **旧地点只写「不在库里」**：不知道它原来叫什么（事件里只有 id）。
- **地点名会变**：历史里显示的是地点**现在**的名字，改名之后旧版本也会跟着改口。
- **不联动下游**：恢复旧场头同样会让这一场的帧过期，但过期小签只说「场头」——这正是 ADR-0057 附记第二条负面。

**跟进**
- 场号与场序调整（牵动镜号与所有引用）。
- 新建 / 编辑地点（名字、模板、主镜）。
- 场头改动与过期标记的联动说明再想一遍。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 新增 `scene.head.updated` 只记场头 | 场头已经是 `scene.updated` 的一项；另开事件会让读模型与历史都写两遍 |
| 每个字段一条历史（内外景、日夜、地点各一份） | 用户看到的三位是一个整体，拆开会读成三个版本 |
| 只存「上一次」一份快照 | 改过三次就只剩两版，来回横跳时看不出中间那版 |
| 恢复时清空后面的历史 | 历史是事实，只能追加；清掉就没法再「用回」 |
| 在 `Project` 里维护 revision 字段 | 推导得出来的东西不落库，否则与事件日志打架（ADR-0011） |
