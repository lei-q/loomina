# ADR-0030 关键道具：进镜头就要有参考图

- 状态：已接受
- 日期：2026-11-10
- 决策者：用户 + Claude
- 关联：ADR-0028（资产层与定妆闸门）、ADR-0029（生成链路接资产锚点）、B8、[CONSISTENCY.md](../CONSISTENCY.md)

## 背景

ADR-0028 加了 `Prop` 实体，但道具只活在数据结构里：

- 镜头没有办法声明"这一镜要出现那只杯子"，`buildShotPrompt` 也从不提道具；
- 定妆台默认所有道具都不必锁（`required: false`），道具进不进镜头对闸门没有影响；
- 示例项目里没有道具，`Shot` 上也没有 `propIds`，等于道具整层是空转的。

短剧里真正难保持一致的往往不是脸，而是反复出现的物件：一只磕了口子的搪瓷杯、一盏绿色玻璃台灯。它们一旦每镜换一个，观众立刻出戏，而且这种漂移比人脸更容易被察觉。

## 决策

1. **`Shot` 增加 `propIds: Id[]`**（默认空数组），表示这一镜要出现的道具。和 `characterIds` 同级，走同一条引用校验。
2. **不变量 `REF_SHOT_PROP`**：镜头引用不存在的道具即违规（与 `REF_SHOT_CHARACTER` 同形）。
3. **闸门规则改为按引用推导**：有镜头引用的道具 `required = true`；没有镜头引用的道具不拖住「进分镜」，但仍显示在定妆台，方便提前准备。锁定时锁的是 `referenceImages`，与角色的三视图走同一张 `Approval` 表。
4. **锚点顺序：人物 → 场景 → 道具**。道具追加在场景之后；名额超过 `MAX_ANCHORS = 4` 时**先丢道具**，因为人脸与空间的一致性是主体，道具是点缀。每个道具只取第一张参考图。
5. **缺参考图按缺失上报**：道具存在但没有可用的参考图时，`shotAnchors.missing` 写上「道具「名称」缺参考图」，链路在模型调用前失败。
6. **提示词加一行 `道具：名称，描述`**，有描述才带描述。道具的"不许变"没有单独字段，细节写在 `description` 里。
7. **UI**：定妆台新增「道具 · 参考」一栏，每个道具一行，2:3 竖版占位图 + 锁定；审片台当前画面下方的锚点行直接显示 `台灯 · 参考图`。

## 理由

- **"镜头里有什么"必须是数据，不是提示词里的自然语言。** 只有进了 `propIds`，闸门、锚点、提示词、溯源才能对同一件事达成一致。
- **道具的必锁性从引用推出，而不是让用户勾"要紧"**。有镜头引用就是要紧，没有就不是；少一个需要人判断的开关。
- **额度分配体现优先级。** 四张图不够时，脸和房间比杯子重要；把道具排在最后并先丢，规则简单且可预期。
- **道具只用一张图**：道具没有多角度需求，一张正面参考足够；多给只会挤掉人脸。
- **缺图就失败**与 ADR-0029 一致：一张错的道具比补一张参考图贵。

## 后果

**正面**
- 示例项目里有了两只道具（搪瓷杯、台灯），SH-05 与 SH-09 的锚点行能看到它们。
- 闸门总数从 5 变成 7（2 角色 + 3 场景 + 2 道具），进分镜的条件第一次把道具算进去。
- 提示词里出现 `道具：搪瓷杯，白底蓝边，杯沿磕了一块`，细节不再只存在于描述字段。
- 同一套 `Approval` 表覆盖角色、场景、道具，没有新增实体。

**负面**
- 道具没有多角度能力，只有一张参考图；真需要多角度时得扩展 `Prop.referenceImages` 的语义。
- 一个镜头最多挂四个道具，第五个会静默丢掉（锚点层面），提示词里仍然全部列出——**锚点与提示词不完全一致**，这是当前的已知取舍。
- 道具的 `description` 同时承担"外观"与"不许变"，靠自然语言约定，没有结构化字段。
- 图片接口仍不接受参考图，道具参考图目前同样只影响提示词与溯源，不影响像素。

**跟进**
- 图片接口能收图后，验证多张参考图里道具排序是否影响输出。
- 锚点被截断时在审片台上明示"道具未进参考图"，而不是静默丢弃。
- 道具可能需要"禁变细节"字段（如"杯沿的缺口"），届时与角色的 `mustNotChange` 合并成一个概念。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 道具写进镜头描述的自然语言 | 闸门与锚点无法据此判断，等于没有 |
| 道具全部必锁 | 没用到的道具会拖住分区入口，用户得为不存在的需求补图 |
| 道具排在场景之前 | 名额不足时空间一致性先崩，比道具漂移更伤 |
| 每个道具最多两张参考图 | 名额有限，两张道具图会挤掉人脸；一张足够 |
| 给 `Prop` 加 `mustNotChange` | 现阶段描述字段够用，多一个字段就多一处要维护的 UI |
