# ADR-0152：地点参考图

- 状态：已采纳
- 日期：2026-11-12
- 相关：B8、ADR-0079、ADR-0063、ADR-0128

## 背景

人物与道具都可以挂多张参考图（ADR-0079），地点只有一张「主镜」。同一个房间换个机位、拍个细节、换一段时间的光，主镜不够用；作者只能把描述写长，生成时却没有任何图能引。

`Location.referenceImages` 字段从第一版就在 schema 里，但 `location.updated` 一直只接受名字、模板与描述，界面也没有入口——这个字段从未被写过。

## 决定

1. **事件**：`location.updated` 的 `patch` 增加 `referenceImages`，整份替换；`applyEvent` 复用人物 / 道具同一套校验——不能重复、最多 `REFERENCE_IMAGES_MAX`（8）张、每张必须指向已存在的资产。
2. **资产**：挂图时先写一条 `asset.updated`（`source: "upload"`），再写 `location.updated`；与人物 / 道具的「贴地址」完全同一条路，不做上传。
3. **锚点**：镜头锚点收集该地点场景的主镜之后，再追加地点的参考图，标签为 `「地点名」 · 参考图`；顺序排在人物与道具之后，用剩下的名额，不改变「脸与房间优先」的既有优先级。地点锁定后，只有锁定时包含的参考图能进锚点。
4. **界面**：定妆页每个地点的主镜下方多一排「参考」，与人物 / 道具同款；可挂、可摘（摘掉只删引用，资产留着），空态写「同一个房间的别的角度、细节、光线参考都挂在这里」。

## 理由

- 字段与校验都已存在，补的是事件入口与界面；不新增资产类型、不新增事件类型。
- 参考图进锚点才有意义：只挂在界面上、生成时看不到，等于一张相册。
- 锚点顺序显式靠后，避免地点细节把人物脸或道具挤掉；参考图数量上限本来就是为了保护提示词。

## 代价

- 地点多一种可写字段，`location.updated` 的校验分支多一条。
- 锚点数量固定时，地点参考图与道具争最后几个名额；作者挂太多会被截断，这是既有上限的延续。

## 不做什么

- 不做地点参考图的自动生成或从主镜裁切。
- 不做按镜头选择地点参考图：锚点取全部（受上限与锁定约束）。
- 不做上传与对象存储之外的清理策略：与 ADR-0079 / ADR-0128 一致。
