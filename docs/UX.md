# 前端与交互形态

> 核心判断：**用户不是来"操作时间线"的，是来"把一条想法变成能发的片子"的。**
> 界面按**任务**组织，不按**工具**组织；专业能力渐进披露，不挡主路径。

---

## 一、先立反面教材

这类产品最容易做成三种样子，都要避免：

| 反面 | 表现 | 为什么错 |
| --- | --- | --- |
| **剪辑软件化** | 首屏就是时间线、轨道、参数面板 | 用户第一眼就不知道该干什么（违反 P10） |
| **节点图化** | ComfyUI 式连线，能力全暴露 | 把"能力"当"产品"，C 端直接劝退 |
| **聊天框化** | 一个输入框，全靠提示词 | 不可控、不可回退、无法精细修改 |

正确形态在两者之间：**有明确阶段的一条流水线，每一阶段都有"默认结果 + 改的入口"。**

---

## 二、产品隐喻：导演工作台

不是"素材库 + 时间线"，而是**"拍一条片"的过程**：

```
想法 → 故事 → 分镜 → 预演 → 拍摄 → 剪辑 → 声音 → 发布
```

用户在界面上的心理模型应该是"我在导一条片"，而不是"我在用软件"。

对应到文档里的四道闸门（OPERATIONS.md），界面就是四个"确认点"。

---

## 三、双形态：桌面创作，手机审批

| | 桌面 Web | 手机伴侣 |
| --- | --- | --- |
| 定位 | **主创作** | **看、批、发** |
| 能力 | 全流程 | 审片、确认、改一句台词、换一个 Take、分享 |
| 不做 | — | 时间线、分镜编辑、参数面板 |
| 关键场景 | 坐下来做一条片 | 通勤时审批、睡前发一条 |

**手机不是缩小版编辑器。** 强行把桌面搬过去，两边都做不好（TECH-SELECTION 里已定 Web 优先、Tauri 后置）。

手机端最有价值的三个动作：

1. **推送审批**：镜头生成好了，点开看，通过/重做。
2. **一句话修改**："第三镜她别笑"，直接改。
3. **一键分享**：分享扩展发到平台（PUBLISHING.md）。

## 四、信息架构

```
首页
├── 新建（一句话 / 模板 / 导入小说）
├── 继续创作（按阶段显示进度）
└── 我的作品

创作流（核心）
├── ① 故事        一句话 → Logline → 人物 → Beat
├── ② 定妆        三视图 / 主镜 / 道具参考 → 锁定资产（闸门 1）
├── ③ 分镜        Beat → 镜头卡 → 3D 走位
├── ④ 预演        Animatic（第一道贵闸门）
├── ⑤ 生成        镜头墙 + Take 对比
├── ⑥ 成片        时间线（折叠）+ 声音 + 字幕
└── ⑦ 发布        预检 + 发布包

侧边
├── 资产库（角色 / 场景 / 道具 / 音乐）
├── 预算与消耗
└── 设置
```

## 五、阶段式主流程 + 自由工作台

两种模式，默认前者：

### 阶段式（默认）

- 顶部一条阶段进度条，当前阶段高亮。
- 每阶段只露出**该阶段需要的东西**。
- 底部固定"确认条"：`[上一步] [这里可以改…] [确认，进入下一步]`。
- 确认后阶段锁定，可回退（回退会提示下游影响）。

### 自由工作台（进阶）

- 熟练用户可切到"全部展开"：分镜、预览、时间线同屏。
- 入口藏在右上角，不主动推。
- 两模式共享同一份 IR，切换不丢状态。

**关键：默认路径不需要教程；专业能力收进"进阶"。**

## 六、四道闸门的 UI 表达

所有闸门用同一个组件，降低学习成本：

```
┌─────────────────────────────────────────┐
│  资产确认                        3/5 角色 │
│  ─────────────────────────────────────  │
│  [角色卡] [角色卡] [角色卡]              │
│  这次确认会锁定：脸、发型、服装、音色      │
│  之后修改需要重新生成已完成的镜头           │
│                                          │
│  [ 再看看 ]        [ 确认，开始分镜 ]      │
└─────────────────────────────────────────┘
```

三条规则：

1. **说清楚"确认什么"**：这次锁定哪些资产。
2. **说清楚"代价"**：确认后改，会影响多少下游。
3. **永远给"再看看"**：不逼用户做决定。

## 七、时间线放哪

**默认不露。** 折叠在"成片"阶段的"精细调整"里。

理由：

- C 端用户不会用时间线，看到轨道就慌。
- 大多数修改可以用**语义编辑**完成（F7）："这里快一点""把这个镜头换成第二个 Take"。
- 时间线是给"想精修的人"的，不是主路径。

时间线一旦展开，保留专业交互：拖拽、吸附、多轨、快捷键。但它是**第二层**。

## 八、参数面板的四层披露

同一个"光影"，对四个人说四种话：

| 层 | 用户看到 | 例子 |
| --- | --- | --- |
| **L0 结果** | 看片、选 Take | "这版更好" |
| **L1 意图** | 自然语言/滑杆 | "更压抑一点" |
| **L2 参数** | 结构化参数 | 光比 1:4、色温 3200K、85mm |
| **L3 提示词** | 编译后的 prompt | 只给排障用，不默认展示 |

默认停在 L0/L1。L2 给进阶，L3 基本不给。

**这是"摄影语言可量化"（P11）的产品化方式**：量化在底层，用户感知在意图层。

## 九、核心交互组件

### 1. 镜头卡（Shot Card）

分镜阶段的基本单位：

```
┌──────────────────┐
│  [首帧缩略图]      │
│  S03 · 近景 · 2.4s│
│  "她把杯子放下"    │
│  情绪：克制 → 决绝 │
│  [换一版] [编辑]   │
└──────────────────┘
```

一屏 6–8 张，可拖拽排序，可批量操作。

### 2. Take 对比

- 并排 / 滑动对比 / 逐帧对比。
- 显示 provenance（模型、seed、成本）。
- 一键"用这版"，非破坏。

审片台（ADR-0026）把它压成一条动作，规则见 ADR-0027：

- 留用 / 淘汰各写一条 `take.updated`；切换当前镜只是界面状态，不写事件。
- 锁定的镜头只读，要改先解锁。
- 重做按钮永远带价；生成链路没接通时禁用并写明原因，不做假进度。

### 3. 首尾帧编辑器

左右两个画框，中间一条时间轴。改首帧 = 改起点情绪；改尾帧 = 改落点。

### 4. 情绪曲线

横轴时间、纵轴强度，叠在 Beat 上。音乐、表演强度、剪辑节奏都挂在这条曲线上。

### 5. 预算条

始终可见的一条细条：`已用 12.4 / 预算 30 点`。接近上限变黄，超限阻断。

顶栏的金额可以点开，给三行数：已花、**全部重做一遍**、预算。整片报价是逐镜相加，依据写在下面（`12 镜，minimax-h3 @ 768p + 首帧 gpt-image-2-c`）；有镜头报不出价时不给总数，只说明原因——少算一镜的价格比不给更糟。

定妆页也显示同一个金额：出图按单价记进已花；价目表里没有那个模型时，写一行「另有 N 张定妆图没有价目，没算进已花」（ADR-0033）——未知不是免费。`IMAGE_MODEL` 现在是 `gpt-image-2-c`（¥0.12 / 张），新图都带价。

预算可在同一个面板里改：输入新数、点「改预算」，写入 `project.updated`，刷新后还是这个数（ADR-0035）。超预算时顶栏那个数字变 `pick` 色，展开里多一行「超出」。**不弹确认框**：超限的处置是"先提高预算"，不是一次点得动的橡皮章。

定妆页的生成按钮上先报价：`生成三视图 ¥0.48`（四格 × 单价）、`生成主镜 ¥0.12`、`生成参考图 ¥0.12`；价目拿不到时不标价、也不拦，取不到价的时候不猜。

金额左侧偶发两个状态词，都不是装饰：**未保存**（`text-pick`，悬停看原因）表示这次的改动没写进本地日志，界面照常可用但不能以为存住了；**只读**表示另一个标签页正拿着写权，这一页能看进度、不能改（ADR-0034），刷新后才能接管。

### 5.5 分镜页的关键帧（首帧 / 尾帧）

分镜页的画面位置显示关键帧，剪影只是还没生成时的占位。画面下方一条两格缩略条「首帧 / 尾帧」：点哪一格，大画面就显示哪一帧，右边的按钮也变成「生成首帧 ¥0.12」或「重生成尾帧 ¥0.12」（有图后是重生成）。缩略条里还没生成的格子显示剪影，正在生成的格子盖一层"……"。两帧可以同时生成，进度分开记，互不覆盖（ADR-0037 / ADR-0038）。

出图后真图替换剪影；镜头锁定时按钮换成"镜头已锁定 · 只读"。生成失败或超预算时，舞台上沿出现一行 `pick` 色的说明，点名是哪一镜。

出图之后又改过画面输入时，大画面左下角挂`过期`小签，缩略条对应格右上角一个小红点、帧名变 `pick` 色；底部胶片轨那一格左上角也有一枚 `pick` 圆点，不用点进去就知道哪几镜的帧对不上。三处悬停都写清改了哪几项（「首帧出图之后改过：动作、场头，建议重生成」），与关键帧页同一套判据（ADR-0057）。

刷新后默认回到首帧——"刚才在看哪一帧"是临时状态，不写进日志。

### 5.6 一句话指令

下带的输入框回车（或 ⌘⏎）即生效，**是查表，不是理解**（ADR-0039）：现在认得「太暗了 / 太亮 / 换个角度 / 靠近一点 / 拉远 / 手持 / 稳住 / 快一点 / 慢一点」九类说法。

- 亮度类落成补充要求：锚点上方出现一行「补充 整体提亮，补足曝光，阴影保留细节」，同一句说两次不会记两条；
- 换角度轮换机位、靠近 / 拉远紧松一档景别：镜号那一行（"特写 · 仰拍"）当场变；
- 快一点 / 慢一点一档 0.5 秒（"太快了"放慢、"太慢了"加快），镜号行后面的秒数与「重做」的报价当场变，提示词不变；
- 认不出的句子什么都不写，舞台上沿直说「没听懂这句」，并列出认得哪些；
- 成功的指令清空输入框；锁定的镜头输入框不可用。

改的是一条 `shot.updated`，刷新与重放都还在。每条补充是一个虚线小签，右侧 `×` 可以划掉（同样写一条 `shot.updated`）；不能直接编辑某一条，要改就划掉再说一遍。

画面下方还有一块折叠区「这一镜会送出的提示词」：点开显示当前选中那一帧的完整提示词，切换首 / 尾帧时跟着变，只读不可编辑（ADR-0040）。"太暗了"有没有进句子，在这里对得上。

折叠区下面一行 `出场`：每个角色一枚小签，点亮即进这一镜，点灭即移出；紧挨着的 `锚点` 行立刻跟着变（多出或少了谁的三视图），提示词同步。出场顺序就是点名顺序。锁定的镜头与只读标签页上签是灰的；有台词的人不能直接点掉——舞台上沿写「周在这一镜还有台词：先删掉，或去剧本页点他的名字换人，再把他从出场里拿掉。」（ADR-0065 / ADR-0070）。

`出场` 下面再一行 `道具`：同一套点签，点亮即把这件道具写进这一镜的 `propIds`，提示词里多一句「道具：…」，锚点里多一张道具参考图（没有参考图时写「缺 道具「X」缺参考图」）。道具没有台词，所以点灭不受限制；锁定的镜头同样置灰（ADR-0066）。两排签都在提示词折叠区与锚点之间；900 高的屏幕上多了这一排后要往下滚一点点才看得全。

### 5.7 锁定这一镜

下带「留用」右边是一个描边的「锁定」：**先留用一条 take 才能锁**（不可锁时置灰，悬停说明原因）。最新 take 还没留用时，这个按钮直接改叫「留用并锁」，一次点击写两条事件（`take.updated` + `shot.updated`），不用再回胶片轨找这一镜（ADR-0041 附记）。锁住之后动作整排换成「已锁定 · 只读」与「解锁」，舞台按钮变成"镜头已锁定 · 只读"，一句话指令输入框禁用，补充的 `×` 也不显示（ADR-0041）。锁与解锁各写一条 `shot.updated{locked}`，可回放。胶片轨上锁住的格子右上角带一枚小锁标，不用逐格点开就知道哪些镜已经定了。

注意：留用与留用并锁都会把选中挪到下一格还没定的镜头；要再改这一镜，从胶片轨点回去。

### 5.8 关键帧页（总览）

顶栏「关键帧」进 `/keyframes`：一镜一张卡（9:16 画面、两个按钮、一行景别 / 机位 / 有无帧小字），十二镜一屏看完。页头三个数：`首帧 n / 12`、`尾帧 n / 12`、`关键帧已花 ¥x`——最后一个只算这两类帧的资产，另有没价目的图单列张数（ADR-0042）。

- 卡上「首帧 / 尾帧」两个按钮各自标价（`¥0.12`），有图后按钮名下写"重生成"；生成时画面盖一层"生成中…"，另一帧的按钮同时禁用，一次只跑一帧。
- 两帧都有时点画面在首帧 / 尾帧之间切换，右上角一个小签写「首」或「尾」；只有尾帧时优先显示尾帧。点画面只切显示，不花钱。
- 出图之后又改过画面输入（动作、景别、机位、人物、道具、补充要求，或所在场头的内外景 / 日夜 / 地点），这一帧的画面左下角挂一枚`过期`小签，页头多一个 `过期 n 帧`；小签悬停写「首帧出图之后改过：动作、场头（21:21），建议重生成」——改了几项就列几项，时刻取最后一次改动（ADR-0057）。分镜页同一帧也挂：大画面左下角同一枚小签，缩略图右上角一个小红点，悬停写「出图之后改过：动作，这一帧已对不上」。生成按钮悬停写「画面改过，这一帧已对不上：重生成」。重生成后小签消失。
- 锁定的镜头卡上带锁图标，两个按钮置灰。
- 卡片下方小字 `特写 · 仰拍 · 首✓ · 尾—` 说清这一镜有没有帧，不靠猜。
- 筛子一排：`全部 12 · 缺首帧 10 · 缺尾帧 11 · 两帧齐 1`，点哪个看哪个；计数写在筛子上，空档会写清"想看的帧都已经有了"（ADR-0042 附记）。
- 筛子右边两个批量按钮：`补缺首帧 9 张 · ¥1.08` / `补缺尾帧 9 张 · ¥1.08`（跳过锁定镜头）。点了按镜号顺序一张一张来，进度写 `补首帧 n / m`，旁边「停下」在**当前这张结束后**生效；任何一张失败就停。批量中单卡按钮全部禁用，避免插队。
- 生成走与分镜页同一个动作：同一 job key、同样一条 `asset.updated` + `shot.updated`、同样的预算拦截；刷新后图还在。
- 另一个标签页在编辑时这一页只读：单卡的两个生成按钮一并置灰，悬停写「另一个标签页在编辑：这一页只读」。

### 5.9 剧本页

顶栏「剧本」进 `/script`：按场次与场内镜序摊平，每镜先动作、后台词，最后一行技术信息（`特写 · 仰拍 · 2.4s`）。页头四个数：场 / 镜 / 台词条数 / 总时长（ADR-0043）。

- 场头一行：`第 1 场 [内 · 夜] 走廊`，右侧 `7.9s · 3 镜`。方括号里的小签可点，就地变成三个下拉——内外景 · 日夜 · 地点，边改边生效；点编辑器外面收起（ADR-0050 / ADR-0056）。地点下拉只列已有地点；要加新的，去定妆页的`新建地点`（ADR-0059）。
- 场头改动过时，下面多一行折叠 `改过 2 次 · 上一版 内 · 夜 · 走廊`；展开是按时间倒序的各版（`21:09 内 · 夜 · 桌边`），每版一个`用这版`，与当前相同的那版置灰；`最初`单独一行。恢复写一条 `scene.updated`，不抹掉历史（ADR-0058）。
- 场头行右侧 `n.ns · m 镜` 后面两个小钮 `↑` / `↓`：一次挪一位，第一场的 `↑`、最后一场的 `↓` 置灰；挪完场号按新顺序连续重排，全局镜号（SH-01…）跟着重算，台词 / take / 帧 / 场头历史都按 id 挂着不动（ADR-0060）。只读标签页不显示这两个钮。
- `↓` 旁边第三个钮 `挪`：点了就地变成一个场次下拉（`挪到…` + 除本场外的每一场，写 `第 N 场`），选完这一场直接落到那一场的位置，中间各场顺次补位；只写一条 `scene.moved`，长片从第 8 场挪到第 2 场不用连点六次（ADR-0060 附记）。下拉失焦或按 Esc 收起，不改任何东西。只读标签页不显示 `↑` / `↓` / `挪`。
- 每场末尾一个虚线 `＋ 加一镜`、整页末尾一个通栏虚线 `＋ 加一场`（只读标签页都不显示）：新场出现在末尾，地点 / 内外景 / 日夜沿用前面那一场（一场都没有时是第一个地点 · 内 · 日），以 `第 N 场 内 · 日 地点 0.0s · 0 镜` 出现，场头照旧可点改；新镜写 `（这一镜还没有动作描述）`、默认 `中景 · 平视 · 3.0s`，计入页头镜数与时长（ADR-0064 / ADR-0069）。一场都没有时，正文先写一句「还没有场次。下面加一场，从场头与第一镜开始写。」
- 场头行最右一个 `删`：点了原地变成 `确认删` 或 `确认删 N 镜` 与 `取消`。删一场会先把它里面的镜头逐条删掉，再删场；场号立刻连续重排。这一场里有锁定的镜头时不删，场头下面一行红字写「这一场里的第 N 镜（SH-0N）已锁定：先解锁再删这一场。」（ADR-0067）。
- 每镜技术行下面一个 `删这一镜`：同样两步确认（`确认删` / `取消`），旁边写「删这一镜，台词与 take 一起删」。锁定的镜头这个钮置灰，悬停写「这一镜已锁定，先解锁才能删」。删掉当前这一镜时，分镜页的选中挪到下一格（没有下一格就退回上一格）。删光了不报错：分镜页写「还没有镜头。去「剧本」页加一场，再回来点名出场、生成关键帧。」（ADR-0067）。
- 需要插在中间时：每镜 `删这一镜` 右边是 `＋ 插一镜`，点一下就在这一镜后面插一镜，后面几镜的镜号顺次后移；每场末尾 `＋ 加一镜` 右边是 `＋ 插一场`，点一下就在这一场后面插一场空场，后面的场号顺次后移，新场的地点 / 内外景 / 日夜沿用被插的那一场（ADR-0068 / ADR-0069）。两个都是虚线小签，与「加在末尾」的 `＋ 加一镜` / `＋ 加一场` 分得开。
- 镜号缩窄列（`SH-01`），动作正文 13px、行距略松；台词缩进在一条细竖线里，说话人小字在上、台词在下。
- 台词小字带时长：`周 · 2.1s`，旁边一个「改」（ADR-0044）。点开就地变成文本框，`保存` / `取消`，⌘↩ 保存、Esc 取消；说明一行「时长按 0.3 秒 / 字重估，镜头跟着挪」。
- 保存后：台词行与镜头技术行的时长同时变，页头总时长跟着变；日志里落两条事件（`dialogue.updated` + `shot.updated`）。
- 改过的台词下面多一行折叠：`改过 n 次 · 换过 m 次人 · 上一版「…」`；展开是按时间倒序的版本，`换人`一段写 `时间 周 → 林` 并带`换回`，最后一行是`最初`那版。不另建版本表，读的是事件日志（ADR-0044 附记 / ADR-0052）。
- 每一版后面一个`用这版`：点一下把文本与那一版的时长一起写回，镜头跟着挪；与当前文本相同的行置灰。回退是追加一条新版本，不抹掉历史。
- 每句台词旁还有`删`：点了变成`确认删 / 取消`；删掉后镜头时长减这一句（ADR-0045）。
- 说话人小字可点：变成下拉，选完立刻换人（一条 `dialogue.speaker.updated`，文本与时长不动，ADR-0046）。
- 每镜技术行下面还有一排 `出场`：这一镜里谁在场（没有出场人物时不显示）。点名字就地变成下拉 `换下 林 →`，选谁就把这一镜的这个人换成谁：出场顺序保持原位，这一镜里他说的台词说话人一起换过去（一次写 `shot.updated { characterIds }`，每条台词各一条 `dialogue.speaker.updated`，ADR-0070）。换上的人本来就在这一镜里时并成一位。锁定的镜头与只读标签页上这些签是灰的，悬停写「这一镜已锁定，先解锁才能换人」；换人被拒的原因贴在这一镜下面。
- 一镜里有两句以上时，每句后面多 `↑` / `↓`：一次挪一位，到顶到底置灰；单句镜头不显示箭头（ADR-0047）。
- 每句台词旁还有`移`：点了变成目标镜头下拉（`SH-03 · 第 1 场`，不含本镜），选完这一句就去那一镜的队尾；源镜与目标镜时长一减一加，页头总时长不动（ADR-0054）。锁定镜头置灰。
- 镜头台词下面一行 `这一镜的顺序改过 n 次`：展开是倒序的顺序版本（`时间 门开着呢。/ 谁在那儿？`），带`用这版`；旧版本里含已删句子时按钮置灰。句子有进出（加句 / 删句 / 跨镜头挪）不算一次「换顺序」（ADR-0053 / ADR-0054）。
- 镜头下面还有一行 `删过 n 句`：展开倒序，每行 `时间 带删除线的正文` + `恢复`；恢复把这一句原样（同 id、同说话人、同长度）放回这一镜队尾，镜头与全片时长加回。已经恢复过的记录按钮置灰，锁定镜头置灰（ADR-0055）。
- 每镜台词末尾有`+ 加一句`：点开是说话人下拉（这一镜里有谁排前面）+ 文本框；保存后镜头时长加这一句。锁定镜头两者都置灰。
- 锁定的镜头：技术行后缀 `已锁定`，「改」置灰，悬停说明先解锁。
- 顶栏`导出`把这一页打成纯文本下载，文件名 `标题-v版本.txt`：标题与版本、四数页头、场头、`SH-xx · 景别 · 机位 · 时长`、动作、缩进的`角色：文本`（ADR-0048）。导出不写事件，日志不变。
- 动作整段可点：点了就地变文本框，`保存` / `取消`，⌘↩ 保存、Esc 取消；改字不动时长（一条 `shot.updated { description }`，ADR-0049）。锁定镜头与只读标签页不可点，悬停说明原因。
- 改过的动作下面有 `改过 n 次 · 上一版「…」` 折叠：展开按时间倒序，每行全文 + `用这版`，最后一行是`最初`；回退是一次新的改写（ADR-0051）。
- 场次的地点与场号仍只读；场头只有内 / 外景与日夜可改。
- 分镜页改过的时长、机位，刷新这一页就同步；整片镜号一致（第二场第一镜是 SH-04，不是 SH-01）。

### 6. 定妆台

定妆阶段的整页形态（ADR-0028），不是弹窗：

```
定妆
先把脸和空间钉住，再谈镜头。
5 / 7 已锁定  ────────────────────────────

人物 · 三视图
林  ▪ 已锁定        正面  3/4  侧面  背面        8:59 锁
短发，深色外套      [ ]  [ ]  [ ]  [ ]           [解锁]
不许变
左眼下的痣
齐肩黑发，中分

场景 · 主镜
走廊  ▪ 已锁定      [master]  同一场的所有镜头都带这张图  [解锁]

道具 · 参考
搪瓷杯  ▪ 可锁定     [ref 1]  在镜头里出现，就要有一张参考图  [锁定道具]
白底蓝边            ↑ 锁住后，带它的镜头都引这一张
```

- 人物按"四格"排：正面 / 3-4 / 侧面 / 背面，各是一张独立的图；缺格的角色显示"缺 N 格"，锁定按钮禁用。
- 人物行有一个"生成三视图"：逐格生成，当前格盖一层"生成中…"，落一张换一张真图（ADR-0031）；锁定的角色没有这个按钮。
- 场景只排一张主镜，旁边一句说明它为什么会被每个镜头引用；旁边一个"生成主镜"，出的是空镜，锁定的场景没有这个按钮（ADR-0032）。
- `场景 · 主镜` 标题右侧一个 `新建地点`（只读标签页不显示）：点开是虚线框内联表单——名字输入 + 模板下拉（走廊 / 门口 / 桌边 / 门厅）+ 描述框（选填）+ `创建` / `取消`，Esc 收起。描述会进主镜提示词（ADR-0063）。新地点立刻多一行，还没挂场次时状态词写`未挂场次`、副标题写`主镜 · 还没挂场次`，不冒充必锁项；到剧本页把它挂到场上之后，状态词变`缺 主镜`并计入应锁数（ADR-0059）。
- 每行地点名旁一个`改名`：点开就地变成名字输入 + 模板下拉 + `保存` / `取消`。只写真正变了的字段；什么都没改时直说「地点没改。」不收按钮（ADR-0059）。
- 地点行中间那栏是场景描述：有描述时直接显示，没有时显示灰字 `＋ 写一句这地方长什么样`，点一下就地变成三行文本框（`保存` / `取消`，Esc 收起），下面一行提示「整句进主镜提示词：空间、陈设、光线，200 字以内」。描述整句进主镜提示词，留空则只按名字画（ADR-0063）。
- 名字旁还有一个`删`：点了变成`确认删` / `取消`，确认后整行消失，日志留一条 `location.removed`；已经生成的主镜图不随删除清理（ADR-0061）。还有场次在这个地点时，确认块里多一个「先搬到哪里」的地点下拉，主按钮改叫`搬过去再删`，确认后这些场次整批换到所选地点再删（ADR-0062）；被占用又没有别的地点可搬时`删`置灰，悬停写「先新建一个地点」。
- 道具一行一张参考图，带一个"生成参考图"；被镜头引用（`Shot.propIds`）的道具算必锁项，没被引用的仍显示，但不计入进度（ADR-0030）。锁定后不能再生成（ADR-0032）。
- 顶部是进度（已锁定 / 应锁定），底部是闸门：没锁完时"进分镜"是灰的，并写明"定妆没锁完，分镜不开"。
- 只对有近景 / 特写的角色要求四格；群演和背影角色不白白生成三视图。

## 十、等待：生成是分钟级的

这是体验设计里最容易被忽略的部分。

- **异步 + 可离开**：提交后可关页面，完成推送。
- **进度可见**：不是转圈，而是"第 7/25 镜生成中"。
- **先给草稿**：draft 先出，用户先看构图，再决定要不要 final。
- **队列透明**：高峰期显示预计等待。
- **失败可续**：中断后从断点继续，不从头再来。

**等待时的正确做法是让用户去干别的，而不是盯着进度条。**

---

## 十一、空状态与默认值

P6 说"默认 AI 初稿，人只做改"。UI 上要落实：

- 新建项目：给 3 个 logline 候选，不是一个空输入框。
- 每个阶段：进入即有可用结果，按钮是"换一个"而不是"生成"。
- 参数：有推荐值，不是空白。
- 没有灵感：模板库 + 题材矩阵（STORY.md）。

---

## 十二、错误不是报错，是诊断

生成失败时，不要弹"生成失败 (code 500)"。要给：

```
这张脸和角色档案不一致（相似度 0.62，阈值 0.75）
可能原因：角度太侧 / 光线太暗
[ 换正面角度 ] [ 提高亮度重试 ] [ 用这版 ]
```

对应 CONSISTENCY.md 的"失败维度 + 修复路由"。**每个错误都要有下一步动作。**

## 十三、设计语言

来自 PRODUCT.md 的品牌调性：**暗房 / 影院**，不是赛博朋克。

- 深色底，低饱和，留白多。
- 强调色克制，只用于"当前动作"和"确认"。
- 光影是视觉主角：缩略图大、边框少。
- 字体：无衬线为主，字幕预览用实际字体。
- 动效：少而慢，服务于"确认感"，不炫技。

具体令牌、布局解剖与图标规范见 [DESIGN-SYSTEM.md](DESIGN-SYSTEM.md)。

## 十五、失败模式

| 失败 | 表现 | 原因 | 对策 |
| --- | --- | --- | --- |
| 功能堆砌 | 首屏全是按钮 | 按工具组织 | 按阶段组织 |
| 时间线恐惧 | 用户不敢动 | 专业界面前置 | 默认折叠 |
| 参数焦虑 | 不知道该调什么 | 参数全暴露 | 四层披露 |
| 等待流失 | 生成时关掉 | 无异步/无推送 | 可离开 + 通知 |
| 错误劝退 | 报错看不懂 | 技术错误直出 | 诊断卡 + 修复 |
| 移动端照搬 | 手机上没法用 | 缩小版桌面 | 只做审批/分享 |
| 确认后悔 | 锁了才发现错 | 没讲清代价 | 闸门说清影响 |

| 指标 | 目标 |
| --- | --- |

## 十七、一句话

**默认路径是一条"向导"，不是一块"画布"。**
用户每一步都看到"下一步做什么"，每个结果都能"换一个"，每个错误都有"怎么办"；时间线和参数是第二层，永远不挡在主路径上。
