# 前端与交互形态

> 核心判断：**用户不是来"操作时间线"的，是来"把一条想法变成能发的片子"的。**
> 界面按**任务**组织，不按**工具**组织；专业能力渐进披露，不挡主路径。

---

## 一、先立反面教材

这类产品最容易做成三种样子，都要避免：

| 反面 | 表现 | 为什么错 |
| --- | --- | --- |
| **剪辑软件化** | 首屏就是时间线、轨道、参数面板 | 用户第一眼就不知道该干什么（违反 P10） |
| **节点图化** | ComfyUI 式连线，能力全暴露 | 把"能力"当"产品"，C 端直接劝退 |
| **聊天框化** | 一个输入框，全靠提示词 | 不可控、不可回退、无法精细修改 |

正确形态在两者之间：**有明确阶段的一条流水线，每一阶段都有"默认结果 + 改的入口"。**

---

## 二、产品隐喻：导演工作台

不是"素材库 + 时间线"，而是**"拍一条片"的过程**：

```
想法 → 故事 → 分镜 → 预演 → 拍摄 → 剪辑 → 声音 → 发布
```

用户在界面上的心理模型应该是"我在导一条片"，而不是"我在用软件"。

对应到文档里的四道闸门（OPERATIONS.md），界面就是四个"确认点"。

---

## 三、双形态：桌面创作，手机审批

| | 桌面 Web | 手机伴侣 |
| --- | --- | --- |
| 定位 | **主创作** | **看、批、发** |
| 能力 | 全流程 | 审片、确认、改一句台词、换一个 Take、分享 |
| 不做 | — | 时间线、分镜编辑、参数面板 |
| 关键场景 | 坐下来做一条片 | 通勤时审批、睡前发一条 |

**手机不是缩小版编辑器。** 强行把桌面搬过去，两边都做不好（TECH-SELECTION 里已定 Web 优先、Tauri 后置）。

手机端最有价值的三个动作：

1. **推送审批**：镜头生成好了，点开看，通过/重做。
2. **一句话修改**："第三镜她别笑"，直接改。
3. **一键分享**：分享扩展发到平台（PUBLISHING.md）。

---

## 四、信息架构

```
首页
├── 新建（一句话 / 模板 / 导入小说）
├── 继续创作（按阶段显示进度）
└── 我的作品

创作流（核心）
├── ① 故事        一句话 → Logline → 人物 → Beat
├── ② 定妆        三视图 / 主镜 / 道具参考 → 锁定资产（闸门 1）
├── ③ 分镜        Beat → 镜头卡 → 3D 走位
├── ④ 预演        Animatic（第一道贵闸门）
├── ⑤ 生成        镜头墙 + Take 对比
├── ⑥ 成片        时间线（折叠）+ 声音 + 字幕
└── ⑦ 发布        预检 + 发布包

侧边
├── 资产库（角色 / 场景 / 道具 / 音乐）
├── 预算与消耗
└── 设置
```

## 五、阶段式主流程 + 自由工作台

两种模式，默认前者：

### 阶段式（默认）

- 顶部一条阶段进度条，当前阶段高亮。
- 每阶段只露出**该阶段需要的东西**。
- 底部固定"确认条"：`[上一步] [这里可以改…] [确认，进入下一步]`。
- 确认后阶段锁定，可回退（回退会提示下游影响）。

### 自由工作台（进阶）

- 熟练用户可切到"全部展开"：分镜、预览、时间线同屏。
- 入口藏在右上角，不主动推。
- 两模式共享同一份 IR，切换不丢状态。

**关键：默认路径不需要教程；专业能力收进"进阶"。**

## 六、四道闸门的 UI 表达

所有闸门用同一个组件，降低学习成本：

```
┌─────────────────────────────────────────┐
│  资产确认                        3/5 角色 │
│  ─────────────────────────────────────  │
│  [角色卡] [角色卡] [角色卡]              │
│  这次确认会锁定：脸、发型、服装、音色      │
│  之后修改需要重新生成已完成的镜头           │
│                                          │
│  [ 再看看 ]        [ 确认，开始分镜 ]      │
└─────────────────────────────────────────┘
```

三条规则：

1. **说清楚"确认什么"**：这次锁定哪些资产。
2. **说清楚"代价"**：确认后改，会影响多少下游。
3. **永远给"再看看"**：不逼用户做决定。

## 七、时间线放哪

**默认不露。** 折叠在"成片"阶段的"精细调整"里。

理由：

- C 端用户不会用时间线，看到轨道就慌。
- 大多数修改可以用**语义编辑**完成（F7）："这里快一点""把这个镜头换成第二个 Take"。
- 时间线是给"想精修的人"的，不是主路径。

时间线一旦展开，保留专业交互：拖拽、吸附、多轨、快捷键。但它是**第二层**。

---

## 八、参数面板的四层披露

同一个"光影"，对四个人说四种话：

| 层 | 用户看到 | 例子 |
| --- | --- | --- |
| **L0 结果** | 看片、选 Take | "这版更好" |
| **L1 意图** | 自然语言/滑杆 | "更压抑一点" |
| **L2 参数** | 结构化参数 | 光比 1:4、色温 3200K、85mm |
| **L3 提示词** | 编译后的 prompt | 只给排障用，不默认展示 |

默认停在 L0/L1。L2 给进阶，L3 基本不给。

**这是"摄影语言可量化"（P11）的产品化方式**：量化在底层，用户感知在意图层。

## 九、核心交互组件

### 1. 镜头卡（Shot Card）

分镜阶段的基本单位：

```
┌──────────────────┐
│  [首帧缩略图]      │
│  S03 · 近景 · 2.4s│
│  "她把杯子放下"    │
│  情绪：克制 → 决绝 │
│  [换一版] [编辑]   │
└──────────────────┘
```

一屏 6–8 张，可拖拽排序，可批量操作。

### 2. Take 对比

- 并排 / 滑动对比 / 逐帧对比。
- 显示 provenance（模型、seed、成本）。
- 一键"用这版"，非破坏。

审片台（ADR-0026）把它压成一条动作，规则见 ADR-0027：

- 留用 / 淘汰各写一条 `take.updated`；切换当前镜只是界面状态，不写事件。
- 锁定的镜头只读，要改先解锁。
- 重做按钮永远带价；生成链路没接通时禁用并写明原因，不做假进度。

### 3. 首尾帧编辑器

左右两个画框，中间一条时间轴。改首帧 = 改起点情绪；改尾帧 = 改落点。

### 4. 情绪曲线

横轴时间、纵轴强度，叠在 Beat 上。音乐、表演强度、剪辑节奏都挂在这条曲线上。

### 5. 预算条

始终可见的一条细条：`已用 12.4 / 预算 30 点`。接近上限变黄，超限阻断。

顶栏的金额可以点开，给三行数：已花、**全部重做一遍**、预算。整片报价是逐镜相加，依据写在下面（`12 镜，minimax-h3 @ 768p + 首帧 gpt-image-2-c`）；有镜头报不出价时不给总数，只说明原因——少算一镜的价格比不给更糟。

定妆页也显示同一个金额：出图按单价记进已花；价目表里没有那个模型时，写一行「另有 N 张定妆图没有价目，没算进已花」（ADR-0033）——未知不是免费。`IMAGE_MODEL` 现在是 `gpt-image-2-c`（¥0.12 / 张），新图都带价。

预算可在同一个面板里改：输入新数、点「改预算」，写入 `project.updated`，刷新后还是这个数（ADR-0035）。超预算时顶栏那个数字变 `pick` 色，展开里多一行「超出」。**不弹确认框**：超限的处置是"先提高预算"，不是一次点得动的橡皮章。

定妆页的生成按钮上先报价：`生成三视图 ¥0.48`（四格 × 单价）、`生成主镜 ¥0.12`、`生成参考图 ¥0.12`；价目拿不到时不标价、也不拦，取不到价的时候不猜。

金额左侧偶发两个状态词，都不是装饰：**未保存**（`text-pick`，悬停看原因）表示这次的改动没写进本地日志，界面照常可用但不能以为存住了；**只读**表示另一个标签页正拿着写权，这一页能看进度、不能改（ADR-0034），刷新后才能接管。

### 5.5 分镜页的关键帧（首帧 / 尾帧）

分镜页的画面位置显示关键帧，剪影只是还没生成时的占位。画面下方一条两格缩略条「首帧 / 尾帧」：点哪一格，大画面就显示哪一帧，右边的按钮也变成「生成首帧 ¥0.12」或「重生成尾帧 ¥0.12」（有图后是重生成）。缩略条里还没生成的格子显示剪影，正在生成的格子盖一层"……"。两帧可以同时生成，进度分开记，互不覆盖（ADR-0037 / ADR-0038）。

出图后真图替换剪影；镜头锁定时按钮换成"镜头已锁定 · 只读"。生成失败或超预算时，舞台上沿出现一行 `pick` 色的说明，点名是哪一镜。

刷新后默认回到首帧——"刚才在看哪一帧"是临时状态，不写进日志。

### 5.6 一句话指令

下带的输入框回车（或 ⌘⏎）即生效，**是查表，不是理解**（ADR-0039）：现在认得「太暗了 / 太亮 / 换个角度 / 靠近一点 / 拉远 / 手持 / 稳住 / 快一点 / 慢一点」九类说法。

- 亮度类落成补充要求：锚点上方出现一行「补充 整体提亮，补足曝光，阴影保留细节」，同一句说两次不会记两条；
- 换角度轮换机位、靠近 / 拉远紧松一档景别：镜号那一行（"特写 · 仰拍"）当场变；
- 快一点 / 慢一点一档 0.5 秒（"太快了"放慢、"太慢了"加快），镜号行后面的秒数与「重做」的报价当场变，提示词不变；
- 认不出的句子什么都不写，舞台上沿直说「没听懂这句」，并列出认得哪些；
- 成功的指令清空输入框；锁定的镜头输入框不可用。

改的是一条 `shot.updated`，刷新与重放都还在。每条补充是一个虚线小签，右侧 `×` 可以划掉（同样写一条 `shot.updated`）；不能直接编辑某一条，要改就划掉再说一遍。

画面下方还有一块折叠区「这一镜会送出的提示词」：点开显示当前选中那一帧的完整提示词，切换首 / 尾帧时跟着变，只读不可编辑（ADR-0040）。"太暗了"有没有进句子，在这里对得上。

### 5.7 锁定这一镜

下带「留用」右边是一个描边的「锁定」：**先留用一条 take 才能锁**（不可锁时置灰，悬停说明原因）。最新 take 还没留用时，这个按钮直接改叫「留用并锁」，一次点击写两条事件（`take.updated` + `shot.updated`），不用再回胶片轨找这一镜（ADR-0041 附记）。锁住之后动作整排换成「已锁定 · 只读」与「解锁」，舞台按钮变成"镜头已锁定 · 只读"，一句话指令输入框禁用，补充的 `×` 也不显示（ADR-0041）。锁与解锁各写一条 `shot.updated{locked}`，可回放。胶片轨上锁住的格子右上角带一枚小锁标，不用逐格点开就知道哪些镜已经定了。

注意：留用与留用并锁都会把选中挪到下一格还没定的镜头；要再改这一镜，从胶片轨点回去。

### 5.8 关键帧页（总览）

顶栏「关键帧」进 `/keyframes`：一镜一张卡（9:16 画面、两个按钮、一行景别 / 机位 / 有无帧小字），十二镜一屏看完。页头三个数：`首帧 n / 12`、`尾帧 n / 12`、`关键帧已花 ¥x`——最后一个只算这两类帧的资产，另有没价目的图单列张数（ADR-0042）。

- 卡上「首帧 / 尾帧」两个按钮各自标价（`¥0.12`），有图后按钮名下写"重生成"；生成时画面盖一层"生成中…"，另一帧的按钮同时禁用，一次只跑一帧。
- 两帧都有时点画面在首帧 / 尾帧之间切换，右上角一个小签写「首」或「尾」；只有尾帧时优先显示尾帧。点画面只切显示，不花钱。
- 锁定的镜头卡上带锁图标，两个按钮置灰。
- 卡片下方小字 `特写 · 仰拍 · 首✓ · 尾—` 说清这一镜有没有帧，不靠猜。
- 筛子一排：`全部 12 · 缺首帧 10 · 缺尾帧 11 · 两帧齐 1`，点哪个看哪个；计数写在筛子上，空档会写清"想看的帧都已经有了"（ADR-0042 附记）。
- 生成走与分镜页同一个动作：同一 job key、同样一条 `asset.updated` + `shot.updated`、同样的预算拦截；刷新后图还在。

### 6. 定妆台

定妆阶段的整页形态（ADR-0028），不是弹窗：

```
定妆
先把脸和空间钉住，再谈镜头。
5 / 7 已锁定  ────────────────────────────

人物 · 三视图
林  ▪ 已锁定        正面  3/4  侧面  背面        8:59 锁
短发，深色外套      [ ]  [ ]  [ ]  [ ]           [解锁]
不许变
左眼下的痣
齐肩黑发，中分

场景 · 主镜
走廊  ▪ 已锁定      [master]  同一场的所有镜头都带这张图  [解锁]

道具 · 参考
搪瓷杯  ▪ 可锁定     [ref 1]  在镜头里出现，就要有一张参考图  [锁定道具]
白底蓝边            ↑ 锁住后，带它的镜头都引这一张
```

- 人物按"四格"排：正面 / 3-4 / 侧面 / 背面，各是一张独立的图；缺格的角色显示"缺 N 格"，锁定按钮禁用。
- 人物行有一个"生成三视图"：逐格生成，当前格盖一层"生成中…"，落一张换一张真图（ADR-0031）；锁定的角色没有这个按钮。
- 场景只排一张主镜，旁边一句说明它为什么会被每个镜头引用；旁边一个"生成主镜"，出的是空镜，锁定的场景没有这个按钮（ADR-0032）。
- 道具一行一张参考图，带一个"生成参考图"；被镜头引用（`Shot.propIds`）的道具算必锁项，没被引用的仍显示，但不计入进度（ADR-0030）。锁定后不能再生成（ADR-0032）。
- 顶部是进度（已锁定 / 应锁定），底部是闸门：没锁完时"进分镜"是灰的，并写明"定妆没锁完，分镜不开"。
- 只对有近景 / 特写的角色要求四格；群演和背影角色不白白生成三视图。

## 十、等待：生成是分钟级的

这是体验设计里最容易被忽略的部分。

- **异步 + 可离开**：提交后可关页面，完成推送。
- **进度可见**：不是转圈，而是"第 7/25 镜生成中"。
- **先给草稿**：draft 先出，用户先看构图，再决定要不要 final。
- **队列透明**：高峰期显示预计等待。
- **失败可续**：中断后从断点继续，不从头再来。

**等待时的正确做法是让用户去干别的，而不是盯着进度条。**

## 十一、空状态与默认值

P6 说"默认 AI 初稿，人只做改"。UI 上要落实：

- 新建项目：给 3 个 logline 候选，不是一个空输入框。
- 每个阶段：进入即有可用结果，按钮是"换一个"而不是"生成"。
- 参数：有推荐值，不是空白。
- 没有灵感：模板库 + 题材矩阵（STORY.md）。

---

## 十二、错误不是报错，是诊断

生成失败时，不要弹"生成失败 (code 500)"。要给：

```
这张脸和角色档案不一致（相似度 0.62，阈值 0.75）
可能原因：角度太侧 / 光线太暗
[ 换正面角度 ] [ 提高亮度重试 ] [ 用这版 ]
```

对应 CONSISTENCY.md 的"失败维度 + 修复路由"。**每个错误都要有下一步动作。**

---

## 十三、设计语言

来自 PRODUCT.md 的品牌调性：**暗房 / 影院**，不是赛博朋克。

- 深色底，低饱和，留白多。
- 强调色克制，只用于"当前动作"和"确认"。
- 光影是视觉主角：缩略图大、边框少。
- 字体：无衬线为主，字幕预览用实际字体。
- 动效：少而慢，服务于"确认感"，不炫技。

具体令牌、布局解剖与图标规范见 [DESIGN-SYSTEM.md](DESIGN-SYSTEM.md)。

## 十四、性能底线

| 指标 | 目标 |
| --- | --- |
| 首屏可交互 | < 2s |
| 镜头卡滚动 | 60fps |
| 预览起播 | < 1s（代理分辨率） |
| 时间线拖动 | 无卡顿（虚拟化） |
| 大项目（100+ 镜） | 不崩 |

技术路径见 TECH-SELECTION：WebCodecs 预览、代理分辨率、虚拟列表、边缘缓存缩略图。

## 十五、失败模式

| 失败 | 表现 | 原因 | 对策 |
| --- | --- | --- | --- |
| 功能堆砌 | 首屏全是按钮 | 按工具组织 | 按阶段组织 |
| 时间线恐惧 | 用户不敢动 | 专业界面前置 | 默认折叠 |
| 参数焦虑 | 不知道该调什么 | 参数全暴露 | 四层披露 |
| 等待流失 | 生成时关掉 | 无异步/无推送 | 可离开 + 通知 |
| 错误劝退 | 报错看不懂 | 技术错误直出 | 诊断卡 + 修复 |
| 移动端照搬 | 手机上没法用 | 缩小版桌面 | 只做审批/分享 |
| 确认后悔 | 锁了才发现错 | 没讲清代价 | 闸门说清影响 |

## 十六、验收指标

| 指标 | 目标 |
| --- | --- |
| 首次出片时间 | ≤ 30 分钟（P10） |
| 新建 → 首个可用 logline | < 2 分钟 |
| 阶段流失率 | 每阶段 < 15% |
| 闸门确认耗时 | < 3 分钟/次 |
| 用户手动改镜比例 | 20–40%（太低=没参与感，太高=AI 不行） |
| 移动端审批占比 | > 30%（说明伴侣端有用） |

## 十七、一句话

**默认路径是一条"向导"，不是一块"画布"。**
用户每一步都看到"下一步做什么"，每个结果都能"换一个"，每个错误都有"怎么办"；时间线和参数是第二层，永远不挡在主路径上。
