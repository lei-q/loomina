## 二、分层职责

### 1. 客户端
- 面向 C 端的**主路径**：故事 → 分镜 → 生成 → 后期 → 导出。专业能力收进"进阶"。
- 时间线基于 **OTIO** 数据模型；预览用 **WebCodecs + WebGPU**。
- 项目状态以 Project IR 为准，客户端只是它的一个视图（见 [DATA-MODEL.md](DATA-MODEL.md)）。

### 2. 应用服务
- 项目文档 CRUD、版本、权限；资产上传与转码；任务提交；发布包生成。
- **不直接调用模型供应商**，一律提交给编排层。

### 3. 编排层
- 生成是长任务（数十秒到数分钟）：需要持久化、自动重试、幂等、超时、预算拦截。
- 典型工作流：`关键帧 → Animatic 确认 → 视频 → QA → 重试 → 入库`。
- **Phase 1：pg-boss + 显式状态机**（Postgres 内事务入队，运维最轻）；**Phase 2** 视复杂度评估 Temporal / Restate（ADR-0010）。
- 所有任务经统一的 `JobRunner` 接口提交，保留替换空间。

### 4. 模型网关
- 统一抽象：`submit(job) / poll(job) / webhook / cancel / estimateCost`。
- 适配器：seedance、可灵、Veo、海螺、Wan、TTS、音乐、ASR 等（以实际可用为准）。
- 能力：路由（按质量/成本/可用性）、降级、限流、计量、结果缓存。
- 业务代码只依赖网关接口（准则 P8）。

### 5. 媒体层
- **渲染**：服务端 ffmpeg 集群，接受 OTIO → 渲染为成片；GPU 节点做 LUT/转码/合成。
- **预览**：客户端实时预览（低分辨率），定稿才走渲染农场。
- **存储**：S3 兼容；国内选阿里云 OSS / 腾讯云 COS。

### 6. 数据层
- Postgres：项目元数据、任务、账务、发布记录。
- Redis：队列、缓存、限流。
- 对象存储：所有媒体资产，带 provenance。

## 三、生成管线（核心）

```
剧本/台词
   │
   ▼
[TTS 配音] ──► 对白音频 + 时长（音频先行，准则 P5）
   │
   ▼
分镜拆解（景别/机位/运镜/时长）
   │
   ▼
关键帧生成（首帧/尾帧，图生图，锁定角色与构图）
   │
   ▼
【Animatic 预演】关键帧 + 对白 + 临时音乐 + 字幕，540p 快速渲染
   │
   ├─ 未确认 → 回到剧本/分镜
   └─ 确认 → 锁定分镜、时长与资产（闸门 2）
   │
   ▼
图生视频（短镜头/分段，首尾帧约束，多模型，多 Take）
   │
   ▼
连续性 QA（视觉模型 + 人脸 embedding 比对 Story Bible 与相邻镜头）
   │
   ├─ 通过 → 入库
   └─ 不通过 → 自动重试（改 seed / 改提示词 / 换模型）→ 超预算转人工
   │
   ▼
自动初剪（OTIO 时间线）→ 配乐卡点 → 混音 → 字幕 → 渲染 → 发布包
```

## 四、一致性体系（产品护城河）

1. **角色档案**：多角度参考图、表情、服装，作为每镜的参考图输入。
2. **场景 / 道具档案**：同构管理，避免"同一间屋子每镜都不同"。
3. **seed 锁定**：同一角色/场景在允许范围内复用 seed。
4. **首尾帧约束**：上一镜尾帧可作为下一镜首帧参考（同场景连续）。
5. **监工 Agent**：抽帧 + 视觉模型打分，输出"哪里不一致"，驱动重试。
6. **人工覆盖**：监工建议不自动覆盖用户已确认的 Take（准则 P7）。
7. **走位/轴线台账**：`SceneState` 记录谁在左/中/右、朝向、服装、道具、屏幕方向，跨镜比对。
8. **量化判定**：人脸 embedding 相似度（ArcFace 类）+ VLM 检查清单，阈值可调，避免"凭感觉"。 

## 五、技术栈建议（待定稿，非决策）

| 层 | 建议 | 理由 |
| --- | --- | --- |
| 前端 | Next.js + React + TypeScript | 生态、招聘、单人开发效率 |
| 时间线/预览 | WebCodecs + WebGPU（Canvas/PixiJS） | 浏览器内实时预览，免装客户端 |
| 状态 | Zustand；后期 Yjs | 先简单，协作时不重构 |
| 后端 | TypeScript（Fastify/NestJS）或 Go | 与前端同语言降低切换成本 |
| ML 编排 | Python 子服务 | TTS/口型/视觉 QA 生态在 Python |
| 工作流 | Phase 1：pg-boss + 显式状态机；Phase 2：评估 Temporal/Restate | 单人运维优先，保留升级路径（ADR-0010） |
| 数据库 | Postgres + Redis | 通用、托管成熟 |
| 存储 | S3 兼容（OSS/COS） | 国内合规与延迟 |
| 渲染 | ffmpeg + GPU 节点 | 成熟、可控 |
| 时间线交换 | OpenTimelineIO | 与达芬奇/Premiere/MLT 互通 |
| 部署 | 国内云，完成 ICP 与生成式 AI 备案 | 合规前置 |

> 技术栈选择一旦定稿，补一条 ADR。原则：**单人可维护 > 极致性能**。

## 六、关键设计取舍

| 取舍 | 选择 | 理由 |
| --- | --- | --- |
| 自研 NLE vs 组合 | 组合（OTIO + WebCodecs + ffmpeg） | 自研 NLE 是数人年投入，且难超剪映（ADR-0004） |
| 客户端渲染 vs 服务端 | 预览在端、定稿在云 | 端侧实时性 + 云端一致性 |
| 单体 vs 微服务 | 模块化单体起步 | 单人开发，运维成本优先 |
| 同步 vs 异步 | 生成全异步 | 模型延迟不可控 |
| 自建推理 vs API | 先 API | 预算充足，先验证产品 |

## 八、本轮新增设计

### 1. Animatic 预演（ADR-0009）
关键帧 + 对白 + 临时音乐 + 字幕，540p 快速渲染。**视频生成前的强制闸门**，同时是产品功能。

### 2. 短镜头与分段（ADR-0012）
单镜默认 2–5 秒；超模型上限的镜头拆 `GenerationSegment`，用尾帧接首帧，且限制段数。

### 3. 连续性台账（SceneState）
跨镜记录位置、朝向、服装、道具、轴线，作为 QA 与提示词的共同输入。

### 4. 语义编辑（F7）
用户自然语言 → LLM 映射为 `CameraSpec` / `LightingSpec` patch → 重新编译提示词 → 预览确认。
这是 C 端可用性的关键：**不要求用户学摄影术语，但参数要真实生效**。

### 5. 预算护栏（H10）
项目/单镜金额上限、最大重试次数、超限降级路径。没有它，重试是无底洞。

### 6. 能力矩阵（B12 / H11）
每个模型的时长、分辨率、首尾帧、参考图、运镜、并发、延迟、单价、**商用条款**。它直接决定网关路由与降级链，是 S1 能力测绘的产出。

### 7. 工作流引擎的分阶段（ADR-0010）
Phase 1 用 pg-boss + 状态机；Phase 2 再评估 Temporal / Restate。
