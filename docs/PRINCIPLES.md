# 准则（Principles / 不变量）

> 这些是项目的**不变量**。功能即使好用，违背准则也不做；确需改变，先开 ADR。
> 编号稳定，不重排、不删除；废弃的条目标注「已废弃」，保留原因。

---

## P1 产品是「短剧生产线」，不是通用 AI 视频工具

任何功能都要过同一道检验：**它是否让"从故事到可发布短剧"更快、更稳、更一致？**

- 违反的表现：功能越做越像 Runway / Pika / 通用文生视频工作台。
- 判断口诀：**竞品是"编剧 + 分镜师 + 剪辑 + 配音"的人力，不是剪辑软件。**

## P2 一份结构化项目文档是唯一事实来源

Project IR（见 [DATA-MODEL.md](DATA-MODEL.md)）是唯一真相。画面、音频、字幕、发布包都是它的**派生物**，不是各自独立存储的成品。

- 违反的表现：项目目录里散落着无来源信息的 mp4；某功能绕过 IR 直接改文件。

## P3 一致性优先于单帧画质

宁可 720p 但角色、服装、光线、道具、空间关系前后一致，也不要 4K 但穿帮。

- 短剧最致命的失败不是画质，是**观众看出"不是同一个人/同一个地方"**。
- 违反的表现：为了追求单帧精美而放弃参考图约束、放弃连续性检查。

## P4 先图后视频（Keyframe-first）

默认路径：**关键帧（首帧/尾帧）→ 图生视频**。纯文生视频只作为补充。

- 理由：图比视频可控一个数量级；角色一致性和构图应在廉价的 image 阶段锁定。
- 违反的表现：默认直接文生视频，然后反复抽卡。

## P5 音频先行（Audio-first）

对白 TTS 先生成，**镜头时长服从音频**；不做事后硬对齐嘴型。

- 顺序：台词 → 配音时长 → 镜头时长/节奏 → 画面生成 → 口型微调。
- 违反的表现：先出画面再配音，靠变速/裁剪硬凑。

## P6 默认 AI 初稿，人只做「改」

每个环节默认给出可用结果，用户从"改"开始，而不是从"空白"开始。

- 适用于：剧本、分镜、画面、配音、配乐、字幕、初剪。
- 违反的表现：把"专业工具"直接丢给 C 端用户，要求他会调参数。

## P7 非破坏 + 可覆盖 + 可回滚

- 每个环节都有 **AI 结果层** 与 **人工覆盖层**；人工覆盖后不被自动流程冲掉。
- 每个镜头保留多个 **Take**，记录 provenance（模型、seed、提示词、参考图）。
- 违反的表现：重新生成即覆盖旧版本；自动流程把用户改过的字幕又冲掉。

## P8 模型无关（Model-agnostic）

业务逻辑不绑定任何单一模型供应商；模型一律通过网关接入，可替换、可降级、可灰度。

- 理由：模型三个月换一茬，绑定即负债。
- 违反的表现：业务代码里直接写某家 SDK 的请求结构。

## P9 合规与标识内建

AI 生成内容标识、内容安全审核、授权与肖像记录是**默认能力**，不是事后补丁。

- 详见 [RISKS.md](RISKS.md)。国内面向公众提供服务，合规是上线前置条件。

## P10 C 端单人、零学习成本

主路径不需要教程；专业能力收进"进阶"，不挡主流程。

- 验收视角：**一个没做过视频的人，30 分钟内能出片。**
- 违反的表现：首屏就是时间线、参数面板、节点图。

## P11 摄影语言必须可量化

光比、色温、焦段、景别、机位、运镜、构图、LUT 都要能落到**参数**，并由参数编译为提示词；不能只停留在形容词。

- 意义：这是《织光机》名字的承诺，也是与通用工具的差异化。
- 不要求专业级精度，但要求**可复现、可解释、可学习**。

## P12 讨论留痕，文档先于代码

任何准则 / 架构 / 功能变更：**先更新 docs，再动实现**。每次讨论在 [DISCUSSIONS.md](DISCUSSIONS.md) 留一条。

- 违反的表现：口头定了方案，下次讨论时没人记得为什么。

## P13 短镜头与覆盖率优先

分镜默认按"为剪辑而写"：**单镜 2–5 秒**，长场景拆成 master / 过肩 / 特写 / 反应镜头，靠剪辑叙事，不写长镜头。

- 理由：视频模型的稳定时长有限，长镜头必然漂移；短剧本身就是快切节奏。
- 详见 ADR-0012。违反的表现：分镜里出现大量 >10 秒的连续镜头。

## P14 阶段闸门与预算护栏

在昂贵的步骤之前设**闸门**（资产确认、Animatic 确认、镜头验收、成片确认）；每个项目与镜头都有**金额上限与重试上限**，超限降级或转人工。

- 理由：越往后改越贵；没有护栏的重试是无底洞。
- 详见 ADR-0009。违反的表现：无预算上限地反复重试；跳过确认直接进入下一阶段。

## P15 分镜是约束求解，不是自由生成

剧本→分镜必须是 **LLM 创意选择 + 规则引擎合法性校验**：轴线、时长、覆盖率、模型能力、预算都是硬约束。

- 理由：好分镜的标准不是"写得漂亮"，而是"拍得出来、接得起来、花得起"。
- 详见 ADR-0015。违反的表现：一次 LLM 调用直接产出一串镜头，不做校验。

## P16 故事是一等公民，不是提示词的附属

项目必须从**经过评分的前提/Logline** 开始，而不是从一句提示词开始。故事层是结构化的（Premise / Logline / Beat / 人物弧光 / 钩子 / 剧本医生报告），可诊断、可评分、可定向改写。

- 理由：生成能力会商品化，故事是唯一可持续的差异化；LLM 擅长"合格但平庸"，必须用结构保证下限、用人的品味抬高上限。
- 违反的表现：跳过前提与 Logline 评分，直接让用户写提示词生成；剧本质检只看"有没有错别字"。
- 详见 [STORY.md](STORY.md)。关联 ADR-0017。

## P17 规则自动发现，但受控晋升

导演语法库可以自动从数据中**发现候选规则**，但 **must 级规则必须人工确认**才能上线；所有晋升必须过评测门槛（A/B、成本、回归）。

- 理由：没有门槛的自动补充必然导致规则膨胀、风格趋同、互相冲突；规则库是产品资产，不是自我漂移的黑盒。
- 违反的表现：模型/统计直接改写全局 must 规则；规则数量无上限增长；无法追溯到证据与评审人。
- 详见 [RULE-EVOLUTION.md](RULE-EVOLUTION.md)。关联 ADR-0018。

## P18 表演是镜头的目的，运镜是手段

每个镜头必须先回答"观众要看到什么表演变化"（一个 objective、一个情绪转折），再决定景别、机位、运镜。没有表演变化的镜头（除空镜/转场）不应存在。

- 理由：观众记住的是脸和选择，不是运镜；先定表演再定镜头，才能避免"为运镜而运镜"。
- 详见 [PERFORMANCE.md](PERFORMANCE.md)。关联 ADR-0019。

## P19 对白是声音的主角

声音分四层（对白 / 音乐 / 音效 / 环境）；混音的第一优先级是**台词清晰**，音乐与音效必须让路。配音按表演处理，不按朗读处理。

- 理由：短剧在手机外放、嘈杂、可能静音的环境下播放；听不清台词，情绪设计全部失效。
- 详见 [SOUND.md](SOUND.md)。关联 ADR-0020。

## P20 发布以导出为底线，不做逆向

发布能力分三层（导出包 / 官方 API / 移动端分享），**L1 导出必须永远可用且自包含**；禁止逆向登录、模拟点击、绕过审核。

- 理由：平台 API 与规则会变，导出不依赖任何平台；逆向的短期收益换不来长期风险。
- 详见 [PUBLISHING.md](PUBLISHING.md)。关联 ADR-0021。

## P21 成本是设计参数，不是事后核算

任何功能在设计时必须给出**成本影响估计**（每项目/每镜头/每档位）；无法估价的方案不进入实现。贵步骤之前必须有闸门，确认之前只能用 draft 档。

- 理由：单条成本决定产品能否成立；成本不可见的系统一定会在规模上亏钱。
- 详见 [COST.md](COST.md)。关联 ADR-0022。

## P22 界面按任务组织，不按工具组织

默认路径是一条**阶段向导**，不是一块画布；时间线、参数、提示词都是第二层，渐进披露，不得挡在主路径上。

- 理由：C 端用户的目标是"出一条片"，不是"使用剪辑软件"；按工具组织会让首屏认知负荷爆炸（违反 P10）。
- 详见 [UX.md](UX.md)。关联 ADR-0023。
