# 成本与单位经济

> 核心判断：**成本不是"单价便宜点"的问题，是"废片率"的问题。**
> 单位经济 = （生成成本 + 重试成本）÷ 通过率 + 固定开销。分子好降，分母才是命门。

---

## 一、先看钱花在哪

一条 60 秒竖屏短剧，成本结构大致是这样：

| 项 | 量级占比 | 说明 |
| --- | --- | --- |
| **视频生成** | **60–80%** | 按秒计费，重试直接翻倍 |
| 关键帧（图） | 10–20% | 每镜 1–3 张，含重试 |
| 语音 TTS | 1–3% | 便宜，但不是零 |
| 音乐 | 2–5% | 按条或按时长 |
| LLM（剧本/分镜/QA） | 1–3% | 便宜 |
| 渲染/存储/带宽 | 1–3% | 相对固定 |
| 内容审核 | 1–2% | 按次数 |

**结论：控制成本 = 控制视频秒数 × 控制重试率。** 其他都是零头。

---

## 二、三个公式

### 单镜成本

```
C_shot = n_keyframe × C_img + n_segment × dur × C_video + C_qa
```

### 项目成本（含重试）

```
C_project = Σ_shots [ C_shot × (1 + retry_rate) ] + C_audio + C_music + C_misc
```

### 有效成本（真正要看的数）

```
C_effective = C_project / 通过镜数
```

`C_effective` 才是单位经济里该用的数。**一条片生成 10 次有 8 次废掉，便宜单价也没意义。**

## 三、基准情景（假设值，需 S1 能力测绘标定）

以 60 秒、25 个镜头、每镜 2–3 秒、双角色对话为例：

| 情景 | 分辨率 | 通过率 | 估算成本/条 |
| --- | --- | --- | --- |
| 乐观 | 720p | 60% | 100–150 元 |
| 中性 | 1080p | 40% | 250–400 元 |
| 悲观 | 1080p | 25% | 600–900 元 |

> 数字是**量级**不是报价；模型单价、通过率都必须在 S1 用真实样片标定。所有价格进 `ModelPrice` 表，不写死在代码里。

### 2026-11-09 首次实测（部分标定）

价目来自中转站 `GET /v1/models` 的公开报价，见 [`MODEL-GATEWAY.md`](MODEL-GATEWAY.md)。按 `minimax-h3 @ 768p` + `gpt-image-2-c`：

| 项 | 实测单价 | 原假设 |
| --- | --- | --- |
| 关键帧 | ¥0.12 / 张 | ¥0.3 / 张 |
| 视频 768p | ¥0.5 / 秒 | ¥1.5 / 秒 |
| 一个 4 秒镜头（一次过） | ¥2.12 | ¥3.9 |
| 一个 4 秒镜头（重做 4 次） | ¥8.48 | — |

前端的重做报价直接读同一张表（`packages/gateway/src/pricing.ts`，经 `@loomina/gateway/pricing` 子路径引入），
按「当前镜头时长 × 每秒单价 + 一张首帧」换算，不复制价目、不在界面里写死（不变量 39）。

**结论要反过来读**：单价低于假设，说明**成本瓶颈在重做次数，不在单价**。
把通过率从 40% 提到 60%，省下的钱比重选一个便宜模型多得多 —— 这正是「一致性系统就是成本系统」的量化版本。

通过率与失败维度尚未实测（测绘时配额 429，见 `MODEL-GATEWAY.md`），所以上表只标定了分子，分母仍是假设。

### 为什么通过率差 2.5 倍，成本差 6 倍

因为重试是乘法：通过率 40% → 平均生成 2.5 次；25% → 4 次。而每次重试不只是一段视频，还有关键帧、QA、人工确认的时间。

**这就是为什么一致性系统（CONSISTENCY.md）本质上是成本系统。**

## 四、成本杠杆（按 ROI 排序）

| # | 杠杆 | 作用 | 量级 |
| --- | --- | --- | --- |
| 1 | **Animatic 闸门** | 在便宜阶段淘汰坏方案 | 省掉整条废片 |
| 2 | **关键帧先行** | 图比视频便宜 10–50 倍 | 大幅降低试错成本 |
| 3 | **提高通过率** | 一致性锚定、能力匹配 | 直接降分母 |
| 4 | **草稿/定稿双档** | 草稿 540p/720p，定稿才 1080p | 草稿成本降 50–70% |
| 5 | **短镜头** | 避免长镜漂移导致的整段重试 | 见下方注意 |
| 6 | **模型路由** | 草稿用便宜模型，定稿用贵的 | 30–60% |
| 7 | **缓存与复用** | 场景/角色/镜头模板复用 | 10–30% |
| 8 | **预算护栏** | 防止单镜无底洞 | 止损 |

### 关于短镜头的成本注意

短镜头**不减少视频总秒数**（总时长不变），还会**增加关键帧数量**（每镜都要首帧）。

它省钱的地方在别处：**长镜头漂移会导致整段重来，短镜头失败只重来 2–3 秒。**

所以判断标准是：`减少的重试成本 > 增加的关键帧成本`。以现在的图像价格，通常是成立的；如果某天图像涨价，要重新算。

## 五、双档渲染

不要把"预览"和"成片"用同一档成本做：

| 档 | 分辨率 | 用途 | 成本 |
| --- | --- | --- | --- |
| **draft** | 540p / 720p，低码率 | 分镜预览、Animatic、内部 QA | 低 |
| **final** | 1080p（必要时 2K），高码率 | 成片、发布 | 高 |

规则：**任何确认动作之前，只能用 draft。** 用户点了"确认"，才允许 final。

这一条能省掉大量"生成了 1080p 才发现构图不对"的浪费。

---

## 六、重试经济学：什么时候该停

重试的边际收益是递减的，而且很快：

```
质量
 ▲
 │        ╭───────  平台期
 │      ╭─╯
 │    ╭─╯
 │  ╭─╯
 └──┴──┴──┴──┴──▶ 重试次数
    1  2  3  4  5
```

停止条件（满足任一）：

- 达到该镜预算上限；
- 达到重试次数上限（建议 3–5 次）；
- 最近一次质量提升 < 阈值（如一致性分 +0.03）；
- QA 连续两次同一维度失败（说明是设计问题，不是运气）。

**同一维度连续失败，应该回去改设计（换机位/拆镜/改首帧），而不是继续抽卡。** 这是最容易烧钱的地方。

## 七、单位经济

### 收入侧的现实

如果一条 60 秒成本 300 元，而 C 端用户愿付 9.9–29.9 元，**毛利是负的**。这是必须直面的问题（R13 / R23）。

三条出路，缺一不可：

1. **把成本压到几十元级**（通过率 + 双档 + 缓存 + 模型降价）；
2. **提高单用户产出**（一个用户做多条，摊薄固定成本）；
3. **改变计价方式**（不是"一条 9.9"，而是按资源消耗计点）。

### 计价建议：点数制

把成本映射成点数，用户买点数，消耗与真实成本挂钩：

| 动作 | 点数（示意） |
| --- | --- |
| 剧本 + 分镜 | 1 |
| 关键帧（每张） | 1 |
| 视频草稿（每秒） | 2 |
| 视频定稿（每秒） | 6 |
| 重新生成 | 同价 |
| Animatic 渲染 | 3 |

好处：成本透明、重试有感知、定价可随模型价格调整。

坏处：用户要理解点数。所以**默认套餐要覆盖"一条完整片"**，点数只在超量时出现。

### 关键指标

| 指标 | 目标方向 |
| --- | --- |
| 单条有效成本 | 越低越好 |
| 首次通过率 | 越高越好（目标 ≥50%，见 PRODUCT.md） |
| 单用户月产出条数 | 越高越好（摊薄） |
| 毛利率 | > 50%（长期） |
| 重试成本占比 | < 40% |

## 八、成本观测与护栏

- **按项目/镜头/模型/档位记账**（H4），每一笔都能归因。
- **生成前估算**：提交任务前给出预计消耗，超预算需确认。
- **异常告警**：单项目成本超均值 3 倍、单镜重试 > 5 次、某模型失败率突增。
- **价格表版本化**：模型调价不改进代码，改 `ModelPrice`。
- **预算护栏**（H10）：项目级 + 镜头级双层上限，超限阻断或降级。

---

## 九、失败模式

| 失败 | 表现 | 原因 | 对策 |
| --- | --- | --- | --- |
| 重试无底洞 | 单镜几十次 | 没有上限/没诊断 | 预算护栏 + 连续失败回设计 |
| 高分辨率草稿 | 预览就烧钱 | 未分档 | draft/final 双档 |
| 长镜漂移 | 整段重来 | 超模型能力 | 拆段 |
| 缓存缺失 | 同场景反复生成 | 无复用 | 场景/角色缓存 |
| 单价写死 | 模型降价没享受到 | 硬编码 | ModelPrice 表 |
| 成本不可见 | 月底才发现亏 | 无归因 | 逐笔记账 |
| 定价脱离成本 | 卖得越多亏得越多 | 按条定价 | 点数制 |

## 十、IR 映射

```ts
interface ModelPrice {
  modelId: string;
  unit: "image" | "video-second" | "tts-char" | "llm-token" | "music-track";
  priceCny: number;
  tier: "draft" | "final";
  effectiveFrom: ISODate;
}

interface CostEstimate {
  projectId: ID;
  shots: { shotId: ID; estimatedCny: number; basis: string }[];
  audioCny: number;
  totalCny: number;
  confidence: "low" | "medium" | "high";
}

interface CostLedger {
  id: ID;
  projectId: ID;
  shotId?: ID;
  modelId: string;
  tier: "draft" | "final";
  units: number;
  cny: number;
  at: ISODate;
}
```

**新增不变量**

36. **每次生成必须写入 `CostLedger`**，无记账的任务不得提交。
37. **超过项目或镜头预算上限时不得提交新任务**；降级路径必须显式记录。
38. **确认动作之前的渲染必须是 draft 档**，不得直接 final。
39. **模型单价只能来自 `ModelPrice` 表**，不得在业务代码中硬编码。
40. **同一镜头连续两次在同一 QA 维度失败时，禁止继续重试**，必须回到设计层修改。

---

## 十一、一句话

**单位经济不是"把单价谈便宜"，是"把废片率压下去"。**
每提升 1% 的首次通过率，都是毛利；每一次无诊断的重试，都是在给模型厂商交学费。
