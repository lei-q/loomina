# 平台运转模型：闭环、闸门与难点

> 本文回答四个问题：平台怎么跑、哪里不闭环、哪里有阻塞、难点在哪。
> 与 [ARCHITECTURE.md](ARCHITECTURE.md) 的区别：那边讲"系统怎么搭"，这边讲"业务怎么转"。

---

## 一、端到端运转（不是流水线，是带闸门的循环）

```
① 想法/小说/模板
      │
      ▼
② 故事：logline → 分集 → 场 → 镜 → 台词
      │
      ▼
③ 选角与美术：角色定妆、声音试镜、场景/道具参考
      │
   【闸门 1：资产确认并锁定】
      │
      ▼
④ 声音：TTS 对白 → 精确时长（音频先行）
      │
      ▼
⑤ 分镜与关键帧：镜头表 + 首帧/尾帧
      │
   【闸门 2：Animatic 确认】  ← 全流程最关键的省钱闸门
      │
      ▼
⑥ 视频生成：分段 + 多 Take + 自动 QA + 重试
      │
   【闸门 3：镜头验收】
      │
      ▼
⑦ 后期：自动初剪 → 人工微调 → 配乐/混音/字幕/调色
      │
   【闸门 4：成片确认】
      │
      ▼
⑧ 渲染 → 发布包 → 分享/发布
      │
      └──► 反馈（播放/完播）回到 ②，用于下一集
```

### 各阶段的输入 / 输出 / 闸门

| 阶段 | 输入 | 输出 | 人工动作 | 闸门 |
| --- | --- | --- | --- | --- |
| ② 故事 | 想法、小说片段、模板 | 结构化剧本（IR） | 改台词、调结构 | — |
| ③ 选角美术 | 剧本中的角色/场景/道具 | 定妆图、声音样本、场景参考 | 选角、定妆、试听 | 闸门 1 |
| ④ 声音 | 台词 | 对白音频 + 时长 | 逐句重录/调情绪 | — |
| ⑤ 分镜关键帧 | 剧本 + 音频时长 + 摄影参数 | 镜头表、首尾帧 | 调机位/构图 | — |
| ⑤b Animatic | 关键帧 + 对白 + 临时音乐 + 字幕 | 低分辨率动态分镜 | 看节奏、改结构 | 闸门 2 |
| ⑥ 视频 | 关键帧 + 时长 + 提示词 | 多 Take 视频 | 选 Take、局部重做 | 闸门 3 |
| ⑦ 后期 | 已验收 Take + 音频 | 时间线 | 剪辑、混音、字幕 | — |
| ⑧ 发布 | 成片 | 发布包 | 选平台、发布 | 闸门 4 |

### 为什么必须是"闸门"而不是"线性"

每一道闸门都做两件事：**确认 + 锁定**。

- 闸门 1 锁定角色/场景资产：后面所有镜头引用同一套图，不允许悄悄漂移。
- 闸门 2 锁定分镜与时长：在花视频钱之前，确认故事和节奏成立。
- 闸门 3 锁定 Take：已验收的镜头不被自动流程覆盖。
- 闸门 4 锁定成片：发布包只从已确认版本生成。

没有闸门，系统就会"越往后改越贵"——这是短剧生产最典型的浪费。

## 二、不闭环的环节（按严重程度）

| 编号 | 不闭环 | 后果 | 建议的闭环方式 | 状态 |
| --- | --- | --- | --- | --- |
| L1 | 剧本 → 分镜的质量没有验收标准 | 花了视频钱才发现节奏不对 | **Animatic 闸门**（关键帧+配音+临时音乐+字幕，低成本预演） | 方案已定（ADR-0009） |
| L2 | 角色/场景资产没有确认点 | 角色定妆后仍被后续生成带偏 | 闸门 1 + 资产锁定 + 引用计数 | 待设计 |
| L3 | 场景空间没有模型 | 同一场景不同机位地理关系错乱 | 场景主镜 + 走位/轴线台账（ContinuityLedger） | 待设计 |
| L4 | 单镜时长 vs 模型时长上限 | 长对白镜头无法一次生成，拼接漂移 | 短镜头/覆盖率优先 + 分段生成（首尾帧衔接） | 方案已定（ADR-0012） |
| L5 | 用户意图 → 参数 | 用户说"再压抑一点"，系统不知道改什么 | 语义编辑：LLM 把自然语言映射为 Camera/Lighting patch | 待设计（F7） |
| L6 | 重试没有终止条件 | 无限重试烧钱 | 预算护栏：单镜次数上限、项目预算、降级素材 | 待设计（H10） |
| L7 | 音画冲突没有裁决规则 | 台词太长，是删词还是加镜头？ | 每镜声明策略：`dialogue-first` / `visual-first` | 待设计 |
| L8 | 预览 ≠ 成片 | 用户看到的效果和导出不一样，失去信任 | 代理分辨率 + 统一色彩管理 + 定稿以服务端为准 | 待设计 |
| L9 | 素材/音乐版权链 | 商用风险 | 只用授权素材库；记录 provenance | 待设计 |
| L10 | 市场反馈没有回流 | 不知道什么内容有效 | 发布记录 + 数据回流（P2，暂缓） | 暂缓 |

### 最值钱的一个补丁：Animatic

传统影视叫 **animatic / previs**：用分镜图 + 配音 + 临时音乐剪成动态分镜，在实拍前确认节奏。

对 AI 短剧，它的价值被放大：

- 成本约为视频生成的 **1/20–1/50**；
- 能在 10 分钟内暴露"故事不成立、节奏拖、台词过长"；
- 本身就是产品功能：用户先看"动态分镜"，确认后再"渲染成片"。

**没有 Animatic，你的产品就是"先花大钱，再看对不对"。** 这是我认为当前设计里最重要的缺口。

## 三、真正的阻塞点

### 硬阻塞（会让产品不成立）

| 编号 | 阻塞 | 为什么会阻塞 | 可能的解法 | 剩余风险 |
| --- | --- | --- | --- | --- |
| H1 | 跨镜头角色一致性达不到"可看"阈值 | 观众一眼看出不是同一个人，故事就不成立 | 关键帧优先 + 角色档案 + 参考图 + 固定 seed + 人脸 embedding QA + 限制同场人数 | 模型能力上限，需持续跟进 |
| H2 | 单位成本不可控 | 重试 × 视频单价，单条成本可能远超用户付费意愿 | 草稿/定稿两档、缓存、预算护栏、短镜头、Animatic 前置 | 视频单价下降前，毛利很薄 |
| H3 | 单人 scope 失控 | 功能面太宽，做不完、维护不动 | 严格 non-goals、模块化单体、托管优先、文档留痕 | 最现实的阻塞 |

> H1 是技术阻塞，H2 是商业阻塞，H3 是执行阻塞。三者必须同时成立，产品才成立。

### 软阻塞（会拖慢，但有解）

- **模型时长上限**：用短镜头 + 分段生成解决（ADR-0012）。
- **场景空间连续性**：用场景主镜 + 走位台账缓解，无法完全消除。
- **自动剪辑的"审美"**：先用规则 + 人工覆盖，不追求全自动。
- **发布资质**：用分享扩展兜底（ADR-0006）。

### 伪阻塞（看起来难，其实成熟）

- 配音（TTS 已足够好）
- 字幕（ASR + 强制对齐成熟）
- 混音/响度（FFmpeg 成熟）
- 视频合成（FFmpeg 成熟）

## 四、业务难点

| 编号 | 难点 | 说明 | 应对方向 |
| --- | --- | --- | --- |
| B1 | 成本 vs 付费意愿 | C 端个人创作者对价格敏感；视频生成是重成本 | 先记录单位成本；模板化降低重试；按分钟计费或订阅待定 |
| B2 | 同质化 | 大厂（剪映/即梦）可能覆盖"生成+剪辑" | 护城河放在一致性、短剧语法、Animatic 工作流与模板资产 |
| B3 | 冷启动 | 用户不知道能做什么、做出来好不好 | 模板剧本、样例成片、一键复刻 |
| B4 | 留存 | 工具型产品用完即走 | 连载/角色 IP/系列项目，让用户"回来做下一集" |
| B5 | 版权与商用授权 | 小说改编、模型输出商用条款、音乐/字体授权 | 只用授权素材；逐个模型确认商用条款 |
| B6 | 审核成本 | 生成内容需审核，误杀影响体验 | 双检 + 申诉 + 分级 |
| B7 | 分发依赖 | 平台算法决定流量 | 多平台发布包；不绑定单一平台 |
| B8 | 单人产能 | 开发、运营、客服、内容全是一个人 | 范围克制，先做透一条线 |

## 五、技术难点（按难度排序）

| 排名 | 难点 | 难点在哪 | 现有手段 | 我们的策略 | 剩余风险 |
| --- | --- | --- | --- | --- | --- |
| T1 | 跨镜头一致性 | 模型每次生成都会"重新想象"人物 | 参考图、IP-Adapter/LoRA、seed、首尾帧 | 关键帧优先 + 角色档案 + 人脸 embedding 相似度 QA + 人工兜底 | 高 |
| T2 | 可控性（运镜/表演/情绪） | 视频模型对运镜和微表情的控制粗 | 部分模型支持运镜参数；关键帧控制表情 | 摄影参数编译 + 首尾帧约束 + 用剪辑代替长表演 | 中高 |
| T3 | 叙事连贯与节奏 | 单镜好不代表整片好 | Animatic、节拍分析 | Animatic 闸门 + 短镜头覆盖率 + 自动初剪 | 中 |
| T4 | 音画同步 | TTS 时长、口型、停顿 | 强制对齐、口型模型 | 音频先行 + 逐词对齐 + 特写才做口型 | 中 |
| T5 | 自动剪辑审美 | "什么时候切"是审美判断 | 节拍检测、规则引擎、LLM 规划 | 规则优先 + 可覆盖，不追求全自动 | 中 |
| T6 | 实时预览性能 | 多轨 1080p 解码 + 合成，浏览器内存/解码压力大 | WebCodecs、WebGPU、代理视频 | 540p 代理 + 可视窗口解码 + 定稿上云 | 中 |
| T7 | 长任务编排与成本 | 生成异步、易失败、需幂等与预算 | 工作流引擎、队列、幂等键 | 状态机 + 预算护栏 + 缓存 | 中 |
| T8 | 提示词编译 | 结构化参数 → 不同模型方言，效果不可预期 | 模板、golden test、A/B | 编译器具名化 + 版本化 + 样例对照库 | 中 |
| T9 | 模型能力差异 | 各家的时长/分辨率/首尾帧/运镜能力不同 | 能力矩阵 | 网关抽象 + 能力探测 + 降级链 | 低中 |
| T10 | 预览与成片一致 | 色彩、缩放、编码差异 | 统一色彩管理、LUT | Rec.709 工作流 + 代理仅用于预览 | 低中 |

## 六、关键设计补充（由本轮讨论新增）

### 1. 短镜头与覆盖率（ADR-0012）

视频模型通常只能稳定生成 5–10 秒。**不要写长镜头，要为剪辑而写。**

- 默认单镜 2–5 秒；
- 长场景拆成 master / over-the-shoulder / close-up 等多镜；
- 超过模型上限的镜头，拆成多个 segment，用上一段尾帧作为下一段首帧（谨慎使用，会累积漂移）。

这同时改善节奏：短剧本来就是快切。

### 2. 场景空间与连续性台账

每场维护一份 `ContinuityLedger`：谁在画面左/中/右、面向哪边、穿什么、拿什么、轴线在哪。

- 每生成一镜，与台账比对；
- 台账由剧本 + 分镜自动生成，人工可改；
- 这是"场景空间板"的数据基础。

### 3. 语义编辑

用户不说参数，说人话：

```
"这个镜头再压抑一点，别太亮"
  → LLM 映射 → { keyRatio: 8, colorTempK: 4300, mood: "压抑" }
  → 生成新提示词 → 预览 → 用户确认
```

这是 C 端可用性的关键：**不要让用户学摄影术语，但要让摄影参数真实生效。**

### 4. 预算护栏

每个项目、每个镜头都有：

- 金额上限；
- 最大重试次数；
- 超限后的降级路径（换便宜模型 / 用已有素材 / 空镜 / 转人工）。

没有护栏，重试就是无底洞。

### 5. 能力矩阵

上线前必须测绘每个模型：最大时长、分辨率、首尾帧、参考图、运镜控制、并发、延迟、失败率、**商用条款**、单价。

这份矩阵不是文档摆设，它直接决定网关的路由与降级链。
