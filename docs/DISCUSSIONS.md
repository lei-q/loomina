## 2026-11-09 定位与架构首次讨论

**参与者**：用户 + Claude

**议题**
1. 产品定位：通用 AI 视频工具 vs 短剧生产线
2. 生成管线：文生视频 vs 先图后视频
3. 后期顺序：画面先行 vs 音频先行
4. 剪辑工具：自研 NLE vs 组合开源
5. 发布：一键发布 / 扫码登录是否可行
6. 故事层与摄影语言如何产品化
7. 用户与市场：C 端、国内首发
8. 文档留痕机制

**确认的结论**
- 产品是**短剧生产线**，面向 **C 端**，国内首发、竖屏 60–180 秒。
- 单人开发，模型 API 预算充足，无短剧行业与 IP 资源。
- 商业模式暂不设定，先打磨产品。
- 采用**先图后视频**、**音频先行**、**多 Take + 非破坏**、**模型无关网关**。
- 剪辑采用 **OTIO + WebCodecs/WebGPU + ffmpeg**，不自研 NLE。
- 发布采用**官方 API + 移动端分享扩展**，明确不做逆向自动化。
- 摄影语言做成**可量化参数系统**（可先做最小集），与短剧语法一起作为一等公民。
- 建立**文档先于代码**的记录机制。

**产物**
- 建立 `docs/` 全套文档与记录协议（[docs/README.md](README.md)）。
- 准则 P1–P12（[PRINCIPLES.md](PRINCIPLES.md)）。
- ADR-0001 ~ ADR-0008（[adr/](adr/)）。

**待定**
1. 首个可交付故事的题材与样例（需要具体剧本验证管线）。
2. 技术栈定稿（当前为建议，见 [ARCHITECTURE.md](ARCHITECTURE.md)）。
3. 移动端形态：PWA / 原生壳 / 独立 App。

## 2026-11-09 第二次讨论：运转、闭环、难点与选型

**参与者**：用户 + Claude

**议题**
1. 平台端到端如何运转
2. 哪些环节不闭环
3. 哪些是真正的阻塞
4. 业务难点与技术难点
5. 技术选型的标准与推荐栈
6. 如何一步一步落地

**确认的结论**
- 运转不是线性流水线，而是**带四道闸门的循环**：资产确认 → Animatic 确认 → 镜头验收 → 成片确认。
- 发现 10 个不闭环点，其中最重要的是 **L1（剧本→分镜无验收）**，用 **Animatic 闸门**解决。
- 三个硬阻塞：**一致性（技术）、成本（商业）、单人 scope（执行）**。
- 技术难点排序：一致性 > 可控性 > 叙事连贯 > 音画同步 > 自动剪辑审美 > 实时预览 > 编排/成本。
- 新增设计：短镜头/覆盖率（ADR-0012）、连续性台账（SceneState）、语义编辑（F7）、预算护栏（H10）、能力矩阵（B12）。
- 落地按**风险退休顺序**（S0 契约 → S1 能力测绘 → S2 Animatic → S3 单镜质量 → S4 前端 → S5 时间线 → S6 发布），**S0–S3 不写 UI**。
- 技术选型原则：单人可维护、托管优先、同语言、无聊技术、接口隔离、先单体。
- 工作流引擎改为**分阶段**：Phase 1 pg-boss + 状态机，Phase 2 评估 Temporal/Restate（ADR-0010）。
- IR 存储定为 **JSONB + 事件日志 + 快照**（ADR-0011）。

**产物**

- 新增 [TECH-SELECTION.md](TECH-SELECTION.md)（选型原则、栈、取舍、落地顺序）。

## 2026-11-09 第三次讨论：一致性与剧本→分镜

**参与者**：用户 + Claude

**议题**
1. 3D 场景板的形态
2. 跨镜头一致性如何解决
3. 剧本 → 分镜如何做

**确认的结论**
- **3D 场景板采用灰盒（gray-box previs）**：场景模板、胶囊人物、机位视锥、轴线检查、depth 导出；**自动优先，手动其次**。MVP 只做最小版（ADR-0013）。
- **一致性拆成 8 个维度**（身份/服化道/场景/光影/空间/表演/动作/风格），采用 **5 层防线**：资产锚定 → 结构锚定（3D+关键帧）→ 生成约束 → 量化验收 → 后期统一（ADR-0014）。
- **一致性要可度量**：人脸 embedding 余弦、VLM 清单、pHash、色温/直方图；分维度打分，阈值按景别分级。
- **明确一致性的天花板**：侧背、复杂花纹、儿童/老人、多人、长镜、极端角度；产品主动规避，不承诺"完全一致"。
- **分镜不是一次 LLM 调用，是约束求解**：LLM 负责创意选择，规则引擎负责合法性（轴线/时长/覆盖率/模型能力/预算）（ADR-0015）。
- 分镜管线定为 **7 步**：Beat 分析 → 覆盖率规划 → 3D 走位 → 机位/镜头 → 时长/节奏 → 台词分配 → 校验。
- 建立**导演语法库**（叙事意图 → 景别/机位/运镜/光 + 覆盖率模板 + 校验规则 V1–V10），作为产品 IP。

**产物**

- 新增 [STORYBOARD.md](STORYBOARD.md)（7 步管线、导演语法库、30 秒例子、失败模式）。
- ADR-0013（3D 灰盒 previs）、ADR-0014（多层一致性）、ADR-0015（分镜混合约束求解）。
- 准则新增 P15（分镜=约束求解）。

## 2026-11-09 第五次讨论：规则进化与故事层

**参与者**：用户 + Claude

**议题**
1. 导演语法库后期能否自动补充？触发机制是什么？
2. 把"故事"聊透。

**确认的结论**
- **规则采用"自动发现、受控晋升"**（P17 / ADR-0018）：四个信号源（失败挖掘、用户覆盖、参考片分析、专家/社区）；触发阈值（重复失败 ≥20/1000 镜或 ≥3 项目、一致覆盖 ≥10/100 镜、规则失效 >10%、参考片模式 p<0.05、新模型、新题材、指标漂移、周期批处理、人工提议）。
- **候选生命周期**：observed → drafted → evaluating → ab → promoted/rejected/revised → versioned。
- **晋升门槛**：must = 人工确认 + 回归零失败 + 2 名评审；should = A/B 胜率 ≥5% + 成本 ≤10% + p<0.05 + 2 周；may = 可自动进风格包。
- **防膨胀**：活跃规则 ≤60、90 天归档、冲突检测、作用域限定、风格与结构分离、回归集。
- **冷启动**：37 条专家规则作 `grammar@0.1`；前 100 项目 / 10,000 镜只收集数据不自动晋升。
- **故事是产品**（P16 / ADR-0017）：生成会商品化，故事是唯一可持续差异化；LLM 擅长"合格但平庸"，用结构保证下限、人的品味抬高上限。
- **短剧十条物理定律**：3 秒法则、15–20 秒增量、一句话前提、欲望-障碍-代价、关系即冲突、结尾留钩、低认知负荷、可视化优先、情绪 > 逻辑、具体 > 抽象。
- **题材矩阵**：首发聚焦都市情感 / 逆袭打脸 / 甜宠（室内、少人、对话驱动，落在模型强项）。
- **故事引擎 8 步**：前提选择 → Logline 评分 → 人物与关系 → Beat Sheet → 场次拆解 → 台词 → 剧本医生 → 原创性检查。
- **剧本医生 12 维 rubric + 触发条件 + 6 种改写模式**；台词单句 ≤15 字、单镜 ≤2 句；人物 ≤5、场景 ≤3。
- **原创性**：先"标记"不"阻断"；相似度 >0.8 进人工复核。

**产物**
- 新增 [RULE-EVOLUTION.md](RULE-EVOLUTION.md)。
- 新增 [STORY.md](STORY.md)。
- ADR-0017（故事层结构化）、ADR-0018（规则自动发现/受控晋升）。
- 准则新增 P16（故事一等公民）、P17（规则受控晋升）。
- 更新 DATA-MODEL（Premise/Hook/CharacterArc/ScriptDoctorReport/OriginalityReport + 4 条不变量）、FEATURES（A14–A20、I10）、README。

**待定**
1. 剧本医生 12 维权重的首批标定（需 30 个短剧样本）。

## 2026-11-09 第六次讨论：表演与镜头内调度

**参与者**：用户 + Claude

**议题**
1. 故事和分镜都定了，"人在画面里怎么演、怎么动"还是空的。
2. AI 的表演能力边界在哪，产品怎么绕开。

**确认的结论**
- **表演是镜头的目的，运镜是手段**（P18 / ADR-0019）：每镜先定"观众要看到什么变化"，再定景别/机位/运镜。
- **一镜一个 objective、一个情绪转折**；想表达两个就拆两个镜头。
- **表演拆五层**：意图 → 情绪 → 微表情 → 身体 → 动作，全部进 IR。
- **表演节拍**：起（反应）/ 转（决定）/ 落（行动）；对应台词前/中/后；**反应镜头是主战场**。
- **关键帧表演法**：首帧定情绪起点、尾帧定终点，中间只做微动作；情绪跨度大用三帧法切两段。
- **情绪越强，动作越小**；把情绪翻译成具体微动作，不写形容词。
- **视线必须显式**（`GazeTarget` 必填），视线是 AI 最易飘、最影响演技的参数。
- **竖屏调度**：少横移、多纵深；前景遮挡造层次；"脸 + 手 + 一件道具"。
- **距离即关系**：脸贴脸=亲密/威胁，隔前景=隔阂/窥视。
- **口型只特写启用**，中景用侧背/遮挡/反应镜头规避。
- **表演 QA**：情绪匹配、视线、动作完整、过火/面瘫、情绪连续；按景别分级阈值。

**产物**
- 新增 [PERFORMANCE.md](PERFORMANCE.md)。
- ADR-0019（表演以关键帧与微动作为主）。
- 准则新增 P18（表演优先于运镜）。
- 更新 DATA-MODEL（PerformanceSpec/ActionBeat/GazeTarget + 4 条不变量）、FEATURES（B16–B18、I11）、README。

**待定**
1. 表演语法库的首批条目（意图 → 微动作 → 避免项）。
2. 各景别的表演强度阈值标定。
3. 表演 QA 与一致性 QA 的管线合并方式。
4. 下一个议题候选：音频与声音设计（配音表演、音乐、音效）或发布与合规。

## 2026-11-09 第七次讨论：声音设计

**参与者**：用户 + Claude

**议题**
1. 表演有了脸，还缺"嗓子"：配音、音乐、音效怎么设计。
2. 短剧的播放环境对混音的约束。

**确认的结论**
- **声音是第二条表演线**，不是后期补丁；拆四层：对白 / 音乐 / 音效 / 环境（P19 / ADR-0020）。
- **播放环境决定混音**：手机外放、单声道近似、低频缺失、环境嘈杂、可能静音 → 信息双通道、中频为主、不依赖低频。
- **配音不是朗读**：逐句参数（语速/音高/音量/气声/停顿/重音/句尾/呼吸）+ 多 Take；一句台词的意思一半在重音落在哪个字。
- **配音节拍对齐画面表演**：台词前 0.3–0.5s 反应、台词中气口、台词后 0.5s 余韵；口型只特写。
- **音乐按 Beat 情绪曲线走**：只做进/转/出，留白，主题动机（leitmotif）；不从头铺到尾。
- **音效克制**：只给有意义动作配音；画外音扩展空间比多拍一镜便宜。
- **混音对白优先**：台词下音乐 ducking 12–18 dB；整体 ≈ −14 LUFS；真峰值 ≤ −1 dBTP；单声道兼容必检。
- **声音也要一致性**：VoiceProfile 跨集固定、场景 reverb 统一、音乐服从 StyleProfile、整片响度归一。
- **声音 QA**：清晰度、响度/削波、音画同步（±40ms）、情绪匹配、静音可懂、空间一致、版权授权。

**产物**
- 新增 [SOUND.md](SOUND.md)。
- ADR-0020（声音分层、对白优先混音）。
- 准则新增 P19（对白是声音的主角）。
- 更新 DATA-MODEL（VoiceProfile/LinePerformance/MusicCue/SfxCue/MixSpec + 5 条不变量）、FEATURES（C9–C13）、README。

**待定**
1. 配音默认参数模板（按情绪/性别/年龄）。
2. 场景混响预设与音乐情绪曲线模板。

## 2026-11-09 第八次讨论：发布与合规

**参与者**：用户 + Claude

**议题**
1. 多平台发布到底能做到什么程度。
2. AI 标识、内容安全、授权链怎么落到管线里。

**确认的结论**
- **发布的第一能力是导出合规成品，不是代发**（P20 / ADR-0021）；平台 API 是增强不是依赖。
- **三层能力**：L1 导出包（P0，永远可用、自包含）、L2 官方 API（P2，需资质）、L3 移动端分享扩展（P1，覆盖无 API 平台）。
- **明确不做**：逆向登录、模拟点击、批量养号、绕过审核、爬取数据（R10）。
- **平台规格不写死在代码**，维护 `PlatformSpec` 表并版本化；矩阵覆盖抖音/快手/小红书/B站/视频号/TikTok/YouTube Shorts/X。
- **AI 标识在渲染阶段写入**：显式（角标/片头/简介烧录）+ 隐式（文件元数据）；不得移除平台标识。
- **内容安全四个检查点**：剧本 → 关键帧 → 成片 → 发布文案；处置 pass/review/block，结果留档。
- **授权台账**：模型输出/音乐/音色/字体/肖像/文本，每项素材挂 `AuthorizationRecord`，缺授权阻断发布。
- **发布流程**：预检（规格+合规+授权）→ 多平台渲染 → 人工确认 → 导出/API/分享 → 台账 → 数据回流。
- **数据回流只做官方允许的指标**，不做爬虫。
- 资质清单（生成式 AI 备案、ICP、算法备案、公安备案等）需专业法律意见，MVP 可先小范围内测。

## 2026-11-09 第九次讨论：成本与单位经济

**参与者**：用户 + Claude

**议题**
1. 一条 60 秒短剧到底花多少钱，钱花在哪。
2. 哪些重试是浪费，定价下限在哪。

**确认的结论**
- **成本的核心是废片率，不是单价**（P21 / ADR-0022）：`C_effective = 总成本 ÷ 通过镜数`。
- **成本结构**：视频生成占 60–80%，关键帧 10–20%，其余是零头。
- **三个公式**：单镜成本、项目成本（含重试）、有效成本；重试是乘法，通过率 40%→25% 会让成本从 2.5 倍变 4 倍。
- **基准情景（待 S1 标定）**：720p/60% ≈ 100–150 元；1080p/40% ≈ 250–400 元；1080p/25% ≈ 600–900 元。
- **成本杠杆按 ROI 排序**：Animatic 闸门 > 关键帧先行 > 提高通过率 > 双档渲染 > 短镜头 > 模型路由 > 缓存 > 预算护栏。
- **短镜头的成本注意**：不减少视频总秒数、还增加关键帧；省的是"长镜漂移导致整段重来"。
- **双档渲染**：draft（540p/720p）用于一切确认前；final（1080p+）只在确认后。
- **重试停止条件**：预算上限、次数上限 3–5、质量提升 < 阈值、同维度连续两次失败（回设计层）。
- **单位经济现实**：单条 300 元 vs C 端 9.9–29.9 元 = 负毛利，必须靠降本 + 提高单用户产出 + 点数计费三条一起解。
- **点数制**：点数映射真实资源消耗；默认套餐覆盖"一条完整片"。
- **观测**：逐笔记账、提交前估算、异常告警、`ModelPrice` 版本化、双层预算护栏。

**产物**
- 新增 [COST.md](COST.md)。

## 2026-11-09 第十二次讨论：接入真实模型（S1 起步）

**确认的结论**

## 第七十一次 · 2026-11-10 · 删一场、删一镜

**背景**

## 第七十三次 · 2026-11-11 · 新场沿用前一场的地点与日夜

**背景**
ADR-0064 / 0068 给新场定的默认值是「第一个地点 · 内 · 日」。实际写剧本时，加一场多半是同一场戏的延续；插在两场中间更几乎总是紧跟前一场。每加一场都去场头重拨地点与日夜，是多余的手工税——ADR-0068 的「负面」里已经记了这一条。

**结论**
- `addScene` 先算新场的 `index`，取 `ordered[index - 1]` 作为前一场；新场的 `locationId / space / timeOfDay` 沿用它的值。
- 没有前一场（插在第 1 位、或项目里还没有场次）时退回旧默认：第一个地点 · 内 · 日。
- 显式传入的 `locationId` 优先，只继承内外景与日夜（UI 暂未使用，留给「在某地点下加一场」）。
- 只改默认值，不新增事件、不动场头历史；事件里写的仍是完整场次，回放确定。

## 第七十四次 · 2026-11-11 · 这一镜里换人

**背景**
「这一镜里换谁」散在两处：分镜页的出场签能点名，但有台词的人点不灭（store 拒绝，提示"先删掉或换人"）；剧本页的台词说话人能逐句换，但出场名单不动。要把林换周，得点灭（被拒）→ 逐句换台词 → 再点灭，三步走完还可能留下"人在场上不说话 / 不在场上却说话"的矛盾。

**结论**
- store 新增 `swapShotCharacter(shotId, fromId, toId)`：一条动作里把出场原位换成目标人，并把这一镜里此人的每句台词写出 `dialogue.speaker.updated`；目标本来就在场时并到第一次出现的位置。
- 事件不新增：`shot.updated { characterIds }` + N 条 `dialogue.speaker.updated`，同一 `at`，先名单后台词。
- 拒绝：锁定、被换的人不在出场里、目标不存在；只读不写。
- 界面在剧本页：每镜技术行下面一排 `出场` 人名签，点开就地选 `换下 林 →`，选完立刻换；无出场人物时不显示。
- 分镜页有台词点不灭的提示改为「先删掉，或去剧本页点他的名字换人，再把他从出场里拿掉。」
- ADR-0070；`UX.md` 剧本页 / 分镜页、`FEATURES.md` A21 同步。

**验证**
- 测试：web 180（新增 4 条断言组：换人同时改出场与台词、并到已出场的人、拒绝四种情况不写事件）、IR 82、gateway 17、pipeline 22，合计 301；`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：分镜页给 SH-01 点出 `林`；剧本页加一句林说的台词后，点 `出场 林` → 选周，出场与说话人同时变成周、镜头时长不变；再换回林并删掉试验台词、分镜页点掉林，页面无报错。

**诚实地说**
- 一次只能换一个人；一次换一组要等后续。
- 可换的人只有定妆页现有的，人物库（新建 / 改名 / 参考图）还没做。
- 换人不可撤销，换错了只能再换回去。
- 已出的帧按 `characterIds` 挂 `过期`，不会自动重出。

## 第七十五次 · 2026-11-11 · 人物库：新建与改名

## 第七十七次 · 2026-11-11 · 删除人物与道具

**背景**

**结论**

- ADR-0073；`UX.md` 定妆页、`FEATURES.md` B1 / B8 同步。

**验证**

**诚实地说**
- 删错就没了：没有撤销、没有回收站，被删对象的图成了孤儿。

## 第八十次 · 2026-11-11 · 删除的撤销

**背景**
删除一直是真删：人物、道具、地点、场次、镜头删掉就没了，日志里只剩一条 `*.removed`。误删一个写着三句台词的人物，只能重建成一模一样再逐镜挂回去。ADR-0073 / ADR-0075 都把"撤销删除"记成跟进项。

**结论**
- 撤销 = **追加补偿事件**，不回滚日志（日志只追加，ADR-0011）：复用 `character.added` / `prop.added` / `location.added` / `scene.added` / `shot.added`，加 `dialogue.added` / `take.added` / `shot.updated`。IR 不新增事件。
- 读模型 `undoableRemoval(events, project)`：从日志末尾往回找第一条"被删对象仍然缺着"的 `*.removed`，已经被恢复过的跳过。所以撤销按删除的逆序走，撤完这一条，页头那行换成更早的那条。
- 复原取删除之前那一份项目（`rebuild` 到那条事件之前）：名字、清单、场号、镜号、台词顺序都按当时的算。
- 场次放回**空场**（删场本来就要求先删镜头）；镜头按原 index 放回，再补台词与 take，最后 `shot.updated { dialogueIds }` 复原顺序，选中跳到这一镜；镜头所在的场也删了时拒绝，让用户先撤场次。
- 资产不处理：删除本来就不清理三视图 / 主镜 / 参考图，引用一回来就重新看得见。
- 界面：定妆页页头「刚删掉人物「X」」+ `撤销`（只管人物 / 道具 / 地点），剧本页页头同样的行（只管镜头 / 场次）；只读标签页不显示。
- ADR-0076；`UX.md` 两处、`FEATURES.md` B1 / B8 / F2 同步。

**验证**
- 测试：web 205（新增 9：store 4、读模型 5）、IR 94、gateway 17、pipeline 22，合计 338；`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：定妆页新建「试撤销」再删 → 页头出现撤销行 → 点 `撤销`，人物带着原 id 回到列表；剧本页删 SH-01 → 页头「刚删掉 镜 SH-01」→ 点 `撤销`，镜头数 2 → 3，台词与出场随之回来；两次都无报错。

**诚实地说**
- 只撤最后一条，没有多步撤销栈；连续删三个，只有第三个能撤。
- 补偿事件写的是撤销时刻，不是当初的时间。
- 场次复原是空的：先删镜再删场要撤两次。
- 镜头的场次被删了就撤不了镜头，得先撤场次。
- 撤销不弹确认；只读标签页连这一行提示都没有。

## 第八十一次 · 2026-11-11 · 出场顺序可调

**背景**
出场顺序就是提示词里的顺序，但定下就改不了：想让「周」排到「林」前面，只能先点掉再重点。点掉还会被"这一镜有台词"挡住（ADR-0070）。道具同理。而且签一直按库存顺序显示，视觉顺序与提示词顺序不一定一致。

**结论**
- 不做拖拽，做一对 `‹` / `›`：已出场的签里嵌两个小箭头，点一下与相邻一位互换；到头置灰。触屏、键盘都能用，一次点击只写一条 `shot.updated`。
- 签改为**按出场顺序排**：已出场在前，未出场在后；视觉顺序从此等于提示词顺序。
- store 新增 `moveShotCharacter` / `moveShotProp`（`delta` 取 `-1 | 1`）：只读 / 锁定拒绝并写页头，不在出场里、到头则不写事件；互换后整份写回 `shot.updated`。
- 两人（件）以上才显示箭头；锁定或只读时不显示。
- ADR-0077；`UX.md` 出场 / 道具两处、`FEATURES.md` B1 / B8 同步。

**验证**
- 测试：web 208（新增 3）、IR 94、gateway 17、pipeline 22，合计 341；`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：分镜页点亮「林」「周」「试撤销」→ 点「周」的 `‹` → 顺序变「周，林，试撤销」；道具「台灯」「搪瓷杯」→ 点「搪瓷杯」的 `‹` → 顺序变「搪瓷杯，台灯」；无报错。

**诚实地说**
- 一次只挪一位，长名单要连点。
- 顺序变化不标帧过期：人物集合没变，但提示词变了，这一点留到"提示词是否影响帧"统一判断。
- 道具锚点标签是否跟随出场顺序还没定，目前锚点顺序未改。

## 第八十二次 · 2026-11-11 · 道具签按场筛选

**背景**
分镜页 `道具` 一行列整个道具库。库一大，签会换好几行把舞台挤下去；而一个镜头通常只用这一场出现过的那几件。

**结论**
- `道具` 标签旁一个虚线 `只列本场` 开关：只列这一场所有镜头 `propIds` 的并集；默认关（不让人一进来以为道具没了），再点回到全部。
- 只是视图：状态留在组件里，刷新回全部，不写事件。
- 读模型给 `StageShot` 加了 `sceneId`，分镜页按场算并集。
- 只筛道具不筛人物：人物签还承担"谁在这一镜"的叙述，数量通常不大。
- 空态写「这一场还没用过道具。点「只列本场」列全部。」
- ADR-0078；`UX.md` 道具行、`FEATURES.md` B8 同步。

**验证**
- 测试：web 210（新增 2）、IR 94、gateway 17、pipeline 22，合计 343；`pnpm typecheck`、`pnpm build` 通过。
- 真实链路：定妆页新建「雨伞」→ 分镜页全部道具含「雨伞」→ 点 `只列本场` 只剩「搪瓷杯」「台灯」→ 再点回来「雨伞」回来；无报错。

**诚实地说**
- 想加"本场还没用过"的道具得先关筛选；筛选态里没有搜索 / 新建。
- 不记忆开关；刷新或切页回来都是全部。

## 第八十九次 · 2026-11-11 · 配音（N2 下半 · C1）

**背景**
预演已经能连着看，但是默片。ADR-0003 把配音定为音频先行：对白的节奏与停顿决定这条片子成不成立。供应商这边列得出 `qwen-audio-3.0-tts-*`，但 `POST /v1/audio/speech` 实测 403 `No authorized bound group supports this request`——链路可以写，现在很可能念不出声。无头 Chrome 也解不开音频，自动化验收只能验到元素与状态。

**结论**
- 数据模型：`DialogueLine.audioAssetId?: ID`（ADR-0085），指向 `kind: "audio"` 的资产；资产 id 固定 `a-voice-<lineId>`，一句一个资产位，重配覆盖旧音轨，不进 `takes`。`Character.voiceProfileId` 可改（`character.updated` 的 patch 增加该字段，空串表示用回默认音色）。
- 网关：`TreecloudClient.requestBytes` 收二进制响应；`TreecloudSpeechAdapter.speak` 调 `POST /v1/audio/speech {model, input, voice, response_format}`。模型读 `TTS_MODEL`、默认音色读 `TTS_VOICE`；没配模型直接报 `tts_not_configured`，**不发请求**。
- 服务端：`GET /api/voice` 只回 `{ model?, voice? }`（不触发生成）；`POST /api/voice` 一句一次请求，回 data URI；文字 ≤ 300 字、音色 ≤ 40 字；没配模型回 500（配置问题，不是 502 供应商错误）。
- 时长以音轨为准（P5）：网关不猜时长，浏览器读 `loadedmetadata` 后由 `fitLineToAudio` 写 `dialogue.updated { durationMs }` + `shot.updated { durationMs }`（按差值挪镜头）+ `asset.updated` 补记 `durationMs`；差值 < 40ms 不写。
- 界面：新增 `/voice` 声音页（顶栏「声音」可达）。角色音色输入、按镜头顺序列每一句、已配的带播放器；每句 `出声 / 重配` 与 `贴音轨`（`http(s)://` 或 `data:audio/`，≤ 8 MB）两条入口；没配模型时「出声」禁用并说明原因。锁定的镜头不出声、不贴。

故事入口让用户从一句话开始，但手里已经有小说或剧本的用户仍要手抄。F6 要做导入，难点不是读文件，而是：原文通常不是一条 60–90 秒单集，且用户可能上传无权使用的文本。不能把整本小说原样塞进 IR，也不能假装平台能核验版权。

**结论**
- `/story` 加第二个标签「导入剧本 txt」，不新开页面。两种来源共用同一份 `StoryDraft` 展示、确认开工与落项目映射；切换标签清掉草稿，输入各自保留（ADR-0089）。
- 文件在浏览器里读：`.txt` / `text/plain`，上限 2 MB；先按 UTF-8 严格解码，失败再按 GB18030，去 BOM。也可以直接粘贴。一次最多 2 万字，超过不偷偷截断，明说先截一段或拆集。
- 必勾「我确认有权使用这段文字（原创或已获授权）」才能导入。声明只在内存，不写日志；它不是版权审核，只是最低边界的用户声明（R29）。
- 新增 `importStoryMessages(source, genre?)`：与想法入口共用体量与枚举约束，额外要求保留人物关系、核心冲突与结局意思，可合并次要人物与场次，不新增原文没有的主要人物，删除旁白与无法拍摄的内心描写，不照抄大段原文。输出仍是同一份 `StoryDraft`，仍过 `parseStoryDraft` 与 `assertValidProject`。
- 台词下限继续收紧到 20–24 句：实测 12 句只有 44 秒，18 句 55 秒，都够不到 60。提示词收紧后，199 字原文生成 13 镜 / 21 句 / 62.6 秒。代价是模型会补反应与短句，所以界面明确标「改编稿 · 原文 n 字」，不叫「原样导入」。
- 确认开工仍写新的 `project.created`；`story.provenance.prompt` 只写「导入剧本（文件名）（n 字）：正文前 300 字」，原文不落服务端、不进事件日志。
- 界面：导入模式有 `选择 txt 文件`、字数 `n / 20000`、权利勾选、`改编成剧本`；结果标「由 <model> 改编」；读文件失败、超限、没勾权利、没配模型分别说；生成中提示 40–100 秒。

**验证**
- 测试：pipeline 30（新增 1：导入提示词保留关系与结局、只输出 JSON）、IR 110、gateway 28、web 278，合计 446；`pnpm typecheck`、`pnpm test`、`pnpm --filter web build` 通过。
- 接口：同一段 199 字剧本 `POST /api/story`（`source`）57 秒返回 3 人 / 2 场 / 13 镜 / 13 句；按 0.3 秒 / 字 + 1 秒余量只估到 44 秒。把台词下限提到 16–20 后再测 64 秒返回 12 镜 / 18 句 / 55 秒；提到 20–24 后 95 秒返回 14 镜 / 23 句 / 61 秒。
- 真实页面（1440×900，无头 Chrome，先关掉所有旧标签页避免单写者锁）：点「导入剧本 txt」→ 填入 199 字原文 → 勾权利 → 按钮变 `改编成剧本` 且可点；点击后忙约 80 秒，出现结果「玉镯当票」（3 人、2 场、13 镜、21 句、估时 62.6s），标「由 claude-sonnet-5-5 改编」「改编稿 · 原文 199 字」。点「用它开工」→「确认开工」跳到 `/script`，页头「场 2 / 镜 13 / 台词 21 / 时长 62.6s」，场次、镜头与台词都在。
- 第一次点击「用它开工」失败是因为同一浏览器里还留着两个旧 `/story` 标签页，单写者锁把新页面标成「只读」；关掉旧标签页、只留一个页面后完整走通。这是锁的正确行为，不是导入的 bug。
- 截图：`/tmp/story-import-result.png`、`/tmp/story-import-script.png`。

**诚实地说**
- 这是改编，不是逐字导入：会删旁白、合并场次、补反应；原文的文学性会损失。界面已经写明，但用户仍可能期待「一字不改」。
- 没有保真校验：不检查人物是否漏掉、关键道具是否保留、结局是否被改；只能靠提示词与用户自己看草稿。
- 只支持单段 txt、最多 2 万字；没有章节识别、多集导入、原文对照视图。
- 权利声明不是核验；用户勾选后仍可能上传无权文本。投诉与下架流程还没做。
- 没有自动重试或逐场重写；JSON 不合格直接报错，整份重来。
- 无头环境只验了页面结构、事件与跳转，没有验真实文件选择器（用 setter 填文本域代替）；GB18030 解码逻辑没有拿真实 GBK 文件测。

## 第九十四次 · 2026-11-11 · AI 生成内容标识（H5 · ADR-0090）

**背景**
ADR-0008 定了「AI 标识内建」，发布包与 OTIO 里已经有 `aiLabel`，但成片页播放器与导出的预览 HTML 上看不到任何标识。法规要求显式标识与隐式标识同时存在；只写 JSON 字段等于只有隐式标识，用户把预览 HTML 发给别人时，对方看不出这是生成内容。

**结论**
- 成片页播放器画面右下角常驻「AI 生成」角标，`pointer-events: none`，不挡播放；没有开关，也不进 Project IR（ADR-0090）。
- 导出预览 HTML 同样在画面右下角显示角标，`<head>` 增加 `<meta name="ai-generated" content="true">` 与 `<meta name="ai-label-standard" content="AI生成">`。
- OTIO `metadata.loom.aiLabel` 与发布包 `aiLabel` 保持 `{ explicit: true, implicit: true, standard: "AI生成" }`。
- 导出区加一句说明：标识不是可选项；预览角标、HTML 元数据、OTIO 元数据与发布包 `aiLabel` 都会带上，mp4 接上后角标也要烧进画面。
- 标识是 `export-cut.ts` 里的常量，不新增事件字段、不做迁移。强制项没有选择，也就不该有状态。

**验证**
- 测试：web 280（新增 2：预览 HTML 的角标与元数据、OTIO 元数据里的 `aiLabel`）、IR 110、gateway 28、pipeline 30，合计 448；`pnpm typecheck`、`pnpm test`、`pnpm --filter web build` 通过。
- 真实页面（1440×900，无头 Chrome，先关掉所有旧标签页避免单写者锁）：`/edit` 页头「成片」，播放器右下角能看到「AI 生成」；角标位置在画面内、不挡字幕与播放控件，`pointer-events` 为 `none`。截图 `/tmp/h5-edit-player.png`。
- 点「导出预览 HTML」得到 `夜班-预览.html`（7.9 KB），导出结果写「预览已导出：0.0 MB」。打开导出的文件：画面右下角同样有「AI 生成」，`<meta name="ai-generated" content="true">` 与 `<meta name="ai-label-standard" content="AI生成">` 都在。截图 `/tmp/h5-preview-html.png`。
- 本轮没有改项目数据，验证后 IndexedDB 仍是示例项目（2 个时间线片段、全长 5.5s）。

**诚实地说**
- **mp4 还没烧录**：当前没有服务端渲染，发布包视频位如实为 `null`；标识只落在预览 HTML、OTIO 与发布包 JSON 上。验收标准 5（导出 MP4 带 AI 标识）仍未满足。
- 预览 HTML 的 `<meta>` 不是签名，任何人都能改；强隐式标识（签名 / 水印）还没做。
- 角标固定在右下角，没有按平台安全区调整；平台 UI 可能遮挡，等 G7 规格库。
- 没有统一的导出闸门：现在四条导出路径都带标识，但新增导出路径仍要靠调用点记得写常量，G8 合规预检还没做。
- 无头环境只验了页面结构与导出文件，没有验真实视频画面上的角标（没有视频可放）。

## 第九十五次 · 2026-11-11 · 成片 MP4 渲染（E6 · ADR-0091）

**背景**
成片页能导出预览 HTML、OTIO、SRT 与发布包，但验收标准 5「导出 MP4（1080×1920，H.264），带 AI 标识」一直没满足。本机 ffmpeg 9.0.2 已可用，却**没有编进 `drawtext` / `subtitles` 滤镜**：中文不能交给 ffmpeg 排版。如果补 libass 与字体，等于在服务端再写一套字幕逻辑，和预览的字距、换行必然漂移。

**结论**
- 新增 `POST /api/render`：浏览器把「片段 + 叠加层 + 音轨」的渲染清单发上来，服务端只做校验、拼滤镜、编码；不读项目、不落盘、不写发布记录（ADR-0091）。
- 浏览器负责排版：字幕按现有 `SUBTITLE_STYLES` 画成 1080×1920 透明 PNG；没有视频 / 首尾帧的片段画斜纹占位图并写 `SH-xx 还没有画面`；「AI 生成」角标单独画一张全画幅透明 PNG，全程叠加。
- 服务端：图片 `loop + trim`，视频 `scale/pad/fps/tpad/trim`，`concat` 拼接，`overlay` 按 `between(t,…)` 叠字幕与角标，音轨 `adelay + amix + apad + atrim` 对齐全长；输出 H.264（veryfast / crf 20 / yuv420p）+ AAC 128k，`+faststart`，容器写 `title` 与 `comment=AI生成`。
- 只收 data URI，服务端不 GET 任意 URL（避免 SSRF，也避免供应商链接过期）。远端视频 / 音轨在浏览器侧跳过并计数，界面写「n 个远端素材没下载」；画面改用首帧或占位。
- 硬上限：≤180 秒、≤60 个片段、单件素材 ≤30 MB、整份 ≤200 MB；缺口、时长对不上、缺 AI 标注直接 400 并说原因。
- 成片页把 `导出成片 MP4` 设为主按钮，渲染中写阶段文案，完成写大小、分辨率、占位片段数与远端跳过数，失败带 ffmpeg 最后几行。

**验证**
- 测试：web 286（新增 6 条渲染清单校验：data URI 字节数、合法清单、拒绝远端、缺口 / 超长、缺 AI 标注 / 叠加层越界、文件名）、IR 110、gateway 28、pipeline 30，合计 454；`pnpm typecheck`、`pnpm test`、`pnpm --filter web build` 通过，构建不再有 Turbopack 动态路径警告。
- 接口（curl / ffprobe）：2 秒双图 + 叠加层 + 静音轨 → 200，H.264 1080×1920 / 30fps / AAC / 2.000s，容器 `comment=AI生成`；2.5 秒「1 秒视频 + 0.5 秒图片 + 500ms 延迟 440Hz 音轨」→ 2.500s，音轨 `mean_volume -25.5 dB`，说明延迟混音生效、视频末帧补足。
- 真实页面（1440×900，无头 Chrome，先关掉所有旧标签页）：`/edit` 点 `导出成片 MP4`，4 秒完成，下载 `夜班-成片.mp4`（79 KB），按钮下方写「成片已导出：0.1 MB · 1080×1920 · 带字幕与「AI 生成」角标。2 个片段用占位图。」
- 抽帧检查（第 1 秒）：1080×1920 斜纹占位、`SH-01 还没有画面` 居中、白色描边字幕、右下角「AI 生成」角标都在。截图 `/tmp/e6-export.png`、`/tmp/e6-frame.png`。
- 本轮没有改项目数据；验证后示例项目仍是 2 个时间线片段、全长 5.5s。

**诚实地说**
- **远端视频不渲染**：供应商返回的 `http(s)` 视频不会进成片，只能用首帧或占位图。示例项目本身没有画面，所以这次导出的是「占位片」，不是能直接发布的成片。
- **一次请求没有进度**：只能显示「通常 20–90 秒」，服务端超时 240 秒；两个标签页同时导出会并行跑 ffmpeg，没有队列与并发控制（H2）。
- **字幕烧死**：成片里的字幕不可关、不可切轨；没有无字幕版与外挂字幕。
- **音频只有对白**：没有配乐、没有响度归一化；多条音轨直接相加，可能削顶（C4 / C12 未做）。
- **平台规格没校验**：固定 1080×1920 / 30fps / H.264，还没有按抖音等平台的码率、封面与时长再校验（G7 / G8）。
- 没有用真实供应商视频做端到端渲染；只验了本地 data URI 视频、图片与音轨。

## 第九十六次 · 2026-11-11 · 下一批任务清单与顺序

**背景**
N1–N6、H5、E6 已落地，MVP 的主要功能面已经连起来。剩下的 P0 不是「还缺一个页面」，而是几组互相依赖的收尾：真实视频进不了成片、渲染没有队列、合规模块空着、故事质量闸门与一致性评分没做。

**结论（建议顺序）**
1. **E6.1 远端素材受控下载**：渲染清单允许带 `http(s)` 地址，但只接受环境变量白名单里的域名，带超时与大小上限；不在白名单的仍跳过并计数。先补 E6 的 R27，不急着接 H3 云端对象存储。
2. **H2 渲染任务队列**：提交后立刻返回任务号，客户端轮询进度；并发固定为 1，失败可重试，临时文件按任务回收。把「一次请求等 90 秒」改成可观察的任务。
3. **H6 内容安全审核 + G8 合规预检**：文本先行，图像 / 视频留接口；导出前统一检查 AI 标识、内容安全与授权链，未过不得导出。
4. **A11 Beat 分析 + A12 覆盖率规划 + A13 分镜校验**：A13 先做本地可判定的时长、预算、覆盖率与模型能力；轴线检查依赖 B17 的站位 / 视线数据，先如实标注未做。
5. **B14 一致性评分 + B6 自动重试与降级**：对应验收标准 2；没有供应商配额时只能先做评分与重试策略的骨架。
6. **B12 / H16 能力矩阵落 UI**：真实单价、时长、分辨率、首尾帧、商用条款与最近一次探测结果，给报价与校验提供依据。
7. **C4 配乐 + C12 混音与响度 + G7 平台规格**：让成片从「能导」到「能发」。
8. **F8 / F9 阶段流与闸门、H10 镜头级预算与重试上限、A9 声音确认**：把已有能力收进同一条创作流。

**暂缓 / 外部阻塞**
- H3 云端对象存储：用户此前明确「先存在本地」；先做 E6.1 的受控下载，不接 S3。
- TTS / ASR 供应商 403、视频配额、文本模型单价：没有授权或账单前，只能验失败路径与骨架。
- A2 / A18 剧本医生、E5 多比例、G3 移动端分享、B13 3D、E7 WebCodecs 留到 Phase 1。

**下一步**
先做 E6.1，再做 H2；两项都完成后，成片链路才算「真实素材可用、过程可观察」。
