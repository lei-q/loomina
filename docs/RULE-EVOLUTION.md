# 规则进化：自动发现，受控晋升

> 回答：导演语法库后期能否自动补充？怎么补？触发机制是什么？
> 核心原则：**自动发现、自动评测，但 must 级规则必须人工确认后才上线。**
> 规则库是产品资产，不是自我修改的黑盒。

---

## 一、先分清两件事

| | 自动发现 | 自动晋升 |
| --- | --- | --- |
| 含义 | 从数据里找出"值得成为规则"的模式 | 直接把候选规则应用到所有用户 |
| 是否自动 | **是** | **分级**：may 可自动；should 需 A/B；must 需人工 |
| 风险 | 低（只是候选） | 高（会影响所有项目） |

> 没有评测与晋升门槛的"自动补充"，最后一定会变成规则膨胀、风格趋同、互相冲突。

---

## 二、四个信号源

### 1. 失败挖掘（最强）
- 数据：QA 失败、用户拒绝的 Take、重试记录、人工修复。
- 模式：同一类问题反复出现（如"对话场景总是缺反应镜头"）。
- 产出：候选规则或对现有规则的修正。

### 2. 用户覆盖（最真实）
- 数据：用户手动改分镜/机位/光影/时长，记录 `before → after`。
- 要区分两类：
  - **纠错**：同一改动在多人/多项目重复 → 可能是规则缺失。
  - **偏好**：个人风格 → 应进 `StyleProfile`，不是全局规则。
- 产出：候选规则 / 风格包。

### 3. 参考片分析（最快冷启动）
- 对授权/公版短剧做：镜头切分、景别分类、运镜分类、光色统计、覆盖序列挖掘。
- 产出：统计规律（如"对峙场景平均镜长递减 30%"）→ 候选规则。

### 4. 专家与社区（最高质量）
- 影视顾问、资深创作者、用户提交。
- 产出：规则草案 + 正反例。

## 三、触发机制（什么时候开始补）

| 触发类型 | 条件（示例，需标定） | 动作 |
| --- | --- | --- |
| **重复失败** | 同一 QA 问题 ≥ 20 次 / 1000 镜，或出现在 ≥ 3 个项目 | 生成候选规则 |
| **一致覆盖** | 同一参数的修改 ≥ 10 次 / 100 镜，且方向一致 | 生成候选或风格包 |
| **规则失效** | must 规则违规率 > 10% | 检查规则是否过严/过时，而非加新规则 |
| **参考片模式** | 新参考片库中某模式显著（p < 0.05） | 生成候选 |
| **新模型上线** | 能力矩阵更新 | 重评 F 类（可行性）规则 |
| **新题材包** | 新增 genre pack | 生成该题材专属规则 |
| **指标漂移** | 重试率/成本/偏好分变化超阈值 | 调查根因，可能触发规则修订 |
| **周期批处理** | 每周/每月 | 聚类 → 候选 |
| **人工提议** | 专家/用户提交 | 进入候选队列 |

> 触发不是"越多越好"。**优先处理重复失败与一致覆盖**，这两类最接近真实问题。

## 四、候选规则的生命周期

```
observed（观察到模式）
   │  证据：次数、项目数、样例
   ▼
drafted（草案）
   │  LLM + 统计生成规则文本、正反例
   ▼
evaluating（离线评测）
   │  在 golden set 上回放：违规率、偏好、成本
   ▼
ab（小流量）
   │  5–10% 项目，2 周
   ▼
promoted（晋升）/ rejected（拒绝）/ revised（修订）
   │
   ▼
versioned（发布 grammar@x.y）
```

### 晋升门槛

| 级别 | 门槛 |
| --- | --- |
| **must** | 人工确认 + 结构回归测试零失败 + 至少 2 名评审（可由用户 + 顾问担任） |
| **should** | A/B 人类偏好胜率 ≥ 5%，成本增幅 ≤ 10%，p < 0.05，持续 2 周 |
| **may** | 可自动进入"风格包"，默认关闭，不影响全局 |

### 每条规则的必备信息
- 触发条件、建议、理由；
- 正例 / 反例；
- 适用范围（题材、场景类型、模型）；
- 证据（次数、项目数、样例链接）；
- 版本与作者。

## 五、防膨胀与冲突治理

1. **活跃规则上限**：建议 ≤ 60 条；超出必须退休旧规则。
2. **使用率追踪**：90 天未被触发的规则归档。
3. **冲突检测**：同一条件推出相反建议 → 标红，按上下文/优先级解决。
4. **作用域限定**：规则可限定题材、场景类型、模型，避免"一条规则管所有"。
5. **风格与结构分离**：风格偏好进 `StyleProfile`，不进全局规则。
6. **回归集**：任何新规则不得让既有 must 规则违规率上升。

## 六、数据结构

```ts
interface RuleCandidate {
  id: ID;
  source: "failure" | "override" | "reference" | "expert" | "model" | "genre";
  proposed: DirectorRule;
  evidence: {
    occurrences: number;
    projects: number;
    examples: ID[];        // 事件/镜头引用
  };
  status: "observed" | "drafted" | "evaluating" | "ab" | "promoted" | "rejected";
  metrics?: {
    violationRate?: number;
    preferenceWinRate?: number;
    costDelta?: number;
    pValue?: number;
  };
  reviewers?: string[];
  createdAt: ISODate;
}

interface GrammarVersion {
  id: string;             // "grammar@0.3.1"
  rules: DirectorRule[];
  changelog: string;
  publishedAt: ISODate;
}
```

## 七、冷启动

没有用户数据时，不要等：

1. 用 37 条专家规则作为 `grammar@0.1`。
2. 用参考片分析补充统计规律（公版/授权素材）。
3. 前 100 个项目只收集数据，不自动晋升。
4. 达到样本量（如 100 项目 / 10,000 镜）后开启候选流水线。

---

## 八、监控与回滚

- 每次规则发布记录：版本、影响范围、指标。
- 关键指标：must 违规率、重试率、成本/分钟、人类偏好、生成成功率。
- 指标恶化超过阈值 → 自动回滚到上一版本。
- 所有规则变更可追溯到证据与评审人。

---

## 九、一句话总结

**自动补充的不是"规则"，是"候选"；真正上线的规则，必须过评测与人工这一关。**
这样既能持续进化，又不会把产品变成自我漂移的黑盒。
