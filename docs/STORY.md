# 故事层：短剧的物理定律与故事引擎

> 核心判断：**生成能力会商品化，故事是唯一可持续的差异化。**
> 但"好故事"不是玄学，它可以被拆成可诊断、可打分、可改写的结构；同时必须给"具体而动人的细节"留出人的位置。

---

## 一、先接受三个事实

1. **LLM 擅长"合格但平庸"。** 它能稳定产出结构完整、套路正确的故事，但很少自动产出"具体、意外、动人"的细节。
2. **短剧不是短电影。** 它有自己的语法：钩子密度、情绪效率、爽点节奏、竖屏观看。
3. **故事必须可拍。** 在 AI 短剧里，"可拍"还包括"模型能生成、成本可控、一致性可维持"。

所以产品要做的不是"让 AI 写故事"，而是：**用结构保证下限，用人的品味抬高上限。**

---

## 二、短剧的十条"物理定律"

| # | 定律 | 含义 |
| --- | --- | --- |
| 1 | 3 秒法则 | 前 3 秒决定大部分留存；第一镜必须是钩子 |
| 2 | 15–20 秒增量 | 不能有"平"的段落；每个区间都要有信息或情绪变化 |
| 3 | 一句话前提 | 高概念；一句话说不清的故事，通常拍不好 |
| 4 | 欲望-障碍-代价 | 主角必须想要什么，且失败要付出代价 |
| 5 | 关系即冲突 | 每对人物关系都要有张力，而不是"设定" |
| 6 | 结尾留钩 | 完播与追更的关键；不要给完整闭合 |
| 7 | 低认知负荷 | 少人物、少场景、关系清晰；观众是刷到的，不是坐下的 |
| 8 | 可视化优先 | 写能拍出来的东西；少内心戏、少抽象描述 |
| 9 | 情绪 > 逻辑 | 先给情绪，逻辑自洽即可；不要为了严密牺牲爽感 |
| 10 | 具体 > 抽象 | "她把伞留在电梯里"胜过"她感到失落" |

## 三、题材与可行性矩阵

不是所有题材都适合 AI 短剧。要同时看**受众规模 × 生成可行性 × 竞争强度**。

| 题材 | 受众 | AI 可行性 | 竞争 | 建议 |
| --- | --- | --- | --- | --- |
| 都市情感 | 大 | 高（室内/少人/对话） | 高 | **P0** |
| 逆袭打脸 | 大 | 高 | 高 | **P0** |
| 甜宠霸总 | 大 | 高 | 高 | **P0** |
| 家庭伦理 | 大 | 高 | 中 | P1 |
| 悬疑复仇 | 中 | 中高 | 中 | P1 |
| 重生穿越 | 中 | 中 | 中 | P1 |
| 校园青春 | 中 | 高 | 中 | P1 |
| 职场 | 中 | 高 | 中 | P1 |
| 古装宫斗 | 中 | 低（服化道/群演/建筑） | 高 | P2 |
| 战神赘婿 | 大 | 中（动作/群演） | 高 | P2 |
| 萌宝亲子 | 中 | 低（儿童一致性） | 中 | P2 |
| 乡村年代 | 中 | 中 | 低 | P3 |

> 首发建议：**都市情感 + 逆袭打脸 + 甜宠**，因为它们是"室内、少人、对话驱动"，正好落在模型的强项上。

> **实现说明（A14，ADR-0104）**：矩阵落在 `packages/pipeline/src/story-kit.ts` 的 `GENRE_MATRIX`（12 条，含受众 / 可行性 / 竞争 / 优先级 / 建议 / 关键词）。故事页以按钮 + 可展开矩阵表呈现，选中的题材随生成请求送给文本模型；P2 / P3 只用 `pick` 色提醒，不拦生成。旧叫法（都市逆袭 / 甜宠 / 悬疑）仍能映射到新题材：都市逆袭 → 逆袭打脸，甜宠 → 甜宠霸总，悬疑 → 悬疑复仇。

## 四、故事引擎：从一句话到剧本（8 步）

```
① 前提选择（题材 × 受众 × 可行性）
      ▼
② Logline 生成与评分（10 选 1）
      ▼
③ 人物与关系设计（3–5 人）
      ▼
④ Beat Sheet（60s: 5–7 beats；3min: 8–12）
      ▼
⑤ 场次拆解（1–3 个场景）
      ▼
⑥ 台词草稿
      ▼
⑦ 剧本医生（评分 + 改写）
      ▼
⑧ 原创性检查 → 分镜
```

每步都有闸门：不达标的方案不进入下一步，避免"垃圾进、垃圾出"。

### 第 ② 步：Logline 评分

对每个候选 logline 按 6 项打分（1–5）：

| 维度 | 问题 |
| --- | --- |
| 高概念 | 一句话能听懂吗？ |
| 冲突 | 谁想要什么？谁阻挡？ |
| 代价 | 失败会失去什么？ |
| 反差 | 有没有新鲜感/意外组合？ |
| 可视化 | 能拍出来吗？ |
| 受众匹配 | 目标观众会在意吗？ |

总分 < 18 的候选淘汰；保留 2–3 个让用户选。

> **实现说明（A15，ADR-0104）**：`scoreLogline(text, genre)` 在本地按词法与结构给六维打分（1–5），返回总分、淘汰 / 保留 / 优先与每维理由；`scoreLoglines` 一行一个候选、最多 10 条。它是**启发式筛子，不是模型评审**：界面写明分数在本机算、最终由人拍板。生成结果下方自动给草稿 logline 打分，输入区另有 `logline 工坊` 可以批量给候选打分。阈值沿用本文：< 18 淘汰，≥ 24 优先。

### 第 ④ 步：Beat Sheet 模板

**60 秒单集**

| 时间 | Beat | 任务 |
| --- | --- | --- |
| 0–3s | hook | 冲突/悬念/反差，抓住注意力 |
| 3–10s | setup | 人物、关系、目标 |
| 10–25s | escalation | 障碍出现，压力上升 |
| 25–40s | turn | 反转/认知变化 |
| 40–55s | climax | 情绪/爽点兑现 |
| 55–60s | endHook | 新悬念，留钩 |

**3 分钟单集**：hook → setup → escalation ×2 → turn → climax → resolution → endHook。

**系列**：每集一个小闭环 + 一个大钩子；前 10 集决定留存；每 3–5 集一个中反转。

> **实现说明（A17，ADR-0104）**：三套模板落在 `BEAT_SHEETS`（60s / 3min / series），每拍有 beat、时间窗与任务；`beatWindows(sheet, totalMs)` 按实际草稿时长等比换算。故事页可选模板并查看时间窗；选中的模板会以 `结构参考「60 秒单集」：…` 的规则写进文本模型的系统提示，但生成目标仍是 60–90 秒、10–14 镜——3 分钟模板是拆长版本用的参考，不在这一轮改变生成规模。

## 五、人物与关系

### 人物卡

```ts
interface CharacterArc {
  want: string;        // 表层欲望
  need: string;        // 深层需要
  wound: string;       // 创伤
  flaw: string;        // 缺陷
  secret: string;      // 秘密
  agency: string;      // 主动做出什么选择
  arc: string;         // 60s 内可以没有完整弧光，但必须有"选择"
}
```

### 关系即冲突

每对关系都要回答三个问题：

1. 他们**想要**对方什么？
2. 他们**害怕**对方什么？
3. 他们**隐瞒**了什么？

没有张力的关系，不值得写进短剧。

### 人数与场景预算

- 单集主要人物 ≤ 5，核心冲突人物 ≤ 3。
- 单集场景 ≤ 3，最好 1–2 个。
- 这不是艺术限制，是**生成可行性与成本**的限制。

---

## 六、台词与钩子

### 台词规则

- 单句 ≤ 15 字（竖屏字幕友好）；单镜 ≤ 2 句。
- 每句要么推进剧情，要么揭示人物；两者都不做的删掉。
- 避免解释性台词（"其实我是你失散多年的……"），用冲突和行动透露。
- 金句：一句能截图传播的话。
- 打脸台词：先抑后扬，短、狠、准。

### 钩子类型

| 开场钩子 | 结尾钩子 |
| --- | --- |
| 悬念（一个未解的问题） | 反转（认知被推翻） |
| 冲突（当场对抗） | 新威胁（更大的危险） |
| 反差（身份/情境错位） | 身份揭露 |
| 危机（倒计时/危险） | 情感悬念（他会不会回头） |
| 秘密（观众知道，角色不知道） | 倒计时/下一集事件 |
| 倒叙（先看结果） | 未完成动作 |

### Hook 评分

- 好奇度：观众想知道答案吗？
- 紧迫度：现在就得看吗？
- 可视化：能用画面表达吗？
- 新鲜度：见过很多次吗？

## 七、剧本医生

不是"润色文字"，而是**结构诊断 + 定向改写**。

### 评分维度（1–5）

| 维度 | 说明 |
| --- | --- |
| Hook 强度 | 前 3 秒是否抓人 |
| 前提清晰度 | 一句话能否说清 |
| 欲望/障碍/代价 | 是否成立 |
| Beat 密度 | 每 15–20 秒是否有增量 |
| 反转质量 | 是否意外且合理 |
| 人物清晰度/主动性 | 主角是否在做选择 |
| 关系张力 | 每对关系是否有冲突 |
| 台词效率 | 是否有废话/解释 |
| 情绪兑现 | 爽点/泪点是否到位 |
| 结尾钩子 | 是否留钩 |
| 可拍性 | 场景/人物/动作是否可控 |
| 原创性 | 是否套路/雷同 |

### 触发条件（不达标就重写）

- Hook < 3；
- Beat 密度 < 1 次 / 20 秒；
- 没有清晰的欲望/障碍/代价；
- 主要人物 > 5；
- 场景 > 3；
- 平均台词长度 > 15 字；
- 没有结尾钩子；
- 原创性相似度 > 0.8；
- 可拍性 < 3。

### 改写模式

- 强化钩子（换开场/加冲突）；
- 加反转（在 25–40s 插入认知变化）；
- 删解释（把说明改成行动）；
- 锐化冲突（让对手更主动）；
- 减人物/减场景（降成本、提清晰度）；
- 重写结尾（留钩而不泄气）。

---

## 八、原创性与版权

- **相似度检查**：文本 n-gram / embedding + 故事 Beat 序列比对 + 人物关系结构比对。
- **标记而非阻断**：高相似度触发人工复核，避免误杀。
- **IP 来源**：
  - 原创生成（默认）；
  - 公版/经典改编（需注明）；
  - 授权 IP（成本高、法律链长，后期）；
  - 用户上传小说（需权利声明）。
- 生成内容的权属与商用条款，写进用户协议与平台规则。

## 九、评测指标

| 指标 | 说明 |
| --- | --- |
| Logline 总分 | 6 维评分 |
| Hook 强度 | 人工 + LLM |
| Beat 密度 | 每 20 秒的增量次数 |
| 反转质量 | 意外性 × 合理性 |
| 台词效率 | 有效台词 / 总台词 |
| 可拍性 | 场景/人物/动作/成本 |
| 原创性 | 与已知作品的相似度 |
| 观众留存 | 上线后：3 秒/完播/追更 |

## 十、失败模式

| 失败 | 表现 | 原因 | 对策 |
| --- | --- | --- | --- |
| 套路化 | 看开头猜到结尾 | 模板依赖过重 | 强制"一个具体细节/意外组合" |
| 解释过多 | 人物在念设定 | LLM 倾向交代 | 改成冲突/行动 |
| 人物扁平 | 好人全好、坏人全坏 | 没有欲望/恐惧/秘密 | 关系三问 |
| 冲突弱 | 没有真正的阻力 | 对手不主动 | 让对手先出手 |
| 钩子假 | 为悬而悬 | 钩子与主线无关 | 钩子必须改变处境 |
| 结尾泄气 | 讲完就完 | 没有留钩 | 强制 endHook |
| 不可拍 | 场景/人物太多 | 写作不顾生成约束 | 题材矩阵 + 可拍性评分 |
| 价值观风险 | 拜金/暴力/歧视 | 未做审核 | 内容安全前置 |
| 同质化 | 所有片子一个味 | 规则/模板统一 | 风格包 + 具体细节 + 人的介入 |

## 十一、与 IR 的映射

| 概念 | IR |
| --- | --- |
| 前提 | `Premise`（题材/受众/基调/约束） |
| Logline | `Project.logline` |
| 人物弧光 | `CharacterArc` |
| Beat | `Beat` |
| 钩子 | `Hook` |
| 剧本医生报告 | `ScriptDoctorReport` |
| 原创性报告 | `OriginalityReport` |
| 故事圣经 | `StoryBible` |

> 故事层不是"一段文本"，而是结构化、可诊断、可回滚的数据。这样剧本医生、分镜、生成才能共用同一份真相。
