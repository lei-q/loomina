# 导演语法库（首批规则）

> 这是"分镜好不好"的核心资产，也是《织光机》区别于通用工具的地方。
> **规则不是提示词，是可执行、可校验、可版本化的约束。**
> 首批 37 条：15 条必须（must）、17 条建议（should）、5 条可选（may）。

---

## 一、规则怎么用

- **must**：结构性/安全性规则，违反即报错或自动修正（轴线、时长、覆盖率、模型能力）。
- **should**：审美默认值，违反给警告，用户可覆盖。
- **may**：风格化选项，默认关闭或按项目开启。

规则由**规则引擎**执行，LLM 负责在规则允许的范围内做创意选择（ADR-0015）。

---

## 二、规则格式

```ts
interface DirectorRule {
  id: string;                 // "S1" / "X3"
  category: "shot-size" | "angle" | "movement" | "axis"
          | "rhythm" | "lighting" | "feasibility";
  priority: "must" | "should" | "may";
  when: string;               // 触发条件
  then: string;               // 建议/强制
  params?: Record<string, unknown>;
  rationale: string;
  positive: string;           // 正例
  negative: string;           // 反例
  version: number;
}
```

## 三、景别（S）

| ID | 规则 | 优先级 | 理由 |
| --- | --- | --- | --- |
| S1 | 建立空间用 wide / extreme-wide | must | 观众先要知道"在哪"，才能理解后面的特写 |
| S2 | 双人对话用 medium / medium-close | should | 兼顾表情与关系 |
| S3 | 情绪转折用 close | must | 转折靠脸，不靠台词 |
| S4 | 信息/细节用 insert / extreme-close | should | 让观众"看到"关键信息 |
| S5 | 对话场景必须有反应镜头 | must | 短剧看的是"另一个人怎么反应" |
| S6 | 连续同景别 ≤ 2 | must | 避免画面单调、节奏平 |
| S7 | 特写连续 ≤ 2 | should | 过度特写会压迫疲劳 |
| S8 | 场景收尾可用 wide 拉远 | may | 留余味、交代结局空间 |

## 四、机位（A）

| ID | 规则 | 优先级 | 理由 |
| --- | --- | --- | --- |
| A1 | 权力/威胁用低机位 | should | 仰拍放大压迫感 |
| A2 | 脆弱/被压用高机位 | should | 俯拍让人显得渺小 |
| A3 | 中立对话用 eye-level | must | 默认视角，避免无动机的倾斜 |
| A4 | 失衡/不安用 dutch，单场 ≤ 1 | may | 过量会廉价 |
| A5 | 对话优先 OTS 建立关系 | should | 过肩镜头同时给两人关系 |
| A6 | POV 需动机，单场 ≤ 1 | may | 无动机 POV 会让观众迷惑 |

## 五、运镜（M）

| ID | 规则 | 优先级 | 理由 |
| --- | --- | --- | --- |
| M1 | 发现/逼近用 push-in | should | 推镜制造"逼近真相" |
| M2 | 抽离/揭示用 pull-out | should | 拉镜揭示环境与孤独 |
| M3 | 跟随/连接用 track / pan | should | 保持空间连续 |
| M4 | 紧迫用手持，单场 ≤ 2 镜 | may | 手持过量会晕 |
| M5 | 固定镜头用于控制/压迫 | should | 静止本身就是态度 |

## 六、轴线与空间（X）

| ID | 规则 | 优先级 | 理由 |
| --- | --- | --- | --- |
| X1 | 180 度规则：同场机位在轴线同侧 | must | 否则人物左右关系跳变 |
| X2 | 越轴必须有过渡镜（中性镜/移动镜头） | must | 让观众重新建立空间 |
| X3 | 视线匹配：A 看右，B 看左 | must | 对话的"看"必须对上 |
| X4 | 屏幕方向一致：移动/追逐方向不反转 | must | 否则观众以为掉头了 |

## 七、节奏（R）

| ID | 规则 | 优先级 | 理由 |
| --- | --- | --- | --- |
| R1 | 前 3 秒必须有 hook | must | 竖屏短剧的生死线 |
| R2 | 每 15–20 秒一个 turn / escalation | must | 维持信息增量 |
| R3 | 切率随冲突强度上升 | should | 节奏要"呼吸"，不是一直快 |
| R4 | 情绪高点前留 0.5–1 秒呼吸 | should | 留白让爆点更响 |
| R5 | 结尾留 hook | must | 完播与下集的关键 |

## 八、光影（L）

| ID | 规则 | 优先级 | 理由 |
| --- | --- | --- | --- |
| L1 | 高光比（≥4:1）用于冲突/悬疑 | should | 明暗对立=戏剧张力 |
| L2 | 低光比（≤2:1）用于温情/喜剧 | should | 柔和=安全 |
| L3 | 暖色温（3000–3500K）用于记忆/亲密 | should | 暖=靠近 |
| L4 | 冷色温（5600–7000K）用于疏离/科技 | should | 冷=距离 |
| L5 | 主光方向决定情绪：侧逆光神秘、顶光压迫、正面光平实 | should | 方向比强度更重要 |
| L6 | 实用光源（台灯/霓虹/窗光）增加真实感与动机 | may | 光要有"来源" |

## 九、生成可行性（F）

| ID | 规则 | 优先级 | 理由 |
| --- | --- | --- | --- |
| F1 | 单镜 ≤ 模型安全时长 | must | 超限必然漂移（ADR-0012） |
| F2 | 运镜必须在能力矩阵内 | must | 否则生成结果与分镜不符 |
| F3 | 规避模型弱项：背影、复杂花纹、多人、极端角度 | must | 一致性天花板（CONSISTENCY.md） |

## 十、覆盖率模板（与规则配套）

| 场景类型 | 镜头序列 |
| --- | --- |
| 双人对话 | master → OTS A → OTS B → CU A → CU B → reaction → insert |
| 对峙/冲突 | CU A ↔ CU B 交替，时长递减 |
| 信息揭示 | wide → detail insert → reaction CU → push-in |
| 单人情绪 | medium → CU → ECU detail → wide |
| 动作 | wide → tracking → impact CU → reaction |
| 蒙太奇 | 4–8 个 insert，按音乐节拍切 |

## 十一、怎么评测这套规则

### 评测集
- 30 个短剧片段（授权素材或自制），标注景别、机位、运镜、光影、Beat。
- 每个 must 规则配 2 个正例 + 2 个反例。

### 指标
| 指标 | 说明 | 目标 |
| --- | --- | --- |
| 规则违规率 | 每 100 镜违反 must 规则的次数 | < 5 |
| 人类偏好 | 与"纯 LLM 分镜"做 A/B，5 分制 | 规则版胜率 > 65% |
| 景别多样性 | 景别分布的熵 | 不低于参考片 |
| 成本 | 每分钟镜头数 × 单价 | 可解释、可预算 |
| 生成成功率 | 一次通过的镜头比例 | 持续上升 |

### 节奏
1. 先只上 **15 条 must**，确保结构正确。
2. 再逐步加 should，每条都做 A/B。
3. may 类默认关闭，作为"风格包"提供。
4. 规则可被用户覆盖，覆盖行为要记录（用于反哺规则）。

---

## 十二、版本与来源

- 规则库独立版本化（`grammar@0.x`），与 IR 解耦。
- 每条规则有 `version` 与变更记录。
- 来源优先级：经典电影语法 → 短剧行业实践 → 自有 A/B 数据。
- 不把"某部片的风格"直接写成全局规则；风格应放在 `StyleProfile`，规则只定结构。

> 这套库越厚、越可测，产品就越像"导演"，而不是"抽卡器"。
