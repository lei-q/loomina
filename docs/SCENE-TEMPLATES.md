# 3D 场景模板库

> 决策：3D 灰盒最小版进 MVP（ADR-0016）。
> 本文定首批模板清单与规格。模板不是写实场景，是**带锚点的灰盒**：够用来摆位、定机位、查轴线、导出 depth。

> **实现现状（2026-11-12，B13.1 / ADR-0126）**：10 个模板既是提示词素材（`Location.templateId`），也带几何（`Location.space`：尺寸 + 锚点坐标与朝向），支持自动摆位、平面视锥与越轴检测。depth / edge 导出仍未做（B13.3，依赖待确认）。落地字段见 §七，验收状态见 §六。

---

## 一、选模板的原则

1. **高频**：覆盖都市短剧 80% 以上的场景。
2. **几何简单**：墙 + 地 + 几件关键家具就能表达空间。
3. **锚点清晰**：门、窗、桌、床、沙发等位置固定，便于自动摆位。
4. **光线可控**：有明确的自然光/实用光方向。
5. **可复用**：同一模板能承载多种剧情（冲突、亲密、谈判、独处）。

## 四、模板数据结构

```ts
interface SceneTemplate {
  id: string;
  name: string;
  category: "interior" | "exterior";
  dimensions: [number, number, number];   // 宽 × 深 × 高
  anchors: TemplateAnchor[];
  defaultCameras: TemplateCamera[];
  lightingDefaults: LightingSpec;
  tags: string[];
}

interface TemplateAnchor {
  id: string;
  type: "door" | "window" | "sofa" | "desk" | "bed" | "table"
      | "wall" | "light" | "prop" | "mirror";
  position: [number, number, number];
  rotation: number;
  capacity?: number;        // 可站/坐人数
}

interface TemplateCamera {
  id: string;
  label: string;            // "沙发正面" / "门口反打"
  position: [number, number, number];
  target: [number, number, number];
  focalLengthMm: number;    // 24 / 35 / 50 / 85
}
```

## 五、自动摆位规则

1. 从剧本识别场景类型与出场人数，匹配模板。
2. 按关系分配位置：
   - 对话双人 → 对面或 90°；
   - 权力关系 → 桌后 / 桌前；
   - 亲密 → 同侧或相邻；
   - 独处 → 画面偏一侧，留负空间。
3. 入场走 `door` 锚点；离场同理。
4. 主光方向优先取 `window`。
5. 自动给出 3 个机位建议：master、OTS A、OTS B。
6. 轴线由两人位置自动生成；所有机位默认在轴线同侧。

## 六、验收标准（MVP）

- [x] 2 人自动摆位 < 1 秒，位置合理。（B13.1：纯函数，无 IO）
- [x] 每个模板给出 3 个合法机位建议（含焦段）。（B13.1：master / OTS A / OTS B，同侧且夹进房间）
- [x] 越轴检测准确，能指出越轴的镜头。（B13.1：有坐标时按叉积判侧；没坐标退回调度近似，文案写「像」）
- [ ] 导出 depth / edge 图，可用于关键帧结构条件。（B13.3，WebGL 渲染器待确认）
- [x] 拖动人物或机位后，同场镜头自动重校验。（B13.1：拖动写 `shot.updated`，store 当场校验，分镜检查重算 V3）
- [ ] 模板切换时保留已有关键帧，只提示需要重生成。（模板切换保留锚点几何，关键帧与走位的回扫未做，见 R52）

## 七、轻量预设的落地形态（ADR-0103，2026-11-11；几何补齐于 B13.1，2026-11-12）

形状（B13.1 之后；`anchors` 从字符串数组变成带坐标的对象）：

```ts
// packages/pipeline/src/scene-templates.ts
interface SceneTemplate {
  id: string;
  name: string;
  category: "interior" | "exterior";
  dimensions: [number, number, number];      // 宽 × 深 × 高（米），现在是几何事实
  anchors: {
    id: string;                              // 换模板时按它保留作者改过的位置
    label: string;                           // "沙发（中左）"：进提示词，也画在俯视图上
    kind: "door" | "window" | "furniture" | "prop" | "light" | "mirror" | "wall";
    position: [number, number, number];      // 场地局部坐标，米，原点在房间中心地面
    facingRad?: number;                      // 绕 Y 轴朝向，0 = 朝 +Z（前）
    capacity?: number;                       // 可站 / 坐人数，0 = 不可承载
  }[];
  cameras: { label: string; focalMm: number }[]; // 机位名 + 焦段
  lighting: string;                           // "窗光 + 顶灯；4300K；光比 3:1"
  tags: string[];
  plots: string[];                            // 能承载的剧情类型
}
```

- 10 个模板全部落地（MVP 6 + v1 4），清单与本文 §二 / §三 一致；`apartment-living` 是 `living-room` 的别名。
- 挂载方式：`Location.templateId`。主镜 / 镜头提示词追加 `场景：走廊（公寓客厅模板（窗光 + 顶灯；4300K；光比 3:1；关键位置：窗（左）、沙发（中左）…））`。
- 定妆台地点行的编辑表单分两组列出模板（场景模板 / 旧模板），选中或展示时给出 `名称 · 宽×深×高 · 光线 · 机位`。
- 旧 id（`corridor` / `doorway` / `table` / `door`）继续可用，只是不带模板说明。
- **B13.1 已补（2026-11-12）**：10 个模板的每个锚点都带 `position` / `facingRad` / `capacity`，`templateSpace()` 把它们转成 `Location.space`。§五 的自动摆位（`suggestBlocking()`）与 §六 的越轴检测（`checkAxis()`）已按坐标工作。仍**未做**：立面与遮挡（B13.2）、depth / edge 导出（B13.3，WebGL 待确认）、模板尺寸与锚点位置的实测校准（现在是经验值，见 R51）。

## 八、B13 设计口径（ADR-0126，2026-11-11）

B13 分三刀，**第一刀不引入任何 3D 依赖**：

| 刀 | 内容 | 依赖 |
| --- | --- | --- |
| B13.1 俯视走位板 | 坐标进 IR、自动摆位、平面视锥、轴线检查 | 无（SVG） |
| B13.2 立面与遮挡 | 相机高度、人物朝向、前后景 | 无（仍是 2D 投影） |
| B13.3 depth / edge 导出 | 关键帧的结构条件 | **WebGL 渲染器，待确认** |

- 坐标系：地点局部坐标，原点在房间中心地面，单位米，右手系，Y 向上；坐标必须落在模板尺寸内（0.1 m 容差），越界拒绝、不夹取。
- 模板的 `dimensions` / `anchors` 从「只进提示词」变成「几何事实」：`Location.space` 存锚点的 `position` / `facingRad` / `capacity`，换模板时按锚点 id 尽量保留作者改过的位置。
- §五 的自动摆位规则落成纯函数 `suggestBlocking()`：**只建议、不写事件**，作者点「用这个摆位」才落 `shot.updated`。
- §六 的越轴检测落成 `checkAxis()`：用真实坐标算机位在轴线哪一侧；**有坐标时用精确版，没有坐标时退回 ADR-0108 的调度近似版**，文案区分「越轴」与「像越轴」。
- depth / edge 导出**不在第一刀**：平面 SVG 画不出 depth，它必须真实渲染几何体。`DepthExporter` 接口先定，实现等依赖确认；缺能力时降级，不假装存在。
- 界面是俯视平面图（房间外框 + 锚点 + 人物圆点与朝向 + 轴线 + 机位视锥），明确标注「这是俯视走位图，不是最终画面」——它没有相机高度与遮挡，不能叫「预演」。

### 落地与验收（B13.1，2026-11-12）

§六 的验收项按「已过 / 未过」分开记，不拿设计口径冒充已完成：

| §六 验收项 | 状态 | 证据 |
| --- | --- | --- |
| 自动摆位 < 1 s | **已过** | `blocking.test.ts` 断言纯函数耗时 < 1 s（实测远低于，无 IO） |
| 给出 3 个合法机位建议 | **已过** | `suggestBlocking()` 返 master / OTS A / OTS B，全部在轴线同侧、`fitInside()` 夹进房间 |
| 越轴检测 | **已过（有坐标时）** | `checkAxis()` 同侧不报、跨侧报、单人镜 `checked: 0`；没坐标的场次退回 V3 近似 |
| 拖动后自动重校验 | **已过** | 拖动写 `shot.updated`，store 当场跑 `blockingProblem`，分镜检查重算 V3 |
| 前后景 / 遮挡 / depth | **未过** | 归 B13.2 / B13.3，界面不出入口 |

坐标全部写在 `packages/pipeline/src/scene-templates.ts` 的模板里，单位米。原点在房间中心地面，`+X` 右、`+Z` 前、`Y` 上。客厅 5×4×2.8 m 的例子：窗在 `[-2.5, 1.2, 0]`，沙发在 `[-1.2, 0.45, 0.9]`，电视墙在 `[0, 1.4, 2]`，入户门在 `[2.5, 0, -1.6]`。

模板坐标是经验值不是实测值（R51）：作者可以在平面图上拖，拖完的坐标同样没有真实性保证。换模板时 `mergeTemplateSpace()` 按锚点 id + kind 保留作者挪过的位置，模板没有的锚点丢掉。
