# 规则评测素材库（I9）

目标：**30 段真实短剧片段**，用来标定分镜规则的阈值（例如「同景别连续 ≤ 2」到底该是 2 还是 3），
并核对规则在真实片子上是会误报还是漏报。协议见 [DIRECTOR-GRAMMAR.md](../../../../../docs/DIRECTOR-GRAMMAR.md) 第十一节。

## 一段素材长什么样

一个片段一个文件，文件名与 `meta.id` 一致：`clip-a01.json`。

```json
{
  "meta": {
    "id": "clip-a01",
    "source": "自制 / 剧名 / 编号",
    "license": "self-made",
    "genre": "悬疑复仇",
    "platform": "douyin",
    "note": "第 3 集，02:10–02:40，共 9 镜"
  },
  "project": { "...": "导出的项目 IR（ProjectSchema 校验）" },
  "expected": ["V6", "V13"]
}
```

- `meta.license` 必填：没有授权的素材不进库（H7 的口径）。
- `project` 是整份 IR，不是截图：规则要能重跑，规则改了也不用重新标注。
- `expected` 是**人工看过这段之后**认为该报的规则编号（V1–V14）。
  只标「确实该报」的；没标 = 人认为这段没问题。

## 为什么不直接存规则输出

存输出等于把旧规则的结论焊死在素材里：规则一改，标注就过期，而且要重标一遍。
存人工标注，规则怎么改都能重跑比对。

## 怎么加一段

**从真实项目导入（推荐）**：

1. 在顶栏「空间 ▾」里点「导出」，得到 `loomina.workspace-export` 包；
2. 跑：

   ```bash
   pnpm eval:corpus:import -- \
     --in ~/Desktop/夜班-2026-11-15.json \
     --source "夜班（自制）" --license self-made
   ```

   默认按场次切（一场一段）；整包当一段就加 `--whole`。
3. 逐段看过，把「确实该报」的规则编号写进 `expected`（导入时是空的）；
4. 跑 `pnpm eval:corpus`，看误报 / 漏报清单。

**手写 / 拷一份现有素材**也行，格式见下。

> 素材单位是**完整场次或整集**，不要切摘录——V1 / V2 / V7 判的是场级事实，
> 摘录会让这三条系统性误报（ADR-0248）。

## 现状

- 回放器：`apps/web/lib/eval-corpus.ts`；命令行：`pnpm eval:corpus`
- 正反例回归（规则方向没写反）：`pnpm eval:rules`
- **素材：5 / 30**，全部来自示例项目「夜班」的 5 个场次（`license: self-made`，
  `note` 写明「不是真实短剧，只验跑分链路」）。

## 第一次跑分（2026-11-15）

```
5 / 30 段，12 镜；违规率 216.67 / 100 镜；景别熵 1.555 bit
与人工标注：精确率 71%，召回率 100%（误报 4，漏报 0）
```

误报全部集中在三条规则：**V1**（场首没有建立镜头）、**V2**（画外音）、**V7**（切率）。
原因不是规则写错了，而是**素材是摘录片段**：

- 从一段完整戏里切出来的场面，本来就不一定有建立镜头；
- 画外音（人在画外说话）是短剧常用手法，V2 按「说话人必须在场」判会误伤；
- 剪出来的片段切率与整片不同，V7 的比较基准失真。

**结论：素材要按「完整场次或一集」收，不要切摘录。** 如果一定要收摘录，
得先给规则加「摘录模式」（关掉 V1/V2/V7），这是下一步的设计问题。
